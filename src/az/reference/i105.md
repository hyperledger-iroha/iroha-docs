# I105 Hesab ünvanı formatı {#i105-account-address-format}

I105 - Iroha 3 `AccountId` üçün kanonik xarici mətn formatıdır.

Onun pay yükü hesab nəzarətçisini təmsil edir.

Onun sentinelli, nəzərdə tutulmuş şəbəkəni zəncir ayırdçısı ilə müəyyənləşdirir.

API, əməliyyat, icazə və ya sorğu üçün kanonik hesab ID istədiyi hər yerdə istifadə edin.

I105 hesabı ID domensizdir.

`treasury@payments.universal` kimi bir dəyər hesab aliasıdır, I105 ID-nin başqa yazılışı deyil.

I105 ID əldə etmək hesabı qeydiyyatdan keçirmir və ya maliyyələşdirmir.

::: warning İnteqrasiya uğursuzluqlarının əksəriyyətinin qarşısını alacaq qaydalar

- Bir ünvanın kodlanmasından və ya təsdiqlənməsindən əvvəl şəbəkə profilini seçin.
- Kanonik UTF-8 silsiləni saxlayın və tam müqayisə edin.
- Hərflərin böyük-kiçikliyini qoruyun və `Unicode` normallaşdırmasını tətbiq etməyin.
- I105 ID-də `@domain` və ya `@domain.dataspace` şəkilçisi olmamalıdır.
- Iroha SDK və ya `iroha tools address` ilə istifadə edin.
- Bir müntəzəm ifadə I105 təsdiqçi deyil.

:::

## Sözün əsl anatomiyası {#literal-anatomy}

I105 hərfinin üç qonşu hissəsi və heç bir ayırıcı yoxdur:

```text
<network sentinel><base-105 canonical payload><six checksum symbols>
```

|Bölmə |Məqsəd|Çek suması əhatə olunması |
| ---------------- | ------------------------------------------------------------------ | ----------------- |
|Şəbəkə sentinalı |Mapping mətni bir `u16` silsilə ayrımcı |Qeyri-müvafiq .|
|Faydalı yük|`base-105` kanonik hesab nəzarətçisi baytlarının kodlanması |Əhatə olunur |
|Çek suması |I105 əlifbası ilə təqdim olunan altı `Bech32m` üslubunda `5-bit` dəyərləri |N/A |

Faydalı yük və yoxlama cəmiyyəti hesab nəzarətçisini müəyyənləşdirir.

Sentinel şəbəkə kontekstini seçir.

Eyni nəzarətçinin Taira və Minamoto üzərində eyni pay yükü və yoxlama miqdarı var, lakin hər bir şəbəkə fərqli bir aparıcı sentinel istifadə edir.

Bir dekoder gözlənilən diskriminantı tətbiq etməlidir.

Çeks suması sentinelin əvəzlənməsini aşkar edə bilməz.

### Şəbəkə sentinelləri {#network-sentinels}

|şəbəkə və ya kontekst |Zəncir ayırdçısı |Hex |Canonical Sentinel |
| ----------------------- | -------------------------------: | -------: | ------------------------------------------- |
|Taira ictimai test şəbəkəsi |                            `369` |`0x0171` |`test` |
|Minamoto ictimai şəbəkə |                            `753` |`0x02f1` |`sora` |
|İnkişaf kontekstində |                              `0` |`0x0000` |`dev` |
|Başqa hər hansı bir `u16` dəyər |Hamısı `0`, `369` və `753` istisna olmaqla. |        — |`n` əlavə ən az desimal, məsələn `n42` |

Adlanmış dəyərlər həmişə öz adlanan gözətçi istifadə edir.

`n00042`, `n369`, `n753` və `n0` kimi formalar kanonik deyil.

Transaksiya zəncirinin ID və I105 zəncir ayırdçısı ayrı dəyərlərdir.

Son nöqtə və ya zəncir ID seçilməsi ünvan profilini açıq-aşkar seçmir.

## Normativ bir açar nümunəsi {#normative-single-key-example}

Aşağıda göstərilən paylı yük və Minamoto forması SDK çapraz uyğunluq qurğusundan gəlir.

Taira formasında eyni pay yükünə Taira sentinelli tətbiq edilir:

```text
Public-key payload:
3B6A27BCCEB6A42D62A3A8D02A6F0D73653215771DE243A63AC048A18B59DA29

Public-key multihash accepted by tooling:
ed01203B6A27BCCEB6A42D62A3A8D02A6F0D73653215771DE243A63AC048A18B59DA29

Canonical account payload:
0x020001203b6a27bcceb6a42d62a3a8d02a6f0d73653215771de243a63ac048a18b59da29

Minamoto I105, discriminant 753:
sorauﾛ1NﾗhBUd2BﾂｦﾄiﾔﾆﾂﾇKSﾃaﾘﾒﾓQﾗrﾒoﾘﾅnｳﾘbQｳQJﾆLJ5HSE

Taira I105, discriminant 369:
testuﾛ1NﾗhBUd2BﾂｦﾄiﾔﾆﾂﾇKSﾃaﾘﾒﾓQﾗrﾒoﾘﾅnｳﾘbQｳQJﾆLJ5HSE
```

Kanonik paylı yüklə başlayır `02 00 01 20`: başlıq `0x02`, kompakt bir açarlı etiket `0x00`, `Ed25519` əyrənmə ID `0x01`, və 32 baytlıq açar uzunluğu `0x20`.

`multihash` prefiksi giriş metadatalarıdır və nəzarətçi pay yükünə nüsxələnmir.

## CLI ilə IDs hazırlayın və yoxlayın. {#create-and-inspect-ids-with-the-cli}

İctimai şəbəkə üçün adı çəkilmiş profil üstünlük verir:

```bash
PUBLIC_KEY='ed01203B6A27BCCEB6A42D62A3A8D02A6F0D73653215771DE243A63AC048A18B59DA29'

TAIRA_ACCOUNT_ID="$(
  iroha tools address convert --profile taira "$PUBLIC_KEY"
)"

MINAMOTO_ACCOUNT_ID="$(
  iroha tools address convert --profile minamoto "$PUBLIC_KEY"
)"
```

Adres-kodek davranışını diaqnozu edərkən I105 girişini normallaşdırın və müqayisə edin:

```bash
NORMALIZED_ACCOUNT_ID="$(
  printf '%s\n' "$TAIRA_ACCOUNT_ID" \
    | iroha tools address normalize --profile taira
)"

test "$NORMALIZED_ACCOUNT_ID" = "$TAIRA_ACCOUNT_ID"
```

Qəbul edilmiş formatı, kanonik hex və seçilmiş şəbəkə kontekstini JSON kimi yoxlayın:

```bash
iroha tools address convert \
  --profile taira \
  --format json \
  "$TAIRA_ACCOUNT_ID"
```

Yeni xətti ilə ayrılmış faylın ünvan-kodek quruluşunu analiz səhvlərini səssiz qəbul etmədən yoxlayın:

```bash
iroha tools address audit \
  --profile taira \
  --input account-ids.txt \
  --format json
```

::: caution CLI təsdiqləmə sərhədi

`convert`, `normalize` və `audit` əmrləri aşağı səviyyəli `AccountAddress` kodek üzərində işləyir.

Onlar sentinel, əlifba, yoxlama suması, bayt uzunluğu, `CurveId` / açar şəklini və ünvan qatının dəqiq yenidən kodlanmasını təsdiqləyirlər.

Onlar `AccountId` materiallaşdırılmır.

Onlar özləri bütün multisig siyasət semantikasını təsdiqləmirlər.

Onlar başlıq sinfinin nəzarətçi ilə uyğun olduğunu sübut etmir.

Avtorizasiyadan və ya davamlı yaddaşa yazmadan əvvəl ciddi `AccountId` təsdiqləməsindən istifadə edin.

:::

Xüsusi bir şəbəkə üçün onun `--network-prefix` ilə açıq şəkildə qurulmuş ayırdçılığı istifadə edin.

Mövcud ünvanı açıq kontekstlər arasında çevirərkən mənbəyə `--expect-prefix` ilə də daxil edin:

```bash
iroha tools address convert \
  --expect-prefix 369 \
  --network-prefix 753 \
  "$TAIRA_ACCOUNT_ID"
```

Yenidən kodlaşdırma yalnız şəbəkə kontekstini dəyişir.

Hesabı hədəf şəbəkədə qeydiyyatdan keçirmir və eyni nəzarətçinin orada yenidən istifadə edilməsini sübut etmir.

## Kodlama alqoritmi {#encoding-algorithm}

Canonical kodlaşdırıcıları aşağıdakı əməliyyatları həyata keçirir:

```text
canonical = header || controller
payload_digits = base_convert(canonical, base_256, base_105)
checksum_digits = bech32m_6(hrp = "snx", convert_8_to_5(canonical, pad = true))
literal = sentinel(discriminant) || alphabet[payload_digits || checksum_digits]
```

Əvvəlki sıfır baytlar sıfır dəyərli `base-105` rəqəmlər kimi saxlanılır.

Kontrol suması `Bech32` `polymod` generatorlarını və sabit `0x2bc830a3` istifadə edir.

Yalnız yoxlama məbləği HRP ASCII silsiləsi `snx`dir.

Yalnız yoxlama suması HRP ünvanda çap edilmir.

Altı yoxlama həcminin dəyəri `0..31` aralığında yerləşir və paylı yüklə eyni I105 əlifbası ilə göstərilmişdir.

### I105 əlifba {#i105-alphabet}

105 simvol məhz bu sırada indekslənir.

Birinci sıra `Bitcoin Base58` əlifbasıdır və `0..57` rəqəmlərini ehtiva edir.

İkinci sıra `58..104` rəqəmlərini ehtiva edir.

Kodek tətbiq edərkən sətirləri konkatenləşdirin.

```text
123456789ABCDEFGHJKLMNPQRSTUVWXYZabcdefghijkmnopqrstuvwxyz
ｲﾛﾊﾆﾎﾍﾄﾁﾘﾇﾙｦﾜｶﾖﾀﾚｿﾂﾈﾅﾗﾑｳヰﾉｵｸﾔﾏｹﾌｺｴﾃｱｻｷﾕﾒﾐｼヱﾋﾓｾｽ
```

Əlifba `Unicode` -ə həssasdır.

Düzgün ardıcıllıqda `compatibility-width` Yapon `kana` simvolları və `ヰ` və `ヱ` üçün göstərilən kod nöqtələrindən istifadə olunur.

NFC, NFKC, simvol eninin çevrilməsi, hərf registrinin qatlanması və ya oxşar görünüşlü simvollarla əvəzləmə tətbiq etməyin.

ASCII `0`, `O`, `I` və `l` əlifba simvolları deyil.

## Canonical hesabının pay yükü {#canonical-account-payload}

`base-105` bədəni ikitərəfli hesabın pay yükünü kodlaşdırır, ictimai açarlı bir silsilə deyil və Norito JSON obyektini yox:

```text
header:u8 || controller:variable
```

Aşağıdakı bütün çox baytlı tam rəqəmlər imzalanmamış və `big-endian`.

Domen, məlumat sahəsi, alias, UAID, və hesab metadata baytları mövcud deyil.

### Başlıq byti {#header-byte}

|Bitlər |Genişlik |Mövcud kodlaşdırıcı çıxışı |Məna|
| ------ | ----: | ---------------------------: | ---------------------------- |
| `7..5` |     3 |                          `0` |Adres formatı versiyası sahəsi |
| `4..3` |     2 |`0` tək açar, `1` çox ədəd |Adres sinifi |
| `2..1` |     2 |                          `1` |Normallaşdırma versiyası sahəsi |
| `0`    |     1 |                          `0` |Rezerv edilmiş `extension flag` |

Hal-hazırda V1 kodlaşdırıcıları bir açarlı nəzarətçi üçün başlıq `0x02` və multisig nəzarətçisi üçün `0x0a` emit edir.

Adres sinifləri `2` və `3` təyin edilməyib.

Bir `extension flag` `1` rədd edilir.

Aşağı səviyyəli dekoder digər versiya və normalizasiya bit dəyərlərini saxlaya bilər və sinfi idarəetmə etiketinə qarşı müstəqil olaraq keçid yoxlamır.

`AccountId` -ə çevrilmək və onun kanonik tərcüməsinin müqayisə edilməsi mövcud V1 kanonikliyini göstərir.

### Tək açarlı nəzarətçi {#single-key-controller}

Xüsusi ictimai açar yükünün ən çox 255 bayt olduğu zaman kompakt formada istifadə edin:

|sahə |Genişlik |Qiymət və ya mənası |
| ------------ | --------------: | ------------------------ |
|`tag` |1 bayt |`0x00` |
|`curve` |1 bayt |`CurveId` qeydiyyat qiyməti |
|`key_len` |1 bayt |Xam açarın uzunluğu |
|`public_key` |`key_len` baytlar |Xam ictimai açar yükü |

255 baytdan uzun olan açarlar genişləndirilmiş formada istifadə edir:

|sahə |Genişlik |Qiymət və ya məna |
| ------------ | --------------: | ---------------------------- |
|`tag` |1 bayt |`0x02` |
|`curve` |1 bayt |`CurveId` qeydiyyat qiyməti |
|`key_len` |2 bayt |Xam açarın uzunluğu, `big-endian` |
|`public_key` |`key_len` baytlar |Xam ictimai açar yükü |

Genişləndirilmiş kodlama kompakt formada uyğun olan bir açar üçün kanonik deyil.

### Multisig nəzarətçisi {#multisig-controller}

|sahə |Genişlik |Qiymət və ya məna |
| ---------------- | -------: | ------------------------------ |
|`tag` |1 bayt |`0x01` |
|`policy_version` |1 bayt |Hələlik qiymət `1` |
|`threshold` |2 bayt |Tələb olunan ümumi təsdiq çəki |
|`member_count` |2 bayt |Aşağıdakı üzvlərin sayı |
|`members` |Dəyişən |Təkrarlanan üzv qeydləri |

Hər üzv qeydləri aşağıdakılardır:

|sahə |Genişlik |Məna|
| ------------ | --------------: | ------------------------ |
|`curve` |1 bayt |`CurveId` qeydiyyat qiyməti |
|`weight` |2 bayt |Üzvlərin təsdiqlənməsi çəkisi |
|`key_len` |2 bayt |Xam açarın uzunluğu |
|`public_key` |`key_len` baytlar |Xam ictimai açar yükü |

Etibarlı siyasətin ən azı bir üzvü və müsbət çəkiləri olmalı, təkrarlanan ictimai açarları olmamalı, həddi isə `1`-dən üzvlərin çəkilərinin cəminədək olmalıdır.

```text
member_count >= 1
all(member.weight > 0)
1 <= threshold <= sum(member.weight)
all_unique(member.public_key)
```

Canonical quruculuğu üzvləri imzalama alqoritminin sabit adı, sıfır ayırıcı bayt və daha sonra xam ictimai açar baytları ilə sıralayır.

```text
member_sort_key = stable_algorithm_name || 0x00 || raw_public_key
```

I105 əlifbasının sabit simvol uzunluğu yoxdur, çünki multisig və post-quantum nəzarətçiləri böyük ola bilər.

## Sərt AccountId təsdiqləmə və kanoniklik {#strict-accountid-validation-and-canonicality}

SDK-ni gözlənilən zəncir ayırdçısı ilə qurduqdan sonra, `AccountId` -ə analiz edin və geri qaytarılan kanonik təsvirin kəsilmiş girişlə müqayisə olun.

Müqayisə əhəmiyyətlidir, çünki parser `AccountId` qurarkən dekodlana biləcək nəzarətçi materialını normallaşdıra bilər.

```rust
use eyre::{ensure, Result};
use iroha::data_model::prelude::AccountId;

fn parse_canonical_account_id(input: &str) -> Result<AccountId> {
    let input = input.trim();
    let parsed = AccountId::parse_encoded(input)?;

    ensure!(
        parsed.canonical() == input,
        "account ID is valid but not in its current canonical I105 form"
    );

    Ok(parsed.into_account_id())
}
```

Güvənilməyən bir ip üçün uyğun tətbiq:

1. Trim yalnız tam dəyər ətrafında boş yerə nəqliyyat etməyə icazə verdi.
2. Gözətçiyi oxuyun və gözlənilən zəncir ayırdçısı tələb edin.
3. Hər qalan `Unicode` simvolunu 105 simvollu əlifba ilə xəritə edin.
4. Yoxlama cəminin altı rəqəmini ayırın.
5. Faydalı yük rəqəmlərini kanonik baytlara çevirin.
6. Kanonik baytlar üzrə yoxlama məbləğini yoxlayın.
7. Başlığı və nəzarəti araşdırın, tələb olunur:
   - sahənin dəqiq uzunluğu
   - bir dəstəklənmiş `CurveId`
   - etibarlı ictimai açar
   - arxasında heç bir bayt yoxdur
   - tətbiq olunduğu halda etibarlı multisig siyasəti
8. `AccountId` qurun.
9. Gözlənilən diskriminant üçün `AccountId` kanonik olaraq təqdim edin.
10. Kənar boşluqları kəsilmiş girişlə `byte-for-byte` bərabərlik tələb edin.

Tələbənin açıq son `render-and-compare` mərhələsi minimal olmayan rəqəmsal sentinelləri, qeyri-kanonik nəzarətçi tərtibatlarını, yenidən təşkil edilmiş siyasət materialını və kodlaşdırıcının hazırkı V1 çıxışı olmayan hər hansı bir digər yazımını rədd edir.

Müvəffəqiyyətli bir yoxlama suması və ya aşağı səviyyəli `AccountAddress` təhlil bu yoxlamanın əvəzinə deyil.

Bu dəyərləri ciddi hesab sahəsində qəbul etməyin: ID

- `alice@wonderland.universal` kimi bir hesab aliasi
- I105 hərfi və əlavə edilmiş `@domain` sufiksi ilə
- `ed0120...` kimi ictimai açarlı `multihash`
- `0x02000120...` kimi kanonik payload hex
- Yanlış zəncir diskriminantının ünvanı
- Böyük və ya kiçik hərflər, xarakter genişliyi, `kana`, pay yükü və ya yoxlama suması dəyişdirilmiş bir simvol

Ərizə sərhədindəki aliasları həll etmək və icazə, imzalanma, icazələr və audit qeydləri üçün geri qaytarılan kanonik I105 ID saxlamaq.

## API, saxlama və nümayiş qaydaları {#api-storage-and-display-rules}

- JSON hesab sahələrində dəqiq I105 UTF-8 simli göndərin.
- `Percent-encode` URL yolun bölməsinə yerləşdirilməzdən əvvəl tam hesabı ID.
- Heç vaxt I105 ID-ni hesab aliası ilə əvəz etməyin.
- Kodek tərəfindən qaytarılan kanonik silsilə `byte-preserving` müqayisə semantikası ilə saxlanılsın.
- Hərflərin böyük-kiçikliyini və simvol enini qoruyan kollasiyadan istifadə edin.
- Hesab məlumatları və yedekləmələri ilə silsilə ayırdçılığı və ya adı verilən şəbəkə profilini saxlayın.
- Bir ünvanı yalnız şəbəkə kontekstində yenidən istifadə edin.
- Tam ünvanı göstərin və bir nüsxə hərəkəti göstərin.
- Hər bir `kana` xarakterini dəqiq qoruyun.
- Kompakt ekranın orta hissəsini qısalaşdırdığı zaman tam ünvanı saxlayın.
- saxlanılan kanonik ID istifadə edin, əvəzinə bir alias-dan yenidən qurmaq.

`AccountId` ekranı və JSON təqdimatı kanonik I105-dən istifadə edir.

Aşağı səviyyəli `AccountAddress` ekran/JSON təmsilçiliyində daxili və düzəltmə kontekstləri üçün kanonik hexdən istifadə olunur.

Xarici hesab ID tələb olunduğu təqdirdə açıq `AccountAddress` I105 kodlayıcısını çağırın.

Hesabların yaradılması və alias həlli iş axınları üçün [Hesabalar və aliases ](/az/cookbook/accounts-and-aliases.md) ilə davam edin.

Hesab məlumatları modeli üçün [Hasibatlar](/az/blockchain/accounts.md)-yə baxın.
