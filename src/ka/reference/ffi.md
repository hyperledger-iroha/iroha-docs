# უცხო ფუნქციების ინტერფეისები (FFI) {#foreign-function-interfaces-ffi}

სააგენტო `iroha_ffi` ყუთი უზრუნველყოფს მაკროებს და თვისებებს C-ის წარმოქმნისთვის ABI
ვალდებულებები Rust APIs. გამოიყენება, როდესაც Iroha ტიპები უნდა გადაკვეთოს FFI
საზღვარი, მაგალითად: SDK ბმულები ან მასპინძელი ინტეგრაციები.

## რატომ? FFI {#why-ffi}

ფუნქცია საკმაოდ აბსტრაქტული ერთეულია და მიუხედავად იმისა, რომ უმეტეს ენები თანხმდებიან
რა უნდა გააკეთოს ფუნქცია, როგორ არის წარმოდგენილი ფუნქციები
ასევე, ზოგიერთ ენაზე, მაგალითად: Rust, შედეგები
ფუნქციის დარეკვისა და ის, რაც მას შეუძლია გააკეთოს ასევე არის
განსხვავებული. Rust APIs საჭიროა სხვა ენაზე დარეკვა
სხვადასხვა მასპინძელი გარემო, Iroha იყენებს უცხო ფუნქციის ინტერფეისს (FFI)
სათამაშო მოედნის გათანაბრებას.

დღეს გამოყენებული ძირითადი სტანდარტი არის C აპლიკაციის ბინარული ინტერფეისი.
მარტივი, ფართოდ ხელმისაწვდომი და სტაბილური.
ყველაფერი ხელით, მაგრამ Iroha უზრუნველყოფს `iroha_ffi` ყუთი, რომელიც უნდა წარმოქმნას
FFI-არსებული ფუნქციების შესაბამისობა Rust API.

რათქმაუნდა, შეგიძლია ეს შენი გზით გააკეთო. `iroha_ffi` ყუთი მხოლოდ
გენერირებს იმ კოდს, რომელიც თქვენ მაინც უნდა შექმნათ.
საჭირო ქოთნის ფირფიტა საკმაოდ დიდი სიფრთხილე და დისციპლინა მოითხოვს.
ყველა ფუნქციის მოწოდება FFI საზღვარი არის `unsafe` პოტენციურად
ჩვენ შევძელით მისი გადაჭრა,
ბრუნავს გამოყენებით **მყარი** `repr(C)` ტიპები.

::: info

ერთადერთი გამონაკლისი არის მანიშნებლები. ნულოვანი შემოწმება და სავალდებულო არ შეიძლება იყოს
მოქმედება მსოფლიო მასშტაბით, ასე რომ ნედლეული გამავლები (როგორც ყოველთვის) გამოიყენება მხოლოდ განსაკუთრებულ შემთხვევაში
ჩვენ ვაძლევთ ფურცლებს თითქმის ყველა შემთხვევაში
ობიექტი Iroha მონაცემთა მოდელი, თქვენ არ უნდა გამოიყენოთ ნედლეული მანიშნებლები
ყველა.

:::

## მაგალითი {#example}

აქ მოცემულია მაგალითი ბმულის წარმოქმნის შესახებ:

```rust
#[derive(FfiType)]
struct DaysSinceEquinox(u32);

#[ffi_export]
impl DaysSinceEquinox {
    pub fn update_value(&mut self, a: &u8) {
        self.0 = *a as u32;
    }
}
```

ზემოაღნიშნული მაგალითი გამოიწვევს შემდეგ კავშირს:
`DaysSinceEquinox` წარმოდგენილი როგორც არაგამჭვირვალე მანიშნავი:

```rust
pub extern fn DaysSinceEquinox__update_value(handle: *mut DaysSinceEquinox, a: *const u8) -> FfiReturn {
    // function implementation
}
```

## FFI დამაკავშირებელი თაობა {#ffi-binding-generation}

სააგენტო `iroha_ffi` კარადი გამოიყენება ფუნქციების წარმოქმნისთვის, რომლებიც შეიძლება გამოძახდეს
FFI. გაცემული `Rust` სტრუქტურები და მეთოდები, ისინი წარმოქმნიან `unsafe` კოდი, რომ
რპწბგა ეა დჲ გპვმვთქ, ჱა ეა ვეთვქ ჟრანთჟს.

ა Rust ტიპი გარდაიქმნება მყარი `repr(C)` ტიპი, რომელსაც შეუძლია გადაკვეთოს
FFI საზღვარი `FfiType::into_ffi`. ეს ხდება პირიქით, როგორც
აჰა. FFI `ReprC` ტიპი გარდაიქმნება `Rust` ტიპი
`FfiType::try_from_ffi`.

::: warning

აღინიშნება, რომ საპირისპირო კონვერტაცია არის შეცდომაში და შეიძლება გამოიწვიოს undefined
მიუხედავად იმისა, რომ ჩვენ შეგვიძლია მაქსიმალური ძალისხმევა გავაკეთოთ იმისთვის, რომ თავიდან ავიცილოთ ყველაზე აშკარა
შეცდომები, თქვენ უნდა უზრუნველყოს პროგრამის სწორი თქვენი მხრივ.

:::

The ძირითადი მახასიათებლები, რომლებიც საშუალებას იძლევა ბინდური წარმოება `ReprC`, `FfiType`, და
`FfiConvert`.

| ხასიათი        | აღწერა                                                                                                                                                                     |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ReprC`      | ეს თვისება წარმოადგენს მყარი ტიპს, რომელიც შეესაბამება C ABI. ტიპი შეიძლება უსაფრთხოდ გაზიარდეს FFI საზღვრები.                                                                |
| `FfiType`    | ეს თვისება განსაზღვრავს შესაბამის `ReprC` მოცემული ტიპისათვის `Rust` ტიპი. განსაზღვრული `ReprC` ტიპი გამოიყენება ნაცვლად `Rust` ტიპი API წარმოქმნილი FFI ფუნქცია. |
| `FfiConvert` | ეს თვისება განსაზღვრავს ორ მეთოდს `into_ffi` და `try_from_ffi` რომელიც გამოიყენება, რათა განახორციელოს კონვერტაცია `Rust` ტიპიდან ან მისკენ `ReprC` ტიპი.                                |

აღინიშნება, რომ არ არსებობს საკუთრების გადაცემა FFI გარდა არაგამჭვირვალე მანიშნელის
ყველა სხვა ტიპი, რომელიც საკუთრებაშია, მაგალითად: `Vec<T>`, არიან კლონირებული.

### სახელი Mangling {#name-mangling}

აღინიშნოს ორმაგი სათავეების გამოყენება გენერირებულ სახელებში FFI ობიექტები:

- სამინისტროში `inherent_fn` მეთოდი, რომელიც განსაზღვრულია `StructName` სტრუქტურა, FFI
  სახელი იქნება `StructName__inherent_fn`.
- სამინისტროში `MethodName` მეთოდიდან `TraitName` ხასიათი
  `StructName` სტრუქტურა, FFI სახელი იქნება
  `StructName__TraitName__MethodName`.
- დასახელება `field_name` სფეროში `StructName` სტრუქტურა, FFI
  ფუნქციის სახელი იქნება `StructName__set_field_name`.
- რომ მიიღოს `field_name` სფეროში `StructName` სტრუქტურა, FFI
  ფუნქციის სახელი იქნება `StructName__field_name`.
- რომ მიიღო მუტივალური `field_name` სფეროში `StructName` სტრუქტურა, FFI
  ფუნქციის სახელი იქნება `StrucuName__field_name_mut`.
- დამოუკიდებელი პირებისთვის `module_name::fn_name`, დასახელება FFI სახელი იქნება
  `module_name::__fn_name`.
- იმ თვისებებისათვის, რომლებიც არ არის გენერული და საშუალებას აძლევს გაზიაროს მათი
  განხორციელება FFI (იხ. `Clone` ქვემოთ), FFI სახელი იქნება
  `module_name::__clone`.

  ```rust
  impl Clone for Type1 {
      fn clone(&self) -> Self;
  }
  impl Clone for Type2 {
      fn clone(&self) -> Self;
  }
  ```
