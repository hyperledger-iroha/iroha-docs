# Norito {#norito}

Norito არის Iroha-ის კანონიკური სერიალიზაციის ფენა. ეს არის ბაიტების ფორმატი, რომელიც გამოიყენება მაშინ, როდესაც ქსელის კვანძები, SDKs, CLI ინსტრუმენტები, Torii, Kura და გენერირებული არტეფაქტები უნდა შეთანხმდნენ ზუსტად იმავე დატვირთვაზე .

გამოიყენეთ Norito, როდესაც მონაცემები შედის კონსენსუსის, ხელმოწერის, ჰეშინგის, მდგრადობის ან კროს-SDK ინტერპერაბილურობის ნაწილში. გამოიყენეთ JSON, როდესაც API საბოლოო წერტილი პირდაპირ გვთავაზობს ადამიანის მიერ წაკითხულ პროექციას ოპერატორებისთვის, დაშბორტებისთვის ან სწრაფი დებეგირებისათვის.

Norito არ არის ჭკვიანი ხელშეკრულების ენა. ეს არის დეტერმინისტური მონაცემთა კონტეინერი და კოდექი, რომელიც ატარებს ტრანზაქციებს, ხელშეკარგულებების ზარებს, ტექნიკურ მანიფესტებსა და API ტიპირებულ დატვირთვებს.

## დატვირთვის მოდელი {#payload-model}

პროტოკოლის გადაცემაში ან დისკზე Norito თითოეული დატვირთვის ჩარჩოში არის სათაური, რომელსაც მოჰყვება კოდირებული სასარგებლო დატვირთვის ბაიტები. სათაურის გარეშე ან შიშველი სასარგებლო ატვირთები რეზერვებულია შიდა ჰეშინგისთვის, სტანდარტებისათვის და დამხმარე APIs, რომელიც შედეგს ტრანსპორტირების წინ დაუყოვნებლივ ამოტვირთა სათაურში.

## განლაგების დროშები {#layout-flags}

Norito ინახავს განლაგების არჩევანს საბოლოო სათაურის ბაიტში. შერჩეული v1-ის დამხმარეები გამოყოფენ `COMPACT_LEN` (`0x02`) კომპაქტური ღირებულების სიგრძის პრეფიქსებისთვის. მუდმივი სიღრმის ფსიქიკური სიგრძის წინამდებარეები კვლავ კითხვად რჩება, როდესაც მოუწოდებლები კოდირებენ `flags = 0x00`.

|დროშა |ჰექსი |სტატუსი |ეფექტი |
| --- | ---: | --- | --- |
|`PACKED_SEQ` |`0x01` |მხარდაჭერა |კოდირება ცვლადი ზომის კოლექციები ოფსეტის ცხრილთან და თანმიმდევარი მონაცემთა ბლოკთან ერთად. |
|`COMPACT_LEN` |`0x02` |ნაგულისხმევი |თითოეული მნიშვნელობის სიგრძის პრეფიქსისთვის კანონიკურ უნიშნო varint-ებს იყენებს. |
|`PACKED_STRUCT` |`0x04` |მხარდაჭერა |კოდები გამომდინარე-გენერირებული სტრუქტურები როგორც შეფუთული ველის დატვირთვები. |
|`VARINT_OFFSETS` |`0x08` |რეზერვებული |გამორიცხულია v1; შეფუთული სიხშირის კომპენსაციები არის ფიქსირებული სიგანის `u64`. |
|`COMPACT_SEQ_LEN` |`0x10` |რეზერვებული |V1- ში უარყოფილია; უმაღლესი დონის რიგის სიგრძის სათაურები არის ფიქსირებული სიგანე `u64`. |
|`FIELD_BITSET` |`0x20` |მხარდაჭერა მოთხოვნებით |დაამატებს ბიტსეტს შეფუთული სტრუქტებისთვის, ასე რომ მხოლოდ ველები, რომლებიც საჭიროებენ მკაფიო ზომებს ატარებენ ზომის პრეფიქსებს. მოითხოვს `PACKED_STRUCT` და `COMPACT_LEN`. |

დროშები არის მკაფიო. დეკოდერები არ მიუთითებენ განლაგებას დატვირთვის ფორმიდან, უმნიშვნელო ვერსიიდან ან ჰეურისტებიდან. უცნობი ან უვნებელი კომბინაციების უარყოფა ხდება ისე, რომ ქსელის ყველა თანატოლი ინტერპრეტებს სასარგებლო დატვირთვას ერთნაირად .

## კოდირების წესები {#encoding-rules}

Norito იყენებს დეტერმინისტურ განლაგებებს მონაცემთა საერთო ფორმებისთვის, რომლებიც გამოჩნდება Iroha მონაცემთა მოდელში:

- მავთულხლართები არის `[len][utf8-bytes]`; `len` მოყვება `COMPACT_LEN`, როდესაც ჩართულია.
- როდესაც `COMPACT_LEN` არის განსაზღვრული, თითოეული მნიშვნელობის სიგრძე კომპაქტური ვარინტის გამოყენებით ხდება.
- როდესაც `COMPACT_LEN` არ არსებობს, თითოეული ღირებულების სიგრძე არის 8-ბაიტიანი პატარა ენდიანული `u64`.
- რიგითი სიგრძის სათაურები ფიქსირდება 8-ბაიტიანი მცირე ენდიან `u64` v1.
- `Vec<u8>` კოდირებულია როგორც `[len_u64][raw-bytes]` ერთ სიგრძის ნაცვლად ბაიტზე.
- შეფუთული თანმიმდევრობები იყენებენ `(len + 1)` მონოტონური `u64` კომპენსაციებს, რასაც მოჰყვება კონკატენირებული ელემენტის დატვირთვები.
- რუკაში ჩანაწერების დათვლის კოდირება ფიქსირებულია `u64` და გამოიყენება დეტერმინისტური საკვანძო რეჟიმი. `HashMap` ჩანაწერები განლაგებულია კოდირებამდე გასაღების მიხედვით; `BTreeMap` იყენებს მის ბუნებრივ რეჟიმს.
- `BigInt` იყენებს მცირე ზომის ორმაგი დანამატის ბაიტებს, რომელთა სიგრძე `u32` არის ბაიტი და 512-ბიტიანი საზღვერი.
- `Numeric` კოდირებულია როგორც `(mantissa, scale)`, სადაც mantissa ინახავს მთელი რიცხვის მნიშვნელობას და მასშტაბი ინახავს ფრაქციონალური ციფრების რაოდენობას.

ეს წესები მნიშვნელოვანია ხელმოწერებისა და კრიპტოგრაფიული ჰეშებისათვის. ორი SDKs რომელიც ქმნის იმავე ლოგიკურ ტრანზაქციას, უნდა წარმოადგინოს იგივე კანონიკური ბაიტები.

## სქემის კრიპტოგრაფიული ჰეშები {#schema-hashes}

ტიპირებული Norito დატვირთვები შეიცავს 16 ბაიტიან სქემას კრიპტოგრაფიულ ჰეშს სათაურში. დეფოლტური კრიპტოგრაფიული ჰეში არის მიღებული სრულად კვალიფიციური ტიპის სახელისგან. ნაგებობები, რომლებიც ხელს უწყობენ სტრუქტურული სქემის ჰეშინგს, მაგივრად იღებენ კრიპტოვრაფიულ ჰეშს კანონიკური სქემიდან.

ტიპირებული დეკოდერები უარყოფენ სქემის შეუსაბამობას. ეს იცავს კლიენტებს მცდარი Norito ჩარჩოს შეცდომით დეკოდირებისაგან, როგორც არასწორი ტიპის და არის ჩვეულებრივი უკმარისობის რეჟიმი, როდესაც SDK სატესტო არტეფაქტის ბუნდელი დრიფტობს კვანძის მონაცემთა მოდელიდან.

## შეკუმშვა და დაჩქარება {#compression-and-acceleration}

Norito მხარს უჭერს მკაფიო და ადაპტიური შეკუმშვას, ლოგიკური დატვირთვის შეცვლის გარეშე:

|მახასიათებელი |მიზანი |
| --- | --- |
|`to_bytes` |კოდირებული სათაური, რომელსაც მოჰყვება არასაკომპრესირებული დატვირთვა. |
| `to_compressed_bytes` | Zstd-ით კოდირება და შეკუმშვის ტეგის სათაურში ჩაწერა. |
|`to_bytes_auto` |გამოიყენეთ დეტერმინისტური ჰეურისტიკა, რათა გადაწყვიტოთ ღირს თუ არა კომპრესია. |
|CRC64 დაჩქარება |ყველგან გამოიყენება პორტატული CRC64-XZ, ხოლო ხელმისაწვდომობისას — CLMUL x86_64-ზე ან PMULL aarch64-ზე |
|GPU CRC64 და შეკუმშვა |ნებაყოფლობითი მეტალის ან CUDA დამხმარე შეიძლება დააჩქაროს დიდი დატვირთვები, შემდეგ კი დაეცემა უკან CPU გზებზე. |

აპარატურის დაჩქარება არასოდეს იცვლის დეკოდირებულ შინაარსს. CRC და JSON აჩქარებლები უნდა შეესაბამებოდეს პორტაბულ გამომავალი ბიტ-ბიტს. Zstd ჩარჩოს ბაიტები შეიძლება განსხვავდებოდეს CPU და GPU კოდირებს შორის, მაგრამ დეკოდებული დატვირთვისა და Norito სათაურის მეტადატანი რჩება დეტერმინისტური მოწმობისთვის.

## გამომდინარე მხარდაჭერა {#derive-support}

Rust მონაცემთა ტიპები, როგორც წესი, იყენებენ დერივულ მაკროებს და არა სახელმძღვანელო კოდეკის კოდს. დერივული ფენა შეიძლება წარმოქმნას Norito ორმაგი კოდეკები, სქემები და JSON დამხმარეები.

საერთო ველის ატრიბუტებია:

|ატრიბუტი |ეფექტი |
| --- | --- |
|`#[norito(rename = "other")]` |გამოიყენება სტაბილური სერიალიზებული სახელი სქემა და JSON თავსებადობისთვის. |
|`#[norito(skip)]` |კოდერი გამორიცხავს ველს. დეკოდერი მიაწოდებს მის `Default` მნიშვნელობას. |
|`#[norito(default)]` |გამოიყენება `Default`, როდესაც დეკოდირებული დატვირთვა არ ატარებს მინდორს |
|`#[norito(skip_serializing_if = "...")]` |გამორიცხავს ველებს JSON როდესაც პრედიკატი შეესაბამება, ხოლო შენარჩუნების დეტერმინისტური დეკოდირების დეფოლტები. |

დერივები ასევე გამოყოფენ კოდირებული სიგრძის მინიშნებებს და ზუსტი სიგრძის გამოთვლას, სადაც ეს შესაძლებელია. კოდერები იყენებენ ამ მინიშნებებს ბუფერების შესანახად და დამატებითი ასლების თავიდან ასაცილებლად.

## Torii და Norito RPC {#torii-and-norito-rpc}

Torii გამოყოფს JSON მრავალი ოპერატორის მარშრუტისათვის, მაგრამ ტიპირებული ორმაგი მარშრუტები იყენებენ Norito. მიმდინარე ტიპის Norito HTTP სხეულებისათვის მედია ტიპი არის `application/x-norito`.

გამოიყენეთ ეს სათაურები, როდესაც API საბოლოო წერტილი იღებს ან აღნიშნავს Norito:

```http
Content-Type: application/x-norito
Accept: application/x-norito
```

როდესაც API საბოლოო წერტილი მხარს უჭერს ორივე წარმოდგენას, კლიენტებს შეუძლიათ გამოაგზავნონ მკაფიო პრეფერენციების ჩამონათვალი:

```http
Accept: application/x-norito, application/json
```

დეკოდირების ჩავარდნა გამოჩნდება როგორც Torii ტიპირებული შეცდომები და ითვლება ტელემეტრიით. გავრცელებულ მიზეზებს შორის არიან არასწორი ჯადოსნობა, დაუჭერელი ვერსია, მხარს არ უჭერს მახასიათებლების დროშა, შეამოწმებელი რაოდენობის შეუსაბამობა, არასწორად ჩამოყალიბებული UTF-8, არასწორი enum ტეგი და სქემის შეუსაბამო.

Norito RPC ტრანსპორტი შეირჩევა ტრანსპორტის კონფიგურაციის საშუალებით. ოპერატორის დაშბორდებმა უნდა აკონტროლონ მოთხოვნის დაგვიანება, ჩავარდნები, აქტიური კავშირები, პასუხის ბიტები და `torii_norito_decode_failures_total` ცალკე JSON ტრაფიკიდან.

## საოპერაციო მიმართულებები {#operational-guidance}

- SDK მშენებლები და წარმოქმნილი ბმულები ხელნაკეთი დამზადებული Norito ბიტების ნაცვლად.
- განიხილეთ სქემის შეუსაბამობა როგორც ვერსია ან ტესტის არტეფაქტის პრობლემა, და არა როგორც გარდამავალი ქსელის უკმარისობა.
- არქივი `.nrt`, `.norito` და ტექნიკური მანიფესტის არტეფაქტები გამოშვების ან ინციდენტების ბუნდელში, რომლებმაც ისინი შექმნეს.
- გამოიყენეთ Norito როგორც სიმართლის წყარო ხელმოწერილი, ჰეშირებული ან შეჩერებული მონაცემებისთვის. გამოიყენეთ პროექციები JSON დაშბორდებისა და სახელმძღვანელო ინსპექტირებისათვის.
- ახალი ტიპირებული Torii API საბოლოო წერტილის დამატებისას, დოკუმენტაცია იმის შესახებ, მიიღებს თუ არა ის JSON, Norito ან ორივე, და გამოაქვეყნეთ მხარდაჭერილი შინაარსის ტიპი `/openapi.json`.
- სანამ აჩქარებელი გააქტიურებთ, შეამოწმეთ პარიტეტის ტესტები სკალარული გამომუშავების წინააღმდეგ. თუ აჩქარო ვერ გამოვა, გამოიყენეთ დეტერმინისტური სკალარული ჩავარდნა. სასარგებლო დატვირთვის სემანტიკა უნდა დარჩეს უცვლელი.
