# `iroha3d` CLI {#iroha3d-cli}

`iroha3d` არის Iroha 3-ის ქსელის კვანძის სტანდარტული დემონი. Cargo პაკეტს `irohad` ეწოდება, ამიტომ წყაროს კოდის სამუშაო ასლიდან ბინარული ფაილი ასე გაუშვით:

```shell
cargo run -p irohad --bin iroha3d -- --config path/to/config.toml
```

საჯარო Taira სატესტო ქსელისთვის გამოშვების გამოსახულება იყენებს `iroha3d_taira`-ს. ის იმავე CLI-ს იღებს, მაგრამ დამატებით კანონიკურ Taira ჯაჭვს, ვალიდატორის, საცავისა და შესრულების გარემოს ხელმომწერის პროფილს აღასრულებს. Taira-ს კონფიგურაცია შესრულების გარემოს ავტორიზაციის მონაცემების გახსნის გარეშე ასე შეამოწმეთ:

```shell
iroha3d_taira --sora \
  --config /etc/iroha/taira/config.toml \
  --check-config
```

გამოიყენეთ კანონიკური Taira პროფილის ოპერატორის მიერ შევსებული ფორმა; რეპოზიტორიაში არსებული შაბლონი კვლავ შეიცავს განთავსების შემავსებლებს. Taira-ზე ტესტირებისას ის არ ჩაანაცვლოთ ზოგადი SORA Nexus ან საწარმოო SoraFS პარამეტრებით.

## `--config` {#arg-config}

- ტიპი: ფაილის გზა
- ალიასი: `-c`

გზა [ქსელის კვანძული კონფიგურაცია](/ka/reference/peer-config/index.md).

## `--genesis-manifest-json` {#arg-genesis-manifest-json}

- ტიპი: ფაილის გზა

არაკომპანიური ბლოკჩეინის გენეზის ტექნიკური მანიფესტი JSON, რომელიც გამოიყენება კონსენსუსის ვალიდაციისათვის.

## `--check-config` {#arg-check-config}

შეამოწმეთ გადაჭრილი კონფიგურაცია და ხელმისაწვდომი ბლოკჩეინის გენეზისის მასალა, შემდეგ გამოდით ქსელის სოქეტების გარეშე.

## `--json` {#arg-json}

- **ტიპი:** ალამი
- **მოითხოვს:** `--check-config`

ამ აწყობისა და კონფიგურაციის თავსებადობის მნიშვნელობები დაბეჭდეთ ერთ Norito JSON ობიექტად, `Ready` ან `Pending` ხაზის ნაცვლად.

## `--check-storage` {#arg-check-storage}

- **ტიპი:** ალამი
- **კონფლიქტი:** `--check-config`

ამ აწყობის დეკოდერებით მხოლოდ წაკითხვის რეჟიმში შეამოწმეთ გაჩერებული კვანძის Kura საცავი და უახლესი მდგომარეობის ასლი, შედეგი დაბეჭდეთ ერთ Norito JSON ობიექტად და წარუმატებლობისას დაასრულეთ არანულოვანი კოდით. შემოწმება იღებს Kura საცავის ფესვის ბლოკირებას, ამიტომ უარყოფს საცავს, რომელსაც გაშვებული კვანძი ფლობს. იგი საცავს არასოდეს ცვლის და მხოლოდ შესრულების დროს გამოყენებულ საიდუმლოებებს არ ხსნის.

## `--check-replay` {#arg-check-replay}

- **ტიპი:** ალამი
- **კონფლიქტი:** `--check-config`, `--check-storage`

ამ აწყობით ხელახლა შეასრულეთ გაჩერებული კვანძის საცავის ასლი და შედეგი დაბეჭდეთ ერთ Norito JSON ობიექტად. ბრძანება ბლოკებს დროებით დირექტორიაში აკოპირებს, იქ აღადგენს უახლეს მდგომარეობის ასლს ან ხელახლა ასრულებს ხელმოწერილ გენეზისს და ყველა შემდგომ ბლოკს თავიდან ასრულებს. თუ ბლოკი სერტიფიცირებულ შედეგს ვერ იმეორებს ან საჭირო სხეული აკლია, ის არანულოვანი კოდით სრულდება; თავდაპირველ საცავში არ წერს და მხოლოდ შესრულების დროის საიდუმლოებებს არ ხსნის.

## `--require-genesis-inrou-deployment-authority` {#arg-require-genesis-inrou-deployment-authority}

- **ტიპი:** ანგარიშის ID
- **მოითხოვს:** `--check-config`

ოფლაინ შემოწმებისას მოითხოვეთ, რომ ამ რეგისტრირებულ ანგარიშს ზუსტი ხელმოწერილი გენეზისის შესრულების შემდეგ SoraCloud განთავსების უფლებამოსილება შეუნარჩუნდეს.

## `--sumeragi-assert-fresh-key` {#arg-sumeragi-assert-fresh-key}

- **ტიპი:** ალამი

მხოლოდ ამ გაშვებისთვის განაცხადეთ, რომ კვანძის კონსენსუსის გასაღებებს ამ ჯაჭვისთვის არასოდეს მოუწერიათ ხელი. Sumeragi თითო გასაღებისთვის უსაფრთხოების ჩანაწერს ინახავს და მის გარეშე არაფერს აწერს ხელს, სანამ არ ექნება მტკიცებულება, რომ ჩანაწერი არ დაკარგულა. ეს ალამი ერთხელ, ახალი გასაღების პირველი გაშვებისას გამოიყენეთ და არასოდეს გამოიყენოთ მონაცემთა დაკარგვის შემდეგ.

## `--trace-config` {#arg-trace-config}

- ტიპი: დროშა
- გარემო: `TRACE_CONFIG`

გააქტიურეთ ტრეის ლოგები კონფიგურაციის ფენების წაკითხვისა და ანალიზის დროს.

## `--config-blake3` {#arg-config-blake3}

- ტიპი: 64 ციფრიანი თექვსმეტობითი BLAKE3 კრიპტოგრაფიული დიჯესტი.
- მოთხოვნები: `--config`

მოითხოვეთ კონფიგურაციის ფაილის ბაიტების შეხება მიწოდებული კრიპტოგრაფიულ დიჯესტს. ინტეგრითი დამაკავშირებელი ფაილი უნდა იყოს დაბლა; მასში არ შეიძლება იყოს `extends`.

## `--terminal-colors` {#arg-terminal-colors}

- ტიპი: ბულიანი, წარდგენილი როგორც `--terminal-colors=true` ან `--terminal-colors=false`
- ავარიული: ტერმინალის შესაძლებლობის გამოვლენა
- გარემო: `TERMINAL_COLORS`

კონტროლი ANSI ფერის გამონადენი.

## `--language` {#arg-language}

- ტიპი: ხაზი

დემონის შეტყობინებებისთვის გამოყენებული სისტემური ენის გადაფარვა.

## `--sora` {#arg-sora}

- ტიპი: დროშა
- გარემო: `IROHA_SORA_PROFILE`

ჩართეთ SORA Nexus პროფილი, რომელსაც SoraFS, SoraNet ხელის ჩამორთმევა და მრავალარხიანი კონსენსუსი იყენებს. Taira გამშვები ყოველთვის ამ ალმით იძახება.

## FastPQ სათადარიგოები {#fastpq-overrides}

`--fastpq-execution-mode <MODE>` და `--fastpq-poseidon-mode <MODE>` იღებენ მხოლოდ `cpu` ან `gpu`. დანარჩენი ვარიანტები უპირატესობას ანიჭებს ტელემეტრიის ეტიკეტებს:

- `--fastpq-device-class <LABEL>`
- `--fastpq-chip-family <LABEL>`
- `--fastpq-gpu-kind <LABEL>`

მაგალითად:

```shell
iroha3d --fastpq-execution-mode gpu \
  --fastpq-poseidon-mode cpu \
  --fastpq-device-class apple-m4 \
  --fastpq-chip-family m4 \
  --fastpq-gpu-kind integrated
```

## გენერირებული დახმარება {#generated-help}

ზემოთ მოცემული პარამეტრების შეჯამება ფიქსირებულ Iroha commit-ში `iroha3d` არგუმენტების განსაზღვრებებს მიჰყვება. თქვენი სამუშაო ასლის ზუსტი დახმარებისთვის გაუშვით:

```shell
cargo run --locked -p irohad --bin iroha3d -- --help
```
