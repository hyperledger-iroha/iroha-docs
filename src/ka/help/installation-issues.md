# ინსტალაციის პრობლემების აღმოფხვრა {#troubleshooting-installation-issues}

ამ განყოფილებაში მოცემულია პრობლემების აღმოფხვრის რჩევები Iroha 3 დამონტაჟება. თუ
პრობლემა, რომელსაც თქვენ განიცდით, აქ არ არის აღწერილი.
დაგვიკავშირდით მეშვეობით [ტელეგრამი](https://t.me/hyperledgeriroha).

## სწრაფი შემოწმებები {#quick-checks}

დამონტაჟების უმეტესობა მოდის ოთხი ადგილიდან:

- ბ) Rust ინსტრუმენტების ჯაჭვი უფრო ძველია ვიდრე ვერსია, რომელიც ჩაკეტილია სამუშაო სივრცეში
- `cargo` ან `rustc` სხვა დანადგარზე გადასასვლელი `rustup`
- დაკარგული სისტემის შექმნის ინსტრუმენტები, როგორიცაა C კომპილერი, `pkg-config`, ან CMake
- ძველად წარმოქმნილი ნაწყვეტები ან ადგილობრივი მშენებლობის არტეფაქტები წყაროს შეცვლის შემდეგ
  რევიზიები

სააგენტოდან Iroha საწყისი გადახდა, დაიწყეთ:

```bash
rustup show
cargo --version
rustc --version
cargo metadata --no-deps
```

თუ: `cargo metadata` ჩავარდება, გამოსწორება ადგილობრივი ინსტრუმენტების ჯაჭვი სანამ გაშვება
`pnpm refresh:iroha --source /path/to/iroha`, რადგან განახლება შეიძლება გამოიწვიოს
Kagami მონაცემთა მოდელის ამჟამინდელი სქემის შექმნა.

## პრობლემების აღმოფხვრა Rust ინსტრუმენტების ჯაჭვი {#troubleshooting-rust-toolchain}

ხანდახან ყველაფერი არ მიდის ისე, როგორც დაგეგმილი იყო. `rust` თქვენი
სისტემა ცოტა ხნის წინ, მაგრამ არ განახლდა. მსგავსი პრობლემა შეიძლება მოხდეს
Python: XKCD აქვს ცნობილი მაგალითი, თუ როგორ შეიძლება გამოიყურებოდეს ეს:

### შეამოწმეთ Rust ვერსია {#check-rust-version}

ჱაღჲრჲ ვ ოჲჟლვევ ნა თგჲ£სა და ნა ჟსალთნთწ, ეყნეთ ჟთდსპნჲ, ფვ
აქვს სწორი ვერსია `cargo` შეკრული სწორი ვერსიით `rustc`.
ამჟამინდელი სამუშაო სივრცე `rust-version = "1.92"` და pin the
ინსტრუმენტების ჯაჭვის არხი `rust-toolchain.toml`. იმისათვის, რომ აჩვენოთ ვერსიები, გააკეთეთ

```bash
$ cargo -V
$ cargo 1.93.1 (...)
```

და შემდეგ

```bash
$ rustc --version
$ rustc 1.93.1 (...)
```

თუ თქვენ გაქვთ უფრო მაღალი ვერსიები, კარგად ხართ. თუ თქვენ გაქვთ დაბალი ვერსია,
შეუძლია გაუშვას შემდეგი ბრძანება მისი განახლებისთვის:

```bash
$ rustup toolchain update stable
```

### შეამოწმეთ დამონტაჟების ადგილი {#check-installation-location}

თუ თქვენ მიიღებთ უფრო დაბალ ვერსია ნომრები **და** თქვენ განახლდა ინსტრუმენტების ჯაჭვი და ის
არ მოქმედებდა... ვთქვათ, რომ ეს საერთო პრობლემაა, მაგრამ მას არ აქვს
საერთო გამოსავალი.

პირველ რიგში, უნდა დაადგინოთ სად არის ვერსია, რომელსაც გსურთ გამოიყენოთ
დამონტაჟებული:

```bash
$ rustup which rustc
$ rustup which cargo
```

ინსტრუმენტების ჯაჭვების მომხმარებელთა ინსტალაციები _ჩვეულებრივ_ დაწვრილებით
`~/.rustup/toolchains/stable-*/bin/`. თუ ეს ასეა, თქვენ უნდა იყოთ
მოქცევა

```bash
$ rustup toolchain update stable
```

და ეს უნდა მოაგვაროს თქვენს პრობლემებს.

### შეამოწმეთ დეფოლტი Rust ვერსია {#check-the-default-rust-version}

კიდევ ერთი ვარიანტი არის, რომ თქვენ გაქვთ up-to-date `stable` ინსტრუმენტების ქსელი, მაგრამ ეს
არ არის განსაზღვრული როგორც გათვალისწინებული.

```bash
$ rustup default stable
```

ეს შეიძლება მოხდეს, თუ თქვენ დააყენეთ `nightly` ვერსია, ან დაყენება კონკრეტული
Rust ვრჟჲნარა, ნჲ რპწბგა ეა დჲ ჲრთევამ.

### შეამოწმეთ, არის თუ არა სხვა Rust ვერსიები {#check-if-there-are-other-rust-versions}

დავრჩებით დევნილთა ხვრელიდან, რომ ჩავარდნოთ, ჩვენ შეიძლება გვქონდეს ქარხანა
სათაურები:

```bash
$ type rustc
$ type cargo
```

თუ ეს მიუთითებს სხვა ადგილებზე, ვიდრე ის, რომელიც თქვენ ნახეთ გაშვებისას
`rustup which *`, მაშინ თქვენ გაქვთ პრობლემა. გაითვალისწინეთ, რომ ეს არ არის საკმარისი
უბრალოდ

```bash
$ alias rustc "~/.rustup/toolchains/stable-*/bin/rustc"
$ alias cargo "~/.rustup/toolchains/stable-*/bin/cargo"
```

რადგან არსებობს შიდა ლოგიკა, რომელიც შეიძლება გატეხილი იყოს, მიუხედავად იმისა, თუ როგორ
რევოლუციონირეთ თქვენი საიდუმლოები.

ყველაზე მარტივი გამოსავალი იქნება, რომ ამოიღოთ ვერსიები, რომლებიც არ გამოიყენებთ.

ეს უფრო ადვილია. _თქვა_ ვიდრე _დამთავრებული_, თუმცა, რადგან ეს მოითხოვს ყველა
ვერსიები rustup ჩვეულებრივ, არსებობს მხოლოდ
მეორე: სისტემის პაკეტების მენეჯერის ვერსია და ის, რომელიც ინსტალირდა
სტანდარტული ადგილმდებარეობა თქვენს სახლში საქაღალდეში, როდესაც თქვენ ამოქმედდა ბრძანება
ამ მასწავლებლის დასაწყისში. პირველისთვის, შეამოწმეთ თქვენი (Linux)
განაწილების სახელმძღვანელო (`apt remove rust`). ამ უკანასკნელისათვის, გაუშვით:

```bash
$ rustup toolchain list
```

და შემდეგ, თითოეული `<toolchain>` (რა თქმა უნდა, კუთხის ბრეკეტების გარეშე):

```bash
$ rustup remove <toolchain>
```

ამის შემდგომ, დარწმუნდით, რომ

```bash
$ cargo --help
```

შედეგია ბრძანება არ არის ნაპოვნი შეცდომა, ანუ რომ თქვენ არ გაქვთ აქტიური Rust
ინსტრუმენტების ჯაჭვი დამონტაჟებულია. შემდეგ, გაუშვით:

```bash
$ rustup toolchain install stable
```

## პრობლემების აღმოფხვრა Python ინსტრუმენტების ჯაჭვი {#troubleshooting-python-toolchain}

როდესაც დააყენებთ Python ბორბლების შეფუთვა, რომელიც გამოიყენება მილის დროს [Python კლიენტის კონფიგურაცია](/ka/guide/tutorials/python.md), თქვენ შეიძლება შეხვდეთ შეცდომას, როგორიცაა:
"იროჰა_პიტონი...*.whl არ არის მხარდაჭერილი ბორბალი ამ პლატფორმაზე".

ეს შეცდომა ნიშნავს, რომ pip არის მოძველებული, ასე რომ თქვენ უნდა განახლდეს იგი.
პირველ რიგში, რეკომენდებულია შეამოწმოთ თქვენი OS განახლებებისათვის და სისტემის განახლებისათვის.

თუ ეს არ მუშაობს, შეგიძლიათ შეეცადოთ განახლება `pip` თქვენი მომხმარებლის დირექტორისთვის.

`python -m pip install --upgrade pip`

დარწმუნდით, რომ `pip` ეს არის დამონტაჟებული თქვენს სახლის დირექტორში. `whereis pip` და შეამოწმეთ, თუ `/home/username/.local/bin/pip` თუ არა, განახლება თქვენი ქარხანა `PATH` ცვლადი.

თუ პრობლემა გრძელდება, გთხოვთ [დაგვიკავშირდით](/ka/help/) და შეატყობინეთ შედეგები.

```
python --version
python3 --version
pip --version
pip3 --version
```
