# პრობლემების აღმოფხვრა განთავსების საკითხებში {#troubleshooting-deployment-issues}

ამ განყოფილებაში მოცემულია პრობლემების აღმოფხვრის რჩევები Iroha 3 განლაგება. თუ პრობლემა
რაც თქვენ განიცდით, აქ არ არის აღწერილი.
დაგვიკავშირდით მეშვეობით [ტელეგრამი](https://t.me/hyperledgeriroha).

## დაიწყეთ შექმნილი არტეფაქტებით {#start-with-generated-artifacts}

ადგილობრივი და სატესტო დანერგვისთვის, უპირატესობა უნდა ჰქონდეს არტეფაქტებს, რომლებიც წარმოქმნილია Kagami სამაგიეროდ
ხელით დაწერილი თანატოლური ფაილების:

```bash
cargo run --bin kagami -- localnet --build-line iroha3 --peers 4 --out-dir ./localnet
```

გენერირებული დირექტორი შეიცავს თანატოლების კონფიგურაციას, გენეზის მასალას, დასაწყისს
სცენარები, და a README სამინისტრო Iroha 3 ნაშენები ხაზი.

## პერ არ იწყება {#peer-does-not-start}

უპირველეს ყოვლისა, შეამოწმეთ ეს ნივთები:

- `irohad --config <path>` ქულები თანატოლების საკუთარ TOML ფაილი.
- `public_key` და `private_key` თანატოლთა კონფიგურაციაში ერთნაირ გასაღებს ეკუთვნებიან
  ორმაგი.
- `genesis.public_key` ეწევა გენეზიის ტრანზაქციისთვის გამოყენებულ გასაღებს.
- დამტკიცებელი თანატოლთა იდენტობის გამოყენება BLS- ნორმალური გასაღები და `trusted_peers_pop`
  შეიცავს ადგილობრივი გასაღების და სანდო თანამოაზრეების მტკიცებულებების მითითებებს.
- პორტები Torii და P2P არ არის უკვე დაკავშირებული სხვა პროცესით.
- დასახელება Kura მაღაზიების დირექტორი ეკუთვნის იმავე ქსელს და არ არის გადაწერილი
  სხვადასხვა ქსელის პროფილი.

გამოიყენეთ კონფიგურაციის თვალსაზრისი, როდესაც daemon კითხულობს მეტი ერთი TOML ფენა:

```bash
cargo run --bin irohad -- --config ./config.toml --trace-config
```

## Docker და შედგება {#docker-and-compose}

გენერირება შედგეს მიმდინარედან Kagami localnet output ასე რომ ბრძანების ხაზი
არგუმენტები და კონფიგურაციული ფაილები შეესაბამება გამოწერილ კოდს:

```bash
cargo run --bin kagami -- localnet --build-line iroha3 --peers 4 --out-dir ./localnet
cargo run --bin kagami -- docker --peers 4 --config-dir ./localnet --image hyperledger/iroha:dev --out-file ./localnet/docker-compose.yml --force
docker compose -f ./localnet/docker-compose.yml up
```

თუ კომპოსის განთავსება იწყება და შემდეგ შეჩერდება, შეამოწმეთ დეიმონის ლოგები:

- არათანაბარი `chain`
- ერთი თანამოაზრე, რომელიც იყენებს განსხვავებულ გენეზის ტრანზაქციას ან მანიფესტს
- რეკლამა P2P მისამართები, რომლებიც მხოლოდ კონტეინერის ქსელში მუშაობს
- ადგილობრივი მოცულობის განმეორებითი გამოყენება გენეზის რეგენერაციის შემდეგ

როდესაც ახალი გენეზის ტესტირება, ამოიღეთ ძველი Kura მოცულობა განახლების წინ
ძველი ბლოკების შენახვა ახალი გენეზის საშუალებით შეცვლის რეპლეი-ს.

## კუბერნეტები {#kubernetes}

Kubernetes- ისთვის, თითოეული ვალიდატორი განიხილეთ როგორც სახელმწიფოებრივი ინფრასტრუქტურა:

- აძლევს თითოეულ თანატოლს სტაბილური იდენტობის გასაღები და სტაბილურ მუდმივ მოცულობას
- გამოხატვა P2P მისამართები, რომლებიც სხვა თანატოლებს შეუძლიათ გადაწყვიტონ კლასტერის შიგნით
- დაყენება კონფიგურაცია და genesis ფაილები როგორც შეუცვლელი კონფიგურა განხორციელებისათვის
- ყველა გენეზის ან ტოპოლოგიის ცვლილების განზრახ განხორციელება, არა როგორც ავტომატური
  კონფიგურაციის რუკის განახლება

თუ კაბა განმეორებით იწყება, შეადარეთ კაბაში წარმოდგენილი კონფიგურაცია
მოსალოდნელი [`peer.template.toml`](/ka/reference/peer-config/index.md#template) და
შეამოწმეთ, განა პარტნიორი ძველს ასრულებს? Kura მონაცემები.

## Sora- ს პროფილი {#sora-profile}

Iroha 3 განთავსება, რომელიც იყენებს Nexus, SoraFS, ან უნდა დაიწყოს მრავალგზის ნაკადები
სორას პროფილის მქონე დეიმონი:

```bash
cargo run --bin irohad -- --config ./config.toml --sora
```

გამოიყენეთ იგივე პროფილი ერთ ქსელში მუდმივად.
