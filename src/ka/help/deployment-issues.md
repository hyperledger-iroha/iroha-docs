# პრობლემების გადაჭრა განთავსების საკითხებში {#troubleshooting-deployment-issues}

ამ განყოფილებაში მოცემულია პრობლემების მოგვარების რჩევები Iroha 3 დანერგვისთვის. თუ პრობლემა არ არის აღწერილი აქ, დაგვიკავშირდით ტელეფონით [ტელეგრამი](https://t.me/hyperledgeriroha).

## დაიწყეთ შექმნილი არტეფაქტებით. {#start-with-generated-artifacts}

ადგილობრივი და სატესტო დანერგვისთვის, სასურველია Kagami-ის მიერ შექმნილი არტეფაქტები ხელით დაწერილი ქსელური თანასწორი ფაილების ნაცვლად:

```bash
cargo run --bin kagami -- localnet --peers 4 --out-dir ./localnet
```

გენერირებული დირექტორია შეიცავს ქსელის კვანძების კონფიგურაციას, ბლოკჩეინის წარმოქმნის მასალას, საწყისი სცენარებს და README Iroha 3 მშენებლობის ხაზისთვის.

## ქსელის კვანძი არ იშვება {#peer-does-not-start}

პირველ რიგში, შეამოწმეთ ეს ნივთები:

- `iroha3d --config <path>` წერტილები ქსელის კვანძის საკუთარი ფაილში TOML.
- `public_key` და `private_key` ქსელის კვანძების კონფიგურაციაში ერთნაირ საკვანძო წყვილს ეკუთვნებიან.
- `genesis.public_key` შეესაბამება გასაღებს, რომელიც გამოყენებულია ბლოკჩეინის გენეზის ტრანზაქციის ხელმოწერისთვის.
- ვალიდატორების ქსელის კვანძთა იდენტობები იყენებენ BLS-ნორმალურ საკიდებს, ხოლო `trusted_peers_pop` შეიცავს ადგილობრივი საკიდისა და ნდობლივი ქსელური პარტნიორის საკუთრების მტკიცებულების მითითებებს.
- Torii და P2P პორტები ჯერ კიდევ არ არიან დაკავშირებულნი სხვა პროცესით.
- Kura მაღაზიების დირექტორი ერთსა და იმავე ქსელს ეკუთვნის და სხვა ქსელური პროფილისგან არ არის გაფორმებული.

გამოიყენეთ კონფიგურაციის თვალსაზრისი, როდესაც დეიმონი კითხულობს ერთზე მეტ TOML ფენას:

```bash
cargo run -p irohad --bin iroha3d -- --config ./config.toml --trace-config
```

## Docker და კომპოზიტი {#docker-and-compose}

Docker-ში ერთი და იმავე რევიზიის ბინარული ფაილებით ოთხი ვალიდატორის ასაწყობად და გასაშვებად მიჰყევით სახელმძღვანელოს [გაშვება Iroha 3](/ka/get-started/launch-iroha.md).

ვალიდატორების ჟურნალების სანახავად ნაკრების საქაღალდიდან გაუშვით `python3 poc.py logs`.

თუ კომპოზიციის განთავსება იწყება და შემდეგ ჩერდება, შეამოწმეთ დეიმონების ლოგები:

- არათანაბარი `chain`
- ერთ-ერთი კვანძი განსხვავებულ გენეზისის ტრანზაქციას ან მანიფესტს იყენებს
- რეკლამირებული P2P მისამართები, რომლებიც მუშაობს მხოლოდ კონტეინერების ქსელში
- ადგილობრივი მოცულობის განმეორებითი გამოყენება ბლოკჩეინის გენეზისი რეგენერაციის შემდეგ

ახალი გენეზისის ბლოკისთვის კვანძის საცავი ცარიელი უნდა იყოს. იმავე ქსელის ხელახლა გასაშვებად გამოიყენეთ `python3 poc.py down` და შემდეგ `python3 poc.py up`. შეინახეთ `state/` მის ოთხ Docker ტომთან ერთად.

## კუბერნეტები {#kubernetes}

Kubernetes- ისთვის, თითოეული ვალიდატორი განიხილეთ როგორც სახელმწიფოებრივი ინფრასტრუქტურა:

- მიეცით თითოეულ ქსელის კვანძს სტაბილური იდენტობის გასაღები და სტაბილურ მუდმივ მოცულობას.
- გამოავლინოს P2P მისამართები, რომლებიც სხვა ქსელის კვანძებს შეუძლიათ გადაწყვიტონ კლასტერის შიგნით.
- დაყენება კონფიგურაცია და ბლოკჩეინის გენეზისი ფაილები როგორც შეუცვლელი კონფიგურა განხორციელებისთვის
- გენეზისისა და ტოპოლოგიის ყველა ცვლილება განზრახ დანერგეთ და არა კონფიგურაციის რუკის ავტომატური განახლების სახით

თუ კადრი განმეორებით იწყება, შეადარეთ კადრში წარმოდგენილი კონფიგურაცია მოსალოდნელით [`peer.template.toml`](/ka/reference/peer-config/index.md#template) და შეამოწმეთ, თუ არა ქსელის კვანძები ძველი თამაშობს Kura მონაცემები.

## Sora- ს პროფილი {#sora-profile}

კერძო ან ადგილობრივი Iroha 3 განთავსებისათვის, რომლებიც იყენებენ Nexus, SoraFS ან მრავალგზის ნაკადებს, უნდა დაიწყოს სტანდარტული დეიმონი Sora-ის პროფილის ჩართულობით:

```bash
cargo run -p irohad --bin iroha3d -- --config ./config.toml --sora
```

გამოიყენეთ იგივე პროფილი მუდმივად ერთი და იმავე ქსელში არსებული ვალიდატორების შორის.

საჯარო Taira ვალიდატორები იყენებენ განკუთვნილ გამშვებელს, რომელიც აამოქმედებს Taira-ის ზუსტ ჯაჭვს, სიაში, შეზღუდულია ჩაშენებული შენახვა-SoraFS და მიმდინარეობის დროის ხელმოწერის პროფილი. გააძლიერეთ წარმოჩენილი Taira კონფიგურაცია მისი დაწყებამდე:

```bash
iroha3d_taira --sora \
  --config /etc/iroha/taira/config.toml \
  --check-config
```

ნუ დაიწყებთ საზოგადოებას Taira ვალიდატორი ზოგადი საშუალებით `iroha3d`; იხილეთ [`iroha3d` CLI რეფერენცია](/ka/reference/iroha3d-cli.md) დაწესებულების პროფილისთვის.
