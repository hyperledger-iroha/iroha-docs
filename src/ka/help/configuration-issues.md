# კონფიგურაციის პრობლემების აღმოფხვრა {#troubleshooting-configuration-issues}

ამ განყოფილებაში მოცემულია პრობლემების აღმოფხვრის რჩევები Iroha 3 კონფიგურაცია. დარწმუნდით რომ თქვენ
[შეამოწმე გასაღები](./overview.md#check-the-keys) პირველ რიგში, როგორც ყველაზე
საკითხების საერთო წყარო Iroha.

თუ პრობლემა, რომელსაც განიცდი, აქ არ არის აღწერილი, დაგვიკავშირდით
[ტელეგრამი](https://t.me/hyperledgeriroha).

## მოძველებული გენეზი Docker Compose დაყენება {#outdated-genesis-on-a-docker-compose-setup}

როდესაც თქვენ იყენებთ Docker Compose ვერსია Iroha, თქვენ შეიძლება შეხვდეთ
ერთ-ერთი თანაბარი კონტეინერის გამოშვება
`Failed to deserialize raw genesis block` შეცდომა. ეს ჩვეულებრივ ნიშნავს თანატოლს,
გაფორმებული გენეზიის ტრანზაქცია და წარმოქმნილი კონფიგურაცია
განსხვავებული Iroha რევიზიები ან პროფილები.

შეამოწმეთ წარუმატებლობა ამ ნაბიჯებით:

1. გამოყენება `docker ps` შეამოწმეთ მიმდინარე კონტეინერები.
   წარმოქმნილი პროფილი, თქვენ ჩვეულებრივ ნახავთ `hyperledger/iroha:dev`
   კონტეინერები. Docker Compose პროფილი შეიცავს ოთხ თანატოლს
   კონტეინერები, მიუხედავად იმისა, რომ თქვენი წარმოებული `docker-compose.yml` შეიძლება განსხვავდებოდეს.

2. შეამოწმეთ დღიურები და ეძებეთ
   `Failed to deserialize raw genesis block` შეცდომა. თუ თქვენ დაიწყოთ თქვენი
   Iroha დაემონის რეჟიმში `docker compose up -d`, გამოყენება
   `docker compose logs` ოპვრთნარაჲ.

ამ პრობლემის გადაჭრის გზა დამოკიდებულია Iroha. თუ ეს არის
ძირითადი დემო და თქვენ არ უნდა შეინარჩუნოთ თანატოლების მონაცემები, რეგენერირება მატჩი
ადგილობრივი ქსელი ან Docker Compose ბუნდი Kagami:

```bash
cargo run --bin kagami -- localnet --build-line iroha3 --peers 4 --out-dir ./localnet
cargo run --bin kagami -- docker --peers 4 --config-dir ./localnet --image hyperledger/iroha:dev --out-file ./docker-compose.yml
```

შემდეგ ამოიღეთ ძველი კონტეინერის მდგომარეობა და განახორციელეთ რეგენერირებული
`genesis.signed.nrt`, პარტნიორი `config.toml` ფაილები და `client.toml`.

თუ თქვენ უნდა აღადგინოს Iroha ინსტანციის მონაცემები, გააკეთეთ შემდეგი:

1. შეაერთეთ მეორე. Iroha peer, რომელიც ასახავს მონაცემებს პირველი
   (შეუძლებელი) პარტნიორი.
2. ველოდოთ ახალ თანატოლს, რომ მონაცემები პირველ თანატოლთან სინქრონიზდეს.
3. ეა ოპვკრთმ ჟჲპთნარა.
4. განახლება გენეზი და კონფიგურაციის ფაილები პირველი თანატოლების მხოლოდ ნაწილად
   კოორდინირებული მიგრაცია.

::: info

არ არსებობს ზოგადი ავტომატური გადაწერის გზა გენეზის ჩანაცვლებისთვის ცოცხალი
ეს არის კოორდინირებული მიგრაცია: შეინარჩუნეთ ძველი სახელმწიფო, მოიტანეთ
up თავსებადი თანატოლები, და მხოლოდ გადაადგილება validators ახალი კონფიგურაცია შემდეგ
ოპერატორები მიგრაციის გეგმაზე თანხმდებიან.

:::

## კერძო და საჯარო გასაღების მრავალფეროვანი ფორმატი {#multihash-format-of-private-and-public-keys}

თუ შეხედავთ
[კლიენტის კონფიგურაცია](/ka/guide/configure/client-configuration.md), შენ კი.
აღნიშნეთ, რომ იქ არსებული გასაღები მოცემულია
[მრავალფუნქციური ფორმატი](https://github.com/multiformats/multihash).

თუ თქვენ არასდროს მუშაობდით მულტიჰეშთან ადრე, ბუნებრივია ვთვლით რომ
მარჯვენა მხარე არ არის საკვანძო ბაიტების hexadecimal წარმოდგენა
(ორი სიმბოლო ბაიტზე), არამედ ბაიტები კოდირებულია როგორც ASCII ან UTF-8),
და ზარი `from_hex` ორივეს ლექსიკონზე `public_key` და
`private_key` აჟიოტაჟი.

ასევე ბუნებრივია ვარაუდობ, რომ მოწოდება `PrivateKey::try_from_str` სააგენტო
string literal მხოლოდ სწორი გასაღები გამოიღებს. ასე რომ, თუ თქვენ მიიღოთ რიცხვი
შეცდომაში ჩასული ბიტების, მაგალითად 32 ბიტი 64-ის წინააღმდეგ.
შეტყობინება.

**ეს ორივე ვარაუდი არასწორია.** სამწუხაროდ, შეცდომის შეტყობინებები
არ დაგეხმარებათ ამ კონკრეტულ ტიპის წარუმატებლობის აღმოფხვრაში.

**როგორ დავასწოროთ**: გამოყენება `hex_literal`. ეს ასევე გადაიქცევა უხეში მავთულხლართი
ქაღალდები ლამაზი პატარა ცხრილში აშკარად ექსადეციმალური ციფრებით.

::: warning

თუნდაც `try_from_str` განხორციელება ვერ შეამოწმებს, არის თუ არა მოცემული სტრიკი
ვალიდური `PrivateKey` და გაგაფრთხილებ, თუ არ არის.

ის აღმოაჩენს გარკვეულ აშკარა შეცდომებს, მაგალითად, თუ რიგში არასწორია
თუმცა, ვინაიდან ჩვენ ვცდილობთ მხარი დავუჭიროთ ბევრ საკვანძო ფორმატს, ეს ვერ გააკეთებს ბევრ რამეს
ეს ვერ გაიგებს, არის თუ არა გასაღები _სწორი_ პირადი გასაღები _მოცემულისთვის
ანგარიში_ ან, თუ თქვენ არ წარუდგენთ ინსტრუქციას.

:::

These ზოგიერთი ფირფიტარული შეცდომა შეიძლება თავიდან იქნას აცილებული, მაგალითად,
დესერიალიზება პირდაპირ სიმბოლოდან ან ახალი
ფრაზების წყვილი იმ ადგილებში, სადაც ეს აზრი აქვს.
