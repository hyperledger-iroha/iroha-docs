# ინტეგრაციის პრობლემების გადაჭრა {#troubleshooting-integration-issues}

ეს განყოფილება გთავაზობთ პრობლემების მოგვარების რჩევებს Iroha 3 ინტეგრაციის შესახებ. თუ პრობლემა, რომელიც თქვენ განიცდიათ არ არის აღწერილი აქ, დაგვიკავშირდით ტელეგრამზე [](https://t.me/hyperledgeriroha).

## კლიენტი ვერ მიერთდება. {#client-cannot-connect}

შეამოწმეთ, რომ მომხმარებლის კონფიგურაცია მიუთითებს პარტნიორის Torii მისამართზე:

```toml
torii_url = "http://127.0.0.1:8080/"
```

CLI შემოწმების შემთხვევაში, გადასცეს იგივე ფაილი მკაფიოდ:

```bash
cargo run --bin iroha -- --config ./localnet/client.toml ledger domain list all
```

თუ პარტნიორი მუშაობს Docker ან Kubernetes, გამოიყენეთ მასპინძელი ან მომსახურების მისამართი, რომელიც ხელმისაწვდომია კლიენტის პროცესიდან. `127.0.0.1` კონტეინერის შიგნით არ არის მასპინძლის მანქანა.

საჯარო Taira გამოცდებისთვის, დაიწყეთ ხელმოწერის გარეშე საბოლოო წერტილის ძებნით:

```bash
curl -fsS https://taira.sora.org/status \
  | jq '{blocks, txs_approved, txs_rejected, queue_size, peers}'

curl -fsS 'https://taira.sora.org/v1/domains?limit=5' \
  | jq -r '.items[].id'
```

იმ შემთხვევაში, თუ ეს ბრძანებები არ შეესაბამება `502`, TLS, DNS ან დროის გამოშვების შეცდომებს, მოასწორეთ ქსელის ხელმისაწვდომობა ან დაველოდოთ საჯარო ტესტნეტის საბოლოო წერტილს ანგარიშის გასაღებების ან ტრანზაქციის სასარგებლო დატვირთვების დებუგირებამდე.

## ტრანზაქციები უარყოფითია {#transactions-are-rejected}

ტრანზაქციის უმეტესობა გამოწვეულია იდენტობის ან ავტორიზაციის შეუსაბამობის გამო:

- მომხმარებლის კონფიგურაციაში არსებული ანგარიშის საჯარო გასაღები არ შეესაბამება ხელმოწერისთვის გამოყენებულ პირად გასაღებს
- ანგარიში არ არის რეგისტრირებული გენეზიის ან წინა ტრანზაქციის შედეგად
- ანგარიშს არ აქვს ნებართვის ტოკი ან როლი, რომელიც runtime validator-ის მიერ არის საჭირო.
- დომენი ID არ აქვს მონაცემთა სივრცის კვალიფიკაცია, მაგალითად, `domain.dataspace`

გამოიყენეთ `--output-format text` დაშვების დროს CLI ბრძანებები, რათა შეცდომები უფრო ადვილად წაიკითხოს:

```bash
cargo run --bin iroha -- --config ./localnet/client.toml --output-format text ledger transaction ping --msg "hello"
```

## შეკითხვები უბრუნებს ცარიელ შედეგებს {#queries-return-empty-results}

ცარიელი შეკითხვის შედეგები ყოველთვის არ ნიშნავს, რომ შეკითხვა წარუმატებელი. შეამოწმეთ:

- ჩადენილია ოპერაცია, რომელიც უნდა შექმნას ობიექტი.
- შეკითხული დომენი, აქტივების განსაზღვრა ან ანგარიში ID არის კანონიკური.
- გვერდების დაფარვა ან ფილტრები არ გამორიცხავს მოსალოდნელი რიგის
- კლიენტი დაკავშირებულია განკუთვნილ ქსელზე და არა სხვა ლოკალურ ქსელში

დომენის შემოწმებისათვის, დაიწყეთ ყველაზე ფართო გამოკითხვით:

```bash
cargo run --bin iroha -- --config ./localnet/client.toml ledger domain list all
```

## მოვლენების ან ბლოკების ნაკადები ადრე შეწყდება {#event-or-block-streams-stop-early}

ბლოკისა და მოვლენების ნაკადის მაგალითები ეყრდნობა Torii სტრიმინგის საბოლოო წერტილებს. შეამოწმეთ, რომ თანაბარი ჯერ კიდევ მუშაობს, შემდეგ ტესტირება დროის გატარებით:

```bash
cargo run --bin iroha -- --config ./localnet/client.toml ledger blocks 1 --timeout 30s
cargo run --bin iroha -- --config ./localnet/client.toml ledger events block
```

HTTP ინტეგრაციებისთვის შეადარეთ თქვენი საბოლოო პუნქტის ბილიკები მიმდინარე [Torii საბოლოო წერტილის რეფერენციასთან](/ka/reference/torii-endpoints.md).
