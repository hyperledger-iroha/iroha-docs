# ქსელის განთავსების გასაღები {#keys-for-network-deployment}

თითოეულ ქსელს სჭირდება განსხვავებული საკვანძო მასალა კლიენტებისთვის, ქსელის კვანძებისთვის, ბლოკჩეინის გენეზისზე ხელმოწერისთვის და NPoS ან Nexus პროფილისთვის BLS ვალიდატორების იდენტობისთვის.

## სადაც გამოიყენება გასაღები {#where-keys-are-used}

- მომხმარებლის ხელმოწერის გასაღები ინახება `client.toml` ქვეშ `[account]`.
- ქსელის კვანძების იდენტობის საკვანძოები ინახება თითოეულ ქსელის კვანძებში `config.toml` როგორც `public_key` და `private_key`.
- ქსელის პარების აღმოჩენა თითოეული ქსელის პარის საჯარო გასაღები იყენებს `trusted_peers`.
- BLS ვალიდატორი NPoS-ის პროფილებისათვის საფლავის მტკიცებულებები შენახულია `trusted_peers_pop` -ში.
- ბლოკჩეინის გენეზისი-ის ხელმოწერა იყენებს `[genesis].public_key` ქსელის კვანძების კონფიგურაციაში და შესაბამისი კერძო გასაღები ტექნიკური მანიფესტის ხელმოწერას.

ადგილობრივი ან ტესტის განთავსებისათვის, Kagami უნდა შექმნას ყველა ეს ფაილი ერთად:

```bash
cargo run --bin kagami -- localnet --peers 4 --out-dir ./localnet
```

არსებული ქსელის ან პროფილისთვის, გამოიყენეთ გაიდებული ნაკადი:

```bash
cargo run --bin kagami -- wizard
```

## გენერირება ინდივიდუალური საკვანძო წყვილი {#generate-individual-key-pairs}

გამოიყენეთ `kagami keys` ცალკე გასაღები მასალისათვის:

```bash
cargo run --bin kagami -- keys --algorithm ed25519 \
  --out-dir ./client-key
```

BLS დამტკიცების მასალისათვის უნდა შეიცვალოს მფლობელობის მტკიცებულება:

```bash
cargo run --bin kagami -- keys --algorithm bls_normal --pop \
  --out-dir ./validator-key
```

გამოიყენეთ `--seed-hex` მხოლოდ ზუსტად 32-ბაიტიან თექვსმეტობით საიდუმლოსთან ერთად, განმეორებადი განვითარების სატესტო მონაცემებისთვის. საწარმოო განთავსებისას გამოტოვეთ იგი, რათა Kagami-მ ოპერაციული სისტემის შემთხვევითობის წყარო გამოიყენოს, შემდეგ კი დაშიფვრის გარეშე ექსპორტირებული პირადი გასაღები დამტკიცებულ დაცულ საზღვარში გადაიტანეთ. ბრძანება პირად გასაღებებს არასოდეს ბეჭდავს.

## ქსელის კვანძების თანმიმდევრობა {#peer-consistency}

ყველა ვალიდატორმა უნდა შეთანხმდეს იმავე ბლოკჩეინის გენეზის ტრანზაქციაზე, ტოპოლოგიაზე, საიმედო ქსელის კვანძე საზოგადოებრივ გასაღებს და ვალიდატორი PoPs. ერთი დაკარგული ან შეუსაბამებელი ქსელის კვანძე გასაღები ხელს უშლის ქსელის დაწყებას ან კონსენსუსის მიღწევას.

მინიმალური ბიზანტიური შეცდომების ტოლერანტობის განთავსებისთვის, გამოიყენეთ მინიმუმ ოთხი ქსელის პარ. თითოეული ქსელის პარ უნდა ჰქონდეს საკუთარი კერძო გასაღები, მაგრამ თითოეულ ქსელურ პარ კონფიგურაციას სჭირდება იგივე საიმედო ქსელის პარ ნაკრები.

## კლიენტთა ანგარიშები {#client-accounts}

`client.toml` კლიენტის ანგარიში უკვე უნდა არსებობდეს ჯაჭვზე. ის შეიძლება დარეგისტრირდეს ბლოკჩეინის გენეზისის ტექნიკური მანიფესტის ან მოგვიანებით ტრანზაქციის მიერ. თავიდან აიცილეთ ბლოკჩეინ-გენეზის ხელმოწერის იდენტობის გამოყენება ხანგრძლივი აპლიკაციის ანგარიშად; ბლოკჩეინ-გენეზის პრივილეგიები გამოიყენება მხოლოდ ბლოკჩეინ-გენეზის რაუნდის დროს, ხოლო წარმოების კლიენტებმა უნდა გამოიყენონ საკუთარი ანგარიშები და როლები.
