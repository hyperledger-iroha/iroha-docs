# ქსელის განთავსების გასაღები {#keys-for-network-deployment}

თითოეულ ქსელს სჭირდება ცალკე საკვანძო მასალა კლიენტებისთვის, თანატოლებისთვის, გენეზისზე ხელმოწერისთვის,
და, NPoS ან Nexus პროფილები, BLS დამტკიცებლის ვინაობა.

## სად გამოიყენება გასაღები {#where-keys-are-used}

- კლიენტის ხელმოწერის გასაღები ინახება `client.toml` ქვემოთ `[account]`.
- თანატოლების იდენტობის გასაღები ინახება თითოეულ თანატოლში `config.toml` როგორც `public_key` და
  `private_key`.
- თანატოლების აღმოჩენა იყენებს თითოეული თანატოლის საჯარო გასაღები `trusted_peers`.
- BLS ვალიდატორი საფლავის მტკიცებულებები ინახება `trusted_peers_pop` NPOS-ისათვის
  პროფილები.
- გათენების ხელმოწერა იყენებს `[genesis].public_key` პარტნიორთა კონფიგურაციაში და
  კერძო გასაღების შესაბამისობა მანიფესტის ხელმოწერისას.

ადგილობრივი ან სატესტო განთავსებისათვის: Kagami წარმოქმნას ყველა ეს ფაილები ერთად:

```bash
cargo run --bin kagami -- localnet --build-line iroha3 --peers 4 --out-dir ./localnet
```

არსებული ქსელის ან პროფილისთვის გამოიყენეთ გათვლილი ნაკადი:

```bash
cargo run --bin kagami -- wizard --profile nexus
```

## შექმენით ცალკეული საკვანძო წყვილები {#generate-individual-key-pairs}

გამოყენება `kagami keys` ცალკე გასაღები მასალისათვის:

```bash
cargo run --bin kagami -- keys --algorithm ed25519 --json
```

სამედიცინო BLS დამტკიცების მასალა, მოიცავს საკუთრების მტკიცებულებას:

```bash
cargo run --bin kagami -- keys --algorithm bls_normal --pop --json
```

გამოყენება `--seed` მხოლოდ რეპროდუქციული განვითარების მოწყობილობებისთვის.
განთავსება, ახალი გასაღების შექმნა და კერძო გასაღებების შენახვა საცავის გარეთ.

## თანასწორობა {#peer-consistency}

ყველა დამტკიცებელი უნდა შეთანხმდეს იმავე გენეზის ტრანზაქციაზე, ტოპოლოგიაზე, სანდო
საჯარო გასაღები და ვალიდატორი PoPs. ერთი დაკარგული ან არათანაბრებელი თანატოლური გასაღები შეიძლება
ხელს უშლის ქსელის დაწყებას ან კონსენსუსის მიღწევას.

ოჲ-ნუვჲბჲჟნჲ ჟა ბზანთნთრვ ნაპაგწვნვნვნთჟრა, სბთეთ ოჲეაპჲლმნჲ ოთკჲ გპვმვ.
პერს უნდა ჰქონდეს საკუთარი კერძო გასაღები, მაგრამ ყველა პერის კონფიგურაციას იგივე სჭირდება
საიმედო თანატოლების ნაკრები.

## მომხმარებლის ანგარიშები {#client-accounts}

კლიენტის ანგარიში `client.toml` უნდა არსებობდეს უკვე ქსელში.
რეგისტრირებულია გენეზის მანიფესტით ან შემდგომ ტრანზაქციით.
გენეზიის ხელმოწერა იდენტობა როგორც ხანგრძლივი განაცხადის ანგარიში; გენეზის პრივილეგიები
გამოიყენება მხოლოდ გენეზის რაუნდის დროს და წარმოების კლიენტებმა უნდა გამოიყენონ საკუთარი
ანგარიშები და როლები.
