# საჯარო და კერძო ბლოკჩეინები {#public-and-private-blockchains}

Iroha შეიძლება ჩატარდეს სხვადასხვა კონფიგურაციებში. როგორც თქვენი საკუთარი ქსელის ადმინისტრატორი, თქვენ გადაწყვეტთ რომელი აღმასრულებელი და ნებართვის პოლიტიკა განსაზღვრავს თუ არა ტრანზაქცია მიიღება.

საერთო პროფილები არის კერძო ნებართული ქსელები და უფრო ღია საჯარო ქსელები. ორივე კონფიგურირებულია გენეზის მდგომარეობისა და შესრულების პოლიტიკის მეშვეობით, არა ცალკეული ბმულების ბინარებით.

ქვემოთ აღვნიშნავთ ამ ორ გამოყენების შემთხვევაში არსებულ ძირითად განსხვავებებს.

## ნებართვები {#permissions}

საჯარო ბლოკჩეინში, ანგარიშების უმეტესობას აქვს ერთი და იგივე ნებართვები. კერძო ბლოკშეინში თითოეულ ანგარიშს მხოლოდ მისი მკაფიო ნებართვა ეძლევა

::: info

დამატებითი დეტალებისთვის იხილეთ [ განყოფილება ნებართვებზე ](/ka/blockchain/permissions.md).

:::

## თანატოლები {#peers}

საჯარო ბლოკჩეინში, თანატოლების მიღება წარმოადგენს ჯაჭვური პოლიტიკის ნაწილს. კერძო ბლოკშეინისთვის, განთავსებები ჩვეულებრივ აკრიფებენ სანდო თანატოლებს კონფიგურაციაში და გენეზისში.

::: info

დამატებითი დეტალებისთვის იხილეთ [ peer management](peer-management.md).

:::

## რეგისტრაციის ანგარიშები {#registering-accounts}

დამოკიდებულია იმაზე, თუ როგორ გადაწყვეტთ შექმნათ თქვენი [გენეზის ბლოკი (`genesis.json`)](genesis.md), ანგარიშის რეგისტრაციის პროცესი შეიძლება ორი გზით განხორციელდეს. იმის გასაგებად, თუ რატომ, ჯერ ვისაუბროთ ნებართვის შესახებ.

შერჩეული აღმასრულებელი განსაზღვრავს, თუ რომელი ნებართვის შემოწმება გამოიყენება. თქვენ შეგიძლიათ გენეზისში მიანიჭოთ [ ნებართვების ჩანთები ](/ka/blockchain/permissions.md) კერძო, ადმინისტრატორის მიერ მართული ქსელის ან უფრო ღია ქსელის ჩამოყალიბებისთვის. მას შემდეგ, რაც ეს ნებართვები არის აქტიური, ანგარიშების რეგისტრაციის პროცესი განსხვავებულია.

საჯარო და კერძო რეგისტრაციის პოლიტიკა, როგორც წესი, განსხვავდება:

- საჯარო რეგისტრაციის პოლიტიკა იღებს ანგარიშის რეგისტრაციას ნებისმიერი დასაშვები მომხმარებლისგან[^1]. მომხმარებელს სჭირდება შესაფერისი კლიენტი, მხარდაჭერილი ალგორითმის კერძო გასაღები და რეგისტრაციული მოთხოვნა, რომელიც მიღებულია პოლიტიკით.

- კერძო რეგისტრაციის პოლიტიკას შეუძლია ერთ ანგარიშზე ან ერთი ჭკვიანი ხელშეკრულების მიერ რეგისტრაციების წარდგენის უფლებამოსილება მიეცეს. საბაჟო პოლიტიკა შეიძლება შეზღუდოს რეგისტრაცია დროის ფანჯარით. მას ასევე შეუძლია მოითხოვოს გამგზავრებელს დახარჯოს ტოკენი, რომლის მიწოდებაც ფიქსირებულია, რადგან არცერთ ორგანოს არ აქვს ნებართვა დაამატოს მეტი.

- პირადი ქსელის ნორმით, არსებული ანგარიში წარადგენს რეგისტრაციას თითოეული ახალი ანგარიშისათვის.

ნებართვის ვალიდატორები მოიცავს ჩვეულებრივ კერძო ბლოკჩეინის გამოყენების შემთხვევას.

::: info

საჯარო და კერძო რეჟიმები არის აღმასრულებელი და გენეზიის პოლიტიკის არჩევანი. ორივე იყენებს იმავე ნოდ ბინარს. შეამოწმეთ შერჩეული აღმასრულებელ და გენესის ნებართვები ღია ქსელის ჩატარების წინ.

:::

[ ინსტრუქციების განყოფილება](/ka/blockchain/instructions.md#un-register) იხილეთ `Register<Account>` ინსტრუქციის შესახებ დამატებითი დეტალებისთვის.

[^1]: `Register<Account>` ქმნის ლიდერის მდგომარეობას კანონიკური, დომენების გარეშე `AccountId`; დომენის მარშრუტირება და საყვედური სახელები მართულია ცალკე.
