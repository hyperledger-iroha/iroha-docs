# ბლოკჩეინის წარმოშობა {#genesis}

ბლოკჩეინის გენეზისი განსაზღვრავს საწყის ჯაჭვის მდგომარეობას. რედაქტირებადი წყარო არის JSON ტექნიკური მანიფესტი, ხოლო Iroha 3 კვანძი მოიხმარს ხელმოწერილი Norito ტრანზაქციის ფაილის.

## ფაილები {#files}

ძირითადი რეპოზიტორია ნაგულისხმევ საწყის შაბლონს `defaults/genesis.template.json`-ში შეიცავს. შაბლონი არასრულია და მისი შემოწმება, ხელმოწერა ან კვანძში გამოყენება შეუძლებელია, სანამ `kagami genesis materialize` მას მანიფესტად არ აქცევს. Kagami-ის გენერირებული ქსელები საკუთარ მანიფესტსა და ხელმოწერილ ტრანზაქციას გამომავალ დირექტორიაში წერს:

```bash
cargo run --bin kagami -- localnet generate --peers 4 --out-dir ./localnet
```

ამ დირექტორში გენერირებული `README.md` აღნიშნავს კონკრეტულ ფაილებს და ამოქმედების ბრძანებებს შერჩეული პროფილისთვის.

## ქსელის კვანძის კონფიგურაცია {#peer-configuration}

კვანძები ხელმოწერილ გენეზის ტრანზაქციას `config.toml`-ის `[genesis]` სექციაში უთითებს, ხოლო მის მოსალოდნელ ჰეშს ცალკე ფაილში აფიქსირებს:

```toml
[genesis]
file = "./genesis.signed.nrt"
public_key = "ed0120..."
expected_hash_file = "./genesis.expected_hash"
```

ქსელის ყველა კვანძს ერთი და იგივე ხელმოწერილი გენეზის ტრანზაქცია და გენეზისის საჯარო გასაღები უნდა ჰქონდეს. მოსალოდნელი ჰეშის ფაილი საჭიროა როგორც პირველად, ისე ხელახალი გაშვებისას; მას `kagami genesis sign --expected-hash-out` წერს.

## ბლოკჩეინის გენეზის ხელმოწერა {#signing-genesis}

თუ ტექნიკური მანიფესტის ხელით რედაქტირებას აკეთებთ, შეამოწმეთ იგი და გააფორმეთ მას ქსელის კვანძების დაწყებამდე:

```bash
cargo run --bin kagami -- genesis validate ./genesis.json
cargo run --bin kagami -- genesis sign ./genesis.json \
  --private-key-file "$GENESIS_PRIVATE_KEY_FILE" \
  --out-file ./genesis.signed.nrt \
  --expected-hash-out ./genesis.expected_hash
```

`GENESIS_PRIVATE_KEY_FILE` უნდა იყოს მფლობელის მიერ განკუთვნილი რეჟიმი-`0600`, ერთი ბმულიანი რიგითი ფაილი, რომელიც შეიცავს კანონიკურ კერძო გასაღების მულტიჰეშს და საბოლოო ახალ ხაზს. Kagami უარყოფს სიმბოლურ ბმულებს და არასდროს იღებს ნედლევარჩევნო ბლოკჩეინის გენეზისის პირად გასაღებს ბრძანების ხაზზე.

NPoS ან SORA Nexus პროფილებისთვის ჩართეთ გენერირებული პროფილის მიერ მოთხოვნილი ტოპოლოგია და BLS ფლობის მტკიცებულებები. Kagami-ის `localnet generate`, `wizard` და `sora-network generate` ბრძანებები ამ დეტალებს ავტომატურად ამუშავებს.

## ბლოკჩეინის გენეზისის განახლება {#recommitting-genesis}

ახალი ქსელი მუშაობას თავისი ხელმოწერილი გენეზისიდან იწყებს. ერთჯერად ლოკალურ ქსელში სხვა გენეზისის გამოსაცდელად გააჩერეთ მონაწილე კვანძები, წაშალეთ მათ მიერ შექმნილი მდგომარეობის დირექტორია და დაიწყეთ ახალი ხელმოწერილი გენეზისიდან. მოქმედმა ქსელმა განახლების მექანიზმად გენეზისი არასოდეს უნდა ჩაანაცვლოს. პროტოკოლის განსაზღვრებების ცვლილებას სჭირდება მმართველობით დამტკიცებული შერჩევის გადასვლები და შერჩეული განსაზღვრებებისა და ვალდებულებების კვალიფიკაცია.
