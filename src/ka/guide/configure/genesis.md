# ბლოკჩეინის წარმოშობა {#genesis}

ბლოკჩეინის გენეზისი განსაზღვრავს საწყის ჯაჭვის მდგომარეობას. რედაქტირებადი წყარო არის JSON ტექნიკური მანიფესტი, ხოლო Iroha 3 კვანძი მოიხმარს ხელმოწერილი Norito ტრანზაქციის ფაილის.

## ფაილები {#files}

აღმავალი რეპროდუქციული სათავსო გზავნის ჩვეულებრივი ტექნიკური მანიფესტი `defaults/genesis.json`. Kagami-ის მიერ შექმნილი ქსელები წერენ საკუთარ ტექნიკურ მანიფსტს და ხელმოწერილ ტრანზაქციას გამომშვებ დირექტორში:

```bash
cargo run --bin kagami -- localnet --peers 4 --out-dir ./localnet
```

ამ დირექტორში გენერირებული `README.md` აღნიშნავს კონკრეტულ ფაილებს და ამოქმედების ბრძანებებს შერჩეული პროფილისთვის.

## ქსელის კვანძის კონფიგურაცია {#peer-configuration}

ქსელის კვანძები `config.toml`-ის `[genesis]` განყოფილებაში ხელმოწერილი ბლოკჩეინის გენეზისის ტრანზაქციაზე მიუთითებენ:

```toml
[genesis]
file = "./genesis.signed.nrt"
public_key = "ed0120..."
```

ქსელში ყველა ქსელის კვანძმა უნდა შეთანხმდეს ხელმოწერილი ბლოკჩეინის გენეზისის ტრანზაქციაზე და ბლოკჩეინის გენეზისი საჯარო გასაღებაზე.

## ბლოკჩეინის გენეზის ხელმოწერა {#signing-genesis}

თუ ტექნიკური მანიფესტის ხელით რედაქტირებას აკეთებთ, შეამოწმეთ იგი და გააფორმეთ მას ქსელის კვანძების დაწყებამდე:

```bash
cargo run --bin kagami -- genesis validate ./genesis.json
cargo run --bin kagami -- genesis sign ./genesis.json \
  --private-key-file "$GENESIS_PRIVATE_KEY_FILE" \
  --out-file ./genesis.signed.nrt
```

`GENESIS_PRIVATE_KEY_FILE` უნდა იყოს მფლობელის მიერ განკუთვნილი რეჟიმი-`0600`, ერთი ბმულიანი რიგითი ფაილი, რომელიც შეიცავს კანონიკურ კერძო გასაღების მულტიჰეშს და საბოლოო ახალ ხაზს. Kagami უარყოფს სიმბოლურ ბმულებს და არასდროს იღებს ნედლევარჩევნო ბლოკჩეინის გენეზისის პირად გასაღებს ბრძანების ხაზზე.

NPoS ან Nexus პროფილისთვის, შეიყვანეთ ტოპოლოგია და BLS წარმოქმნილი პროფილის მიერ საჭირო მფლობელობის მტკიცებულებები. Kagami `localnet`, `wizard` და პროფილების წარმოების ბრძანებები ამ დეტალებს ავტომატურად მართავენ.

## ბლოკჩეინის გენეზისის განახლება {#recommitting-genesis}

ქსელის კვანძი გენეზისს მხოლოდ მაშინ აფიქსირებს, როდესაც მისი საცავი ცარიელია. ერთჯერად ლოკალურ ქსელში ახალი გენეზისის გამოსაცდელად გააჩერეთ კვანძები, წაშალეთ მათი გენერირებული მდგომარეობის კატალოგი და ახალი ხელმოწერილი გენეზისიდან დაიწყეთ. მოქმედ ქსელში გენეზისი არ ჩაანაცვლოთ, თუ ყველა ვალიდატორი ერთსა და იმავე მიგრაციას არ კოორდინირებს.
