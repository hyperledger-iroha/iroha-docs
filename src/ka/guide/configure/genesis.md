## ფაილები {#files}

ზედა დინების საცავი აგზავნის ნაგულისხმევ მანიფესტს `defaults/genesis.json`.
Kagami- გენერირებული ქსელები წერენ საკუთარ მანიფესტს და ხელმოწერილ ტრანზაქციას
გამომავალი დირექტორია:

```bash
cargo run --bin kagami -- localnet --peers 4 --out-dir ./localnet
```

გენერირებული `README.md` ამ დირექტორიაში იწერს ზუსტ ფაილებს და გაშვებას
ბრძანებები არჩეული პროფილისთვის.

## თანატოლების კონფიგურაცია {#peer-configuration}

თანატოლები მიუთითებენ ხელმოწერილი გენეზის გარიგებაზე `[genesis]` განყოფილება
`config.toml`:

```toml
[genesis]
file = "./genesis.signed.nrt"
public_key = "ed0120..."
```

ქსელის ყველა თანატოლი უნდა შეთანხმდეს ხელმოწერილ გენეზის ტრანზაქციაზე და
genesis საჯარო გასაღები.

## გენეზისის ხელმოწერა {#signing-genesis}

თუ მანიფესტს ხელით არედაქტირებთ, დაადასტურეთ და მოაწერეთ ხელი მას თანატოლების დაწყებამდე:

```bash
cargo run --bin kagami -- genesis validate ./genesis.json
cargo run --bin kagami -- genesis sign ./genesis.json \
  --private-key-file "$GENESIS_PRIVATE_KEY_FILE" \
  --out-file ./genesis.signed.nrt
```

`GENESIS_PRIVATE_KEY_FILE` უნდა იყოს მფლობელის კონტროლის რეჟიმი-`0600`, ერთი ბმული
რეგულარული ფაილი, რომელიც შეიცავს ერთ კანონიკურ კერძო გასაღების მულტიჰეშს და საბოლოო
ახალი ხაზი. Kagami უარყოფს სიმბოლურ კავშირებს და არასოდეს იღებს ნედლეულ გენეზისის პირადს
გასაღები ბრძანების ხაზზე.

NPoS-სთვის ან Nexus პროფილები, მოიცავს ტოპოლოგიას და BLS საკუთრების დამადასტურებელი საბუთი
საჭიროა გენერირებული პროფილის მიერ. Kagami `localnet`, `wizard`, და პროფილი
გენერირების ბრძანებები ავტომატურად ამუშავებს ამ დეტალებს.

## გენეზისის ხელახლა ჩადენა {#recommitting-genesis}

თანატოლი მხოლოდ მაშინ ჩაიდენს გენეზისს, როცა მისი საცავი ცარიელია.ახალი გენეზის შესამოწმებლად
ერთჯერადი ლოკალური ქსელი, შეაჩერე თანატოლები, ამოიღეთ მათი გენერირებული სახელმწიფო დირექტორია,
და დავიწყოთ ახალი ხელმოწერილი გენეზისიდან.არ შეცვალოთ გენეზისი სირბილზე
ქსელი, თუ ყველა ვალიდატორი არ კოორდინაციას უწევს იმავე მიგრაციას.
