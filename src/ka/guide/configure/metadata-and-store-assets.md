# მეტა მონაცემები და ლეჯერის შენახვის არჩევანი {#metadata-and-ledger-storage-choices}

Iroha 3 მონაცემთა მოდელს არ აქვს ცალკე `Store` აქტივის ტიპი კვანძური მნიშვნელობის მონაცემებისთვის. გამოიყენეთ შემდეგი შენახვის არჩევანი.

## მეტა მონაცემები {#metadata}

გამოიყენეთ [მეტა მონაცემები](/ka/blockchain/metadata.md) პატარა JSON ველებისათვის, რომლებიც ეკუთვნებიან რეგისტრაციის ობიექტს:

- დასახელება და ეტიკეტები
- ინტეგრაცია IDs
- მცირე პოლიტიკური დროშები
- ჰაშები, URIs, CIDs ან SoraFS გზები, რომლებიც მიუთითებენ უფრო დიდ სასარგებლო ტვირთებზე;

Metadata არის მსოფლიო მდგომარეობის ნაწილი და დაბრუნდება ობიექტთან ერთად, რომელიც მას ფლობს. შეინახეთ გასაღები სტაბილური, ღირებულებები კომპაქტური და ნებართვები მკაფიო. არ ინახოთ დიდი დოკუმენტები, ლოგები ან მაღალი ჩერნის აპლიკაციის მდგომარეობა პირდაპირ მეტადი მონაცემებში.

## ციფრული აქტივები და NFTs {#numeric-assets-and-nfts}

გამოიყენეთ აქტივები [](/ka/blockchain/assets.md) და [NFTs](/ka/blockchain/nfts.md), როდესაც მდგომარეობა არის ღირებულების მქონე:

- ფუნქციონირებადი სალანდების რიცხვობრივი აქტივები
- NFTs უნიკალურ საკუთრებაში არსებული ჩანაწერებისთვის
- [RWAs](/ka/blockchain/rwas.md) და სხვა დომენის სპეციფიკური ობიექტები, როდესაც აქტიური მონაცემების მოდელი მათ ასახავს

აქტივებსა და NFTs აქვს საკუთარი IDs, სიცოცხლის ციკლის მოვლენები, გადაცემის ქცევა და ნებართვის შემოწმება. ისინი უკეთესია მეტადატებზე, როდესაც საკუთრება, სიმცირე ან გადაცემის ისტორია მნიშვნელოვანია.

## გარეთ ქსელის მონაცემები {#off-chain-data}

გამოყენება offchain შენახვა დიდი ან mutable სასარგებლო ტვირთები. შეინახეთ მხოლოდ სტაბილური რეფერენციის onchain, როგორიცაა:

- შინაარსის ჰეში
- a URI
- SoraFS გზა ან რეფერენციის მანიფესტი;
- კომპაქტური ვალდებულება, რომელიც გამოყენებულია განაცხადის მტკიცებულებით

ამით WSV მცირდება, ამასთანავე საშუალებას აძლევს აპლიკაციებს დაადასტურონ, რომ ჯაჭვის გარეშე სასარგებლო ტვირთი შეესაბამება ჯაჭვზე არსებულ რეფერენციას.

## ადგილის არჩევა {#choosing-a-location}

გამოიყენეთ ეს წესი:

- თუ ეს არის კომპაქტური ატრიბუტი წიგნის ობიექტში, გამოიყენეთ მეტა მონაცემები.
- თუ ეს არის ღირებულების მქონე ან გადასატანი, მოდელირებული უნდა იყოს როგორც აქტივი, NFT, ან დომენის სპეციფიკური ობიექტი.
- იმ შემთხვევაში, თუ ეს არის დიდი, მაღალი მოცულობის ან აპლიკაციის პირადი, შეინახეთ იგი WSV გარეთ და დააყენეთ შემოწმებადი რეფერენცია ჯაჭვზე.

მეტა მონაცემთა ნებართვებისთვის იხილეთ [ ნებართვის ტოქნები ](/ka/reference/permissions.md).
