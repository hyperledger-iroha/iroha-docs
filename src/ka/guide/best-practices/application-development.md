# აპლიკაციის შემუშავება {#application-development}

Iroha აპლიკაციებმა უნდა განახორციელონ ტრანზაქციის ქცევა მკაფიოდ, შეინარჩუნონ ხელმოწერის მდგომარეობა და გამოიყენონ კითხვები და მოვლენები ისე, რომ პროდუქციაში ადვილად აღინიშნოს.

## კლიენტის დაყენება {#client-setup}

- შეინახეთ კლიენტის კონფიგურაცია აპლიკაციის წყარო კოდის გარეთ. დატვირთეთ ჯაჭვის ID, Torii URL, ხელმოწერის ანგარიში და ტრანზაქციის პარამეტრები გარემოს სპეციფიკური კონფიგურიდან.
- შეინახეთ `client.toml` ფაილები ცალკე ლოკალურ ქსელში, Taira, Minamoto და კერძო ქსელებში. გადაწერილი ტესტნეტის კრიპტოგრაფიული ხელმოწერა არასდროს უნდა გახდეს მთავარი ქსელის კრიპტოლოგიური ხელმოწერა.
- განზრახ დააყენეთ ტრანზაქციის ხანგრძლივობა და სტატუსის დროები. ძალიან მოკლე ხანგრძლივი პერიოდი შეიძლება ამოიწუროს ნორმალური ქსელის ტრიფტის დროს, ხოლო ძალიან დიდი ხანგრძლივები შეიძლება გაუჭირდება დუბლიტური წარდგენების დასაბუთება.
- გამოიყენეთ `nonce = true` მხოლოდ მაშინ, როდესაც განმეორებადი ტრანზაქციები უნდა შეიცავდეს ცალკეულ კრიპტოგრაფიულ ჰეშებს. idempotent ბიზნეს ოპერაციებისათვის, შეინახეთ და გაიმეორეთ განაცხადის მოთხოვნის ID ასე რომ განმეორებითი მცდელობები არის თვალსაჩინო.

იხილეთ [მომხმარებლის კონფიგურაცია](/ka/guide/configure/client-configuration.md) მიმდინარე TOML ველებისათვის.

## ოპერაციები {#transactions}

- ტრანზაქციები შეიქმნას SDK ტიპირებული ინსტრუქციებიდან, სადაც შესაძლებელია ნედლეულის JSON ან მავთულხლართებით შეკრებილი დატვირთვების ნაცვლად.
- წინასწარი შემოწმება მნიშვნელოვანი წერს მხოლოდ კითხვაზე: ანგარიშის არსებობა, აქტივების ბალანსი, ნებართვის მდგომარეობა, საფასური აქტივების ხელმისაწვდომობა და მიზნობრივი ობიექტის მდგომარეობა.
- ჩაწერეთ ტრანზაქციის კრიპტოგრაფიული ჰეში, ავტორიზაციის ძირითადი ანგარიში, ინსტრუქციების შეჯამება და მოსალოდნელი მდგომარეობის ცვლილება წარდგენამდე.
- `Rejected`, `Expired` და დროის შეწყვეტის შედეგები განსხვავდება. დროის შეზღუდვა ნიშნავს, რომ კლიენტმა საბოლოო სტატუსი არ დააკვირდა; ეს არ მტკიცებს, რომ ქსელმა ტრანზაქცია იგნორირა.
- წარმატებული ჩანაწერის შემდეგ, შეამოწმეთ მიღებული მდგომარეობა მოთხოვნის ან მოვლენის შემოწმების პუნქტით, რომელიც ემთხვევა ბიზნეს ოპერაციას.

ტრანზაქციის მექანიკის შესახებ იხილეთ [ოპერაციები](/ka/blockchain/transactions.md).

## კითხვები და მოვლენები {#queries-and-events}

- გამოიყენეთ შეკითხვები მიმდინარე მდგომარეობისა და მოვლენების ნაკადებისთვის ცვლილების შესახებ შეტყობინებებისათვის. თავიდან აიცილეთ მოვლენის მართვის შეცვლა მრავალჯერადი ფართო შეკითხვებით.
- ფართო განმეორებადი მოთხოვნების გვერდები, როგორიცაა ანგარიში, აქტივი და ბლოკის სიები.
- ფართო ფილტრები სასარგებლოა დიაგნოსტიკისთვის, მაგრამ შეიძლება დაამატოს ზედმეტი შესრულება და კლიენტის მხრიდან დამუშავება .
- შეინახეთ მხოლოდ წაკითხვის მქონე სიგარეტის შემოწმება ხელმოწერილი ტრანზაქციული ტესტებისგან, რათა API საბოლოო წერტილის ხელმისაწვდომობა უფრო ადვილი იყოს დიაგნოსტიკა.

იხილეთ [კითხვები](/ka/blockchain/queries.md), [მოვლენები](/ka/blockchain/events.md) და [ფილტრები](/ka/blockchain/filters.md).

## სააგენტო დახმარებით განვითარება {#agent-assisted-development}

- ნება მიეცით აგენტებს შეამოწმონ დოკუმენტები, SDK კოდი და მხოლოდ წაკითხვის ქსელის სტატუსი სანამ სთხოვენ მათ ჩაწერონ ტრანზაქციის კოდი.
- გაითვალისწინეთ ცოცხალი ქსელის ტესტების ჩატარება გარემოს დროშის მიღმა, როგორიცაა `TAIRA_LIVE=1`.
- არ ჩასვით კერძო გასაღები, ანგარიშის აღდგენის მასალა, API ტოკენები ან გადამისამართებული ავტოგრაფების სათაურები შეტყობინებებში.
- მოითხოვეთ ტრანზაქციის გეგმა, სანამ რომელიმე აგენტი უგზავნის ცოცხალ ტესტნეტს. გეგმამ უნდა დაასახელოს ქსელი, ავტორიზაციის პრინციპალი, ინსტრუქციები, საფასური აქტივი, ფრენის წინასწარი წაკითხვა, მოსალოდნელი შედეგი და განმეორებითი მცდელობის ქცევა .

Taira MCP სამუშაო პროცესის შესახებ იხილეთ [SORA 3-ზე: Taira და Minamoto](/ka/get-started/sora-nexus-dataspaces.md#taira-mcp-for-agents).

## SDK ჰიგიენა {#sdk-hygiene}

- SDK და ბინარული ვერსიები ერთად, გამოყენებული [შეთავსების მატრიცა](/ka/reference/compatibility-matrix.md).
- შენარჩუნება გენერირებული კლიენტის კოდი, snippets და მაგალითები სინქრონიზებულია დამაგრებული ძირითადი სამუშაო სივრცე რევიზიის.
- დაამატეთ ერთეულის ტესტები ტრანზაქციების მშენებლობის კოდისა და ინტეგრაციის ტესტების მინიმალური წაკითხვისა და წერის გზები თქვენი განაცხადი დამოკიდებულია.
