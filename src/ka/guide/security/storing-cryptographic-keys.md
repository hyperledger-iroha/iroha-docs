# კრიპტოგრაფიული გასაღების შენახვა {#storing-cryptographic-keys}

თქვენი მგრძნობიარე მონაცემები მხოლოდ იმ შემთხვევაში რჩება კონფიდენციალურ <abbr title="Operational Security">OPSEC</abbr> სოციალური ინჟინერიის საფრთხეები, როდესაც ვინმე, რომელიც ავტორიტეტული ფიგურას წარმოადგენს, ცდილობს დაგეხმაროთ პირადი კრიპტოვალუტის გასაცემად, რეალურია. ყოველთვის იყავით ფრთხილები და არ გაზიაროთ თქვენი კერძო გასაღები, ისე მოექცევით მას, როგორც თქვენს ბინის გასაღებს მხოლოდ ნდობის მქონე პირებისთვის განკუთვნიდით.

დამატებითი ინფორმაციისთვის <abbr title="Operational Security">OPSEC</abbr> და მისი საუკეთესო პრაქტიკა, იხილეთ [ოპერაციული უსაფრთხოება](./operational-security).

## კრიპტოგრაფიული გასაღების ციფრული შენახვა {#storing-cryptographic-keys-digitally}

როდესაც საქმე ეხება ციფრული გასაღების დაცვას, ძირითადად მხოლოდ ორი მიდგომა[SSH](https://www.ssh.com/) და [GPG](https://www.gnupg.org/)ამ მეთოდებმა უზრუნველყოფს უსაფრთხოების ფენა, რათა თავიდან იქნას აცილებული თქვენი კრიპტოგრაფიული გასაღები.

ბევრი Iroha არქიტექტურული გადაწყვეტილებები გავლენას ახდენს **უსაფრთხო ქარხანა** (`SSH`) პროტოკოლი, რის გამოც ამ განყოფილებაში ძირითადად ორიენტირებულია `SSH` მიდგომა, რომელიც გთავაზობთ ინსტრუქციებს იმის შესახებ, თუ როგორ შეიძლება ეფექტურად განხორციელდეს პროტოკოლი თქვენი კრიპტოგრაფიული გასაღების შენახვისთვის Iroha ეკოსისტემა.

### გამოყენება SSH და SSH აჟანტ. {#using-ssh-and-ssh-agent}

**უსაფრთხო შელის პროტოკოლი** (`SSH`) არის კრიპტოგრაფიული ქსელის პროტოკოლი, რომელიც ემსახურება ვირტუალური გეტვაიტის ფუნქციას. SSH საკვანძო შესაბამებელი პირობები. იგი უზრუნველყოფს ეფექტურ გზას სისტემებთან დისტანციური ურთიერთქმედებისათვის ფიზიკური ყოფნის აუცილებლობის გარეშე. ამ კონტექსტში, `SSH` უზრუნველყოფს ორი ძირითადი ავთენტიფიკაციის მექანიზმს: ტრადიციული პაროლიზე დაფუძნებული მიდგომა და უფრო უსაფრთხო საჯარო-კერძო გასაღები წყვილის მეთოდი.

დამატებითი ინფორმაციისთვის `SSH`, იხილეთ [დაკავშირებული SSH აკადემიის თემა](https://www.ssh.com/academy/ssh).

შესვლის პროცესის გამარტივებისა და განმეორებითი შეყვანის აუცილებლობის გარეთ გადასასვლელად, შესაძლებელია `SSH` გასაღები **SSH აჟანტ.** (`ssh-agent`)ის ასისტენტური პროგრამა, რომელიც გახსოვს თქვენი `SSH` სესიის ხანგრძლივობის გასაღები და/ან პაროლი. ეს კონფიგურაცია საშუალებას იძლევა `SSH` კარიბჭე, რომლის საშუალებითაც გასაღებებზე ადვილად მივაღწიოთ, როდესაც ის დაკავშირებულია სხვა მანქანებთან.

აქ სამუშაო პროცესის მიმდინარეობა ასეთია: თქვენ გაქვთ თქვენი საჯარო გასაღები შენახული დისტანციურ სისტემაზე და შეინახეთ თქვენი პირადი გასაღები დაცულად. `ssh-agent` ნაბიჯები თქვენი კომუნიკაციისთვის _საზოგადოება_ შემდეგ დისტანციური სისტემა გამოგზავნის [გამოწვევა](https://en.wikipedia.org/wiki/Challenge%E2%80%93response_authentication) რომ მხოლოდ თქვენი _კერძო_ კვრთამ შეიძლება სათანადოდ რეაგირება. `ssh-agent` ამ გამოწვევის გადაჭრა თქვენი _კერძო_ თუ პასუხი შეესაბამება სისტემის მოლოდინს, თქვენ მიიღებთ წვდომას.

სილამაზე `ssh-agent` ეს არის ის, რომ თქვენი პირადი გასაღები შენარჩუნდება თქვენს სესიის დროს, ასე რომ არ არის აუცილებელი შეყვანა თქვენი პაროლი ან პირადი გასახვის ფრაზა ყოველ ჯერზე თქვენ დაკავშირება დისტანციური სისტემა.

დამატებითი ინფორმაციისთვის `ssh-agent`, იხილეთ [დაკავშირებული SSH აკადემიის თემა](https://www.ssh.com/academy/ssh/agent).

::: info შენიშვნა

დეტალური მიმოხილვისთვის `SSH` პროტოკოლი და `ssh-agent` ინსტრუმენტი, იხილეთ შემდეგი [SSH აკადემია](https://www.ssh.com/academy) თემები:

  - [რა არის SSH (Secure Shell)?](https://www.ssh.com/academy/ssh)
  - [ssh-აგენტი: როგორ კონფიგურაცია ssh-agent, აგენტის გადაგზავნა, & აგენტის პროტოკოლი](https://www.ssh.com/academy/ssh/agent)

:::

### პაროლი მენეჯერის პროგრამის დამატება {#adding-a-password-manager-program}

რეკომენდირებულია თქვენი `SSH` გასაღები, რომლებიც დაცულია პაროლით, რაც დამატებით ხელს უშლის მავნე მხარეებს თქვენი სენსიტიური ინფორმაციის მოპოვების მიზნით.

სხვადასხვა პაროლი მენეჯერები შეიძლება გამოყენებულ იქნას მომხმარებლის პაროლების შესანახად და `SSH` ჱაღჲრჲ ვ მკაფნჲჟრ, [KeePass](https://keepass.info/) გამოიყენება როგორც მაგალითი პაროლი მენეჯერი, კონკრეტულად, [KeePassXC](https://keepassxc.org/) ლინუქსზე დაფუძნებული ოპერაციული სისტემების პორტი.

ინსტრუქციების მისაღებად KeePassXC იხილეთ [კონფიგურაცია KeePassXC](#configuring-keepassxc) ქვემოთ მოცემული ნაწილი.

![KeePassXC: `Main` ეკრანი UI](../../../img/KeePassXC.png)

KeePassXC უზრუნველყოფს გაძლიერებულ უსაფრთხოებას, მოქნილობასა და კონტროლს. `SSH` გასაღები. როდესაც გამოიყენება გასაღების შენახვისთვის, ეს პაროლი მენეჯერი უზრუნველყოფს `ssh-agent` შენახული გასაღები, რომლებიც შემდეგ დაუყოვნებლივ ამოღებულია მისი მეხსიერებიდან KeePassXC ფანჯარა დახურულია.

::: tip

თეორიულად, ნებისმიერი KeePass პორტები [ოფიციალურ ვებგვერდზე](https://keepass.info/download.html) შეიძლება გამოყენებულ იქნას ძირითადი შენახვის მიზნით.
ჩვენ გირჩევთ რომელიმე შემდეგი: [KeePassX](https://www.keepassx.org/) ან [KeePassXC](https://keepassxc.org/).

:::

#### კონფიგურაცია KeePassXC {#configuring-keepassxc}

კონფიგურაცია KeePassXC, შეასრულოს შემდეგი ნაბიჯები:

1. გაშვება KeePassXC, მაშინ წადი **ინსტრუმენტები** > **პარამეტრები**, ან აირჩიეთ **მოწყობილობა** ღილაკი ზემოდან UI პანელი.

2. დაწვრილებით **აპლიკაციის პარამეტრები** ჩანართი, რომელიც გამოჩნდება, აირჩიეთ **SSH აჟანტ.** მარცხენა მენიუდან და შემდეგ აირჩიეთ **ჩართვა SSH აგენტების ინტეგრაცია** საჯარო ყუთი.

   ::: info აჩვენეთ მინიშნება ეკრანის ნახვა

   ![KeePassXC `SSH Agent` ჩანართი: გაშვება SSH აჟანტ.](../../../img/keepassxc_ssh_agent.png)

   :::

3. შეიქმნას ახალი KeePassXC მონაცემთა ბაზა. ინსტრუქციისთვის იხილეთ [KeePassXC მომხმარებლის სახელმძღვანელო > თქვენი პირველი მონაცემთა ბაზის შექმნა](https://keepassxc.org/docs/KeePassXC_UserGuide#_creating_your_first_database).

4. თითოეული გასაღები, რომელსაც გსურთ შეინახოთ KeePassXC შექმნილი მონაცემთა ბაზა, შეასრულეთ შემდეგი ნაბიჯები:

   - დაამატეთ ახალი მითითება მონაცემთა ბაზაში. ინსტრუქციისთვის იხილეთ [KeePassXC მომხმარებლის სახელმძღვანელო > თქვენი პირველი მონაცემთა ბაზის შექმნა](https://keepassxc.org/docs/KeePassXC_UserGuide#_creating_your_first_database).

   - ახალი ჩანაწერის დამატებისას დააკავშიროთ ფაილი, რომელიც შეიცავს გასაღებს შემდეგი რამით: **განვითარებული** მარცხენა მენიუდან, შემდეგ აირჩიეთ **დამატება** დაწვრილებით **დანართები** განყოფილებაში, აირჩიეთ საჭირო ფაილი **აირჩიეთ ფაილები** ფანჯარა, რომელიც ჩანს.

   - როდესაც დაამატეთ ახალი შეტყობინება, აირჩიეთ **SSH აჟანტ.** მარცხენა მენიუდან, შემდეგ აირჩიეთ საკვანძო ფაილი თქვენ დაამატეთ **მიმაგრება** მენიუში **კერძო გასაღები** განყოფილება; შემდეგ შეარჩიეთ შემდეგი ჩანართები:

      - **დაამატეთ სააგენტოზე გასაღები მონაცემთა ბაზის გახსნის/გამორთვისას**

      - **ამოიღეთ სააგენტოდან გასაღები მონაცემთა ბაზის დახურვის/კეტვის დროს**

      - **მომხმარებლის მიერ დადასტურების მოთხოვნა, როდესაც ეს გასაღები გამოიყენება**

   - საჭიროების შემთხვევაში, შეკეთეთ სხვა ცვლილებები ჩანაწერში.

   - როდესაც მზად არის, აირჩიეთ **OK** ჱა ეა ჟლსპვმ ჲეჟვნ.

##### მოსალოდნელი შედეგები {#expected-results}

- კრიპტოგრაფიული და `shh` გასაღები ინახება როგორც ჩანაწერები KeePassXC მონაცემთა ბაზა, რომელიც შეიძლება მიეღოთ KeePassXC ფანჯარა ღიაა.

- შენახული კრიპტოგრაფიული და `ssh` გასაღები შეიძლება გამოყენებულ იქნას ნებისმიერ დროს, როდესაც ისინი ავტორიზაციისათვის საჭიროა.

- შენახული კრიპტოგრაფიული და `ssh` გასაღები ამოღებულია `ssh-agent` ერთხელ KeePassXC ფანჯარა დახურულია.

::: info შენიშვნა

არ შეუძლიათ **მომხმარებლის მიერ დადასტურების მოთხოვნა, როდესაც ეს გასაღები გამოიყენება** ვარიანტი: `ssh-agent` შეიძლება არ აკონტროლოს პროცესი, რომელმაც მას გასაღები მიაწოდა. იმ შემთხვევაში, თუ პაროლი მენეჯერის პროცესი malware ან სისტემური სერვისი `SIGKILL` სიგნალი, გასაღები სავარაუდოდ დარჩება `ssh-agent`, როგორც Unix სისტემის პროგრამები ვერ შეჭრის `SIGKILL`.

:::

## კრიპტოგრაფიული გასაღების ფიზიკური შენახვა {#storing-cryptographic-keys-physically}

მათთვის, ვინც უმაღლესი დონის უსაფრთხოების გარეშე ეძებს, კრიპტოგრაფიული გასაღებების შენახვის ვარიანტი ფიზიკურად უზრუნველყოფს, რომ გასაღები სრულად გაწყვეტილია ციფრული ქსელებიდან, ამით მინიმუმამდე მიდის არავტორიზებული წვდომის რისკი. ფიზიკური ვარიანტის აღიარება ხაზგასმით აღნიშნავს ჩვენს ვალდებულებას, შევუდგეთ სხვადასხვა უსაფრთხოების საჭიროებებს.

### ტექნიკური გასაღების გამოყენება {#using-a-hardware-key}

ჩვენი გუნდი მიიჩნევს, რომ ჰარდვერიანი გასაღები ერთ-ერთი საუკეთესო უსაფრთხოების ზომაა. USB აპარატის მოწყობილობა, რომელსაც აქვს ჩვეულებრივი ფლეშ დრაივის ზომა, მხოლოდ უსაფრთხოებასთან დაკავშირებული მოვლენების გადამუშავებას ახერხებს, როდესაც იგი მიერთებულია მანქანასთან. ეს საშუალებას გაძლევთ მარტივად გამოაშოროთ მოწყობილება უსაფრთხოების დარღვევის შემთხვევაში ან უბრალოდ დაუკავშირდეთ მას სხვა მანქანას ნებისმიერ დროს, როცა ეს საჭიროა.

თუმცა, რადგან არსებობს მრავალი ბრენდი აპარატურული გასაღები, თითოეული მათგანის უნიკალური APIs მნიშვნელოვანია ბაზრის შესწავლა, რათა იპოვოთ ის გასაღები, რომელიც თქვენს საჭიროებებს ყველაზე მეტად შეესაბამება.

ამ დრომდე, ჩვენს გუნდმა შიდა ტესტირება ჩაატარა [YubiKey 5C](https://www.yubico.com/il/product/yubikey-5c/) აპარატურის გასაღები, რომელიც აღმოჩნდა ბევრი დადებითი თვისებები, მათ შორის მრავალმხრივი API ფუნქციონირება.

თუმცა, არსებობს პოტენციური მინუსი, რომელიც უნდა გავითვალისწინოთ. [HMAC გამოწვევა-პასუხის ავთენტიფიკაცია](https://en.wikipedia.org/wiki/Challenge%E2%80%93response_authentication) და შესაბამისი შენახვის _კერძო_ ამ რეაგირების საკვანძო შეიძლება შექმნას დაუცველობა. YubiKey 5C-ის მეხსიერება, რითაც საფრთხე შეექმნა ზოგადი უსაფრთხოებისთვის.

საბედნიეროდ, ამ დაუცველობის შემცირება შესაძლებელია ალტერნატიული მიდგომის მიღებით YubiKey 5C. იდეა არის გამოყენება YubiKey 5C უსაფრთხო წვდომისათვის KeePassXC მონაცემთა ბაზა, რომელიც შენახავს თქვენს კრიპტოგრაფიულ და `SSH` ეს მეთოდი შეიძლება ითქვას სასარგებლო, რადგან ის აღემატება პაროლების უმეტესობის უსაფრთხოებას და საჭიროა მავნე მხარისათვის თქვენი აპარატურის გასაღები KeePassXC მონაცემთა ბაზა გაჟონდა.

### მნემონიური ფრაზის გამოყენება {#using-a-mnemonic-phrase}

ალტერნატიულად, შეგიძლიათ დაიმახსოვროთ პირადი გასაღები როგორც სიტყვების სერია, რომელიც ცნობილია როგორც _მნემონიური ფრაზა_. ამ მეთოდს, რომელიც გამოიყენება ბევრ საფულეში, მოითხოვს დაახლოებით 25 კონკრეტული სიტყვის გახსენება. პაროლების მენეჯერების უმეტესობა, მათ შორის ადრე განხილული KeePassXC, მნემონიკური პაროლი ფრაზის გენერაცია.
