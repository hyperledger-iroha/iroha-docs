# კრიპტოგრაფიული გასაღების შენახვა {#storing-cryptographic-keys}

თქვენი მგრძნობიარე მონაცემები მხოლოდ იმ შემთხვევაში რჩება კონფიდენციალური, თუ კრიპტოგრაფიული გასაღების დაცვის მიზნით მიიღებთ <abbr title="Operational Security">OPSEC</abbr> პრაქტიკას. სოციალური ინჟინერიის საფრთხეები, სადაც ვინმე ავტორიტეტული ფიგურად ცდილობს დაგემანიპულიროთ და მათ პირადი კრიპტოფრატული გასაღები მიეცით, რეალურია. ყოველთვის იყავით ფრთხილები და მოერიდეთ თქვენი პირადი გასაღების გაზიარებას, ისე მოექცევით მას, როგორც თქვენს საცხოვრებელ ფართის გასაღებს მხოლოდ სანდო პირებისთვის შეინახავთ.

დამატებითი ინფორმაციისათვის <abbr title="Operational Security">OPSEC</abbr> და მისი საუკეთესო პრაქტიკის შესახებ იხილეთ [ოპერაციული უსაფრთხოება ](./operational-security).

## კრიპტოგრაფიული გასაღების ციფრული შენახვა. {#storing-cryptographic-keys-digitally}

როდესაც საქმე ციფრული გასაღებების დაცვას ეხება, ძირითადად ხელმისაწვდომია მხოლოდ ორი მიდგომა: [SSH](https://www.ssh.com/) და [GPG](https://www.gnupg.org/). ეს მეთოდები უზრუნველყოფენ უსაფრთხოების ფენა თქვენს კრიპტოგრაფიულ გასაღებებზე უნებართვო წვდომის თავიდან ასაცილებლად.

ბევრი Iroha არქიტექტურული გადაწყვეტილება გავლენას ახდენს Secure Shell-ის (`SSH`) პროტოკოლის პრინციპებზე, რის გამოც ამ განყოფილებაში ძირითადად ყურადღება გამახვილებულია `SSH` მიდგომაზე. გთავაზობთ ინსტრუქციებს იმის შესახებ, თუ როგორ უნდა განახორციელოს თქვენი კრიპტოგრაფიული გასაღების შენახვის პროტოკოლი Iroha ეკოსისტემაში.

### გამოყენებით SSH და SSH აგენტი {#using-ssh-and-ssh-agent}

Secure Shell Protocol (`SSH`) არის კრიპტოგრაფიული ქსელის პროტოკოლი, რომელიც ემსახურება ვირტუალური შესასვლელად, რაც საშუალებას იძლევა უსაფრთხო წვდომა დისტანციურ აპარატებზე პოტენციურად არც თუ ისე უსაფრთხო ქსელების მეშვეობით SSH გასაღები წვდომის სანებართვო პირობების გამოყენებით. ეს უზრუნველყოფს სისტემებთან დისტანციური ურთიერთქმედების ეფექტურ გზას ფიზიკური ყოფნის აუცილებლობის გარეშე. ამ კონტექსტში `SSH` გთავაზობთ ორ ძირითად ავთენტიფიკაციის მექანიზმს: ტრადიციულ პაროლზე დაფუძნებულ მიდგომასა და უფრო უსაფრთხო საჯარო-პირადი გასაღები წყვილი მეთოდს.

დამატებითი ინფორმაცია `SSH`, იხილეთ [თან დაკავშირებული SSH აკადემიის თემა](https://www.ssh.com/academy/ssh).

შესასვლელის პროცესის გამარტივებისა და განმეორებითი შეყვანის აუცილებლობის გარდა, შესაძლებელია `SSH` კლავიატურების გაერთიანება SSH აგენტთან (`ssh-agent`)  ასისტენტის პროგრამით, რომელიც სესიის ხანგრძლივობის განმავლობაში იხსენებს თქვენს `SSH` კლავიატრებსა და/ან პაროლს. აღნიშნული დაყენება საშუალებას იძლევა `SSH` კარიბჭე ადვილად მიაღწიოს გასაღებს, როდესაც ის დაკავშირებულია სხვა აპარატებთან.

აქ მუშაობის მიმდინარეობა ასეთია: თქვენ გაქვთ თქვენი საჯარო გასაღები შენახული დისტანციურ სისტემაზე და ინარჩუნებთ თქვენს პირად გასაღებს უსაფრთხო. ყოველთვის, როდესაც გსურთ დისტანციის სისტემაში წვდომა, `ssh-agent` შედის იმისთვის, რომ თქვენი საჯარო გასაღები მიეწოდოს ხელმისაწვდომი სისტემას. დისტანციური სისტემა შემდეგ გამოგზავნის [ გამოწვევას](https://en.wikipedia.org/wiki/Challenge%E2%80%93response_authentication), რომელსაც მხოლოდ თქვენი პირადი გასაღები შეუძლია სწორად რეაგირება. თქვენი `ssh-agent` ამ გამოწვევას იყენებს თქვენს პირად გასაღებს და სწორი პასუხს გამოგზავნებს დისტანციის სისტემას. თუ რეაგირება შეესაბამება იმას, რასაც სისტემა ელოდა, თქვენ მიიღებთ წვდომას.

`ssh-agent` -ის სილამაზეა ის, რომ ის შენარჩუნებს თქვენს პირად გასაღებელს თქვენი სესიის დროს, ასე რომ არ არის აუცილებელი შეყვანა პაროლი ან პირადი გასაღების ფრაზა ყოველ ჯერზე, როდესაც მიერთდებით დისტანციურ სისტემას.

დამატებითი ინფორმაციისთვის იხილეთ `ssh-agent`, [, შესაბამისი SSH აკადემიის თემა](https://www.ssh.com/academy/ssh/agent).

::: info შენიშვნა

`SSH` პროტოკოლისა და `ssh-agent` ინსტრუმენტის დეტალური მიმოხილვისთვის იხილეთ შემდეგი თემები [SSH აკადემიის ](https://www.ssh.com/academy):

  - [რა არის SSH?](https://www.ssh.com/academy/ssh)
  - [ssh-აგენტი: როგორ კონფიგურაცია ssh-agent, აგენტის გადაგზავნა, & აგენტის პროტოკოლი](https://www.ssh.com/academy/ssh/agent)

:::

### პაროლი მენეჯერის პროგრამის დამატება {#adding-a-password-manager-program}

რეკომენდებულია თქვენი `SSH` საკვანძოების უსაფრთხოება გაძლიერდეს პაროლით მათი დაცვით, რაც დამატებით ხელს უშლის მავნე მხარეებს, რომლებიც მიზნად ისახავენ თქვენს საგრძნობი ინფორმაციის მოპოვებას.

მომხმარებლის პაროლების და `SSH` საკვანძოების დროებით შენახვისთვის შეიძლება გამოყენებულ იქნას სხვადასხვა პაროლის მენეჯერები. სიცხადის მიზნით, [KeePass](https://keepass.info/) გამოიყენება პაროლების მართვის მაგალითად, კერძოდ, Linux-ზე დაფუძნებულ ოპერაციულ სისტემებზე მომუშავე პორტი [KeePassXC](https://keepassxc.org/).

KeePassXC დაყენების ინსტრუქციისთვის იხილეთ ქვემოთ მოცემული განყოფილება [ კონფიგურაცია KeePassXC](#configuring-keepassxc).

![KeePassXC: `Main` ეკრანი UI](../../../img/KeePassXC.png)

KeePassXC უზრუნველყოფს გაძლიერებულ უსაფრთხოებას, მოქნილობასა და კონტროლს. იგი არამარტო ინახავს პაროლებს, არამედ ასევე `SSH` გასაღებს. როდესაც გამოიყენება საკვანძოების შენახვისთვის, ეს პაროლი მენეჯერი უზრუნველყოფს `ssh-agent` შენახულ გასაღებს, რომელიც შემდეგ დაუყოვნებლივ ამოღებულია მისი მეხსიერებიდან KeePassXC ფანჯრის დახურვისთანავე.

::: სათქმელი

თეორიულად, ნებისმიერი KeePass პორტები [ოფიციალურ ვებგვერდზე მითითებული](https://keepass.info/download.html) შეიძლება გამოყენებულ იქნას ძირითადი შენახვის მიზნით. ჩვენ გირჩევთ ნებისმიერი შემდეგი: [KeePassX](https://www.keepassx.org/) ან [KeePassXC](https://keepassxc.org/).

:::

#### კონფიგურაცია KeePassXC {#configuring-keepassxc}

KeePassXC კონფიგურაციისას, შეასრულეთ შემდეგი ნაბიჯები:

1. გაუშვით KeePassXC, შემდეგ გადადით ინსტრუმენტები > პარამეტრები, ან აირჩიეთ ღილაკი Gear ზედა UI პანელიდან.

2. აპლიკაციის პარამეტრების ჩანართში, რომელიც გამოჩნდება, აირჩიეთ SSH აგენტი მარცხენა მენიუდან და შემდეგ შეარჩიეთ განახლება SSH აგენტის ინტეგრაციის ობიექტი.

   ::: info სათაური ეკრანის გადაღება

   ![KeePassXC `SSH Agent` ჩანართი: SSH აგენტი](../../../img/keepassxc_ssh_agent.png) გაშვება

   :::

3. შეიქმნას ახალი KeePassXC მონაცემთა ბაზა. ინსტრუქციების მისაღებად იხილეთ [KeePassXC მომხმარებლის სახელმძღვანელო > თქვენი პირველი მონაცემთა ბაზის შექმნა](https://keepassxc.org/docs/KeePassXC_UserGuide#_creating_your_first_database).

4. თითოეული გასაღებისათვის, რომელიც გსურთ შეინახოთ შექმნილი KeePassXC მონაცემთა ბაზაში, შეასრულეთ შემდეგი ნაბიჯები:

   - დაამატეთ ახალი მითითება მონაცემთა ბაზაში. ინსტრუქციებისთვის იხილეთ [KeePassXC მომხმარებლის სახელმძღვანელო > თქვენი პირველი მონაცემთა ბაზის შექმნა](https://keepassxc.org/docs/KeePassXC_UserGuide#_creating_your_first_database).

   - ახალი ჩანაწერის დამატებისას, დაამატეთ ფაილი, რომელიც შეიცავს გასაღებს შემდეგნაირად: აირჩიეთ Advanced მარცხენა მენიუდან, შემდეგ აირჩიეთ Add in the Attachments განყოფილებაში, აირჩიეთ საჭირო ფაილი გამოჩენილი ფანჯრის "Select files"-ში.

   - ახალი ჩანაწერის დამატებისას აირჩიეთ SSH აგენტი მარცხენა მენიუდან, შემდეგ შეარჩიეთ საკვანძო ფაილი, რომელიც დაამატეთ მიერთების მენიუში კერძო გასაღები განყოფილებაში; შემდეგ აირჩიეთ შემდეგი ჩაკეტვა ყუთები:

      - დაამატეთ სააგენტოზე გასაღები მონაცემთა ბაზის გახსნის/გამორთვისას

      - ამოიღეთ გასაღები სააგენტოდან მონაცემთა ბაზის დახურვის/კეტვის დროს

      - მოითხოვოს მომხმარებლის მიერ დადასტურება, როდესაც ეს გასაღები გამოიყენება

   - საჭიროების შემთხვევაში, შეიტანეთ სხვა ცვლილებები ჩანაწერში.

   - როდესაც მზად არის, აირჩიეთ OK, რათა შეინახოთ ჩანაწერი.

   ::: details აჩვენეთ რეფერენციის ეკრანის გადაღებები

   ![KeePassXC `SSH Agent` ჩანართი: დამატება კერძო გასაღების დანართი](../../../img/keepassxc_pk_agent.png)

##### მოსალოდნელი შედეგები {#expected-results}

- კრიპტოგრაფიული და `shh` გასაღები შენახულია როგორც შეტყობინებები KeePassXC მონაცემთა ბაზაში, რომელზეც შესაძლებელია წვდომა, სანამ ფანჯარა KeePassXC ღიაა.

- შენახული კრიპტოგრაფიული და `ssh` გასაღები შეიძლება გამოყენებულ იქნას ნებისმიერ დროს, როდესაც ისინი საჭიროა ავტორიზაციისათვის.

- შენახული კრიპტოგრაფიული და `ssh` გასაღები ამოღებულია `ssh-agent` ფანჯრიდან, როგორც კი KeePassXC ფანჯარა დაიხურება.

::: info შენიშვნა

მომხმარებლის დადასტურების მოთხოვნის გარეშე, როდესაც ეს გასაღები გამოიყენება ვარიანტი, `ssh-agent` არ შეიძლება აკონტროლოს პროცესი, რომელმაც მას გასაღები მიაწოდა. იმ შემთხვევაში, თუ პაროლის მენეჯერის პროცესი შეწყდება მავნე პროგრამული უზრუნველყოფის ან სისტემური სერვისის მიერ `SIGKILL` სიგნალის საშუალებით, გასაღები სავარაუდოდ დარჩება `ssh-agent`-ში, რადგან UNIX სისტემის პროგრამები ვერ შეჭრენ `SIGKILL`.

:::

## კრიპტოგრაფიული გასაღების ფიზიკური შენახვა {#storing-cryptographic-keys-physically}

მათთვის, ვინც უმაღლესი დონის უსაფრთხოებას ცდილობს ოფლაინში, კრიპტოგრაფიული გასაღების შენახვის ვარიანტი ფიზიკურად უზრუნველყოფს, რომ გასაღები მთლიანად გაწყვეტილია ციფრული ქსელებისაგან და ამით მინიმუმამდეა მიყვანილი არაავტორიზებული წვდომის რისკი. ფიზიკური ვარიანტის აღიარება ხაზგასმით აღნიშნავს ჩვენს ვალდებულებას უზრუნველვყოთ უსაფრთხოების სხვადასხვა საჭიროებები.

### ტექნიკური გასაღების გამოყენება {#using-a-hardware-key}

ჩვენი გუნდი მიიჩნევს, რომ აპარატურული გასაღები უსაფრთხოების ერთ-ერთი საუკეთესო ზომაა. აპარატურის გასაღები - კომპაქტური მოწყობილობა, რომელიც დაკავშირებულია USB პორტის მეშვეობით და აქვს ტიპიური ფლეშ დრაივის ზომა. მხოლოდ უსაფრთხოებასთან დაკავშირებული მოვლენების გადამუშავება ხდება, როდესაც ის დაკავშირებულია მანქანასთან. ეს საშუალებას გაძლევთ მარტივად გათიშოთ მოწყობილობა უსაფრთხოების დარღვევის შემთხვევაში, ან უბრალოდ დაუკავშირდეთ მას სხვა აპარატს ნებისმიერ დროს, როდესაც ეს საჭიროა.

თუმცა, რადგან არსებობს მრავალი ბრენდი აპარატურული გასაღები, თითოეული მათგანის უნიკალური APIs, მნიშვნელოვანია ბაზრის შესწავლა იმისათვის, რომ იპოვოს ის გასაღება, რომელიც საუკეთესოდ შეესაბამება თქვენს საჭიროებებს.

ამ დრომდე, ჩვენს გუნდმა შიდა ტესტირება ჩაატარა [YubiKey 5C](https://www.yubico.com/il/product/yubikey-5c/) აპარატურული გასაღები რომელიც აღმოჩნდა ბევრი დადებითი მახასიათებელი, მათ შორის მრავალფეროვანი API ფუნქციონირების.

მიუხედავად ამისა, არსებობს პოტენციური ნაკლოვანება. [HMAC გამოწვევის რეაგირების ავტორიზაციის ](https://en.wikipedia.org/wiki/Challenge%E2%80%93response_authentication) დანერგვა და შესაბამისი კერძო გასაღები შენახვა ამ პასუხისთვის შეიძლება შექმნას დაუცველობა. აღნიშნული კონფიგურაცია შესაძლოა, თავდამსხმელებს უნებლიედ შეეძლოთ განათლებული ვარაუდების გაკეთება YubiKey 5C-ის მეხსიერებაში შენახული ინფორმაციის შესახებ, რითაც საფრთხე ემუქრებათ ზოგადი უსაფრთხოება.

საბედნიეროდ, ეს დაუცველობა შეიძლება შეამციროს YubiKey 5C გამოყენების ალტერნატიული მიდგომის მიღებით. იდეა არის გამოიყენოთ YubiKey 5C უსაფრთხო წვდომისთვის KeePassXC მონაცემთა ბაზაზე, სადაც შენახულია თქვენი კრიპტოგრაფიული და `SSH` გასაღები. ეს მეთოდი შეიძლება ითქვას სასარგებლოც კი, რადგან იგი აღემატება პაროლების უმეტესობის უსაფრთხოებას და აუცილებელია მავნე მხარისათვის თქვენი აპარატურის გასაღები იმ შემთხვევაში, თუ KeePassXC მონაცემთა ბაზა გაჟონვა.

### მნემონური ფრაზის გამოყენება {#using-a-mnemonic-phrase}

ალტერნატიულად, თქვენ შეგიძლიათ დაიმახსოვროთ პირადი გასაღები როგორც სიტყვების სერია, რომელიც ცნობილია როგორც მნემონიკური ფრაზა. ეს მეთოდი, რომელიც გამოიყენება ბევრ საფულეში, მოითხოვს დაახლოებით 25 კონკრეტული სიტყვის გახსენებას. პაროლების მენეჯერების უმეტესობა, მათ შორის ადრე განხილული KeePassXC, გთავაზობთ მნემონური პაროლის გენერაციას.
