# კრიპტოგრაფიული გასაღების შენახვა {#storing-cryptographic-keys}

კერძო გასაღები შეუძლია ავტორიზაცია ყველა ქმედება ნებადართული მისი ავტორიზაციის ხელმძღვანელი არასოდეს გაზიაროს კერძო საკეტი. დაიცვას თესლის მასალა, აღდგენის საიდუმლოებები, მფლობელის ტოკენები და ექსპორტირებული ფაილების იგივე ზრუნვით.

შეარჩიეთ სათავსო დიზაინი წარმოების დაწყებამდე. დიზაინი უნდა შეესაბამებოდეს რისკის ღირებულებას, ანგარიშის კონტროლის პოლიტიკას და განთავსების აღდგენის პროცესს.

## განსაზღვრეთ მზრუნველობის საზღვარი {#define-the-custody-boundary}

- შეინახეთ ინვენტარი თითოეული ავტორიზაციის ძირითადი, საჯარო გასაღები, ალგორითმი, გარემო, მიზანი, მფარველი, შენახვის ადგილმდებარეობა, სარეკლამო და შეცვლის პროცედურა.
- გამოიყენეთ ცალკე გასაღები განვითარების, ტესტის, წარმოების, რუტინული ოპერაციების, მმართველობის, განთავსებისა და აღდგენისთვის.
- მიეცით ადამიანებს და პროცესებს მხოლოდ მათი როლით მოთხოვნილ გასაღებად წვდომა.
- მოითხოვოს დამოუკიდებელი დამტკიცება მაღალი ღირებულების ან მმართველობის ხელმოწერისთვის, როდესაც ამას საჭიროებს რისკის მოდელი.
- აღრიცხეთ, რომელი ქსელისა და ავტორიტეტის გამოყენება შეუძლია ხელმომწერს. ხელმოწერის სერვისმა ამ მოქმედების ფარგლებს გარეთ არსებული მოთხოვნები უნდა უარყოს.

## აირჩიეთ შესაფერისი შენახვის მეთოდი {#choose-an-appropriate-storage-method}

ადგილობრივი განვითარების, კონტროლირებული ტესტების ან უსაფრთხო შენახვის გადაცემისათვის გასაღები შეიძლება ექსპორტირდეს ნებართვებით შეზღუდულ ფაილში. მხარდაჭერილი Unix პლატფორმაზე, შეიქმნას ახალი გასაღების დირექტორი `kagami`:

```bash
cargo run --bin kagami -- keys --algorithm ed25519 --out-dir ./client-key
```

მშობლიური დირექტორი უნდა არსებობდეს. სამიზნე უნდა იყოს ახალი ან უკვე არსებული მომხმარებლის საკუთრება, რეჟიმი `0700`, თავისუფალი სიმბოლური ბმულების და ცარიელი. Kagami წერს `public.key` და `private.key` რეჟიმით `0600`; `--pop` ასევე წერს `pop.hex`. ბრძანება არ მუშაობს პლატფორმებზე, სადაც Kagami ვერ ახორციელებს ფაილების სისტემის წესებს მხოლოდ მფლობელის მიერ.

კერძო გასაღების ფაილი არის გაუმშიფრებელი ექსპორტი. შეინახეთ იგი წყარო კონტროლის, საერთო საქაღალდეების, ლოგის, ბილეთების, ჩატისა და არტეფაქტებისგან. შეიტანეთ წარმოების გასაღები მის დამტკიცებულ შენახვის საზღვრებში, შემდეგ ამოიღეთ ექსპორტი განთავსების პროცედურის შესაბამისად. არ გამოიყენოთ განვითარების გასაღები პროდუქციაში.

წარმოებისათვის სასურველია აუდიტირებული დაცვის საზღვარი, როგორიცაა:

- აპარატურის უსაფრთხოების მოდული ან აპარატური მხარდაჭერილი საკვანძო მაღაზია
- ოპერაციული სისტემა ან მობილური საკვანძო მაღაზია
- ცალკე ხელმოწერის სერვისი
- საიდუმლო მენეჯერი, რომელიც გასაღებას მხოლოდ ავტორიზებულ სამუშაო დატვირთვას აძლევს.

შეინახეთ საკვანძო მასალა არექსპორტირებადი, როდესაც შერჩეული ინტეგრაცია მხარს უჭერს ამ თვისებას. დაადასტურეთ, რომ შენახვის სისტემა მხარს უწყობს ალგორითმსა და ხელმოწერის ოპერაციას, რომელიც მოითხოვს Iroha ავტორიზაციის პრინციპული.

ჩიფტირება დასვენების დროს იცავს შენახულ ასლს. ის არ იცავს გასაღებს, მას შემდეგ რაც არაავტორიზებული პროცესი ან ოპერატორი იღებს გაშიფრებულ ბაიტებს. გამკაცრდეს ჰოსტერი, შეზღუდოს შესრულების გარემოში წვდომა და აკონტროლოს ხელმოწერის აქტივობა.

## დაიცავით ხელმოწერის სამუშაო პროცესები {#protect-signing-workflows}

- გამოიყენეთ დასახელებული ოპერატორის ვინაობა, ძლიერი ავთენტიფიკაცია და აუდიტირებული წვდომა ხელმოწერის სისტემებზე.
- შეინახეთ ნედლეულის გასაღები ბრძანების ხაზის არგუმენტებში, ქელის ისტორიაში, გარემოს ჩამოტვირთვაზე, პროცესების ჩამონათვალებზე, ჩავარდნის ანგარიშებსა და აპლიკაციის დღიურებზე.
- კრიპტოგრაფიული ხელმოწერის გახსნა მხოლოდ საჭირო ოპერაციისთვის. სესიის დახურვა ან გამოყენების შემდეგ ამოწურვა.
- ნებართვის მიღებამდე აჩვენეთ ავტორიზაციის ხელმძღვანელი, ქსელი, ინსტრუქცია, აქტივები და საფასურები.
- საჭიროა პირდაპირი დადასტურება პრივილეგირებული ან მაღალი ღირებულების ტრანზაქციებისთვის.
- შეინახეთ ნედლეული კერძო გასაღები ბრაუზერის გვერდებისა და ზოგადი მიზნების აპლიკაციის პროცესების გარეთ, როდესაც მომხმარებელთა მორგებული ინტეგრაცია შეუძლია დელეგირება ხელმოწერის.

ღია ტექსტის კლიენტის კონფიგურაცია გამოდგება მხოლოდ ლოკალური შემუშავებისა და კონტროლირებადი ტესტებისთვის. საწარმოო ინტეგრაციამ ხელმოწერები უნდა მიიღოს დამტკიცებული დაცული შენახვის საზღვრის მეშვეობით. სტანდარტული Iroha CLI კითხულობს პირად გასაღებს კლიენტის კონფიგურაციიდან და ზოგად გარე ხელმომწერის ადაპტერს არ უზრუნველყოფს. სპეციალიზებულ კლიენტებს შეუძლიათ შექმნან ტრანზაქციის სასარგებლო დატვირთვის ჰეში და დაურთონ გარე ხელმომწერის მიერ შექმნილი ხელმოწერა.

## უკან დააბრუნე გასაღები {#back-up-and-recover-keys}

- ბეკაპი მხოლოდ იმ გასაღებს, რომელთა აღდგენის პოლიტიკა საჭიროა ბეკაპი.
- კოდირებული ბაკუპები და შეინახეთ ისინი ცალკე ცოცხალი კრიპტოგრაფიული ხელმოწერისგან.
- გამოიყენეთ იგივე წვდომისა და დამტკიცების კონტროლი სარეზერვო ფუნქციაზე, როგორც ცოცხალი გასაღები.
- აღდგენის მოწმობების დამოუკიდებელი დაცვის ქვეშ შენახვა, როდესაც საჭიროა გადასახადების განცალკევება.
- საცდელი რესტავრაცია წარმოების საკვანძო მასალის გამონახვის გარეშე.
- დაფიქსირეთ და გადახედეთ ყველა სარეზერვო შექმნა, წვდომა, აღდგენა და განადგურება.

არ ჩათვალოთ, რომ დაკავშირებული მფულე mnemonic ფორმატი შეიძლება წარმოადგენდეს Iroha კერძო გასაღები. გამოიყენეთ მხოლოდ აღდგენის ფორმატი მხარდაჭერილი და ტესტირებულია შერჩეული შენახვის სისტემის მიერ.

## შეცვალეთ გამოფენილი ან ამოღებული გასაღები. {#replace-exposed-or-retired-keys}

მომზადება შეცვლის წინ ინციდენტი. პროცედურა უნდა განსაზღვროს:

1. რომელსაც შეუძლია გამოაცხადოს, რომ გასაღები გაჟღენთილია ან ამოღებულია
2. როგორ იზოლირდება დაზიანებული კრიპტოგრაფიული ხელმოწერა
3. როგორ ხდება ახალი გასაღების შექმნა და დამტკიცებული დაცვის ქვეშ მოყვანა
4. ანგარიშისათვის, როგორ ქმნის ავტორიზებული კონტროლერის შეცვლა ან სოციალური აღდგენა შეცვლის კანონიკური `AccountId` და მიგრირებს დაკავშირებულ სახელმწიფოს
5. კვანძის ან ქსელის კვანძისთვის, როგორ არის ავტორიზებული ჯაჭვის კონსენსუს-კეტების როტაცია ან გამორთვა კოორდინირებული BLS PoP, აქტივაციის და გადახრის პოლიტიკა, ადგილობრივი საკეტის კონფიგურაცია, `trusted_peers_pop` და განლაგების ტოპოლოგია
6. როგორ მიიღებენ დამოკიდებული კონფიგურაციები, აპლიკაციები და ოპერატორები ახალ `AccountId`, საჯარო გასაღების ან ქსელის კვანძის ვინაობას;
7. როგორ მოიხსნება ძველი გასაღების ავტორიზაციის პრინციპული და მისი ასლები არქივდება ან განადგურებულია
8. როგორ ხდება ქსელის და დამოკიდებული აპლიკაციების შემდგომ შემოწმება

::: warning

დაშიფვრა ან ახალი პაროლი ვერ უზრუნველყოფს კოპირებული პირადი გასაღების უსაფრთხოებას. როდესაც ეჭვი ეპარება გამოხატვის შესახებ, შეწყვიტეთ გასაღების გამოყენება და დაიცავით დამტკიცებული ჩანაცვლების ან მოხსნის პროცედურა.

:::
