# ვირტუალური კერძო ქსელები {#virtual-private-networks}

ა <abbr title="Virtual Private Network">VPN</abbr> არის ქსელის კონტროლი, რომელიც
შეზღუდვები, რომლებსაც შეუძლიათ მიაღწიონ Iroha მომსახურება. ეს ყველაზე სასარგებლოა კერძო და
კონსორციუმის დანერგვა, სადაც დამტკიცებლები, აპლიკაციების ბაქტენდები და ოპერატორები
უნდა კომუნიკაცია პირად მისამართებზე, არა ღია ინტერნეტ მარშრუტებზე.

ა VPN არ შეიცავს Iroha პარტნიორების გასაღები, ანგარიშის გასაღებები, ნებართვები, ფაირვუალი
წესები, მონიტორინგი ან უსაფრთხო გასაღების შენახვა.
განთავსების საზღვარი: VPN შეამცირებს ქსელის ხელმისაწვდომობას, ხოლო Iroha
კონფიგურაცია და მმართველობა განსაზღვრავს, რომელ თანატოლებსა და ანგარიშებს ენდობიან.

## როდის უნდა გამოიყენოთ VPN {#when-to-use-a-vpn}

გამოიყენეთ A VPN როდესაც:

- დამტკიცებლები სხვადასხვა ორგანიზაციების მიერ ან სხვადასხვა ჰოსტინგში იმუშავებენ
  გარემო
- Torii უნდა იყოს ხელმისაწვდომი მხოლოდ აპლიკაციის backends, ოპერატორები ან საიმედო
  კლიენტები
- მეტრიკები, ლოგები, SSH, ან სხვა ადმინისტრაციული საბოლოო წერტილები უნდა დარჩეს კერძო
  ოპერატორის ქსელი
- საცდელი ან ეტაპობრივი ქსელი უნდა ჰგავდეს წარმოების წვდომის კონტროლს
  საჯარო საბოლოო წერტილების გამოხატვა

ა VPN საჯარო ქსელები შესაძლოა მიზანმიმართულად
გამოხატვა Torii საჯარო კარიბჭე, ტვირთის ბალანსერი ან რევერსული პროქსი.
ამ შემთხვევაში, შეინახეთ validator peer-to-peer მოძრაობა და ადმინისტრაციის საბოლოო წერტილები
შეზღუდული ქსელი, სადაც ეს შესაძლებელია.

::: tip

ბრაუზერი VPN მხოლოდ ამ ბრაუზერის ტრაფიკს იცავს.
`irohad`, CLI, SDK, SSH, მაჩვენებლები ან სათადარიგო ტრაფიკი, თუ ეს პროცესები არ არის
იგივე კერძო ქსელის მეშვეობით.

:::

## განთავსების ნიმუში {#deployment-pattern}

კერძო ვალიდატორის ქსელისათვის, თითოეულ ვალიდატორს მიეცით სტაბილური VPN მისამართი ან
კერძო DNS სახელი. კონფიგურაცია თანატოლები ისე, რომ მათი რეკლამირებული თანატოლური მისამართები
ამ ქსელის მეშვეობით სხვა ვალიდატორებისგან ხელმისაწვდომია:

```toml
trusted_peers = [
  "PUBLIC_KEY_1@10.20.0.11:1337",
  "PUBLIC_KEY_2@10.20.0.12:1337",
  "PUBLIC_KEY_3@10.20.0.13:1337",
  "PUBLIC_KEY_4@10.20.0.14:1337",
]

[network]
address = "10.20.0.11:1337"
public_address = "10.20.0.11:1337"

[torii]
address = "10.20.0.11:8080"
```

გამოიყენეთ მისამართი, რომელიც მიენიჭება მიმდინარე თანატოლს `network.address` და
`network.public_address`. თითოეულმა თანატოლმა უნდა დაასახელოს იგივე სანდო თანატოლების ვინაობა,
მაგრამ მისამართებით, რომლებიც ხელმისაწვდომია საკუთარი VPN საგზაო მაგიდა.

კლიენტი და CLI კონფიგურაციები უნდა მიუთითონ Torii საბოლოო წერტილი, რომლის საშუალებითაც მივაღწევთ
დასახელება VPN ან კონტროლირებადი შიდა კარიბჭის მეშვეობით:

```toml
torii_url = "http://10.20.0.11:8080"
```

თუ: Torii უნდა იყოს ხელმისაწვდომი გარეთ VPN, დააყენეთ იგი სათადარიგო პროქსი ან
ტვირთის ბალანსერი, რომელიც უზრუნველყოფს TLS, ავთენტიფიკაცია, საფასურის შეზღუდვა და ჩანაწერები.
პრეპარატის გამოყენებისას, არ უნდა გამოავლინოთ პირდაპირ პორტები ან მიწოდების ბოლო წერტილები.
საჯარო ინტერნეტი.

## საფეირვო კედლის წესები {#firewall-rules}

გამოიყენეთ ჰოსტისა და ღრუბლის ფაირვუალის წესები მაშინაც კი, როდესაც VPN არსებობს:

| მომსახურება | რეკომენდებული წვდომა |
| --- | --- |
| პორტი "პერ-ტუ-პერ" | სხვა ვალიდატორი VPN მხოლოდ მისამართები |
| Torii | აპლიკაციების ბექგენდები, ოპერატორები ან საიმედო კლიენტი VPN ფარგლებში |
| მაჩვენებლები და ჯანმრთელობის კონტროლი | ოპერატორის ქსელის მონიტორინგის სისტემები |
| SSH და ადმინისტრაცია | ბასტიონის მასპინძელი, პრივილეგირებული ოპერატორი VPN სფერო ან მინის დაშლის პროცესი |
| ბეკაპები და შენახვის რეპლიკაცია | სათადარიგო სისტემები კერძო ქსელში |

დეფოლტის უარყოფის წესები უფრო ადვილია აუდიტირდეს, ვიდრე ფართო ნებართვის წესები.
გაერთიანება ქსელში, განახლება VPN წევრობა, firewall ნებართვის სია და Iroha
საიმედო თანატოლების კონფიგურაცია, როგორც ერთი კოორდინირებული ცვლილება.

## ოპერაციული კონტროლის სია {#operational-checklist}

- აირჩიეთ აუდიტირებული და აქტიურად მოთავსებული VPN განხორციელება, როგორიცაა:
  WireGuard, IPsec, ან ორგანიზაციის მიერ დამტკიცებული მართული კერძო ქსელი.
- გამოიყენეთ უნიკალური VPN თითოეული მასპინძლისა და ოპერატორის საკრედიტო მონაცემები. არ გაზიაროთ VPN გასაღები
  ვალიდატორებს შორის.
- შენარჩუნება VPN საკრედიტო უფლებამოსილებები, რომლებიც განცალკევებულია Iroha კერძო გასაღები და გენეზის ხელმოწერა
  მასალა.
- მონიტორი VPN ლეტენცია, პაკეტის დაკარგვა, ხელახლა დაკავშირება და მარშრუტის ცვლილებები.
  მგრძნობიარე ქსელის გაგრძელებული არასტაბილურობის მიმართ.
- შეამოწმეთ ეფექტურობა MTU. პაკეტების ფრაგმენტაცია შეიძლება გამოიყურებოდეს როგორც დროებით თანასწორობა
  ან Torii წარუმატებლობები.
- დოკუმენტი, რომელიც VPN ტერიტორიები შეიძლება მიაღწიოს პერ-to-პერ, Torii, მაჩვენებლები,
  SSH, და სათადარიგო საბოლოო წერტილები.
- ბრუნვა VPN საკრედიტაციო მონაცემები მასპინძლის, ოპერატორის ან ორგანიზაციის გასვლისას
  ქსელი.
- ერიდეთ ერთსაც. VPN კარიბჭე, როგორც ერთადერთი მარშრუტი ვალიდატორებს შორის. გეგმა
  საწარმოო ქსელების გადამეტებული კარიბჭეები ან საიტიდან საიტამდე მარშრუტები.
- შეავსეთ VPN ჩავარდნა ინციდენტის რეაგირების წვრთნების დროს, რათა ოპერატორებმა იცოდნენ როდის უნდა
  განასხვავოს ქსელის პარტიცია Iroha პროცესის ჩავარდნა.
