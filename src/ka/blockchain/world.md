# მსოფლიო {#world}

`World` არის გლობალური სუბიექტი, რომელიც შეიცავს სხვა სუბიექტებს. `World`
შედგება:

- Iroha [კონფიგურაციის პარამეტრები](/ka/guide/configure/client-configuration.md)
- რეგისტრირებული თანატოლები
- რეგისტრირებული დომენები
- დარეგისტრირებული [გამამოძრავებელი](/ka/blockchain/triggers.md)
- დარეგისტრირებული
  [როლები](/ka/blockchain/permissions.md#permission-groups-roles)
- დარეგისტრირებული
  [ნებართვის ნიშნების განსაზღვრები](/ka/blockchain/permissions.md#permission-tokens)
- ნებართვის ნიშნები ყველა ანგარიშზე
- [გაშვების დროის ვალიდატორების ჯაჭვი](/ka/blockchain/permissions.md#runtime-validators)

როდესაც დომენები, თანატოლები ან როლები რეგისტრირებულია ან არ არის `World`
არის რეგისტრაციის (არ) მიზანი
[ინსტრუქცია](/ka/blockchain/instructions.md).

## მსოფლიო მდგომარეობის ხედვა (WSV) {#world-state-view-wsv}

World State View არის მეხსიერებაში წარმოდგენა მიმდინარე blockchain
სახელმწიფო. ეს მოიცავს `World`, ჩაბარებული ბლოკების ჰეშები, ტრანზაქციული ინდექსები;
და თანატოლები არჩეული დღევანდელი ეპოქისთვის. სრული ბლოკის სასარგებლო ტვირთები ემსახურება
Kura ნაცვლად დუბლიკაციისა, როგორც მუტირებადი WSV მონაცემები.

სააგენტო WSV ეს არის ის მდგომარეობა, რომ კითხვები წაიკითხა და რომ ბლოკის შესრულება mutates.
არ არის ჭეშმარიტების მუდმივი წყარო თვითონ.
[Kura](#kura-storage), და WSV შეიძლება აღდგეს Kura ბლოკები ან დატვირთული
სახელმწიფო snapshot და შემდეგ დაიჭირა მიერ replaying უფრო ახალი Kura ბლოკები.

### რაა ეს? WSV კვალი {#what-the-wsv-tracks}

სააგენტო WSV არის უფრო ფართო, ვიდრე `World` საგანი. პრაქტიკაში იგი შეიცავს:

- დასახელება `World`: პარამეტრები, თანატოლები, დომენები, ანგარიშები, აქტივები, NFTs, როლები,
  ნებართვები, გამშვები, განმახორციელებელი მონაცემები და სხვა რეგისტრირებული მონაცემთა მოდელი
  ობიექტები
- დადებული ბლოკის ჰეშები და ბოლო დადებული სიმაღლე
- ტრანზაქციების ბლოკირების ინდექსები, რომლებიც გამოიყენება შეკითხვებისა და მიღებების დროს
- ამჟამინდელი და წინა კომიტეტის ტოპოლოგია, რომელიც კონსენსუსით გამოიყენება
- ჩართული ბლოკებისგან მიღებული ინდექსები, როგორიცაა მონაცემთა ხელმისაწვდომობა
  ვალდებულებები, მიღების კურსორები, pin განზრახვები და შეკითხვის პროექციის მარკერები
- დეტერმინისტური ბლოკების შესრულებისთვის საჭირო გამშვები დროის კონფიგურაციის გადაღებები,
  კრიპტოგრაფია, მმართველობა, მილსადენი, შინაარსი, ანგარიშსწორება და Nexus
  პარამეტრები

შეკითხვები ჩვეულებრივ იღებს მხოლოდ წაკითხვის `StateView` ამ სტრუქტურებზე.
ნახვა არის თანმიმდევრული snapshot გამოკითხვის შესრულების; ეს არ საშუალებას პირდაპირი
მუტაცია WSV.

### როგორ WSV ცვლილებები {#how-the-wsv-changes}

WSV ცვლილებები განხორციელდება მანამ, სანამ ისინი ჩატარდება. ბლოკის შესრულება ქმნის
ბლოკის მასშტაბით სახელმწიფო overlay, და თითოეული მიღებული ტრანზაქცია გამოიყენება მისი
ინსტრუქციები ტრანზაქციის მასშტაბით განსაზღვრულ საფარში.
ოპერაციები იმავე ბლოკის კონტექსტში მიმდინარეობს. დროის გამომწვევები შეფასდება შემდეგ, რაც
ბლოკის ტრანზაქციის ეფექტები.

კონსენსუსის შემდეგ ბლოკი დადებულია, თანამოაზრე პირველ რიგში იკავებს დადებულ ბლოკს
დაწვრილებით Kura. თუ ეს ნაბიჯი არ შედგება, WSV არ არის განახლებული და
კონსენსუსის ბლოკი კვლავ ცდილობს ან მოითხოვს ბლოკის სასარგებლო დატვირთვას. როდესაც ბლოკი
მიღებული Kura რიგზე, Iroha გამოიყენება ბლოკის ეფექტები შესრულების შემდგომ,
განახლება წარმოშობითი ინდექსები, და აპირებს ეტაპობრივად WSV ცვლილებები a
ეს ხელს უშლის მკითხველს დააკვირდეს ნაწილობრივ ჩართულ
ბლოკ.

კონსენსუს-კრიტიკული წესი არის, რომ თანატოლები უნდა მიაღწიონ იმავე WSV სააგენტოდან
იგივე ჩართული ბლოკები. პირდაპირი ადგილობრივი რედაქტირება WSV მონაცემების შემოვლითი ინსტრუქციები და
გააჩნებს თანატოლების აზრთა სხვადასხვაობას ვალიდაციის ან განმეორებითი თამაშის დროს.

### დაწყება და გათამაშება {#startup-and-replay}

ოპვჟრთნაჲ, Iroha ინიციალიზებს Kura პირველი და ისწავლის შენახული ბლოკის სიმაღლე.
შემდეგ ის ცდილობს ატვირთოს მდგომარეობის სურათი. თუ არ არის ხელმისაწვდომი
გადაღება უარყოფითად ითვლება, როგორც აღდგენადი; Iroha ქმნის საწყის მდგომარეობას და
ჩაბარებული ბლოკების განახლება Kura. თუ სმარტფონი არის მოქმედი, მაგრამ უკან Kura,
მხოლოდ დაკარგული სიმაღლის დიაპაზონი იხსნება.

რეპლეი ადასტურებს თითოეულ შენახულ ბლოკს, აღადგენს ამ ბლოკის commit roster-ს
სიმაღლე, მოქმედებს ბლოკის ეფექტები WSV, და აპირებს შედეგად მიღებულ
ეს ნიშნავს, რომ Kura არის აღდგენის გზა WSV, მაშინ როდესაც snapshots არის
ოპტიმიზაცია, რომელიც თავიდან აცილებს მთელი ჯაჭვის განმეორებას.

## Kura შენახვა {#kura-storage}

_კურა_ არის Iroha ჟაჟრთმჲ ბლაკთრვ. ჟაჟთმჲ ჟაჟტმჲ ბლთაკთრვ და
აღდგენის მეტა მონაცემები. იგი არ ინახავს მეორე ცვალებად ასლს WSV.

Kura შენახვის საფუძველია [`kura.store_dir`](/ka/reference/peer-config/params.md#param-kura-store-dir).
ამ ფესვის შიგნით, ბლოკის მონაცემები იყოფა ზოლზე ან სეგმენტზე.
სეგმენტისთვის:

| გზა | მიზანი |
| --- | --- |
| `blocks/<segment>/blocks.data` | თანმიმდევრული Norito- ჟრანჟირებული ბლოკების სასარგებლო ტვირთები. |
| `blocks/<segment>/blocks.index` | მუდმივი ზომის `(start, length)` მითითებები, რომ რუკა ბლოკის სიმაღლე bytes in `blocks.data`. |
| `blocks/<segment>/blocks.hashes` | ბლოკე ჰაშები სიმაღლის მიხედვით სწრაფი ძებნის და სტარტაპის დასადასტურებლად. |
| `blocks/<segment>/blocks.count.norito` | მდგრადი commit მარკერი, რომელიც აღნიშნავს რამდენი ბლოკის ინდექსის მითითება უსაფრთხოა გამოყენებისთვის. |
| `blocks/<segment>/da_blocks/` | გამოყვანილი ბლოკის სასარგებლო ტვირთები, რომლებიც გარეთ ინახება `blocks.data` როდესაც დისკის ბიუჯეტის აღსრულება ძველ სხეულებს გადააქვს ცხელ ფაილში. |
| `blocks/<segment>/pipeline/sidecars.norito` და `sidecars.index` | საფეხმავლო ავტომობილები, რომლებიც აღდგენითი ბლოკების სიმაღლეზეა დამოკიდებული. |
| `blocks/<segment>/pipeline/roster_sidecars.norito` და `roster_sidecars.index` | ბლოკების სინქრონიზაციისა და განმეორებითი თამაშის დროს გამოყენებული უახლესი კომპიუტერული გვერდითი ავტომობილები. |
| `merge_ledger/<segment>.log` | გაერთიანების რეგისტრაციის ჩანაწერები განსაზღვრული ბლოკებით. |
| `commit-rosters.norito` | შენახული ვალდებულების სერტიფიკატები და ბოლო ბლოკებისთვის დამტკიცებელი საკონტროლო პუნქტები. |

Kura ინარჩუნებს კომპაქტური მეხსიერების ვექტორი ჯაჭვისთვის: თითოეულ სიმაღლეზე აქვს
ბლოკ ჰაში და, ვარიანტულად, ბლოკის სხეული. გენეზის ბლოკი რჩება დაცული,
და უახლესი [`kura.blocks_in_memory`](/ka/reference/peer-config/params.md#param-kura-blocks-in-memory)
არა-გენეზის ბლოკები თავიანთ სხეულებს მეხსიერებაში ინახავენ. უფრო ძველი ბლოკების სხეულები
და გადატვირთულია Kura დოკუმენტები საჭიროების შემთხვევაში.

ინიციალიზაციის დროს, `strict` რეჟიმი ადასტურებს შენახული ბლოკები ბლოკიდან
სასარგებლო ტვირთები და გადაწერს hash ფაილი, თუ საჭიროა. `fast` რეჟიმი იწყება შენახულიდან
hash/index მეტა მონაცემები და იწევს მკაცრი ინიციალიზაცია, თუ ეს მეტა მონაცემების
არ არის თანმიმდევრული. თუ Kura აღმოაჩენს დაზიანებულ კუდს, იგი სათავსო ჭურჭელს
უკანასკნელი დადასტურებული ბლოკი.

Kura ბლოკების წერა ფონზე მწერლის მეშვეობით.
სასარგებლო ტვირთები, ჰაშები და ინდექსის ჩანაწერები, შემდეგ წინ მდგრადი გათვლის მარკერი
კონფიგურირებული fsync პოლიტიკა. როდესაც დისკის ბიუჯეტის აღსრულება არის
აქტიური, Kura შეიძლება წაშალოს პენსიონერი სეგმენტები ან გამოიყვანოს უფროსი ბლოკის სხეულები
`da_blocks/` ჰეშების და ინდექსის შესატყვისთვის ხელმისაწვდომი შენარჩუნება
და ეძებს.
