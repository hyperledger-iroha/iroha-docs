# ანონიმური ტრანზაქციები {#anonymous-transactions}

ანონიმური ოპერაციები Iroha კონფიდენციალურ აქტივზეა აგებული
საჯარო ანგარიშზე გადარიცხვის ნაცვლად
საჯარო თანხები, ქაღალდი გადაიტანს ღირებულებას დაფარულ წიგნში და შემდეგ ხარჯავს
გაუმჭვირვალე შენიშვნები ნულოვანი ცოდნის მტკიცებულებით.

საჯარო წიგნი ჯერ კიდევ აღნიშნავს, რომ მოხდა კონფიდენციალური ოპერაცია.
აღწერს ვალდებულებებს, გაუქმებელს, მტკიცებულების ჰაშებს და მოვლენებს, მაგრამ არ
დაფიქსირდეს ბარათის მფლობელი, მიმღები ან თანხა ჩანთით-ჩანთით
ტრანზაქციის ჩვეულებრივი კონვერტზე შეიძლება კვლავ გაჟღერდეს წარდგენილი
ანგარიში, ასე რომ "ანონიმური" აქ ნიშნავს ანონიმურ აქტივების მოძრაობას და არა ავტომატურ
ქსელის ან ანგარიშის დონეზე ანონიმურობა.

## შენობის ბლოკები {#building-blocks}

| კონცეფცია            | ლიდერის წარმოდგენა                                                                                              |
| ------------------ | ------------------------------------------------------------------------------------------------------------------ |
| დაფარული ნოტა      | კერძო საფულე ჩანაწერი, რომელიც შეიცავს აქტივს, თანხას, მფლობელის მონაცემებს და შემთხვევითობას.                                   |
| ვალდებულება         | 32-ბაიტიანი საჯარო ღირებულება, რომელიც ჩანაწერზე ვალდებულია მისი ველების გამოცხადების გარეშე.                                        |
| ანულირებელი          | 32-ბაიტიანი საჯარო ღირებულება, რომელიც მიღებულია როდესაც ნოტა ხარჯულია. Iroha უარყოფს განმეორებით გამორიცხველებს, რათა თავიდან აიცილოს ორმაგი ხარჯვა. |
| მარკლის ფესვი        | ნვღჲ ოჲჟლვენა ჟრანთწრა ნა მფლობელთ.                        |
| მტკიცებულების დამონტაჟება   | ა `ProofAttachment` რომელიც შეიცავს მტკიცებულების ბაიტებს და დამატებით შემოწმების გასაღების რეფერენციას ან საშინაო გადამოწმების გასაკეტს.                 |
| კონფიდენციალური მოვლენა | წიგნის მოვლენა, როგორიცაა: `ConfidentialEvent::Shielded`, `Transferred`, ან `Unshielded`.                              |

ძირითადი ინსტრუქციები:

- `RegisterZkAsset`: რეგისტრირებს აქტივს, როგორც ZK-შეძლებადი და ვალდებული გადარიცხვა,
  ტყავის და უტყავის შემოწმების გასაღები.
- `Shield`: დააბრუნებს საჯარო ბალანსს და აერთიანებს დაცულ ნოტის ვალდებულებას.
- `ZkTransfer`: დაფარული ბანკნოტები ახალი ვალდებულებების ფარგლებში ხარჯავს.
- `Unshield`: დახარჯავს ფარდებული ნოტები და აძლევს საჯარო ანგარიშის ბალანსს.
- `ScheduleConfidentialPolicyTransition` და
  `CancelConfidentialPolicyTransition`: შეცვალოს აქტივის კონფიდენციალურობა
  პოლიტიკა მმართველობის საშუალებით.

აქტივების განსაზღვრა ასევე მოიცავს
[`AssetConfidentialPolicy`](/ka/reference/data-model-schema.md).
პოლიტიკის რეჟიმის კონტროლი, რომლის ნაკადებიც მოქმედებს:

| რეჟიმი              | მნიშვნელობა                                                          |
| ----------------- | ---------------------------------------------------------------- |
| `TransparentOnly` | მიღებულია მხოლოდ ჩვეულებრივი საჯარო ბალანსი და გადარიცხვები.          |
| `Convertible`     | მომხმარებელს შეუძლია გადაიტანოს ღირებულება საჯარო ბალანსებსა და დაცულ ნოტებს შორის. |
| `ShieldedOnly`    | აქტივების გამოშვება და გადარიცხვა უნდა დარჩეს დაცულ ლიტერატურაში.   |

## როგორ გამოიყენოთ ისინი {#how-to-use-them}

1. შეამოწმეთ კონფიდენციალური მხარდაჭერა ვალიდატორების კვანძებზე. ვალიდიტორები უნდა შეთანხმდნენ
   მამოწმებლის უკანა მხარე, აქტიური მამოწმებელი გასაღები, Poseidon/Pedersen პარამეტრი
   IDs, და კონფიდენციალური წესების ვერსია. კვანძები უარყოფენ თანატოლებს ან ბლოკებს
   არასწორი კონფიდენციალური თვისებების დიგესტები.
2. გამოაქვეყნეთ ან დაარეგისტრირეთ საკონტროლო გასაღები და პარამეტრების ნაკრები, რომლებიც გამოიყენება
   კარიბჭეები და ოპერატორები უნდა მიმართონ გასაღებს
   `VerifyingKeyId`, მაგალითად, `halo2/ipa:vk_transfer`.
3. დარეგისტრირეთ აქტივი როგორც ZK-შეძლებელია `RegisterZkAsset`, ან ეტაპი A
   პოლიტიკის გადასვლა `TransparentOnly` დაწვრილებით `Convertible` ან
   `ShieldedOnly`.
4. საჯარო ფონდების დაცვა `Shield`. ქაღალდი ქმნის ჩანაწერის ვალდებულებას
   და კოდირებული სასარგებლო ტვირთი მიმღებელს, სანამ ის წარუდგენს
   ოპერაცია.
5. გადარიცხვა კერძოდ `ZkTransfer`. კაპიკა აძლევს მტკიცებულებას, რომ
   ფლობს შესასვლელ ნოტებს, რომ შესასვლელი და გამოსასვლელი ღირებულებები ბალანსირდება და რომ
   ყოველი დახარჯული ნოტა დამყარებულია ახლახანდელი ვალდებულების ხეზე.
6. გათავისუფლება მხოლოდ მაშინ, როდესაც აქტივების პოლიტიკა ამის საშუალებას იძლევა. `Unshield` აჩვენებს
   საჯარო თანხა და მიმღების ანგარიში, ხარჯავს კერძო ნოტის ანულიფიკატორს,
   და შეუძლია შექმნას კერძო ცვლილებების გამომავალი.
7. აუდიტი კონფიდენციალურ მოვლენების, მტკიცებულებების ჩანაწერების, ანულირებელი სტატუსის კითხვით;
   და ანონიმური საფინანსო ანგარიშები ტიპირებული შეკითხვების მეშვეობით და Torii საბოლოო წერტილები.

## CLI მაგალითები {#cli-examples}

სააგენტო ZK CLI ბრძანებები განკუთვნილია ოპერატორის და სატესტო ნაკადებისთვის. წარმოება
საფულეებმა უნდა წარმოადგინონ ვალდებულებები, დაშიფვრილი სასარგებლო ტვირთები და მტკიცებულებები
საფულე/მასწავლებლის ბიბლიოთეკა მიღებული ინსტრუქციების წარდგენის წინ.

ჰიბრიდის რეგისტრაცია ZK-შეღავათიანი აქტივი:

```bash
iroha app zk register-asset \
  --asset <asset-definition-id> \
  --allow-shield true \
  --allow-unshield true \
  --vk-transfer halo2/ipa:vk_transfer \
  --vk-unshield halo2/ipa:vk_unshield \
  --vk-shield halo2/ipa:vk_shield
```

შეიქმნას ვერსია დაშიფრებული სასარგებლო ტვირთის კონვერტი დაცული შენიშვნა:

```bash
iroha app zk envelope \
  --ephemeral-pubkey 0101010101010101010101010101010101010101010101010101010101010101 \
  --nonce-hex 020202020202020202020202020202020202020202020202 \
  --ciphertext-b64 AQIDBA== \
  --print-json \
  --output note-envelope.bin
```

საჯარო ფონდების დაცვა აქტივის დაცულ მთავარ წიგნში:

```bash
iroha app zk shield \
  --asset <asset-definition-id> \
  --from <account-id> \
  --amount 1000 \
  --note-commitment ABABABABABABABABABABABABABABABABABABABABABABABABABABABABABABABAB \
  --enc-payload note-envelope.bin
```

## SDK მაგალითი {#sdk-example}

ზუსტი მტკიცებულების ბაიტები მოდის კონფიგურირებული მტკიცებულებების უკანასკნელი.
ტრანზაქციის სასარგებლო ტვირთისთვის საჭიროა მხოლოდ საჯარო შეყვანები და მტკიცებულების თანდართვა:

```rust
use iroha_data_model::{
    isi::zk::{Unshield, ZkTransfer},
    prelude::{AccountId, AssetDefinitionId, InstructionBox},
    proof::{ProofAttachment, ProofBox, VerifyingKeyId},
};

fn transfer_instruction(
    asset: AssetDefinitionId,
    input_nullifier: [u8; 32],
    output_commitment: [u8; 32],
    anchor_root: [u8; 32],
    proof_bytes: Vec<u8>,
) -> InstructionBox {
    let backend = "halo2/ipa".into();
    let proof = ProofBox::new(backend, proof_bytes);
    let vk = VerifyingKeyId::new("halo2/ipa", "vk_transfer");
    let attachment = ProofAttachment::new_ref("halo2/ipa".into(), proof, vk);

    ZkTransfer::new(
        asset,
        vec![input_nullifier],
        vec![output_commitment],
        attachment,
        Some(anchor_root),
    )
    .into()
}

fn unshield_instruction(
    asset: AssetDefinitionId,
    recipient: AccountId,
    amount: u128,
    input_nullifier: [u8; 32],
    anchor_root: [u8; 32],
    proof_bytes: Vec<u8>,
) -> InstructionBox {
    let backend = "halo2/ipa".into();
    let proof = ProofBox::new(backend, proof_bytes);
    let vk = VerifyingKeyId::new("halo2/ipa", "vk_unshield");
    let attachment = ProofAttachment::new_ref("halo2/ipa".into(), proof, vk);

    Unshield::new(
        asset,
        recipient,
        amount,
        vec![input_nullifier],
        attachment,
        Some(anchor_root),
    )
    .into()
}
```

## ანონიმური აქტივების გადახდა {#anonymous-asset-escrow}

ანონიმური აქტივების საფარდობო ფარგლებში გამოიყენება იგივე დაცული გადარიცხვის მანქანა
საფინანსო ანაზღაურების თანხა
საფინანსო ანგარიშსწორება, მაგრამ დაფინანსების, გათავისუფლების, გაუქმებისა და რეზოლუციის ფაზები
გამოიყენეთ დამცავი ანულიფიკატორები და გამონადენი ვალდებულებები.

დეტალური დაფარვისთვის ISI ქცევა და მაგალითები, იხილეთ
[ნაციონალური აქტივების გადახდა](/ka/blockchain/escrow.md#anonymous-escrow).

სიცოცხლის ციკლი:

1. `OpenAnonymousAssetEscrow` იხარჯება ფარდებული თანხის ბონუსები და ქმნის ერთ
   საფინანსო ვალდებულება.
2. `AcceptAnonymousAssetEscrow` მყიდველის ჩანაწერები.
3. `MarkAnonymousEscrowPaymentSent` ჩანაწერები, რომ მყიდველმა გადახდა გამოგზავნა
   ოფ-კეინიდან.
4. `ReleaseAnonymousAssetEscrow` ხარჯავს მყიდველის მიერ დადებული ვალდებულების საფინანსო ვალდებულება
   პროდუქტის მიღების ვალდებულებები.
5. `CancelAnonymousAssetEscrow` გადაიხდის საფარდობო ვალდებულებას გამყიდველს
   პროდუქტის მიღების ვალდებულებები, როდესაც გადახდა არ არის აღნიშნული.
6. `OpenAnonymousEscrowDispute` და `ResolveAnonymousEscrowDispute` ხელნაჭი
   სადავო საფარდობები მტკიცებულებების ჰაშებით და გამგებლის მიერ კონტროლირებადი გაყოფით.

გამოიყენეთ ანონიმური საფინანსო მოთხოვნები, რომლებიც მოცემულია
[კითხვები](/ka/reference/queries.md#escrow-and-proof-records) დავალიანების შემოწმება
დოკუმენტები და სტატუსი.

## მათემატიკის {#math}

ქვემოთ მოცემული ნოტაცია აღწერს კონფიდენციალურ აქტივების ნაკადებს.
გამოიყენეთ აქტიური მიმოხილვა და პარამეტრი IDs აქტივების პოლიტიკიდან და შემოწმებიდან
რეგისტრი, ასე რომ კლიენტები უნდა განიხილონ ვალდებულებები, nullifiers და დამტკიცების bytes
როგორც საფულე/პროცენტის არაგამჭვირვალე გამოსავალი.

დაფარული შენიშვნა შეიძლება აღწერილი იყოს როგორც:

$$
n = (\mathsf{asset}, \mathsf{amount}, \mathsf{owner}, \rho)
$$

სად `owner` მიიღება მიმღებ პირის მიერ ნახვის ან ხარჯვის მასალიდან და
`rho` ეს არის ნოტის შემთხვევითობა.

ბლოკზე აღებული ვალდებულება არის დამალული ვალდებულება:

$$
C = \mathsf{Commit}(\mathsf{asset}, \mathsf{amount}, \mathsf{owner}, \rho)
$$

ამჟამინდელი კონფიდენციალური გადაცემის ციკლებისათვის საჯარო შეყვანები მოიცავს:
აღნიშნული ვალდებულებები, ბათილებლები, მერკლის ფესვი, აქტივის თეგი და ჯაჭვური თეგი.
მიმოქცევა ამ ფორმის ვალდებულების ურთიერთობას იძულებს:

$$
C = H_c(\mathsf{amount}, \rho, \mathsf{owner\_tag}, \mathsf{asset\_tag})
$$

როდესაც ბარათი იხარჯება, საფულე იღებს ანულიფიკატორს:

$$
N = H_n(\mathsf{spend\_key}, \rho, \mathsf{asset\_tag}, \mathsf{chain\_tag})
$$

`N` საჯაროა. ის არ გვიჩვენებს ნოტას, მაგრამ ის სტაბილურია ამ ნოტისთვის
და ჯაჭვი, ასე რომ Iroha შეუძლია უარყოს მეორე დახარჯვა იმავე ანულიფიკატორით.

კაპიტანი აძლევს ვალდებულებას,
`C_i`, მტკიცებულება მოიცავს კერძო Merkle გზა `C_i` ბოლო პერიოდში
საჯარო ფესვი:

$$
\mathsf{MerkleRoot}(C_i, \mathsf{path}) = R
$$

დაფარულიდან დაფარულზე გადაცემის შემთხვევაში, მტკიცებულება ასევე აძლევს ღირებულებას
კონსერვაცია:

$$
\sum \mathsf{inputs} = \sum \mathsf{outputs}
$$

საჯარო თანხა შედის:

$$
\sum \mathsf{inputs} = \mathsf{public\_amount} + \sum \mathsf{private\_change}
$$

წარმოდგენილი მტკიცებულება შეიძლება შეჯამდეს შემდეგი სახით:

$$
\mathsf{Verify}(\mathsf{vk}, \mathsf{public\_inputs}, \pi) = \mathsf{true}
$$

სად `public_inputs` არის ვალდებულებები, ბათილებლები, ფესვი, აქტივების ტეგები,
ქათმის ჩანართი და ნებისმიერი საჯარო ფასი. მოწმე შეიცავს ნოტას
ფასი, შემთხვევითობა, მატერიალური ხარჯები და მერკლის გზები.
მტკიცებულება და შემდეგ მოუტაცია მთავარ წიგნს მდგომარეობა, დამატებით output ვალდებულებები და
შეღავათების ანულიფიკატორების გათვალისწინება ხარჯულად.

## რა არის საჯარო {#what-is-public}

ანონიმური ტრანზაქციები არ ხდის ყველა შესამჩნეველ ფაქტს პირად.
შემდეგი მონაცემები კვლავ შეიძლება იყოს საჯარო:

- ტრანზაქციის ჰეში, ბლოკის სიმაღლე და შეკვეთა
- გაცემული ოპერაციების ავტორი, თუ განაცხადი არ იყენებს
  კერძო შესასვლელი წერტილი ან რელეიერის ნიმუში
- გამოყენებული აქტივების განსაზღვრა
- ანულიფიკატორები და გამომუშავების ვალდებულებები
- დამტკიცების ჰეშები, საკვანძო რეფერენციები და ფულადი კონვერტის ჰეშები
- საჯარო თანხა და მიმღების ანგარიში `Unshield`
- ანონიმური საფინანსო გამყიდველი, მყიდველი, სტატუსი, დროის შტამპები და მტკიცებულებების ჰეშები

დიზაინის აპლიკაციები, ასე რომ ეს საჯარო მეტა მონაცემები არ გვიჩვენებს ბიზნესის
ურთიერთობა, რომლის დაცვასაც ცდილობ.
