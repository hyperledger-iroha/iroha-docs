# ფილტრები {#filters}

აფილტრებს შევიწრო მოვლენების ნაკადებს და განაპირობებს პირობებს.
მოვლენების ფილტრი არის `EventFilterBox`, რომელიც შეიძლება შეესაბამებოდეს ამ ღონისძიებების ოჯახებს:

- `Pipeline`
- `Data`
- `Time`
- `ExecuteTrigger`
- `TriggerCompleted`

გამოიყენეთ ყველაზე ვიწრო ფილტრი, რომელიც შეესაბამება სამუშაო პროცესს. ფართო ფილტრები, როგორიცაა
`DataEventFilter::Any` დიაგნოსტიკისთვის სასარგებლოა, მაგრამ ისინი ყველა მოვლენას ქმნიან
გადაიხადოს გათიშვის ან აბონენტთა შედარების ღირებულება.

## მონაცემთა მოვლენების ფილტრები {#data-event-filters}

`DataEventFilter` შეესაბამება რეგისტრაციის მონაცემთა მოვლენებს. მისი მიმდინარე ვარიანტები მოიცავს:

| ვარიანტი | მოვლენების ოჯახი |
| --- | --- |
| `Any` | ნებისმიერი მონაცემთა მოვლენა |
| `Peer` | თანატოლების ცხოვრების ციკლის მოვლენები |
| `Domain` | დომენის სიცოცხლის ციკლი და მეტა მონაცემების მოვლენები |
| `Account` | ანგარიშის სიცოცხლის ციკლი, მეტა მონაცემები, საიდუმლო და იდენტობის მოვლენები |
| `Asset` | აქტივების ბალანსი და მეტა მონაცემების მოვლენები |
| `AssetDefinition` | აქტივების განსაზღვრის სიცოცხლის ციკლი, პოლიტიკა და მეტა მონაცემების მოვლენები |
| `Nft` | NFT სიცოცხლის ციკლის მოვლენები და მეტა მონაცემები |
| `Rwa` | რეალურ სამყაროში აქტივების სიცოცხლის ციკლის მოვლენები |
| `Trigger` | ტრიგერების სიცოცხლის ციკლი და მეტა მონაცემთა მოვლენები |
| `Role` | როლების ცხოვრების ციკლის მოვლენები |
| `Configuration` | ქსელზე კონფიგურაციის მოვლენები |
| `Executor` | Runtime აღმასრულებელი მოვლენები |
| `Proof` | მტკიცებულების გადამოწმების სიცოცხლის ციკლის მოვლენები |
| `Confidential` | კონფიდენციალური აქტივების მოვლენები |
| `VerifyingKey` | რეგისტრაციის ღილაკების გადამოწმება |
| `RuntimeUpgrade` | გაშვების დროის განახლების მოვლენები |
| `Soradns` | რეზოლუციური დირექტორიის მართვის მოვლენები |
| `Sorafs` | SoraFS საგუშაგოების შესაბამისობის მოვლენები |
| `SpaceDirectory` | კოსმოსური დირექტორი სიცოცხლის ციკლის მოვლენების მანიფესტი |
| `Escrow` | მკაფიო ადგილობრივი აქტივების საფინანსო გადაცემის სიცოცხლის ციკლის მოვლენები |
| `Offline` | აუდიტორიული ანგარიშსწორების ღონისძიებები |
| `Oracle` | Oracle- ის შეღავათების მოვლენები |
| `Social` | ვირუსული სტიმულირების ღონისძიებები |
| `Bridge` | ხიდების ღონისძიებები |
| `Governance` | მმართველობის ღონისძიებები, როდესაც გამგებლობის ფუნქცია ჩართულია |

ბეტონის ფილტრების უმეტესობა ასევე საშუალებას იძლევა ვარიანტური ID მაჩერსა და ღონისძიების დადგმულ ნიღაბს.
მაგალითად, აქტივების ფილტრს შეუძლია შეესაბამოს ერთ აქტივს ან აქტივების მოვლენების კლასს;
მაშინ როდესაც საგამოძიებო ფილტრი შეიძლება შეესაბამებოდეს საგამოშვო ID და საგამოძრავებელი მოვლენების კომპლექტი.

## მილსადენის ფილტრები {#pipeline-filters}

მილსადენის ფილტრები შეესაბამება დამუშავების მოვლენებს, როგორიცაა ბლოკი, ტრანზაქცია, გაერთიანება,
და მოწმეების მოვლენები. გამოიყენეთ ისინი ოპერაციული აბონენტებისთვის, ბლოკ-პროცესინგისთვის
დაშბორდები, და გამშვები, რომლებიც რეაგირებენ მილსადენის მდგომარეობაზე და არა მთავრობის მონაცემებზე
ობიექტები.

## საფილტრები {#trigger-filters}

ტრიგერები ინახავენ თავიანთ მდგომარეობას როგორც `EventFilterBox`. აგრეთვე საგამოძრავებელი მოქმედება
მაღაზიები:

- აღსრულებადი
- განმეორების პოლიტიკა
- ორგანოს ანგარიში
- ვარიანტი დროის გათიშვის განმეორებითი მცდელობის პოლიტიკა
- მეტა მონაცემები

საგამოძრავებელი ორგანოს უნდა ჰქონდეს განხორციელებისათვის საჭირო ნებართვები.
უპირატესობა აქვს სპეციალურ ტექნიკურ ანგარიშებს ხანგრძლივი გამამოწვევებისათვის.

## გამოკითხვის ფილტრები {#query-filters}

გამოკითხვის ფილტრები განცალკევებულია მოვლენების ფილტრებისაგან. გადაცემული გამოკითხვები შეიძლება გამოავლინოს
პრედიკატისა და სელექტორის მხარდაჭერა. გამოიყენეთ შეკითხვის სპეციფიკური ტიპირებული ფილტრები SDK
ასე რომ ფილტრის შეღება ემთხვევა გამოშვების ტიპს.
