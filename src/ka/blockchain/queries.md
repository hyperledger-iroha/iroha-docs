# კითხვები {#queries}

მოვლენების აბონენტებს და ფილტრებს შეუძლიათ აკვირდნენ ცვლილებებს ბლოკჩეინის მდგომარეობაში. გამოიყენეთ მოთხოვნა, როდესაც თქვენ გჭირდებათ პირდაპირი ნახვა მიმდინარე მდგომარეობის შესახებ.

მოთხოვნები პატარა ინსტრუქციების მსგავსი ობიექტებია. გააგზავნეთ ერთი Iroha ქსელის კვანძზე, რათა მიიღოთ დეტალები მისი ამჟამინდელი მსოფლიო მდგომარეობის ხედვის შესახებ.

ქსელმა შეიძლება გამოავლინოს სხვა ინფორმაცია. მსოფლიოს სახელმწიფოების შესახებ ინფორმაციის მოძიება ერთადერთი სახის გარანტირებულია, რომელიც ყველა Iroha ქსელში იქნება ხელმისაწვდომი.

თითოეული Iroha განთავსებისას შეიძლება არსებობდეს სხვა ხელმისაწვდომი ინფორმაცია. მაგალითად, ტელემეტრიული მონაცემების ხელმისაწვდომობა დამოკიდებულია ქსელის ადმინისტრატორებზე. ეს მთლიანად მათი გადაწყვეტილებაა, უნდათ თუ არა გადანაწილდეს დამუშავების ძალა სამუშაოს თვალსაზრისით და არა მისი გამოყენებით რეალური სამუშაოს შესასრულებლად. ამის საპირისპიროდ, გარკვეული ფუნქციები ყოველთვის საჭიროა, მაგალითად, თქვენი ანგარიშის ბალანსზე წვდომა.

შეკითხვების შედეგები შეიძლება იყოს [დალაგებული](#sorting), [გვერდითი გვერდები](#pagination) და [ფილტრირებული](#filters) ერთდროულად. სორტირება ხორციელდება ლექსიკოგრაფიულად მეტამონაცემთა კლავიატურებზე. ფილტრირება შესაძლებელია სხვადასხვა პრინციპით, დომენის სპეციფიური (ადამიანური IP მისამართის ფილტრების ნიღაბები) დან ქვესტრიკის მეთოდებამდე, როგორიცაა `begins_with`, რომელიც კომბინირებულია ლოგიკური ოპერაციების გამოყენებით.

## განახორციელეთ ეს სამუშაო პროცესი Taira {#try-it-on-taira}

Taira გამოყოფს მხოლოდ წაკითხვის შეკითხვების დამხმარეებს JSON-ზე საერთო რესურსებისთვის. გამოიყენეთ ისინი პაჟირებისა და პასუხების მართვის შესაქმნელად, სანამ გაერთიანებთ SDK:

```bash
TAIRA_ROOT=https://taira.sora.org

curl -fsS "$TAIRA_ROOT/v1/accounts?limit=3" \
  | jq '{total, ids: [.items[].id]}'

curl -fsS "$TAIRA_ROOT/v1/domains?limit=3" \
  | jq '{total, domains: [.items[].id]}'

curl -fsS "$TAIRA_ROOT/v1/assets/definitions?limit=3" \
  | jq '{total, assets: [.items[] | {id, name, total_quantity}]}'
```

აპლიკაციის დიაგნოსტიკისთვის, შეინახეთ ეს სიგარეტის შემოწმება ხელმოწერილი ტრანზაქციული ტესტებისგან ცალკე. მხოლოდ წაკითხვის მოთხოვნის წარუმატებლობა ჩვეულებრივ მიუთითებს API საბოლოო წერტილის ხელმისაწვდომობაზე, ქსელის მისაღწევადობას ან მარშრუტის თავსებადობაზე, სანამ კრიპტოგრაფიული ხელმომწერის პარამეტრზე მიუთითებთ.

## შეიქმნას შეკითხვა {#create-a-query}

გამოიყენეთ SDK ან CLI-ის ტიპირებული მოთხოვნის შემქმნელები. მაგალითად, მიმდინარე მონაცემთა მოდელი ასახავს `FindAccounts` სარეკლამო ანგარიშებისთვის:

```rust
let query = FindAccounts;
```

Alice აქტივების მოძიების მაგალითი წარმოადგენს:

```rust
let alice_id = load_canonical_account_id_from_client_config()?;
let query = FindAssetsByAccountId::new(alice_id);
```

## გვერდების გათვლა {#pagination}

ცალკეული და მცირე იტერირებადი შეკითხვები, შეგიძლიათ გამოიყენოთ `client.request` წარადგინოს შეკითხვა და მიიღოს შედეგი ერთ სვლაში.

თუმცა ფართო იტერირებადმა მოთხოვნებმა, როგორიცაა `FindAccounts`, `FindAssets` ან `FindBlocks`, შეიძლება შედეგების დიდი ნაკრები დააბრუნოს. კვანძისა და კლიენტის დატვირთვის შესამცირებლად გამოიყენეთ გვერდებად დაყოფა.

`Pagination` კონსტრუქციის შესაქმნელად აუცილებელია გამოუწოდოთ `client.request_with_pagination(query, pagination)`, სადაც `pagination` შემდეგი წესით არის შემუშავებული:

```rust
let starting_result: u32 = _;
let limit: u32 = _;
let pagination = Pagination::new(Some(starting_result), Some(limit));
```

## ფილტრები {#filters}

როდესაც თქვენ შექმნით მოთხოვნას, შეგიძლიათ გამოიყენოთ ფილტრი მხოლოდ იმ შედეგების დაბრუნებისთვის, რომლებიც შეესაბამება მითითებულ ფილტრს.

ფილტრები კონკრეტული მოთხოვნის ტიპზეა დამოკიდებული. მაგალითად, ანგარიშების მოთხოვნები შეიძლება შეიზღუდოს ანგარიშის იდენტობით ან მეტამონაცემებით, ხოლო აქტივების მოთხოვნები — აქტივის განსაზღვრებით, მფლობელის ანგარიშით ან დომენის პროექციით. შეძლებისდაგვარად გამოიყენეთ SDK-ის ტიპიზებული მოთხოვნის შემქმნელები, რათა ფილტრის ტიპი მოთხოვნის შედეგის ტიპს შეესაბამებოდეს.

## დახარისხება {#sorting}

Iroha შეუძლია ლექსიკოგრაფიულად დაასორტიროს ელემენტები [მეტამონაცემები](/ka/blockchain/metadata.md)-თან, თუ შეკითხვის მშენებლობის დროს გასარკვევად საკვანძო მიუთითებთ. ტიპიური გამოყენების შემთხვევაა ანგარიშებისთვის `registered-on` მეტადატატის შესვლა, რომელიც დაასორდირების შემდეგ საშუალებას გაძლევთ ნახოთ ანგარიშის რეგისტრაციის ისტორია.

სორტირება მხოლოდ იმ სუბიექტებზე ვრცელდება, რომელთაც [მეტამონაცემები](/ka/blockchain/metadata.md) აქვთ, ვინაიდან მოთხოვნის შედეგების დასამუშავებლად გამოიყენება მეტამონაცემთა გასაღები.

თქვენ შეგიძლიათ შეურიგოთ სორტირება გვერდების დაფილტრებით. გაითვალისწინეთ, რომ სორტირება არის ვარიანტული მახასიათებელი, უმეტეს მოთხოვნებში გვერდების გამოყენებით ეს არ იქნება საჭირო.
