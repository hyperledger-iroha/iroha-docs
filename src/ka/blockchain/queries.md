# კითხვები {#queries}

მიუხედავად იმისა, რომ ბევრი ინფორმაცია blockchain-ის მდგომარეობის შესახებ შეიძლება იყოს
მიღებული, როგორც ჩვენ გვიჩვენა ადრე, გამოყენებით ღონისძიების აბონენტი და ფილტრი
შეამცირეთ მოვლენების ფარგლებში საინტერესო, ზოგჯერ თქვენ უნდა
ვ ოჲეაპაჟრთმ ჟრნა. _შეკითხვები_.

კითხვები არის პატარა ინსტრუქციის მსგავსი ობიექტები, რომ, როდესაც გაიგზავნა Iroha
ჟრანთ, მოგაწოდეთ პასუხი დეტალებით დღევანდელი მსოფლიო მდგომარეობის შეხედულებით.

ეს არ არის აუცილებლად ერთადერთი ტიპის ინფორმაცია, რომელიც ხელმისაწვდომია
ქსელი, მაგრამ ეს არის ერთადერთი სახის ინფორმაცია, რომელიც _გარანტირებული_ დაწვრილებით
ხელმისაწვდომია ყველა ქსელში.

თითოეული განთავსებისათვის Iroha, შეიძლება არსებობდეს სხვა ხელმისაწვდომი ინფორმაცია.
მაგალითად, ტელემეტრიული მონაცემების ხელმისაწვდომობა ქსელზეა დამოკიდებული
ადმინისტრატორები. მთლიანად მათი გადაწყვეტილებაა, სურთ თუ არა
გადამუშავების ძალა მიეყოს სამუშაოების შესაკვალებლად, ნაცვლად მისი გამოყენებისა
ამ მხრივ, გარკვეული ფუნქციები ყოველთვის საჭიროა.
თქვენი ანგარიშის ბალანსზე წვდომა.

შეკითხვების შედეგები შეიძლება იყოს [დალაგებული](#sorting), [გვერდითა დაწყება](#pagination)
და [გაფილტრებული](#filters) ერთდროულად ყველა პარტნიორი.
ლექსიკოგრაფიული მეთოდების გამოყენება. ფილტრირება შესაძლებელია სხვადასხვა
პრინციპები, დომენის სპეციფიკური (individual) IP მისამართის ფილტრების ნიღაბები)
ქვესტრილის მეთოდები, როგორიცაა: `begins_with` კომბინირებულია ლოგიკური ოპერაციების გამოყენებით.

## სცადე. Taira {#try-it-on-taira}

Taira გამოავლინებს მხოლოდ წაკითხვის შეკითხვების დამხმარეები over JSON საერთო რესურსებისთვის. გამოიყენეთ ისინი
პრაქტიკაში pagination და პასუხის მართვა სანამ wiring an SDK:

```bash
TAIRA_ROOT=https://taira.sora.org

curl -fsS "$TAIRA_ROOT/v1/accounts?limit=3" \
  | jq '{total, ids: [.items[].id]}'

curl -fsS "$TAIRA_ROOT/v1/domains?limit=3" \
  | jq '{total, domains: [.items[].id]}'

curl -fsS "$TAIRA_ROOT/v1/assets/definitions?limit=3" \
  | jq '{total, assets: [.items[] | {id, name, total_quantity}]}'
```

აპლიკაციის დიაგნოსტიკისთვის, შეინახეთ ეს სიგარეტის შემოწმება ხელმოწერილი ტრანზაქციიდან
ტესტები. ჩვეულებრივ, მხოლოდ კითხვაზე გამოძიების არარსებობა მიუთითებს საბოლოო წერტილის ხელმისაწვდომობაზე,
ქსელის ხელმისაწვდომობა ან მარშრუტის თავსებადობა, სანამ ის მიუთითებს ხელმომწერის პარამეტრზე.

## შეიქმნას შეკითხვა {#create-a-query}

გამოიყენეთ ტიპირებული შეკითხვების მშენებლები SDK ან CLI. მაგალითად, მიმდინარე მონაცემები
მოდელის ექსპოზიციები `FindAccounts` რეგისტრირების ანგარიშებისთვის:

```rust
let query = FindAccounts;
```

აქ არის მაგალითი კითხვის, რომელიც ალიცის ქონებას იპოვის:

```rust
let alice_id = load_canonical_account_id_from_client_config()?;
let query = FindAssetsByAccountId::new(alice_id);
```

## გვერდების გათვლა {#pagination}

ცალკეული და პატარა გამუდმებითი შეკითხვებისათვის შეგიძლიათ გამოიყენოთ `client.request`
შეკითხვის წარდგენა და შედეგის მიღება ერთჯერად.

თუმცა, ფართო iterable კითხვები, როგორიცაა `FindAccounts`, `FindAssets`, ან
`FindBlocks` შეიძლება დაბრუნდეს დიდი შედეგების ნაკრები. გამოიყენეთ pagination შეამციროს დატვირთვა
პერსა და კლიენტს.

აგრესიის შექმნა `Pagination`, შენ უნდა დარეკო
`client.request_with_pagination(query, pagination)`, სადაც `pagination`
კონსტრუქციაა შემდეგი:

```rust
let starting_result: u32 = _;
let limit: u32 = _;
let pagination = Pagination::new(Some(starting_result), Some(limit));
```

## ფილტრები {#filters}

როდესაც შექმნით შეკითხვას, შეგიძლიათ გამოიყენოთ ფილტრი მხოლოდ შედეგების დაბრუნებისთვის
რომელიც შეესაბამება მითითებულ ფილტრს.

ფილტრები შეკითხვების სპეციფიკურია. მაგალითად, ანგარიშის შეკითხვები შეიძლება შეზღუდული იყოს
ანგარიშის იდენტობა ან მეტა მონაცემები, ხოლო აქტივების გამოკითხვები შეიძლება შეზღუდული იყოს აქტივების მიხედვით
განსაზღვრა, მფლობელის ანგარიში ან დომენის პროექცია. გამოიყენეთ SDK შეკითხვაა დარეგისტრირებული
კონსტრუქტორები, სადაც ეს შესაძლებელია, რათა ფილტრის ტიპი შეესაბამებოდეს გამოშვების ტიპს.

## დახარისხება {#sorting}

Iroha შეიძლება საგნების დარიგება [მეტა მონაცემები](/ka/blockchain/metadata.md)
ლექსიკოგრაფიულად, თუ თქვენ მიაწოდებთ გასაღებს მშენებლობის დროს
ჩვეულებრივი გამოყენების შემთხვევაა, რომ ანგარიშებს აქვთ `registered-on`
მეტა მონაცემების შეღება, რომელიც, როდესაც დალაგებულია, საშუალებას გაძლევთ ნახოთ ანგარიში
რეგისტრაციის ისტორია.

განრიგება მხოლოდ იმ სუბიექტებზე ვრცელდება, რომელთაც
[მეტა მონაცემები](/ka/blockchain/metadata.md), როგორც მეტა მონაცემთა გასაღები გამოიყენება
შეკითხვის შედეგების დალაგება.

თქვენ შეგიძლიათ შეურიგოთ სორტირება გვერდების და ფილტრებით. გაითვალისწინეთ, რომ სორტირება
ამოცანა არ არის, პაჟირებით განთავსებული გამოკითხვების უმეტესობას ეს არ სჭირდება.
