# კითხვები {#queries}

მიუხედავად იმისა, რომ ბევრი ინფორმაცია ბლოკჩეინის მდგომარეობის შესახებ შეიძლება მოიპოვოთ, როგორც ჩვენ გვიჩვენეთ ადრე, გამოყენებით მოვლენების აბონენტისა და ფილტრის შეზღუდვის მიზნით საინტერესო მოვლენების ფარგლებში, ზოგჯერ თქვენ უნდა მიიღოთ უფრო პირდაპირი მიდგომა. შეიყვანეთ კითხვები.

კითხვები არის პატარა ინსტრუქციის მსგავსი ობიექტები, რომლებიც, როდესაც გაიგზავნა Iroha თანატოლს, მოუწოდებს პასუხი დეტალებით დღევანდელი მსოფლიო მდგომარეობის ხედვა.

ეს არ არის აუცილებლად ერთადერთი ტიპის ინფორმაცია, რომელიც ხელმისაწვდომია ქსელში, მაგრამ ეს არის ერთადერთი სახის ინფორმაცია, რომელსაც გარანტირებული აქვს ყველა ქსელში ხელმისაწვდომობა.

თითოეული Iroha განთავსებისას შეიძლება არსებობდეს სხვა ხელმისაწვდომი ინფორმაცია. მაგალითად, ტელემეტრიული მონაცემების ხელმისაწვდომობა დამოკიდებულია ქსელის ადმინისტრატორებზე. ეს მთლიანად მათი გადაწყვეტილებაა, უნდათ თუ არა გადანაწილდეს დამუშავების ძალა სამუშაოს თვალსაზრისით და არა მისი გამოყენებით რეალური სამუშაოს შესასრულებლად. ამის საპირისპიროდ, გარკვეული ფუნქციები ყოველთვის საჭიროა, მაგალითად, თქვენი ანგარიშის ბალანსზე წვდომა.

შეკითხვების შედეგები შეიძლება ერთდროულად იყოს [სორტირებული](#sorting), [გვერდებიანი](#pagination) და [ფილტრული](#filters) peer-side. სორტირება ხორციელდება ლექსიკოგრაფიულად მეტა მონაცემების გასაღებად. ფილტრირება შეიძლება განხორციელდეს სხვადასხვა პრინციპით, დომენის სპეციფიკიდან (ინდივიდუალური IP მისამართის ფილტრის ნიღაბები) ქვესტრიგების მეთოდებამდე, როგორიცაა `begins_with`, რომელიც კომბინირებულია ლოგიკური ოპერაციებით.

## სცადეთ Taira {#try-it-on-taira}

Taira გამოყოფს მხოლოდ წაკითხვის შეკითხვების დამხმარეებს JSON-ზე საერთო რესურსებისთვის. გამოიყენეთ ისინი პაჟირებისა და პასუხების მართვის შესაქმნელად, სანამ გაერთიანებთ SDK:

```bash
TAIRA_ROOT=https://taira.sora.org

curl -fsS "$TAIRA_ROOT/v1/accounts?limit=3" \
  | jq '{total, ids: [.items[].id]}'

curl -fsS "$TAIRA_ROOT/v1/domains?limit=3" \
  | jq '{total, domains: [.items[].id]}'

curl -fsS "$TAIRA_ROOT/v1/assets/definitions?limit=3" \
  | jq '{total, assets: [.items[] | {id, name, total_quantity}]}'
```

აპლიკაციის დიაგნოსტიკისთვის, შეინახეთ ეს სიგარეტის შემოწმება ხელმოწერილი ტრანზაქციის ტესტებისგან ცალკე. მხოლოდ წაკითხვის გამოკითხვის წარუმატებლობა ჩვეულებრივ მიუთითებს საბოლოო წერტილის ხელმისაწვდომობაზე, ქსელის მისაღწევად ან მარშრუტის თავსებადობაზე, სანამ ის მიუთითებთ ხელმომწერის პარამეტრზე.

## შეიქმნას შეკითხვა {#create-a-query}

გამოიყენეთ SDK ან CLI-ის ტიპირებული გამოკითხვის შემქმნელები. მაგალითად, მიმდინარე მონაცემთა მოდელი ასახავს `FindAccounts` სარეკლამო ანგარიშებისთვის:

```rust
let query = FindAccounts;
```

აქ არის მაგალითი გამოკითხვის, რომელიც ალიცის ქონებას იპოვნებს:

```rust
let alice_id = load_canonical_account_id_from_client_config()?;
let query = FindAssetsByAccountId::new(alice_id);
```

## გვერდების გათვლა {#pagination}

ცალკეული და მცირე iterable შეკითხვები, შეგიძლიათ გამოიყენოთ `client.request` წარადგინოს შეკითხვა და მიიღოს შედეგი ერთ სვლაში.

მიუხედავად ამისა, ფართო განმეორებადი გამოკითხვები, როგორიცაა `FindAccounts`, `FindAssets` ან `FindBlocks` შეიძლება დაბრუნდეს დიდი შედეგების ნაკრებები. გამოიყენეთ პაჟინაცია, რათა შეამციროთ დატვირთვა პარტნიორსა და კლიენტზე.

იმისათვის, რომ `Pagination` შეიქმნას, საჭიროა დარეკოთ `client.request_with_pagination(query, pagination)`, სადაც `pagination` არის შემდეგი:

```rust
let starting_result: u32 = _;
let limit: u32 = _;
let pagination = Pagination::new(Some(starting_result), Some(limit));
```

## ფილტრები {#filters}

როდესაც თქვენ შექმნით გამოკითხვას, შეგიძლიათ გამოიყენოთ ფილტრი მხოლოდ იმ შედეგების დაბრუნებისთვის, რომლებიც შეესაბამება მითითებულ ფილტრს.

ფილტრები შეკითხვების სპეციფიკურია. მაგალითად, ანგარიშის შეკითხვები შეიძლება შეზღუდული იყოს ანგარიშის იდენტობის ან მეტა მონაცემების მიხედვით, ხოლო აქტივების შეკითხვები შესაძლებელია შეზღუდულ იქნას აქტივების განსაზღვრის, მფლობელის ანგარიშის ან დომენის პროექციის მიხედვით . გამოიყენეთ SDK ტიპირებული გამოკითხვის მშენებლები, სადაც ეს შესაძლებელია, რათა ფილტრის ტიპი შეესაბამებოდეს გამოკითხვის გამოსავალი ტიპს.

## დახარისხება {#sorting}

Iroha შეუძლია ლექსიკოგრაფიულად დაასორტიროს ელემენტები [ მეტა მონაცემებით](/ka/blockchain/metadata.md), თუ შეკითხვის მშენებლობის დროს მიუთითებთ გასაღებს. ტიპიური გამოყენების შემთხვევა არის ანგარიშებისთვის `registered-on` მეტა მონაცემთა შესვლა, რომელიც, როდესაც დაასორდირდება, საშუალებას გაძლევთ ნახოთ ანგარიშის რეგისტრაციის ისტორია .

დარიგება მხოლოდ იმ სუბიექტებზე ვრცელდება, რომელთაც [ მეტა მონაცემები](/ka/blockchain/metadata.md) აქვთ, რადგან მიმოხილვის შედეგების დარიგებისთვის გამოიყენება მეტა მონაცემთა გასაღებები.

თქვენ შეგიძლიათ შეურიგოთ სორტირება გვერდების დაფილტრებით. გაითვალისწინეთ, რომ სორტირება არის ვარიანტული მახასიათებელი, უმეტეს გამოკითხვებში გვერდების გამოყენებით ეს არ იქნება საჭირო.
