# ანგარიშები {#accounts}

ანგარიში არის ავტორიზაციის პრინციპალი, რომელსაც შეუძლია ხელი მოაწეროს ტრანზაქციებს და ფლობდეს ბლოკჩეინის რეესტრის მდგომარეობას. მიმდინარე Iroha 3 მონაცემთა მოდელში, `AccountId` არის კანონიკური და დომენების გარეშე: ის გამომდინარეობს ანგარიშის კონტროლისგან და კოდირებულია კანონიკური ფორმით [I105](/ka/reference/i105.md). ადამიანის მიერ წაკითხადი დომენის და მონაცემთა სივრცის კონტექსტი განეკუთვნება ცალკეულ ანგარიში-სასურველი ბმულებს.

## სტრუქტურა {#structure}

რეგისტრირებული `Account` შეიცავს:

- `id`: კანონიკური `AccountId`
- `metadata`: ვაკანსიური ანგარიშის მეტამონაცემები
- `label`: ნებაყოფლობითი სტაბილური ალიასი
- `uaid`: ვარიანტური უნივერსალური ანგარიშის ID, რომელიც გამოიყენება Nexus ნაკადების მიერ
- `opaque_ids`: გაუმჭვირვალე იდენტიფიკატორები, რომლებიც დაკავშირებული არიან ანგარიშის UAID

ანგარიშის შესაქმნელად გამოყენებული ტრანზაქციის დატვირთვა არის `NewAccount`. იგი შეიცავს იმავე იდენტობას, მეტამონაცემებს, ეტიკეტს, UAID და არაგამჭვირვალე ID ველებს, რომლებიც რეგისტრირებულ ანგარიშში გამოიყენება.

`uaid` შეავსებს კანონიკურ `AccountId`; იგი არ შეცვლის მას. გამოიყენეთ ის, როდესაც Nexus სერვისებს სჭირდებათ სტაბილური მომხმარებლის ან ორგანიზაციის მენეჯლი მონაცემთა სივრცეებში, კონფიდენციალურობის დაცვის რეგისტრაცია ან მომსახურების შესაძლებლობების ძებნა. შესრულების გარემო ინარჩუნებს UAID ერთ-ერთზე ანგარიშის ინდექსს, მოითხოვს გამჭვირვალე იდენტიფიკატორების ჩართვას UAID, და უარყოფს ორმაგი ან შეჯახებული გამჭვირვალი იდენტიფექციები. იხილეთ [FHE და UAID](/ka/blockchain/sora-nexus-services.md#fhe-and-uaid) Nexus მომსახურების ფენის ნაკადის შესახებ.

## ანგარიშის კონტროლერები {#account-controllers}

კონტროლერი განსაზღვრავს, თუ როგორ ავტორიზებს ანგარიში ქმედებებს. დეფოლტური კლიენტის ნაკადი იყენებს Ed25519 საკვანძო წყვილს, მაგრამ მონაცემთა მოდელი ასევე მხარს უჭერს უფრო მდიდრ კონტროლერებს, როგორიცაა მრავალხელმოწერის პოლიტიკის კონტროლორები.

კლიენტის კონფიგურაცია ინახავს ხელმოწერის ავტორიზაციის პრინციპს ქსელის კვანძების კონფიგურისგან ცალკე:

```toml
[account]
public_key = "ed0120..."
private_key = { digest_function = "ed25519", payload = "..." }
```

იხილეთ [კლიენტის კონფიგურაცია](/ka/guide/configure/client-configuration.md) და [საკვანძო თაობა](/ka/guide/security/generating-cryptographic-keys.md) ამჟამინდელი საკვანძო ფორმატებისთვის.

## განახორციელეთ ეს სამუშაო პროცესი Taira {#try-it-on-taira}

ჩამოთვალეთ რამდენიმე კანონიკური ანგარიშის ID საჯარო Taira ტესტის ქსელიდან:

```bash
curl -fsS 'https://taira.sora.org/v1/accounts?limit=5' \
  | jq -r '.items[] | [.id, (.primary_alias // "-")] | @tsv'
```

ანგარიშის აქტივების შესამოწმებლად, გადაწერეთ ანგარიშის ID პირველი ტექნიკური მოწოდებიდან და URL - კოდირდით იგი გზაზე განთავსებამდე. ეს Python ნაწყვეტი ამას აკეთებს პირველ ჩამოთვლილ ანგარიშზე:

```bash
python3 - <<'PY'
import json
import urllib.parse
import urllib.request

root = "https://taira.sora.org"
accounts = json.load(urllib.request.urlopen(f"{root}/v1/accounts?limit=1"))["items"]
account_id = accounts[0]["id"]
encoded = urllib.parse.quote(account_id, safe="")
assets = json.load(
    urllib.request.urlopen(f"{root}/v1/accounts/{encoded}/assets?limit=5")
)

print(json.dumps({"account_id": account_id, "assets": assets["items"]}, indent=2))
PY
```

ეს არის საჯარო წაკითხვები. ანგარიშის შექმნა ან განახლება ხელმოწერილი ოპერაციაა და მოითხოვს ტესტნეტის მიერ დაფინანსებულ Taira ინსტრუქციას, რომელიც აღწერილია [დაკავშირება SORA Nexus მონაცემთა სივრცეებთან](/ka/get-started/sora-nexus-dataspaces.md).

## რეგისტრაცია და ნებართვები {#registration-and-permissions}

ანგარიშები რეგისტრირებულია და არ არის რეგისტრებული გენერიკთან [`Register` და `Unregister`](/ka/blockchain/instructions.md#un-register) ინსტრუქციები. აქტიური შესრულების გარემოს ვალიდატორს გადაწყვეტს ვის შეუძლია შექმნას ანგარიშები და რა ნებართვის ტოქენები ან როლებია საჭირო.

რეგისტრაციის შემდეგ, ანგარიშს შეუძლია:

- ტრანზაქციების გაფორმება
- ქონება
- საკუთარი დომენები
- მიიღოს როლები და ნებართვის ტოკენები
- შენახვის მეტამონაცემები
- მონაწილეობა მიიღოს ალიასი, გასაღების შეცვლა, აღდგენა და Nexus იდენტობის ნაკადებში, როდესაც ეს მახასიათებლები ჩართულია;

## პირადობის პრობლემების აღმოფხვრა {#troubleshooting-identity-issues}

თუ ტრანზაქცია მოულოდნელად უარყოფითია, შეამოწმეთ, თუ:

- კლიენტის საჯარო გასაღები შეესაბამება ხელმოწერისთვის გამოყენებულ პირად გასაღებს
- ანგარიში იყო დარეგისტრირებული ბლოკჩეინ გენეზში ან საბოლოო ტრანზაქციით.
- ავტორიზაციის ხელმძღვანელს აქვს ინსტრუქციის მიერ მოთხოვნილი ნებართვები
- მკაცრი ანგარიშის ველები იყენებენ კანონიკური I105 ანგარიშის ID- ს, ხოლო კითხვადი სახელების გადაჭრა ხდება აქტიური ანგარიშის ალიასის ბმით-ით
