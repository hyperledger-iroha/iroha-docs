# ნებართვები {#permissions}

ანგარიშებს სჭირდებათ ნებართვის ტოქნები სხვადასხვა ქმედებებისთვის ბლოკჩეინზე, მაგალითად
ქონების დამუშავება ან დაწვა.

არსებობს განსხვავება საჯარო და კერძო ბლოკჩეინს შორის
მომხმარებელს მინიჭებული ნებართვები. საჯარო ბლოკჩეინში, ანგარიშების უმეტესობა
იგივე ნებართვების ნაკრები. კერძო ბლოკჩეინში, ანგარიშების უმეტესობა
დადგენილია, რომ მათთვის მინიჭებული უფლებამოსილების მიღმა არაფრის გაკეთება შეუძლიათ
გარდა იმისა, რომ შესაბამისი ნებართვა გამოხატულია.

ნებართვის მიღება ნიშნავს, რომ ანგარიშს აქვს
შესაბამისი `Permission`. ნებართვა შეიძლება გაიცემოს პირდაპირ ან
[`Role`](#permission-groups-roles), რომელიც შეკრებს ნებართვების ერთეულს.
ნებართვა გაიცემა `Grant` განათლება. ნებართვები და როლები
არ ამოიწუროს; მოაშორეთ ისინი ერთად `Revoke` ინსტრუქცია.

## ნებართვის ტოქნები {#permission-tokens}

ნებართვის ნიშნები არის ტიპირებული ობიექტები განსაზღვრული აქტიური აღმასრულებელი. ზოგიერთი
ტოქნები გლობალურია, როგორიცაა: `CanManagePeers`, და სხვები მიზნად ისახავს
კონკრეტული ლიდერის ობიექტი, როგორიცაა ანგარიში, აქტივი, აქტივის განსაზღვრა, დომენი;
NFT, როლი, ან გამომწვევი.

აქ მოცემულია რამდენიმე მაგალითი პარამეტრების გამოყენებული სხვადასხვა ნებართვის ტოქენებისთვის:

- ტოკი, რომელიც აძლევს ნებართვას კონკრეტული ანგარიშის მეტა მონაცემების შესწორებისთვის
  ატარებს `account` ველი:

  ```json
  {
    "account": "<AccountId>"
  }
  ```

- ტოქენი, რომელიც აძლევს საშუალებას გადარიცხოს აქტივები კონკრეტული აქტივისთვის
  განსაზღვრა ატარებს `asset_definition` ველი:

  ```json
  {
    "asset_definition": "<AssetDefinitionId>"
  }
  ```

- გლობალური ტოკი, როგორიცაა `CanManagePeers` არ აქვს ველები:

  ```json
  {}
  ```

### წინასწარ კონფიგურებული ნებართვის ტოქნები {#pre-configured-permission-tokens}

თქვენ შეგიძლიათ იპოვოთ ჩამონათვალი წინასწარ კონფიგურირებული ნებართვის ტოქენები [რეფერენცია](/ka/reference/permissions) თავი.

## ნებართვის ჯგუფები (ფუნქციები) {#permission-groups-roles}

ნებართვების ერთეულს ეძახიან **როლი**. ანალოგიურად ნებართვის ქაღალდებს,
როლები შეიძლება მიენიჭოს გამოყენებით `Grant` მითითება და გაუქმდა გამოყენებით
`Revoke` ინსტრუქცია.

ანგარიშზე როლის მინიჭებამდე, პირველ რიგში უნდა იყოს რეგისტრირებული.

როლები სასარგებლოა, როდესაც რამდენიმე ანგარიში უნდა მიიღოს იგივე ნებართვა
დაწესდეს როლი ერთხელ, მიეცეთ ნებართვები როლს და შემდეგ მიეცით ან
გააუქმოს ფუნქცია ინდივიდუალურ ანგარიშებზე.

### დარეგისტრირდით ახალ როლს {#register-a-new-role}

აჱ ეა ოჲეპაგთმ ნვღჲ ოპვრთნარა როლა, კჲდარჲ, კჲდაკჲა ნაოპაგთმ, ვ ჲოთრგევმ ჟალთ.
ხელმისაწვდომობა [მეტა მონაცემები](/ka/blockchain/metadata.md) მაუსის ანგარიშში:

```rust
let role_id = RoleId::from_str("ACCESS_TO_MOUSE_METADATA")?;
let role = iroha_data_model::role::Role::new(role_id.clone(), mouse_id.clone())
    .add_permission(CanModifyAccountMetadata {
        account: mouse_id.clone(),
    });
let register_role = Register::role(role);
```

### გადმოგეცით როლი {#grant-a-role}

კაჟრაჲ ეა დჲ ნაოპაგთ, მაუჟა მჲზვ ეა დჲ ნაპაგთ ალის:

```rust
let grant_role = Grant::account_role(role_id, alice_id);
let grant_role_tx = TransactionBuilder::new(chain_id, mouse_id)
    .with_instructions([grant_role])
    .sign(mouse_private_key);
```

## ნებართვის ვალიდატორები {#permission-validators}

ნებართვები არსებობს ისე, რომ მხოლოდ ანგარიშები საჭირო ნებართვის token
შეუძლია განახორციელოს დაცული ქმედება. დეფოლტური აღმასრულებელი აკონტროლებს ნებართვებს
ინსტრუქციის, შეკითხვის და გამოხატვის შესრულების დროს.

რეგისტრირებული მონაცემთა ბაზა

- პარტნიორთა მართვა
- დომენები და ანგარიშები
- აქტივები, NFTs, და საფარდნოები
- გამამოძრავებელი
- როლები და ნებართვები
- აღმასრულებელი/სამუშაო დრო, მტკიცებულებები, ხიდები და SORA/Nexus მოდულები

ზუსტი ტოქნების სია არის წყარო-დაჭერული
[ნებართვის ტოქნების მითითება](/ka/reference/permissions.md).

### გაშვების დროის ვალიდატორები {#runtime-validators}

ნებართვის შემოწმება ახორციელებს აქტიური აღმასრულებელი.
აღსრულებელი უზრუნველყოფს ჩაშენებულ ნებართვის ვალიდატორებსა და ტოქნის განსაზღვრებს,
და ქსელს შეუძლია შეცვალოს პოლიტიკა მისი გამოყენების მიერ განახლების საშუალებით.

ვალიდატორები უბრუნებენ **დამტკიცების განაჩენი**. ვალიდატორს შეუძლია
ოპერაცია, უარყოფითი მიზეზით, ან გადატოვება თუ ოპერაცია გარეთ
ამ კანდიდატის სფერო. შერჩეული მოსამართლე ამ განაჩენებს აერთიანებს
გადაწყვიტოს, შეიძლება თუ არა განცხადება, შეკითხვა ან გამოთქმა გაგრძელდეს.
