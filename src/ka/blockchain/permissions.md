# ნებართვები {#permissions}

ანგარიშებს სჭირდებათ ნებართვის ნიშნები სხვადასხვა ქმედებებისთვის ბლოკჩეინზე, მაგალითად, აქტივების გამოცემის ან განადგურებისათვის.

საჯარო და კერძო ბლოკჩეინებს შორის განსხვავება არსებობს მომხმარებლებისთვის მინიჭებული ნებართვების თვალსაზრისით. საჯარო ბლოკჩეინში, უმეტეს ანგარიშებს აქვთ ერთი და იგივე ნებართვები. კერძო ბლოკჩეინში, უმეტეს ანგარიშებს არ აქვთ შესაძლებლობა გააკეთონ რაიმე მათთვის მინიჭებული ავტორიზაციის პრინციპის გარეთ, თუ მათ კონკრეტულად არ მიენიჭათ შესაბამისი უფლება.

ნებართვის მიღება ნიშნავს, რომ ანგარიშს აქვს შესაბამისი `Permission`. ნებართვა შეიძლება უშუალოდ ან პირდაპირ [`Role`](#permission-groups-roles), რომელიც აერთიანებს ნებართვების ერთეულს. ნებართვები გაიცემა `Grant` ინსტრუქციით. ნებართვები და როლები არ ვრცელდება; ამოიღეთ ისინი `Revoke` ინსტრუქციით.

## ნებართვის ტოკენები {#permission-tokens}

ნებართვის ტოკენები არის ტიპირებული ობიექტები, რომლებიც განსაზღვრულია აქტიური აღმასრულებლის მიერ. ზოგიერთი ქაღალდი გლობალურია, როგორიცაა `CanManagePeers`, ხოლო სხვები განკუთვნილია კონკრეტულ ბლოკჩეინის რეესტრის ობიექტზე, როგორიცაა ანგარიში, აქტივი, აქტივის განსაზღვრა, დომენი, NFT, როლი ან გამშვები.

აქ მოცემულია პარამეტრების რამდენიმე მაგალითი, რომლებიც გამოიყენება სხვადასხვა ნებართვის ტოკენებისთვის:

- ქაღალდი, რომელიც აძლევს ნებართვას კონკრეტული ანგარიშის მეტამონაცემების შეცვლისთვის, შეიცავს ველს `account`:

  ```json
  {
    "account": "<AccountId>"
  }
  ```

- ქონების განსაზღვრისთვის აქტივების გადაცემის ნებართვის მინიჭებული ტოკი შეიცავს `asset_definition` ველს:

  ```json
  {
    "asset_definition": "<AssetDefinitionId>"
  }
  ```

- გლობალური ტოქნი, როგორიცაა `CanManagePeers`, არ შეიცავს ველებს:

  ```json
  {}
  ```

### წინასწარ კონფიგურებული ნებართვის ნიშნები {#pre-configured-permission-tokens}

თქვენ შეგიძლიათ იხილოთ წინასწარი კონფიგურაციის ნებართვის ნიშნების სია [რეფერენცია](/ka/reference/permissions) თავში.

## ნებართვის ჯგუფები (ფუნქციები) {#permission-groups-roles}

ნებართვების კომპლექტს როლს უწოდებენ. ნებართვის ტოკენების მსგავსად, როლები შეიძლება დაენიშნოს `Grant` ინსტრუქციის გამოყენებით და გააუქმონ `Revoke` ინსტრუქციით.

ანგარიშზე როლის მინიჭებამდე, პირველ რიგში უნდა იყოს რეგისტრირებული.

როლები სასარგებლოა, როდესაც რამდენიმე ანგარიში უნდა მიიღოს ერთი და იგივე ნებართვის ნაკრები. რეგისტრირეთ როლი ერთხელ, მიეცით ნებართვები როლს, შემდეგ კი მიეცით ან გააუქმეთ როლი ცალკეული ანგარიშებისთვის.

### დარეგისტრირდით ახალ როლს {#register-a-new-role}

დავრეგისტრიროთ ახალი როლი, რომელიც, მისაცემის შემთხვევაში, საშუალებას მოგცემს სხვა ანგარიშზე [მეტამონაცემები](/ka/blockchain/metadata.md) წვდომას Mouse-ს ანგარიშში:

```rust
let role_id = RoleId::from_str("ACCESS_TO_MOUSE_METADATA")?;
let role = iroha_data_model::role::Role::new(role_id.clone(), mouse_id.clone())
    .add_permission(CanModifyAccountMetadata {
        account: mouse_id.clone(),
    });
let register_role = Register::role(role);
```

### გადმომეცეთ როლი {#grant-a-role}

მას შემდეგ, რაც როლი დარეგისტრირებულია, Mouse შეუძლია მისცეს იგი Alice:

```rust
let grant_role = Grant::account_role(role_id, alice_id);
let grant_role_tx = TransactionBuilder::new(chain_id, mouse_id)
    .with_instructions([grant_role])
    .sign(mouse_private_key);
```

## ნებართვის ვალიდატორები {#permission-validators}

ნებართვები არსებობს ისე, რომ მხოლოდ საჭირო ნებართვის ტოქნის მქონე ანგარიშებს შეუძლიათ დაცული მოქმედება განახორციელონ. დეფოლტური აღსრულებელი შეამოწმებს ნებართვებს ინსტრუქციის, მოთხოვნის და გამოხატვის შესრულების დროს.

დეფოლტური ვალიდატორის ზედაპირი დაჯგუფებულია ბლოკჩეინ ლეგერზე:

- ქსელის კვანძთა მართვა
- დომენები და ანგარიშები
- აქტივები, NFTs, და საფინანსო ვალდებულებები
- ტრიგერი
- როლები და ნებართვები
- დამსრულებელი/მუშაობის დრო, მტკიცებულებები, ხიდები და SORA/Nexus მოდულები.

ზუსტი ტოკენების სია არის წყარო-დაჭერული [ნებართვის ტოკენების მითითება](/ka/reference/permissions.md).

### შესრულების გარემო ვალიდატორები {#runtime-validators}

ნებართვის შემოწმებას ახორციელებს აქტიური აღმასრულებელი. დეფოლტურად აღმასრულებელმა უზრუნველყოფს ჩაშენებული ნებართვების ვალიდატორები და ტოქნის განსაზღვრები, ხოლო ქსელს შეუძლია შეცვალოს პოლიტიკა გამოყენებული აღმასრულებლის გაუმჯობესებით.

ვალიდატორები უბრუნებენ დამტკიცების განაჩენს. ვალიდატორი შეიძლება დაუშვას ოპერაცია, უარყოს მას მიზეზით ან გადაიტოვოს ის, თუ ოპერაცია ამ ვალიდატორის მოქმედების ფარგლებს გარეთაა. შერჩეული მოსამართლე ამ განაჩენებს აერთიანებს იმის დასადგენად, შეიძლება თუ არა ინსტრუქციას, კითხვას ან გამოხატვას განაგრძო.
