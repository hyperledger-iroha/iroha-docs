# ნებართვები {#permissions}

ანგარიშებს სჭირდებათ ნებართვის ტოქნები სხვადასხვა ქმედებებისთვის ბლოკჩეინზე, მაგალითად, აქტივების დაფარვა ან დამწვრობისთვის.

საჯარო და კერძო ბლოკჩეინებს შორის განსხვავება არსებობს მომხმარებლებისთვის მინიჭებული ნებართვების თვალსაზრისით. საჯარო ბლოკშეინში, უმეტეს ანგარიშებს აქვთ ერთი და იგივე ნებართვები. კერძო ბლოკჩეინში, სავარაუდოდ, ანგარიშების უმრავლესობას არ შეუძლია გააკეთოს რაიმე მათთვის მინიჭებული უფლებამოსილების მიღმა, თუ მათ პირდაპირ არ მიენიჭა შესაბამისი ნებართვა.

ნებართვის მიღება ნიშნავს, რომ ანგარიშს აქვს შესაბამისი `Permission`. ნებართვები შეიძლება დაენიშნოს პირდაპირ ან [`Role`](#permission-groups-roles), რომელიც აერთიანებს ნებართვების ერთეულს. ნებართვები გაიცემა `Grant` ინსტრუქციით. ნებართვები და როლები არ ვრცელდება; ამოიღეთ ისინი `Revoke` ინსტრუქციით.

## ნებართვის ქაღალდები {#permission-tokens}

ნებართვის ქაღალდები არის ტიპირებული ობიექტები, რომლებიც განსაზღვრულია აქტიური აღმასრულებლის მიერ. ზოგიერთი ქაღალდი გლობალურია, როგორიცაა `CanManagePeers`, ხოლო სხვები განკუთვნილია კონკრეტულ ლიდერის ობიექტზე, როგორიცაა ანგარიში, აქტივი, აქტივის განსაზღვრა, დომეინი, NFT, როლი ან საგამოძრაო.

აქ მოცემულია პარამეტრების რამდენიმე მაგალითი, რომლებიც გამოიყენება სხვადასხვა ნებართვის ქაღალდებისთვის:

- ქაღალდი, რომელიც აძლევს ნებართვას კონკრეტული ანგარიშის მეტა მონაცემების შეცვლისთვის, შეიცავს ველს `account`:

  ```json
  {
    "account": "<AccountId>"
  }
  ```

- ქონების განსაზღვრისთვის აქტივების გადაცემის ნებართვის მინიჭებული ტოკი შეიცავს `asset_definition` ველს:

  ```json
  {
    "asset_definition": "<AssetDefinitionId>"
  }
  ```

- გლობალური ტოქნი, როგორიცაა `CanManagePeers`, არ შეიცავს ველებს:

  ```json
  {}
  ```

### წინასწარ კონფიგურებული ნებართვის ნიშნები {#pre-configured-permission-tokens}

წინასწარი კონფიგურაციის ნებართვის ნიშნების სია შეგიძლიათ იხილოთ [Reference](/ka/reference/permissions) თავში.

## ნებართვის ჯგუფები (ფუნქციები) {#permission-groups-roles}

ნებართვების კომპლექტს როლს უწოდებენ. ნებართვის ტოკენების მსგავსად, როლები შეიძლება დაენიშნოს `Grant` ინსტრუქციის გამოყენებით და გააუქმონ `Revoke` ინსტრუქციით.

ანგარიშზე როლის მინიჭებამდე, პირველ რიგში უნდა იყოს რეგისტრირებული.

როლები სასარგებლოა, როდესაც რამდენიმე ანგარიში უნდა მიიღოს ერთი და იგივე ნებართვის ნაკრები. რეგისტრირეთ როლი ერთხელ, მიეცით ნებართვები როლს, შემდეგ კი მიეცით ან გააუქმეთ როლი ცალკეული ანგარიშებისთვის.

### დარეგისტრირდით ახალ როლს {#register-a-new-role}

მოდით დაარეგისტრიროთ ახალი როლი, რომელიც, მისაცემის შემთხვევაში, სხვა ანგარიშს საშუალებას მისცემს მიაღწიოს [მეტოდატას](/ka/blockchain/metadata.md) Mouse- ის ანგარიშში:

```rust
let role_id = RoleId::from_str("ACCESS_TO_MOUSE_METADATA")?;
let role = iroha_data_model::role::Role::new(role_id.clone(), mouse_id.clone())
    .add_permission(CanModifyAccountMetadata {
        account: mouse_id.clone(),
    });
let register_role = Register::role(role);
```

### გადმოგეცით როლი {#grant-a-role}

კჲდარჲ როლია ნაოპაგთლ, მაუჟი მჲზვ ეა დჲ ნაპაგთ ალისს:

```rust
let grant_role = Grant::account_role(role_id, alice_id);
let grant_role_tx = TransactionBuilder::new(chain_id, mouse_id)
    .with_instructions([grant_role])
    .sign(mouse_private_key);
```

## ნებართვის ვალიდატორები {#permission-validators}

ნებართვები არსებობს ისე, რომ მხოლოდ საჭირო ნებართვის ტოქნის მქონე ანგარიშებს შეუძლიათ დაცული მოქმედება განახორციელონ. დეფოლტური აღსრულებელი შეამოწმებს ნებართვებს ინსტრუქციის, გამოკითხვის და გამოხატვის შესრულების დროს.

რეგისტრაციის სფეროს მიხედვით დაჯგუფებულია ვალიდატორი ზედაპირი:

- პარტნიორთა მართვა
- დომენები და ანგარიშები
- აქტივები, NFTs, და საფინანსო ვალდებულებები
- გამომწვევი
- როლები და ნებართვები
- დამსრულებელი/მუშაობის დრო, მტკიცებულებები, ხიდები და SORA/Nexus მოდულები.

ზუსტი ტოქნების ჩამონათვალი წყაროზეა დადასტურებული [ Permission Tokens რეფერენციაში ](/ka/reference/permissions.md).

### გაშვების დროის ვალიდატორები {#runtime-validators}

ნებართვის შემოწმებას ახორციელებს აქტიური აღმასრულებელი. დეფოლტურად აღმასრულებელმა უზრუნველყოფს ჩაშენებული ნებართვების ვალიდატორები და ტოქნის განსაზღვრები, ხოლო ქსელს შეუძლია შეცვალოს პოლიტიკა გამოყენებული აღმასრულებლის გაუმჯობესებით.

ვალიდატორები უბრუნებენ დამტკიცების განაჩენს. ვალიდატორი შეიძლება დაუშვას ოპერაცია, უარყოს მას მიზეზით ან გადაიტოვოს ის, თუ ოპერაცია ამ ვალიდატორის მოქმედების ფარგლებს გარეთაა. შერჩეული მოსამართლე ამ განაჩენებს აერთიანებს იმის დასადგენად, შეიძლება თუ არა ინსტრუქციას, კითხვას ან გამოხატვას განაგრძო.

## მხარდაჭერილი კითხვები {#supported-queries}

ნებართვის ქაღალდები და როლები შეიძლება გამოკითხული იყოს.

როლების შესახებ შეკითხვები:

- [`FindRolesByAccountId`](/ka/reference/queries.md#accounts-and-permissions)

შეკითხვები ნებართვის ქაღალდებისთვის:

- [`FindPermissionsByAccountId`](/ka/reference/queries.md#accounts-and-permissions)
