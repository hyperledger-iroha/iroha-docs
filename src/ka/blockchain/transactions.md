# ოპერაციები {#transactions}

ა **ტრანზაქცია** ეს არის ხელმოწერილი თხოვნა, რომ ჩატარდეს მუშაობა ბლოკჩეინზე.
განხორციელებადი სასარგებლო ტვირთის შეიძლება იყოს დალაგებული თანმიმდევრობა
[ინსტრუქციები](./instructions.md), ხელშეკრულების გამოძახება, IVM ბაიტკოდი ან
დამტკიცებული IVM აღსრულება. იხილეთ [ჭკვიანი ხელშეკრულებები](./smart-contracts.md) ამჟამად
ხელშეკრულების შესრულების მოდელი.

ტრანზაქციები განახორციელებენ სახელმწიფოს შეცვლას ან შესრულებად სამუშაოს. მხოლოდ წაკითხვის ინსპექტირება
იყენებს ხელმოწერილი გამოკითხვებს ან საჯარო წაკითხვის საბოლოო წერტილებს და არ ქმნის ტრანზაქციას.

ვალდებულ ბლოკში მიღებული ტრანზაქცია შენახულია მისი განხორციელებისას
შედეგი, მათ შორის განხორციელების უარის თქმა.
დაშვება, როგორიცაა არასწორი კონვერტი ან ტრანზაქცია, რომელიც უარი თქვეს რიგში,
არ ინახება ბლოკში.

პირადი ცხოვრების დაცვის აქტივების გადაადგილების შესახებ იხილეთ
[ანონიმური ტრანზაქციები](./anonymous-transactions.md). ანონიმური
ტრანზაქციები იყენებენ დაცულ აქტივებზე, ვალდებულებებზე, ანულირებებზე და
ნულოვანი ცოდნის მტკიცებულებები საჯარო ანგარიშზე ბალანსის ცვლილებების ნაცვლად.

დოკუმენტების გამოყენებისას, შეფასება უნდა მოხდეს:
[FastPQ](./fastpq.md). FastPQ აჭარბებს სიკვდილით დასჯის მოწმეებს ჩვეულებრივად
ტრანზაქციის განხორციელება და დეტერმინისტური მტკიცებულების პარტიები აშენებს მხარდაჭერილი
სახელმწიფო გადასვლები.

## სცადე. Taira {#try-it-on-taira}

გამოიყენეთ მკვლევართა მარშრუტები, რათა შეამოწმოთ ბოლო საზოგადოება Taira ბლოკები და ტრანზაქცია
სტატუსები ხელმოწერის გარეშე:

```bash
curl -fsS 'https://taira.sora.org/v1/explorer/blocks?page=1&per_page=3' \
  | jq '{pagination, blocks: [.items[] | {height, hash, transactions_total, transactions_rejected}]}'

curl -fsS 'https://taira.sora.org/v1/explorer/transactions?page=1&per_page=5' \
  | jq '{pagination, txs: [.items[] | {hash, block, status, executable}]}'
```

თქვენი აპლიკაციის მიერ წარდგენილი ტრანზაქციის დასაკვალიერებლად, აკოპირეთ `hash` სააგენტოდან
ჩამოთვალეთ და შეამოწმეთ მკვლევარის დეტალური მარშრუტი:

```bash
TX_HASH='<transaction-hash>'

curl -fsS "https://taira.sora.org/v1/explorer/transactions/$TX_HASH" \
  | jq '{hash, block, status, authority, executable}'
```

ეს ჯერ კიდევ მხოლოდ წაკითხვაა. ტრანზაქციის წარდგენა მოითხოვს ხელმოწერილი Norito
კონვერტი, სწორი ჯაჭვი ID, საფასურის მეტა მონაცემები და საბანქის ფინანსური Taira ანგარიში.

საფასურის გადახდის მაგალითებისათვის Taira, Save the faucet დამხმარე
[მიიღეთ Testnet XOR დაწვრილებით Taira](/ka/get-started/sora-nexus-dataspaces.md#_4-get-testnet-xor-on-taira)
როგორც `taira_faucet_claim.py`, შემდეგ ფინანსდება ხელმოწერილი საჯარო ნაჟეტის მეშვეობით
პირველი:

```bash
export TAIRA_ACCOUNT_ID='<TAIRA_I105_ACCOUNT_ID>'
export TAIRA_FEE_ASSET=6TEAJqbb8oEPmLncoNiMRbLEK6tw

curl -fsS https://taira.sora.org/v1/accounts/faucet/puzzle | jq .
python3 taira_faucet_claim.py "$TAIRA_ACCOUNT_ID"

iroha --config ./taira.client.toml ledger asset get \
  --definition "$TAIRA_FEE_ASSET" \
  --account "$TAIRA_ACCOUNT_ID"
```

თუ საბაგირო საიდუმლო ან პრეტენზიის მარშრუტი დაბრუნდება `502`, დაველოდოთ და კიდევ ერთხელ შეეცადეთ
თავად ტრანზაქციის დებეგირება.

შემდეგ მიაერთეთ Taira გადასახადის აქტივების მეტა მონაცემები ტრანზაქციის წარდგენისას:

```bash
printf '{"gas_asset_id":"%s"}\n' "$TAIRA_FEE_ASSET" > taira.tx-metadata.json

iroha --config ./taira.client.toml \
  --metadata ./taira.tx-metadata.json \
  ledger transaction ping --msg "faucet-funded taira transaction"
```

## Offline ტრანზაქციები {#offline-transactions}

Iroha აქვს ორი ოპერაციული პროცესის ოფლაინ ფლოუსი:

- **ოფლაინ ხელმოწერა** ქმნის ჩვეულებრივ ხელმოწერილი ტრანზაქციას ხელმოწერის დროს
  მოწყობილობა გათიშულია. ტრანზაქცია არ ხდება, სანამ ონლაინ
  კლიენტი წარუდგენს ხელმოწერილი კონვერტს Torii, ასე რომ მას მაინც სჭირდება
  სწორი ჯაჭვი ID, უფლებამოსილება, ნებართვები, გადასახადები და ტრანზაქციის სიცოცხლე.
- **კაგემუში ფულადი თანხა** ფულის თავზე აყენებს, სანამ ის ონლაინ არის, მხარს უჭერს
  მიმღების მიერ დაწყებული საფულე-საფულის გადაცემები, როდესაც ორივე საფული არის
  ოფაინში, და შეძენს შედეგად ნოტის მდგომარეობა, როდესაც მიმღები ბრუნდება
  ონლაინ.

Torii გაშუქებს კაგემუშას სიცოცხლის ციკლს `/v1/offline/*`:

| მეთოდი და საბოლოო წერტილი | მიზანი |
| --- | --- |
| `GET /v1/offline/readiness` | შეაფასეთ კაგემუშას მზადყოფნა ერთისთვის `asset_definition_id` |
| `POST /v1/offline/receiver-lineage` | დარეგულირებული მტკიცებულებით მიმღები მოთხოვნის აქტიური რეგისტრაციის შტაბის განხილვა |
| `POST /v1/offline/top-up` | წარადგინეთ ხელით გაფორმებული ონლაინ-ოფლაინ ოპერაცია |
| `POST /v1/offline/redeem` | წარადგინეთ ოფლაინ გადახდის ოპერაცია |
| `GET /v1/offline/operations/{operation_id}` | წაიკითხეთ დამატების ან გამოსყიდვის კანონიკური სტატუსი |

შეამოწმეთ აქტივის მზადყოფნა ოპერაციის ოფლაინ განხორციელებამდე:

```bash
curl -fsS --get https://taira.sora.org/v1/offline/readiness \
  --data-urlencode 'asset_definition_id=<canonical_asset_definition_id>' \
  | jq '{ready, blockers, artifact_set}'
```

მზადყოფნა კაპიტას აქტიურ ხიდთან აკავშირებს ABI 21 და დამოწმებული V4
არტეფაქტის ნაკრები. გვარის, დამატების და გამოსასყიდის მოთხოვნები გამოიყენება typed
`application/x-norito` არქივები. შეავსება და გამოსასყიდის დაბრუნება `202 Accepted`
ა `Location` სათაური, რომელიც მიუთითებს ოპერაციის რესურსზე; ჩაშენებული
ნულოვანი ოპერაცია ID მარაგებს უმოქმედობის გასაღებს.

ტიპიური ნაკადი არის:

1. შეკითხვა მზადყოფნა და შეჩერება თუ `ready` არის ცრუ ან ნებისმიერი ბლოკერი გამოიყენება.
2. გამოიყენეთ ტიპირებული Swift ან JVM საფულე კანონიკური დამატებითი არქივის შესაქმნელად,
   წარადგინოს იგი და შეინახოს როგორც შესასვლელი ნოტის მდგომარეობა, ასევე მუშაობა ID სანამ
   ოპერაცია მიაღწევს საბოლოო ჯაჭვის მდგომარეობას.
3. საჭიროების შემთხვევაში გადაწყვიტოს მიმღებელის რეგისტრაციის გვარის დადგენა,
   შეამოწმეთ თითოეული თანატოლური გადაცემა ადგილობრივად და გააგრძელეთ კოდირებული შენიშვნების მდგომარეობა
   სანამ გადაცემას აღიარებთ.
4. როდესაც მიმღები ონლაინშია, შექმენით კანონიკური გამოსყიდვის არქივი.
   წარადგინოს იგი, და გამოკითხვა მისი ოპერაციული რესურსი საბოლოო.

ლეჯერი ვერ შეამოწმებს კონფლიქტური Offline გადაცემა სანამ შენიშვნა მდგომარეობა
ონლაინ ცხოვრების ციკლის განმავლობაში დაბრუნება. საფულე და ოპერატორის პოლიტიკა უნდა იყოს
შესაბამისად, ამოქმედდეს ღირებულების ლიმიტები, ვადის გასვლის ვადა, მიღებული ემიტენტები, მდგრადი ადგილობრივი
შენახვა და შერიგების ფანჯრები.

აქ მოცემულია მაგალითი ახალი ტრანზაქციის შექმნის შესახებ `Grant`
ამ გარიგებაში, მაუსი ალისს აძლევს მითითებულ
როლი (`role_id`ეთქვა:
[სრული მაგალითი](./permissions.md#register-a-new-role).

```rust
let grant_role = Grant::account_role(role_id, alice_id);
let grant_role_tx = TransactionBuilder::new(chain_id, mouse_id)
    .with_instructions([grant_role])
    .sign(mouse_private_key);
```
