# Iroha 3-ის გაშვება {#launch-iroha-3}

დახურულ გარემოში ინტეგრაციის შესამოწმებლად ერთ Linux ვირტუალურ მანქანაზე (VM) გაუშვით Iroha 3-ის ოთხი ვალიდატორი. გაგზავნეთ ხელმოწერილი ტრანზაქცია, გააჩერეთ ერთი ვალიდატორი და შეამოწმეთ, რომ დანარჩენი სამი მეორე ტრანზაქციასაც ადასტურებს. ასე მიიღებთ დამოუკიდებელ რეესტრს, რომელშიც მონაწილეობა ნებართვას მოითხოვს. მისი მართულ მონაცემთა სივრცედ SORA Nexus-თან დაკავშირებას ცალკე გამართვა სჭირდება.

## ვირტუალური მანქანის (VM) მომზადება {#prepare-the-vm}

გამოიყენეთ Linux x86_64, Docker Engine, Buildx, Compose v2, Python 3.8 ან უფრო ახალი ვერსია და `unzip`. თქვენს ანგარიშს Docker-ზე წვდომა სჭირდება. პირველი აწყობისას HTTPS-ით ხელმისაწვდომი უნდა იყოს GitHub, Docker Hub, Debian-ის პაკეტების სარკისებრი სერვერები და crates.io.

ნაკრები ავაწყვეთ და რამდენიმე სინთეზური ტრანზაქციით გამოვცადეთ ვირტუალურ მანქანაზე (VM), რომელსაც ჰქონდა ექვსი vCPU და 32 GiB RAM ოპერატიული მეხსიერება. საცავის მოცულობა შეარჩიეთ დატვირთვისა და მონაცემთა შენახვის ვადის მიხედვით. Docker Engine-ის თითოეულ ეგზემპლარზე გამოიყენეთ ნაკრების ერთი ასლი და ადგილობრივ ინტერფეისზე 18080–18083 პორტები თავისუფალი დატოვეთ.

[ჩამოტვირთეთ ოთხი ვალიდატორის ნაკრები](/downloads/iroha-trade-poc.zip). მასში შედის გამშვები პროგრამა, დამოკიდებულებების ფიქსირებული ვერსიების სია და შესწორებები, რომლებითაც ვალიდატორი და კლიენტი Iroha-ს ერთი და იმავე რევიზიიდან აიწყობა. ჩამოტვირთვის საქაღალდეში შეამოწმეთ არქივის საკონტროლო ჯამი და გახსენით არქივი.

```sh
echo 'b12d450f9f15c0126dfe5eca83cdfad8bc420c779a78f916d374f433a2b3da0e  iroha-trade-poc.zip' | sha256sum --check
unzip iroha-trade-poc.zip
cd iroha-trade-poc
```

## ოთხივე ვალიდატორის გაშვება და შემოწმება {#start-and-verify-all-four-validators}

```sh
python3 poc.py up
python3 poc.py verify
```

პირველი გაშვებისას პროგრამა აწყობს კონტეინერის იმიჯს და ვირტუალურ მანქანაზე (VM) ქმნის ჯაჭვის იდენტიფიკატორს, გასაღებებსა და ხელმოწერილ საწყის ბლოკს. თითოეულ ვალიდატორს საკუთარი მუდმივი საცავი აქვს. შემოწმებისას პროგრამა ხელს აწერს საცდელ ტრანზაქციას და ელოდება, სანამ ოთხივე ვალიდატორი დააბრუნებს სამ დაკავშირებულ პარტნიორ კვანძს და ახალი ბლოკის ერთსა და იმავე ჰეშს. საწყისი ბლოკი შეიცავს სანიმუშო ანგარიშებს. გამოიყენეთ სინთეზური მონაცემები და APIs მხოლოდ ადგილობრივ ინტერფეისზე გახსენით.

ვირტუალური მანქანიდან (VM) პირველი ვალიდატორის სტატუსის სანახავად პირდაპირ მიუთითეთ JSON ფორმატი.

```sh
curl -fsS -H 'Accept: application/json' http://127.0.0.1:18080/status
```

## ერთი ვალიდატორის გათიშვის შემოწმება {#test-a-validator-failure}

```sh
python3 poc.py failover
```

ტესტი აჩერებს ერთ ვალიდატორს, აგზავნის ახალ ტრანზაქციას და ამოწმებს დადასტურებული ბლოკის ჰეშს დანარჩენ სამ ვალიდატორზე. შემდეგ იგი ხელახლა უშვებს მეოთხე ვალიდატორს და ელოდება, სანამ ის იმავე ბლოკს მიიღებს. ვირტუალური მანქანის (VM) გათიშვისას ოთხივე ვალიდატორი გაჩერდება. ერთი ფიზიკური ჰოსტის გათიშვის გამოსაცდელად გამოიყენეთ ოთხი დამოუკიდებელი ჰოსტი და თითოეულზე განათავსეთ ერთი ვალიდატორი.

## შეჩერება და მუშაობის განახლება {#stop-and-resume}

```sh
python3 poc.py down
python3 poc.py up
```

ორივე ბრძანება გაუშვით იმ საქაღალდიდან, სადაც არქივი გახსენით. შეინახეთ `state/` საქაღალდე Docker-ის ოთხივე საცავთან ერთად, რათა ხელახლა გაშვებისას ვალიდატორებმა იგივე რეესტრი გახსნან. თუ გაშვება შეფერხდა, იმავე საქაღალდეში გაუშვით `python3 poc.py logs`.

## საჯარო წვდომის წერტილის შემოწმება {#try-the-public-endpoint}

აპლიკაციას შეუძლია Taira-ზე წაიკითხოს SORA Nexus-ის უნივერსალური მონაცემთა სივრცე რეესტრისთვის ვირტუალური მანქანის (VM) გაშვების გარეშე. სამუშაო სადგურიდან, სადაც დაყენებულია `curl` და `jq`, საცდელ ქსელს გაუგზავნეთ შემდეგი მხოლოდ წასაკითხი მოთხოვნა.

```sh
curl -fsS -H 'Accept: application/json' https://taira.sora.org/status \
  | jq '{peers, blocks, txs_approved, queue_size}'
```

პასუხში მოცემულია დაკავშირებული კვანძების, დადასტურებული ბლოკების, დამტკიცებული ტრანზაქციებისა და რიგში მყოფი ტრანზაქციების რაოდენობა მოთხოვნის მიმღებ კვანძზე. განთავსების დაგეგმვისას იხილეთ [ქსელის განთავსება](/ka/guide/best-practices/network-deployment.md).
