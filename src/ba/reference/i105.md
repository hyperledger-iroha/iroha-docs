# I105 Иҫәп адресы форматы {#i105-account-address-format}

I105 - Iroha 3 `AccountId` өсөн канон тышҡы текст форматы.

Уның файҙалы йөкләмәһе - иҫәп контролеры.

Уның һаҡсыһы тәғәйенләнгән селтәрҙе сылбыр айырмасыһы менән билдәләй.

Уны API, транзакция, рөхсәт йәки һорау буйынса канон иҫәбенә ID һораған һәр ерҙә ҡулланығыҙ.

I105 иҫәбенә ID домен юҡ.

`treasury@payments.universal` кеүек ҡиммәт иҫәбенә алмаш исем булып тора, был I105 ID тип башҡа яҙыу түгел.

I105 ID алыу иҫәбенә теркәлмәй һәм финанслай алмай.

::: warning Интеграцияның күпселек уңышһыҙлыҡтарын булдырмау өсөн ҡағиҙәләр

- Адресты кодлауҙан йәки раҫлауҙан алда селтәр профилен һайлағыҙ.
- UTF-8 каноник штрихты һаҡлағыҙ һәм аныҡ сағыштырығыҙ.
- Хәрефтәрҙең ҙур-бәләкәй булыуын һаҡлағыҙ һәм `Unicode` нормалләштереүен ҡулланмағыҙ.
- Һөҙөмтәлә I105 ID булырға тейеш түгел `@domain` йәки `@domain.dataspace` һуффикс.
- Iroha SDK йәки `iroha tools address` билдәләрен ҡулланығыҙ.
- Регуляр аңлатма I105 валидаторы түгел.

:::

## Һүҙмә - һүҙ анатомияһы {#literal-anatomy}

I105 хәрефтәрендә өс бер-береһенә йәнәш торған өлөшө һәм айырыусыһы юҡ:

```text
<network sentinel><base-105 canonical payload><six checksum symbols>
```

|Өҫтәмә |Маҡсат |Контроль суммаһын ҡаплау |
| ---------------- | ------------------------------------------------------------------ | ----------------- |
|Селтәр sentinel-ы |Тексты бер `u16` сылбыр дискриминантына тап килтерә |Ҡапланмаған |
|Файҙалы йөкләмә|`base-105` каноник иҫәп контроллеры байттарын кодлау |Ҡапланған |
|Күҙәтеү суммаһы |I105 алфавиты менән бирелгән алты `Bech32m` стилендәге `5-bit` ҡиммәттәре |N/A |

Файҙалы йөкләмә һәм контроль сумма иҫәп контроллерын билдәләй.

С sentinel селтәр контексты һайлай.

Бер үк контроллер Taira һәм Minamoto селтәрҙәрендә бер үк файҙалы йөкләмәгә һәм контроль суммаһына эйә, әммә һәр селтәр башҡа төп һаҡсыны ҡуллана.

Декодер көтөлгән дискриминаторҙы ҡулланырға тейеш.

Тикшереү суммаһы һаҡсыны алмаштырыуҙы асыҡлай алмай.

|Сеть йәки контекст |Сылбырлы айырмасы |Хекс |Canonical Sentinel |
| ----------------------- | -------------------------------: | -------: | ------------------------------------------- |
|Taira асыҡ тест селтәре |                            `369` |`0x0171` |`test` |

|Үҫеш контексты |                              `0` |`0x0000` |`dev` |

Исемендәге ҡиммәттәрҙә һәр саҡ үҙ исемле һаҡсыһы ҡулланыла.

`n00042`, `n369`, `n753` һәм `n0` кеүек формалар каноник түгел.

Транзакция сылбыры ID һәм I105 сылбырының айырмасыһы айырым ҡиммәттәр булып тора.

ID һуңғы нөктәһен йәки сылбырҙы һайлау адрестың профилен һайлап булмай.

## Норматив бер клавишалы миҫал {#normative-single-key-example}

Түбәндәге файҙалы йөк һәм Minamoto формаһы SDK тәңгәленең үтәлеше ҡағиҙәләрен үтәү системаһынан килә.

Taira формаһы шул уҡ файҙалы йөккә Taira ҡарауылсыһын ҡуллана:

```text
Public-key payload:
3B6A27BCCEB6A42D62A3A8D02A6F0D73653215771DE243A63AC048A18B59DA29

Public-key multihash accepted by tooling:
ed01203B6A27BCCEB6A42D62A3A8D02A6F0D73653215771DE243A63AC048A18B59DA29

Canonical account payload:
0x020001203b6a27bcceb6a42d62a3a8d02a6f0d73653215771de243a63ac048a18b59da29

Minamoto I105, discriminant 753:
sorauﾛ1NﾗhBUd2BﾂｦﾄiﾔﾆﾂﾇKSﾃaﾘﾒﾓQﾗrﾒoﾘﾅnｳﾘbQｳQJﾆLJ5HSE

Taira I105, discriminant 369:
testuﾛ1NﾗhBUd2BﾂｦﾄiﾔﾆﾂﾇKSﾃaﾘﾒﾓQﾗrﾒoﾘﾅnｳﾘbQｳQJﾆLJ5HSE
```

Каноник файҙалы йөк менән башлана `02 00 01 20`: башлыҡ `0x02`, компактлы бер төймәле билдә `0x00`, `Ed25519` бөгөлө ID `0x01`, һәм 32 байтлы асҡыс оҙонлоғо `0x20`.

`multihash` префиксы инеү метамәғлүмәттәре булып тора һәм контроллер файҙалы йөкләнешенә күсерелмәй.

## IDs менән CLI төҙөү һәм тикшереү {#create-and-inspect-ids-with-the-cli}

Йәмәғәт селтәре өсөн атамалы профиль өҫтөнлөк итә:

```bash
PUBLIC_KEY='ed01203B6A27BCCEB6A42D62A3A8D02A6F0D73653215771DE243A63AC048A18B59DA29'

TAIRA_ACCOUNT_ID="$(
  iroha tools address convert --profile taira "$PUBLIC_KEY"
)"

MINAMOTO_ACCOUNT_ID="$(
  iroha tools address convert --profile minamoto "$PUBLIC_KEY"
)"
```

Адрес-кодек тәртибен диагностикалағанда I105 инешен нормализациялау һәм сағыштырыу:

```bash
NORMALIZED_ACCOUNT_ID="$(
  printf '%s\n' "$TAIRA_ACCOUNT_ID" \
    | iroha tools address normalize --profile taira
)"

test "$NORMALIZED_ACCOUNT_ID" = "$TAIRA_ACCOUNT_ID"
```

JSON тип асыҡланған форматты, каноник шесник һәм һайлап алынған селтәр контексын тикшерегеҙ:

```bash
iroha tools address convert \
  --profile taira \
  --format json \
  "$TAIRA_ACCOUNT_ID"
```

Яңы һыҙыҡтар менән айырылған файлдың адрес-кодек структураһын аудит итеү, анализлау хаталарын тауышһыҙ ҡабул итмәйенсә:

```bash
iroha tools address audit \
  --profile taira \
  --input account-ids.txt \
  --format json
```

::: caution CLI раҫлау сиге

`convert`, `normalize` һәм `audit` командалары түбәнге кимәлдәге `AccountAddress` кодекҡа эшләй.

Улар sentinel-ды, алфавитты, контроль сумманы, байт оҙонлоҡтарын, `CurveId`/асҡыс формаһын һәм адрес ҡатламының теүәл ҡабат кодланыуын тикшерә.

Улар `AccountId` объектын булдырмай.

Улар үҙҙәре генә multisig сәйәсәтенең бөтә семантикаһын тикшермәй.

Улар башлыҡ класының контроллер менән тап килеүен иҫбатлай алмай.

Авторизациялау йәки даими һаҡлау алдынан `AccountId`-ҙы ҡәтғи тикшереүҙе ҡулланығыҙ.

:::

Шәхси селтәр өсөн, уның `--network-prefix` менән асыҡтан-асыҡ билдәләнгән айырмаһын ҡулланығыҙ.

Хәҙерге адресты асыҡ контексттар араһында үҙгәрткәндә, сығанаҡҡа `--expect-prefix` тип яҙырға кәрәк:

```bash
iroha tools address convert \
  --expect-prefix 369 \
  --network-prefix 753 \
  "$TAIRA_ACCOUNT_ID"
```

Яңынан кодлау селтәр контексын ғына үҙгәртә.

Ул иҫәпте маҡсатлы селтәрҙә теркәмәй һәм унда шул уҡ контроллерҙы ҡабаттан ҡулланырға кәрәклеген иҫбат итмәй.

## Шифрлау алгоритмы {#encoding-algorithm}

Canonical кодерҙары түбәндәге операцияларҙы башҡара:

```text
canonical = header || controller
payload_digits = base_convert(canonical, base_256, base_105)
checksum_digits = bech32m_6(hrp = "snx", convert_8_to_5(canonical, pad = true))
literal = sentinel(discriminant) || alphabet[payload_digits || checksum_digits]
```

Һылтанмалы нуль байттар `base-105` цифрҙары булараҡ һаҡлана.

Тикшереү суммаһы `Bech32` `polymod` генераторҙары һәм даими `0x2bc830a3` ҡулланыла.

Тик тикшереү суммаһы HRP - ASCII серияһы `snx`.

Текс суммаһы ғына HRP адресҡа баҫылмай.

Алты контроль суммаһы дәүмәле `0..31` диапазонында һәм файҙалы йөк менән бер үк I105 алфавитында күрһәтелә.

### I105 алфавиты {#i105-alphabet}

105 символ ошо тәртиптә индексацияланған.

Беренсе сиратта `Bitcoin Base58` алфавиты һәм унда `0..57` һандары бар.

Икенсе сиратта `58..104` һандары бар.

Кодектты ғәмәлгә ашырыуҙа сираттарҙы конкатенат итегеҙ.

```text
123456789ABCDEFGHJKLMNPQRSTUVWXYZabcdefghijkmnopqrstuvwxyz
ｲﾛﾊﾆﾎﾍﾄﾁﾘﾇﾙｦﾜｶﾖﾀﾚｿﾂﾈﾅﾗﾑｳヰﾉｵｸﾔﾏｹﾌｺｴﾃｱｻｷﾕﾒﾐｼヱﾋﾓｾｽ
```

Әлифбаһы `Unicode` -ға ҡарата һиҙгер.

Дөрөҫ тәртиптә `compatibility-width` Японияның `kana` символдары һәм `ヰ` һәм `ヱ` өсөн күрһәтелгән код пункттары ҡулланыла.

NFC, NFKC, киңлекте үҙгәртеү, хәреф регистрын берләштереү йәки оҡшаш күренгән символға алмаштырыуҙы ҡулланмағыҙ.

ASCII `0`, `O`, `I` һәм `l` - алфавит символдары түгел.

## "Кананик" иҫәбенең файҙалы йөкләмәһе {#canonical-account-payload}

`base-105` корпусы бинар иҫәбенең файҙалы йөкләмәһен кодлай, асыҡ асҡыслы штрих түгел һәм Norito JSON объекты түгел:

```text
header:u8 || controller:variable
```

Түбәндәге күп байтлы тулы һандарҙың барыһы ла ҡултамғаланмаған һәм `big-endian`.

Домен, мәғлүмәт киңлеге, псевдонимы, UAID, һәм иҫәп-хисап метамәғлүмәттәренең байты юҡ.

### Баш бит байты {#header-byte}

|Беттар |Киңлеге |Хәҙерге кодлаусы сығышы |Мәғәнәһе |
| ------ | ----: | ---------------------------: | ---------------------------- |
| `7..5` |     3 |                          `0` |Адрес форматындағы версияһы |
| `4..3` |     2 |`0` бер асҡыс, `1` күп тамғалы |Адрес класы |
| `2..1` |     2 |                          `1` |Нормализация версияһы |
| `0`    |     1 |                          `0` | Резервтағы `extension flag` |

Хәҙерге V1 кодлаусылары бер асҡыслы контроллер өсөн `0x02` башлығын һәм multisig контроллер өсөн `0x0a` башлығын сығара.

`2` һәм `3` адрестар кластары билдәләнмәгән.

`extension flag` `1` аҡсаһы кире ҡағыла.

Түбән кимәлдәге декодер башҡа версиялар һәм нормализация биттәре ҡиммәттәрен һаҡлай ала һәм класты контроллер билдәһе менән үҙ аллы контролдә тота алмай.

`AccountId` тип үҙгәртеү һәм уның каноник тәржемәһен сағыштырыу V1 ҡануниальлеген раҫлай.

### Бер генә асҡыс менән идара итеүсе {#single-key-controller}

Асыҡ асҡыстың сей йөкмәткеһе 255 байттан артмаһа, компакт форманы ҡулланығыҙ:

|Баҫыу |Киңлеге |Ҡиммәт йәки мәғәнә |
| ------------ | --------------: | ------------------------ |
|`tag` |1 байт |`0x00` |
|`curve` |1 байт |`CurveId` реестры ҡиммәте |
|`key_len` |1 байт |Сей асҡыс оҙонлоғо |
|`public_key` |`key_len` байт |Сей асыҡ асҡыс йөкмәткеһе |

255 байттан оҙонораҡ асҡыстар киңәйтелгән форманы ҡуллана:

|Баҫыу |Киңлеге |Ҡиммәт йәки мәғәнә |
| ------------ | --------------: | ---------------------------- |
|`tag` |1 байт |`0x02` |
|`curve` |1 байт |`CurveId` реестры ҡиммәте |
|`key_len` |2 байт |Сей асҡыс оҙонлоғо, `big-endian` |
|`public_key` |`key_len` байт |Сей асыҡ асҡыс йөкмәткеһе |

Өҫтәмә кодлау компакт формаға тура килгән асҡыс өсөн каноник түгел.

### Күпселек контроллеры {#multisig-controller}

|Баҫыу |Киңлеге |Ҡиммәт йәки мәғәнә |
| ---------------- | -------: | ------------------------------ |
|`tag` |1 байт |`0x01` |
|`policy_version` |1 байт |Хәҙерге ҡиммәт `1` |
|`threshold` |2 байт |Кәрәкле дөйөм раҫлау ауырлығы |
|`member_count` |2 байт |Артабанғы ағзаларҙың һаны |
|`members` |Үҙгәрешле |Ҡабатланған ағза яҙмалары |

Һәр ағзаның яҙмаһы:

|Баҫыу |Киңлеге |Мәғәнәһе |
| ------------ | --------------: | ------------------------ |
|`curve` |1 байт |`CurveId` реестры ҡиммәте |
|`weight` |2 байт |Ағзаның раҫлау ауырлығы |
|`key_len` |2 байт |Сей асҡыс оҙонлоғо |
|`public_key` |`key_len` байт |Сей асыҡ асҡыс йөкмәткеһе |

Яраҡлы сәйәсәттә кәм тигәндә бер ағза һәм ыңғай ауырлыҡтар булырға, ҡабатланған асыҡ асҡыстар булмаҫҡа, ә сик `1`-ҙән ағзалар ауырлыҡтарының суммаһына тиклем булырға тейеш.

```text
member_count >= 1
all(member.weight > 0)
1 <= threshold <= sum(member.weight)
all_unique(member.public_key)
```

Каноник төҙөлөш ағзаларҙы ҡултамға алгоритмының тотороҡло исеме, нуль айырыусы байт, шунан сей асыҡ асҡыс байттары буйынса сортлай.

```text
member_sort_key = stable_algorithm_name || 0x00 || raw_public_key
```

I105 хәрефенең билдәләнгән тамға оҙонлоғо юҡ, сөнки мультисиг һәм постквантовый контроллерҙар ҙур булыуы мөмкин.

### `CurveId` реестры {#curveid-registry}

| ---: | -------------------------------------------- | ------------------------ |

|  `2` |`ML-DSA` | —                        |
|  `3` |`BLS12-381 normal` |`bls` |
|  `4` |`secp256k1` | —                        |
|  `5` |`BLS12-381 small` |`bls` |
| `10` |`GOST R 34.10-2012 256-bit, parameter set A` |`gost` |
| `11` |`GOST R 34.10-2012 256-bit, parameter set B` |`gost` |
| `12` |`GOST R 34.10-2012 256-bit, parameter set C` |`gost` |
| `13` |`GOST R 34.10-2012 512-bit, parameter set A` |`gost` |
| `14` |`GOST R 34.10-2012 512-bit, parameter set B` |`gost` |
| `15` |`SM2` |`sm` |

Бүләкләнмәгән IDs һәм алгеoritмдар ҡабул итеүсе төҙөүҙә һүндерелгән кире ҡағыла.

Шулай уҡ `CurveId` тарафынан һайланған алгоритм өсөн төп файҙалы йөкләмә структура буйынса ла ғәмәлдә булырға тейеш.

## AccountId ҡәтғи раҫлау һәм каноникальлек {#strict-accountid-validation-and-canonicality}

SDK-ны күҙалланған сылбыр айырмасыһы менән конфигурациялағандан һуң, `AccountId` -ға анализ яһап, кире ҡайтарылған каноник тапшырыуҙы киҫәкләнгән инеү менән сағыштырып ҡарағыҙ.

Сағыштырыу әһәмиәтле, сөнки анализлаусы `AccountId` конструкцияһын төҙөгәндә декодировкаларға мөмкин булған контроллер материалын нормализациялай.

```rust
use eyre::{ensure, Result};
use iroha::data_model::prelude::AccountId;

fn parse_canonical_account_id(input: &str) -> Result<AccountId> {
    let input = input.trim();
    let parsed = AccountId::parse_encoded(input)?;

    ensure!(
        parsed.canonical() == input,
        "account ID is valid but not in its current canonical I105 form"
    );

    Ok(parsed.into_account_id())
}
```

Ышанысһыҙ ҡыл өсөн, тейешле ҡушымта:

1. Trim тулы ҡиммәттең тирә-яғын ғына ташыу мөмкинлеген бирә.
2. Һаҡсыны уҡығыҙ һәм көтөлгән сылбыр айырмасыһын талап итегеҙ.
3. Һәр ҡалған `Unicode` символын 105-се символ алфавиты буйынса картаға төшөрөп ҡарағыҙ.
4. Контроль суммаһының алты цифрын айырып алығыҙ.
5. Яҡшы йөкләмә цифрҙарын ҡабаттан каноник байтҡа әйләндер.
6. Ошо каноник байттар өсөн контроль сумманы тикшерегеҙ.
7. Баҫманы һәм контроллерығыҙҙы тикшерегеҙ, шуға күрә:
   - яландың теүәл оҙонлоғо
   - ярҙам ителгән `CurveId`
   - раҫланған асыҡ асҡыс
   - артта ҡалған байттар юҡ
   - ҡулланылған осраҡта ғәмәлдә булған күп ҡултамғалы сәйәсәт
8. `AccountId` төҙөү.
9. `AccountId` билдәһен көтөлгән дискриминант өсөн каноник рәүештә ҡайтарығыҙ.
10. `byte-for-byte` тигеҙлеген талап ителеү, ҡырҡылған инеш менән.

Ҡушымтаның асыҡ һуңғы `render-and-compare` аҙымы минималь булмаған һанлы sentinel-дарҙы, контроллерҙың каноник булмаған урынлашыуҙарын, яңынан тәртипкә һалынған сәйәсәт материалын һәм декодланған, әммә кодлаусының ағымдағы V1 сығышы булмаған башҡа һәр яҙылышты кире ҡаға.

Уңышлы тикшереү суммаһы йәки түбән кимәлдәге `AccountAddress` анализы был тикшереүҙе алмаштыра алмай.

Был ҡиммәттәрҙе ҡаты иҫәп-хисап буйынса ID майҙанда ҡабул итмәгеҙ:

- `alice@wonderland.universal` иҫәбенә исем ҡушымтаһы
- I105 хәрефе һәм ҡушымтаһы `@domain` менән
- `multihash` кеүек асыҡ асҡыслы `ed0120...`
- `0x02000120...` кеүек ҡануни файҙалы йөкләмәләр
- яңылыш сылбыр дискриминаторы адресы
- ҙур йәки бәләкәй хәрефтәре, тамға киңлеге, `kana`, файҙалы йөкмәтке йәки контроль суммаһы үҙгәртелгән ҡыл.

Ҡулланыу сигендә ҡушаматтарҙы хәл итеү һәм рөхсәт, ҡултамғалау, рөхсәт һәм аудит яҙмалары өсөн кире ҡайтарылған каноник I105 ID һаҡлап ҡалыу.

## API, һаҡлау һәм ҡуйыу ҡағиҙәләре {#api-storage-and-display-rules}

- I105 UTF-8 теҙелешен JSON иҫәбендәге майҙандарға ебәреү.
- `Percent-encode` тулы иҫәп ID уны URL Юл сегменты.
- I105 ID урынына бер ҡасан да иҫәп ҡушаматын ҡулланмағыҙ.
- `byte-preserving` сағыштырыу семантикаһы менән кодек кире ҡайтарған каноник штринг һаҡларға.
- Хәрефтәрҙең ҙур-бәләкәй булыуын һәм символ киңлеген һаҡлаған сағыштырыу тәртибен ҡулланығыҙ.
- Сылбыр айырмалы йәки исемләнгән селтәр профилен экспортланған иҫәп-хисап мәғлүмәттәре һәм резервтар менән һаҡларға.
- Адресты уның селтәр контексты менән генә ҡабаттан ҡулланығыҙ.
- Тулы адресын күрһәтегеҙ һәм күсермә яһағыҙ.
- Һәр `kana` тамғаһын теүәл һаҡлағыҙ.
- Уртаһын ҡыҫҡартҡанда, тулы адресты ҡуйырға кәрәк.
- Һаҡланған ID каноникаһын ҡулланығыҙ, уны ялған исемдән үҙгәртеп ҡороу урынына.

`AccountId` дисплейы һәм JSON күрһәтелеше каноник I105 ҡуллана.

Түбән кимәлдәге `AccountAddress` дисплейы/JSON күрһәтелеше эске һәм көйләү контексттары өсөн каноник ун алтылыҡ форманы ҡуллана.

Әгәр тышҡы иҫәп-хисап ID кәрәк булһа, асыҡтан-асыҡ `AccountAddress` I105 кодлаусыһына шылтыратығыҙ.

Иҫәптәр булдырыу һәм алфавиттарҙы хәл итеү буйынса эш ағымдары өсөн [Аҡсалар һәм алфавиттар менән дауам итегеҙ ](/ba/cookbook/accounts-and-aliases.md).

Хисап мәғлүмәттәренең моделе өсөн ҡарағыҙ [Хисаптар](/ba/blockchain/accounts.md).
