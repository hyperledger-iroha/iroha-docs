# Torii Оҙаҡҡы һыҙаттар {#torii-endpoints}

Torii был HTTP, SSE, һәм WebSocket ҡапҡаһы өсөн Iroha 3. Ул икеләтә лә иҫәп-хисапҡа ҡараған APIs һәм операторҙың һуңғы нөктәләре.

Хәҙерге протокол ҡағиҙәләре:

- Ҡанунлы бинар форматы Norito
- JSON бик күп һуңғы нөктәләр ҙә ярҙам итә, һеҙ `Accept: application/json` ебәргәндә
- метрикалар Prometheus форматында күрһәтелгән

Формат мәғлүмәттәре, йөкмәтке менән һөйләшеү, плагин билдәләре, схема хештары һәм Norito RPC күрһәтмәһе өсөн [Norito шиғырын ҡарағыҙ](/ba/reference/norito.md).

SSE һорауы өсөн, төп ағымды өҫтәп типографиялағы ҡабатлауҙы иғлан итегеҙ:

```http
Accept: text/event-stream, application/json
```

Torii тәүҙә һорау ҡатламында JSON йәки Norito сағылышы менән һөйләшә, һуңынан `text/event-stream` үҙенсәлекле яуапты раҫлай. Шуға күрә бары тик `text/event-stream` ғына ебәреү `406` менән кире ҡағыла; [ ағымлы ваҡиғалар рецепты](/ba/cookbook/stream-events.md) тулы баш биттә ҡуллана.

`/openapi.json` — схемала күрһәтелгән маршруттар өсөн төҙөлгән контракт, әммә ул оператив тикшереүҙәрҙең тулы исемлеге түгел. Ағымдағы документта `/livez` һәм `/readyz` юҡ, ә `/health` тасуирламаһы әҙерлек handler-ынан артта ҡалырға мөмкин. Маршрут клиенттарын тере документтан төҙөгөҙ, ләкин liveness һәм readiness-ты эшләп торған төйөнгә һәм беркетелгән handler-ҙарға туранан-тура ҡарата тикшерегеҙ. Теүәл өҫкө йөҙ build функцияларына һәм runtime конфигурацияһына бәйле булып ҡала. Тере документты йөкләү, JSON маршруттарын һынау, curl һорауҙарын күсереү һәм ағымдағы схеманан клиент кодын төҙөү өсөн [Torii API консолен](/ba/reference/torii-api-console.md) ҡулланығыҙ.

Һәр OpenAPI каталог ярҙамында башҡарылған операцияға `x-iroha-route-auth` объект инә. MCP каталог ярҙамы менән эшләнгән инструменттар `_meta["iroha/routeAuth"]` менән бер үк килешеүҙе асыҡлай. Ике проекция ла `schemaVersion`, `stableRouteId`, `authentication` һәм `admission`. `1` версияһын теүәл килешеү итеп ҡарағыҙ: уның аутентификацияһы йәки ҡабул итеү тамғалары нисек тәржемә ителергә тейешлеген фаразлау урынына, хупланмаған `schemaVersion` версияһын кире ҡағығыҙ. Маршрут метамәғлүмәттәре һорау сиген һүрәтләй; ул был сик талап иткән таныҡлыҡ документтарын алмаштыра алмай.

## Taira тура юлдарҙы һынап ҡарағыҙ {#try-live-taira-routes}

Йәмәғәт Taira тест селтәре ҡулланыу клиенттары уҡыу өсөн генә эҙләнеү өсөн ҡулланылған шул уҡ Torii JSON өҫкө йөҙөн аса. Был командалар асҡыстарҙы талап итмәй:.

```bash
TAIRA_ROOT=https://taira.sora.org

curl -fsS -H 'Accept: application/json' "$TAIRA_ROOT/status" \
  | jq '{blocks, txs_approved, txs_rejected, queue_size, peers}'

curl -fsS "$TAIRA_ROOT/openapi.json" \
  | jq -r '.paths | keys[]' \
  | grep '^/v1/' \
  | head -n 20

curl -fsS -H 'Accept: application/json' \
  "$TAIRA_ROOT/v1/node/capabilities" \
  | jq '{abi_version, data_model_version, query: .query.aggregate.supported_resources}'
```

Хәҙерге донъя хәленә ҡарап сығайыҡ:

```bash
curl -fsS "$TAIRA_ROOT/v1/domains?limit=5" \
  | jq -r '.items[].id'

curl -fsS "$TAIRA_ROOT/v1/assets/definitions?limit=5" \
  | jq -r '.items[] | [.id, .name, .total_quantity] | @tsv'
```

Әгәр асыҡ тест селтәре маршруты кире ҡайта `502`, ваҡыттарҙы өҙөп, йәки туйынған сират тураһында хәбәр итһә, уны һуңғы нөктәлә булыу проблемаһы тип ҡарағыҙ һәм клиент кодын дебэглауҙан алда тағы ла тырышығыҙ.

## Аккаунт аутентификацияһы, күренеүсәнлек һәм Explorer курсорҙары {#account-authentication-visibility-and-explorer-cursors}

### Ҡулланма иҫәп-хисапҡа мөрәжәғәт итеү протоколы {#app-account-request-protocol}

Ҡулланыуға ҡараған маршруттарҙа аутентификация башлыҡтары юҡ, бер тура бер төймәле иҫбатлау йәки бер күп һанлы шаһит ҡабул ителә. Һәр аутентификациялау башлығы бер тапҡыр ғына күрһәтелергә тейеш.

Тура иҫбатлау өсөн, дүрт башлыҡты ла бергә ебәр:

- `X-Iroha-Account`: тура каноник бәләкәй хәрефле `0x` иҫәп-хисап адресы шэкс йәки актив каноник ASCII иҫәбенең ҡушаматы. I105 тексы HTTP яланының баһаһы булараҡ хәүефһеҙ түгел; был хисап өсөн каноник шестер яҙыу ҡулланығыҙ.
- `X-Iroha-Signature`: ҡәтғи тултырылған-база64 ҡултамға файҙалы йөкләмә.
- `X-Iroha-Timestamp-Ms`: конфигурацияланған кәүҙәлелек тәҙрәһендә миллисекундтарҙа каноник имзаланмаған унсылыҡ Unix ваҡыт маркаһы.
- `X-Iroha-Nonce`: 1 - 256 баҫыла торған ASCII байт (`0x21` - `0x7e`), ҡабаттан уйнатыу тәҙрәһендә үҙенсәлекле.

Теркәлгән яңғыҙ асҡыс контроллеры ошо теүәл байттарҙы билдәләй:

```text
iroha.app.request.network.v1\0 || <genesis-derived network_id[32]> ||
<UPPERCASE_METHOD>\n
<exact request path>\n
<canonical query>\n
<lowercase hex SHA-256 of the raw body>\n
<canonical timestamp_ms>\n
<nonce>
```

Canonical query төҙөү raw query-ны `application/x-www-form-urlencoded` итеп анализлай (`+` space аңлата), уның pair-ҙарын percent-decode итә, уларҙы `(key, value)` буйынса теҙә һәм ҡабат form-encode итә. Протокол иң күбе 64 decoded pair һәм 64 KiB raw query text ҡабул итә. Body byte-тарын тап тапшырылғанса hash-лағыҙ. Фиксированный 32-byte network ID менән uppercase method араһында separator өҫтәмәгеҙ.

V1 верификаторы шулай уҡ метод символын 32 байтҡа, процент менән кодланған һорау юлына 64 KiB тип сикләй. һәм 36 KiB адресы буйынса тура иҫәп-хисап идентификаторы анализлауҙан алда. Иҫәп яҙмаһы алиастарының структура сиктәре өс исем сегменты һәм уларҙың айырыусылары менән нығыраҡ тығыҙ. Бер сикләүҙән тыш, ҡултамғаны раҫлауҙан йәки сығанаҡ күләмендәге бүлеү алдынан аутентификация үтәлмәй.

Күп һанлы контроллер урынына `X-Iroha-Witness` ебәрергә тейеш, ҡәтғи ҡапланған-база64 каноник Norito һәм ҡалдырырға тейеш `X-Iroha-Signature`, `X-Iroha-Timestamp-Ms`, һәм `X-Iroha-Nonce`. `X-Iroha-Account` был формала факультатив; булғанда, ул шаһит менән тиң булырға тейеш `subject_account`. `CanonicalRequestWitnessV1` составында `schema_version`, `subject_account`, `timestamp_ms`, `nonce` һәм Iroha `Hash` туранан-тура селтәр һорауы байтлары бар, әммә яңылыҡ ҡырҙары юҡ, һәм иң күп 64 ағза ҡултамғаһы. Һәр ағза ҡултамғалар массивынан тыш шул уҡ файҙалы йөкләмәнең каноник Norito кодировкаһына ҡул ҡуя. раҫланған ағзалар иҫәбенең ғәмәлдәге күп тамғалы сәйәсәтен ҡәнәғәтләндерергә тейеш. кодланған шаһит 1 MiB менән сикләнә.

Автентификация башлыҡтарын бирмәү аноним инеүҙе һайлай. өлөшләтә, ҡатнаш, ҡабатланған, формалашмаған, иҫкергән йәки ҡабатланған иҫбатлауҙы биреү аутентификацияланмай; ул бер ҡасан да аноним күренеклелеккә кире төшмәй.

### Операторҙың заявка протоколы {#operator-request-protocol}

Оператор менән раҫланған тип билдәләнгән маршруттар өсөн дүрт берлектәге башлыҡ талап ителә:

- `x-iroha-operator-public-key`: Iroha күп һанлы асыҡ асҡыс.
- `x-iroha-operator-timestamp-ms`: миллисекундтағы каноник имзаланмаған унсылыҡ Unix ваҡыт маркаһы.
- `x-iroha-operator-nonce`: 1 - 256 баҫтырыла торған ASCII байт, ҡабаттан уйнатыу тәҙрәһендәге был клавиша өсөн үҙенсәлекле.
- `x-iroha-operator-signature`: ҡәтғи тултырылған-база64 ҡултамға файҙалы йөкләмә.

Башлыҡ ҡиммәттәрендә тирә-яҡтағы whitespace булырға тейеш түгел. Оператор асҡысы түбәндәгеләргә ҡул ҡуя:

```text
iroha.operator.http-request.network.v1\0 || <genesis-derived network_id[32]> ||
<UPPERCASE_METHOD>\n
<exact request path>\n
<canonical query>\n
<lowercase hex SHA-256 of the raw body>\n
<canonical timestamp_ms>\n
<nonce>
```

Юл, һорау, корпус, ваҡыт маркаһы һәм nonce ҡағиҙәләре - ҡушымта протоколы ҡулланған шул уҡ каноник ҡағиҙәләр. Ключты шулай уҡ ҡабул итергә тейеш `[torii.operator_signatures]`: исемлеккә индерергә `allowed_public_keys`, йәки асыҡтан-асыҡ мөмкинлек бирә `allow_node_key` узел клавиатураһын ҡулланғанда. Replay cache тулһа, система `503 Service Unavailable` менән fail closed эшләй.

Дағүә итеүҙең теүәл имзаһы һәр ваҡыт мотлаҡ. Әгәр `[torii.operator_auth].enabled = true` булһа, һәр ябай оператор маршруты шулай уҡ ғәмәлдә булған `x-iroha-operator-session` талап итә; ҡасан `require_mtls = true`, өҫтәмә рәүештә талап итә `x-forwarded-client-cert` Ул - ышаныслы фәрештә. Был ике фактор ҙа үтенестәрҙең ҡултамғаһын алмаштыра алмай.

WebAuthn теркәлеү һәм инеү өсөн был дүрт JSON тамамлау пункттарын ҡулланырға:

|Метод һәм маҡсат |Маҡсат |
| --------------------------------------------- | ---------------------------------------- |
|`POST /v1/operator/auth/registration/options` |WebAuthn таныҡлыҡ алыуҙы башлау |
|`POST /v1/operator/auth/registration/verify` |Кредитлау документын тикшереп тороу һәм дауам итеү |
|`POST /v1/operator/auth/login/options` |WebAuthn аутентификацияһын башлау |
|`POST /v1/operator/auth/login/verify` |раҫлауҙы тикшерегеҙ һәм ултырыш үткәрегеҙ |

`torii.operator_auth.tokens` -ҙы махсус стартлау билдәләре менән конфигурациялағыҙ. Ниндәй ҙә булһа таныҡлыҡ документтары булғанға тиклем, беренсе теркәүҙе башлар өсөн `x-iroha-operator-token` тип ебәрегеҙ. Был токен бер ҡасан да ғәҙәти оператор маршрутын рөхсәт итмәй, ә тыңлаусы `x-api-token` ҡиммәттәрен был ағым өсөн ҡабатланмай. Кредитенциал булғандан һуң, икенсе аккредитивты яҙыу өсөн аутентификацияланған сеанс талап ителә. Логинте раҫлау сеанс билдәһен һәр яңы теүәл селтәр операторы һорауының ҡултамғаһы менән бергә ебәреү өсөн кире ҡайтара. `<torii.data_dir>/operator_auth/operator_webauthn.json` аҫтында аккредициялар һаҡлана.

ISO 20022 маршруттары ике бойондороҡһоҙ тикшереү үтә. һорауға тәүҙә был операторҙың рөхсәт исемлеге һәм ҡултамға протоколы үтәлергә тейеш; ISO менән идара итеүсе, һуңынан шул уҡ асҡысты түбәндә һүрәтләнгән конкрет ҡатнашыусы йәки аудит ролен башҡарыу өсөн талап итә.

### Леджерҙың күренеүсәнлеге һәм Explorer курсорҙары {#ledger-visibility-and-explorer-cursors}

Ҡушымтаға ҡараған иҫәп яҙмаһын уҡыу өҫтәмә ҡушымта иҫәбенә сикләүҙе ҡуллана. ҡултамғаланмаған үтенесе бары тик асыҡ тип конфигурацияланған мәғлүмәттәр базаһы ала. Яҡшы ҡул ҡуйылған үтенес өҫтәлә UAID аккаунты менән бәйләнгән мәғлүмәттәр киңлектәре, һәр сикләнгән мәғлүмәт киңлеге `CanReadRestrictedDataspace { dataspace }` рөхсәте менән аталған, йәки бөтә маршруттар иҫәбенә `CanReadAllLedgerData` булған осраҡта.

Зинһар, саҡырыусынең хоҡуғына тап килгән маршрутты ҡулланығыҙ:

|Метод һәм маҡсат |Аутентификация һәм күренеүсәнлек |
| ------------------------------------- | --------------------------------------------------------------- |
|`POST /v1/transactions/visible/query` |Canonical иҫәбенә ҡултамғаһы; саҡырыусының күренеше |
|`POST /v1/transactions/query` |Оператор ҡултамғаһын һорай; глобаль оператор ҡарауын рөхсәт итә |
|`GET /v1/triggers/completed` |Оператор ҡултамғаһын һорай; узел-локаль тамамлау яҙмаларын уҡый |

Шул уҡ күренеүсәнлек объекты account, domain, asset-definition, asset, NFT, RWA, holder һәм Explorer уҡыуҙарын фильтрлай. Булмаған объект менән саҡырыусының күренгән маршруттарынан ситтәге объект аңлы рәүештә айырылмаҫлыҡ итеп күрһәтелә. commit ителгән transaction һәм instruction тарихы транзакция өсөн теркәлгән һәр маршрут өлөшө күренгәндә генә күрһәтелә. Шуға күрә ҡатнашыусының хатта бер өлөшө саҡырыусының сиктәренән ситтә булһа, ҡатнаш dataspace транзакцияһы йәшерелә; юғалған, иҫкергән йәки боҙолған routing context-ты глобаль уҡыусы ғына күрә.

Донъя хәле менән тәьмин ителгән алты Explorer коллекцияһы opaque canonical base64url keyset cursor-ҙарын ҡуллана. Ғәҙәттәге бит лимиты 25, максимум 100, ә бер бит иң күбе 512 кандидат асҡысты тикшерә. Һәр cursor үҙ коллекцияһына, фильтрҙарына, һуңғы canonical асҡысҡа һәм саҡырыусының күренгән маршруттар йыйылмаһы digest-ына бәйләнгән, шуға күрә уны икенсе һорауҙа йәки саҡырыусының күренеүсәнлеге үҙгәргәндән һуң ҡабат ҡулланып булмай.

Блок, транзакция, һуңғы транзакциялар, инструкциялар һәм һуңғы күрһәтмәләр тарихы курсорҙары өҫтәмә рәүештә commit ителгән мгновенный бейеклекте һәм блок хэш билдәләй. яуаптар `pagination.limit`, `pagination.snapshot_height`, `pagination.snapshot_hash`, `pagination.next_cursor` һәм `pagination.has_more`. Башҡа маршрут йәки фильтр йыйылмаһы өсөн курсор, үҙгәртелгән күреүсәнлек дайджесты, йәки узел инде раҫлай алмай snapshot ябыла. тарих сканерлау Torii һорау-ҡабул итеү рөхсәте эсендә ҡала блокировкалы эшсе эшләй.

Эксплорер WebSocket ағымдар фильтрланған резюмелар сығара һәм күреүсәнлеген иҫәпләмәй башлыҡ рөхсәттәре үҙгәргәндә. `GET /v1/blocks/stream` маршрут башҡа: ул тулыһынса ҡул ҡуйылған блоктар сығара, талап итә `CanReadAllLedgerData` ҡул һелтәү ваҡытында, һәм рөхсәт һуңғараҡ кире ҡағылһа ябыла. Мәғлүмәт киңлеге буйынса тикшеренеүсе өсөн урындағы ағымды файҙаланма.

## Kaigi Сессиялар {#kaigi-sessions}

Kaigi түләүле, ысын ваҡытлы аудио/видео бүлмәләре менән тәьмин итә SORA Nexus. Ҡулланырға кәрәк, әгәр ҡушымтаға иҫәп яҙмаһы ярҙамында сессия булдырыу, реестры үҙгәрештәрен, эстафетаны манифестар, шифрланған сигнализация һәм ҡулланыу өлгөһө урынына тотоноу өсөн бөтә конференц-хәллеген сит сылбырҙан.

Реестрға нигеҙләнгән lifecycle:

- `CreateKaigi`: домен аҫтында шылтыратыу булдырыу һәм уның сәйәсәтен, графигын, метамәғлүмәттәрен һәм ирекле эстафетаны һаҡлау.
- `JoinKaigi`: саҡырыуҙар исемлеген яңыртыу. `zk-roster-v1` режимында асыҡ саҡырыу ҡарауы ҡатнашыусы иҫәбенә түгел, ә йөкләмәләр һәм юҡҡа сығарыу һандарын асыҡлай IDs.
- `LeaveKaigi`: ҡатнашыусыны үтә күренмәле саҡырыуҙан алып ташлау. Шәхси режимда сығыу беренсе сығарылыш протоколында селтәрҙән ситтә була.
- `RecordKaigiUsage`: иҫәпләнгән ваҡыт һәм газ суммаһын өҫтәгеҙ.
- `EndKaigi`: ултырышты ябып, һуңғы ваҡыт билдәһен яҙҙыр.

Torii ҡушымтаға ҡараған түбәндәге һүҙҙәрҙе асыҡлай:

|`/v1/kaigi/relays` |рөхсәт ителгән исемлеккә индерелгән операторҙың үтенесе |эстафета резюме |

### CLI smoke test {#cli-smoke-test}

`iroha app kaigi` CLI менән башлағыҙ, әгәр һеҙ Torii һуңғы нөктәһенә тоташтырыу алдынан Kaigi транзакцияларын ҡабул итеүен раҫларға теләһәгеҙ. ```bash


Сценарийлы ағымдар өсөн бүлмәләрҙең йәшәү циклын асыҡтан-асыҡ идара итеү:

```bash
iroha app kaigi create \
  --domain kaigi.universal \
  --call-name daily \
  --host <i105-account-id> \
  --privacy-mode transparent \
  --room-policy authenticated

iroha app kaigi join \
  --domain kaigi.universal \
  --call-name daily \
  --participant <i105-account-id>

iroha app kaigi leave \
  --domain kaigi.universal \
  --call-name daily \
  --participant <i105-account-id>

iroha app kaigi record-usage \
  --domain kaigi.universal \
  --call-name daily \
  --duration-ms 120000 \
  --billed-gas 1500

iroha app kaigi end --domain kaigi.universal --call-name daily
```

Relays viewer tickets-һыҙ күрһәтә алған rooms өсөн `--room-policy public`, ә exits viewer authentication талап итергә тейеш булғанда `--room-policy authenticated` ҡулланығыҙ. Network-та Kaigi roster һәм usage verifying keys configured булғандан һуң ғына `--privacy-mode zk-roster-v1` ҡулланығыҙ; юғиһә joins, leaves һәм private usage records deterministic verification ваҡытында fail итә.

## CLI Ҡыҫҡа юлдар {#cli-shortcuts}

`iroha` CLI был һуңғы һыҙаттарҙың күбеһен инде үҙ эсенә ала:

```bash
export IROHA_OPERATOR_KEY_FILE=/run/secrets/iroha/operator.key

iroha --config ./localnet/client.toml --operator-private-key-file "$IROHA_OPERATOR_KEY_FILE" \
  --output-format text ops sumeragi status
iroha --config ./localnet/client.toml --operator-private-key-file "$IROHA_OPERATOR_KEY_FILE" \
  --output-format text ops sumeragi diagnostics
iroha --config ./localnet/client.toml --operator-private-key-file "$IROHA_OPERATOR_KEY_FILE" \
  ops sumeragi params
iroha --config ./localnet/client.toml --operator-private-key-file "$IROHA_OPERATOR_KEY_FILE" \
  --output-format text ops sumeragi evidence count
```
