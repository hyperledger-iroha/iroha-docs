# Izanami менән хаос һынауҙары {#chaos-testing-with-izanami}

Izanami - Iroha өҫкө ағымындағы эш майҙанындағы хаос селтәре оркестраторы. Ул бер тапҡыр ҡулланылған урындағы Iroha кластерын башлай, конфигурацияланған эш йөкләмәһен тапшыра һәм һайланған пирҙарға хаталарҙы инжекциялай, шуға күрә операторҙар контролгә алынған уңышһыҙлыҡ ваҡытында селтәрҙең алға китешен тикшерә ала.

Izanami-ны производствоға тиклемге сыҙамлылыҡ тикшереүҙәре, регрессия воспроизведениеһы һәм консенсус көйләү өсөн ҡулланығыҙ. Уны етештереү селтәренә йүнәлтмәгеҙ: инструмент ул башлаған пирҙарға эйә булыу өсөн тәғәйенләнгән, шул иҫәптән пирҙарҙың ҡайтанан старты, һаҡлау сүплектәре, ваҡытлыса ышаныслы пирҙар менән бүлеүҙәр, урындағы CPU йәки диск баҫымы.

## Шарттар {#prerequisites}

Izanami-ны [Iroha сығанаҡ репозиторийынан](https://github.com/hyperledger-iroha/iroha) түгел, ә был документтар репозиторияһынан эшләтергә:

```bash
git clone https://github.com/hyperledger-iroha/iroha.git
cd iroha
cargo build -p izanami
```

Бинарға селтәрле пирҙары булдырыу һәм улар менән идара итеүгә асыҡтан-асыҡ рөхсәт бирергә кәрәк. TUI булмаған һәр йүгереү өсөн `--allow-net` үтә, йәки TUI системаһында `allow_net` ҡеүәтенә эйә булыу.

```bash
cargo run -p izanami -- --allow-net --peers 4 --faulty 1 --duration 120s
```

Интерактив хәрәкәт конфигурацияһы өсөн:

```bash
cargo run -p izanami -- --tui --allow-net
```

Izanami TUI һәм CLI параметрҙарын ҡулланыусылар конфигурацияһы каталогы аҫтында һаҡлай. Беренсе сығарылыш файлында бер асыҡтан-асыҡ V1 макеты байты бар; алдынғы сығарыу йәки башҡа төрлө версияһыҙ ҡуйылған параметрҙар кире ҡағыла һәм күсереү урынына яңынан барлыҡҡа килтерелергә тейеш. Хәҙерге профилде яңынан ҡулланыр алдынан күрһәтелгән параметрҙарҙы тикшерегеҙ.

## Башланғыс күрһәткес {#baseline-run}

Ауыр хаталар өҫтәлмәҫтән алда бер ҡабатланырлыҡ башланғыс күрһәткес менән башларға кәрәк:

```bash
cargo run -p izanami -- \
  --allow-net \
  --peers 4 \
  --faulty 1 \
  --duration 5m \
  --target-blocks 100 \
  --progress-interval 15s \
  --progress-timeout 120s \
  --latency-p95-threshold 2s \
  --tps 15 \
  --max-inflight 32 \
  --submitters 1 \
  --seed 42
```

Был йүгереү бары тик кластер һоралған блок маҡсатына еткән, ваҡыт үтеү ваҡыты эсендә алға китеш яһаған һәм факультатив p95 блок интервале сигенән түбән ҡалған осраҡта ғына уңышлы була.

Команданы, орлоҡто, Iroha commit, peer count, faulty-peer count, workload profile, target TPS һәм latency thresholdты яҙҙырығыҙ. Был ҡиммәттәрһеҙ башҡа оператор шул уҡ уңышһыҙлыҡ моделен ҡабатлай алмай.

## Эш йөкләмәһе профилдәре {#workload-profiles}

Izanami-ның ике эш йөкләмәһе профиле бар:

|Профиль |Уны  өсөн ҡулланырға|Белешмәләр |
| -------- | -------------------------------------------------- | -------------------------------------- |
|`stable` |Оҙайлы һыу һибеүҙәр һәм ҡабатланғыс һөҙөмтәлелек тикшереүҙәре |Ҡулланыуға хәүефһеҙ рецепттарҙы хуплай |
|`chaos` |Яуызлыҡ юлы менән тәьмин итеү |Маҡсатлы рәүештә ялған рецепттарҙы үҙ эсенә ала |

Тәүҙә тотороҡло профилде ҡулланығыҙ:

```bash
cargo run -p izanami -- --allow-net --workload-profile stable --seed 42
```

Төп һыҙығы инде аңлайышҡас, хаос профиленә күсеү:

```bash
cargo run -p izanami -- --allow-net --workload-profile chaos --seed 42
```

Контрактҡа урынлаштырыу өсөн рецепттар, әгәр быны асыҡтан-асыҡ рөхсәт ителмәһә, тотороҡло этапта эшләмәй:

```bash
cargo run -p izanami -- \
  --allow-net \
  --workload-profile stable \
  --allow-contract-deploy-in-stable
```

`--nexus` ҡулланыу, әгәр йүгереү өҫтәмә эш майҙанынан индерелгән SORA Nexus ҡалыптарҙы ҡулланырға тейеш.

## Хаталар менән идара итеү {#fault-controls}

`--faulty` нулдән ҙурыраҡ булғанда, кәм тигәндә бер хата сценарийы әүҙем булырға тейеш. Хата күсергестәре ғәҙәттә әүҙем була, ә логик флагтарҙы `=false` ярҙамында һүндереп була.

|Гонаһ |CLI флаг |Ул нимә эшләй ?|
| ------------------------ | ------------------------------------------ | ------------------------------------------ |
|Авария һәм яңынан стартлау |`--fault-enable-crash-restart` |Пирҙар процесын юғалтыу һәм тергеҙеү |
|Һаҡлауҙы һүндереп , ҡабаттан ҡуҙғатыу |`--fault-enable-wipe-storage` |Юғалған урындағы дәүләттән һауыҡтырыу |
|Яуыз транзакция спамы |`--fault-enable-spam-invalid-transactions` |Ҡабул итеү һәм кире ҡағыу юлдары |
|Ауырыу ваҡыты |`--fault-enable-network-latency` |Тәкәббер һөйләшеүҙәр һәм һуңғараҡ килеү хәбәрҙәре |
|Сеть бүлеү |`--fault-enable-network-partition` |Ваҡытлыса ышаныслы тиңдәрҙән айырылып тороу |
|CPU стресс |`--fault-enable-cpu-stress` |Урындағы валидациялау һәм графиклау баҫымы |
|Дисктың тығыҙлығы |`--fault-enable-disk-saturation` |Урындағы һаҡлау баҫымы |

Тик селтәр бүленеше өсөн:

```bash
cargo run -p izanami -- \
  --allow-net \
  --peers 4 \
  --faulty 1 \
  --duration 5m \
  --fault-window-start 60s \
  --fault-window-end 180s \
  --tps 15 \
  --submitters 1 \
  --max-inflight 32 \
  --fault-enable-crash-restart=false \
  --fault-enable-wipe-storage=false \
  --fault-enable-spam-invalid-transactions=false \
  --fault-enable-network-latency=false \
  --fault-enable-network-partition=true \
  --fault-enable-cpu-stress=false \
  --fault-enable-disk-saturation=false \
  --seed 42
```

`--fault-window-start` һәм `--fault-window-end` ҡулланып, инжекцияланған уңышһыҙлыҡҡа тиклем һәм унан һуң контрольле стационар торошо һаҡлай. Был яңылышлыҡтың һөҙөмтәһенән старт тауышын айырыуҙы еңеләйтә.

## Сценарий формалары {#scenario-shapes}

Үрге ағымы Izanami каталогы CLI профилдәренә блокчейн аралашыу уңышһыҙлығы формаларын карталар. Һеҙ уларҙы шул уҡ флагтар менән өлгөләй алаһығыҙ:

|Сценарий |Типтик форма |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------ |
|Маҡсатлы йөкләмә |`--faulty 0`, юғары `--tps`, бер тапшырыусы, юғары `--max-inflight` |
|Ваҡытлы уңышһыҙлыҡ |Сикләү / ҡабаттан башлауҙы сикләнгән хаталы тәҙрә эсендә генә ҡулайлаштырыу |
|Туҡтау һәм һауыҡтырыу |crash / restart менән ҙур хаталы- peer популяцияһы ҡулланыу |
|Лидерҙар изоляцияһы |Тик селтәр бүлеү хатаһы менән тап бер хаталы пир ҡулланыу; Izanami Sumeragi лидер телеметрияһын тота |

Бер үк ваҡытта бер үҙгәреүсәнде тоторға кәрәк. Әгәр һеҙ бер үк ваҡытта пирҙар һанын, эш йөкләмәһе профилен, хаталар тәҙрәһен һәм TPS үҙгәрһәгеҙ, һөҙөмтәне тәржемә итеү ҡыйын буласаҡ.

## Нимә күрергә кәрәк? {#what-to-watch}

Йүгереү ваҡытында һөҙөмтәлелекте раҫлау өсөн ҡулланылған сигналдарҙы күҙәтегеҙ:

- һәр йүгереүсе менән бергә блок бейеклеге буйынса алға китеш
- тапшырылған, ҡабул ителгән, кире ҡағылған һәм ваҡытлыса тамамланған операциялар
- сират тәрәнлеге, сират тығыҙлығы һәм һуңғы нөктәләрҙең кире баҫымы
- ҡарау үҙгәрештәрен, тергеҙеү юлдарын, юғалған блоктарҙы һәм юғалған кворум сертификаттарын
- RS16 ҡул ҡуйылған доступность backlog, сираттағы ултырыштар һәм консенсус хәрәкәтенең кисектерелеүе
- CPU, хәтер, диск һәм селтәрҙең туйыныусы хост башҡарыусы пирҙары

Валидация-оҙайлылыҡ анализы өсөн, төп әйләнештәге дебог журналдарын булдырыу:

```bash
RUST_LOG=iroha_core::sumeragi::main_loop=debug \
  cargo run -p izanami -- --allow-net --seed 42
```

Һәр block `block validation timings` аша `stateless_ms`, `execution_ms` һәм `total_ms` сығарырға тейеш. Consensus timers-ты үҙгәртер алдынан был timings-ты p95 block intervals, view-change counters һәм queue pressure менән сағыштырығыҙ.

## Һөҙөмтәләрҙе аңлатыу {#interpreting-results}

Барлыҡ һайлап алынған пирҙар блоктарҙы commit итеүен дауам иткәндә, артта ҡалыуҙар сикләнмәйенсә үҫмәгәндә һәм конфигурацияланған тәҙрә тамамланғандан һуң хаталар яңы тергеҙеү эшмәкәрлеген тыуҙырыуҙы туҡтатҡанда йүгереүҙе сәләмәт тип иҫәпләгеҙ.

Йүгереүҙе уңышһыҙлыҡ тип һанарға кәрәк:

- `--progress-timeout` тиклем оҙайлы блок прогресс эстафетаһы
- Пирҙарҙың бейеклектәре айырыла һәм ҡабаттан бер-береһенә ҡушылмай
- p95 задержкаһы `--latency-p95-threshold`
- Яуызлыҡ тәҙрәһе ябылғандан һуң, сираттар дауам итә
- кире ҡаҡҡан йәки ваҡытлыса тамамланған транзакциялар һайлап алынған йөкләмә менән аңлатылмай
- Бер-береһе менән ҡабаттан башлау, һаҡлауҙы таҙартыу йәки бүлеүҙәрҙе тергеҙеү ҡулдан йыйыштырыу талап итә

Яуызлыҡ булғандан һуң ҡабаттан шул уҡ орлоҡ менән һәм бер аҙ яңылышлыҡ төрө менән эшләгеҙ, был эш йөкләмәһен һәм ваҡытты ҡабатландырыуға мөмкинлек бирә.
