# Конфигурация мәсьәләләрен хәл итеү {#troubleshooting-configuration-issues}

Был бүлектә Iroha 3 конфигурацияһы өсөн проблемаларҙы хәл итеү буйынса кәңәштәр бирелә. Тәүҙә [ төймәләрен](./overview.md#check-the-keys) тикшерегеҙ, сөнки был Iroha-та иң йыш килеп сыҡҡан мәсьәләләр сығанағы.

Әгәр һеҙ кисергән проблема бында һүрәтләнмәгән икән, [Telegram](https://t.me/hyperledgeriroha) аша беҙҙең менән бәйләнешкә инегеҙ.

## Docker Compose ҡоролмаһы буйынса иҫкергән генез {#outdated-genesis-on-a-docker-compose-setup}

Әгәр һеҙ ҡулланыу Docker Compose версияһы Iroha, һеҙ бер-береһе менән тиң контейнерҙар проблемаһын осратырға мөмкин `Failed to deserialize raw genesis block` хата. Был, ғәҙәттә, пирҙар, ҡул ҡуйылған генез транзакцияһы һәм барлыҡҡа килгән конфигурация башҡалар тарафынан эшләнгән Iroha ревизиялар йәки профилдәр.

Валидаторҙарҙың журналдарын ҡарау өсөн йыйылма каталогында `python3 poc.py logs` командаһын башҡарығыҙ. Docker мөхитендә бер үк версиянан йыйылған башҡарылма файлдар менән дүрт валидатор төҙөү һәм эшләтеп ебәреү өсөн [Башлау Iroha 3](/ba/get-started/launch-iroha.md) ҡулланмаһын ҡарағыҙ.

Шул уҡ селтәрҙе ҡабат эшләтеп ебәреү өсөн тәүҙә `python3 poc.py down`, унан `python3 poc.py up` командаларын башҡарығыҙ. `state/` каталогын селтәрҙең дүрт Docker томы менән бергә һаҡлағыҙ.

::: info

Эшләп торған селтәрҙә башланғыс блокты алмаштырыу өсөн дөйөм автоматик ысул юҡ. Быны килешелгән күсереү итеп ойоштороғоҙ: элекке хәлде һаҡлап ҡалығыҙ, ярашлы төйөндәрҙе эшләтеп ебәрегеҙ һәм операторҙар күсереү планын килешкәс кенә валидаторҙарҙы яңы конфигурацияға күсерегеҙ.

:::

## Шәхси һәм асыҡ асҡыстарҙың мультихеш форматы {#multihash-format-of-private-and-public-keys}

Әгәр һеҙ [клиент конфигурацияһына ҡараһағыҙ](/ba/guide/configure/client-configuration.md), ундағы асҡыстарҙың [ күп һанлы хэш форматында бирелгәнен күрерһегеҙ](https://github.com/multiformats/multihash).

Әгәр ҙә һеҙ быға тиклем күп-хаш менән эшләмәгәнһегеҙ икән, уң яҡта төп байттарҙың (байтҡа ике символ), ә ASCII (йәки UTF-8) тип кодланған байттарҙың алты тигеҙлектәге сағылышы түгел, тип фаразлау тәбиғи. һәм `public_key` менән `private_key` экземплярҙарында уҡ буквалға `from_hex` саҡырыу.

`PrivateKey::try_from_str`-ҙы string literal-да саҡырыу дөрөҫ key-ҙы ғына бирер тип уйлау ҙа тәбиғи. Шуға күрә key-ҙағы bit һанын яңылыш күрһәтһәгеҙ, мәҫәлән 32 bytes урынына 64, error message сығыр тип көтөргә мөмкин.

Был ике фараз да дөрөҫ түгел. Ҡыҙғанысҡа ҡаршы, хата хәбәрҙәре был типтағы уңышһыҙлыҡты асыҡлауҙа ярҙам итмәй.

Тейешләү ысулы: `hex_literal` ҡуллана. Был шулай уҡ ҡырағай хәрефтәрҙе матур бәләкәй таблицаға әйләндерәсәк, ул һигеҙенсе һандарҙан тора.

::: warning

Хатта `try_from_str` ғәмәлгә ашырыуы бирелгән ҡылдың `PrivateKey` буламы-юҡмы икәнен тикшерә алмай һәм әгәр булмаһа, иҫкәртә алмай.

Ул ҡайһы бер асыҡ хаталарҙы тотор, мәҫәлән, ҡылда ғәмәлһеҙ символ бар икән. Әммә беҙ күп кенә төп форматтарҙы яҡларға тырышҡанға күрә, ул башҡа бик күп эш итә алмай. Әгәр ҙә һеҙ инструкция бирмәһәгеҙ, ул индерелгән иҫәб өсөн шәхси асҡыстың дөрөҫмө икәнен дә әйтә алмай.

:::

Ошондай хаталарҙан һаҡланырға мөмкин, мәҫәлән, туранан-тура сылбырлы хәрефтәрҙән дезерализация яһап йәки мәғәнәле урындарҙа яңы асҡыс парын барлыҡҡа килтереү.
