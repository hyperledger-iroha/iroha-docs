# Torii Хөгжлийн түвшин {#torii-endpoints}

Torii Энэ бол HTTP, SSE, болон WebSocket нэвтрүүлэг Iroha 3. Энэ нь аль алинд нь номын сан руу чиглэсэн APIs болон операторын төгсгөлийн цэгүүд.

Одоогийн протоколын дүрэм нь:

- Каноникийн бинар хэлбэр нь Norito
- олон төгсгөл нь ч дэмждэг JSON та илгээх үед `Accept: application/json`
- метрик нь Prometheus хэлбэрээр илрүүлж байна

Форматын дэлгэрэнгүй мэдээллийг, агуулгын хэлэлцээр, зохион байгуулалтын тэмдэг, схемын хэшиг, Norito RPC заавар, үзнэ үү [Norito дуудлага](/mn/reference/norito.md).

SSE хүсэлтийн хувьд эх сурвалжийн урсгалыг нэмж түрэмгийлсэн дутагдалтыг сурталчил:

```http
Accept: text/event-stream, application/json
```

Torii хамгийн түрүүнд JSON эсвэл Norito төлөөллийг хүсэлтийн давхар дээр хэлэлцүүлнэ, дараа нь үндсэн `text/event-stream` хариултыг баталгаажуулна. Тиймээс зөвхөн `text/event-stream` илгээлтийг `406`-ээр татгалздаг; [ урсгалын үйл явдлуудын рецепт ](/mn/cookbook/stream-events.md) нь бүрэн цөм хуудас ашиглана.

`/openapi` схемаар илэрхийлэгдсэн чиглэлийн үндсэн гэрээ, Одоогийн баримт бичигт үйл ажиллагааны шинжилгээний цогц жагсаалт байхгүй. `/livez` болон `/readyz`, болон түүний `/health` тодорхойлолт нь бэлэн байдлын хяналтын ажилтныг салах боломжтой. Амьд баримтаас маршрутын үйлчлүүлэгчийг бий болгох, Харин хөдөлгөөнт түймэр болон хамарсан хэрэглэгчдийн эсрэг шууд амьжиргаатай, бэлэн байдлыг баталгаажуулна. Тухайн талбай нь бүтээн байгуулалтын шинж чанар, гүйлгээний хугацааны конфигурацыос хамаарна. [Torii API консоль](/mn/reference/torii-api-console.md) Энэ амьд баримтыг борлуулахын тулд шалгалт JSON зам, хувилбар curl хүсэлтүүд, өнөөгийн схемаас үйлчлүүлэгчний код бий болгох.

## Амьдрал Taira замыг туршиж үзээрэй {#try-live-taira-routes}

Олон нийтийн Taira туршилтын сүлжээ нь зөвхөн уншдаг хайгуулын тулд хэрэглэлийн үйлчлүүлэгчид ашиглаж буй ижил Torii JSON гадаргыг илрүүлж байна. Эдгээр захирамжийн хувьд түлхүүр шаардлагагүй:

```bash
TAIRA_ROOT=https://taira.sora.org

curl -fsS -H 'Accept: application/json' "$TAIRA_ROOT/status" \
  | jq '{blocks, txs_approved, txs_rejected, queue_size, peers}'

curl -fsS "$TAIRA_ROOT/openapi.json" \
  | jq -r '.paths | keys[]' \
  | grep '^/v1/' \
  | head -n 20

curl -fsS -H 'Accept: application/json' \
  "$TAIRA_ROOT/v1/node/capabilities" \
  | jq '{abi_version, data_model_version, query: .query.aggregate.supported_resources}'
```

Дэлхийн өнөөгийн байдалтай харьцуулахад ресурс уншдаг:

```bash
curl -fsS "$TAIRA_ROOT/v1/domains?limit=5" \
  | jq -r '.items[].id'

curl -fsS "$TAIRA_ROOT/v1/assets/definitions?limit=5" \
  | jq -r '.items[] | [.id, .name, .total_quantity] | @tsv'
```

Хэрэв олон нийтийн тестний замаар `502`, цаг хугацааг дуусгах, эсвэл дүүрэн шугам мэдээлэх бол эцсийн цэглэлийн хүртээмжтэй асуудлаар авч үзээрэй, дараа нь үйлчлүүлэгчдийн кодгоо засварлах өмнө дахин туршиж үзээрэй.

## Акунтын баталгаажуулалт, илрүүлэлт, хайгуулын cursors {#account-authentication-visibility-and-explorer-cursors}

### Хэрэглээний бүртгэлийн хүсэлтийн протокол {#app-account-request-protocol}

Хэрэглээний чиглэлд итгэлийг баталгаажуулах гадаргуудыг хүлээн зөвшөөрөхгүй, нэг шууд ганц түлхэгийн батламж, эсвэл нэг олон талт гэрч.

Турах гэрчилгээ авахын тулд дөрвөн гарын үсэг нэгтүүлээрэй:

- `X-Iroha-Account`: тод санхүүгийн `0x` бүртгэлийн хаяг хекс эсвэл идэвхтэй санхүүгийн ASCII бүртгэл хекс. I105 бичгийг HTTP талбайны үнэ цэнэ гэж баталгаажуулахгүй; тухайн сүлжээний хувьд санхүүгийн хекс орчуулгыг ашиглана.
- `X-Iroha-Signature`: хязгаарлагдмал 64 гарын үсэг зурсан хэрэглээний ачаалал.
- `X-Iroha-Timestamp-Ms`: конфигуруулсан сүлжээний цонхины дотор миллисекундээр тэмдэглэгдэж буй Canonical unsigned decimal Unix Time Stamp.
- `X-Iroha-Nonce`: 1 - 256 хэвлэх боломжтой ASCII байт (`0x21`ээс `0x7e` хүртэл), дахин тоглох цонхины дотор цогц.

Тус бүртгэгдсэн нэг түлхүүртэй хяналтын тоног төхөөрөмж нь яг эдгээр байтыг тэмдэглэдэг:

```text
iroha.app.request.network.v1\0 || <genesis-derived network_id[32]> ||
<UPPERCASE_METHOD>\n
<exact request path>\n
<canonical query>\n
<lowercase hex SHA-256 of the raw body>\n
<canonical timestamp_ms>\n
<nonce>
```

Каноникийн асуултын бүтэц нь түүхий хайрыг `application/x-www-form-urlencoded` (`+` гэдэг нь орон зай гэсэн үг) гэж шинжилгээ хийж, хувь нь хосуудыг унтрааж, `(key, value)`-ээр ангилагдаж, дахин хэлбэрээр кодлодог. Протокол нь хамгийн ихдээ 64 декодируулсан хосууд болон 64 KiB түүхий хайлтын текст хүлээн зөвшөөрөгддөг. Байт хэсгийг дамжуулахад яг ижил төстэй болгоно. Нөөц 32-байтын сүлжээ ID болон томоохон бичгийн арга хооронд хуваагчийг оруулбаарай.

V1 баталгаажуулагч нь мөн арга зүйн токенд 32 байт, хувийн кодлогдсон хүсэлтийн замыг 64 KiB болон шууд дансны тодорхойлолтыг 36 KiB-д шинжилгээ хийхээс өмнө барьж өгдөг. Акунтын нууц нэрүүд нь гурван нэр хэсгээс гадна тэдгээрийн хуваагчдын бүрэлдэхүүнд хатуу бүтцийн хязгаартай байдаг.

Үүнээс гадна олон тамгын захирал нь `X-Iroha-Witness` Үндсэн хуулийн 64 дэглэм Norito болон хаяж байна `X-Iroha-Signature`, `X-Iroha-Timestamp-Ms`, болон `X-Iroha-Nonce`. `X-Iroha-Account` энэ хэлбэрээр сонголттой; одоо болтол гэрчтэй тэнцэх ёстой `subject_account`. Үндсэн хуулийн `CanonicalRequestWitnessV1` агуулагддаг `schema_version`, `subject_account`, `timestamp_ms`, `nonce`, нэг Iroha `Hash` Тухайн сүлжээний хүсэлт байт нь биеийн хоолой дамжуулан, гэхдээгүй УИХ-ын гишүүн бүр Каноникийн гэрээг бичиж Norito Тухайн хэрэглээний ачааны кодлогыг гарын үсэг зурах массивгүйгээр кодлах. Сангийн одоогийн олон тамгын бодлогыг хангасан байх ёстой MiB.

Үнэнчлэлийн гарын үсэггүй байх нь нууцлан ашиглах боломжийг сонгон шалгаруулдаг. Бусад хэсгэгдсэн, халуун, давтамдсан, алдаатай, хуучин эсвэл дахин тоглосон баталгааг өгөх нь үнэнчлэлийг үгүй болгодог; энэ нь хэзээ ч нууцлан илрүүлэхэд хүрэхгүй байна.

### Үйлчлүүлэгчдийн хүсэлтний протокол {#operator-request-protocol}

Үйлчлүүлэгчээр баталгаажуулсан гэж тэмдэглэгдсэн замыг бүх дөрвөн цорын ганц толгой нь шаарддаг:

- `x-iroha-operator-public-key`: Iroha олон хэсгийн олон нийтийн товч.
- `x-iroha-operator-timestamp-ms`: санхүүгийн гарын үсэг зурдаггүй унсийн Unix цаг хугацааны тэмдэг нь милсекунд.
- `x-iroha-operator-nonce`: 1-256 хэвлэх боломжтой ASCII байт, дахин тоглох цөмөр дотор байгаа түлшний хувьд онцлог.
- `x-iroha-operator-signature`: хязгаарлагдмал 64 гарын үсэг зурсан хэрэглээний ачаалал.

Газар товчлогын үнэ цэнэ нь эргэн тойрон дахь цагаан оргилгүй байх ёстой.

```text
iroha.operator.http-request.network.v1\0 || <genesis-derived network_id[32]> ||
<UPPERCASE_METHOD>\n
<exact request path>\n
<canonical query>\n
<lowercase hex SHA-256 of the raw body>\n
<canonical timestamp_ms>\n
<nonce>
```

Зам, хайл, бие, цаг мөрийн тэмдэг, нонс дүрэмүүд нь апп протоколын ашигладаг мөн адил хуулийн дүрэм юм. Үндсэн цэг нь мөн `[torii.operator_signatures]`: жагсаалтад оруулах `allowed_public_keys`, эсвэл тодорхой зөвшөөрөл олгох `allow_node_key` Нөөц товчлогыг ашиглахдаа. Torii хүсэлтээ хүлээн зөвшөөрөхгүй `503 Service Unavailable`. Үндсэн хуулийн дагуу WebAuthn эсвэл mTLS үйлдвэрийн баталгаажуулалт нь нэмэлт хүчин зүйл бөгөөд энэ шаардлагын яг гарын үсэг хэзээ ч залгамжлахгүй.

ISO 20022 замаар хоёр бие даасан хяналт шалгаруулалт явагдана. Хэрэглэгчийн зөвшөөрлийн жагсаалт болон гарын үсэг зурах протоколыг түрүүлнэ; дараа нь ISO үйлдвэрийн гүйцэтгэгч нь доор заасан яг оролцогч эсвэл аудитын үүргийг гүйцэтгэхэд ижил цөмөө шаарддаг.

### "Леджер"-ийн илрүүлэлт, "Эксплорер" -ийн гадуурч {#ledger-visibility-and-explorer-cursors}

Хэрэглээний чиглэсэн томоохон бичиг нь дээрх сонголттой хэрэглэлийн дансны хязгаарыг ашигладаг. Гарын үсэг зураагүй хүсэлтийг зөвхөн олон нийтээр тохируулсан өгөгдлийн газар хүлээн авна. Хэрэглэгчийн одоогийн UAID-д холбогдсон өгөгдлийн талбай, тодорхой `CanReadRestrictedDataspace { dataspace }` зөвшөөрөлтэйгээр нэрлэсэн хязгаарлагдсан өгөгдэл талбай тус бүр, эсвэл бүртгэлтэй `CanReadAllLedgerData` болгон бүх чиглэлүүд.

Үүнтэй ижил харагдалтай объект нь бүртгэл, домен, хөрөнгийн тодорхойлолт, хөрөнгө, NFT, RWA, эзэмшигч, Explorer уншдаг. Транзакцын хувьд бүртгэгдсэн бүх маршрутын хөл нь харагдаж байх үед л гүйцэтгэсэн гүйлгээ, зааварчилгааны түүхийг харуулна. Тиймээс оролцогчдын нэг хөл нь ч дуудлагын хүрээний гадна байх үед нуугдаж байдаг; алдагдалтай, богино эсвэл алдаатай чиглэлийн контекст нь зөвхөн дэлхийн уншигчдад харагддаг.

Дэлхий даяар дэмжлэг үзүүлж буй Explorer зургаан цуглуулга нь нээлттэй бус каноникийн base64url товчлогын курсоруудыг ашигладаг. Дашрамд хуудсны хязгаар нь 25, хамгийн их нь 100, нэг хуудас хамгийн ихдээ 512 нэр дэвшигч тоног шалгаж байна. Аливаа курсор нь цуглуулга, филтр, Canonical хамгийн сүүлдний түлхүүр болон шалгуурчийн харагдаж буй маршрут-сэт дигестэй холбогддог тул үүнийг өөр хайлт дээр эсвэл шалгуурчны үзэгдэл өөрчлөгдсөн дараа дахин тоглуулах боломжгүй.

Блок, гүйлгээ, хамгийн сүүлдээ хийсэн гүйлгэл, заавар, хамгийн сүүлийн үеийн заавар түүх Cursors нэмэлт нь заасан хяналтын зургийн өндөр болон block hash. Хариуд илрүүлж `pagination.limit`, `pagination.snapshot_height`, `pagination.snapshot_hash`, `pagination.next_cursor`, болон `pagination.has_more`. Torii өөр чиглэл эсвэл филтр байгуулсан курсор, харагдалтын өөрчлөлтийг үгүйсгэнэ эсвэл түймрийн баталгаажуулах боломжгүй хүйцэтгэг. Torii Хөдөлмөрийг зогсоох ажилтан яваад байх хугацаандаа шалгаруулалтын зөвшөөрөлтэй.

Эксплорер WebSocket урсгал нь филтрлэгдсэн товчлогыг гаргаж, томоохон бүртгэлийн зөвшөөрөл өөрчлөгдөх үед харагдахыг дахин тооцоолж байна. `GET /v1/blocks/stream` зам нь өөр: энэ нь бүрэн гарын үсэг зурсан блок гаргадаг, шаарддаг `CanReadAllLedgerData` Энэ зөвшөөрлийг дараа нь цуцлах бол хаадаг. Мэдээллийн орон зайтай хайгуулагчаар эх үүсвэрийн урсгалыг бүү ашигла.

## ISO 20022 гүүр {#iso-20022-bridge}

Torii нь ISO 20022 гүүрг `/v1/iso20022/*` -ийн дүнд байрлуулж байгаа бол аппликейшнээр чиглэсэн API болон гүүрний гүйлгээний цаг хугацаа идэвхтэй байдаг. Энэ нь ерөнхий зориулалттай ISO 20022 хийнэлийн хаалга биш, сонгогдсон төлбөрийн мэдээллийг Iroha гарын үсэг зурсан шилжүүлэн суулгах болон тэдгээрийн томоохон номын жагсаалтын байдлыг дагаж мөрдөнө гэсэн дэмжлэгтэй дэд баг юм.

Ямар ч өргөн мэдүүлгийг хүлээн зөвшөөрөхээсээ өмнө тогтвортой локалыг `torii.iso_bridge.store_dir` тохируулна. Конфигурацийн талбай нь зөвхөн унших эсвэл оношилгооны зориулалттай хэрэглээнд эхлэх боломжтой байхын тулд сонголттой юм: ISO-ийн баталгаажуулсан бүх өргөн мэдүүлэгт номын жагсаалтыг шаарддаг бөгөөд үргэлжлүүлэлгүй байх үед эсвэл дахин тоглох ёсны чулуу эсвэл бага бүртгэлийн бичлэг алдаатай бол сэргээгдэх `503 Service Unavailable`-ийг буцааж өгдөг.

### Үүнд оролцогчдын зөвшөөрөл, амьдралын мөрийг эзэмших эрх {#participant-authorization-and-lifecycle-ownership}

Аливаа зөвшөөрөлтэй гүүр нь оролцогчдын жагсаалтыг эзэмшдэг. оролцогчдын бүртгэл тусгай оролцогч ID, нэг эсвэл хэд хэдэн операторуудын олон нийтийн түлхүүр, нэг буюу хэд хэдэн санхүүгийн тодруулгыг, зөвшөөрөлтэй профилийн багц болон `originator`, `counterparty` эсвэл хоёулаа гүйцэтгэдэг. Үйлчлөгчний түлхүүр болон санхүүгийн тодруулгыг нэгээс дээш оролцогчтой байж болохгүй. `audit_admin_keys`-ийг тусдаа тохируулна; аудитын захиргааны түлхүүн нь мөн оролцогчдын мутацийн түлхүүл байж чадахгүй.

Бүх ISO замаар operator-ийн шинэхэн гарын үсэг зурах шаардлагатай. анхны `pacs.008`, `pacs.009`, `sese.023` эсвэл `colr.012` өргөн мэдүүлэг хийхэд баталгаажуулсан оператор нь өргөдлийн толгой `From` -ийн санхүүгийн тодруулгын дагуу тодорхойлсон оролцогчтой холбоотой байх ёстой. `To` тодорхойлолт нь `counterparty` үүрэг гүйцэтгэгчтэй конфигуруулсан оролцогчтой тохирох ёстой бөгөөд сонгогдсон хувилбар нь аль алинд нь зөвшөөрөлтэй байх ёстой. Байнгын бүртгэл нь эх үүсвэрлэгч, өрсөлдөгч, хүлээн зөвшөөрөгдсөн оролцогч болон үйлдвэрийн түлхүүр, анхны хувилбар болон гарын үсэг зурах бодлогыг баримтлах.

Амьдралын мөрийн зөвшөөрөл нь шалгуурчийн сонгосон үнэ цэнэээс бус энэ өөрчлөгдөхгүй бүртгэлээс үүдэлтэй:

|Амьдралын шатны мэдээ |Шаардлагатай оролцогч |
| ---------------------------------------------- | -------------------------------------------------- |
|`pacs.002`, `pacs.004`, `sese.024`, `sese.025`|`counterparty` үүрэг гүйцэтгэгч үндсэн контрагент |
|`camt.056` |`originator` үүрэг бүхий анхны эх үүсвэрч |

Эхний хувилбар болон гарын үсэг зурах бодлого нь бүхэлдээ хэвээр үлдлээ амьдралын мөчлөг, тиймээс дуудлага авдаг хүн шинэчлэл хийхэд хялбар хувилбарыг сонгож чадахгүй. `pacs.002` зохицуулалтыг илэрхийлэх код (`ACSC`, `ACCP`, `SETT`, эсвэл `SETTLED`) эх сурвалж бичгийг зөвхөн . Torii гүйлгээний гэрчилгээ хийжээ.

Аль ч анхны оролцогч нь өөрийн мэдээний бүртгэл болон үүсгэсэн гарын үсэг баримтыг уншиж болно. Аудитын төгсгөлийн цэг зөвхөн баталгаажуулсан оролцогч эхлүүлэгч эсвэл эсрэг этгээд байдаг бүртгэлийг буцааж байна. Өөрөөр хэлбэл тохируулсан аудитын захирал нь дэлхийн зөвхөн унших аудитын үзэл баримтыг хүлээн авдаг бөгөөд мэдээллийг ирүүлэхгүй, өөрчлөхгүй байна.

### Удахгүй тоглоомын тавилга, гарын үсэг зурсан аутбокс баримтууд {#durable-replay-identity-and-signed-outbox-documents}

Torii нь уншиж чадахгүй, хэт том хэмжээний, алдаатай, буруу нэртэй, зөрчилдөж байгаа эсвэл тодорхойгүй нийцүүлэггүй хошууны чулууг эхлүүлэхээр ашигладаг. Мөн энэ нь тодорхой бус схэмийн хувилбартай баялаг бүртгэл, оролцогч, профиль эсвэл гарын үсэг зургийн бодлогын хувьд одоогийн конфигурацын дутагдаагүй, эсвэл үл тохирсон амьд хошууны чулуу юм.

Бусад бага бүртгэлийн хохирол нь өөрөөр шийдвэрлэгддэг: уншишгүй эсвэл их хэмжээний файлууд, хүчингүй JSON, хүчингүй одоогийн схемын баримтууд, хууль ёсны бус файлын нэрүүд, зөрчилдөж байгаа дурдах тодруулгыг бүртгүүлж эсвэл орхидог. Одоогийн хувилбарын аудитын үнэлгээний уншиж чадахгүй эсвэл хүчингүй гэсэн индекс хадгалан үлдсэн бүртгэлээс сэргээн засвагддаг; зөвхөн тодорхой зохистой бус аудитын индексийн хувилбар нь эхлүүлэх үйл ажиллагааг зогсоодог. Барилгатын тэмдэглэлийг хяналт тавих, сэргээсэн аудитын манифстийг хангахын оронд бүх гэмтсэн бай бүртгэлийн файл нь түймэр үйлчлэхээс урьдчилан сэргийлэх гэж үзээрэй.

Нөхөрөгчдийн эзэмшлийн түүхий эдийг хадгалж үлдээсэн баялаг бүртгэлийн бүрэлдэхүүн нь өөрчлөгдөхгүй. ID, нөөц ачаалал хэш, бизнесийн мэдээ ID, болон UETR бүрэн дугаарлахын тулд TTL Тэр ч бүү хэл бага хэмжээний баримт бичгийн дэлгэрэнгүй мэдээллийг боловсруулсан ч гэсэн.

Torii нь амьдрах мөрийн мэдээллийг гарын үсэг зурахаасаа өмнө дахин тоглоомын хүлээн зөвшөөрөл хэвээр байна. Энэ нь хэзээ ч дуусгалын хугацааг дуусдаггүй дахин тоглоомыг устгахгүй. Хэрэв тохируулсан хүчин чадал бүрэн хамгаалалттай баримт бичиг эсвэл дууссан дурдах тодруулгыг эзэмшиж байгаа бол өргөн мэдүүлэг нь амьдралын мөчлөг болон нягтлан бодох байдлын өөрчлөлтийггүйгээр эргэн шилжүүлэх боломжтой `503 Service Unavailable` хүлээн авна.

Хүн төрөлхтний `pacs.002`, `pacs.004`, `camt.029`, `sese.024`, эсвэл `sese.025` баримт бичиг нь `application/xml` дараах хариуны цэгүүдтэй:

|Үргэлт|Энэ нь юу вэ?|
| ------------------------------ | ----------------------------------------------------- |
|`X-Iroha-Iso-Signature-Domain` |Байнга `iroha.iso20022.outbound.v2` |
|`X-Iroha-Iso-Signer` |Конфигуруулсан гүүрний гарын үсэг зурагчаар зориулсан Canonical public key |
|`X-Iroha-Iso-Signature` |Доменийн хуваарилсан XML байт дээр Base64 гарын үсэг зурах |

Хөдөлмөрийн гарын үсэг UTF-8 байт цуврал `iroha.iso20022.outbound.v2`, нэг нөлөөний байт, яг хариу биеийн. XML хяналт шалгахын өмнө.

## Kaigi Уулзалтууд {#kaigi-sessions}

Kaigi нь төлбөртэй, бодит цаг хугацааны аудио / видео өрөөнүүдийг SORA Nexus дээр хангадаг. Хэрэглэгт хэрэглээний бүртгэлээр дэмжлэг үзүүлэх сессийг бий болгох, жагсаалтыг өөрчлөх, ээлжит манифестүүд, шифрлэсэн сигнал өгөх, ашиглалтын хэмжилтийг хийх оронд бүх зөвлөлдөх хэсгийг гараагүй байлгахад ашиглаарай.

Тогтлан бодох бүртгэлийн амьдралын мөчлөг нь:

- `CreateKaigi`: доменийн хүрээнд дуудлагыг бий болгож, түүний бодлого, хуваарийн хугацаа, метабараа болон сонголттой ээлжит манифст хадгалах.
- `JoinKaigi` болон `LeaveKaigi`: дуудлагын жагсаалтыг шинэчлэн найруулж байна. Хувийн хэвээр оролцогчид оролцогчдын бүртгэл IDs-ийг шууд илрүүлэхийн оронд үүрэг гүйцэтгэх, хүчингүй болгох, жагсаалтын баталгааг ашиглана.
- `RecordKaigiUsage`: хэмжигдсэн хугацаа, газын нийт хэмжээг нэмнэ.
- `EndKaigi`: чуулганыг дуусгаж, эцсийн цаг мөрийг бүртгэж байна.

Torii цахилгаан дамжуулагчдын телеметрийг `/v1/kaigi/relays`, `/v1/kaigi/relays/{relay_id}`, `/v1/kaigi/relays/health`, болон `/v1/kaigi/relays/events` хэрэгсэл API Уулзалтын нөхцөл байдал нь Kaigi Тухайлбал, `KaigiRosterSummary`, `KaigiRelayManifestUpdated`, `KaigiRelayHealthUpdated`, болон `KaigiUsageSummary`.

### CLI Дамхины шинжилгээ {#cli-smoke-test}

Үүнээс эхлээд `iroha kaigi` CLI хэрэв та Torii төгсгөл нь хүлээн зөвшөөрдөг Kaigi бүтээн байгуулалтын өмнө UI. Удахгүй эхлэх команд нь идэвхтэй эсэргүүцлийн түр байранд ордог Torii төгсгөлийн цэг, дуудлагын тодруулгын товчлогыг хэвлэж, командлагыг нэгтгэх; ба SoraNet дугуйны илтгэл:

```bash
iroha kaigi quickstart --auto-join-host --summary-out kaigi-summary.json
```

Скриптийн урсгалын хувьд өрөөний амьдралын мөрийг тодорхой удирдаж үзээрэй:

```bash
iroha kaigi create \
  --domain streaming \
  --call-name daily \
  --host <i105-account-id> \
  --privacy-mode transparent \
  --room-policy authenticated

iroha kaigi join --domain streaming --call-name daily --participant <i105-account-id>
iroha kaigi leave --domain streaming --call-name daily --participant <i105-account-id>

iroha kaigi record-usage \
  --domain streaming \
  --call-name daily \
  --duration-ms 120000 \
  --billed-gas 1500

iroha kaigi end --domain streaming --call-name daily
```

Хэрэглээ `--room-policy public` үзэгчдийн төлбөргүйгээр дамжуулах боломжтой өрөөнүүдийн хувьд, эсвэл `--room-policy authenticated` нэвтрүүлэгчид үзэгчний баталгаажуулалтыг шаардагдах тохиолдолд `--privacy-mode zk-roster-v1` зөвхөн сүлжээ нь Kaigi жагсаалт, хэрэглээний баталгаажуулах түлхүүр тохируулсан; өөрөөр хэлбэл холболт, хуудас, болон хувийн хэрэглээний бүртгэл нь тодорхойлолтын шалгалтаар алдаатай байна.

### JavaScript дэммоор шинжилгээ хийх {#testing-with-the-javascript-demo}

[soramitsu/iroha-demo-javascript](https://github.com/soramitsu/iroha-demo-javascript) ширээний дэмог төгсгөл ба түлхүүр гарцааны туршилт хийхэд ашигла. Демо нь цахилгаан болон Vue аппликейшн юм бөгөөд орон нутгийн `@iroha/iroha-js` холбоос дамжуулан шууд Torii -д ярилцаж, браузерт үүссэн нэгээс нэг хэвлэл мэдээллийн хэрэгслийн `/kaigi` замыг багтаадаг.

Demo-ийг ашигла [`@iroha/iroha-js`](https://github.com/hyperledger-iroha/iroha/tree/0010c5a70039eac101a4846499ba9ceaf43eb65c/javascript/iroha_js) УИХ-ын Iroha Эх сурвалжийн агууламж. SDK дамжуулан `file:../iroha/javascript/iroha_js`, Тиймээс хоёр төлбөрийг энэ ах дүүгийн зураг төхөөрөмжээр хадгалах:

```bash
mkdir iroha-wallet-workspace
cd iroha-wallet-workspace
git clone https://github.com/hyperledger-iroha/iroha.git
git clone https://github.com/soramitsu/iroha-demo-javascript.git

cd iroha/javascript/iroha_js
npm install
npm run build:native
npm run build:dist

cd ../../../iroha-demo-javascript
npm install
npm run dev
```

Хэрэглээ Node.js 20 болон шинэ, Rust тоног төхөөрөмжийн сүлжээний тул эх орон `iroha_js_host` Модулын бүтээн байгуулалт хийж болно. SDK ах дүүгийн хувьд Iroha эх үүсвэрийг өөрчлөсний дараа төлөх; цэвэр багцын зураг төсөл нь `npm run build:native`.

Хяналтын шинжилгээний хувьд Kaigi -ийн чадвартай Torii төгсгөлийн цэг дээр дэмо үзүүлэлтийг зааж өгөх:

1. SORA/Kaigi хэрэглээнд чиглэсэн APIs нэгийг ашиглаж Iroha түймрийг эхлүүлж, эсвэл танд хэрэгтэй Kaigi гадаргуудыг илрүүлэх олон нийтийн төгсгөлийг ашигла.
2. Үндэсний хүртээмжтэй байдлыг шалгах `/health`, Дараа нь амьд замын давхаргыг шалгах `/openapi` эсвэл `/openapi.json`. Зарим нэвтрүүлэгүүд нь бас илрүүлэх `/v1/health`, Гэхдээ `/health` Энэ бол гар утасны амьжиргааны шалгалт юм.
3. Үүнд TAIRA, шууд уулзалт хийхээс өмнө ээлжит телеметрийн замыг шалгах:

   ```bash
   TAIRA=https://taira.sora.org
   curl -fsS "$TAIRA/health"
   curl -fsS "$TAIRA/v1/kaigi/relays"
   curl -fsS "$TAIRA/v1/kaigi/relays/health"
   ```

Эдгээр шалгалтууд нь Torii болон Kaigi ээлжит телеметрийн хүрэлцээг баталгаажуулдаг. Тэд уулзалт үүсгэдэггүй; `CreateKaigi` ба `JoinKaigi`-д аливаа санхүүжилттэй мөнгөний ханш, гарын үсэг зурсан гүйлгээ өргөн мэдүүлэг шаардлагатай байна.
4. Демо дэлгэцээ нээх, Тансагварын хэсгээр зайлах, Torii URL-ийг байгуулж, хэрэгслийн ID зангилаа болон сүлжээний префиксийг эцсийн цэгээс ачаалан гаргана.
5. Дэммо дээр хоёр орон нутгийн хөрөнгийг бий болгох, сэргээх. Үйлчлүүлэгч болон зочид буудлын байдал нь тусдаа байхын тулд өөр хоорондын аппликейшнүүд, хувилбар эсвэл машин ашиглах.

Kaigi UI-ийн шинжилгээ хийхэд:

1. Хост дэлгэцэнд Kaigi нээх, уулзалт эхлүүлэх сонгогдон нэрээ байгуулж, хувийн уриалгыг эсвэл ил тод уриалтыг сонгогдон үзээрэй.
2. WebRTC нь орон нутгийн хэвлэл мэдээллийн хэрэгсэлтэй байхын тулд камер, микрофонг идэвхжүүлнэ.
3. Хуралдааны холбоосыг бий болгоороо сонгоно. Амьд хөрөнгийн сан `CreateKaigi` -ийг ирүүлнэ; дараа нь `iroha://kaigi/join?call=...&secret=...` дуудлага болон `#/kaigi?...` -ийн эргэлтийн замыг үзүүлнэ.
4. Үйлчлүүлэгч цонхны дэлгэцээ нээлттэй байлгаж, уриалгыг зочидтай хуваалцаарай.
5. зочид буудлын үзэсгэлэнд урьлыг нээж, уулзалт дээр элсүүлж, орон нутгийн хэвлэл мэдээллийн хэрэгслийг идэвхжүүлэн хуралдаанд оролцохыг сонгоно. Амьдрал санхүүжилт нь Torii-ээс шифрлэгдсэн хостийн санал авдаг бөгөөд `JoinKaigi` -ийг шифрлэгдсэн хариултын мета өгөгдөлтэй хүргүүлнэ.
6. Үйлчлөгч нь Kaigi дуудлагын сигналыг дамжуулан эсвэл санал асуулга явуулж анхны хариултыг автомат хэрэглэх ёстой. Хоёр цонх нь холбогдсон хэвлэл мэдээллийн хэрэгсэл болон холбооны шинэчилсэн мэдээллийг харуулна.
7. Үйлчлүүлэгчээс уулзалт дуусгавал CLI `iroha kaigi end` команд нь ижил дуудлага ID дээр ашиглана.

Хувийн Kaigi хэрэгцээг хамгаалах XOR нь хувийн нэвтрүүлгийн цэгтийн төлбөрийг төлүүлэхэд шаардлагатай. Хэрэв демо нь хувийн Kaigi хэрэгцээгийг хамгаалах XOR гэж мэдээлвэл, аппликейшн дэх өөрийгөө хамгаалах илтгэлийг ашиглаж, бүтээх эсвэл нэгдэх үйлдлийг дахин туршиж үзээрэй. Хэрэв баталгаа үүсгэх, хувийн санхүүжилт, эсвэл амьд сигнал өгөх боломжгүй бол демо нь ил тод / дасан зохиолын урсгалд буцаж ирэх боломжтой.

Demo repo-д автомат хяналт шалгахын тулд:

```bash
npm test -- tests/kaigiView.spec.ts tests/preloadKaigiBridge.spec.ts
npm run e2e:ui
npm run verify
```

Vitest-ийн төвлөрсөн Suite нь Kaigi уулзалтын холбоосыг бий болгох, компакт уриалгыг борлуулах, хувийн бүтээх / нэгдэн оруулах / төгсгөх модны дуудлага, бие даасан хамгаалалтын илтгэлийг, гарын авлигуудыг хангах, хариултын санал асуулгаг хамруулдаг. UI хоолой шинжилгээний туршилтад ширээний болон гар утасны хэмжээний үзэсгэлэн дээр `/kaigi` замыг багтаадаг. Хоёр хөрөнгийн сангийн хооронд амьд хэвлэл мэдээллийн хэрэгсэл нь цахилгаан камер/микрофоны зөвшөөрөл болон дундаж хэвлэлийн урсгал нь байгаль орчинд тодорхой байдаг тул хоёр ширээний дасан зохицуулалтын туршилтыг хийх шаардлагатай.

Үлгэрийн интеграцийн код [г үзнэ үү Kaigi-ийг JavaScript-ийн App](/mn/guide/tutorials/kaigi.md)-д багтаажээ.

## Статус, үзүүлэлт {#status-and-metrics}

Статус болон метрикийн төгсгөл нь хамгийн түрүүнд дашборд руу холбогдсон зүйл юм:

- `/status` нь дээд түвшний өрсөлдөгч, блок, шуурхай, тохиролцооны талбайдыг илрүүлнэ
- `/metrics` нь Prometheus-ийн тооллогч, хэмжүүлэгч, хистограммыг илрүүлж байна

Nexus-ийн хүчин чадалтай түймрүүд дээр, статусын гарааны хувьд замын хөдөлгөөн болон өгөгдлийн орон зайг мэддэг хэсгүүд ч байдаг. `nexus.enabled = false` бол эдгээр хэсгүүд орхигддог.

## JSON v. Norito {#json-vs-norito}

Хөдөлмөрийн хэрэгслийн хэд хэдэн эцсийн цэг нь буцаадаг Norito Үндсэн хэсгээр: JSON, ирүүлнэ:

```http
Accept: application/json
```

Энэ нь:

- `/v1/sumeragi/status`
- `/v1/sumeragi/qc`
- `/v1/sumeragi/commit_qc/{hash}`

Хөгжлийн тоног төхөөрөмж нь Norito-ийг шууд хүлээн зөвшөөрөх эсвэл буцаадаг бол `application/x-norito` -г агуулгын төрөл болон `Accept` -ийн сонгосон үнэ цэнэ болгон ашиглаарай. Тээврийн дэлгэрэнгүй мэдээллийг [Norito](/mn/reference/norito.md#torii-and-norito-rpc)-д үзнэ үү.

## Telemetry Profiles {#telemetry-profiles}

Хөгжлийн тоног төхөөрөмжийн харагдал нь түйүлгийн `telemetry.profile` тохируулгаас хамаарна. Одоогийн конфигурацын хувьд таван профилийн түвшинг:

|Профиль |`/status` |`/metrics` |Хөгжлийн чиглэлүүд |
| --- | --- | --- | --- |
|`disabled` |Үгүй.|Үгүй.|Үгүй.|
|`operator` |Тийм ээ .|Үгүй.|Үгүй.|
|`extended` |Тийм ээ .|Тийм ээ .|Үгүй.|
|`developer` |Тийм ээ .|Үгүй.|Тийм ээ .|
|`full` |Тийм ээ .|Тийм ээ .|Тийм ээ .|

## CLI Урьдчилсан зам {#cli-shortcuts}

`iroha` CLI нь эдгээр төгсгөлийн олон зүйлийг аль хэдийнээ багтааж байна:

```bash
iroha --config ./localnet/client.toml --output-format text ops sumeragi status
iroha --config ./localnet/client.toml --output-format text ops sumeragi phases
iroha --config ./localnet/client.toml ops sumeragi params
iroha --config ./localnet/client.toml --output-format text ops sumeragi telemetry
```
