# Torii Хөгжлийн түвшин {#torii-endpoints}

Torii Энэ бол HTTP, SSE, болон WebSocket нэвтрүүлэг Iroha 3. Энэ нь аль алинд нь номын сан руу чиглэсэн APIs болон операторын төгсгөлийн цэгүүд.

Одоогийн протоколын дүрэм нь:

- Каноникийн бинар хэлбэр нь Norito
- олон төгсгөл нь ч дэмждэг JSON та илгээх үед `Accept: application/json`
- метрик нь Prometheus хэлбэрээр илтгэнэ

Форматын дэлгэрэнгүй мэдээллийг, агуулгын хэлэлцээр, зохион байгуулалтын тэмдэг, схемын хэшиг, Norito RPC заавар, үзнэ үү [Norito дуудлага](/mn/reference/norito.md).

SSE хүсэлтийн хувьд эх сурвалжийн урсгалыг нэмж түрэмгийлсэн дутагдалтыг сурталчил:

```http
Accept: text/event-stream, application/json
```

Torii хамгийн түрүүнд JSON эсвэл Norito төлөөллийг хүсэлтийн давхар дээр хэлэлцүүлнэ, дараа нь үндсэн `text/event-stream` хариултыг баталгаажуулна. Тиймээс зөвхөн `text/event-stream` илгээлтийг `406`-ээр татгалздаг; [ урсгалын үйл явдлуудын рецепт ](/mn/cookbook/stream-events.md) нь бүрэн цөм хуудас ашиглана.

`/openapi` схемаар илэрхийлэгдсэн чиглэлийн үндсэн гэрээ, Одоогийн баримт бичигт үйл ажиллагааны шинжилгээний цогц жагсаалт байхгүй. `/livez` болон `/readyz`, болон түүний `/health` тодорхойлолт нь бэлэн байдлын хяналтын ажилтныг салах боломжтой. Амьд баримтаас маршрутын үйлчлүүлэгчийг бий болгох, Харин хөдөлгөөнт түймэр болон хамарсан хэрэглэгчдийн эсрэг шууд амьжиргаатай, бэлэн байдлыг баталгаажуулна. Тухайн талбай нь бүтээн байгуулалтын шинж чанар, гүйлгээний хугацааны конфигурацыос хамаарна. [Torii API консоль](/mn/reference/torii-api-console.md) Энэ амьд баримтыг борлуулахын тулд шалгалт JSON зам, хувилбар curl хүсэлтүүд, өнөөгийн схемаас үйлчлүүлэгчний код бий болгох.

## Амьдрал Taira замыг туршиж үзээрэй {#try-live-taira-routes}

Олон нийтийн Taira туршилтын сүлжээ нь зөвхөн уншдаг хайгуулын тулд хэрэглэлийн үйлчлүүлэгчид ашиглаж буй ижил Torii JSON гадаргыг илрүүлж байна. Эдгээр захирамжийн хувьд түлхүүр шаардлагагүй:

```bash
TAIRA_ROOT=https://taira.sora.org

curl -fsS -H 'Accept: application/json' "$TAIRA_ROOT/status" \
  | jq '{blocks, txs_approved, txs_rejected, queue_size, peers}'

curl -fsS "$TAIRA_ROOT/openapi.json" \
  | jq -r '.paths | keys[]' \
  | grep '^/v1/' \
  | head -n 20

curl -fsS -H 'Accept: application/json' \
  "$TAIRA_ROOT/v1/node/capabilities" \
  | jq '{abi_version, data_model_version, query: .query.aggregate.supported_resources}'
```

Дэлхийн өнөөгийн байдалтай харьцуулахад ресурс уншдаг:

```bash
curl -fsS "$TAIRA_ROOT/v1/domains?limit=5" \
  | jq -r '.items[].id'

curl -fsS "$TAIRA_ROOT/v1/assets/definitions?limit=5" \
  | jq -r '.items[] | [.id, .name, .total_quantity] | @tsv'
```

Хэрэв олон нийтийн тестний замаар `502`, цаг хугацааг дуусгах, эсвэл дүүрэн шугам мэдээлэх бол эцсийн цэглэлийн хүртээмжтэй асуудлаар авч үзээрэй, дараа нь үйлчлүүлэгчдийн кодгоо засварлах өмнө дахин туршиж үзээрэй.

## ISO 20022 гүүр {#iso-20022-bridge}

Torii нь ISO 20022 гүүрг `/v1/iso20022/*` -ийн дүнд байрлуулж байгаа бол аппликейшнээр чиглэсэн API болон гүүрний гүйлгээний цаг хугацаа идэвхтэй байдаг. Энэ нь ерөнхий зориулалттай ISO 20022 хийнэлийн хаалга биш, сонгогдсон төлбөрийн мэдээллийг Iroha гарын үсэг зурсан шилжүүлэн суулгах болон тэдгээрийн томоохон номын жагсаалтын байдлыг дагаж мөрдөнө гэсэн дэмжлэгтэй дэд баг юм.

|`GET /v1/iso20022/messages/{msg_id}/camt029` |Одоогийн цуцлах тогтоолыг `camt.029` XML гэж өгөөч. |
|`GET /v1/iso20022/messages/{msg_id}/sese024` |Одоогийн тооцооны байдлыг `sese.024` XML гэж өгөөч. |
|`GET /v1/iso20022/messages/{msg_id}/sese025` |Одоогийн тооцооны баталгааг `sese.025` XML гэж өгөх. |

`pacs.008` өргөн мэдүүлэгт ID, банк хоорондын зохицуулалтын хэмжээ, валют, зохицуулын өдөр, өрийн болон итгэмжлэгчийн IBANs болон өрийн болон батлан өгөгдлийн BICs мэдээллийг хүргэж байна. Сэргээлийн өгөгдлийг конфигуруулбал, шугам нь үүсгэсэн гүйлгээний урсгалд орж ирэхээс өмнө BIC, IBAN болон ISO 4217 валютын хилжилтийг шалгаж байна.

`pacs.009` өргөн мэдүүлэгт бизнесийн мэдэгдэл ID, мэдээллийн тодорхойлолт ID, бүтээлийн цаг хугацаа, банк хоорондын зохицуулалтын хэмжээ, валют, зохицуулын өдрийг тусгаж өгөх ёстой. BICs захиалгын агент, захиалгын төлөөлөгч, өрийн халдагч болон итгэмжлэгчийн төлөөлөл IBANs. Мэдээлэлд `Purp` ордог бол цахилгаан нь одоогоор зөвхөн үнэт цаасны зориулалттай санхүүжилтийг хүлээн зөвшөөрдөг: `Purp=SECU`.

`pacs.008` болон `pacs.009` өргөн мэдүүлгийн төгсгөлийн цэгүүд нь XML ISO загварыг хүлээн зөвшөөрч, эсвэл гүүрний туршилт хийхэд хэрэглэгддэг тайван талбайн хэлбэрээр ашиглана. сонголттой `SplmtryData` талбай нь зорилтын Iroha номын санг татаж болно. эх үүсвэр, зорилтот данс IDs эсвэл хаяг, хөрөнгийн тодорхойлолт ID. Хариулт нь `202 Accepted` буюу `message_id`, `transaction_hash`, `status`, `pacs002_code` болон шийдвэрлэсэн томоохон бүртгэл/хувь сан/гөвийн хүрээнд байна.

## Kaigi Уулзалтууд {#kaigi-sessions}

Kaigi нь төлбөртэй, бодит цаг хугацааны аудио / видео өрөөнүүдийг SORA Nexus дээр хангадаг. Хэрэглэгт хэрэглээний бүртгэлээр дэмжлэг үзүүлэх сессийг бий болгох, жагсаалтыг өөрчлөх, ээлжит манифестүүд, шифрлэсэн сигнал өгөх, ашиглалтын хэмжилтийг хийх оронд бүх зөвлөлдөх хэсгийг гараагүй байлгахад ашиглаарай.

Тогтлан бодох бүртгэлийн амьдралын мөчлөг нь:

- `CreateKaigi`: доменийн хүрээнд дуудлагыг бий болгож, түүний бодлого, хуваарийн хугацаа, метабараа болон сонголттой ээлжит манифст хадгалах.
- `JoinKaigi` болон `LeaveKaigi`: дуудлагын жагсаалтыг шинэчлэн найруулж байна. Хувийн хэвээр оролцогчид оролцогчдын бүртгэл IDs-ийг шууд илрүүлэхийн оронд үүрэг гүйцэтгэх, хүчингүй болгох, жагсаалтын баталгааг ашиглана.
- `RecordKaigiUsage`: хэмжигдсэн хугацаа, газын нийт хэмжээг нэмнэ.
- `EndKaigi`: чуулганыг дуусгаж, эцсийн цаг мөрийг бүртгэж байна.

Torii цахилгаан дамжуулагчдын телеметрийг `/v1/kaigi/relays`, `/v1/kaigi/relays/{relay_id}`, `/v1/kaigi/relays/health`, болон `/v1/kaigi/relays/events` хэрэгсэл API Уулзалтын нөхцөл байдал нь Kaigi Тухайлбал, `KaigiRosterSummary`, `KaigiRelayManifestUpdated`, `KaigiRelayHealthUpdated`, болон `KaigiUsageSummary`.

### CLI Дамхины шинжилгээ {#cli-smoke-test}

Үүнээс эхлээд `iroha kaigi` CLI хэрэв та Torii төгсгөл нь хүлээн зөвшөөрдөг Kaigi бүтээн байгуулалтын өмнө UI. Удахгүй эхлэх команд нь идэвхтэй эсэргүүцлийн түр байранд ордог Torii төгсгөлийн цэг, дуудлагын тодруулгын товчлогыг хэвлэж, командлагыг нэгтгэх; ба SoraNet дугуйны илтгэл:

```bash
iroha kaigi quickstart --auto-join-host --summary-out kaigi-summary.json
```

Скриптийн урсгалын хувьд өрөөний амьдралын мөрийг тодорхой удирдаж үзээрэй:

```bash
iroha kaigi create \
  --domain streaming \
  --call-name daily \
  --host <i105-account-id> \
  --privacy-mode transparent \
  --room-policy authenticated

iroha kaigi join --domain streaming --call-name daily --participant <i105-account-id>
iroha kaigi leave --domain streaming --call-name daily --participant <i105-account-id>

iroha kaigi record-usage \
  --domain streaming \
  --call-name daily \
  --duration-ms 120000 \
  --billed-gas 1500

iroha kaigi end --domain streaming --call-name daily
```

Хэрэглээ `--room-policy public` үзэгчдийн төлбөргүйгээр дамжуулах боломжтой өрөөнүүдийн хувьд, эсвэл `--room-policy authenticated` нэвтрүүлэгчид үзэгчний баталгаажуулалтыг шаардагдах тохиолдолд `--privacy-mode zk-roster-v1` зөвхөн сүлжээ нь Kaigi жагсаалт, хэрэглээний баталгаажуулах түлхүүр тохируулсан; өөрөөр хэлбэл холболт, хуудас, болон хувийн хэрэглээний бүртгэл нь тодорхойлолтын шалгалтаар алдаатай байна.

### JavaScript дэммоор шинжилгээ хийх {#testing-with-the-javascript-demo}

[soramitsu/iroha-demo-javascript](https://github.com/soramitsu/iroha-demo-javascript) ширээний дэмог төгсгөл ба түлхүүр гарцааны туршилт хийхэд ашигла. Демо нь цахилгаан болон Vue аппликейшн юм бөгөөд орон нутгийн `@iroha/iroha-js` холбоос дамжуулан шууд Torii -д ярилцаж, браузерт үүссэн нэгээс нэг хэвлэл мэдээллийн хэрэгслийн `/kaigi` замыг багтаадаг.

Demo-ийг ашигла [`@iroha/iroha-js`](https://github.com/hyperledger-iroha/iroha/tree/main/javascript/iroha_js) УИХ-ын Iroha Эх сурвалжийн агууламж. SDK дамжуулан `file:../iroha/javascript/iroha_js`, Тиймээс хоёр төлбөрийг энэ ах дүүгийн зураг төхөөрөмжээр хадгалах:

```bash
mkdir iroha-wallet-workspace
cd iroha-wallet-workspace
git clone https://github.com/hyperledger-iroha/iroha.git
git clone https://github.com/soramitsu/iroha-demo-javascript.git

cd iroha/javascript/iroha_js
npm install
npm run build:native
npm run build:dist

cd ../../../iroha-demo-javascript
npm install
npm run dev
```

Хэрэглээ Node.js 20 болон шинэ, Rust тоног төхөөрөмжийн сүлжээний тул эх орон `iroha_js_host` Модулын бүтээн байгуулалт хийж болно. SDK ах дүүгийн хувьд Iroha эх үүсвэрийг өөрчлөсний дараа төлөх; цэвэр багцын зураг төсөл нь `npm run build:native`.

Хяналтын шинжилгээний хувьд Kaigi -ийн чадвартай Torii төгсгөлийн цэг дээр дэмо үзүүлэлтийг зааж өгөх:

1. SORA/Kaigi хэрэглээнд чиглэсэн APIs нэгийг ашиглаж Iroha түймрийг эхлүүлж, эсвэл танд хэрэгтэй Kaigi гадаргуудыг илрүүлэх олон нийтийн төгсгөлийг ашигла.
2. Үндэсний хүртээмжтэй байдлыг шалгах `/health`, Дараа нь амьд замын давхаргыг шалгах `/openapi` эсвэл `/openapi.json`. Зарим нэвтрүүлэгүүд нь бас илрүүлэх `/v1/health`, Гэхдээ `/health` Энэ бол гар утасны амьжиргааны шалгалт юм.
3. Үүнд TAIRA, шууд уулзалт хийхээс өмнө ээлжит телеметрийн замыг шалгах:

   ```bash
   TAIRA=https://taira.sora.org
   curl -fsS "$TAIRA/health"
   curl -fsS "$TAIRA/v1/kaigi/relays"
   curl -fsS "$TAIRA/v1/kaigi/relays/health"
   ```

Эдгээр шалгалтууд нь Torii болон Kaigi ээлжит телеметрийн хүрэлцээг баталгаажуулдаг. Тэд уулзалт үүсгэдэггүй; `CreateKaigi` ба `JoinKaigi`-д аливаа санхүүжилттэй мөнгөний ханш, гарын үсэг зурсан гүйлгээ өргөн мэдүүлэг шаардлагатай байна.
4. Демо дэлгэцээ нээж, Тансагварын хэсгээр зайлуулж, Torii URL-ийг байгуулж, хэрэгслийн зах зээлийг ID болон сүлжээний префиксийг эцсийн цэгтээс ачаалах.
5. Дэммо дээр хоёр орон нутгийн хөрөнгийг бий болгох, сэргээх. Үйлчлүүлэгч болон зочид буудлын байдал нь тусдаа байхын тулд өөр хоорондын аппликейшнүүд, хувилбар эсвэл машин ашиглах.

Kaigi UI-ийн шинжилгээ хийхэд:

1. Хост дэлгэцэнд Kaigi нээж, уулзалт эхлүүлэх сонгогдон нэрээ байгуулж, хувийн уриалгыг эсвэл ил тод уриалтыг сонгох.
2. WebRTC нь орон нутгийн хэвлэл мэдээллийн хэрэгсэлтэй байхын тулд камер, микрофонг идэвхжүүлнэ.
3. Хуралдааны холбоосыг бий болгоороо сонгоно. Амьд хөрөнгийн сан `CreateKaigi` -ийг ирүүлнэ; дараа нь `iroha://kaigi/join?call=...&secret=...` дуудлага болон `#/kaigi?...` -ийн эргэлтийн замыг үзүүлнэ.
4. Үйлчлүүлэгч цонхны дэлгэцээ нээлттэй байлгаж, уриалгыг зочидтай хуваалцаарай.
5. зочид буудлын үзэсгэлэнд урьлыг нээж, уулзалт дээр элсүүлж, орон нутгийн хэвлэл мэдээллийн хэрэгслийг идэвхжүүлэн хуралдаанд оролцохыг сонгоно. Амьдрал санхүүжилт нь Torii-ээс шифрлэгдсэн хостийн санал авдаг бөгөөд `JoinKaigi` -ийг шифрлэгдсэн хариултын мета өгөгдөлтэй хүргүүлнэ.
6. Үйлчлөгч нь Kaigi дуудлагын сигналыг дамжуулан эсвэл санал асуулга явуулж анхны хариултыг автомат хэрэглэх ёстой. Хоёр цонх нь холбогдсон хэвлэл мэдээллийн хэрэгсэл болон холбооны шинэчилсэн мэдээллийг харуулна.
7. Үйлчлүүлэгчээс уулзалт дуусгавал CLI `iroha kaigi end` команд нь ижил дуудлага ID дээр ашиглана.

Хувийн Kaigi хэрэгцээг хамгаалах XOR нь хувийн нэвтрүүлгийн цэгтийн төлбөрийг төлүүлэхэд шаардлагатай. Хэрэв демо нь хувийн Kaigi хэрэгцээгийг хамгаалах XOR гэж мэдээлвэл, аппликейшн дэх өөрийгөө хамгаалах илтгэлийг ашиглаж, бүтээх эсвэл нэгдэх үйлдлийг дахин туршиж үзээрэй. Хэрэв баталгаа үүсгэх, хувийн санхүүжилт, эсвэл амьд сигнал өгөх боломжгүй бол демо нь ил тод / дасан зохиолын урсгалд буцаж ирэх боломжтой.

Demo repo-д автомат хяналт шалгахын тулд:

```bash
npm test -- tests/kaigiView.spec.ts tests/preloadKaigiBridge.spec.ts
npm run e2e:ui
npm run verify
```

Vitest-ийн төвлөрсөн Suite нь Kaigi уулзалтын холбоосыг бий болгох, компакт уриалгыг борлуулах, хувийн бүтээх / нэгдэн оруулах / төгсгөх модны дуудлага, бие даасан хамгаалалтын илтгэлийг, гарын авлигуудыг хангах, хариултын санал асуулгаг хамруулдаг. UI хоолой шинжилгээний туршилтад ширээний болон гар утасны хэмжээний үзэсгэлэн дээр `/kaigi` замыг багтаадаг. Хоёр хөрөнгийн сангийн хооронд амьд хэвлэл мэдээллийн хэрэгсэл нь цахилгаан камер/микрофоны зөвшөөрөл болон дундаж хэвлэлийн урсгал нь байгаль орчинд тодорхой байдаг тул хоёр ширээний дасан зохицуулалтын туршилтыг хийх шаардлагатай.

Үлгэрийн интеграцийн код [г үзнэ үү Kaigi-ийг JavaScript-ийн App](/mn/guide/tutorials/kaigi.md)-д багтаажээ.

## Статус, үзүүлэлт {#status-and-metrics}

Статус болон метрикийн төгсгөл нь хамгийн түрүүнд дашборд руу холбогдсон зүйл юм:

- `/status` нь дээд түвшний өрсөлдөгч, блок, шуурхай, тохиролцооны талбайдыг илрүүлнэ
- `/metrics` нь Prometheus-ийн тооллогч, хэмжүүлэгч, хистограммыг илрүүлж байна

Nexus-ийн хүчин чадалтай түймрүүд дээр, статусын гарааны хувьд замын хөдөлгөөн болон өгөгдлийн орон зайг мэддэг хэсгүүд ч байдаг. `nexus.enabled = false` бол эдгээр хэсгүүд орхигддог.

## JSON v. Norito {#json-vs-norito}

Хөдөлмөрийн хэрэгслийн хэд хэдэн эцсийн цэг нь буцаадаг Norito Үндсэн хэсгээр: JSON, ирүүлнэ:

```http
Accept: application/json
```

Энэ нь:

- `/v1/sumeragi/status`
- `/v1/sumeragi/qc`
- `/v1/sumeragi/commit_qc/{hash}`

Хөгжлийн тоног төхөөрөмж нь Norito-ийг шууд хүлээн зөвшөөрөх эсвэл буцаадаг бол `application/x-norito` -г агуулгын төрөл болон `Accept` -ийн сонгосон үнэ цэнэ болгон ашиглаарай. Тээврийн дэлгэрэнгүй мэдээллийг [Norito](/mn/reference/norito.md#torii-and-norito-rpc)-д үзнэ үү.
