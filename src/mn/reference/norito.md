## Хөдөлмөрийн ачаалалтын загвар {#payload-model}

Бүх цахилгаан болон диск Norito нөөц ачаа нь гарын үсэг, дараа нь
Хэдэргүй, эсвэл халуун хэрэглээний ачаалл нь дотоод
хэшинг, шалгуур үзүүлэлт, туслах APIs үр дүнг шууд
тээвэрлэхээс өмнө гадаргуу.

| Үргэлтийн талбар | Өргөн хэмжээ | Зорилго |
| --- | ---: | --- |
| Магич | 4 байт | ASCII `NRT0`, хэрэглэв.Norito Мэдээлэл эрт. |
| Төгсч | 1 байт | Томоохон хувилбарыг хэлбэлзүүлэх `0`. |
| Жижиг хэмжээний | 1 байт | V1 шилжилтийн зөвлөгөөг байлгах. Одоогийн хэрэглээний ачаалл ашиглах `0x00`; Уурхайн сонголт нь зургуудад амьдардаг. |
| Схемийн хаш | 16 байт | Тайптируулсан декодерүүдээр гэнэтийн ашигтай ачааллыг татгалзахын тулд ашигладаг төрлийн тодорхойлолт. |
| Сэтгэгдэл | 1 байт | `0 = None`, `1 = Zstd`. Мэдээгүй үнэ цэнэүүдийг татгалзаж байна. |
| Хөдөлмөрийн ачааны урт | 8 байт | Хөдөлмөрийн ачаалал бага хэмжээний урттай `u64`. |
| CRC64 | 8 байт | CRC64-XZ Хөрөгдөлний ачааллын хяналтын дүн. |
| Тэмбэл | 1 байт | Нөхөн урт, багтаж буй урсгал, багтаж байгаа ургамлын зургуудыг зохион байгуулж байна. |

Үргэлт нь 40 байт. Декодруулагчид маги, хувилбар, дэмжлэг үзэгдлийг баталгаажуулдаг
Маск, ашиг шилжилтийн урт, хяналтын тоо, схемын хэш

## Нүүр хуудас {#layout-flags}

Norito v1 хяналтын хувилбарын сонголт эцсийн гадаргын байт дахь хадгаламж
нэвтрүүлэг `COMPACT_LEN` (`0x02`) нь компактт дундаж хэмжээний урттай префиксийн хувьд.
Тодорхой өргөн урттай товчоо нь дуу хоологчид
`flags = 0x00`.

| Тэмцэг | Хекс | Үндсэн байдал | Үр дүн |
| --- | ---: | --- | --- |
| `PACKED_SEQ` | `0x01` | дэмжлэг үзүүлэх | Үндэсний хэмжээний цуглуулгыг орчуулалт хүснэгт болон дараах мэдээллийн блоктай кодлуулж байна. |
| `COMPACT_LEN` | `0x02` | Урьдчилсан | Үр дүнгийн уртны урьдчилсан хэсгүүдийн хувьд Canonical unsigned varints ашигладаг. |
| `PACKED_STRUCT` | `0x04` | дэмжлэг үзүүлэх | Дэргэдэх "Derive-Generated Strokes" нь "Packed Field Payloads" гэж нэрлэгддэг. |
| `VARINT_OFFSETS` | `0x08` | Үргэлт | V1 -д үгүйсгэгдсэн; багтаж буй урсгалын орчуулга нь тогтмол өргөн байна `u64`. |
| `COMPACT_SEQ_LEN` | `0x10` | Үргэлт | V1 -д татгалзсан; дээд түвшний дараалалны уртын толгой нь тогтмол өргөн байна `u64`. |
| `FIELD_BITSET` | `0x20` | Шаардлагатайгаар дэмжлэг үзүүлэх | Багаруулсан уран бүтээлүүдэд битсэт нэмнэ. `PACKED_STRUCT` болон `COMPACT_LEN`. |

Тус тэмдгүүд тодорхой байдаг. Декодер нь хувилбарыг ашигтай ачааны хэлбэрээс дүгнэхгүй,
Бүрэн дугаар хэлбэр, эсвэл эвристик.
Бүх өрсөлдөгчид ашиг ачааг ижил төстэй байдлаар тайлбарлаж байна.

## Кодирын дүрэм {#encoding-rules}

Norito Энэ нь нийтлэг өгөгдлийн хэлбэрүүдэд тодорхойлолт зохион байгуулалтыг ашигладаг
УИХ-ын гишүүн Iroha Мэдээллийн загвар:

- Хадгалууд нь `[len][utf8-bytes]`; `len` Дараах: `COMPACT_LEN` Хэрэв боломжтой бол.
- Үүнд тооцогдох урт нь компакт арьс хэрэглэдэг `COMPACT_LEN` өөрөөр хэлбэл тохируулсан
  8 байтын жижиг андиан `u64`.
- Сургуулийн урт нь 8 байтын бага хэмжээний `u64` v1-д.
- `Vec<u8>` Энэ нь: `[len_u64][raw-bytes]` нэг байт дахь уртын оронд.
- Багасан цуврал ашиглах `(len + 1)` нэгтгэн `u64` цаашид:
  Зурагшилсан элементийн ашигтай ачаалл.
- Картууд нь бүртгэлийн тоог тогтмол `u64` нэрийн тодорхойлох товчлогыг ашиглах.
  `HashMap` бичиг баримтыг кодлоос өмнө товчооноор ангилдаг; `BTreeMap` ашигладаг
  Байгалийн тогтолцоо.
- `BigInt` жижиг эндиан хоёр-ийн нэмэлт байт ашигладаг `u32` байт урт
  Мөн 512 битүүний гадаргуу.
- `Numeric` Энэ нь: `(mantissa, scale)`, Мантисса нь
  Тодорхой тооны үнэ цэнэ, хэмжээнд хувьсан цифрдын тоо хадгалагдаж байна.

Эдгээр дүрэмүүд нь гарын үсэг, хашийн хувьд чухал юм. SDKs ижил төстэй
логик бүтээн байгуулалтад ижил хуулийн байт үүсэх ёстой.

## Схемийн хэшүүд {#schema-hashes}

Үргэлт Norito 16 байтын схемын хэшийг гадрын дотор хадгалж байна
hash нь бүрэн эрхтэй тип нэрээс үүдэлтэй.
Структураль схемын хашинг нь хашиг каноникийн схемаас гаргаж авдаг.

Энэ нь үйлчлүүлэгчдийг санамсаргүй
хүчин төгөлдөр Norito дугуй нь буруу хэлбэртэй бөгөөд хэвийн алдааны хэв маяг юм
тухайн үед SDK Үргэлт бандл нь түймрийн мэдээллийн загвараас буураад байна.

## Сэтгэл, хурдац {#compression-and-acceleration}

Norito логик хэсгийг өөрчлөхгүйгээр тодорхой, тохируулалттай товчлогыг дэмждэг
хэрэглээний ачаалл:

| Үргэлж | Зорилго |
| --- | --- |
| `to_bytes` | Хэдэрний хүрээтэй цогцолболтгүй ачааллыг кодлуулж байна. |
| `to_compressed_bytes` | Zstd-ээр кодлож, товчлолт хэсгийг толгой дээр бүртгэнэ. |
| `to_bytes_auto` | Сэтгэмжлэл нь үнэ цэнэтэй эсэхийг шийдвэрлэхэд дэтерминист эвристик хэрэглэж болно. |
| CRC64 хурдацлах | Хөдөлмөрийн хэрэгсэл CRC64-XZ хаа сайгүй, CLMUL x86 дээр_64 эсвэл PMULL ашиглах боломжтой бол aarch64 дээр. |
| GPU CRC64 болон хатуулах | Барилгасан металл эсвэл CUDA туслагч нь том ачааг хурдаж, дараа нь эргэж CPU Залуудыг. |

Хардверт хурдац нь уншилтгүй агуулгыг хэзээ ч өөрчлөхгүй. CRC болон JSON
Зстд дугуйны байт нь
хоорондоо ялгаатай CPU болон GPU коджуулагч, гэхдээ нэвтрүүлсэн ашиг ачаалл болон Norito товч
Мета өгөгдөл нь баталгаажуулахын хувьд тодорхой хэвээр байна.

## Дэргэдэх дэмжлэг {#derive-support}

Rust Мэдээллийн хэлбэрүүд нь гарын үсэгт кодек кодтой харьцуулахад ихэвчлэн дэрвив макрог ашигладаг.
Үргэлтний давхар үүсгэх боломжтой Norito дундаж кодек, схема JSON Хөдөлмөрийн туслах.

Нийтлэг талбайн шинж чанар нь:

| Тавилга | Үр дүн |
| --- | --- |
| `#[norito(rename = "other")]` | Схема болон JSON нийцүүлэл. |
| `#[norito(skip)]` | Барилгын талбайг устгаж, `Default` Хөгжил тогтоох үедээ. |
| `#[norito(default)]` | Хэрэглээ `Default` нэвтрүүлэгт оролцогчдоод |
| `#[norito(skip_serializing_if = "...")]` | Үргэлт JSON Үндсэн хуулийн дагуу дэглэмийг тодорхойлох нь тохиромжтой. |

Үр дэргэдэх түлхүүрүүд нь мөн кодлогдсон уртын нэгийг болон үнэн уртын тооцоодыг илрүүлнэ.
Хөгжүүлэгчид эдгээр нэгийг ашиглан буфер хадгалах, нэмэлт хувилбаруудыг сахиулах зорилгоор ашигладаг.

## Torii болон Norito RPC {#torii-and-norito-rpc}

Torii нэвтрүүлэг JSON олон оператор замын хувьд, гэхдээ дугаарлалттай хошой замыг ашигладаг
Norito. Урьдчилсан эрчим хүчний хэвлэлийн төрөл Norito HTTP бие махбод
`application/x-norito`.

Хөгжлийн хэсгийг хүлээн зөвшөөрөх эсвэл буцааж өгөх үед эдгээр загадлагыг ашигла Norito:

```http
Content-Type: application/x-norito
Accept: application/x-norito
```

Нэг төгсгөл нь аль алиныг ч дэмжиж байгаа бол үйлчлүүлэгчид тодорхой
Сайхан хувилбар:

```http
Accept: application/x-norito, application/json
```

Хөдөлмөрийн шилжилтийн алдааг түрээслэгдсэн байдлаар илрүүлнэ Torii алдаа, телеметриар тооцогддог.
Үндсэн шалтгаан нь хүчингүй маги, дэмжлэггүй хувилбар, дэмжлэг үзэл
цол, хяналтын дүн зөрчсөн, алдаатай UTF-8, хүчингүй enum тэмдэг, схемын зөрүү.

Norito RPC тээврийн хэлбэрээр сонгогддог.
Дашборд нь хүсэлтийн хориотой байдал, алдаа, идэвхтэй холболт,
хариуын байт, `torii_norito_decode_failures_total` тусгаарлан JSON
Замын хөдөлгөөнийг.

## Norito Хэвлэлийн урсгал {#norito-streaming}

Norito Стриминг нь хэвлэл мэдээллийн хэрэгсэл болон бодит цаг хугацааны эсрэг ижил тодорхойлолттай хандлагыг өргөжүүлнэ
Төмөрлөгийн гол хэсэг нь:

| Хэвлэлийн урсгалын онцлог | Зорилго |

Norito Тиймээс маршрут, төлбөр тооцоо, дахин тоглолт болон аудитын баримтыг нөхөн сэргээх боломжтой.

## Үйл ажиллагааны удирдамж {#operational-guidance}

- Би илүү дуртай. SDK барилгач, гар ургамал дээр үүссэн холболт Norito Байт.
- Схемийн зөрчлийг түр хугацааны хувьд биш, хувилбар эсвэл тоног төхөөрөмжийн асуудал гэж үзнэ
  Сүлжээний алдаа.
- Хөрөөж байна `.nrt`, `.norito`, нэвтрүүлэг болон үйл явдлын дараах артефактыг илрүүлэх
  Тэдгээрийг бий болгосон цогц.
- Хэрэглээ JSON Дашборд болон гарна хяналтын зураг төслийг Norito Үүнд
  гарын үсэг зурсан, хэшлэгдсэн эсвэл хэвээр үлдсэн мэдээллийн үнэн эх үүсвэр.
- Шинэ хэвлэлийн хувилбарыг нэмэхдээ Torii төгсгөлийн цэг, хүлээн зөвшөөрөх эсэхийг баримтлах JSON,
  Norito, эсвэл хоёулаа нь илрүүлэн, дэмжлэг үзүүлэх агуулгын төрөлүүдийг `/openapi`.
- Давгайчдыг идэвхжүүлэхдээ, скалар үр дүнтэй харьцуулахад партитын шинжилгээг хийхээс өмнө
  Урьдчилан шилжилтийн алдаа нь өөрчлөгдөхөөс илүү цэвэр унасан байх ёстой
  ашигтай ачааллын утга зохиол.
