# Гадаад Функцийн Интерфейсүүд (FFI) {#foreign-function-interfaces-ffi}

`iroha_ffi` програм хангамжийн багц нь Rust APIs-аас C ABI холболтуудыг үүсгэхэд зориулсан макро болон шинж чанаруудыг өгдөг. Энэ нь Iroha төрлүүд FFI хязгаарлалтыг давах шаардлагатай үед, жишээлбэл SDK холболтууд эсвэл хост интеграцчлалд ашиглагддаг.

## Яагаад FFI {#why-ffi}

Функц нь харьцангуй ойлгомж муутай нэг юм бөгөөд ихэнх програмчлалын хэлнүүд функц юу хийх ёстойг зөвшөөрдөг ч, функцийг хэрхэн илэрхийлэх нь маш их ялгаатай байдаг. Түүнчлэн, Rust зэрэг зарим хэлүүдэд функц дуудах үр дагавар болон түүний хийх зөвшөөрөгдсөн зүйлс нь мөн ялгаатай байдаг. Rust үед APIs нь өөр хэл эсвэл өөр хост орчноос дуудагдах хэрэгтэй, Iroha нь талбайг хэвийн болгохын тулд гадаад функцийн интерфэйс (FFI) ашигладаг.

Өнөөдөр хэрэглэгдэж буй гол стандарт нь C програмын бинар интерфейс юм. Энэ нь энгийн, өргөн ашиглагддаг, тогтвортой. Үндсэн зарчмын хувьд та бүх зүйлийг гараар хийж болох ч, Iroha нь `iroha_ffi` програмын багцыг ашиглан одоо байгаа Rust API-ээс FFI-тай нийцсэн функцуудыг үүсгэх боломжийг олгодог.

Мэдээж та үүнийг өөрийнхөөрөө хийж болно. `iroha_ffi` програм хангамжийн багц нь ердөө л та аль хэдийн үүсгэх шаардлагатай кодыг үүсгэдэг. Шаардлагатай давтагдсан загвар кодыг бичих нь ихээхэн хичээл зүтгэл, сахилга бат шаарддаг. Бүх функцийн техникийн дуудах нь FFI хязгаарыг давж гүйцлээх бүрт тодорхойгүй үйлдэл үүсгэх боломжтой `unsafe` юм. Бид үүнийг шийдвэрлэх арга нь бат бөх `repr(C)` төрлүүдийг ашиглахтай холбоотой.

::: info

Цорын ганцexception нь заагчид юм. Null шалгалт болон хүчинтэй байдлыг дэлхий даяар хэрэгжүүлэх боломжгүй тул түүхий заагчууд (бүх цагт) зөвхөн exception тохиолдолд ашиглагддаг. Бид Iroha өгөгдлийн загвар дахь объект бүрийн бараг бүх тохиолдлын эргэн тойронд програм хангамжийн адаптеруудыг өгдөг учраас та бүхэлдээ түүхий заагчуудыг ашиглах шаардлагагүй.

:::

## Жишээ {#example}

Энд холболт үүсгэх жишээ байна:

```rust
#[derive(FfiType)]
struct DaysSinceEquinox(u32);

#[ffi_export]
impl DaysSinceEquinox {
    pub fn update_value(&mut self, a: &u8) {
        self.0 = *a as u32;
    }
}
```

Дээрх жишээ нь `DaysSinceEquinox`-ыг тодоорхойгүй заагчаар илэрхийлсэн дараахь холболтыг үүсгэнэ:

```rust
pub extern fn DaysSinceEquinox__update_value(handle: *mut DaysSinceEquinox, a: *const u8) -> FfiReturn {
    // function implementation
}
```

## FFI Холболт үүсгэх {#ffi-binding-generation}

`iroha_ffi` програмын багцыг FFI хэлбэрээр дуудах боломжтой функцуудыг үүсгэхэд ашигладаг. `Rust` бүтэц, аргуудыг харгалзан, холбоосыг гатлахын тулд шаардлагатай `unsafe` кодыг үүсгэдэг.

Rust төрлийг `FfiType::into_ffi`-р дамжин FFI хил дамжиж чадах бат бөх `repr(C)` төрөл рүү шилжүүлдэг. Энэ нь эсрэгээрээ ч хийгддэг: FFI `ReprC` төрөл нь `FfiType::try_from_ffi`-ээр дамжуулан `Rust` төрөл рүү шилждэг.

::: warning

Эсрэг хөрвүүлэг алдаатай байж болзошгүй бөгөөд тодорхой бус үйлдэл үүсгэж болдог болохыг анхаарна уу. Бид хамгийн илэрхий алдаанаас зайлсхийхийн тулд бүх хүчээ гаргаж чадах боловч, програмын зөв байдлыг өөрийн тал дээр баталгаажуулах шаардлагатай.

:::

Барьц үүсгэх гол шинж чанарууд нь `ReprC`, `FfiType`, ба `FfiConvert` юм.

|Онцлог|Тайлбар|
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ReprC`      |Энэ шинж чанар нь C ABI-нд нийцсэн бат бөх төрлийг илэрхийлдэг. Энэхүү төрөл нь FFI хязгаарлалт хооронд аюулгүйгээр хуваалцах боломжтой.|
| `FfiType`    |Энэ шинж чанар нь өгөгдсөн `Rust` төрлийн хувьд тохирох `ReprC` төрлийг тодорхойлдог. Тодорхойлсон `ReprC` төрлийг үүсгэгдсэн FFI функцийн API дахь `Rust` төрлийн оронд ашигладаг.|
| `FfiConvert` |Энэхүү шинж чанар нь `Rust` төрлийг `ReprC` төрөлд хөрвүүлэх эсвэл буцаж хөрвүүлэхэд ашиглагддаг хоёр аргыг `into_ffi` болон `try_from_ffi` тодорхойлдог.|

Тэмдэглээрэй, FFI-ийн өмчлөл шилжихгүй, ил тод бус зааврын төрөлүүдээс бусад бүх тохиолдолд. Өмчлөл тээгч бусад бүх төрөлүүд, жишээлбэл `Vec<T>`, хуулбарлагддаг.

### Нэрний хутгалт {#name-mangling}

Үүссэн FFI объектуудын нэрэнд хоёр доогуур зурвас ашиглагдааг анхаарна уу:

- `StructName` бүтэц дээр тодорхойлогдсон `inherent_fn` аргын хувьд, FFI нэр нь `StructName__inherent_fn` байх болно.
- `StructName` бүтэц дэх `TraitName` шинжийн `MethodName` арга дээр FFI нэр нь `StructName__TraitName__MethodName` байх болно.
- `StructName` бүтэц дэх `field_name` талбарыг тохируулахын тулд FFI функцийн нэр нь `StructName__set_field_name` байх болно.
- `StructName` бүтэц дэх `field_name` талбарыг авахын тулд FFI функцын нэр нь `StructName__field_name` байх болно.
- `StructName` бүтэц дэх өөрчлөгдөж болох `field_name` талбарыг авахын тулд FFI функцын нэр нь `StrucuName__field_name_mut` байх болно.
- Өөрөө зогсож буй `module_name::fn_name` хувьд, FFI нэр нь `module_name::__fn_name` байх болно.
- Ерөнхий бус шинж чанарууд болон тэдний хэрэгжилтийг FFI-д хуваалцах боломж олгодог шинж чанаруудын хувьд (доор `Clone`-ийг үзнэ үү), FFI нэр нь `module_name::__clone` байх болно.

  ```rust
  impl Clone for Type1 {
      fn clone(&self) -> Self;
  }
  impl Clone for Type2 {
      fn clone(&self) -> Self;
  }
  ```
