# Izanami-тэй хаос туршилт {#chaos-testing-with-izanami}

Изанами нь урсгалд орших хаос торгийн зохион байгуулагч Iroha Ажлын газар.
нэг удаа хэрэглэх орон нутгийг эхлүүлнэ Iroha кластер, тохируулж болох ажлын ачааллыг хүргүүлнэ;
болон сонгогдсон дундад түвшинд алдааг элсүүлж байгаа тул оператор нь
Сүлжээ нь хяналтын алдаатай үедээ хөгжил дэвшилтэй байна.

Izanami-ийг үйлдвэрлэлийн өмнөх уялдуулалтын шалгалт, регресийн нөхөн үржихүүнд ашиглах
Үйлдвэрлэлийн сүлжээг чиглүүлж болохгүй: хэрэгсэл нь
эхлүүлсэн зэрэглэлийг эзэмшүүлэхэд зориулсан, тэр дундаа ижил төстэй дахин эхлүүлэх, хадгалах
цахилгаан хэрэгсэл, хиймэл багцыг алдаж, орон нутгийн CPU эсвэл дискний даралт.

## Урьдчилсан шаардлага {#prerequisites}

Izanami-ийг
[Iroha эх сурвалжийн хадгаламж](https://github.com/hyperledger-iroha/iroha),
Энэ баримтын сангаас биш:

```bash
git clone https://github.com/hyperledger-iroha/iroha.git
cd iroha
cargo build -p izanami
```

Бинэрийн хэрэгслийг сүлжээнд холбогдсон бүтээх, зохицуулах боломжийг тодорхой зөвшөөрөх ёстой
Эдгээрийнхэн. `--allow-net` -Хэрэг бус хүн бүрт...TUI ажиллуулах, эсвэл `allow_net` .д
УИХ-ын гишүүн TUI.

```bash
cargo run -p izanami -- --allow-net --peers 4 --faulty 1 --duration 120s
```

Интерактив гүйлгээний конфигурацын хувьд:

```bash
cargo run -p izanami -- --tui --allow-net
```

Изанами үргэлжлүүлэн TUI болон CLI хэрэглэгчийн конфигурацийн товчооны доор байрлах тохируулалт,
өмнөх хувилбарыг дахин ашиглахаас өмнө дэлгэцнээ тавьсан тохируулгыг хянах.

## Баталгын шуурхай {#baseline-run}

Асуур алдааг нэмэхээс өмнө нэг нөхөн сэргээгдэх эхлэлийг эхлүүлнэ:

```bash
cargo run -p izanami -- \
  --allow-net \
  --peers 4 \
  --faulty 1 \
  --duration 5m \
  --target-blocks 100 \
  --progress-interval 15s \
  --progress-timeout 120s \
  --latency-p95-threshold 2s \
  --tps 15 \
  --max-inflight 32 \
  --submitters 1 \
  --seed 42
```

Энэ гүйлт нь зөвхөн цуглуулгыг хүссэн блок зорилт хүрсэн тохиолдолд амжилттай болно.
цаг хугацааны дотор дэвшилтэй байх, сонголттой p95-ийн доор үлдэх
Блок интервалын хязгаар.

Тухайн захирамжийг бич, үрэвс. Iroha үйлдэл, дундаж тоо, алдаатай дундаж тооллолт,
ажлын ачаалал, зорилт TPS, Хөгжлийн тэмдэглэлүүдтэй хориотой байдлын түвшин
Эдгээр үнэ цэнэүүдийг өөр оператор нь ижил алдааны загварыг дахин тоглож чадахгүй.

## Ажлын ачаалал Profiles {#workload-profiles}

Izanami-ийн хоёр ажлын ачаалал:

| Профиль  | Үүнийг ашиглах                                         | Хэвлэл                                  |
| -------- | -------------------------------------------------- | -------------------------------------- |
| `stable` | Удаан угаах явц, нөхөн сэргээгдэх гүйцэтгэлийн шалгалт | Үндсэн хуульд заасна          |
| `chaos`  | Хөдөлмөрийн алдааны зам                              | Дашрамд зориулан хүчингүй рецептууд |

Хамгийн түрүүнд тогтвортой хувилбарыг ашигла:

```bash
cargo run -p izanami -- --allow-net --workload-profile stable --seed 42
```

Эхний хэсгийг аль хэдийн ойлгосон үед хаосны профилд шилжих:

```bash
cargo run -p izanami -- --allow-net --workload-profile chaos --seed 42
```

Гэрээний хэрэглээний рецепт нь тодорхой бус тохиолдолд тогтвортой явцад гараагүй
зөвшөөрөлтэй:

```bash
cargo run -p izanami -- \
  --allow-net \
  --workload-profile stable \
  --allow-contract-deploy-in-stable
```

Хэрэглээ `--nexus` гүйлтийн явцад багтаан SORA Nexus .
цахилгаан хөдөлмөр замын өмнөд хэсгийн ажлын газар.

## Халуун хяналт {#fault-controls}

Хэзээ `--faulty` 0-аас дээш бол хамгийн багадаа нэг алдаатай нөхцөл байдал байх ёстой
алдааны товчлол нь урьдчилан сэргийлэгдэж, boolean flags
хөгжлийн бэрхшээлтэй `=false`.

| Гэмтлэл                    | CLI галт тэрэг                                   | Энэ нь юу хийдэг вэ                          |
| ------------------------ | ------------------------------------------ | ------------------------------------------ |
| Хөгж, дахин шуурхай        | `--fault-enable-crash-restart`             | Хөгжлийн үр дүнгийн алдагдал, сэргээлт             |
| Хөөцөлдөж, сэргээх | `--fault-enable-wipe-storage`              | Уласнаас сэргээсэн орон нутгийн орон нутаг          |
| Ашиглалгүй гүйлгээний спам | `--fault-enable-spam-invalid-transactions` | Хөгжил авах болон үгүйсгэх зам              |
| Сүлжээний хорио          | `--fault-enable-network-latency`           | Удахгүй яриад, санал нэгдлийн илтгэлийг хойшлуулах |
| Сүлжээний хуваарилалт        | `--fault-enable-network-partition`         | Урьдчилан итгэмжлэгдсэн хүмүүстэй тусгаарлах           |
| P2P багцын алдагдал          | `--fault-enable-network-packet-loss`       | Хэрэглэлийн загварын хөдөлгөөнийг бууруулсан          |
| CPU стресс               | `--fault-enable-cpu-stress`                | Орон нутгийн баталгаажуулах, хуваарийн даралт   |
| Дискийн орчин          | `--fault-enable-disk-saturation`           | Орон нутгийн хадгаламжийн даралт                     |

Зөвхөн багцын алдагдалтай гүйлтэд:

```bash
cargo run -p izanami -- \
  --allow-net \
  --peers 20 \
  --faulty 5 \
  --duration 800s \
  --fault-window-start 133s \
  --fault-window-end 266s \
  --tps 200 \
  --submitters 20 \
  --max-inflight 512 \
  --fault-enable-crash-restart=false \
  --fault-enable-wipe-storage=false \
  --fault-enable-spam-invalid-transactions=false \
  --fault-enable-network-latency=false \
  --fault-enable-network-partition=false \
  --fault-enable-network-packet-loss=true \
  --fault-enable-cpu-stress=false \
  --fault-enable-disk-saturation=false \
  --fault-network-packet-loss-percent 75 \
  --seed 42
```

Хэрэглээ `--fault-window-start` болон `--fault-window-end` хяналт тавих
инъекцийн алдааны өмнө болон дараагийн тогтвортой байдлын хугацаа.
эхлүүлэх шуугийг алдааны нөлөөгээс ангилах нь илүү хялбар.

Изанами-ийн захиргааны каталог нь блокчейн харилцааны хохирол
хэлбэртэй CLI Та тэдгээрийг ижил зургуудтай загваруулж болно:

| Сценарий              | Тухайн хэлбэр                                                                                                            |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| Зорилгосон ачаалл         | `--faulty 0`, өндөр `--tps`, нэг өргөн мэдүүлэгч, өндөр `--max-inflight`                                                         |
| Цаг хугацааны алдаа     | Зөвхөн хязгаарлагдмал алдааны цонхны дотор авагдал / сэргээлт хийх боломжтой                                                                  |
| Багацааны хохирол           | Зөвхөн пакетийн алдагдал боломжийг олгоно, ихэвчлэн 75%-ийн алдагдалтай                                                          |
| Хөөцөлдөж, сэргээх | Халуун / сэргээн сурвалжлахын зэрэглэлтэй алдаатай олон тооны хэрэглээ                                                                    |
| Захиргааны удирдагчийн тусгаарлалт      | Зөвхөн сүлжээний хуваарилалт эсвэл пакетын алдагдалтай нэг алдаатай өрсөлдөгч ашиглах; Izanami дараа Sumeragi удирдагч телеметри |

Нэг удаад нэг өөрчлөгдөлийг тогтвортой байлгаарай.
хувилбар, алдааны цонх, TPS Үүнээс гадна, үр дүн нь
тайлбарлах.

## Ямар зүйлийг харах хэрэгтэй вэ? {#what-to-watch}

Удамжиртын үеэр гүйцэтгэлийг баталгаажуулахын тулд ашигласан ижил сигналыг анхаараарай:

- Блок өндөрний хөгжил нь гүйлтийн бүх өрсөлдөгчдэд
- өргөн мэдүүлсэн, хүлээн зөвшөөрсөн, татгалзсан болон хугацааны дагуу дууссан гүйлгээ
- шугам гүнзгийрэл, шугам дүүрэн байдал, төгсгөлийн цэг дээр давхар
- үзлэг өөрчлөлт, нөхөн сэргээлтийн замыг, алдаатай блок, алдагдаагүй кворум
  Гэрчилгээ
- RBC Хөгжлийн хяналт тавих, хэлэлцүүлэг хийх, тохиролцооны хөдөлгөөнийг хоцорсон
- CPU, хоолой, диск болон дотуурлын давхарт нь

Хяналтын хохирлын дүн шинжилгээ хийхэд гол мөрийн алдааны тэмдэгүүдийг хүчингүй болго:

```bash
RUST_LOG=iroha_core::sumeragi::main_loop=debug \
  cargo run -p izanami -- --allow-net --seed 42
```

Блок бүр дамжуулах ёстой `block validation timings` хамтран `stateless_ms`,
`execution_ms`, болон `total_ms`. Эдгээр цаг хугацааг p95 блоктой харьцуул
мөрийн хоорондоо, үзэл бодлоо өөрчлөх тооны тооллогчид, өөрчлөлтийн өмнө шуурхайн даралт
Зөвлөлдөх цаг хугацаа.

## Үр дүнг тайлбарлах {#interpreting-results}

Сонгон шалгагдсан бүх өрсөлдөгчдийн үргэлжлүүлэн бөмбөг барьдаг бол гүйлгээг эрүүл гэж үзээрэй.
хязгаарлагддаггүй, алдаа нь шинэ сэргээлт үүсгэхгүй
тохируулсан цонх дууссан дараа үйл ажиллагаа.

Хэрэв:

- Хөгжилтийн мөчлөлийг `--progress-timeout`
- Хөгжлийн өндөр нь ялгаатай бөгөөд дахин нийлбэрэхгүй
- p95 засах хугацаа хэтэрсэн `--latency-p95-threshold`
- Халуун цахилгаан дэлгэц хаагдсанаас хойш дараагийн шугам нь өсөж байна
- татгалзсан эсвэл цаг хугацаа дууссан гүйлгээг сонгогдсон
  ажлын ачаалал
- Дундаж сэргээлт, хадгаламжийн хураах эсвэл пакетын алдагдалтай нөхөн сэргээлт нь дасгал хөдөлгөөн шаарддаг
  цэвэрлэгээ

Хөгжлийн бэрхшээлээс хойш ижил үр тариа, нэг удаа бага алдаатайгаар дахин ажиллуулъя.
ажлын ачаалал, цаг хугацааг нөхөн сэргээх боломжтой болгодог бөгөөд алдааг бууруулдаг
гадаргуу.
