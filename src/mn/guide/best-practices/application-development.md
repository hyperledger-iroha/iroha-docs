# Хэрэглээний хөгжил {#application-development}

Iroha өргөдөлүүд нь гүйлгээний зан үйл явцыг тодорхой болгож, гарын үсэг зурах байдлаа хадгалж, хайлт болон үйл явдлыг үйлдвэрлэлэд хялбар ажиглах аргаар ашиглах ёстой.

## Хэрэглэгчийн тохируулалт {#client-setup}

- Хэрэглэлийн эх үүсвэрийн кодны гадна үйлчлүүлэгчдийн конфигурацийг хадгалах. ID, Torii URL зангилаа, гарын үсэг зурах бүртгэл, гүйлгээний тохируулгыг байгаль орчинд зориулсан тохируулалтаас борлуулах.
- `client.toml` файлуудыг lokalnet, Taira, Minamoto болон хувийн сүлжээний хувьд тусгаарлан хадгалах. Тэстнет-ийн гарын үсэг зурагч нь хэзээ ч гол гарын үсгийн гарын үстэй байх ёстой.
- Транзакцын цаг хугацаа, статусын хугацааг санаачлан байгуулж байна. Хэдэнхан хугацааны хугацаа нь хэвийн сүлжээний хөдөлгөөнд дуусч, маш урт хугацаа нь дубликатын мэдүүлэгт ойлгуулах хүндрэлтэй болно.
- `nonce = true` нь зөвхөн давтамжсан гүйлгээний ялгаатай хэштэй байх үед ашиглана. Үйлдвэрлэлийн үйл ажиллагаанд зориулалтгүй тохиолдолд ариун хүсэлтийг ID хадгалах, дахин ашиглах тул дахин туршиж үзэх боломжтой.

Одоогийн TOML талбайн хувьд [Арилжааны конфигурацыг](/mn/guide/configure/client-configuration.md) үзнэ үү.

## Арилжаа {#transactions}

- Магадгүй JSON ёсны ачаалал эсвэл арьстай хуримтлагдсан хэрэглээний ачааллын оронд SDK бичиг баримтаас бүтээн байгуулалт хийх.
- Preflight чухал нь зөвхөн уншигч асуултуудтай бичдэг: дансны оршин тогтнол, хөрөнгийн тэнцвэр, зөвшөөрлийн байдал, төлбөрийн хөрөнгийн хүртээмж, зорилтот объектний байдал.
- Транзакцын хэш, эрх мэдлийн данс, заалын товчлолт, хүлээсэн байдлын өөрчлөлтийг хүргүүлэхийн өмнө бүртгэнэ.
- `Rejected`, `Expired`-ийг харьцуулахад цаг хугацааны дуусгалын үр дүн өөр байдаг. Цаг хугацаа нь үйлчлүүлэгч эцсийн байдлыг ажиглаагүй гэсэн үг юм; энэ нь сүлжээ нь гүйлгээг үл тоомлосон гэдгийг баталдаггүй.
- Үйл ажиллагааны үйл ажиллагаанд нийцсэн асуулга эсвэл үйл явдлын хяналтын цэгээр амжилттай бичигдэсний дараа үр дүнтэй байдлыг баталгаажуулна.

Арилжааны механизмын талаар [Арилжаа](/mn/blockchain/transactions.md)-ийг үзнэ үү.

## Судалгаа, үйл явдал {#queries-and-events}

- Урьдчилсан өөрчлөлтийн мэдэгдэлд одоогийн байдал болон үйл явдлын урсгалын хайгуудыг ашигла. Үйл ажиллагааны удирдлагаг давтамжлах өргөн хайгуулаар солихгүй байх хэрэгтэй.
- Хэтгэл, актив, блок жагсаалтыг гэх мэт өргөн дахин давтагдах асуултуудыг хуудасчлан гарга.
- Тавилга, түлхүүжүүлэгчд зориулсан жижиг филтрүүд илүү тохиромжтой. Шижин фильтр нь оношилгоонд ашигтай боловч шаардлагагүй гүйцэтгэл болон үйлчлүүлэгчийн талын боловсруулалт нэмэх боломжтой.
- Өргөдлийн тоног төхөөрөмжийн үнэлгээг гарын үсэг зурсан гүйлгээний туршилтээс тусгаарлан байлгаж, эцсийн нүктейн хүртээмжийг илүү хялбар тогтоох боломжтой болно.

[Эрүүлэлтүүд](/mn/blockchain/queries.md), [Үлс хэрэгсэл](/mn/blockchain/events.md) болон [Филтрүүд](/mn/blockchain/filters.md)г үзнэ үү.

## Үйлчилгээний туслалцаатай хөгжил {#agent-assisted-development}

- Хэрэглэгчид транзакцын код бичэхийг хүсэхээсээ өмнө доктэйл, SDK кодыг, зөвхөн уншдаг сүлжээний хэсгийг шалгаарай.
- `TAIRA_LIVE=1` гэх мэт байгаль орчны тэмдгийн ард амьд сүлжээний туршилт явуулахыг сонгох.
- Хувийн түлхүүр, дансны нөхөн сэргээлт материал, API токенүүд, эсвэл автын дугаарт дамжуулсан уншруудыг анхан шатны захиалгад элсэхгүй байна.
- Тус төлөвлөгөө нь сүлжээ, эрх мэдэл, удирдамж, төлбөрийн хөрөнгө, нислэгээс өмнө уншдаг, хүлээсэн үр дүн, дахин туршиж үзэх хандлага гэсэн нэртэй байх ёстой.

Үндсэн хуулийн Taira MCP ажлын урсгал, хар [Үндсэн барилдаан SORA 3: Taira болон Minamoto](/mn/get-started/sora-nexus-dataspaces.md#taira-mcp-for-agents).

## SDK Гигиена {#sdk-hygiene}

- Пин SDK болон бинар хувилбар нь хамтдаа [Нэг нийцүүлэл матрицыг ашиглаж байна](/mn/reference/compatibility-matrix.md).
- Хэрэглэгчийн код, дүгнэлт, үлгэр жишээг үүсгэн бүтээсэн нь өмнөд урсгалын ажлын байрны шинэчлэлтэй хуваарилсан байна.
- Транзакцын бүтээн байгуулалтын код болон интеграцийн тестүүдийн нэгж шинжилгээг хамгийн бага унших, бичүүлэх замаар нэмнэ. Таны аппликейшн нь хамаарна.
