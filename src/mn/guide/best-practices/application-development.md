# Програм хангамжийн хөгжүүлэлт {#application-development}

Iroha програмууд гүйлгээний зан үйлийг тодорхой илэрхийлэх, гарын үсгийн төлөвийг хадгалах, мөн үйлдвэрлэлд хянахад амархан байдлаар асуулт, үйл явдлыг ашиглах хэрэгтэй.

## Клиент тохируулах {#client-setup}

- Аппликешны эх кодоос гадна хэрэглэгчийн тохиргоог хадгал. Гинжийн ID, Torii URL, гарын үсгийн акаунт, гүйлгээний тохиргоог орчны тусгай тохиргооноос ачаал.
- Localnet, Taira, Minamoto болон хувийн сүлжээ бүрийн `client.toml` файлыг тусад нь хадгална. Хуулсан testnet гарын үсэг зурагчийг хэзээ ч mainnet гарын үсэг зурагч болгож ашиглахгүй.
- Гүйлгээний насжилт болон төлөвийн хугацааг зориуд тогтооно уу. Маш богино насжилт нь энгийн сүлжээний хэлбэлзлийн үеэр дуусч болно, харин маш урт насжилт нь давхар илгээх ажиллагааг ойлгоход хүндрэл үүсгэж болно.
- Давтан гүйлгээ тус бүрт тусдаа криптографийн hash үүсэх ёстой үед л `nonce = true`-ийг ашиглана уу. Идэмпотент бизнесийн үйлдлүүдэд дахин оролдоход мөрдөж болохоор байдлаар хүсэлтийн ID-г хадгалж, дахин ашигла.

Одоогийн TOML талбаруудыг үзэхийн тулд [Клиент тохиргоо](/mn/guide/configure/client-configuration.md)-г үзнэ үү.

## Гүйлгээ {#transactions}

- Боломжтой тохиолдолд түүхий JSON эсвэл тэмдэгт мөрөөр угсрагдсан payload-ийн оронд төрөлжүүлсэн SDK заавраас гүйлгээ бүтээх.
- Онцгой анхаарах урьдчилсан шалгалт нь зөвхөн унших боломжтой асуултуудаар хийгддэг: дансны байдлын шалгалт, хөрөнгийн үлдэгдэл, зөвшөл өгөх нөхцөл, төлбөрийн хөрөнгийн боломж, ба зорилтот объектын байдал.
- Гүйлгээг илгээхээс өмнө криптографийн хэш, зөвшөөрөл олгосон үндсэн данс, зааврын товч тайлбар, хүлээгдэж буй төлөв өөрчлөлтийг тэмдэглэ.
- Төрөлхийн `Rejected`, `Expired` болон хугацаа дуусах үр дүнг ялгаатайгаар авч үзнэ. Хугацаа дуусах нь клиент эцсийн төлөвийг ажиглаагүй гэсэн үг бөгөөд энэ нь сүлжээ гүйлгээний хүсэлтийг үл тоосон гэсэн нотолгоо биш юм.
- Амжилттай бичсний дараа бизнесийн үйл ажиллагаатай тохирох асуулт эсвэл үйл явдлын шалгах цэгээр үүссэн төлөвийг шалга.

Гүйлгээний процессын талаар [Гүйлгээ](/mn/blockchain/transactions.md)-ийг үзнэ үү.

## Асуултууд болон Үйл явдал {#queries-and-events}

- Одоогийн төлөвийн төлөө лавлагаа, өөрчлөлтийн мэдэгдэлд зориулан эвент урсгалыг ашигла. Эвентыг боловсруулахыг давтагдсан өргөн лавлагаагаар орлуулахыг бүү хичээ.
- Данс, хөрөнгө, ба блокын жагсаалтын өргөн давтагдах асуултуудыг хуудаслах.
- Үнэн, хязгаарлагдмал шүүлтүүрийг захиалгууд болон триггерүүдэд ашиглахыг илүүд үз. Өргөн шүүлтүүрүүд нь оношлогоонд хэрэгцээтэй байж болох ч шаардлагагүй гүйцэтгэл болон клиент талын боловсруулалтыг нэмэгдүүлж болно.
- Зөвхөн унших байдлын утаа шалгалтуудыг гарын үсэгтэй гүйлгээний туршилтуудаас тусгаарлаж байвал API төгсгөлийн хүртээмжийг илүү амархан оношилж болно.

Үүнийг үзнэ үү [Асуултууд](/mn/blockchain/queries.md), [Үйл явдлууд](/mn/blockchain/events.md), ба [Шүүлтүүрүүд](/mn/blockchain/filters.md).

## Агентын тусламжтай хөгжүүлэлт {#agent-assisted-development}

- Агентуудыг гүйлгээний код бичихийг хүсэхээсээ өмнө баримт бичиг, SDK код, зөвхөн унших боломжтой сүлжээний төлөвийг шалгуул.
- Амьд сүлжээний туршилтуудыг `TAIRA_LIVE=1` шиг орчны флагийн ард сонголтоор хадгалаарай.
- Нууц түлхүүр, дансны сэргээх материал, API токенууд, эсвэл илгээсэн баталгаажуулалтын толгойг асуултуудад нааж болохгүй.
- Агент нь амьд тестнет гүйлгээ илгээхээс өмнө гүйлгээний төлөвлөгөө шаарддаг. Төлөвлөгөөнд сүлжээ, зөвшөөрлийн эрх бүхий этгээд, заавар, төлбөрийн хөрөнгө, урьдчилсан уншилт, хүлээгдэж буй үр дүн, дахин оролдлогын зан байдал гэх мэт мэдээллийг заавал оруулах ёстой.

[SORA 3 дээр барина: Taira ба Minamoto](/mn/get-started/sora-nexus-dataspaces.md#taira-mcp-for-agents)-г үзнэ үү, Taira MCP урсгалын ажлын хувьд.

## SDK Ариун цэвэр {#sdk-hygiene}

- Pin SDK ба бинар хувилбаруудыг [Тохиромжийн Матриц](/mn/reference/compatibility-matrix.md) ашиглан хамтдаа.
- Үүсгэсэн клиент код, жишээ, ба бадагчилсан хэсгүүдийг дээд түвшний хадгалагдсан ажлын орчны хувилбартай синхрончлуулах.
- Гүйлгээг үүсгэх кодод нэгжийн тест нэмэх болон таны програм хамаардаг хамгийн жижиг унших ба бичих замуудад интеграцийн тест нэмэх.
