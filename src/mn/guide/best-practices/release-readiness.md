# Релизийн бэлэн байдал {#release-readiness}

Iroha хэрэглээ эсвэл сүлжээний өөрчлөлтийг нэвтрүүлэхээс өмнө холбогдох эрсдэлийг илрүүлж чадах хамгийн жижиг орчинд ажиллагааг нь баталгаажуул. Дараа нь хамтарсан тестнет болон үйлдвэрлэлийн шалгууруудыг зориудын дарааллаар давна.

## Орон нутгийн сүлжээний хаалга {#localnet-gate}

- Iroha урсгалын ижил төстэй, хамгийн ойрын практикийн баталгаажуулагчдын тоотой нэг удаагийн орон нутгийн сүлжээг эхлүүлэх.
- Транзакцын бүтээн байгуулагч, хайлтын шинжилгээ, татгалзсан хэрэгслийн хангамж, конфигурацийн ачааллын нэгжийн туршилтыг явуулаарай.
- Хэрэглээний дараа ашиглах ижил SDK эсвэл CLI хэлбэрээр хамгийн жижиг амжилттай унших, бичүүлэх замыг туршиж үзээрэй.
- Экспериментийн артефакт дээр хүлээгдсэн гүйлгээний хэшүүд, статусууд, үйл явдлууд, байдлын тоог аваарай.

[Гэрээгүүлэх Iroha 3](/mn/get-started/launch-iroha.md) болон [SDK Сургалтын хувилбар](/mn/guide/tutorials/).

## Хамтарсан тест торгийн хаалга {#shared-testnet-gate}

- Endpoint-ийн ажиллагаа, шимтгэл, дансны санхүүжилт, latency болон ажиллагааны сургуулилтад Taira эсвэл өөр хамтарсан тестнет ашиглана.
- Ердийн туршилт сүлжээний бэлэн байдлаас хамаарахгүй, testnet хөрөнгө зарцуулахгүй байлгахын тулд амьд testnet-д бичих үйлдлийг зөвхөн илэрхий сонгосон үед ажиллуулна.
- Шууд тестийн гүйлгээ бүрийг илгээхээс өмнө гарын үсэг зурагчийн санхүүжилт, шимтгэлийн хөрөнгийн мета өгөгдөл, эрх бүхий этгээдийн зөвшөөрөл болон хүлээгдэж буй төлөвийг шалгана.
- Эцсийн төлөв иртэл хүлээгээд, үүссэн төлөвийг зөвхөн унших query-ээр баталгаажуулна.

Та үзээрэй. [Үргэлжүүлээрэй SORA 3: Taira болон Minamoto](/mn/get-started/sora-nexus-dataspaces.md).

## Төв сүлжээ эсвэл үйлдвэрлэлийн хаалга {#mainnet-or-production-gate}

- Үйлдвэрлэлийн гарын үсэг зурагчид, санхүүжилт, домэйнууд болон тохиргооны замуудыг тусад нь ашиглана. Тестнетийн түлхүүр болон faucet-ийн таамаглалыг үйлдвэрлэлд бүү шилжүүл.
- Шаардлагатай SDK хоорондын хувилбаруудыг [Нийцтэй байдлын матриц](/mn/reference/compatibility-matrix.md)-аар баталгаажуулна. Мөн байршуулалтад ашиглах яг тэр CLI, зангилааны binary, тохиргоо болон сүлжээний гаргалтыг тусад нь тогтоож туршина.
- Релизийн цонхоос өмнө зөвшөөрөл, шимтгэлийн sponsorship, rate limit, monitoring, backup-ийн төлөв болон rollback шалгуурыг хянана.
- Их нөлөөтэй бичих үйлдэлд бичгээр баталгаажуулсан transaction эсвэл migration төлөвлөгөө шаардана.

## Буцаалт ба сэргээх ажиллагаа {#rollback-and-recovery}

- Ямар өөрчлөлтийг код байршуулж буцаах, аль нь блокчейн дээрх гүйлгээ шаардах, алийг нь шууд буцаах боломжгүйг тодорхойлно.
- On-chain өгөгдлийн өөрчлөлтөд анхны үйлдвэрлэлийн бичилтээс өмнө нөхөн transaction эсвэл migration script бэлтгэнэ.
- Сүлжээний өөрчлөлтийн үед өмнөх binary, тохиргооны багц, гарын үсэгтэй genesis болон ажиллагааны зааврыг гаргалтын турш бэлэн байлгана.
- Татгалзалтын хувь, дарааллын өсөлт, саатал эсвэл зангилааны эрүүл байдал зэрэг бодит дохионд үндэслэн нэвтрүүлэлтийг зогсоох шийдвэрийн цэг тогтооно.

## Эцсийн шалгалтын жагсаалт {#final-checklist}

- Тохиргоо нь тухайн орчинд зориулагдсан бөгөөд зөвхөн тестэд хэрэглэх нууц агуулаагүй.
- Transaction retry нь idempotent эсвэл илэрхий хязгаартай.
- Хэрэглээ rejection, expiry, timeout болон endpoint availability-ийн алдааг хооронд нь ялгаж чадна.
- Monitoring нь throughput, latency, queue depth, rejection, view change болон холбогдох бизнесийн үйл явдлыг хамарна.
- Операторуудад хүлээгдэж буй алдааны горим бүрийн runbook байна.
- Аюулгүй байдлын хяналт нь түлхүүрийн хамгаалалттай хадгалалт, зөвшөөрөл, сүлжээнд ил гарсан байдал болон автоматжуулалтын эрхийг хамарсан.
