# Сүлжээний байршуулах {#network-deployment}

Сүлжээний Iroha системийг зохицуулсан систем гэж үзээрэй. Баталгаажуулагчид блокчейн үүсгэх үе, топологи, итгэмжлэгдсэн сүлжээний хамтрагчид, консенсус-түүхтэй тохиргоонд зөвшилцсөн байх ёстой бөгөөд үүнээс өмнө сүлжээ ажиллаж эхлэх ба блокыг эцэслэн баталгаажуулж байж чадна.

## Орчныг салгах {#environment-separation}

- Орон нутгийн хөгжүүлэлт, нийтлэг тестнет, туршилтын орчин, үйлдвэрлэлийн зориулалттай тусдаа тохиргооны багцуудыг хадгалаарай.
- Бүх дахин ашиглах боломжгүй орчных бүрт шинээр түлхүүр үүсгээрэй. Стандарт орон нутгийн сүлжээ буюу Taira түлхүүр материалыг үйлдвэрлэлд дахин ашиглаарай.
- Сүлжээний хослуулсан тохиргоо, клиент тохиргоо, гарын үсэгтэй блокчэйнийн генезис, скриптүүд, ба байршуулах тайлбаруудыг хувилбарласан гаргасан файл болгон хамт хадгал.
- Хувийн түлхүүрүүдийг агуулах ба тавигдах загваруудаас гадна хадгал.

Үүнийг үзнэ үү [Сүлжээний Тархалтын Түлхүүрүүд](/mn/guide/configure/keys-for-network-deployment.md).

## блокчейн үүсгэл ба Топологи {#genesis-and-topology}

- Профайл шаарддаг тохиолдолд бүх баталгаажуулагчид ижил гарын үсэг зурсан блокчэйн эх транзакц, найдвартай сүлжээний түншүүдийн багц, топологи, баталгаажуулагчийн эзэмшлийн нотолгоог ашиглах ёстой.
- Багадаа дөрвөн баталгаажуулагчийг Бизнантын алдаанд тэсвэртэй минималь байршуулалтад ашигла.
- Багтаамжийн төлөвлөлтөд хянагчдыг ажиглагчдаас тусгаарла. Ажиглагчид санал өгдөггүй, санал гаргадаггүй, мэдээлэл цуглуулдаггүй боловч тэд хадгалах сан, блокийн синк, сүлжээний өргөдлийг хэрэглэсээр байдаг.
- Блокчэйн үүсгэгч, гүйцэтгэгч, тэгш хэмийн өөрчлөлтүүдийг нэг л хүнд зориулсан засвар гэхийн оронд зохицуулагдсан шилжилтүүд гэж үзээрэй.

Үүнийг үзнэ үү [блокчэйн уг эх](/mn/reference/genesis.md), [сүлжээний хамтрагчийн удирдлага](/mn/guide/configure/peer-management.md), ба [Гүйцэтгэл ба үзүүлэлтүүд](/mn/guide/advanced/metrics.md#node-count-and-quorum).

## Torii ба Сүлжээний Хандалт {#torii-and-network-access}

- Хэрэв Torii нь хост буюу хувийн сүлжээнээс гадна ил болбол түүнийг урвуу прокси эсвэл галт хана ард байрлуул.
- TLS-ыг дуусгаж, нэвтрэлтэд үндсэн баталгаажуулалт, хурдны хязгаарлалт болон хүсэлт хэмжээний хяналтыг талд нь хэрэгжүүл. Үлдсэн хүчин чадлыг суурилуулалт шаардлагатай үед энэ арга хэмжээг авч үзнэ.
- Орчны шаардлагатай API төгсгөлүүдийг л нийтэл. Үйлдүүлэгч ба телеметрийн замууд нийтийн зөвхөн унших замуудаас илүү хязгаарлагдмал байх ёстой.
- Сүлжээний хамтрагчид шууд алсын тээвэрийг хүлээн авах ёсгүй үед сонсогчийн хаягийг орон нутгийн интерфэйстэй холбох.

Үүнийг [Torii API төгсгөлийн цэгүүд](/mn/reference/torii-endpoints.md) ба [Виртуаль хувийн сүлжээ](/mn/guide/security/vpn.md) харна уу.

## Нийтлэг ойлголт ба Чадвар {#consensus-and-capacity}

- Нийтлэг тохиргооны цаг хэмжигчийг тохируулахын өмнө развертлтийг хэмж. Цагийн хязгаарыг бууруулах нь зөвхөн сүлжээ, хадгалах болон гүйцэтгэлийн давхаргуудтай хөл нийлүүлэн ажиллаж байвал хоцрогдлыг бууруулж чадна.
- Зөвхөн дамжуулалтын богино хэмжээний дээж биш, эгнээгийн чиглэлийг ажигла. Тогтвортой ачааллаар эгнээ өсч байвал сүлжээ дэндүү ачаалалд орсон гэсэн үг.
- Бүх тэнцүүлэх туршилт бүрийн үр дүнтэй Sumeragi параметрүүд, телеметрийн профайл, баталгаажуулагчийн тоо, сүлжээ RTT, ачааллын хэлбэр, ба тоног төхөөрөмжийн мэдээллийг бүртгэнэ үү.
- Нэг удаад нэг хязгаарлагдмал эгнээ эсвэл ачаа сэргээх хязгаарыг өөрчилж, өмнөх ба дараах хүлээлт, тээвэрлэлтийн хэмжээ, санах ой, болон нөөцийн даралтын нотлох баримтыг хадгалаарай.

Үзнэ үү [Гүйцэтгэл ба үзүүлэлтүүд](/mn/guide/advanced/metrics.md).

## Түүхий металл ба процессын удирдлага {#bare-metal-and-process-management}

- Төлөв бүрийн сүлжээний тус бүрийн `config.toml`, хувийн түлхүүр, хадгалах директор, болон портуудыг тусад нь байлга.
- Тодорхой дахин эхлүүлэх, бүртгэл хийх, нөөцийн бодлоготой systemd зэрэг процесс менежерүүдийг ашиглаарай.
- Туршилтын топологийг удирдлагатай хост руу хөрвүүлэх үед үүсгэсэн README ба Kagami localnet багцаас эхлүүлэх командлалыг хадгалах.

Хар [Цэвэр металл дээр Iroha ажиллуулах](/mn/guide/advanced/running-iroha-on-bare-metal.md).
