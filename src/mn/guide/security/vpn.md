# Виртуаль хувийн сүлжээ {#virtual-private-networks}

<abbr title="Virtual Private Network">VPN</abbr> нь хэнд Iroha үйлчилгээнд нэвтрэхийг хязгаарладаг сүлжээний хяналт юм. Энэ нь голчлон хувийн болон консорциумын байршуулалтыг ашиглахад тохиромжтой бөгөөд зөвшөөрөгдсөн баталгаажуулагчид, програмын серверүүд, операторууд нь нээлттэй интернет маршрутаар биш, хувийн хаягаар харилцаж байх ёстой.

A VPN нь Iroha сүлжээний хамтрагчийн түлхүүрүүд, дансны түлхүүрүүд, зөвшөөрлүүд, гал хамгаалагчийн дүрмүүд, хяналт, эсвэл аюулгүй түлхүүр хадгалалтыг солихгүй. Үүнийг нэг давхарга гэж үзнэ үү. тархалтын хязгаар: VPN нь сүлжээний хүрэлцээг багасгадаг бол Iroha тохиргоо ба засаглалыг аль сүлжээний хамтрагчид, дансууд итгэлтэй болохыг шийддэг.

## VPN-г хэзээ ашиглах вэ {#when-to-use-a-vpn}

Дараах үед VPN хэрэглэнэ:

- баталгаажуулагчдыг өөр өөр байгууллагууд эсвэл өөр өөр хостинг орчны дор ажиллуулдаг
- Torii-д зөвхөн програмын арын холбоосууд, операторууд, эсвэл итгэмжлэгдсэн хэрэглэгчид нэвтрэх боломжтой байх ёстой
- метрик, бүртгэл, SSH, эсвэл бусад удирдлагын API цэгүүд хувийн операторын сүлжээнд байх ёстой
- шалгалт эсвэл туршилтын сүлжээ нь нийтийн API төгсгөлүүдийг ил гаргахгүйгээр үйлдвэрлэлийн хандалтын хяналтыг дуурайх ёстой

Бүх байршилд VPN хэрэггүй. Нийтийн сүлжээнүүд нь зориудаар Torii-ыг нийтийн шлюз, ачааллыг тэнцвэржүүлэгч, эсвэл эсрэг проксийн дамжуулж ил гаргаж болно. Тэр нөхцөлд ч гэсэн баталгаажуулагчийн хөрш-руу-хөрш холболт болон удирдлагын API төгсгөл цэгүүдийг аль болох хязгаарлагдмал сүлжээнд хадгалах хэрэгтэй.

::: tip

Вэб хөтчиг VPN зөвхөн тухайн хөтчөөс гарч буй траффикийг хамгаална. Энэ нь `iroha3d`, CLI, SDK, SSH, метрик болон нөөцлөлтийн траффикийг хамгаалахгүй, хэрэв эдгээр процессуудыг нэгэн адил хувийн сүлжээгээр дамжуулж холбохгүй бол.

:::

## Түгээмэл хэв маяг {#deployment-pattern}

Хувийн баталгаажуулагчийн сүлжээнд, бүх баталгаажуулагч бүрт тогтмол VPN хаяг эсвэл хувийн DNS нэр өг. Сүлжээний хамтрагчдыг тохируулж, тэдний зарласан хамтрагч-ба-хамтрагч хаягуудыг бусад баталгаажуулагчид тухайн сүлжээнээс хандах боломжтой болгоно:

```toml
trusted_peers = [
  "PUBLIC_KEY_1@10.20.0.11:1337",
  "PUBLIC_KEY_2@10.20.0.12:1337",
  "PUBLIC_KEY_3@10.20.0.13:1337",
  "PUBLIC_KEY_4@10.20.0.14:1337",
]

[network]
address = "10.20.0.11:1337"
public_address = "10.20.0.11:1337"

[torii]
address = "10.20.0.11:8080"
```

Одоогийн сүлжээний хамтрагчид `network.address` ба `network.public_address` дотор олгогдсон хаягийг ашиглана уу. Тус бүр сүлжээний хамтрагчид ижил итгэмжлэгдсэн сүлжээний хамтрагчдын ID-ийг жагсааж, үүнийхээ VPN маршрутын хүснэгтээс очиж болох хаягуудыг ашиглах ёстой.

Клиент болон CLI тохиргоонууд нь VPN-ийн дамжуулалт эсвэл удирдлагатай дотоод гарцаар хүрч болох Torii API эцсийн цэгийг заах ёстой:

```toml
torii_url = "http://10.20.0.11:8080"
```

Хэрэв Torii нь VPN-аас гадна ашиглагдах ёстой бол үүнийг TLS, баталгаажуулалт, хурд хязгаарлалт, болон бүртгэл хийх боломжийг олгодог урвуу прокси эсвэл ачаалал тэнцүүлэгчийн ард байрлуул. Шууд нийтэд зориулсан интернетэд түүхий peer-to-peer порт болон удирдлагын API эцсийн цэгүүдийг ил задгай болгохоос зайлсхий.

## Галын хана дүрэм {#firewall-rules}

Хост ба үүлэн галын хана дүрмийг VPN байгаа тохиолдолд ч ашиглах:

|Үйлчилгээ|Зөвлөсөн нэвтрэх эрх|
| --- | --- |
|Хамтдаа порт|Бусад баталгаажуулагч VPN зөвхөн хаягууд|
| Torii |Програмын арын систем, операторууд, эсвэл итгэмжлэгдсэн клиент VPN хүрээ|
|Хэмжигдэхүүн ба эрүүл мэндийн шалгалт|Үйл ажиллагаа эрхлэгчийн сүлжээнд хяналтын системүүд|
| SSH ба захиргаа |Бастионы сервер, онцгой эрхтэй оператор VPN хүрээ, эсвэл шилэн эвдэх процесс|
|Нөөц болон хадгалах сангийн хувилбарууд|Хувийн сүлжээнд зориулсан нөөцлөх системүүд|

Анхдагч-болон татгалзах дүрмийг өргөн зөвшөөрөх дүрмээс илүү хялбар аудит хийх боломжтой. Шинэ сүлжээний хамтрагч сүлжээнд нэгдсэнээр VPN гишүүнчлэл, гал хамгаалагчийн зөвшөөрөлт жагсаалт, болон Iroha итгэлтэй сүлжээний хамтрагчийн тохиргоог нэгтгэсэн өөрчлөлт болгон шинэчилнэ үү.

## Үйл ажиллагааны шалгалтын жагсаалт {#operational-checklist}

- Аудитлагдсан, идэвхтэй засварлагдаж байгаа VPN хэрэгжилтийг сонгоно уу, жишээлбэл WireGuard, IPsec, эсвэл байгууллагаас зөвшөөрсөн удирдлагатай хувийн сүлжээ.
- Бүх хост болон оператор бүрт өвөрмөц VPN нэвтрэх мэдээллийг ашигла. Баталгаажуулагчдын хооронд VPN түлхүүрүүдийг хуваалцаж болохгүй.
- VPN баталгаажуулалтын мэдээллийг Iroha хувийн түлхүүр болон блокчэйн анхны гарын үсгийн материалтай тусад нь хадгал.
- Сүлжээний саатал, багц хаягдал, дахин холболт болон чиглэлийн өөрчлөлтийг VPN хянах. Туйлшрал нь тогтмол сүлжээний тогтворгүй байдалд мэдрэмтгий байдаг.
- Үр дүнтэй MTU-ийг туршиж үзнэ үү. Багц хуваагдсанаас шалтгаалан сүлжээний хамтрагч эсвэл Torii алдаанууд завсардмал мэт харагдаж болно.
- Документ нь VPN хүрээ нь түншээс-түнш рүү хүрэх боломжтой, Torii, хэмжүүрүүд, SSH, болон нөөцлөх API төгсгөлүүдийг заана.
- Сүлжээнээс хост, операторын данс эсвэл байгууллага гарвал VPN баталгаажуулалтыг эргүүлэх.
- Баталгаажуулагчдын хооронд ганц VPN гарцыг цорын ганц зам болгон ашиглахаас зайлсхий. Үйлдвэрлэлийн сүлжээнүүдэд дахин давтагдсан гарцууд эсвэл сайт-сайт холболтуудыг төлөвлөөрэй.
- Сүлжээний тасалдлыг Iroha процессын алдаанаас ялгахыг операторуудад мэдэгдэхийн тулд ослын хариу арга хэмжээний сургалтад VPN алдааг оруулна уу.
