# Гүйлгээ {#transactions}

Гүйлгээ нь блокчейнд ажлыг гүйцэтгэхийг хүссэн гарын үсэг зурсан хүсэлт юм. Гүйцэтгэх боломжтой агуулга нь дараалсан [заавар](./instructions.md), гэрээний техникийн дуудлага, IVM байт код, эсвэл батлагдсан IVM гүйцэтгэл байж болно. Одоогийн гэрээний гүйцэтгэлийн загварыг мэдэхийн тулд [Өөрөө гүйцэтгэгдэх гэрээ](./smart-contracts.md)-ийг үзнэ үү.

Гүйлгээ нь төрлийн өөрчлөлт оруулах буюу гүйцэтгэлийн ажил хийдэг. Зөвхөн унших шалгалт нь гарын үсэгтэй асуулт эсвэл олон нийтийн унших API төгсгөлүүдийг ашигладаг бөгөөд гүйлгээ үүсгэдэггүй.

Төгсгөлд хүрсэн блок руу орсон гүйлгээг гүйцэтгэлийн үр дүнтэй нь хамт хадгалдаг бөгөөд үүнд гүйцэтгэлийг татгалзсан тохиолдлууд орно. Блокт орохоос өмнө татгалзсан хүсэлтүүд, жишээлбэл, хүчин төгөлдөр бус өгөгдлийн сав эсвэл цуваагаар татгалзсан гүйлгээ, блокт хадгалагддаггүй.

Нууцлалыг хамгаалсан хөрөнгийн шилжүүлгийн талаар [Нэргүй гүйлгээ](./anonymous-transactions.md)-г үзнэ үү. Нэргүй гүйлгээ нь нийтийн данс хоорондын үлдэгдлийн өөрчлөлтийн оронд хамгаалалттай хөрөнгийн тэмдэглэл, криптографийн амлалт, nullifier болон тэг-мэдлэгийн нотолгоо ашиглана.

Сонгосон ил тод гүйцэтгэлийн үр нөлөөний нотолгоо доказыг үзэхийг хүсвэл [FastPQ](./fastpq.md) руу орно уу. FastPQ энгийн гүйлгээний гүйцэтгэлийн дараа гүйцэтгэлийн гэрчүүдийг хэрэглэж, дэмжигдсэн төлөв шилжилтүүдэд зориулсан детерминист баталгаат багцыг бүтээдэг.

## Энэ урсгалыг Taira-д ажиллуулна уу {#try-it-on-taira}

Эксплорерын маршрутуудыг ашиглан гарын үсэг зурсан дансгүйгээр сүүлийн үеийн нийтийн Taira блок болон гүйлгээний статусыг шалгана уу:

```bash
curl -fsS 'https://taira.sora.org/v1/explorer/blocks?page=1&per_page=3' \
  | jq '{pagination, blocks: [.items[] | {height, hash, transactions_total, transactions_rejected}]}'

curl -fsS 'https://taira.sora.org/v1/explorer/transactions?page=1&per_page=5' \
  | jq '{pagination, txs: [.items[] | {hash, block, status, executable}]}'
```

Өмнө таны апп гаргасан гүйлгээг дагахын тулд жагсаалтаас `hash`-г хуулж, судалгааны дэлгэрэнгүй маршрут руу орно уу:

```bash
TX_HASH='<transaction-hash>'

curl -fsS "https://taira.sora.org/v1/explorer/transactions/$TX_HASH" \
  | jq '{hash, block, status, authority, executable}'
```

Энэ нь одоо ч зөвхөн унших горимтой байна. Гүйлгээ илгээхийн тулд гарын үсэгтэй Norito өгөгдлийн сав, зөв гинжний ID, төлбөрийн мета өгөгдөл, мөн тестнэтээр санхүүжүүлсэн Taira данс шаардлагатай.

Taira дээр төлбөртэй жишээ ажиллуулахдаа [Taira-аас testnet XOR авах](/mn/get-started/sora-nexus-dataspaces.md#_4-get-testnet-xor-on-taira) хэсгийн faucet туслахыг `taira_faucet_claim.py` нэрээр хадгалж, эхлээд нийтийн faucet-аар гарын үсэг зурагчийг санхүүжүүлнэ:

```bash
export TAIRA_ACCOUNT_ID='<TAIRA_I105_ACCOUNT_ID>'
export TAIRA_FEE_ASSET=6TEAJqbb8oEPmLncoNiMRbLEK6tw

curl -fsS https://taira.sora.org/v1/accounts/faucet/puzzle | jq .
python3 taira_faucet_claim.py "$TAIRA_ACCOUNT_ID"

iroha --config ./taira.client.toml ledger asset get \
  --definition "$TAIRA_FEE_ASSET" \
  --account "$TAIRA_ACCOUNT_ID"
```

Faucet-ийн таавар эсвэл нэхэмжлэх маршрут `502` буцаавал гүйлгээг оношлохоос өмнө хүлээгээд дахин оролдоно.

Дараа нь гүйлгээг илгээх үед Taira төлбөрийн хөрөнгийн метадатаг хавсаргана:

```bash
printf '{"gas_asset_id":"%s"}\n' "$TAIRA_FEE_ASSET" > taira.tx-metadata.json

iroha --config ./taira.client.toml \
  --metadata ./taira.tx-metadata.json \
  ledger transaction ping --msg "faucet-funded taira transaction"
```

## Өөрөө ажилладаг гүйлгээ {#offline-transactions}

Iroha-д хоёр офлайн гүйлгээний ажиллах урсгал байна:

- Оффлайн гарын үсэг зурах нь гарын үсгийн төхөөрөмж салгасан үед хэвийн гарын үсэгтэй гүйлгээг үүсгэдэг. Гүйлгээ нь онлайн клиент гарын үсэгтэй өгөгдлийн савыг Torii-д илгээтэл боловсруулагдахгүй, тиймээс зөв гинжний ID, эрх олгох үндсэн элемент, зөвшөөрөл, төлбөр шаардлагатай хэвээр байна, буюу гүйлгээний амьдралын хугацаа.
- Kagemusha офлайн бэлэн мөнгө нь цахим хэтэвчийг онлайн үед нь нөхдөг, хүлээн авагч эхлүүлсэн хэтэвчээс хэтэвч рүү шилжүүлгийг хоёулаа офлайн үед дэмждэг, мөн хүлээн авагч онлайн болсны дараа үүссэн тэмдэгтийн төлвийг гүйцэлдүүлдэг.

Torii нь `/v1/offline/*` дор Kagemusha-ийн бүрэн амьдралын мөчлөгийг ил болгож байна:

|Арга ба API төгсгөлийн цэг|Зорилго|
| --- | --- |
| `GET /v1/offline/readiness` |Kagemusha-гийн бэлэн байдлыг нэг `asset_definition_id` үнэлэх|
| `POST /v1/offline/receiver-lineage` |Гэрчлэл бүхий идэвхтэй бүртгэлийн удамшлыг гарын үсэг зурсан хүлээн авагчийн хүсэлтэд шийдвэрлэх|
| `POST /v1/offline/top-up` |Гарын үсэг зурсан онлайн-оос оффлайн төлбөрт шилжүүлэх үйлдлийг илгээнэ үү|
| `POST /v1/offline/redeem` |Гарын үсэг зурсан оффлайн нөхөн олговрын үйл ажиллагааг илгээх|
| `GET /v1/offline/operations/{operation_id}` |Нэмэлт эсвэл буцаан авах үйлдлийн нэг протокол-стандартын статустыг уншина уу|

Оффлайн үйл ажиллагаа барихын өмнө хөрөнгийн бэлэн байдлыг шалгана уу:

```bash
curl -fsS --get https://taira.sora.org/v1/offline/readiness \
  --data-urlencode 'asset_definition_id=<canonical_asset_definition_id>' \
  | jq '{ready, blockers, artifact_set}'
```

Бэлэн байдал нь түргэн гүүр ABI 21 болон баталгаажсан V4 урлагийн бүтээлүүдтэй түрийвчийг холбоно. Удам угшил, дүүргэлт, буцаан худалдан авах хүсэлтүүд нь бичигдсэн `application/x-norito` архивуудыг ашиглана. Дээр дүүргэлт ба нөхөн олговорын буцаалт `202 Accepted` нь үйлдлийн нөөц рүү заасан `Location` гарчигтай; ороогүй тэг биш үйлдлийн ID нь идемпотент түлхүүрийг өгдөг.

Ерөнхий урсгал нь:

1. Бэлтгэл байдлыг шалгаад, хэрэв `ready` буруу бол эсвэл ямар нэгэн саад тулгарвал зогсоно уу.
2. Нэг протоколын стандарттай цэнэглэх архивыг байгуулахын тулд бичиж оруулсан Swift эсвэл JVM түрийвчийг ашиглаж, үүнийг илгээж, үйлдэл эцсийн гинжийн төлөвт хүртэл оруулах тэмдэглэлийн төлвийг болон үйлдлийн ID-ийг хадгална уу.
3. Хүлээн авагчийн бүртгэлийн гарал үүслийг шаардлагатай үед шийдэж, сүлжээний әр нэг түншийн шилжүүлгийг орон нутгаар бүтээж шалгаж, дамжуулалтыг баталгаажуулахаас өмнө нууцлагдсан тэмдэгтийн төлөвийг хадгалаарай.
4. Хүлээн авагч онлайн байх үед, нэг протоколын стандартын нөхөн сэргээх архивыг байгуулж, илгээгээд, түүний ажиллах нөөцийг эцсийн байдлаар шалга.

Блокчэйн бичиглэл нь тэмдэгтийн байдал онлайн амьдралын мөчлөгөөр эргэж ирэх хүртэл зөрчилтэй оффлайн дамжуулалтыг ажиглаж чадахгүй. Иймээс түрийвч болон операторын бодлого нь үнэ цэнийн хязгаар, хүчин төгөлдөр хугацаа, хүлээн зөвшөөрөгдсөн гаргагчид, удаан хадгалах боломжтой орон нутгийн хадгалалт, мөн тохируулах цонхыг хэрэгжүүлэх ёстой.

Энд `Grant` зааврыг ашиглан шинэ гүйлгээг үүсгэх жишээ байна. Энэ гүйлгээнд, Mouse нь Alice-д тодорхойлсон үүрэг (`role_id`) олгож байна. [бүрэн жишээ](./permissions.md#register-a-new-role)-ийг шалгаарай.

```rust
let grant_role = Grant::account_role(role_id, alice_id);
let grant_role_tx = TransactionBuilder::new(chain_id, mouse_id)
    .with_instructions([grant_role])
    .sign(mouse_private_key);
```
