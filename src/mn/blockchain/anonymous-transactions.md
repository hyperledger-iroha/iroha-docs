# Аноним гүйлгээ {#anonymous-transactions}

Iroha -ийн нэрэмжит гүйлгээ нь нууцлаг хөрөнгийн үйл ажиллагаанаас үүдэлтэй. Төрийн өмчийн бүртгэлээс бүртгэлийн төлбөрт шилжүүлэн суулгахын оронд, буцаан үнэ цэнийг хамгаалалттай номын сан руу нэвтрүүлж, дараа нь нурын мэдлэгийн баталгаа бүхий ил тод тэмдэглэлүүдийг зарцуулдаг.

Олон нийтийн номын сан нь нууцлалтай үйлдэл болсон тухай хэвээр тэмдэглэдэг. Энэ нь үүрэг гүйцэтгэх, хүчингүй болгох, баталгаажуулах хэшүүд болон үйл явдлыг бүртгэдэг боловч тэмдэглэлийн эзэмшигч, хүлээн авагч эсвэл хамгаалалттай хөдөлгөөний хэмжээг бүртгэхгүй. Худалдааны хэвийн хуудас нь өргөн мэдүүлсэн дансыг илрүүлэх боломжтой тул "аноним" гэдэг бол цахим сүлжээний болон дансны түвшинд нууцлагддаггүй, үл мэдэгдэх хөрөнгийн хөдөлгөөн гэсэн үг юм.

## Барилгын блок {#building-blocks}

|Төгсгөл|Номын сангийн төлөөлөл |
| ------------------ | ------------------------------------------------------------------------------------------------------------------ |
|Сэтгэлэгт тэмдэглэл|Мөнгө, хэмжээ, эзэмшигчдийн мэдээлэл, санамжгүй байдалтай хувийн хөрөнгийн тэмдэгт. |
|Үүнд үүрэг гүйцэтгэгч|32 байтын олон нийтийн үнэ цэнэ нь тэмдэглэлийн талбайдыг илрүүлэхгүйгээр нэгтгэдэг. |
|Үргэлжүүлэгч |Iroha нь хоёр дахин зарцуулахыг саад сэргийлэх зорилгоор давтамжлах хүчингүй болгодог. |
|Merkle түлх |Ашигт малтмалын үүрэг гүйцэтгэх дэргийн сүүлийн үеийн гаралтай зүйл.|
|Дашрамд холбогдсон |`ProofAttachment` нь баталгааны байт болон хяналтын түлхэгийн сэнслэл эсвэл гарын үсэгт хяналт тавих түлхэйтэй. |
|Үндсэн нууц үйл явдал |`ConfidentialEvent::Shielded`, `Transferred`, эсвэл `Unshielded` гэх мэт номын сангийн үйл явдал. |

Үндсэн чиглэл нь:

- `RegisterZkAsset`: хөрөнгийг ZK-ийн хүчин чадалтай гэж бүртгэж, шилжүүлэн суулгах, хамгаалах болон хамгаалагдашгүй баталгаажуулах түлхүүдийг байлгаж байна.
- `Shield`: олон нийтийн тэнцвэрт төлбөрийг хадгалах, хамгаалалттай тэмдэгтийн үүрэг гүйцэтгэх.
- `ZkTransfer`: хадгаламжтай тэмдэгтийг шинэ хамгаалалттай тэмдэгтийн үүрэг гүйцэтгэхэд зарцуулдаг.
- `Unshield`: хяналт тавих тэмдэгтийг зарцуулдаг, төрийн сангийн үлдэгдэл олгодог.
- `ScheduleConfidentialPolicyTransition` болон `CancelConfidentialPolicyTransition`: хөрөнгийн нууцлалын бодлогыг удирдлагаар өөрчилж байна.

Ашигт малтмалын тодорхойлолтод [`AssetConfidentialPolicy`](/mn/reference/data-model-schema.md) нь мөн байдаг:

|Дээрх хэв маяг|Энэ нь юу вэ?|
| ----------------- | ---------------------------------------------------------------- |
|`TransparentOnly` |Зөвхөн энгийн төрийн үлдэгдэл, шилжүүлэн суулгалыг хүлээн авдаг. |
|`Convertible` |Хэрэглэгчид үнэ цэнийг олон нийтийн тэнцвэр болон хадгаламжтай тэмдэгтийн хооронд хөдөлгөх боломжтой. |
|`ShieldedOnly` |Ашигт малтмалын санхүүжилт, шилжүүлэн суурьлах үйл ажиллагааны бүртгэлд үлдэх ёстой. |

## Тэднийг хэрхэн ашиглах вэ? {#how-to-use-them}

1. Үнэлгээний цэгүүд дээр нууцлан дэмжлэг олгох. Үнэлгээгчийн хяналт шалгаруулагч, идэвхтэй баталгаажуулах товчоо, Poseidon/Pedersen параметр IDs, болон нууцлалтын дүрэмүүдийн хувилбарыг тохиролцох ёстой.
2. Ширээний хэрэглэгддэг санхүүжилтийн түлхүүр, параметрын багцсыг хэвлүүлнэ, бүртгэнэ. Валет болон оператор нь `VerifyingKeyId`, жишээ нь `halo2/ipa:vk_transfer` хэмээх түлхүүдийг дурдсан байх ёстой.
3. Ашигт малтмалыг ZK-ийн хөрөнгө оруулалтаар `RegisterZkAsset` бүртгүүлэх, эсвэл бодлогын шилжилтийг `TransparentOnly` -ээс `Convertible` буюу `ShieldedOnly` -д хийх.
4. Төрийн хөрөнгийг `Shield` -ээр хамгаалах. Суулгавар нь гүйлгээг өргөн мэдүүлэхээс өмнө хүлээн авагчдад тэмдэгтийн үүрэг гүйцэтгэл болон шифрлэгдсэн ашиг ачааллыг бий болгодог.
5. `ZkTransfer` -тай нууцлан шилжүүлнэ. Номын сан нь орж ирсэн тэмдэгтүүдийг эзэмшдэг, орж ирж байгаа болон гарч буй үнэ цэнэ тэнцэж байгааг баталгаажуулдаг бөгөөд зарцуулсан тэмдэгт бүр сүүлийн үеийн үүрэг гүйцэтгэлийн модгоор байрладаг гэсэн баримтыг бий болгоно.
6. `Unshield` нь олон нийтийн хэмжээ болон хүлээн авагчдын дансыг илрүүлж, хувийн тэмдэглэлийн хүчингүй болгох хэрэглээг зарцуулж, хувийн өөрчлөлтийн гараа бий болгож болно.
7. Үндсэн нууц үйл явдлууд, баталгааны баримт бичгүүд, хүчингүй болгох байдлын байдал, үл тодруулсан хадгаламжийн баримт бичгүүдийг Torii эцсийн цэгүүдээр дамжуулан уншиж үзүүлэх аудитын ажил.

## CLI Жишээ нь: {#cli-examples}

ZK CLI команд нь оператор болон шинжилгээний урсгалд зориулагдсан байдаг. Үйлдвэрлэлийн буулганаар хариуцлага, шифрлэгдсэн ашиг ачаалл, баталгаажуулалтыг буулгана/проверорын номын сантай дамжуулан хүргэх ёстой бөгөөд үр дүнтэй заалыг ирүүлэхийн өмнө .

ZK -ийн хибрид хөрөнгийг бүртгүүлэх:

```bash
iroha app zk register-asset \
  --asset <asset-definition-id> \
  --allow-shield true \
  --allow-unshield true \
  --vk-transfer halo2/ipa:vk_transfer \
  --vk-unshield halo2/ipa:vk_unshield \
  --vk-shield halo2/ipa:vk_shield
```

Сэргээн хамгаалалттай тэмдэглэлд зориулсан шифрлэгдсэн ашиг ачааны хуудасны хувилбар бариарай:

```bash
iroha app zk envelope \
  --ephemeral-pubkey 0101010101010101010101010101010101010101010101010101010101010101 \
  --nonce-hex 020202020202020202020202020202020202020202020202 \
  --ciphertext-b64 AQIDBA== \
  --print-json \
  --output note-envelope.bin
```

Төрийн хөрөнгийн санхүүжилтийг хөрөнгийн хамгаалалттай номонд хадгалах:

```bash
iroha app zk shield \
  --asset <asset-definition-id> \
  --from <account-id> \
  --amount 1000 \
  --note-commitment ABABABABABABABABABABABABABABABABABABABABABABABABABABABABABABABAB \
  --enc-payload note-envelope.bin
```

Дашрамд халуун төхөөрөмжтэй хамгаалалтгүй JSON:

```bash
cat > unshield-proof.json <<'JSON'
{
  "backend": "halo2/ipa",
  "proof_b64": "BASE64_PROOF_BYTES",
  "vk_ref": {
    "backend": "halo2/ipa",
    "name": "vk_unshield"
  }
}
JSON

iroha app zk unshield \
  --asset <asset-definition-id> \
  --to <account-id> \
  --amount 1000 \
  --inputs DEADBEEFDEADBEEFDEADBEEFDEADBEEFDEADBEEFDEADBEEFDEADBEEFDEADBEEF \
  --proof-json unshield-proof.json
```

## SDK Жишээлбэл {#sdk-example}

Тухайн баталгааны байт нь тохируулсан баталгааны хяналтын хэсгээс ирдэг. Транзакцыоны ашигтай ачааллд зөвхөн олон нийтийн өгөгдлүүд болон баталгааны хавсралт хэрэгтэй:

```rust
use iroha_data_model::{
    isi::zk::{Unshield, ZkTransfer},
    prelude::{AccountId, AssetDefinitionId, InstructionBox},
    proof::{ProofAttachment, ProofBox, VerifyingKeyId},
};

fn transfer_instruction(
    asset: AssetDefinitionId,
    input_nullifier: [u8; 32],
    output_commitment: [u8; 32],
    anchor_root: [u8; 32],
    proof_bytes: Vec<u8>,
) -> InstructionBox {
    let backend = "halo2/ipa".into();
    let proof = ProofBox::new(backend, proof_bytes);
    let vk = VerifyingKeyId::new("halo2/ipa", "vk_transfer");
    let attachment = ProofAttachment::new_ref("halo2/ipa".into(), proof, vk);

    ZkTransfer::new(
        asset,
        vec![input_nullifier],
        vec![output_commitment],
        attachment,
        Some(anchor_root),
    )
    .into()
}

fn unshield_instruction(
    asset: AssetDefinitionId,
    recipient: AccountId,
    amount: u128,
    input_nullifier: [u8; 32],
    anchor_root: [u8; 32],
    proof_bytes: Vec<u8>,
) -> InstructionBox {
    let backend = "halo2/ipa".into();
    let proof = ProofBox::new(backend, proof_bytes);
    let vk = VerifyingKeyId::new("halo2/ipa", "vk_unshield");
    let attachment = ProofAttachment::new_ref("halo2/ipa".into(), proof, vk);

    Unshield::new(
        asset,
        recipient,
        amount,
        vec![input_nullifier],
        attachment,
        Some(anchor_root),
    )
    .into()
}
```

## Аноним хөрөнгийн хадгаламж {#anonymous-asset-escrow}

Анноним хөрөнгийн хадгаламж нь хадгаламжийн хадгаламжид мөн адил хамгаалалттай шилжүүлэн суулгах машиныг ашигладаг. Талууд болон хадгаламжийг хадгаламжны бүртгэлд хэвээр тэмдэглэгддэг боловч санхүүжилт, чөлөөлөлт, цуцлах, шийдвэрлэх хөлүүд нь хамгаалалттай хүчингүй болгох болон гаргах үүрэг гүйцэтгэлийг ашигладаг.

ISI хяналт тавих үйл ажиллагаа, жишээг дэлгэрэнгүй үзнэ үү [ Үндэсний хөрөнгийн хяналтын ](/mn/blockchain/escrow.md#anonymous-escrow).

Амьдралын эргэлт нь:

1. `OpenAnonymousAssetEscrow` санхүүжилтийн хамгаалалттай нотлуудыг зарцуулдаг бөгөөд нэг хадгаламжийн үүрэг гүйцэтгэгчтэй.
2. `AcceptAnonymousAssetEscrow` худалдан авагч бүртгэнэ.
3. `MarkAnonymousEscrowPaymentSent` худалдан авагч төлбөрийг гадаад зах зээлээс илгээсэн тухай баримтыг бүртгэж байна.
4. `ReleaseAnonymousAssetEscrow` худалдан авагч гаргах үүрэг гүйцэтгэгчээс хадгаламж хүлээсэн үүргийг зарцуулна.
5. `CancelAnonymousAssetEscrow` нь төлбөрийг тэмдэглэхгүй бол худалдааны гүйцэтгэх үүрэг хариуцлагад хадгаламж хүлээлгэн өгөх.
6. `OpenAnonymousEscrowDispute` болон `ResolveAnonymousEscrowDispute` нь баталгааны хэшүүдтэй, шийдвэрлэгчээр хяналтын хуваарилалтай маргаан тушаалтай хадгаламж хариуцан ажилладаг.

[Эрүүлэг ](/mn/reference/queries.md#escrow-and-proof-records)-д жагсаалсан нууцлан бүртгэгдсэн хадгаламжийн асуултуудыг ашиглан хадгаламж бичиг, статусыг хянах болно.

## Математик {#math}

Доорх тэмдэглэл нь нууц хөрөнгийн урсгалыг тодорхойлдог. хэрэгжилтэд активын бодлого болон баталгаажуулагчийн бүртгэлийн идэвхитэй тойрог, параметр IDs -ийг ашигладаг тул үйлчлүүлэгчид үүрэг гүйцэтгэл, хүчингүй болсонд тооцгоогч, нотолгооны байтыг гарын үсэг / даалгаварны ил тод үр дүн гэж үзэх ёстой .

Сэргэлттэй тэмдэглэлг:

$$
n = (\mathsf{asset}, \mathsf{amount}, \mathsf{owner}, \rho)
$$

`owner` нь хүлээн авагчийн үзэх эсвэл зарцуулах материалаас үүдэлтэй бөгөөд `rho` нь санамсар ёсны тэмдэглэл юм.

Номын үүрэг гүйцэтгэгч нь нууцлагдсан үүрэг гүйцэлдэг:

$$
C = \mathsf{Commit}(\mathsf{asset}, \mathsf{amount}, \mathsf{owner}, \rho)
$$

Одоогийн нууцлагдсан шилжүүлэн суулгах эргэлтэд олон нийтийн өгөгдлүүд нь тэмдэглэлийн үүрэг гүйцэтгэгч, хүчингүй болгогч, Merkle түлх, хөрөнгийн тэмдэг, сүлжээний тэмдэг зэрэг юм.

$$
C = H_c(\mathsf{amount}, \rho, \mathsf{owner\_tag}, \mathsf{asset\_tag})
$$

Номыг зарцуулахдаа мөнгөн тэмдэгт нь хүчингүй болгож өгдөг:

$$
N = H_n(\mathsf{spend\_key}, \rho, \mathsf{asset\_tag}, \mathsf{chain\_tag})
$$

`N` нь олон нийтэд нээлттэй байдаг. Энэ тэмдэгтийг илтгэхгүй, гэхдээ энэ тэмдэглэл болон сүлжээний хувьд тогтвортой тул Iroha нь ижил хүчингүй болгож байгаа хоёр дахь зарцуулыг татгалзаж болно.

Зохиоллын мод нь тэмдэглэлийн оршин тогтнолыг баталдаг. Хэрэв гарын үсэг `C_i` -ийг зарцуулдаг бол энэ баримт нь `C_i` -ээс сүүлийн үеийн олон нийтийн суурь руу хувийн Merkle замыг багтааж байна:

$$
\mathsf{MerkleRoot}(C_i, \mathsf{path}) = R
$$

Үргэлтгүй шилжүүлэн суулгахад үнэ цэнийг хадгалахыг баталгаажуулах нь мөн:

$$
\sum \mathsf{inputs} = \sum \mathsf{outputs}
$$

Гаалийн хэмжээг хамгаалалттайгүй тохиолдолд:

$$
\sum \mathsf{inputs} = \mathsf{public\_amount} + \sum \mathsf{private\_change}
$$

Нэвтрүүлэгний дүгнэлтийг дараах байдлаар товчлуулж болно:

$$
\mathsf{Verify}(\mathsf{vk}, \mathsf{public\_inputs}, \pi) = \mathsf{true}
$$

`public_inputs` нь үүрэг гүйцэтгэгч, хүчингүй болсоор тооцдог, түлхүүр, хөрөнгийн тэмдэг, сүлжээний тэмдэг болон олон нийтийн нууцалтгүй хэмжээ юм. Гэрч нь тэмдэглэлийн хэмжээ, санамжлалт байдал, зарцуулах материал, Merkle чиглэлүүд байна. Үнэлгээний баталгаажуулагчид нотолгоог шалгаж, дараа нь гарааны үүрэг гүйцэтгэлийг нэмж, өгөгдлийн хүчингүй болгогчдыг зарцуулсан гэж тэмдэглэж, нотолгооны хэсгийг өөрчлөх.

## Олон нийтийн мэдээллийн хэрэгсэл {#what-is-public}

Аноним үйл ажиллагаа нь ажиглагдаж буй бүх баримтыг нууц болгодоггүй. Дараах мэдээллүүд хэвээр байх боломжтой:

- гүйлгээний хэш, блок өндөр болон захиалгын
- төлөөлөгч гүйлгээний эрх мэдэл, эсэх тохиолдолд хүсэлт нь хувийн нэвтрүүлгийн цэг эсвэл эргэлтийн загварыг ашигладаг.
- ашиглаж буй хөрөнгийн тодорхойлолт
- Үргэлжүүлэгч, үржихүйн үүрэг
- баталгаажуулах хэшүүд, шалгаруулалтын түлхүүрний сүлжээнүүд, сонголттой хуудасны хэшүүд
- `Unshield` -ийн олон нийтийн хэмжээ, хүлээн авагчдын бүртгэл
- үл тодруулсан хадгаламжийн худалдаалагч, худалдан авагч, байдал, цаг хугацааны тэмдэг, гэрчилгээний хэш

Хэрэглээлийг зохион байгуулж, энэ олон нийтийн метабараа нь та хамгаалж байгаа бизнесийн харилцааг илрэхгүй байх болно.
