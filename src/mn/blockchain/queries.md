# Судалгаа {#queries}

Чалалтын төлөөлөгчид болон филтрүүд нь блокчейн байдлын өөрчлөлтийг дагаж болно. Одоогийн байдлын шууд үзлэг хэрэгтэй бол асуултыг ашиглаарай.

Судалгаа нь даалгавартай төдийлөн жижиг зүйл. Iroha Дэлхийн өнөөгийн нөхцөл байдлын талаарх дэлгэрэнгүй мэдээллийг авна.

Хүлжээ нь бусад мэдээллийг илрүүлнэ. Дэлхийн улс орнуудын талаарх мэдээлэл бол бүх Iroha сүлжээнд хангагдах баталгаатай цорын ганц төрлийн мэдээлэл юм.

Iroha-ийн ашиглалтын хувьд бусад мэдээлэл байж болох юм. Жишээ нь, телеметрийн мэдээллийн хэрэгсэл нь сүлжээний удирдлагуудтай холбоотой байдаг. Хөдөлмөрийг гүйцэтгэхэд ашиглахын оронд боловсруулалтын хүчин чадал эзэмшүүлэх эсэх нь цаашид тэдний шийдвэр юм. Харин зарим функцүүд үргэлж шаардлагатай байдаг, жишээ нь таны дансны тэнцвэрийг олж авах боломжтой.

Судалгааны үр дүн нь [төрөлжсөн](#sorting), [цахим хуудас](#pagination) болон [угаасан](#filters) Тодруулгыг метадаталны товчоор лексикографийн дагуу хийж болно. Уул уурхайн тухайн бүсээс бүрдэх олон төрлийн зарчмаар IP нэвтрүүлэгний хавсралтын загварууд `begins_with` логикийн үйлдлийг ашиглан нэгтгэсэн.

## Taira дээр туршиж үзээрэй. {#try-it-on-taira}

Taira нь нийтлэг нөөцүүдээр JSON дээр зөвхөн уншдаг хайлтын туслагчдыг илрүүлж байна. SDK-ийг дамжуулах өмнө тэдгээрийг хуудасчлах, хариултыг зохицуулахад ашиглах:

```bash
TAIRA_ROOT=https://taira.sora.org

curl -fsS "$TAIRA_ROOT/v1/accounts?limit=3" \
  | jq '{total, ids: [.items[].id]}'

curl -fsS "$TAIRA_ROOT/v1/domains?limit=3" \
  | jq '{total, domains: [.items[].id]}'

curl -fsS "$TAIRA_ROOT/v1/assets/definitions?limit=3" \
  | jq '{total, assets: [.items[] | {id, name, total_quantity}]}'
```

Хэрэглэлийн оношилгоо хийхэд эдгээр дулааны шалгалтыг гарын үсэг зурсан гүйлгээний туршилтуудаас тусгаарлан байлгаарай. Зөвхөн уншдаг асуултын алдаа нь гарын үсгийн хангамж, сүлжээний хүртээмж, эсвэл замын нийцүүлэлээс өмнө гарын үсийг тохируулна.

## Судалгааг бий болгох {#create-a-query}

SDK эсвэл CLI-ийн хэвлэлийн хайлтын бүтээн байгуулагчдыг ашиглах. Жишээ нь, одоогийн мэдээллийн загварын дагуу `FindAccounts` нь жагсаалтын бүртгэлийн бүртгэлд:

```rust
let query = FindAccounts;
```

Энд Алисийн эд хөрөнгийг олох хайлтын жишээ байна:

```rust
let alice_id = load_canonical_account_id_from_client_config()?;
let query = FindAssetsByAccountId::new(alice_id);
```

## Сүрхлэг {#pagination}

Ганцхан асуултууд болон жижиг эргэлтийн асуултуудад `client.request` -ийг ашиглан асуултыг өргөн мэдүүлж, үр дүнг нэг удаа авах боломжтой.

Гэсэн хэдий ч `FindAccounts`, `FindAssets`, эсвэл `FindBlocks` зэрэг өргөн дахин давтагдах асуултууд нь томоохон үр дүнгийн цуглуудыг буцааж чадна.

`Pagination` байгуулахын тулд `client.request_with_pagination(query, pagination)` гэж дууддаг бөгөөд `pagination` нь дараахь хэлбэрээр бүтэдэг:

```rust
let starting_result: u32 = _;
let limit: u32 = _;
let pagination = Pagination::new(Some(starting_result), Some(limit));
```

## Фильтр {#filters}

Та асуултыг бий болгоход зөвхөн тодорхойлсон фильтртэй нийцсэн үр дүнг буцаахын тулд филтрийг ашиглаж болно.

Жишээлбэл, сангийн асуулгыг дансны тодруулгын болон метадэт мэдээллийн дагуу саатуулах боломжтой бол хөрөнгийн асуултыг хөрөнгийн дагуу саатуулж болно. тодорхойлолт, эзэмшигч данс эсвэл доменийн проекц. SDK -ийн түрүүлсэн асуултын бүтээн байгуулагчдыг аль болох ашиглаж, тул фильтр хэлбэр нь хайлтын гарааны хэлбэртэй нийцнэ.

## Тодруулбал {#sorting}

Iroha эд зүйлсийг [металл мэдээлэл](/mn/blockchain/metadata.md) лексикографийн хувьд хайлтын бүтээн байгуулалтын үеэр ангилах ач холбогдол өгч байгаа бол. Эдгээрийн хэрэглээний тохиолдол нь `registered-on` Metadata өгөгдлийн нэвтрүүлэг, энэ нь ангилагдсанаар та дансны бүртгэлийн түүхийг харах боломжийг олгодог.

Тодруулга нь зөвхөн [ метрийн өгөгдлийг ](/mn/blockchain/metadata.md) эзэмшсэн нэгжүүдэд хэрэглэгддэг бөгөөд асуултын үр дүнг тодруулхад метамедианы түлхүүр ашиглагддаг.

Та жагсаалтыг хуудасчилгаа болон филтрүүдтэй нэгтгэж болно. Худалдах нь сонголттой шинж чанар гэдгийг анхаарна уу, хуудасчлалтай ихэнх асуултууд үүнийг шаарддаггүй.
