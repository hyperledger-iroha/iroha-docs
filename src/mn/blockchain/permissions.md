# Зөвшөөрөл {#permissions}

Данснууд блокчэйн дээр янз бүрийн үйлдэл хийхэд зөвшөөрлийн токен хэрэгтэй байдаг, жишээ нь хөрөнгийг гаргах эсвэл устгах.

Олон нийтэд нээлттэй болон хувийн блокчэйнд хэрэглэгчдэд олгогдож буй зөвшөөрлийн хувьд ялгаа байдаг. Олон нийтэд нээлттэй блокчэйнд ихэнх дансууд нэг төрлийн зөвшөөрөлтэй байдаг. Хувийн блокчэйнд ихэнх дансууд нь хамаарах зөвшөөрлийг тодорхой байдлаар олгоогүй бол зөвшөөрөгдсөн эрхийн дагуу ямар нэг зүйл хийж чадахгүй гэж тооцогддог.

Ямар нэгэн зүйлийг хийх зөвшөөрөлтэй байх нь тухайн дансанд түүний зохих зөвшөөрөл байна гэсэн үг юм `Permission`. Зөвшөөрлийг шууд эсвэл дамжуулан олгож болно [`Role`](#permission-groups-roles), эрхийн багцыг нэгтгэх. Эрхийг олгоно `Grant` заавар. Зөвшөөрөл ба үүрэг дуусахгүй; тэдгээрийг авч хаяна уу `Revoke` заавар.

## Өөрт нь зөвшөөрөл өгөх тэмдэг {#permission-tokens}

Баталгаажуулах токенууд нь идэвхитэй гүйцэтгэгчээр тодорхойлогдсон төрөлтэй объектууд юм. Зарим токенууд нь дэлхий даяар хэрэглэгддэг, жишээ нь `CanManagePeers`, зарим нь тодорхой блокчейн бүртгэл объектод хамаардаг, жишээ нь данс, хөрөнгө, хөрөнгийн тодорхойлолт, домэйн, NFT, үүрэг, эсвэл триггер.

Энд төрөл бүрийн зөвшөөрлийн токенуудад ашиглагддаг параметрүүдийн зарим жишээг үзүүлэв:

- Тодорхой дансны метадатыг өөрчлөх зөвшөөрлийг олгодог токен нь `account` гэсэн талбартай ирдэг:

  ```json
  {
    "account": "<AccountId>"
  }
  ```

- Тодорхой хөрөнгийн тодорхойлолтоор хөрөнгийг шилжүүлэх зөвшөөрлийг олгодог токен нь `asset_definition` талбарыг агуулдаг:

  ```json
  {
    "asset_definition": "<AssetDefinitionId>"
  }
  ```

- Дэлхийн түвшний токен болох `CanManagePeers` нь ямар ч талбаргүй:

  ```json
  {}
  ```

### Урьдчилан тохируулагдсан зөвшөөрлийн токенууд {#pre-configured-permission-tokens}

Та [Лавлагаа](/mn/reference/permissions) бүлгээс урьдчилан тохируулсан зөвшөөрлийн токенуудын жагсаалтыг олж болно.

## Зөвшөөрлийн бүлгүүд (Үүрэгүүд) {#permission-groups-roles}

Зөвшөөрлийн багцыг үүрэг гэж нэрлэдэг. Зөвшөөрлийн токенуудын адил үүрэгт `Grant` заавраар олгож, `Revoke` заавраар хүчингүй болгох боломжтой.

Нэг аккаунтод үүрэг олгохоос өмнө эхлээд уг үүргийг бүртгсэн байх ёстой.

Тодорхой үүргүүд нь хэд хэдэн данс ижил эрхийн багцыг авах шаардлагатай үед ашигтай байдаг. Үүргийг нэг удаа бүртгэж, үүрэгт эрх олгож, дараа нь тус бүрийн дансад үүргийг олгох эсвэл цуцлах боломжтой.

### Шинэ үүрэг бүртгүүлэх {#register-a-new-role}

Шинэ үүрэг бүртгэх бөгөөд олгосон тохиолдолд өөр аккаунт Mouse-ийн дансны [мета мэдээлэл](/mn/blockchain/metadata.md)-д нэвтрэх боломжтой болно:

```rust
let role_id = RoleId::from_str("ACCESS_TO_MOUSE_METADATA")?;
let role = iroha_data_model::role::Role::new(role_id.clone(), mouse_id.clone())
    .add_permission(CanModifyAccountMetadata {
        account: mouse_id.clone(),
    });
let register_role = Register::role(role);
```

### Үүрэг олгох {#grant-a-role}

Тухайн үүрэг бүртгэгдсэний дараа, Mouse үүнийг Alice руу олгож болно:

```rust
let grant_role = Grant::account_role(role_id, alice_id);
let grant_role_tx = TransactionBuilder::new(chain_id, mouse_id)
    .with_instructions([grant_role])
    .sign(mouse_private_key);
```

## Өөрчлөлт зөвшөөрөл шалгагчид {#permission-validators}

Зөвшөөрөл нь зөвшөөрлийн токентэй дансууд л хамгаалагдсан үйлдлийг гүйцэтгэх боломжтой байхыг хангахын тулд байдаг. Анхны гүйцэтгэгч нь заавар, асуулт, илэрхийллийн гүйцэтгэлтийн үед зөвшөөрлийг шалгадаг.

Анхдагч баталгаажуулагчийн гадаргууг блокчэйн бүртгэлийн хэсгээр бүлэглэдэг:

- сүлжээний хамтрагчийн удирдлага
- доменууд ба акаунтууд
- хөрөнгүүд, NFTs, ба эскроу
- триггерүүд
- эрх үүрэг болон зөвшөөрөл
- гүйцэтгэгч/байнгын орчин, нотолгоонууд, гүүрүүд, болон SORA/Nexus модульууд

Яг түүний тэмдэгтийн жагсаалт нь [Зөвшөөрлийн Токенуудын лавлагаа](/mn/reference/permissions.md)-д эх сурвалжтай байна.

### програм хангамжийн гүйцэтгэх орчны баталгаажуулагчид {#runtime-validators}

Зөвшөөрлийн шалгалтуудыг идэвхтэй гүйцэтгэгч хэрэгжүүлдэг. Урьдчилсан тохиргоотой гүйцэтгэгч нь суулгасан зөвшөөрлийн шалгагчид болон токений тодорхойлолтуудыг өгдөг бөгөөд сүлжээ нь ашиглаж буй гүйцэтгэгчээ шинэчлэх замаар бодлогыг өөрчилж болно.

Баталгаажуулагчид баталгаажуулалтын дүгнэлт гаргадаг. Баталгаажуулагч нэг үйлдлийг зөвшөөрч болно, шалтгаан зааж татгалзаж болно, эсвэл үйлдэл нь тухайн баталгаажуулагчийн эрхлэх хүрээнээс гадна бол орхиж болно. Сонгогдсон шүүгч эдгээр дүгнэлтийг нэгтгэн заавар, лавлагаа, эсвэл илэрхийлэл цааш үргэлжлэх эсэхийг шийддэг.
