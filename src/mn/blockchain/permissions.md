# Тусгай зөвшөөрөл {#permissions}

Нягтлан бодох бүртгэл нь блокчейн дээр янз бүрийн үйлдлүүдэд зөвшөөрлийн токенүүд хэрэгтэй, жишээ нь хөрөнгийг буулгах эсвэл шатаах.

Олон нийтийн болон хувийн блокчейн хооронд хэрэглэгчдэд олгогдсон зөвшөөрлийн хувьд ялгаа байдаг. Нийтийн блокчейн дээр ихэнх данс ижил зөвшөөрлийн багцтай байдаг. Хувийн блокчейн дээр ихэнх данс нь холбогдох зөвшөөрөлгүй бол тэдэнд олгогдсон эрх мэдлийн гадна юу ч хийж чадахгүй гэж үзэж болно.

Нэг зүйлийг хийх зөвшөөрөлтэй бол тухайн дансанд `Permission` гэсэн үг юм. Тусгай зөвшөөрлийг шууд эсвэл [`Role`](#permission-groups-roles), Энэ нь зөвшөөрлийн цуврал юм. Үйлчилгээний зөвшөөрөл `Grant` заагаар олгодог. Тусгай зөвшөөрөл, үүрэг хугацаа нь дуусгаваргүй бөгөөд `Revoke` заавар хэрэглэн арилгаж болно.

## Тусгай зөвшөөрлийн тэмдэгүүд {#permission-tokens}

Хууль зөвшөөрлийн токенүүд нь идэвхтэй гүйцэтгэгчээр тодорхойлсон төрөлжсөн объектууд юм. Зарим токенүүд дэлхийн хэмжээний байдаг, жишээ нь `CanManagePeers`, бусад нь тухайн номын сангийн объектанд зориулагдсан, жишээлбэл, данс, хөрөнгө, хөрөнгийн тодорхойлолтоор, домен, NFT, үүрэг, эсвэл түлхүүжилт юм.

Энд олон төрлийн зөвшөөрлийн токейн хувьд ашигладаг параметрүүдийн зарим жишээг хүргэж байна:

- Тухайн дансын метадэтгэлийг өөрчлөх зөвшөөрөл олгодог тэмдэгт `account` талбайтай:

  ```json
  {
    "account": "<AccountId>"
  }
  ```

- Тухайн хөрөнгийн тодорхойлолтоор хөрөнгийг шилжүүлэх зөвшөөрлийг олгодог тэмдэг нь `asset_definition` талбайтай:

  ```json
  {
    "asset_definition": "<AssetDefinitionId>"
  }
  ```

- `CanManagePeers` гэх мэт дэлхийн токенд ямар ч талбай байхгүй:

  ```json
  {}
  ```

### Урьдчилсан зөвшөөрлийн токенүүд {#pre-configured-permission-tokens}

Та [Reference](/mn/reference/permissions) бүлэгт урьдчилан тохируулсан зөвшөөрлийн тэмдэгүүдийн жагсаалтыг олох боломжтой.

## Тусгай зөвшөөрлийн бүлэгүүд (роль) {#permission-groups-roles}

Зөвлөлийн цуврал нь үүрэг гэж нэрлэдэг. Зөвлөлийн токейн адил `Grant` заавар ашиглан үүрэг олгож, `Revoke` заавар ашигланып хүчингүй болсонд хүргэж болно.

Ахуйн нэгжэд үүрэг олгохын өмнө тухайн үүргийг хамгийн түрүүнд бүртгэх хэрэгтэй.

Олон данс ижил зөвшөөрөлтэй байх үед дүрүүд ашигтай байдаг. Тус үүргийг нэг удаа бүртгүүлж, тус үүрэгт зөвшөөрөл олгож, дараа нь тухайн бүртгэлд оролцох үүргийг олгоно эсвэл цуцлуулдаг.

### Шинэ үүргийг бүртгүүлэх {#register-a-new-role}

Бид шинэ үүргийг бүртгүүлэх болно, энэ нь олгогдсоны дараа Mouse-ийн дансанд [ метрийн өгөгдлийг ](/mn/blockchain/metadata.md) ашиглах боломжийг бүрдүүлнэ:

```rust
let role_id = RoleId::from_str("ACCESS_TO_MOUSE_METADATA")?;
let role = iroha_data_model::role::Role::new(role_id.clone(), mouse_id.clone())
    .add_permission(CanModifyAccountMetadata {
        account: mouse_id.clone(),
    });
let register_role = Register::role(role);
```

### Хөдөлмөрийг өгөөч {#grant-a-role}

Роль бүртгэгдсний дараа, Маус Алисэд олгох боломжтой:

```rust
let grant_role = Grant::account_role(role_id, alice_id);
let grant_role_tx = TransactionBuilder::new(chain_id, mouse_id)
    .with_instructions([grant_role])
    .sign(mouse_private_key);
```

## Тусгай зөвшөөрлийн баталгаажуулагч {#permission-validators}

Зөвшөөрөл байдаг тул зөвхөн шаардлагатай зөвшөөрлийн тэмдэгт бүхий данс нь хамгаалалттай үйлдлийг гүйцэтгэж болно. Дашрамдсан гүйцэтгэгч заавар, хайл, илэрхийлэл гүйцэтгэх үед зөвшөөрлийг шалгаж байна.

Үндсэн хуулийн баталгаажуулагчийн гадаргуурыг номын сангийн талбайгаар бүлэглэдэг:

- хамтын ажиллагааны удирдлага
- домен, данс
- хөрөнгө, NFTs болон хадгаламж
- түлхүүжүүлэг
- үүрэг, зөвшөөрөл
- гүйцэтгэгч / ажиллуулах цаг, баталгаа, гүүр, SORA/Nexus модул

Тухайн тэмдэгтийн жагсаалтыг [Permission Tokens ](/mn/reference/permissions.md) нэвтрүүлэгт эх үүсвэрээр баталгаажуулсан байна.

### Хөдөлмөрийн цаг хугацааны баталгаажуулагч {#runtime-validators}

Тус зөвшөөрлийн шалгалтыг идэвхтэй гүйцэтгэгч хэрэгжүүлнэ. Төгсөлтийн гүйцэтгэгч нь баригдсан зөвшөөрлийн баталгаажуулагч, токен тодорхойлолт өгдөг бөгөөд сүлжээ хэрэглэж байгаа гүйцэтгчийг шинэчлэх замаар бодлогыг өөрчилж чадна.

Хяналт шалгагч нь баталгаажуулах шийдвэрийг буцааж өгдөг. Хэрэв үйл ажиллагаа нь энэ баталгаажуулагчийн хүрээний гадна байгаа бол үйлдлийг зөвшөөрөх, үндэслэлээр үгүйсгэх эсвэл орхих боломжтой. Сонгон сонгогдсон шүүгч эдгээр шийдвэрийг нэгтгэж заавар, асуулт, илэрхийлэл үргэлжлэх эсэхийг шийдвэрлэж болно.
