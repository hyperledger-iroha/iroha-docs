# Үргэлт үүсгэгч жишээ {#event-trigger-example}

Энэ жишээ нь Canonical domainless бүртгэл ашигладаг IDs болон төлөвлөсөн хөрөнгө
Хэвлэл Iroha 3 Мэдээллийн загвар.

Сүлжээ нь:

- Алисийн цөмөөр хяналт тавих санхүүгийн бүртгэл
- Мэдээгүй шатарчны цөмөөр хяналт тавьсан санхүүгийн захирал
- хөрөнгийн тодорхойлолтыг: `tea` доор `wonderland.universal`
- тухайн хөрөнгийн үлдэгдэл

Зорилго нь Алисийн цайны тэнцвэрт байдлыг ажиглаж байгаа учрыг бүртгэх явдал юм
нийлүүлэх мэдээллийн үйл явдлын дараа Mad Hatter-ийн дансны хуралдаанаас шилжүүлэн суулгана
нэвтрүүлсэн.

## 1. Санхүүжилт, хөрөнгө боловсруулах {#_1-prepare-accounts-and-assets}

Үүнд оролцох бүртгэл болон хөрөнгө тодорхойлолт анх бүртгэнэ.
одоогийн Iroha, данс IDs Санхүүжилтийн хяналтын ажилтнуудаас
домен ашиглах `domain.dataspace` хэлбэр:

```text
domain: wonderland.universal
asset definition projection: tea in wonderland.universal
holder accounts: AccountId(controller=alice_key), AccountId(controller=mad_hatter_key)
```

Ашигт малтмалын тодорхойлолт нь өнөөг хүртэл ногоон хаягийг эзэмшдэг.
бүртгэл хийсний дараах хаягийг ашиглаж, үйл ажиллагааг эхлүүлэхэд ашиглана.

## 2. Тэгжигч байгууллага сонгох {#_2-choose-the-trigger-authority}

Урьдчилгааны техникийн дансыг боломжийн тохиолдолд зориулсан дансанд тохируулна.
нэвтрүүлэг хийхэд ямар зөвшөөрөл шаардагдах вэ
гүйцэтгэх, хөдөлгөөнчдийн хувийн гарын үсэгт холбогдох хэрэгслийг холбохгүй
Хүйц.

Техникийн сан нь аль хэдийн бий байх ёстой бөгөөд
Тэгнэгч гүйцэтгэхэд заасан.

## 3. гүйцэтгэхэд тодорхойлох {#_3-define-the-executable}

Хөдөлмөрийн гүйцэтгэх нь үйл явдлын дараалал
Энэ жишээний хувьд нэг дамжуулалттай:

```text
Transfer(
  source = AssetId(tea_definition, mad_hatter_account),
  value = Numeric(1),
  destination = AssetId(tea_definition, alice_account)
)
```

Хөдөлмөрийн SDK Одоогийн хэрэглээний ачаалалтай бүтээн байгуулалтын гүйцэтгэгчид .
Хөгжилтэй хуучин текст IDs түлхүүрний код; шалгалт эсвэл хайлын санхүүжилт IDs
гүйцэтгэгчийг бүтээхийн өмнө.

## 4. үйл явдлын филтр тодорхойлох {#_4-define-the-event-filter}

Мэдээллийн үйл явдлын филтр ашиглан үйл явдлыг та сонирхож буй зүйл рүү хязгаарлах:

```text
EventFilterBox::Data(
  DataEventFilter for asset changes involving
  AssetId(tea_definition, alice_account)
)
```

Сэтгэвчийг практиктайгаар тодорхой болгомоо. `AcceptAll` фильтр нь
алдаа гаргах, гэхдээ энэ нь бүх тохируулалт үйл явдлыг төлөх зардал
үнэлгээ.

## 5. Тэгчийг бүртгүүлэх {#_5-register-the-trigger}

Тэгчийг:

- хонгор `TriggerId`
- гүйцэтгэх заалын дараалал
- `Repeats::Indefinitely` эсвэл `Repeats::Exactly(n)`
- техникийн тайлан
- үйл явдлын филтр
- сонголттой метабараа

Триггер бүртгэл нь өөрөө хэвийн бүтээн байгуулалтын нэг юм.
Эрдэм шинжилгээний байгууллагаас мэдээллийн хэрэгслийн
Тэгжер гүйцэтгэхэд шаардлагатай зөвшөөрөл.

## Эрүүгийн шийдвэр гаргах тушаал {#execution-order}

Блок гүйцэтгэхдээ:

1. Эхэндээ хэвийн гүйлгээний заавар хэрэглэдэг.
2. Энэ чиглэлээр үүссэн үйл явдлын мэдээллийг цуглуулдаг.
3. Эдгээр үйл явдлын дараах филтр нь тохиромжтой.
4. Триггерээс үүссэн үр дагаврыг блок гүйцэтгэх урсгалд
   хязгааргүй рекурсив үүсгэгчийг гүйцэтгэх боломжийг олгодог.

Тэгзер ашиглалтанд орсон тохиолдолд `Repeats::Exactly(n)`, тоолсон үед шинэ гараа нэвтрүүлнэ
Энэ нь маш их хэрэгцээтэй.
