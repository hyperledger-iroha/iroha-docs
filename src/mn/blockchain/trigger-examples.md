# Үйлдвэрийн үүсгэгч жишээ {#event-trigger-example}

Энэ жишээ нь Iroha 3 өгөгдлийн загварын IDs доменгүй сангийн санхүүжилт болон урьдчилсан хөрөнгийн тодорхойлолт ашигладаг.

Сүлжээний:

- Алисийн цөмөөр хяналт тавьсан санхүүгийн бүртгэл.
- Crazy Hatter's Key-ийн удирдлагаар зохиогдох санхүүгийн мэдээ
- `wonderland.universal` дэргэдэх `tea` гэж төлөвлөсөн хөрөнгийн тодорхойлолт
- тухайн сангийн хадгаламжийн үлдэгдэл

Зорилго нь Алисийн цайны тэнцвэрт байдлыг ажиглаж, нийцсэн мэдээллийн үйл явдлыг гаргахдаа галзуу шатарны дансны хуралдаанаас шилжүүлэн суулгах үйлдлийг бүртгэх явдал юм.

## 1. Нягтлан бодох бүртгэл, хөрөнгийг бэлтгэх {#_1-prepare-accounts-and-assets}

Эхлээд оролцогч дансыг болон хөрөнгийн тодорхойлолтыг бүртгүүлэх. одоогийн Iroha-д IDs-ийн данс нь дансны хяналтын ажилтнуудаас ирдэг бөгөөд төлөвлөөд буй доменүүд `domain.dataspace` хэлбэрийг ашигладаг:

```text
domain: wonderland.universal
asset definition projection: tea in wonderland.universal
holder accounts: AccountId(controller=alice_key), AccountId(controller=mad_hatter_key)
```

Ашигт малтмалын тодорхойлолт нь өнөөг хүртэл хуулиар заасан үл ил тод хаягийг эзэмшдэг. Энэ хаягийг бүртгэл хийсний дараа хадгалах эсвэл асууж, түлхэц үйлдэлд ашиглана.

## 2.Эрүүлэгч байгууллагыг сонгох {#_2-choose-the-trigger-authority}

Тагварын техникийн дансыг боломжтой бол зориулсан дансанд тохируулна. Тус данс нь тагварын гүйцэтгэхэд ямар зөвшөөрөл шаардагдах талаар тодорхой болгодог бөгөөд тагварыг операторын хувийн гарын үсэг зурах товчтой холбохгүй байна.

Техникийн сан нь аль хэдийн бий байх ёстой бөгөөд заавар сурталчилгааг гүйцэтгэхэд зөвшөөрөлтэй байх ёстой.

## 3. гүйцэтгэхэд тодорхойлох {#_3-define-the-executable}

Хөдөлмөрийн хэрэгсэл нь үйл явдлын филтр тохиромжтой байх үед хөдөлгөөнч дамжуулдаг заавар шугам юм. Энэ жишээний хувьд энэ нь нэг шилжүүлэн суулгах:

```text
Transfer(
  source = AssetId(tea_definition, mad_hatter_account),
  value = Numeric(1),
  destination = AssetId(tea_definition, alice_account)
)
```

эцсийн гүйлгээний ашигтай ачаалал хийхэд SDK -ийн одоогийн хэвлэлийн бүтээн байгуулагчдыг ашигла. Хөгжилтийн код дээр хуучин текст IDs-ийг хатуу кодлохоос урьдчилан сэргийлэх; гүйцэтгэгчийг бүтээхийн өмнө шинжилгээ эсвэл асуултын санхүүжилт IDs -ийг ашигла.

## 4. үйл явдлын филтр тодорхойлох {#_4-define-the-event-filter}

Мэдээллийн үйл явдлын филтр ашиглан үйл явдлыг та сонирхож буй объектт хязгаарлах:

```text
EventFilterBox::Data(
  DataEventFilter for asset changes involving
  AssetId(tea_definition, alice_account)
)
```

`AcceptAll` фильтр нь хяналт тавихын тулд ашигтай боловч тохируулалтын бүх үйл явдлыг эхлүүлэх үнэлгээний зардлыг төлөх болно.

## 5. Тэгчийг бүртгэнэ. {#_5-register-the-trigger}

Үргэлтгээ:

- `TriggerId`
- гүйцэтгэх үүргийн дараалал
- `Repeats::Indefinitely` эсвэл `Repeats::Exactly(n)`
- Техникийн сан
- үйл явдлын филтр
- сонголттой метабаярууд

Триггер бүртгэл нь өөрөө хэвийн гүйлгээ юм, тиймээс бүртгэх данс үүсгэгчийг бүртгэх зөвшөөрөл шаарддаг. Техникийн данс нь үүсгэгчийн гүйцэтгэхэд шаардагдах зөвшөөрлийг шаардаж байна.

## Эрүүл мэндийн тушаал {#execution-order}

Блокийн гүйцэтгэхэд:

1. Ер нь хэвийн гүйлгээний заавар хэрэглэдэг.
2. Эдгээр чиглэлээр үүссэн үйл явдлын мэдээллийг цуглуулдаг.
3. Тухайн үйл явдлуудтай нийцсэн фильтрүүд үүсгэгддэг.
4. Триггерээс үүссэн үр дагаврыг блок гүйцэтгэх урсгалд хязгааргүй рекурсив үйл ажиллагаа явуулах боломжийг олгохгүйгээр зохицуулж байна.

Хэрэв түймэр `Repeats::Exactly(n)` -ийг ашигладаг бол тоог дуусч, мөн адил үйлдлийг дахин хийхэд шинэ түймрийг бүртгүүлээрэй.
