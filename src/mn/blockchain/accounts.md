# Санхүүжилт {#accounts}

Санхүүжилт бол бүтээн байгуулалтын гарын үсэг зурах, өөрийн томоохон бүртгэлийн байдлаа илэрхийлэх эрх мэдэл юм. Одоогийн Iroha 3 мэдээллийн загварын хувьд `AccountId` нь каноник бөгөөд доменгүй байдаг: энэ нь дансны хяналтын ажилтангаас үүдэлтэй бөгөөд I105 гэж хуулиар кодлагдсан байна. Хүний уншдаг домен, өгөгдлийн орчны хүрээлэнг нь тусгаарлан бүртгэл-аяар холбогдсон байна.

## Структура {#structure}

бүртгэгдсэн `Account` нь:

- `id`: `AccountId` хуулийн дагуу
- `metadata`: үл хөдлөх хөрөнгийн санхүүжилтийн өгөгдөл
- `label`: сонголттой тогтвортой цогцолбор
- `uaid`: Nexus урсгалд зориулсан сонголттой "Универсалтын данс ID"
- `opaque_ids`: Сангийн UAID бүртгэлтэй холбогдсон ил тод тодорхойлолтууд

Акаунтыг бий болгохын тулд хэрэглэгддэг гүйлгээний ашигтай ачаалал нь `NewAccount`. Энэ нь бүртгэгдсэн дансанд ашиглагддаг ижил тодорхойлолт, метабарууд, тэмдэглэл, UAID болон ил тод ID талбайдыг агуулсан байна.

`uaid` Canonical-ийг нэмнэ `AccountId`; Энэ нь түүнийг солихгүй. Nexus үйлчилгээний хэрэглэгчийн эсвэл байгууллагын тогтвортой хяналт нь мэдээллийн талбайд, хувийн хэвшлийг хадгалах бүртгэл шаарддаг. Хөдөлмөрийн цаг хугацаа нь нэгээс нэг UAID-сэтгэлэгт бүртгүүлэх индекс, ил тод тодорхойлогчдыг UAID, болон дубликат эсвэл зөрчигдсөн ил тод тодорхойлогчдыг үгүйсгэнэ. [FHE болон UAID](/mn/blockchain/sora-nexus-services.md#fhe-and-uaid) . Nexus үйлчилгээний давхаргын урсгал.

## Нягтлан бодох бүртгэлийн удирдлагууд {#account-controllers}

Хяналтын ажилтан нь бүртгэлийн үйл ажиллагааг хэрхэн зөвшөөрдөг вэ гэдгийг тодорхойлдог. Дашрамд клиент урсгал Ed25519 товчооны хосууд ашигладаг боловч мэдээллийн загвар нь олон гарын үсэг бодлогын хяналтын тоног төхөөрөмж гэх мэт илүү баялаг хяналтчдыг дэмжиж байна.

Клиентын конфигурац нь гарын үсэг зурах эрх мэдлийг ижил төстэй конфигурацыос тусгаарлан хадгалдаг:

```toml
[account]
public_key = "ed0120..."
private_key = { digest_function = "ed25519", payload = "..." }
```

[клиентын конфигурацыг](/mn/guide/configure/client-configuration.md) болон [ний түлхүүр үйлдвэрлэлийг](/mn/guide/security/generating-cryptographic-keys.md) одоогийн түлхүүдийн хэлбэрээр үзнэ үү.

## Taira дээр туршиж үзээрэй. {#try-it-on-taira}

Олон нийтийн Taira шалгалтын сүлжээний IDs хэд хэдэн санхүүгийн мэдээллийг жагсаарай:

```bash
curl -fsS 'https://taira.sora.org/v1/accounts?limit=5' \
  | jq -r '.items[] | [.id, (.primary_alias // "-")] | @tsv'
```

Сангийн хөрөнгийг шалгахын тулд эхний дуудлагаас ID дансыг нунтаглаж, замаар нэвтрүүлэхээс өмнө URL кодлаарай. Энэ Python дүгнэлт нь эхний бүртгэгдсэн дансны хувьд үүнийг хийдэг:

```bash
python3 - <<'PY'
import json
import urllib.parse
import urllib.request

root = "https://taira.sora.org"
accounts = json.load(urllib.request.urlopen(f"{root}/v1/accounts?limit=1"))["items"]
account_id = accounts[0]["id"]
encoded = urllib.parse.quote(account_id, safe="")
assets = json.load(
    urllib.request.urlopen(f"{root}/v1/accounts/{encoded}/assets?limit=5")
)

print(json.dumps({"account_id": account_id, "assets": assets["items"]}, indent=2))
PY
```

Энэ нь олон нийтийн уншилт юм. Акаунтыг бий болгох эсвэл шинэчлэх нь гарын үсэг зурсан гүйлгээ бөгөөд Taira-ийн төхөөрөмжээр санхүүжүүлсэн [ байгууламжийг шаарддаг SORA Nexus-ийн мэдээллийн газарт холбогдох ](/mn/get-started/sora-nexus-dataspaces.md).

## Бүртгэл, зөвшөөрөл {#registration-and-permissions}

Нягтлан бодох бүртгэл нь [`Register` болон `Unregister`](/mn/blockchain/instructions.md#un-register) чиглэлээр бүртгэгддэг бөгөөд бүртгэлгүй байдаг.

Та бүртгэлтэй болсны дараа:

- гүйлгээний гарын үсэг
- хөрөнгийг хадгалах
- өөрийн доменүүд
- үүрэг гүйцэтгэх болон зөвшөөрлийн тэмдэгүүдийг хүлээн авах
- хадгалах метабараа
- тухайн шинж чанарууд хүчинтэй бол Nexus тодорхойлолт, рекей, нөхөн сэргээлтийн урсгалд оролцох

## Хууль зүйн асуудлыг шийдвэрлэх {#troubleshooting-identity-issues}

Хэрэв гүйлгээг гэнэтийн байдлаар татгалзсан бол:

- үйлчлүүлэгчдийн олон нийтийн түлхүүр нь гарын үсэг зурахад ашигласан хувийн түлхэнд нийцдэг.
- Санхүүжилт нь эх үүсвэрт бүртгэгдсэн эсвэл үүрэг гүйцэтгэсэн гүйлгээгээр хийгдсэн
- байгууллага нь зааварчилсан дагуу зөвшөөрөлтэй
- "Strict account" талбайд I105 санхүүгийн ID дансыг ашигладаг бол уншигдах нэрүүд нь идэвхтэй дансны нууц үсэгээр холбогддог.
