# Суурилуулалтын асуудлыг шийдвэрлэх {#troubleshooting-installation-issues}

Энэ хэсэг нь Iroha 3 суулгах талаар асуудлыг шийдэх зөвлөмжийг санал болгодог. Хэрэв та тулгарч буй асуудал энд дурдагдаагүй бол бидэнтэй [Телеграм](https://t.me/hyperledgeriroha) хаягаар холбогдоно уу.

## Хурдан шалгалтууд {#quick-checks}

Төлөвлөсөн суурилуулалтын ихэнх бүтэлгүйтэл дөрвөн газраас нэгэнд үүсдэг:

- дээрх ажлын орчныг тодорхойлсон хувилбараас хуучин Rust хэрэгслийн гинжин
- `cargo` эсвэл `rustc` нь `rustup`-оос өөр суулгалт руу чиглэж байна
- C компилятор, `pkg-config` эсвэл CMake зэрэг системийн бүтээх хэрэгслүүд дутагдаж байна
- эх сурвалжийн хувилбаруудыг өөрчлөхөд хуучирсан үүсгэсэн хэсгүүд эсвэл локал бүтээлийн гаралт

Iroha эх кодын ажиллаж байгаа хувилбараас эхлэн:

```bash
rustup show
cargo --version
rustc --version
cargo metadata --no-deps
```

Хэрэв `cargo metadata` амжилтгүй болбол, `pnpm refresh:iroha --source /path/to/iroha`-ийг ажиллуулахын өмнө орон нутгийн хэрэгслийн гинжлэлийг зас, учир нь шинэчлэх үед одоогийн өгөгдлийн загварын схемийг үүсгэхийн тулд Kagami-г дуудаж болно.

## Алдаа шийдвэрлэх Rust Багцын хэрэгсэл {#troubleshooting-rust-toolchain}

Заримдаа, зүйлс төлөвлөсөн ёсоор болохгүй байдаг. Ялангуяа хэрвээ та өмнө нь системдээ `rust` суулгасан боловч шинэчилээгүй бол. Үүнтэй төстэй асуудал Python-д ч гарч болох юм: XKCD нь үүний ямар байж болохын нэрд гарсан жишээг харуулдаг:

### Rust хувилбарыг шалгана уу {#check-rust-version}

Таны болон бидний хэвийн байдлыг хадгалахын тулд, `cargo`-ын зөв хувилбарыг `rustc`-ын зөв хувилбартай хослуулсан эсэхээ шалгаарай. Одоогийн upstream ажлын орчин `rust-version = "1.92"`-ыг зарлаж, `rust-toolchain.toml`-д хэрэгслийн сувгийг тогтоосон байна. Хувилбаруудыг харуулахын тулд,

```bash
$ cargo -V
$ cargo 1.93.1 (...)
```

тэгээд

```bash
$ rustc --version
$ rustc 1.93.1 (...)
```

Хэрэв танд өндөр хувилбарууд байгаа бол та асуудалгүй. Хэрэв танд доод хувилбарууд байгаа бол үүнийг шинэчлэхийн тулд дараах командыг ажиллуулж болно:

```bash
$ rustup toolchain update stable
```

### Суурилуулах байршлыг шалгах {#check-installation-location}

Хэрвээ та доод хувилбарын тоог авсан бол, багажын гинжийг шинэчилсэн боловч ажиллахгүй байсан бол… үүнийг нийтлэг асуудал гэж хэлж болно, гэхдээ үүнд нийтлэг шийдэл байдаггүй.

Юуны өмнө та ашиглахыг хүсэж буй хувилбар хаана суулгагдсан болохыг тогтоох ёстой:

```bash
$ rustup which rustc
$ rustup which cargo
```

Хэрэглэгчийн гарын авлагын оруулсан хэрэгслийн сүлжээ нь ихэвчлэн `~/.rustup/toolchains/stable-*/bin/` дээр байдаг. Хэрэв ийм тохиолдол гарвал та ажиллуулж чадах ёстой

```bash
$ rustup toolchain update stable
```

энэ нь таны асуудлыг шийдэж өгөх ёстой.

### Өгөгдсөн Rust хувилбарыг шалгана уу {#check-the-default-rust-version}

Өөр нэг боломж нь шинэчилсэн `stable` toolchain суусан боловч анхдагчаар сонгогдоогүй байх явдал юм. Дараахыг ажиллуулна:

```bash
$ rustup default stable
```

Дараах байдлаар `nightly` хувилбарыг суулгана эсвэл тодорхой Rust хувилбарыг тохируулахад, дараа нь үүнийг арилгахгүй бол энэ асуудал үүсч болно.

### Бусад Rust хувилбарууд байгаа эсэхийг шалга {#check-if-there-are-other-rust-versions}

Алдаа оношлох асуудлын нүхээр үргэлжлүүлэн ороход, бидэнд shell alias-ууд байж болно:

```bash
$ type rustc
$ type cargo
```

Хэрэв эдгээр нь `rustup which *`-ийг ажиллуулж байх үед та харсан байршлаас өөр байршлуудыг зааж байвал, танд асуудал үүсчээ. Иймэрхүү нэрийн өөр хувилбаруудыг нэмэх нь хангалтгүй гэдгийг анхаарна уу:

```bash
$ alias rustc "~/.rustup/toolchains/stable-*/bin/rustc"
$ alias cargo "~/.rustup/toolchains/stable-*/bin/cargo"
```

Дотоод логик нь таны шеллийн овог нэрийг хэрхэн зохицуулсан ч гэсэн алдагдаж болно.

Хамгийн энгийн шийдэл нь та ашигладаггүй хувилбаруудыг устгах явдал байх болно.

Гэхдээ энэ нь хэлэхээсээ хялбар биш, учир нь энэ нь таны суулгасан ба ашиглах боломжтой rustup-ийн бүх хувилбаруудыг хянах шаардлагатай гэсэн үг юм. Ихэвчлэн зөвхөн хоёр байдаг: системийн багц удирдагчийн хувилбар ба энэ семинарын эхлэлийн командыг ажиллуулсан үед таны гэрийн хавтасны стандарт байршилд суулгасан хувилбар. Эхнийхэд нь таны (Linux) тархацын гарын авлагыг үзнэ үү, (`apt remove rust`). Хоёр дахь хувилбарын хувьд, ажиллуулна уу:

```bash
$ rustup toolchain list
```

Тэгээд дараа нь, бүх `<toolchain>` бүрийн хувьд (мэдээж өнцөгийн хаалтуудыг оролцуулахгүй):

```bash
$ rustup remove <toolchain>
```

Төхөөрөмжийн сүлжээг устгасны дараа энэ команд нь command-not-found гэсэн алдааг харуулах ёстой:

```bash
$ cargo --help
```

Тэр алдаа идэвхтэй Rust хэрэгслийн сүлжээ суулгагдаагүй байгааг баталж байна. Дараа нь гүйцэтгэнэ үү:

```bash
$ rustup toolchain install stable
```

## Алдаа шийдвэрлэх Python хэрэгслийн гинж {#troubleshooting-python-toolchain}

[Python хэрэглэгчийн тохиргоо](/mn/guide/tutorials/python.md) үед pip ашиглан Python Wheel багцыг суулгах үед та дараах алдаатай тулгарч магадгүй: "iroha_python-*.whl энэ платформ дээр дэмжигдсэн дугуй биш юм".

Энэ алдаа нь pip хуучирсан гэсэн утгатай бөгөөд үүнийг шинэчлэх шаардлагатай болно. Юуны түрүүнд, таны OS-ийг шинэчлэлтүүдийн хувьд шалгаж, системийг шинэчлэхийг зөвлөж байна.

Хэрэв энэ ажиллахгүй бол, та хэрэглэгчийн лавлахынхаа `pip`-г шинэчлэхийг оролдож болно.

`python -m pip install --upgrade pip`

Таны гэрийн хавтсанд суусан `pip` байгаа эсэхийг шалгаарай. Үүнийг хийхийн тулд `whereis pip`-г ажиллуулж, `/home/username/.local/bin/pip` замуудын дунд байгаа эсэхийг шалгаарай. Хэрэв үгүй бол, таны shell-ийн `PATH` хувьсагчийг шинэчил.

Хэрэв асуудал үргэлжилвэл, [бидэнтэй холбоо барих](/mn/help/) хийх ба үр дүнгүүдийг тайлагнах уу.

```
python --version
python3 --version
pip --version
pip3 --version
```
