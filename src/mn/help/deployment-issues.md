# Хөдөлмөрийн хэрэгслийн асуудлыг шийдвэрлэх {#troubleshooting-deployment-issues}

Энэ хэсэг нь Iroha 3 нэвтрүүлэгний асуудал шийдэх зөвлөмжүүдийг санал болгодог. Хэрэв та дурдаж буй асуудлыг энд тодорхойлж чадахгүй бол [Telegram](https://t.me/hyperledgeriroha)-ээр бидэнтэй холбоо бариарай.

## Бүтээгдсэн артефактоор эхлээрэй {#start-with-generated-artifacts}

Орон нутгийн болон шинжилгээний хэрэглээнд Kagami нь бүтээсэн артефактыг гарын үсэгээр бичигдсэн ижил төстэй файлуудын оронд сонгох хэрэгтэй:

```bash
cargo run --bin kagami -- localnet --build-line iroha3 --peers 4 --out-dir ./localnet
```

Бүтээгдсэн захиалга нь Iroha 3 бүтээн байгуулалтын шугамд өрсөлдөгчдийн тохируулалт, генезисийн материал, эхлүүлэх скриптүүд болон README-ийг бүрдүүлдэг.

## Дундах нь эхлэхгүй {#peer-does-not-start}

Хамгийн түрүүнд эдгээр зүйлсийг шалгаарай:

- `irohad --config <path>` баримт нь ижил хүйстний TOML файл дээр байдаг.
- `public_key` болон `private_key` нь ижил төстэй түлхүүрний хосууд юм.
- `genesis.public_key` нь генезис бүтээн байгуулалтын гарын үсэг зурахад ашигласан түлхэцтэй нийлж байна.
- баталгаажуулагч өрсөлдөгчний тодруулгыг BLS-Нормаль түлхүүр ашигладаг бөгөөд `trusted_peers_pop` нь орон нутгийн түлхүүн болон итгэмжлэгдсэн өрсөлөгчдийн эзэмшлийн гэрчилгээний бүртгэлтэй байдаг.
- Torii болон P2P-ийн боомтууд нь аль хэдийн өөр үйл явцтай холбоотойгүй.
- Kura дэлгүүрний сүлжээ нь ижил зангилаар хамаарагддаг бөгөөд өөр сүлжээний профилээс дуулдаггүй юм.

Daemon нь нэгээс илүү TOML шатыг уншдаг бол конфигуратын байцаах системийг ашигла:

```bash
cargo run --bin irohad -- --config ./config.toml --trace-config
```

## Docker болон Композит {#docker-and-compose}

Урьдчилсан Kagami локаль сүлжээний өнөөгийн өгөгдлийг бүрдүүлэн командын шугамын аргумент, конфигурацийн файлууд шалгарсан кодтой нийцүүлнэ:

```bash
cargo run --bin kagami -- localnet --build-line iroha3 --peers 4 --out-dir ./localnet
cargo run --bin kagami -- docker --peers 4 --config-dir ./localnet --image hyperledger/iroha:dev --out-file ./localnet/docker-compose.yml --force
docker compose -f ./localnet/docker-compose.yml up
```

Хэрэв Composite-ийн хэрэглээг эхлүүлж, дараа нь зогсоосон бол:

- үл нийцсэн `chain`
- янз бүрийн генезис транзакцын эсвэл манифестийг ашиглаж байгаа нэгэн ижил төстэй
- P2P хаяг нь зөвхөн контейнерийн сүлжээний дотор ажилладаг байна
- генез нөхөн сэргээлтийн дараа орон нутгийн хэмжээний дахин ашиглах

Шинэ генезисыг шинээр туршиж үзэхэд, хуучин Kura томоохон хэсгийг дахин эхлүүлэхээс өмнө хасах хэрэгтэй.

## Кубернетис {#kubernetes}

Kubernetes-ийн хувьд аль нэг баталгаажуулагчаар улс төрийн бүтэц гэж үзнэ үү:

- аль алинд нь тогтвортой тодруулгын түлхүүр, тогтвортой хэвтлийн хэмжээг өгөх
- P2P хаяг нь бусад өрсөлдөгчид цувралны дотоод хэсгээр шийдэх боломжтой
- нэвтрүүлэг хийхэд өөрчлөх боломжгүй конфигурац болон генезис файлуудыг монтаж
- бүх генезис болон топологийн өөрчлөлтийг автомат шинэчлэх хэлбэрээр бус сайн дураараа оруулна.

Хэрэв модуль хэд хэдэн удаа сэргээгдвэл, модулийн дүрслэгдсэн конфигуралыг [`peer.template.toml`](/mn/reference/peer-config/index.md#template) хүлээлттэйтэй харьцуулж, ижил төстэй нь хуучны Kura мэдээллийг дахин тоглож байгаа эсэхийг шалгаарай.

## Сорагийн хувилбар {#sora-profile}

Iroha 3 ашиглаж байгаа хэрэгслийн Nexus, SoraFS, эсвэл олон замын урсгал нь Sora хувилбарыг ашиглаж, Daemon-ийг эхлүүлэх ёстой:

```bash
cargo run --bin irohad -- --config ./config.toml --sora
```

Нэг л сүлжээний баталгаажуулагчдын хооронд ижил профилийг тогтмол ашиглах.
