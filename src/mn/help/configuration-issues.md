# Тохиргооны асуудлыг шийдвэрлэх {#troubleshooting-configuration-issues}

Энэ хэсэг нь Iroha 3 тохиргооны алдааг оношлох зөвлөмжүүдийг санал болгодог. Юуны түрүүнд [түлхүүрүүдийг шалгасан](./overview.md#check-the-keys)-ыг хийхийг баталгаажуулна уу, учир нь энэ нь Iroha-д гардаг хамгийн нийтлэг асуудлын эх үүсвэр юм.

Хэрэв та тулгарч буй асуудал энд тодорхойлогдоогүй бол [Телеграм](https://t.me/hyperledgeriroha) хаягаар бидэнтэй холбогдоно уу.

## Docker Compose тохиргоонд хуучирсан блокчэйн үүсгэл {#outdated-genesis-on-a-docker-compose-setup}

Та Iroha-ын Docker Compose хувилбарыг ашиглаж байхдаа сүлжээний нэг хөрш контейнер `Failed to deserialize raw genesis block` алдаатай хүчин чадалгүй болох асуудалтай тулгарах боломжтой. Энэ нь ихэвчлэн сүлжээний хамтрагч, гарын үсэг зурсан блокчэйн-эхлэл гүйлгээ, болон үүсгэсэн тохиргоог өөр өөр Iroha хувилбарууд эсвэл профайлуудаар үйлдвэрлэсэн гэсэн үг юм.

Алдааг дараах алхмуудаар шалгана уу:

1. Одоогийн савыг шалгахын тулд `docker ps` ашигла. Үлдсэн профайлын дагуу та ихэвчлэн `hyperledger/iroha:dev` савуудыг харах болно. Анхдагч Docker Compose профайл нь дөрвөн сүлжээний ижил түвшний савыг агуулдаг боловч таны үүсгэсэн `docker-compose.yml` ялгаатай байж болно.

2. Тэмдэглэлүүдийг шалгаж, `Failed to deserialize raw genesis block` алдааг хайна уу. Хэрэв та Iroha-ыг `docker compose up -d`-тай daemon горимд эхлүүлсэн бол `docker compose logs` командыг ашиглана уу.

Ийм асуудлыг шийдвэрлэх арга Iroha-ийн хэрэглээнээс хамаарна. Хэрэв энэ нь энгийн демо бөгөөд та сүлжээний түншийн өгөгдлийг хадгалах шаардлагагүй бол Kagami-оор нийцэж буй localnet эсвэл Docker Compose багцыг дахин үүсгээрэй:

```bash
cargo run --bin kagami -- localnet --peers 4 --out-dir ./localnet
cargo run --bin kagami -- docker --peers 4 --config-dir ./localnet --image hyperledger/iroha:dev --out-file ./docker-compose.yml
```

Дараа нь хуучин контейнерын төлөвийг устгаж, дахин үүсгэсэн `genesis.signed.nrt`, сүлжээний түнш `config.toml` файлууд, ба `client.toml`–аас дахин эхлүүлнэ үү.

Хэрэв та Iroha тохиолдлын өгөгдлийг сэргээх шаардлагатай бол дараах зүйлийг хийгээрэй:

1. Эхний (амжилтгүй болсон) сүлжээний хамтрагчаас өгөгдлийг хуулбарлах хоёр дахь Iroha сүлжээний хамтрагчийг холбох.
2. Шинэ сүлжээний хамтрагчийг анхны сүлжээний хамтрагчтай өгөгдлийг синхрончлохыг хүлээнэ үү.
3. Шинэ сүлжээний хамтрагчийг идэвхитэй орхино уу.
4. Анхны сүлжээний хамтрагчийн блокчейн үүсгэл ба тохиргооны файлуудыг зөвхөн зохицуулсан шилжилтийн хүрээнд шинэчилнэ үү.

::: info

Амьд сүлжээнд блокчейн үүсгэлтийг солих ерөнхий автомат дахин бичлэлийн зам байдаггүй. Үүнийг зохицуулалттай шилжилт гэж үз: хуучин төлөв байдлыг хадгалж, нийцтэй сүлжээний хамтрагчдыг ажиллуулж, операторууд шилжилтийн төлөвлөгөөн дээр санал нэгдсэний дараа зөвхөн баталгаажуулагчдыг шинэ тохиргоо руу шилжүүл.

:::

## Хувийн болон олон нийтийн түлхүүрийн олон нэвтрүүлгийн формат {#multihash-format-of-private-and-public-keys}

Хэрэв та [клиент тохиргоо](/mn/guide/configure/client-configuration.md)-ийг харвал, тэнд буй товчнууд нь [олон хэш формат](https://github.com/multiformats/multihash)-д өгөгдсөн болохыг анзаарна.

Хэрэв та өмнө нь олон хэштэй ажиллаж үзээгүй бол баруун тал нь түлхүүрийн байтын арван зургаан талт илэрхийлэл биш гэж таамаглах нь хэвийн. байт), харин ASCII (эсвэл UTF-8) хэлбэрээр кодлогдсон байтуудыг, мөн хоёр дахь `public_key` ба `private_key` үүсгэлтэд тэмдэгт мөрөн дээр `from_hex`-г дуудах.

Стрингийн литералыг дээр `PrivateKey::try_from_str` гэж дуудахад зөвхөн зөв түлхүүрийг өгөх нь мөн л байгалийн арга гэж үзэх нь ойлгомжтой. Тэгэхээр хэрэв та түлхүүрийн битийн тоог буруу авбал, жишээ нь 32 байттай харьцуулбал 64, энэ нь алдааны мессеж гаргах болно.

Эдгээр хоёр таамаглал буруу байна. Харамсалтай нь, алдааны мэдэгдлүүд энэ төрлийн бүтэлгүйтлийг оношлоход туслахгүй байна.

Яаж засах вэ: `hex_literal` ашиглана уу. Энэ нь бас муухай тэмдэгтүүдийн цувааг тодорхой_HEX_ тоонуудын жижиг хүснэгт болгож хувиргана.

::: warning

Хэдий `try_from_str` хэрэгжилт ч өгөгдсөн тэмдэгт мөр нь хүчинтэй `PrivateKey` эсэхийг баталгаажуулж чадахгүй бөгөөд хэвийн бус бол анхааруулах боломжгүй.

Энэ нь зарим илэрхий алдааг илрүүлэх болно, жишээ нь мөрөнд хүчин төгөлдөр бус тэмдэгт орсон бол. Гэсэн хэдий ч бид олон төрлийн түлхүүрийн форматыг дэмжихийг зорьж байгаа тул үүнээс их үүрэг гүйцэтгэж чадахгүй. Мөн өгсөн дансны хувийн түлхүүр зөв эсэхийг хэлж чадахгүй, та заавар өгтөл.

:::

Ийм төрлийн нарийн алдаануудыг жишээлбэл, текстэн утгаас шууд десериализаци хийх эсвэл утга нь тохиромжтой газруудад шинэ түлхүүрийн хос үүсгэх замаар зайлсхийж болно.
