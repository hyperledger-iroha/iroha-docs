# Нөхөнтгэлийн асуудлыг шийдвэрлэх {#troubleshooting-configuration-issues}

Энэ хэсгээс Iroha 3 -Таныг шалгахын тулд
[нэгийг шалгасан](./overview.md#check-the-keys) нэгдүгээрт, хамгийн их
БНСУ-ын Iroha.

Хэрэв та дурдаж буй асуудал энд тодорхойлдоггүй бол бидэнтэй холбоо бариарай
[Телеграм](https://t.me/hyperledgeriroha).

## Үргэлжсэн генезис Docker Compose тоног төхөөрөмж {#outdated-genesis-on-a-docker-compose-setup}

Хэрэв та Docker Compose Хэвлэл Iroha, та очсон байх
Хөдөлмөрийн хэрэгслийн нэгдэл
`Failed to deserialize raw genesis block` Энэ нь ихэвчлэн ижил төстэй,
гарын үсэг зурсан генезис бүтээн байгуулалтын болон үүсгэсэн конфигурацыг
янз бүрийн Iroha шинэчлэл, хувилбар.

Энэ алхамгаар алдааг шалгаарай:

1. Хэрэглээ `docker ps` Одоогийн контейнерийг шалгах.
   үүсгэсэн хувилбар, та ихэнхдээ харах болно `hyperledger/iroha:dev`
   контейнер. Docker Compose хувилбар нь дөрвөн ижил төстэй
   агууламж, хэрэв таны үйлдвэрлэсэн `docker-compose.yml` өөр байж болно.

2. Тодруулгыг шалгаж,
   `Failed to deserialize raw genesis block` алдаа. Хэрэв та эхлүүлсэн
   Iroha "Daemon" режист `docker compose up -d`, хэрэглээ
   `docker compose logs` Засаг дарга.

Ийм асуудлыг шийдэх арга нь Iroha. Хэрэв энэ бол
түүнээс гадна, та эгнээн дутагдалтай мэдээлэл хадгалах шаардлагагүй
орон нутгийн сүлжээ эсвэл Docker Compose хамтлагтай Kagami:

```bash
cargo run --bin kagami -- localnet --build-line iroha3 --peers 4 --out-dir ./localnet
cargo run --bin kagami -- docker --peers 4 --config-dir ./localnet --image hyperledger/iroha:dev --out-file ./docker-compose.yml
```

Дараа нь хуучны контейнерийн байдлыг арилгаж, сэргээсэн
`genesis.signed.nrt`, өрсөлдөгч `config.toml` баримт бичиг, `client.toml`.

Хэрэв та сэргээх хэрэгтэй бол Iroha үлгэр жишээний мэдээллийг дараах байдлаар хий:

1. Хоёр дахь нь холбоно Iroha анхны өгөгдлийг нунтаглана
   (Үргэлжсэн) хамтарч.
2. Шинэ дундаж нь анхны дундажтай мэдээллээ тохируулна гэж хүлээх.
3. Шинэ залууг идэвхтэй байлгаарай.
4. Эхний дундажны генез, конфигурацийн файлуудыг зөвхөн
   зохицуулсан шилжилт.

::: info

Женезийг амьд дээр солих ерөнхий автомат шинэчлэлийн зам байхгүй
Энэ нь хамтарсан шилжилт гэж үзээрэй: хуучин оршин тогтнолыг хадгалах,
нийцсэн ижил төстэй, зөвхөн шинэ конфигурацынд validators шилжүүлэх дараа
үйл ажиллагаа эрхлэгчид шилжилтийн төлөвлөгөөний талаар тохиролцож байна.

:::

## Хувийн болон олон нийтийн түлхүүрний олон хэш хэлбэр {#multihash-format-of-private-and-public-keys}

Хэрэв та
[үйлчлүүлэгчдийн тохируулга](/mn/guide/configure/client-configuration.md), та
нэвтрүүлэгт зориулсан
[олон хаш хэлбэртэй](https://github.com/multiformats/multihash).

Хэрэв та өмнө нь олон хаштай ажилласангүй бол
баруун талд нь гол байтын зургаан арван дахь дүрс биш
(байтт нь хоёр символ), харин байт нь ASCII (эсвэл UTF-8),
болон дуудлага `from_hex` Хоёр дахь уран зохиол дээр `public_key` болон
`private_key` Урьдчилгаа.

Түүнчлэн, дуудлага `PrivateKey::try_from_str` .
Энэ нь зөвхөн зөв цөм хийлгэх болно.
Энэ нь 32 байт, 64 байт гэх мэт алдааг үүсгэдэг.
Мэдээлэл.

**Энэ хоёр үзэл баримт нь буруу.** Харамсалтай нь алдааны мэдээ
Энэ төрлийн алдааг арилгахад туслахгүй.

**Хэрхэн зохицуулах вэ**: хэрэглээ `hex_literal`. Энэ нь ч бас буурсан зангилаа
Зүгээр л зургаан арван жижиг тооны сайхан хүснэгтээр тэмдэглэгдсэн байна.

::: warning

Тэр ч байтугай `try_from_str` хэрэгжилт нь тухайн жижиг зангилаа
хүчинтэй `PrivateKey` Хэрэв тийм биш бол та нарыг анхааруулна.

Энэ нь зарим ил тод алдааг олж авах болно, жишээ нь, акор нь хүчингүй
Гэхдээ бид олон үндсэн хэлбэрүүдийг дэмжих зорилготой тул энэ нь маш их хийж чадахгүй
Үндсэн цөм нь _зөв_ хувийн түлхүүр _тухайн
данс_ Хэрэв та үүрэг даалгаврыг хүргэхгүй бол.

:::

These Тухайлбал,
Утасны үсэгээс шууд дэсэриалж, эсвэл шинэхэн
Энэ нь утга учиртай газар дээр түлхэц-дэмлэг.
