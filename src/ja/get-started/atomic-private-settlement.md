# Atomic Private Data-Cross-Space Settlement を実行する {#run-atomic-private-cross-dataspace-settlement}

`AtomicPrivateSettlementV1`は2〜255の SORA Nexus データスペスのそれぞれに1つの機密決済ステップを調整し,グローバルステートトランザクションですべてのステップを最終化します.拒否された,期限切れまたは中止されたバンドルはいずれもステップに適用されません.透明ネイティブ AMX DvP/PvP は別々のプロトコルパスとして残ります.

::: warning リリース状態 この機能は管理され,デフォルトで無効化されます.
そしてまだ生産資格がない.公開された機能性,プライバシー,故障,性能,再現可能なビルドまで実際の CBDC 値で有効化しないでください.独立の暗号化レビューとアーティファクト出版ゲートが 正確なリリースに合格しました.

## プロトコルに隠されていること {#what-the-protocol-hides}

各脚は固定された2入力,3出力プライベートノート証明を使用します.委員会検証者は証明と不透明な状態移行を確認します;彼らは平文パーティ,資産,金額,メモ,またはビジネス結果を受け取らない.認可されたローカル・オーディターは,包装された監査カプセルを解読し,その内容を確認し,目的別な承認に署名します.デフォルトポリシーでは,管理される監査機セットから1回の承認を受け付けます.

公営航空会社と領収書が故意に示しているのは:

- ネットワークおよびバンドル識別子
- 参加者データスペース経路と参加者の数
- タイムリングと有効期限の高さは
- 安定した不透明なプール識別子,ルーツ,無効化符,コミットメント,および固定暗号文字スロット
- 委員会当局と正確な3/4の可用性,準備,およびコミット証明書
- スポンサー,公共ネットワーク料金,ターミナル状態

これはトラフィックフローの匿名性ではなく,コンテンツの機密性です.タイムリング,参加者数,データスペースのアイデンティティ,および安定プール活動が公開されます.ただひとつの CBDC をホストするデータ空間は,文字どおりのアセット識別子が公表されていないにもかかわらず,ルートから資産を減算することもできます.

## 部署の要件 {#deployment-requirements}

アクティベーションの前に,オペレーターは以下のすべてを必要とします.

1. 各参加データスペースに正確に4つの検証器があり,異なる BLS コンセンサスキーと所有の証明書がある.
2. 必須の Sumeragi DA/RBC はすべての高度に有効です
3. 管理された機密な決済池とすべてのデータスペースの初期ルート
4. アクティブ V1 プライベートメモ機能と別々の決済証明プロファイル
5. 少なくとも1つの管理されたローカル `PrivateSettlementAuditPolicyV1` を含め,異なる監査署名とハイブリッド暗号化キー,重要な時代,高さの有効性,承認の限界を含む.
6. 配置された保存期間のために十分なプライベートサイドカー貯蔵庫
7. 最終的な公共航空会社を提出できる中立スポンサーアカウント

監査者は検証器を操作することもできますが,別々のコンセンサス,監査署名,および監査暗号鍵を使用する必要があります.規制保存期間のために解読鍵を退役に保管し,またはそれらを退役する前に制御とテストカプセルの再巻く必要があります.

4 つの検証者権限は,クライアントが提供していない状態に固定されています. マニフェストの `authority_context_height` で,すべての認証者は正確な順序されたレーン/データスペースリストとアクティブレーンのインカーネーションを解決します BLS 鍵と所有権証明書を確認する.アップロード,準備,最終領収書入力はすべて同じ歴史的権威を使用します.

## 入口を設定する {#configure-admission}

すべての生産行動はノード構成から発生する.環境変数はこの経路を活性化することはできません.送信されたデフォルトは `enabled = false`;機能を無効にしておくには,設定特定の配置が不要です.

管理が必要な機能を登録し,適切な通知でアクティベーション高度を選択した後,すべての関連するノードを一貫して構成します.

```toml
[nexus.atomic_private_settlement]
enabled = true
activation_height = 500000
minimum_activation_notice_blocks = 7200
proof_profile_version = 1
max_participants = 255
max_expiry_blocks = 7200
audit_timeout_blocks = 1200
prepare_timeout_blocks = 1200
commit_timeout_blocks = 1200
capsule_padding_classes_bytes = [4096, 16384, 65536, 262144]
max_proof_bytes = 8388608
max_capsule_bytes = 1048576
max_carrier_bytes = 4194304
sidecar_retention_blocks = 1000000
sidecar_max_records = 256
sidecar_max_total_bytes = 3221225472
default_min_auditor_approvals = 1
permitted_policy_versions = [1]
```

この例では,運送された V1 制限が用いられ,パフォーマンス推奨ではありません. 保存,証明,カプセル,キャリア,および遅延封筒を測定します運行制限を選択する前に意図されたハードウェア. 3段階のタイムアウトは `max_expiry_blocks` の内側に収められ,サイドカー保持は少なくともその有効期限を設定する必要があります.

`max_capsule_bytes` カノニカルを制限する Norito 全体のコード化 `PrivateSettlementAuditCapsuleV1`: AAD, ノンセ,暗号文字,ベクトルフレームリング,監査人の身分,そしてすべての包装された DEK 暗号文字のみの制限ではありません. 各構成されたパッディングクラスは,保存的な全カプセル封筒に適合する必要があります少なくとも `default_min_auditor_approvals` 監査人 Torii また,新たに承認された政策を拒絶し, `min_approvals` 完全にカノニカルなコードが大きすぎた実際のカプセルを拒絶します

`max_carrier_bytes` は,認証されたバンドだけでなく,完全な法規的なスポンサーが署名したトランザクションを制限します.カウントには登録された指示フレームリング,トランザクション権限およびメタデータ,料金の意図と署名が含まれます.通常のネットワークトランザクションの限界は依然として独立した上限として適用されます.

制御された機能がアクティブである限り,その状態とアクティベーションの高さは通知期間を満たし,コンパイルされた証明プロフィールが一致する V1,および連鎖上のプールと監査記録が現在の場合を除いては,起動できません.構成フラグのみを有効にすることは十分ではありません.

## 決済作業流 {#settlement-workflow}

クライアントは本地で証明書と暗号化されたカプセルを作成します.秘密の証人はネイティブウォレットまたはネイティブワーカーに留まなければなりません;それらをアプリケーションログ, Python オブジェクト, HTTP リクエスト,または持続的な調整記録にシリアル化しないでください.

カプセルおよび各監査人 DEK 包装で認証されたデータには,正確な国営アンカー委員会と `authority_context_height` のダイジェスト,ネットワークが含まれます.ルート/インカネーション,バンドル,フェグ,ポリシー,キー・エポーク,そして plaintextコミットメント. 包装された鍵は別のリストまたは歴史的な権威文脈に移動することはできません.

コーディネーターは,各カノニカル・ペットに対して次の順序を実行します:

1. 暫定暗号化された資料を4つの検証者全員にアップロードし, 正確な3/4の可用性証明書を取得する.
2. 認証された監査官に カプセルを回収して解読させ 公的な義務を再計算し 地元の方針を実行し 承認を提出してください
3. 要求 4 つの検証者からの投票を準備する. 各認証者は独立して確認し,投票前にデルタを持続的に段階化します. すべての段階化された応答者に定例的な 3 の 4 の準備証明書が残ります.
4. 各脚が 準備証明書を持っている後,変更できない完全な準備障壁を構築します. 3つの4つのコンビート証明書を要求して維持します. コーディネーターが再起動した場合は、参加ノードにローカルで永続化された Prepare および Commit 証明書を問い合わせます。同じクォーラムを表す正規証明書を選択し、処理を続行する前に再配布します。認証されていないローカルキャッシュから証明書を再構築してはなりません。
5. マネスティック・スポンサーのサインを持ち,正確に1つのグローバル航空会社を提出してください.その航空会社には1つの `FinalizeAtomicPrivateSettlementV1` 指示と正確な完全な認証パネルが含まれています.コーディネーターおよび WSV 飛行前は登録された指示枠を含む完全なボックス完成命令を測定します.Torii とコアワンショットキャリアの拘束力 (binding force) は,権限,メタデータ,料金の意図および署名を含む正確なカノニカル・スポンサーが署名したトランザクションに対して `max_carrier_bytes` を執行します.Torii は,その権限の枠組み前に,期限切れまでに最終性に達する可能性のある最後のエントランス高度またはそれ以降,又は規制された期限を超えて運航者を拒否する.
6. グローバル決済まで公開バンドの状態と受信を問い合わせます.地元のサイドカー状態を一時的な状態として 変えられないグローバル・ターミナル記録を調和させるまで待遇する

Rust クライアントは,この流れを `certify_and_upload_private_settlement_legs_v1`, `prepare_private_settlement_bundle_v1`, `commit_private_settlement_bundle_v1`,および`submit_private_settlement_bundle_v1`を含む方法によって暴露する.再起動に安全な調整では、`recover_or_prepare_private_settlement_bundle_v1` と `recover_or_commit_private_settlement_bundle_v1` を使用します。委員会と監査の呼び出しには明示的な役割認証が必要です.彼らは通常のアカウント署名者を再利用しません.

## 監査方針を安全に操作する {#rotate-an-auditor-policy-safely}

プライバシー・ガバナンス (Privacy-Governance-authorized `RotatePrivateSettlementPoolPolicyV1`) の指示を使用します. この命令は,現在の正確なガバナンスのダイジェストを指定し,同じ経路,プール,および資産拘束のコミットメントを維持し,ガバナンスを1つずつ修正し,厳格に新しいキー時代と異なる政策/ガバナナンスダイジェストを使用する必要があります.プールの境界線,ルーツ,無効化器,出力,リプレイセット,最終的な領収書が保存されます.同じルート/プールを回転のアクティベーション高度に触る領収書を含まない.指示はその境界を拒絶します.

パブリックプールのプロジェクションは,完全に置き換えられたポリシー修正ラインを保持しています. ローテーション前に最終的な領収書は,再起動後も有効であり,その正確な領収書の再生は無効です.系統は未完成の作業を許可しません.アクティベーション境界を越えた古いポリシーバンドルは,グローバル状態の変化前に閉鎖されなくなります.保存されたカプセルを開くために必要なすべての古い解読キーを保持し,または破壊する前に管理およびテストしたカプセルを再巻くことができます.

## 失敗と回復 {#failure-and-recovery}

欠けているまたは時代遅れの監査人の承認,3件未満の検証者投票,誤った根や時代,二重無効性証明書,代替された証拠またはカプセル,非定規的な足順,期限切れのバンドル,不一致な補償条件はすべてグローバル変異の前に失敗します.義務証明書には 私立国家が変異しない

Validatorsは,再起動時に可信性のある記録から予約を再構築し,その後不変なグローバル領収書,中止マーカー,または有効期限を調整します.監督された調停機は,調理する最終候補者が存在しない場合でも,同期的に観測される権限の高さで端末保持切割も行います.そして,切断エラーで閉じるのが失敗する.唯一の権威あるグローバルターミナルレコードがステージロックをリリースします.同じ最終的な領収書を再再生することは無力です.矛盾した再再生は決定的に失敗します.

予約のアイデンティティには完全なルートが含まれます.プールヘッドは `(route, pool_id, epoch, root)`,無効化器は `(route, pool_id, nullifier)`を使用し,アウトプットが `(route, pool_id, commitment)` を使用します.他のルートで同じ不透明な値は独立します.再起動中に正確なルート衝突がロックされます.

運用アラートには,不透明なバンドル,ルート,フェーズ,ダイジェスト,高度,理性級のフィールドのみを使用する必要があります.ログ,イベント,メトリックラベル,または追跡範囲に解読されたカプセル,アカウントまたは資産識別子,金額,メモ,ビューデータ,証明証人,解析用荷を決して置かないこと.

## 真の価値前の資格 {#qualification-before-real-value}

導入する予定の正確なビルドとコンフィギュレーションについては,以下の資料をアーカイブする.

- 逆境証明,カプセル,ポリシー,鍵回転,補償,再プレイケース
- 2, 3, 4, 8 および 16 のデータパース, Validator と Coordinator を 再起動する 認証された 5%, 10% と 20% のメッセージ損失,フェーズパーティション,復元,および持続性制限のクラッシュを含む実際の4つの検証者プロセスは
- Torii,P2P,ブロック, Kura,スナップショット,クエリ,イベント,ログ,およびテレメトリのカナリアと差異性漏洩分析
- リアルネットワーク参加者数につき少なくとも5つのウォームアップと30の測定バンドル, p50,p95,p99,信頼間隔,リソース,トラフィック,証明書および領収書のサイズ,そして透明な AMX を制御する.
- 厳格な作業場テスト,リントとフォーマットチェック,ランダム化された種子,浸泡,再現可能なビルド, SBOMs,および署名されたアーテファクトハッシュ
- 2つの形式的な層: 3/255足のカウント・シンメトリーチェックと正確な4つの検証者委員会-インデックス N=2 検証者集中加え完全な境界線-欠陥,紙-プライマリ N=3 欠陥,N=4 クリーン,およびN=3 終了/再再生構成,各委員会に独立した欠陥予算がある
- 証明関係,模擬スロットセレクター,資産とカプセル結合,払い戻し関係,暗号化,クロスデータスペース状態マシンの独立したレビュー

DOI がサポートする不変なアーテファクトに原材料および消毒された証拠,脅威モデル,プロトコル аргумент,制限,コミット ID,ハードウェア説明,および監査報告書を公開します.リポジトリテストだけでは機能を生産資格のある CBDC 決済システムには変えることはできません.

すべての原始の故障実行および遅延サンプルは,完全なリリースコミット,構造化された固定ハードウェア記述の SHA-256 およびその正確な参加者数設定の SHA-256 を結合する必要があります.N=2,3,4,8,16 をカバーするカノニカル構成マニストをアーカイブし,各エントリは保持された構成バイットを参照し,データスペースごとに正確に4つの検証者,3分の4のクォーラム,および必須署名 RS16 DA/RBC を主張しなければならない.リリース検証は,異なるビルド,ハードウェアプロフィール,またはネットワーク構成で作成された概要を拒絶します.個々の損失,段階カット,および持続性-クラッシュ行ごとに,さらに,世界的に再利用できない正確な JSONL レコード参照が SHA-256 に制限されている必要があります.認証されたコントローラーと原子性を捕捉するアーテファクト.リリース検証機はこれらの消化処理を解決し,行列が実行アイデンティティ,試験インデックスおよびパラメータ,コントローラ承認または復元結果,連続チェックカウントに一致するように要求します.後にリリースされた p95/p99の比較では,ハードウェアや構成,または測定要件が候補者とは異なる署名されたベースラインも拒絶します.最終検証者は,独立した基準要約を信頼する代わりに,アーカイブされた原油サンプルから報告されたすべてのパーセンテイル, MADs,および決定的な信頼間隔を再生します.また カナリーマニフェストをリロードし 独立してアーカイブされたすべてのプライバシー表面をスキャンします だからファイル消化を再結合した後 レポートは埋め込まれた秘密のヒットを抑制することはできませんまた,アーカイブには,必要なすべてのプライバシー面のための正確な左と右のファイルパス,タイプ,バイト長さ,および SHA-256 ダイジェストを結びつける法定差異対マニフェストも含まれなければならない.その宣言された根は,ペアしたアーカイブ・インベントリーを正確に含める必要があります.最終検証は独立して同じサイズを必要とし,公的な形状 JSON を再計算するので,同じ大きさ構造漏洩または配合されていない差異ファイルが漏洩報告を書き換えることで隠すことはできません.
