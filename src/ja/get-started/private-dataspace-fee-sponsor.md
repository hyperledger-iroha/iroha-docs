# プライベートデータスペースの手数料を肩代わりする {#sponsor-fees-for-a-private-data-space}

SORA Nexus の手数料スポンサープログラムは、プライベートデータスペースにルーティングされる適格なトランザクションのグローバル実行手数料を支払えます。トランザクション全体には、引き続きユーザーが署名します。型付きの `FeePaymentIntent` で、正確なスポンサープログラムと不変のリビジョン、必要な場合のガス上限、最大課金額を選択します。

データスペースのカタログ項目を登録しても、独立して署名されるルートは作られません。独立したデータスペースのルートには、固有のコミット済み手数料通貨とポリシーがあります。公開のスポンサーボールトは、そのプライベートルートの手数料を認可できません。スポンサーの仕組みを設計する前に、実行ルートを確立してください。

## 1. コミット済みの手数料ポリシーを確立する {#_1-establish-the-committed-fee-policy}

署名済みジェネシスで、`RootFeePolicy` を含む一つのカスタムパラメーター `root_fees_v1` を作成します。これは、手数料通貨、手数料の受け取り先、スポンサーの保管アカウント、請求の免除、料率を結び付けます。通常の各ブロックと見積もりは、それぞれが取得したコミット済みポリシーを使います。料率、手数料の受け取り先、請求の免除に対する認可された変更は、次のブロックから適用されます。手数料通貨とスポンサーの保管アカウントは、最初のブロックの後には変更できません。

グローバル実行のネイティブ手数料では、署名により正確に指定されたネットワークの XOR 通貨をバーンします。この通貨は、スポンサーのプログラムボールトから供給されます。ノード設定やトランザクションのメタデータで、支払者を選択したりスポンサーによる支払いを有効化したりすることはできません。

ネットワークの正規の通貨識別子とアカウント識別子を使ってください。エイリアス解決によって、コミット済みの通貨、保管先、手数料受け取り先の識別子が別の対象に向けられてはなりません。

## 2. スポンサープログラムを作成して資金を供給する {#_2-create-and-fund-a-sponsor-program}

プログラム ID は `<canonical-sponsor-account>/<program-name>` の形式です。現在の SDK とデータモデルが公開する型付き命令で作成・設定します。

| 命令 | 目的 |
| --- | --- |
| `CreateFeeSponsorProgram` | 必須の払い出し先アカウントを指定し、有効化前のプログラムを作成する。 |
| `StageFeeSponsorProgramRevision` | 適格性、操作、予算について、一つの不変のポリシーを定義する。 |
| `EnrollFeeSponsorBeneficiary` | 適格な受益者をオンチェーンに記録する。 |
| `FundFeeSponsorProgram` | 資産を保管先に移転し、指定されたプログラムボールトに入金する。 |
| `ActivateFeeSponsorProgramRevision` | 準備済みリビジョンを有効化できる最も早いブロック高を設定する。 |

プログラムの管理は、スポンサーまたは明示的に権限を委任された管理者が認可します。出金にはスポンサー自身の認可が必要です。プログラムが一時停止中または終了処理中の場合に限り、記録された払い出し先アカウントだけに資金を戻せます。

各リビジョンは次を指定します。

- 明示的な登録、または登録に加えて許可された経路デフォルトによる適格性。
- 正確なネイティブ命令のワイヤー ID、またはコントラクトのアドレス、コードハッシュ、エントリーポイントに対する許可・拒否規則。
- 資産ごとの、トランザクション、ブロック、プログラムのエポック、受益者のエポックの各単位の上限。
- 最低準備残高と、決定論的なエポック長。

拒否規則は許可規則に優先します。データスペースの `fee_sponsor_program_id` が経路デフォルトによる適格性を与えるのは、有効なリビジョンがそれを許可する場合だけです。トランザクションには、引き続き正確なプログラムとリビジョンの明示が必要です。前のリビジョンの未消化の割り当てが期限切れになるまで、有効化が延期される場合があります。

スポンサーボールトの資産には、`Global` 残高ポリシーを使う必要があります。スポンサーの通常のアカウントに入金するだけでは、独立したプログラムボールトには入金されません。また、あるプログラムが別のプログラムの残高を消費することはできません。

## 3. 対象トランザクションの手数料を見積もり、署名して送信する {#_3-quote-sign-and-submit-the-exact-transaction}

SDK を使った連携では、次の手順を実行します。

1. 権限主体、実行内容、タイムスタンプ、ノンス、メタデータ、正確なスポンサープログラムのリビジョン、必要なガス上限を指定して、未署名の `TransactionPayload` を組み立てます。最大課金額は最初は空でもかまいません。
2. `{"payload": <payload>}` を指定した `POST /v1/fees/quote` に、アカウントの署名を付けます。リクエストの署名者は、トランザクションの権限主体でなければなりません。
3. 観測されたブロック高、解決されたデータスペース経路、手数料の内訳、引き落とし元、スポンサーの余力を確認します。選択した支払者、リビジョン、ガス上限が応答でも維持されていることを検証してください。
4. `payload.fee_payment` だけを推奨されたインテントに置き換え、そのペイロード自体に署名して送信します。
5. トランザクションを、状態から確認された `Applied` のファイナリティまで追跡し、実際のスポンサープログラム、リビジョン、課金額を含む受領記録を保存します。

見積もりは台帳を参照するだけで、容量を予約しません。キューへの受け入れ時に適格性を再検査し、署名された最大額を予約します。スポンサーによる支払いが拒否された場合は、ユーザーへの課金に切り替えることなく、トランザクションを拒否します。

CLI でも、同じ手数料の支払元を明示します。例えば、プログラムがこの正確な資産移転を許可し、アカウントが適格である場合は、次のようにします。

```bash
iroha --config ./user.client.toml \
  --fee-payer sponsor \
  --fee-program '<SPONSOR_CANONICAL_I105>/team-payments' \
  --fee-program-revision 1 \
  ledger asset transfer \
  --definition '<ASSET_DEFINITION_BASE58>' \
  --account '<USER_CANONICAL_I105>' \
  --to '<RECIPIENT_CANONICAL_I105>' \
  --quantity 1
```

使用するネットワークの有効なリビジョンと正確な識別子を使ってください。ユーザー設定に含める署名者は、そのユーザー自身だけです。適格なスポンサー付きトランザクションの送信に、スポンサーの秘密鍵は必要ありません。

## 4. ユーザーがアプリケーション手数料を支払うかを決める {#_4-decide-whether-the-user-pays-an-application-fee}

スポンサーがグローバル手数料を負担し、アプリケーションはユーザーに何も請求しない形にもできます。アプリケーションがローカルトークンを徴収する場合は、その移転またはコントラクト規則を、ユーザーが署名する実行内容に明示してください。すべての操作をスポンサーのリビジョンのポリシーに含め、ペイロード全体の見積もりを確認します。ネットワーク手数料のインテントから、アプリケーショントークンの移転を推測してはなりません。

## 拒否の原因を調べる {#diagnose-a-refusal}

ノードが返す、安定した手数料コードと対処方法の詳細を使ってください。

| コード | 確認対象 |
| --- | --- |
| `program_not_found` | 正確な正規プログラム識別子。 |
| `revision_not_active`, `program_not_active` | リビジョンの有効化とプログラムのライフサイクル。 |
| `beneficiary_not_eligible` | 登録、または許可された経路デフォルトによる適格性。 |
| `operation_not_allowed`, `operation_denied` | 署名されたすべての操作の正確な内容と拒否規則。 |
| `invalid_gas_limit`, `signed_limit_exceeded` | 最新の見積もりに対するガス上限と署名済みの最大額。 |
| `vault_insufficient` | このプログラムの、指定された通貨のボールトに入金された残高。 |
| 予算枯渇のコード | トランザクション、ブロック、プログラムのエポック、受益者のエポックごとの余力。 |

送信結果が不明な場合の調査では、元のトランザクションハッシュと手数料拒否の詳細を保存してください。代替トランザクションを組み立てる前に、元のトランザクションの状態を確認します。
