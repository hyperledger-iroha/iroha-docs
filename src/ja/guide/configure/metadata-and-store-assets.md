# メタデータとブロックチェーン台帳の保存方法の選択 {#metadata-and-ledger-storage-choices}

Iroha 3 データモデルには、任意のキーと値のデータのための別個の`Store`アセットタイプはありません。次のストレージオプションを使用してください。

## メタデータ {#metadata}

ブロックチェーン台帳オブジェクトに属する小さな JSON フィールドには [メタデータ](/ja/blockchain/metadata.md) を使用してください:

- 表示名とラベル
- 統合ID
- 小さな方針旗
- 暗号ハッシュ、URIs、CIDs、またはより大きなペイロードを指す SoraFS パス

メタデータはワールドステートの一部であり、それを所有するオブジェクトとともに返されます。キーは安定させ、値はコンパクトにし、権限は明示的にしてください。大きなドキュメント、ログ、または高頻度で変更されるアプリケーションステートをメタデータに直接保存しないでください。

## 数値資産と NFTs {#numeric-assets-and-nfts}

状態が値を持つときは、[資産](/ja/blockchain/assets.md) と [NFTs](/ja/blockchain/nfts.md) を使用してください。

- 代替可能な残高のための数値資産
- NFTs は独自に所有されているレコード用
- [RWAs](/ja/blockchain/rwas.md)およびアクティブなデータモデルがそれらを公開しているときのその他のドメイン固有オブジェクト

資産と NFTs にはそれぞれ独自のID、ライフサイクルイベント、転送動作、権限チェックがあります。所有権、希少性、または転送履歴が重要な場合、メタデータよりも優れています。

## オフチェーンデータ {#off-chain-data}

大きなまたは変更可能なペイロードにはオフチェーンストレージを使用します。チェーン上には安定した参照のみを保存します。例えば:

- 内容暗号ハッシュ
- a URI
- a SoraFS パスまたは技術マニフェストの参照
- アプリケーション証明で使用されるコンパクトな暗号コミットメント値

これにより、WSV を小さく保ちつつ、アプリケーションがオフチェーンのペイロードがオンチェーンの参照と一致することを確認できるようになります。

## 場所を選ぶ {#choosing-a-location}

この経験則を使ってください：

- もしそれがブロックチェーン台帳オブジェクトのコンパクトな属性である場合、メタデータを使用してください。
- もしそれが価値を持つものであったり、譲渡可能である場合は、資産、NFT、またはドメイン固有のオブジェクトとしてモデル化してください。
- もしそれが大きい、回転率が高い、またはアプリケーション専用である場合は、それを WSV の外に保存し、検証可能な参照をオンチェーンに置いてください。

メタデータの権限については、[許可トークン](/ja/reference/permissions.md) を参照してください。
