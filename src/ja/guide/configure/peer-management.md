# ネットワークピア管理 {#peer-management}

もし言語別のガイドに従ったなら、今では人々が参加したくなるような、よく機能するネットワークを持っていることになります。

## パブリックブロックチェーン {#public-blockchain}

オープンネットワークでは、ネットワークピアの参加は依然としてチェーンポリシーの決定です。ノードは正しいソフトウェアを実行し Torii に接続することができますが、ネットワークがそのネットワークピアのアイデンティティを承認して初めてコンセンサスに参加します。

## プライベートブロックチェーン {#private-blockchain}

銀行の環境では、誰もが自由に参加できるようにすることはセキュリティ上のリスクです。安全のため、プライベートな Iroha の展開では、オープンなディスカバリに頼る代わりに、通常ネットワークピアのトポロジーを構成およびブロックチェーンのジェネシスに固定します。

### ネットワークピアを登録する {#registering-peers}

ネットワークにネットワークピアを追加するには、手動で登録する必要があります。このプロセスを完了するために取るべき手順について話し合いましょう。

#### 1. ユーザーに権限を付与する {#_1-grant-the-user-permissions}

ネットワークピアを登録するアカウントは、適切な`Permission`を持っている必要があります。これは`Role`を通じて付与することも、直接権限を付与することも可能です。

アカウントが時間をかけてネットワークピアを管理する場合は、役割を付与します。ネットワークピアを管理しないアカウントによる一度限りの登録には、直接の権限付与を使用してください。

::: info

デフォルトの実行者は、ネットワークピアの登録および登録解除に `CanManagePeers` 権限トークンを使用します。

:::

私たちは、[別の章](/ja/blockchain/permissions.md) で権限と役割についてより詳しく議論します。

#### 2. ネットワークピアを設定する {#_2-set-up-a-peer}

新しいネットワークピアに権限が付与された後、それを設定する必要があります。

ノードを許可する前に、現在のネットワークピア設定を要求してください。Torii は、この目的のためにノードパラメータと機能 API エンドポイントを公開します。ネットワークピアのブートストラップはこれらの値を自動的に交渉しません：オペレーターはタイムアウト、バッチサイズ、その他のコンセンサスに関連する設定がネットワークと一致していることを確認する必要があります。

プロセスを簡素化するために、ネットワーク管理者に特権情報（ネットワークピアのプライベートキーなど）を除外した`config.toml`の編集済みバージョンを依頼することができます。

#### 3. 指示を提出する {#_3-submit-the-instruction}

ネットワークピアが稼働したら、ピア登録の指示を送信する必要があります。ネットワークピアはハンドシェイクプロセスを経て、ネットワークとの通信を開始します。

::: tip

ネットワークピア登録の指示を送信しても、新しいネットワークピアプロセスは生成されません（生成することもできません）。

:::

### ネットワークピアの登録解除 {#unregistering-peers}

ネットワークピアの登録解除はどうでしょうか？セキュリティ上の理由から、このプロセスは一方的です。ネットワークは、あるネットワークピアを削除したいという合意に達しますが、そのネットワークピア自身は、なぜ誰も自分と通信していないのかについてあまり知りません。

ほとんどの場合、ネットワークピアの登録を解除したい場合、それはビザンチン障害が原因であることが多いです。このネットワークピアを単に「無視」するだけで、ネットワーク上の悪意のある行為者の活動を困難にします。
