# ピアマネジメント {#peer-management}

言語指針のいずれかをフォローした場合は 現在 人々が参加したい 機能するネットワークがあります

## パブリック・ブロックチェーン {#public-blockchain}

オープンなネットワークでは,ピア・アドミッションは依然としてチェーン政策の決定である.ノードが正しいソフトウェアを実行して Torii に接続できるが,ネットワークがピア・アイデンティティを認めた後にコンセンサスに参加する.

## プライベート・ブロックチェーン {#private-blockchain}

銀行環境では,誰もが自由に参加できるようにすることはセキュリティリスクである.安全のために,プライベート Iroha 部署は通常,オープン発見に頼るのではなく,ピアトポロジーを構成と生成に固定します.

### 同級者の登録 {#registering-peers}

ネットワークにペアを追加するには,手動で登録する必要があります. このプロセスを完了するために必要な手順について議論しましょう.

#### 1. ユーザーに許可を与えること {#_1-grant-the-user-permissions}

同級者を登録するアカウントには適切な `Permission` が入っている必要があります.これは `Role` を介してまたは直接許可の授予として与えられます.

ユーザが管理者として働く場合,役割を与えることは意味があり,ネットワーク内の同僚を長期的に維持することが彼らの責任である.ピアを登録する当事者は,一般的にピアを登録するための責任を持っていない場合,一度の許可授予は有用ですが,ネットワーク管理者は新しいピアを設定するのに時間を使わなく (または使いたい) ではありません.

::: 情報

デフォルト実行者は `CanManagePeers` 許可トークンを登録および登録しない同行に使用します.

:::

[の別の章](/ja/blockchain/permissions.md)では,許可と役割について詳細に議論します.

#### 2. 仲間を組む {#_2-set-up-a-peer}

新しい同級生が許可を受けた後, 設定する必要があります.

Torii は,この目的のためにノードパラメータと能力エンドポイントを暴露します.Peer bootstrap ではこれらの値は自動的に交渉されません:運用者は,タイムアウト,パッチサイズ,および他の合意関連設定がネットワークに一致していることを確認しなければならない.

プロセスを簡素化するために,ネットワーク管理者に `config.toml` の編集されたバージョンを依頼し,ピアプライベートキーなどの特権情報を除外できます.

#### 3. 指示を提出する {#_3-submit-the-instruction}

同僚が実行した後,同級者登録の指示を提出する必要があります. 同僚は握手プロセスを通してネットワークとチャットを開始します.

::: トップ

同級登録の指示を提出することは,新しい同級手続きを即座にすることではない (し,実行できない).

:::

### 登録されていない同級生 {#unregistering-peers}

登録 し ない 同級 者 たち に は どう なる でしょ う か.セキュリティ上の理由から このプロセスは 一面的なものですネットワークは 同僚を削除したいという合意に達したが 同僚自身は なぜ誰も話さないのかあまり知らないそれまで

多くの場合 同僚の登録を撤回したいと 思うのは ビザンツィニア人のせいだからだ この同級者の"幽霊化"だけで ネットワーク上の悪意ある俳優の生活が難しくなる
