# パブリックおよびプライベートブロックチェーン {#public-and-private-blockchains}

Iroha はさまざまな構成で実行できます。自身のネットワークの管理者として、どの実行者と権限ポリシーが取引の承認を決定するかを決定します。

一般的なプロファイルは、プライベートな許可制ネットワークと、よりオープンなパブリックネットワークです。どちらも、個別のノードバイナリを通してではなく、ブロックチェーンのジェネシスステートと実行者ポリシーを通して構成されます。

以下に、これら二つのユースケースの主な違いを概説します。

## 権限 {#permissions}

パブリックブロックチェーンでは、ほとんどのアカウントは同じ権限セットを持っています。プライベートブロックチェーンでは、各アカウントは明示的な権限のみを受け取ります。

::: info

詳細については、[権限に関する専用セクション](/ja/blockchain/permissions.md) を参照してください。

:::

## ネットワークピア {#peers}

パブリックブロックチェーンでは、ネットワークピアの参加はチェーンポリシーの一部です。プライベートブロックチェーンでは、デプロイ時に信頼されたネットワークピアのセットを設定やブロックチェーンのジェネシスに固定することが一般的です。

::: info

詳細については[ネットワークピア管理](peer-management.md)を参照してください。

:::

## アカウントの登録 {#registering-accounts}

あなたがどのように設定することに決めるかによって [ブロックチェーンのジェネシスブロック（`genesis.json`)](genesis.md), アカウント登録のプロセスは、2つの方法のいずれかで進む可能性があります。なぜそうなるのかを理解するために、まず権限について話しましょう。

選択された実行者は、どの権限チェックが適用されるかを定義します。ブロックチェーンのジェネシスでデフォルトの [許可トークン](/ja/blockchain/permissions.md) を付与することで、プライベートで管理者が運営するネットワークや、よりオープンなネットワークを形成することができます。これらの権限が有効になると、アカウント登録のプロセスは異なります。

公的および私的な登録ポリシーは通常異なります:

- 公開登録ポリシーは、資格のあるユーザーからのアカウント登録を受け入れます[^1]。ユーザーは、適切なクライアント、サポートされているアルゴリズムのプライベートキー、およびポリシーによって承認された登録リクエストが必要です。

- プライベート登録ポリシーは、1つのアカウントまたは1つのスマートコントラクトが登録を提出することを許可できます。カスタムポリシーは、登録を特定の時間枠に制限することができます。また、送信者がトークンを使用することを要求することもできます。そのトークンは供給量が固定されており、追加発行する権限を持つ主体が存在しないためです。

- デフォルトのプライベートネットワークパターンでは、既存のアカウントが各新しいアカウントの登録を提出します。

デフォルトの権限バリデーターは、一般的なプライベートブロックチェーンのユースケースをカバーします。

::: info

パブリックモードとプライベートモードは、エグゼキューターとブロックチェーンのジェネシスポリシーの選択です。どちらも同じノードバイナリを使用します。オープンネットワークを実行する前に、選択したエグゼキューターとブロックチェーンのジェネシス権限を確認してください。

:::

`Register<Account>`の指示に関する詳細については、[指示](/ja/blockchain/instructions.md#un-register)のセクションを参照してください。

[^1]: `Register<Account>` は、標準形式のドメインなし `AccountId` について台帳状態を作成します。ドメインルーティングとエイリアスは別個に管理されます。
