# 公的および私的なブロックチェーンは {#public-and-private-blockchains}

Iroha は様々な設定で実行できます. 自分のネットワークの管理者として,どの執行機関と許可ポリシーが取引を承認するか決めるのはあなたです.

一般的なプロファイルはプライベート許可されたネットワークとよりオープンなパブリックネットワークです.両方とも,分離したノードバイナリーではなく,ジェネスステートおよび実行者ポリシーで構成されています.

以下は,この2つの使用例の主要な違いについて説明します.

## 許可 {#permissions}

公開ブロックチェーンの場合,ほとんどのアカウントには同じ許可があります.プライベートブロックチェーンの場合は,各アカウントは明示的な許可のみを受け取ります.

::: info

詳細については, [専用の許可に関するセクション](/ja/blockchain/permissions.md)を参照してください.

:::

## 同級者 {#peers}

公開ブロックチェーンでは,ピア・アドミションはチェーンポリシーの一部である.プライベートブロックチェーンの場合は,デプロイメントは通常設定と生成に信頼性の高いピアセットを固定する.

::: info

詳細については [ピアマネジメント](peer-management.md) を参照してください.

:::

## 登録口座 {#registering-accounts}

[ゲネシスブロック (`genesis.json`) ](genesis.md)を設定する方法を決定すると,アカウントの登録プロセスは2つの方法の一つで行われる可能性があります.なぜかを理解するには,まず許可について話しましょう.

選択された実行者は,どの権限チェックが適用されるかを定義します.プライベート・管理者管理ネットワークまたはよりオープンなネットワークを形作るために,先端でデフォルトの [許可トークン](/ja/blockchain/permissions.md) を許容できます.これらの権限が有効になると,アカウントの登録プロセスは異なります.

公的および私的な登録政策は通常異なります

- 公的な登録方針は,適格なユーザーからアカウントの登録を受け入れます[^1].ユーザーは適切なクライアント,サポートされているアルゴリズムのためのプライベートキー,およびポリシーによって承認された登録要求が必要です.

- プライベート登録ポリシーでは,アカウントまたはスマートコントラクトに登録を提出する権限を与えることができます.カスタムポリシーでは,登録をタイムウィンドウに制限することができます. また,送信者が供給が固定されているトークンを消費するよう要求することも可能です. 当局はこれ以上発行許可がないため.

- 既定のプライベートネットワークパターンでは,既存のアカウントが各新しいアカウントの登録を提出します.

デフォルト許可認証は典型的なプライベートブロックチェーン使用ケースをカバーします.

::: info

パブリックとプライベートモードは実行者と生成ポリシー選択です.どちらも同じノードバイナリを使用します.オープンなネットワークを実行する前に選択された実行者と生成権限をレビューします.

:::

[指示](/ja/blockchain/instructions.md#un-register)のセクションを参照して, `Register<Account>`指示についての詳細をご覧ください.

[^1]: `Register<Account>` は,法定でドメインのない `AccountId` のレジャー状態を作成し,ドメインルーティングとニックネームは別々に管理されます.
