# ネットワーク展開 {#network-deployment}

Iroha ネットワークを調整されたシステムとして扱います。バリデーターは、ネットワークが開始されブロックを最終確定し続ける前に、ブロックチェーンのジェネシス、トポロジー、信頼できるネットワークピア、コンセンサス関連の設定について合意する必要があります。

## 環境の分離 {#environment-separation}

- ローカル開発、共有テストネット、ステージング、本番用にそれぞれ別の設定バンドルを維持する。
- 廃棄可能でないすべての環境について、新しいキーを生成してください。ローカルネットや Taira のキー素材を本番環境で再利用しないでください。
- ネットワークピアの設定、クライアントの設定、署名済みブロックチェーンジェネシス、スクリプト、およびデプロイメントノートを、バージョン管理されたリリースアーティファクトとしてまとめて保持します。
- プライベートキーはリポジトリやデプロイメントテンプレートの外に格納してください。

[ネットワーク展開のための鍵](/ja/guide/configure/keys-for-network-deployment.md) を参照してください。

## ブロックチェーンのジェネシスとトポロジー {#genesis-and-topology}

- プロファイルで要求される場合、すべてのバリデーターが同じ署名付きブロックチェーンジェネシストランザクション、信頼されたネットワークピアセット、トポロジー、およびバリデーターの所有証明を使用するようにします。
- 最小のビザンチン障害許容デプロイメントには、少なくとも4つのバリデータを使用してください。
- キャパシティ計画において、バリデーターをオブザーバーから分離する。オブザーバーは投票、提案、収集を行わないが、それでもストレージ、ブロック同期、ネットワーク帯域を消費する。
- ブロックチェーンのジェネシス、エグゼキューター、およびトポロジーの変更は、単一ノードの編集ではなく、協調されたマイグレーションとして扱うべきです。

見る [ブロックチェーンのジェネシス](/ja/reference/genesis.md), [ネットワークピア管理](/ja/guide/configure/peer-management.md), そして [パフォーマンスと指標](/ja/guide/advanced/metrics.md#node-count-and-quorum).

## Torii とネットワークアクセス {#torii-and-network-access}

- ホストまたはプライベートネットワークの外部に公開される場合、Torii をリバースプロキシまたはファイアウォールの背後に置いてください。
- 展開が必要な場合、TLS を終了し、エッジで基本認証、レート制限、およびリクエストサイズの制御を適用します。
- 環境で必要な API エンドポイントのみを公開してください。オペレーターおよびテレメトリのルートは、公開読み取り専用ルートよりも制限されるべきです。
- ネットワークピアがリモートトラフィックを直接受け入れるべきでない場合、リスナーのアドレスをホストローカルのインターフェースにバインドします。

[Torii API エンドポイント](/ja/reference/torii-endpoints.md) と [仮想プライベートネットワーク](/ja/guide/security/vpn.md) を参照してください。

## コンセンサスと能力 {#consensus-and-capacity}

- コンセンサスタイマーを調整する前にデプロイメントを測定してください。ネットワーク、ストレージ、実行レイヤーが追いついている場合にのみ、タイムアウトを短くするとレイテンシを減らすことができます。
- スループットの短いサンプルだけでなく、キューの方向を監視してください。安定した負荷の間にキューが増加する場合、ネットワークが過負荷になっています。
- 各ベンチマークについて、実際の Sumeragi パラメータ、テレメトリプロファイル、バリデーター数、ネットワーク RTT、ワークロード形状、およびハードウェアの詳細を記録してください。
- 一度に1つの制限付きキューまたはペイロード回収の制限を変更し、変更前後のレイテンシ、トラフィック、メモリ、およびバックプレッシャーの証拠を保持します。

[パフォーマンスと指標](/ja/guide/advanced/metrics.md) を参照してください。

## ベアメタルとプロセス管理 {#bare-metal-and-process-management}

- 各ネットワークピアの`config.toml`、プライベートキー、ストレージディレクトリ、ポートをそれぞれ分けてください。
- 明示的な再起動、ログ記録、リソースポリシーを伴う systemd のようなプロセスマネージャーを使用してください。
- テストトポロジーを管理対象ホストに変換する際、生成された README と Kagami ローカルネットバンドルからの開始コマンドを保持します。

[ベアメタル上で Iroha を実行する](/ja/guide/advanced/running-iroha-on-bare-metal.md) を参照してください。
