# セキュリティとアクセス {#security-and-access}

Iroha におけるセキュリティ実践は、限定的な認可の原則、管理された鍵の保管、明示的なネットワーク露出、および監査可能な変更に基づくべきです。

## 鍵の保管 {#key-custody}

- 本番用のエントロピーで本番用キーを生成し、秘密鍵はリポジトリ、課題追跡システム、プロンプト、チャットログ、CI 出力の外部に保管してください。
- クライアント、ネットワークのピア、ブロックチェーンのジェネシス署名者、バリデーター、手数料のスポンサー、技術アカウントにはそれぞれ別の鍵素材を使用してください。
- キーは文書化されたプロセスに従って回転させ、実際のインシデントの前に復旧手順をリハーサルしてください。
- デプロイメントのリスクが正当化される場合、高価値の署名鍵にはハードウェア対応またはオペレーティングシステム対応のストレージを使用してください。

[暗号鍵の生成](/ja/guide/security/generating-cryptographic-keys.md) と [暗号鍵の保存](/ja/guide/security/storing-cryptographic-keys.md) を見てください。

## 権限 {#permissions}

- ワークフローをサポートする最小の権限トークンまたはロールを付与してください。
- サービス、トリガー、エージェント、および自動化には専用の技術アカウントを使用することを推奨します。個人のオペレーターアカウントを通じて長時間実行される自動化は避けてください。
- 本番リリース前に、ネットワークピア管理、メタデータの変更、発行、破棄、トリガー登録、実行者の変更、および SORA/Nexus ガバナンスの権限を確認してください。
- メンテナンス時間やそれを必要とした移行後に、一時的な権限を取り消します。

[権限](/ja/blockchain/permissions.md) と [許可トークン](/ja/reference/permissions.md) を参照してください。

## ネットワーク露出 {#network-exposure}

- 環境に応じて、ピアツーピア、Torii、テレメトリ、およびオペレーター経路を制限してください。公開読み取りアクセスは、公開書き込みまたはオペレーターアクセスを意味するものではありません。
- 展開に適切な場合は、VPNs、ファイアウォール、リバースプロキシ、TLS 終了、およびレート制限を使用してください。
- 基本認証の資格情報、プロキシトークン、および転送されたヘッダーを、ソース管理に保存された設定から除外してください。
- 許可されていないクライアントが制限されたルートにアクセスできないことをテストする。

[仮想プライベートネットワーク](/ja/guide/security/vpn.md) と [Torii API エンドポイント](/ja/reference/torii-endpoints.md) を参照してください。

## 詐欺および虐待の監視 {#fraud-and-abuse-monitoring}

- 予期しない資産の移動、権限付与、トリガーの変更、ネットワークピアの変更、繰り返し拒否された取引に対して、ブロックチェーンの台帳イベントと運用信号を監視します。
- 取引の暗号化ハッシュ、ブロック高、イベント記録、ログ、およびステータススナップショットで証拠を保存する。
- 影響を受ける資産やワークフローに責任を持つセキュリティ、運用、ビジネス担当者にアラートをルーティングします。

[不正監視](/ja/guide/security/fraud-monitoring.md) を参照してください。

## エージェントおよび自動化ガードレール {#agent-and-automation-guardrails}

- ワークフローがレビューされた後にのみ、書き込み権限のプリンシパルを追加し、読み取り専用権限で自動化を開始します。
- 自動化が意図的に展開された本番サービスでない限り、ライブネットワークの変更には明示的な人間の承認を必要とする。
- プライベートキーをエージェントのプロンプトにさらさないでください。環境変数、キーチェーン、ハードウェア暗号署名装置、または無視される設定ファイルからシークレットを読み込むローカルコードを使用してください。
- 秘密情報を漏らさずに、監査をサポートする形で自動化の決定を記録します。
