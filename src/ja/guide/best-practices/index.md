# ベストプラクティス {#best-practices}

このセクションでは、Iroha アプリケーションおよびネットワークの運用指向のガイダンスをまとめています。これは、実装する機能ではなく、あなたが下す必要のある意思決定ごとに整理されています。

共有テストネットのリハーサル、本番環境でのローンチ、または主要なクライアント向けリリースの前にチェックリストとして使用してください。

## 横断的ルール {#cross-cutting-rules}

- ローカル開発、共有テストネット、および本番環境の構成を分けておく。
- ブロックチェーンのジェネシス、ネットワークピアのトポロジー、実行ポリシー、およびキー素材を管理されたデプロイメントアーティファクトとして扱う。
- 大規模で耐久性のあるブロックチェーン台帳の状態を意図的に設計してください。大きな、プライベートな、または更新頻度の高いデータの投棄場としてメタデータを使用しないでください。
- 拒否、期限切れ、再試行、および遅延ステータスを処理できる冪等ワークフローを通じてトランザクションを送信します。
- 広範な管理者アクセスよりも、狭い権限、専用の技術アカウント、明確な運用手順書を優先してください。
- まず使い捨てのローカルネットワークで挙動を確認し、その後、Taira や他の共有テストネットでリハーサルを行ってから、メインネットでの操作を行ってください。
