# 解放する準備 {#release-readiness}

Iroha アプリケーションまたはネットワーク変更を推進する前に,関連するリスクを暴露できる最小限の環境で動作を証明し,その後,共有テストネットと生産ゲートを意図的に移動します.

## ローカルネットゲート {#localnet-gate}

- Iroha 同じトラックと最も近い実用的な検証者数を持つ一次性ローカルネットワークを起動する.
- トランザクションビルダー,クエリ解析,拒絶処理,コンフィギュレーションロードのためのユニットテストを実行します.
- SDK または CLI の同じ形を使って,アプリケーションが後に使用する最小の成功読書経路を練習します.
- テストアーテファクトで期待されるトランザクションハッシュ,ステータス,イベント,状態の読み取りを捕まえます.

[打ち上げ Iroha 3](/ja/get-started/launch-iroha.md)と [SDK チュートリアル](/ja/guide/tutorials/)を参照してください.

## 共有テストネットゲート {#shared-testnet-gate}

- Taira または他の共有テストネットを使用してエンドポイントの行動,料金,アカウント資金提供,遅延および運用リハーサルを行う.
- オンラインテストネットはオプトインを書き込み,通常のテストランスはネットワークの利用可能性やテストネット資金支出に依存しない.
- 各ライブテスト取引を提出する前に署名者の資金,料金の資産メタデータ,当局の許可と予想状態を確認する.
- ターミナル状態を待って,読み込みのみのクエリで結果の状態を確認します.

見て下さい [成長する SORA 3: Taira そして Minamoto](/ja/get-started/sora-nexus-dataspaces.md).

## メインネットまたは生産ゲート {#mainnet-or-production-gate}

- 生産サイン,資金提供,ドメイン,コンフィギュレーション経路を別々に使用する.テストネットキーや faucet 仮定を宣伝しないでください.
- [互換性マトリックス](/ja/reference/compatibility-matrix.md) で必要なクロス-SDK シナリオを確認します. 部署によって使用された正確な CLI,ピアバイナリー,構成,およびネットワークリリースを別々にピンしてテストしてください.
- レビュー許可,料金のスポンサーシップ,料金制限,モニタリング,バックアップ状態,リリースウィンドウ前のロールバック基準.
- 高い影響のある書き込みのために書面の取引または移行計画を要求する.

## ロールバック と 回復 {#rollback-and-recovery}

- コードデプロイによって取り消すことができる変更を定義し,チェーン上の取引を必要とし,直接取り消すことはできない変更を定義する.
- チェーン上のデータ変更については,最初の生産書き込み前に,補償取引や移行スクリプトを準備する.
- ネットワーク変更については,以前のバイナリ,コンフィギュレーションバンドル,署名されたゲネス,および運用ランブックをリリース中に利用可能にしておく.
- 拒否率,キュー成長,遅延または同級者の健康などの客観的な信号に基づいて展開を中止する決定点を設定します.

## 最終的なチェックリスト {#final-checklist}

- 設定は環境特有のもので,テストのみの秘密を含まない.
- トランザクション再試行動は無力または明示的に制限されています.
- アプリケーションは拒否,有効期限,タイムアウト,エンドポイント利用可能性障害を区別できます.
- 監視は,吞吐量,遅延,キュー深さ,拒否,ビュー変更,および関連するビジネスイベントをカバーする.
- オペレーターは予想される故障モードのランブックを持っています.
- セキュリティレビューはキー保管,許可,ネットワーク曝露,自動化権限を対象とした.
