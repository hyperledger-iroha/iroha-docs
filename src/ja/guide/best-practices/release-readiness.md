# リリース準備 {#release-readiness}

昇進させる前に Iroha アプリケーションまたはネットワークの変更に関して、関連するリスクを明らかにできる最小の環境でその挙動を証明してください。 それから、意図的に共有テストネットおよび本番ゲートを通過する。

## ローカルネットゲート {#localnet-gate}

- 同じ Iroha トラックと、実用上最も近いバリデータ数で使い捨てのローカルネットワークを起動します。
- トランザクションビルダー、クエリ解析、拒否処理、および設定の読み込みのユニットテストを実行します。
- 後でアプリケーションが使用する同じ SDK または CLI の形状を通じて、最小限の成功した読み取りおよび書き込み経路を実行します。
- テストアーティファクトに、期待されるトランザクションの暗号ハッシュ、ステータス、イベント、および状態の読み取りを記録します。

[Iroha 3 を起動](/ja/get-started/launch-iroha.md) と [SDK チュートリアル](/ja/guide/tutorials/) を参照してください。

## 共有テストネットゲート {#shared-testnet-gate}

- API エンドポイントの動作、手数料、アカウントへの資金供給、レイテンシ、および運用リハーサルのために、Taira またはその他の共有テストネットを使用してください。
- 通常のテスト実行がネットワークの可用性に依存したり、テストネットの資金を消費したりしないように、ライブテストネットの書き込みはオプトインにしておく。
- 各ライブテスト取引を送信する前に、暗号署名者の資金、手数料資産のメタデータ、認可プリンシパルの権限、および予想される状態を確認してください。
- 終了状態を待ってから、読み取り専用クエリで結果の状態を確認してください。

[SORA 3 を基に構築する: Taira と Minamoto](/ja/get-started/sora-nexus-dataspaces.md) を参照してください。

## メインネットまたは本番ゲート {#mainnet-or-production-gate}

- 別々の本番用暗号署名者、資金、ドメイン、および設定パスを使用してください。テストネットのキーやテストネット資金サービスの仮定を推奨しないでください。
- [互換性マトリックス](/ja/reference/compatibility-matrix.md)と必要なクロス-SDK シナリオを確認します。展開で使用される正確な CLI、ネットワークピアバイナリ、構成、およびネットワークリリースを個別に固定してテストします。
- リリースウィンドウの前に、権限、料金スポンサーシップ、レート制限、監視、バックアップ状況、およびロールバック基準を確認してください。
- 高影響のある書き込みには、書面による取引または移行計画を要求する。

## ロールバックとリカバリー {#rollback-and-recovery}

- コードデプロイでロールバックできる変更、オンチェーントランザクションが必要な変更、そして直接元に戻せない変更を定義してください。
- オンチェーンデータの変更については、最初の本番書き込みの前に、補償取引やマイグレーションスクリプトを準備してください。
- ネットワークの変更については、リリース中に以前のバイナリ、設定バンドル、署名済みブロックチェーンジェネシス、および運用用ランブックを利用できる状態にしておいてください。
- 拒否率、キューの増加、レイテンシ、ネットワークピアの状態などの客観的な指標に基づいて、ロールアウトを中止するための判断ポイントを設定します。

## 最終チェックリスト {#final-checklist}

- 設定は環境ごとに異なり、テスト専用の秘密情報は含まれていません。
- トランザクションの再試行動作は冪等性があるか、明示的に制限されています。
- このアプリケーションは、拒否、期限切れ、タイムアウト、そして API エンドポイントの可用性の失敗を識別できます。
- モニタリングは、スループット、レイテンシ、キューの深さ、拒否、ビューの変更、および関連するビジネスイベントをカバーします。
- オペレーターは、予想される故障モードのための運用手順書を持っています。
- セキュリティレビューは、鍵の管理、権限、ネットワークの露出、および自動化の認可プリンシパルを対象としました。
