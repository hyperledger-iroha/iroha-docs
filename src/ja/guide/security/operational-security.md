# 運用安全 {#operational-security}

運用セキュリティ (OPSEC) は,安全とリスク管理に対する体系的なアプローチであり,基本的には不正アクセスおよびデータ漏洩を防止するための特定の使用事例に採用された戦略やアドバイスの集である.

<abbr title="Operational Security">OPSEC</abbr>は,ほとんどの企業が資産の利用性と安定性を保証するための標準慣行である.これは物理的セキュリティなどの要因を考慮することを含みます (例えば,監視されていないポスト・イットメモに敏感なデータが含まれていないことを確認すること),安全な通信プロトコル (例えば,暗号化されていない SMS で敏感なデータを送信しないこと),脅威分析 (たとえば,潜在的な悪意のある当事者を特定する,最新の攻撃方法について学ぶこと),人材訓練 (例えば,従業員が <abbr title="Operational Security">OPSEC</abbr> の措置に従わないこと).遅かれ早かれ効果がないことが証明される) とリスク軽減 (例えば,ハードディスクや USB デバイスの暗号化).

Iroha は財務本として展開される可能性が高いため, <abbr title="Operational Security">OPSEC</abbr>の措置と慣行を真剣に検討する必要があります.このトピックでは, Iroha を使用する個人や組織が業務の一環として考慮すべき戦略とアプローチについて説明します.広範なセキュリティプロトコルです

## 推奨される OPSEC 対策 {#recommended-opsec-measures}

- 警視して [可能性が高い](https://arxiv.org/pdf/2209.08356.pdf) 区块链で資産を失くす方法は 敏感な情報を出すことです.

- ディスクを暗号化します. 起動デバイスを暗号化することで,攻撃者がハードウェアにアクセスできたとしても,データを保護できます.携帯端末で行うことは2倍も重要です.

- 信頼性の高いソフトウェアを使用します. 再現可能なバイナリービルドで送信されるソフトウェアが,ソースから構築されているのが最も信頼できるものです. 監査されていない独自のまたはオープンソースのソフトウェアは,真剣に受け止めなければならない潜在的なリスクです.

- 敏感なデータを持つ携帯デバイスを監視せずに放置しないでください. 一秒間の分は,デバイスを盗むのに十分です

- バイナリーパッケージの署名を確認する.これは Iroha 内で使用されている公開鍵暗号とあまり異なるものではありません.

- 許可 さ れ ない アクセス を 防ぐ ため に,監視 さ れ て い ませ ん と し た 時 に パソコン や パソコン を 常に 安全 に 保つ こと が でき ます.強力な パスワード を 使用 し,画面 を ロック し,デバイス の 安全 に 関する 最高 的 な 慣行 を 遵守 する よう に なり ます.

- セキュリティを確立する [空気の隙間](https://en.wikipedia.org/wiki/Air_gap_(networking)まず鍵を暗号化して,オフラインデバイスに保存します理想的には電磁シールドが設置されている. [ハードウェアのキー](./storing-cryptographic-keys.md#using-a-hardware-key) 特別にこの目的のために設計されています.

- コンピュータや電話を含むすべてのデバイスでソフトウェアの最新バージョンを常に更新してください.定期的な更新は脆弱性を修正し,そのような脆弱性が明らかになる前にも,時代遅れなソフトウェアに関連する潜在的なリスクを最小限に抑えるのに役立ちます.

## ブラウザを使用する {#using-browsers}

Iroha に接続されたアプリケーションに Web UI が搭載されている場合,ブラウザはセキュリティを支援するか潜在的な脅威をもたらす可能性があります.特にインストールするプラグインに関して注意を払うことが不可欠です.

ブラウジングの安全性を高めるために以下の措置を考慮してください.

- ブラウザのセキュリティモデルが悪くてユーザーのデータを漏洩していることで知られるブラウザを使用しないでください.任意のブラウザーでプライバシー侵害やセキュリティ問題を調べることができます.例えば, [このブラウザプライバシーの記事](https://www.unixsheikh.com/articles/choose-your-browser-carefully.html)では,さまざまなブラウザとその安全性について議論します.プロプライエタリなブラウザ (Chrome,Safari,Opera,Vivaldi,Edgeなど) は,そのコードが公開から隠されているため,監査するのが一般的には非常に難しいので,それがどれほど安全なのかは分かりません.

- ユーザのプライバシーとセキュリティを評価し保護する確固たる履歴を持つブラウザを好む.
  - [Librewolf](https://librewolf.net/),[Icecat ](https://www.gnu.org/software/gnuzilla/), [Firedragon](https://github.com/dr460nf1r3/firedragon-browser),など セキュリティ機能が追加された Mozilla Firefoxの確立したフォークです.
  - [](https://github.com/ungoogled-software/ungoogled-chromium) はGoogle Chromeの高度に監査されたオープンソースバージョンで,追加的なセキュリティ対策により強化され,Googleに関連するすべてのウェブサービスを削除しています.
  - [Brave](https://brave.com/)  [Google Chromium](https://www.chromium.org/Home/) の高度に監査されたオープンソースバージョンで,追加的なセキュリティ対策により強化され,内蔵されている <abbr title="Virtual Private Network">VPN</abbr>および広告ブロック機能があります.
  - [フォークン](https://www.falkon.org/) オープンソースのQtベースのウェブブラウザ ( `QtWebEngine`, 包装用 [Google Chromium](https://www.chromium.org/Home/)) セキュリティの既知の履歴を持つ; [KDE 店舗ページ](https://store.falkon.org/browse/).
  - [クーテブラウザー](https://qutebrowser.org/) オープンソースのQtベースのウェブブラウザ ( `QtWebEngine`, 包装用 [Google Chromium](https://www.chromium.org/Home/)) が安全であるという既知の記録を持つ; シンプルなキーボードを中心としたアプローチが GUI; セキュリティ専門家の選択のブラウザとして見られています

- `JavaScript`を必要でない限り有効にしない.

- インストールされたプラグインが持つアクセス権を制限するために,ブラウザの内蔵的なプラグイン制限メカニズムを使用します.

- 重要な操作前におよび後にクッキーを消します.私をサインインし,私を覚えておく機能を有効にしないように注意してください.一部のウェブサイトにはデフォルトでこの機能が有効になっていることを忘れないでください.

- 広告ブロックを使用します.これは広告をブロックするだけでなく,サイト追跡機能も無効化します.使用しているブラウザに応じて,広告ブロックは組み込み機能ではないかもしれません.

- 似たキャラクターに注意してください (例えば `0`, `θ`, `O`, `О`, `ዐ` そして `߀` このような細部に注意を払えば フィッシング攻撃を防ぐことができます.

- Web UI 電子メール クライアントをデスクトップ クライアントに好むように避けてください.使用する前に, GPG キーサインをサインし確認するためにデスクトップメール クライアント設定してください.

- 例えば,Discord (悪名高い `electron` フレームワークで構築された) は,WebバージョンのDiscordがオープンしたGoogle Chromiumウィンドウと同じ攻撃にさらされる可能性が高い.

- 可能な限り,ブラウザを最新のバージョンに更新します.更新には脆弱性を解決する重要なセキュリティパッチが含まれます.

- ブラウザ エクステンションをインストールする際には注意してください.評判の良い情報源から知られ,信頼されるエクステンションをのみ使用します.不正な拡張子は,お客様のデータとプライバシーに危険をもたらす可能性があります.

- 異なるタスクのために別々のブラウザプロフィールを作成する.日常のブラウジングに1つのプロフィールを使用し,高度なセキュリティと敏感データを含む活動に使用します.このようにして,日常ブラウジングのためのプロフィールにインストールされた拡張子は安全なものから敏感データにアクセスできません.

- USB フラッシュドライブにコピーされたブラウザのポータブルバージョンを使用します.この方法は,セキュリティバグがインストールされたプラグインの一つにプロフィール間のデータへのアクセスを許可しても,セキュリティ関連のプロフィールは別々の取り除けるデバイスに残ることを保証します.

- ブラウザのキャッシュとクッキーを定期的に削除して,デバイスに偶然保存される可能性のある敏感なデータを削除します.

## 回復計画 {#recovery-plan}

緊急事態,例えば鍵を失う場合やセキュリティ侵害に直面した場合,十分に構造化され,事前に準備された復興計画が不可欠な救生線である.適切な手順を明確に設定することで 被害を軽減し 安全性を迅速に回復させる.

組織は,復興計画を策定する際には次の重要な側面を考慮すべきです.

- 鍵が失われる場合やその他のセキュリティ上の事故が発生した場合に従うべき段階的な手順を概説する.これらのステップはユーザーおよび/または従業員にとって容易にアクセス可能であり理解可能なことを確認する.

- セキュリティ侵害や潜在的脅威,例えば暗号鍵とパスワードが漏洩または失われたような情報を迅速に報告するために使用できる通信チャンネルを確立する.

- セキュリティ対策としてハードウェアキー (例えば, [YubiKey](https://www.yubico.com/products/)または [SoloKeys Solo](https://solokeys.com/collections/all)) を使用する場合,冗長性戦略を採用することを検討してください. 2つの鍵を保持してください: 1つは日常用であり,もう1つは安全な場所に保管されます.この予防措置は,主要な鍵が破損または失われた場合でもアクセスを確保します.

- セキュリティー の 漏洩 や 漏れ が 報告 さ れ た 時,影響 を 受け て いる キー と パスワード を 交換 し たり 無効 し たり する こと に よっ て 迅速 な 反応 を 行なう.この 積極 的 な 対応 は,潜在的な 危険 と 損害 を 最小 に 減らす こと です.

- 復旧計画を定期的にレビューし更新します. これにより,セキュリティの状況が変化するにつれて,その計画は関連的で有効なままに保証されます.

::: 警告

復旧計画が単なる文書ではないことを忘れないでください.それどころか 意外な挑戦を乗り越えるための救命線です可能性のあるシナリオを予期し,行動のための明瞭なロードマップを作成することによって,運用安全を強化し,あらゆるセキュリティインシデントに効果的に対応する準備を強化します.

:::
