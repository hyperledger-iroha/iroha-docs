# 公開鍵暗号 {#public-key-cryptography}

公開鍵暗号は関連する公開鍵と秘密鍵を使用します。公開鍵は共有できます。秘密鍵は権限者の管理下に置く必要があります。セキュリティは、サポートされているアルゴリズムを使用し、鍵を安全な乱数で生成し、秘密鍵を保護することに依存します。

## 電子署名 {#digital-signatures}

暗号署名者は秘密鍵を使ってデジタル署名を作成します。検証者は対応する公開鍵で署名を確認します。

有効な署名は、署名されたバイトが変更されておらず、かつ秘密鍵の所有者がそれを承認したことを示します。それ自体で個人を特定するものではありません。身元は、公開鍵やアカウント管理者がどのように登録され、管理されているかに依存します。

署名は、完全性と認証の証拠を提供します。署名された内容を暗号化するものではありません。

## 公開鍵暗号 {#public-key-encryption}

いくつかの公開鍵方式は、受信者の公開鍵のためにデータを暗号化します。受信者は対応する秘密鍵でそのデータを復号します。暗号化と署名は別々の操作であり、異なる鍵やアルゴリズムを使用する場合があります。

Iroha トランザクション署名は、パブリックブロックチェーンの台帳データを機密にするものではありません。ペイロードの内容を非公開にする必要がある場合は、デプロイメントで承認された機密保持メカニズムを使用してください。

## クライアント側のキー {#keys-on-the-client-side}

すべての取引は、設定されたアカウントコントローラーポリシーを満たす必要があります。単純なアカウントは1つの署名キーを使用できます。管理されたアカウントは、より複雑なコントローラーポリシーを使用できます。

クライアントソフトウェアは、秘密鍵およびその他のコントローラ素材を保護しなければなりません。平文のクライアント構成は、ローカル開発および制御されたテストのみ適しています。本番環境の統合は、シークレットマネージャー、ハードウェア支援キー保管、分離された署名サービス、またはその他の監査済み署名境界を使用する必要があります。

環境や目的ごとに別々のキーを使用してください。同じキーを再利用すると、それらの使用が結びつき、漏洩の影響が大きくなります。
