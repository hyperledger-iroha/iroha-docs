# パスワードセキュリティ {#password-security}

ブロックチェーンのセキュリティでは パスワードの保護が至关重要です. あなたのデータとその代表するすべては 無許可アクセスに守られるようにするために, パスワードの安全性の微細を深めていきましょう.

## パスワードの強さ {#password-strength}

パスワードの長さ,特殊文字の追加などといったアドバイスを伴う可能性が高い.そのような勧告はエントロピーに依存するパスワードの強さを高めることを目的としている,すなわちパスワードのランダム性.

強力なパスワードは高エントロピーのパスワードです.

パスワードのエントロピーを計算するには,エントロピーの公式に従ってください

::: tip エントロピーの公式

$L$  パスワードの長さ; パスワード内のシンボルの数.\ $S$  キャラクターセット;ユニークな可能なシンボルのプールのサイズ.\ $S^L$  可能な組み合わせの数.

$$Entropy=log_2(S^L)$$

パスワードのエントロピービットの数です 番号が高くなるほど パスワードは破解するのが難しくなります

エントロピーの値を知った場合,このエントロピーを用いてパスワードを強制するために必要な試みの量は以下の公式を使用して得ることができる.

$$S^L=2^Entropy$$

パスワードのエントロピーがどれほど高いかについては,普遍的な答えはありません.金融機関では,パスワードのエントロピーを `64` から `127` ビット (`128` ビットまたはそれ以上は一般的に過剰な殺戮とみなされる) の範囲内に保つことが推奨されています.しかし, <abbr title="Graphics Processing Unit">GPU</abbr>は絶えず進化し,パスワードクラッキングに必要な時間は時間の経過とともに減少し続けることを覚えておいてください.

:::

エントロピーの配方に従って,以下の2つの例を比較してみましょう:

  1. 16文字のパスワードは,現代の英語アルファベット (26文字) の小文字のみを使用し,$43*10^21$) 可能な組み合わせを約43x000000 (約430x0000000) に達する.

$$Entropy=log_2(26^{16})=log_2(43,608,742,899,428,874,059,776)=75.20703...$$

  2. 文字セットが96に拡張された16文字のパスワードは,大文字と特殊符号を含む可能性のある組み合わせの数を驚異的な52 nonmillion ($52*10^30$) に膨らませて,エントロピーを大幅に改善します.

$$Entropy=log_2(96^{16})=log_2(52,040,292,466,647,269,602,037,015,248,896)=105.35940... $$

見られるように,文字セットを26から96個のシンボルに拡大するだけで,悪意のある当事者が Bruteforce に必要とする可能な組み合わせの数は $1.1933*10^9$ 倍に増加した.

パスワードの長さをさらに増やすことで,可能な組み合わせの数がさらに増加し,そのためパスワードのエントロピーの強さも向上する.

しかし,複雑さに対処する代わりに, [KeePassXC](https://keepassxc.org/)のようなパスワード管理プログラムを使用することをお勧めします (詳細については, [Password Manager Program](./storing-cryptographic-keys.md#adding-a-password-manager-program)と [Configuring KeePassXC](./storing-cryptographic-keys.md#configuring-keepassxc) を参照してください. パスワードを生成して安全に保存するために.

::: トップ

一部のウェブサイトはパスワードの最大可能なエントロピーを制限します. つまり,最大限のパスワード長さや受け入れられた文字セットを制限するか両者ともです.

この ウェブサイト を 使用 する 時 に,この こと を 考慮 し て い ます.そして パスワード を 定期 的 に 更新 する よう 努め ます.

:::

## パスワードの脆弱性 {#password-vulnerabilities}

パスワードは粗暴な力攻撃の犠牲になり,通常は強力な GPUs を辞書と併用して実行するか,あらゆる可能性を通じて徹底的な繰り返す.この よう な 試み を 阻止 する ため に,生日 日,住所,電話番号,社会保障 番号 など の 個人 情報 が ない 独自の パスワード を 作る こと が でき ます.攻撃 者 たち に 容易に 推測 できる 手がかり を 提供 する こと は なく なり ませ ん.

では 現代のパスワードを破解するのはどれくらい難しいのでしょうか?

設定は [ケビン・ミットニック](https://en.wikipedia.org/wiki/Kevin_Mitnick)やってる [クラスター設定](https://twitter.com/kevinmitnick/status/1649421434899275778?s=20) 住宅 24 NVIDIA® GeForce RTX 4090年代と6年 NVIDIA® GeForce RTX 2080年代,すべて走っている [ハシュトポリス](https://github.com/hashtopolis) ソフトウェアで パスワードを破解し わずか半ヶ月で"年かかるはずだった

しかし,それを単一と比較してみましょう RTX 4090 は,300まで処理できる <abbr title="Hashes per second">H/s</abbr> 使用する [`NTLM`](https://www.tarlogic.com/cybersecurity-glossary/ntlm-hash) そして200 <abbr title="Hashes per second">H/s</abbr> 使用する [`bcrypt`](https://en.wikipedia.org/wiki/Bcrypt), 概要されているように [このツイート](https://twitter.com/Chick3nman512/status/1580712040179826688).

以前のエントロピー計算の延長として,次の予測破裂時間を調べてみましょう.

  1. $31,540,000$秒は,常規の高年ではない. 最悪のシナリオを仮定すると, `NTLM`, $300*10^9$ <abbr title="Hashes per second">H/s</abbr>の速度で単一の RTX 4090 約 $4,608.83$ 年を要して 現代英語のアルファベットの26文字の文字セットを持つ16文字のパスワードを破解します

  2. もし `NTLM` の代わりに `bcrypt` を使って,繰り返しの速度を $200*10^3$ <abbr title="Hashes per second">H/s</abbr> に減らしながら,文字セットを 96 に拡張し,大文字や特殊符号を含む場合,破解時間は約 $8,249,887,835,549,662,270.456$ 年に上昇します.宇宙の年齢を遥かに上回っています

したがって,単により高いエントロピーを選択することで,パスワードを理解できない数字に破解するのにかかる時間が増加します.はい,複数の GPUs を使用することによってプロセスは加速することができますが,この方法は [XKCD アプローチ](https://xkcd.com/538/)と比較して薄いです.

大幅な文字セットは,高エントロピーに達するために必ずしも必要ではないことを注意することが重要です.それは複数ワードのパスワード,または特に長い文を使用して得ることができます.クラシック [XKCD 漫画](https://xkcd.com/936/)はこの概念を口頭よく示しています.

::: 警告

パスワードをどこにでも書き留めるのを避ける. パスワード復旧式を安全に保存する. 文が長くなったら,それを書き留めて,後で読み出し入力できるようにしてください. 文の物理的なコピーを安全な場所に保管し/またはコンテナに.

:::
