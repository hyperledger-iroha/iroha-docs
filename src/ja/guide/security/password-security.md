# パスワードのセキュリティ {#password-security}

パスワードは、オペレーターコンソール、秘密のストア、バックアップ、およびローカルキー・ファイルを保護できます。パスワードは単なる一つの管理手段に過ぎません。利用可能な場合は、セキュアなキー管理、アクセス制御、多要素認証と併用してください。

## 独自の生成されたパスワードを使用する {#use-unique-generated-passwords}

- すべてのアカウントと環境に対して異なるパスワードを生成してください。
- パスワードマネージャーを使って、長くてランダムなパスワードを作成し、保存してください。
- 十分に大きなリストから無作為に言葉が選ばれた場合にのみ、複数語のパスフレーズを使用してください。
- 名前、日付、住所、引用文、キーボードのパターン、再利用された断片はパスワードに含めないでください。
- サービスがその方法をサポートしている場合、人間が入力したパスワードの代わりに、サービス生成のトークンまたは暗号化キーを使用してください。

長さと予測不可能性は、装飾的な置き換えよりも重要です。予測可能な単語に1つの記号を追加しただけでは、安全な結果にはなりません。

## パスワードベースのアカウントを保護する {#protect-password-based-accounts}

- 利用可能な場合は、フィッシング耐性のある多要素認証を有効にしてください。
- 繰り返される認証失敗に対して、レート制限、ロックアウトポリシー、およびアラートを適用します。
- パスワードは認証済みの暗号化されたチャネルを通じてのみ送信してください。
- パスワードや回復コードをログ、コマンドライン、ソースリポジトリ、設定ファイル、チケット、チャットに記録しないでください。
- サーバー側のパスワード検証器を、ソルト付きでメモリ負荷の高いパスワードハッシュ関数と、導入先に適したパラメータで保存してください。

## 貯蔵、回収、交換 {#storage-recovery-and-replacement}

- 監査済みのパスワードマネージャーを、暗号化され、テスト済みのバックアップと一緒に使用してください。
- 復旧コードは、それが回復するデバイスとは別に保管してください。保護されたオフラインの紙のコピーは、復旧用資料として適切な場合があります。
- パスワードマネージャーのエクスポートやバックアップメディアへのアクセスを制限する。
- 疑わしい漏洩、無許可の再利用、または交換を要求するポリシーイベントの後にパスワードを変更してください。
- 本番リリース前にアカウント復旧手順をテストしてください。

::: warning

秘密鍵を解除するパスワードは、公開されたその鍵のコピーを安全にすることはできません。秘密鍵の漏洩が疑われる場合は、配備時の鍵の交換または失効手順に従ってください。

:::
