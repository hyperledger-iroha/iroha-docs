# セキュリティの原則 {#security-principles}

An Iroha ブロックチェーン台帳は、署名された指示を検証し、権限を適用します。それは、秘密鍵、ホスト、アプリケーション、オペレーターのワークステーション、またはガバナンス手続きを保護するものではありません。展開はそれらのシステムを保護する必要があります。

これらの原則を、Iroha ネットワークの設計および運用時に使用してください。

## 認可プリンシパルをセキュリティ境界として扱う {#treat-authority-as-a-security-boundary}

- 秘密鍵を管理する個人またはプロセスは、その鍵に割り当てられた認可主体として行動することができます。
- 各環境および運用役割に対して、個別の認可プリンシパルを付与してください。
- 本番用のキーとリカバリーキーは、通常の開発やテスト用の資格情報とは分けて管理してください。
- 各認可主体の所有者、暗号署名者がどこに保管されているか、そしてどのように交換または取り消すことができるかを記録してください。

[公開鍵暗号](./public-key-cryptography.md) と [暗号鍵の保存](./storing-cryptographic-keys.md) を参照してください。

## 最小特権を適用する {#apply-least-privilege}

- 役割に必要な Iroha 権限、ホストアクセス、およびネットワークアクセスのみを付与します。
- ルーチンの取引署名を、ガバナンス、デプロイメント、および回復承認プリンシパルから分離する。
- バリデータのメンバーシップ、特権権限、または高額資産に影響を与える可能性のある変更については、独立した承認を必要とする。
- 役割の変更後にアクセスを確認し、不要になったアクセスを削除してください。

## 多層防御を使用する {#use-layers-of-protection}

- 暗号署名者、アプリケーション、オペレーティングシステム、ネットワーク、および物理的アクセスを保護してください。1つの制御に頼らないでください。
- デプロイメントに必要な Torii、ネットワークピア、モニタリング、およびアプリケーションルートのみを公開してください。
- 管理者アクセスおよび機密データには、認証済みで暗号化されたチャネルを使用してください。
- システムにパッチを適用し、展開で使用されないサービスを無効にしてください。
- 秘密はソース管理、コマンドライン、ログ、チケット、チャット、公開ドキュメントから外しておくこと。

## 展開をレビュー可能にする {#make-deployments-reviewable}

- 秘密でない設定とデプロイ自動化をバージョン管理に保持してください。
- バイナリ、設定、ブロックチェーンのジェネシスマテリアル、バリデータのメンバーシップ、権限、および公開ルートの変更を確認してください。
- 展開前にリリース成果物を確認してください。承認されたバージョンと暗号ハッシュを記録します。
- 本番環境で実行される正確なバイナリと構成の組み合わせをテストする。
- ネットワークの決定論的な動作を維持する。ハードウェアアクセラレーションは、ピアに見える結果を変更してはならない。

## 証拠を監視して保存する {#monitor-and-preserve-evidence}

- ネットワークピアの状態、コンセンサスの進行、権限の変更、特権命令、認証失敗、および予期しない構成の変更を監視します。
- 影響を受けたホストに依存しないシステムに重要な警告を送信する。
- 関連するログ、ブロックチェーンの台帳参照、構成データのスナップショット、および取引の暗号ハッシュを信頼できるタイムスタンプとともに保存してください。
- モニタリングデータの欠落は、調査が必要な運用上の問題として扱うべきです。

## 起動前にリカバリを準備する {#prepare-recovery-before-launch}

- インシデントを宣言できる人物と、復旧措置を承認できる人物を定義する。
- バックアップ、復元、鍵の交換、権限の取り消し、およびネットワークピアの回復手順をテストする。
- インシデント発生時に、信頼できるリリース成果物、構成、ブロックチェーンのジェネシス記録、および在庫を利用可能な状態にしておく。
- まず読み取りと監視を復元してください。回復したネットワークと依存するアプリケーションがチェックに合格した後にのみ、書き込みを再開してください。
- すべてのインシデントを確認し、コントロール、オートメーション、および演習を更新する。

::: warning

ブロックチェーンの台帳上の操作は元に戻せない場合があります。回復やガバナンスのトランザクションを提出する前に、事前に確認された手順と必要な承認を使用してください。

:::
