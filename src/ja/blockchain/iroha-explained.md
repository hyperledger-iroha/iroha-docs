# Iroha 説明 {#iroha-explained}

Iroha 3 は最初のリリースです Hyperledger Iroha 同じコアでは自主ホストのネットワークと SORA Nexus データスペースと多レーンルーティングの実行モデル.

## 主要な建材 {#core-building-blocks}

- `irohad` 仲間を運営する
- Torii はクライアントとオペレーターのゲートウェイです
- Sumeragi は共感を扱う
- Norito は[カノニカルバイナリフォーマット](/ja/reference/norito.md)である
- IVM は携帯スマートコントラクトとバイトコードを実行します
- Kotodama 高級のコンパイル `.ko` 契約 IVM `.to` バイトコード
- Kagami は鍵,生成,プロフィール,ローカルネットを準備する
- SORA Nexus サービス機を追加する Soracloud, インルー SoraNet, SoraFS, そして SoraDNS アプリのホスティング,プライバシー輸送,ストレージ,命名

## 実行モデル {#execution-model}

トランザクションには 指示が載っているか IVM バイトコードと Torii 顧客がそれを提出したり,その効果を観察したりする主な方法です.

- Nexus - 意識の設定は複数のレーンを定義できます
- データスペースは,同じレジャーモデルの一部でありながら,ワークロードを分離します.
- ルーティング方針は,どのレーンとデータスペースが作業クラスの処理を行うかを決定します.

## 多データ空間アーキテクチャ {#multi-dataspace-architecture}

データスペースは,別々のブロックチェーンではなくルーティングとネームスペースの境界である.ランタイムにはまだ`World`,トランザクションモデル,1つ,コンセンサスパイプラインがある. Nexus はノードに列間のパーティション作業やその列が提供するデータスペスの名前付け方法を伝えるカタログを追加します.

実行時に,データスペースは数値的な `DataSpaceId` とカタログのメタデータで表現されます. `DataSpaceId::UNIVERSAL` は `0` として予約されています.デフォルトカタログには `universal` データスペースが含まれています.各構成されたデータ空間には:

- 単一の番号 ID
- `universal`,`governance`,または `zk`などのユニークな名前です.
- 操作者の表面のオプション説明
- リレー委員会を測定するために使用されたゼロでない値 `fault_tolerance`

レーンは,これらのデータデータベースに繋がる実行およびストレージ経路である. `LaneId`, について `DataSpaceId` 匿名で,可視性 (`public` または `restricted`),保管プロフィール (`full_replica`, `commitment_only`, または `split_replica`),証明システム,およびオプションのガバナンス,決済,スケジュールメタデータ.走行時間は,このカタログから各レーンのストレージジオメトリーを導き出します. Kura セクション名と決定的なキープレフィックス.

経路は:

1. コンフィギュレーションは検証された `DataSpaceCatalog`, `LaneCatalog`,および`LaneRoutingPolicy`を構築する.複数のレーン,複数のデータスペス,またはデフォルトでないルーティングが要求される `nexus.enabled = true`.
2. トランザクションキューでは,アクティブレーンルーターから `RoutingDecision` を求め,レーン ID とデータスペース ID を含む.
3. 明確なルーティングルールは,権限/アカウントまたは指示ラベルによって一致することができます.一致するルールなしでは,ルーターはドメイン IDs,資産定義予測,データスペーススケープの許可,決済脚本,または当局の拘束されたアカウント範囲からデータ領域を導き出すことができます.
4. 解消された経路は両方のカタログに対して確認されます.未知の行列,未知データ領域,およびレーン/データ領域の不一致は決定的なルーティングエラーです.取引が2つの異なるデータ空間目標に書き込まれる場合,相互矛盾するルートとして拒否され,クロスデータスペース DVP/PVP 決済は普遍的なコーディネーターレーンを通る.
5. Sumeragi とテレメトリは,レーンおよびデータスペースの活動,バックログ,コミットメントの瞬時に割り当てを可視化します.

そのため,オブジェクト識別子は重要である.ドメインには ID のデータスペースの別名が含まれます.例えば `payments.universal` で,ドメインスケープによる書き込みがルーティングできます.アカウントはカノニカルでありドメインレスであり,同じアカウントが `AccountId` を変更せずに異なるアプリケーションスケープに結びつけることができます.アセット定義は,ドメイン/データスペースのプロジェクションを搭載し,資産操作が正しいデータ空間経路を継承できるようにします.

Nexus のオーバーライドがないと,ノードは単行列と `universal` データスペースを使用します.バンドルされた SORA プロファイルは,3行列のカタログで置き換えられます:`core`は通用公路, `governance`はガバナンストラフィック,および `zk`はゼロ知識の接続と契約部署トラフィック.

これらの3つのデフォルトは,作業負荷のクラスを分離するために存在する.

|データの空間|レーン|なぜ存在するのか|
| ------------ | ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------- |
|`universal`|`core`|通常の公共レジャートラフィックおよびバックバックルーティングのために預設されたデフォルトデータ空間 (`DataSpaceId::UNIVERSAL == 0`) |
|`governance`|`governance`|管理と議会交通は制限されているため,制御平面の活動は一般的な適用書に混同されない. |
|`zk`|`zk`|ゼロ知識証明,添付,および契約部署のルーティングのために制限されたレーンで,証明重なワークフローを通常の書き込みから分離します.|

唯一 `universal` 予約したベースラインです `governance` そして `zk` は SORA バンダリングされたカタログとルーティングポリシーにコード化されたプロフィール選択操作者は,異なるデータスペースの境界線を必要とする場合,別のカタログを定義できます.

Sumeragi は常にデータ利用性と信頼性の高い放送を使用します.これらの経路は Iroha 3 合意プロトコルの一部であり,デプロイメントプロファイルによって無効化できません.

実行時の動作は,構成ファイルやチェーン上のパラメータから得られます.環境変数は生産機能ゲートではありません.
