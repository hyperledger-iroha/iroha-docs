# Iroha 説明済み {#iroha-explained}

Iroha 3 は、初回リリースの Hyperledger Iroha プラットフォームです。同じコアがセルフホスト型ネットワークと、データスペースおよびマルチレーンルーティング用の SORA Nexus 実行モデルをサポートします。

## コアビルディングブロック {#core-building-blocks}

- `iroha3d` はネットワークピアを実行します
- Torii はクライアントおよびオペレーターゲートウェイです
- Sumeragi はコンセンサスを処理します
- Norito は [標準的バイナリ形式](/ja/reference/norito.md) です
- IVM はポータブルスマートコントラクトとバイトコードを実行します
- Kotodama は高水準の `.ko` コントラクトを IVM `.to` バイトコードにコンパイルします
- Kagami はキー、ブロックチェーンのジェネシス、プロファイル、およびローカルネットを準備します
- SORA Nexus サービスプレーンは、アプリホスティング、プライバシー転送、ストレージ、ネーミングのために Soracloud、Inrou、SoraNet、SoraFS、および SoraDNS を追加します

## 実行モデル {#execution-model}

世界の状態へのすべての変更は依然としてトランザクションを通じて行われます。トランザクションは命令または IVM バイトコードを運び、Torii はクライアントがそれらを送信したり、その効果を観察したりする主な方法です。

- データスペースは、機関のデータ、権限、ポリシー、アプリケーションのための環境を提供する
- レーンは、その環境内でルーティングと認証の処理能力を提供する
- 独立して署名されたデータスペースのルートが、独自の State とローカルなファイナリティを管理する

## データスペースと実行ルート {#multi-dataspace-architecture}

データスペースのカタログ項目は、環境とその識別情報を定義します。カタログ項目だけでは、独立した実行ルートは確立されません。公開レーンは、グローバルチェーンが実行するトランザクションバッチを認証します。一方、独立して署名されたデータスペースのルートは、独自の State、委員会、ローカルなファイナリティを持ちます。

`DataSpaceCatalog` はデータスペースを、`LaneCatalog` はレーンを定義します。各レーンは `dataspace_id` を通じて厳密に一つのデータスペースを参照し、一つのデータスペースには複数のレーンを含められます。`DataSpaceId` と `LaneId` は異なる識別子です。レーンのエイリアスによって別のデータスペースが作られるわけではありません。

実行時には、数値の `DataSpaceId` とカタログのメタデータでデータスペースを表します。`DataSpaceId::UNIVERSAL` には `0` が予約されており、既定のカタログには `universal` データスペースが含まれます。設定された各データスペースは次を持ちます。

- ユニークな数値ID
- `universal` や明示的に登録された機関名など、一意のエイリアス
- オペレーターサーフェスの任意の説明
- リレー委員会のサイズを決定するために使用されるゼロでない `fault_tolerance` 値

レーンは、それらのデータスペースに結び付いた、ルーティングと認証のための資源です。レーンの項目には、`LaneId`、そのレーンが属する `DataSpaceId`、エイリアス、可視性（`public` または `restricted`）、ストレージプロファイル（`full_replica`、`commitment_only`、`split_replica` のいずれか）、証明方式、および任意のガバナンス・決済・スケジューラーのメタデータが含まれます。実行環境は、このカタログからレーンごとのストレージ構成を導出します。これには Kura のセグメント名と決定論的なキー接頭辞が含まれます。

ルーティングパスは次のとおりです：

1. 設定から、検証済みの `DataSpaceCatalog`、`LaneCatalog`、`LaneRoutingPolicy` を構築します。SORA Nexus のルーティングは必須です。複数のデータスペースやレーン、または既定と異なるルーティングには、SORA Nexus プロファイル（`--sora`）と NPoS を使います。
2. トランザクションキューは、トランザクションとコミット済み状態から `RoutingPlan` を決定します。各コーディネーター経路と参加者経路には、レーン ID とデータスペース ID が含まれます。Native AMX プランは、参加者の集合全体を保持します。
3. グローバル実行では、完全な制御プレーンのバッチと、データスペースをまたぐコーディネーターがレーン `0` を使います。命令やコントラクトアドレスがユニバーサル以外の具体的な対象を指定する場合は、アカウント規則や命令ラベル規則より先に、対象のデータスペースと委員会に一致する、受け入れ済みの固定レーンを選びます。それ以外の処理はコミット済みの明示的な規則と既定のシャーディングに従います。具体的なユニバーサルの対象は、ユニバーサルのレーン内に留まります。
4. 各経路をカタログと稼働中レーンの状態に照らして検証します。不明な ID やレーンとデータスペースの不一致は拒否されます。利用できないプライベートの対象を、ユニバーサル実行に切り替えることはできません。複数のデータスペースを対象とする処理は、Native AMX プランを生成できます。トランザクションのメタデータ `amx_policy` が `reject_cross_dataspace` の場合は、データスペースをまたぐプランを拒否します。ルーティングプランだけでは、独立したルート間の決済は認可も完了もされません。
5. Sumeragi とテレメトリにより、レーンやデータスペースの稼働状況、未処理量、コミットメントのスナップショットとして、割り当て状況を確認できます。

オブジェクト識別子が重要なのはこのためです。ドメインの ID には、`payments.universal` のようにデータスペースのエイリアスが含まれるので、ドメインに属する書き込みの経路を決定できます。アカウントの識別子は正規形式でドメインを含まないため、同じアカウントの `AccountId` を変えずに、異なるアプリケーションの範囲へ関連付けられます。資産定義にはドメインとデータスペースへの対応付けを保持できるため、資産操作は正しいデータスペースの経路を引き継げます。

SORA Nexus の設定を上書きしない場合、ノードは単一のレーンと `universal` データスペースを使います。同梱の SORA Nexus プロファイルでは、これを三つのレーンを持つカタログに置き換えます。`core` はユニバーサルの公開レーン、`governance` はガバナンスの通信、`zk` はゼロ知識証明の添付データとコントラクト配備の通信を扱います。

同梱される三つのレーンはすべて公開で、同じ `universal` データスペースを参照します。これらは処理の種類を分けるためのものです。

| データスペース | レーン | 目的 |
| ------------ | ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| `universal` | `core` | 通常の公開台帳の通信と既定のルーティング。 |
| `universal` | `governance` | 公開のガバナンスと SORA Parliament の通信。 |
| `universal` | `zk` | 公開のゼロ知識証明の添付データとコントラクト配備の通信。 |

`DataSpaceId::UNIVERSAL == 0` は予約された基準です。上記の `governance` と `zk` はレーンの名前であり、別々のデータスペースではありません。機関ごとに境界を分けるには、明示的なデータスペース項目が必要です。独立して実行するには、さらに独立して認証されたルートが必要です。

これらの関係は、固定されたソースの[プロファイル構築処理](https://github.com/hyperledger-iroha/iroha/blob/c8c872461e92f04325c350cdd952f4276e96f9dc/crates/iroha_config/src/parameters/actual.rs)、[レーン実装](https://github.com/hyperledger-iroha/iroha/blob/c8c872461e92f04325c350cdd952f4276e96f9dc/crates/iroha_core/src/sumeragi/lanes/mod.rs)、[独立ルートの仕様](https://github.com/hyperledger-iroha/iroha/blob/c8c872461e92f04325c350cdd952f4276e96f9dc/specs/sumeragi.md)で定められています。

Sumeragi は常にデータの利用可能性と信頼できるブロードキャストを使用します。これらの経路は Iroha 3 コンセンサスプロトコルの一部であり、デプロイメントプロファイルによって無効にすることはできません。

ソフトウェアの実行時の動作は、設定ファイルとオンチェーンのパラメータから生成されます。環境変数は本番の機能ゲートではありません。
