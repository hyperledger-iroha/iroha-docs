# Iroha 説明済み {#iroha-explained}

Iroha 3 は、初回リリースの Hyperledger Iroha プラットフォームです。同じコアがセルフホスト型ネットワークと、データスペースおよびマルチレーンルーティング用の SORA Nexus 実行モデルをサポートします。

## コアビルディングブロック {#core-building-blocks}

- `iroha3d` はネットワークピアを実行します
- Torii はクライアントおよびオペレーターゲートウェイです
- Sumeragi はコンセンサスを処理します
- Norito は [標準的バイナリ形式](/ja/reference/norito.md) です
- IVM はポータブルスマートコントラクトとバイトコードを実行します
- Kotodama は高水準の `.ko` コントラクトを IVM `.to` バイトコードにコンパイルします
- Kagami はキー、ブロックチェーンのジェネシス、プロファイル、およびローカルネットを準備します
- SORA Nexus サービスプレーンは、アプリホスティング、プライバシー転送、ストレージ、ネーミングのために Soracloud、Inrou、SoraNet、SoraFS、および SoraDNS を追加します

## 実行モデル {#execution-model}

世界の状態へのすべての変更は依然としてトランザクションを通じて行われます。トランザクションは命令または IVM バイトコードを運び、Torii はクライアントがそれらを送信したり、その効果を観察したりする主な方法です。

- Nexus 対応の構成は、複数の実行レーンを定義することができます
- データスペースは、同じブロックチェーン台帳モデルの一部でありながら、ワークロードを隔離します
- ルーティングポリシーは、ある作業クラスをどの実行レーンとデータスペースが処理するかを決定します

## マルチデータスペースアーキテクチャ {#multi-dataspace-architecture}

データスペースはルーティングおよび名前空間の境界であり、別のブロックチェーンではありません。ソフトウェアランタイムには依然として1つの `World`、1つのトランザクションモデル、1つのコンセンサスがありますソフトウェア処理ワークフロー。Nexus は、ノードが実行レーン間で作業をどのように分割するか、またその実行レーンが提供するデータスペースにどのように名前を付けるかを指示するカタログを追加します。

ソフトウェアの実行時に、データスペースは数値の`DataSpaceId`とカタログメタデータによって表されます。`DataSpaceId::UNIVERSAL`は`0`として予約されています。デフォルトのカタログには`universal`データスペースが含まれています。設定された各データスペースには次のものがあります:

- ユニークな数値ID
- たとえば `universal`、`governance`、または `zk` のようなユニークなエイリアス
- オペレーターサーフェスの任意の説明
- リレー委員会のサイズを決定するために使用されるゼロでない `fault_tolerance` 値

実行レーンは、それらのデータスペースに結び付けられた実行およびストレージのルートです。実行レーンのエントリには`LaneId`、それが提供する`DataSpaceId`、エイリアス、可視性（`public`または`restricted`）、ストレージプロファイル（`full_replica`、`commitment_only`、または`split_replica`）、証明スキーム、およびオプションのガバナンスが含まれます。金融取引の決済およびスケジューラのメタデータ。ソフトウェアのランタイムは、このカタログから各レーンのストレージ構成を導出し、Kura セグメント名および決定論的キー接頭辞を含みます。

ルーティングパスは次のとおりです：

1. 構成は、検証済みの `DataSpaceCatalog`、`LaneCatalog`、および `LaneRoutingPolicy` を構築します。複数の実行レーン、複数のデータスペース、または非デフォルトのルーティングには `nexus.enabled = true` が必要です。
2. トランザクションキューは、実行レーンIDとデータスペースIDを含む`RoutingDecision`を求めてアクティブな実行レーンルーターに問い合わせます。
3. 明示的なルーティングルールは、権限／アカウントまたは指示ラベルによって一致させることができます。一致するルールがない場合、ルーターはドメインID、資産定義の投影、データスペースに限定された権限、金融転送部分、または認可プリンシパルに紐付けられたアカウント範囲からデータスペースを導き出すことができます。
4. 解決されたルートは両方のカタログで確認されます。未知の実行レーン、未知のデータスペース、レーン／データスペースの不一致は決定論的ルーティングエラーです。ある取引が二つの異なるデータスペースターゲットに書き込もうとすると、競合ルートとして拒否されます；データスペース間の DVP/PVP 金融取引決済は、ユニバーサルコーディネーター実行レーンを通じてルーティングされます。
5. Sumeragi とテレメトリは、実行レーンおよびデータスペースの活動、バックログ、および暗号化コミットメント値のスナップショットとして課題を可視化したままにします。

これがオブジェクト識別子が重要である理由です。ドメインには、例えば `payments.universal` のように ID にデータスペースのエイリアスが含まれているため、ドメインスコープの書き込みをルーティングすることができます。アカウントは引き続き標準的でドメインレスです。したがって、同じアカウントをその`AccountId`を変更せずに異なるアプリケーション範囲に紐付けることができます。アセット定義はドメイン/データスペースの投影を持つことができ、これによりアセット操作が正しいデータスペース経路を継承することができます。

なし Nexus オーバーライドの場合、ノードは単一の実行レーンを使用し、そして `universal` データスペース。バンドルされた SORA プロファイルはそれを三車線のカタログに置き換えます: `core` 一般公開処刑専用車線のために、 `governance` ガバナンスのトラフィック、および `zk` ゼロ知識のアタッチメントおよび契約デプロイメントのトラフィック用です。

これらの3つのデフォルトは、ワークロードクラスを分けるために存在します:

|データスペース|実行レーン|なぜそれが存在するのか|
| ------------ | ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| `universal` |`core`|通常の公共ブロックチェーン台帳トラフィックおよびフォールバックルーティングのための予約済みデフォルトデータスペース（`DataSpaceId::UNIVERSAL == 0`）。|
| `governance` | `governance` |ガバナンスおよび議会のトラフィック専用の制限実行レーンのため、コントロールプレーンの活動が一般のアプリケーションの書き込みと混ざらないようになっています。|
| `zk`         |`zk`|ゼロ知識証明、添付ファイル、および契約デプロイのルーティングのための制限付き実行レーンであり、証明が重いワークフローを通常の書き込みから分離します。|

唯一の予約済みベースラインは `universal` です。`governance` と `zk` は、バンドルされたカタログおよびルーティングポリシーにエンコードされた SORA プロファイルの選択肢です；オペレーターは異なるデータスペース境界が必要な場合に、異なるカタログを定義できます。

Sumeragi は常にデータの利用可能性と信頼できるブロードキャストを使用します。これらの経路は Iroha 3 コンセンサスプロトコルの一部であり、デプロイメントプロファイルによって無効にすることはできません。

ソフトウェアの実行時の動作は、設定ファイルとオンチェーンのパラメータから生成されます。環境変数は本番の機能ゲートではありません。
