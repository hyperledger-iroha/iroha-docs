# Համացանցի տեղակայումը {#network-deployment}

Iroha ցանցին վերաբերվեք որպես համակարգված համակարգ: Վալիդատորները պետք է համաձայնվեն գենեզի, տոպոլոգիայի, վստահելի զուգընկերների եւ կոնսենսուսի հետ կապված կազմավորումների վերաբերյալ, նախքան ցանցը կարողանա սկսել եւ շարունակել վերջնականացնել բլոկերը:

## Շրջակա միջավայրի բաժանում {#environment-separation}

- Կառավարել տեղական զարգացման, ընդհանուր թեստային ցանցի, բեմադրման եւ արտադրության համար առանձին կոնֆիգերի փաթեթներ:
- Ստեղծեք նոր բանալիներ յուրաքանչյուր ոչ մի օգտագործման միջավայրի համար: Չօգտագործեք արտադրության ժամանակ տեղական ցանց կամ Taira բանալիր նյութը:
- Պահպանեք զուգընկերների config, հաճախորդի config, ստորագրված գեներեզը, սցենարները եւ տեղաբաշխման գրառումները միասին ՝ որպես տարբերակային թողարկման արվեստախաղ:
- Պահպանեք գաղտնի բանալիները պահեստների եւ տեղակայման ձեւանմուշներից դուրս:

Նայեք [Աջակցային տեղակայման բանալիները ](/hy/guide/configure/keys-for-network-deployment.md).

## Ծննդոց եւ տոպոլոգիա {#genesis-and-topology}

- Թույլ տվեք, որ յուրաքանչյուր վավերացնող օգտագործի նույն ստորագրված գեներիզ գործարքը, վստահելի զուգընկերների հավաքածու, տոպոլոգիա եւ վավերացնողը Պրոֆիլը պահանջում է դրանք:
- Օգտագործեք առնվազն չորս վավերացնողներ ՝ նվազագույն բիզանտական սխալների հանդուրժողական տեղակայման համար:
- Հզորության պլանավորման մեջ դիտորդներից առանձին վավերացնողներ. դիտորդները չեն քվեարկում, առաջարկում կամ հավաքում, բայց նրանք դեռ օգտագործում են պահեստավորում, բլոկ սինկրոնիկացում եւ ցանցի թողունակություն:
- Բարեւեք գենեզի, կատարողի եւ տոպոլոգիայի փոփոխությունները որպես համակարգված միգրացիաներ, այլ ոչ թե մեկ զուգընկերային խմբագրություններ:

Դիտեք [Ծննդոց](/hy/reference/genesis.md), [Ընկերների կառավարում](/hy/guide/configure/peer-management.md) եւ [Աշխատանքային եւ չափանիշային ցուցանիշներ](/hy/guide/advanced/metrics.md#node-count-and-quorum).

## Torii եւ ցանցային հասանելիություն {#torii-and-network-access}

- Torii տեղադրեք հակառակ պրոկսի կամ կրակոցային պատի հետեւում, երբ այն բացված է հյուրընկալողից կամ մասնավոր ցանցից դուրս:
- Սեղմեք TLS եւ կիրառեք հիմնարար հավաստագրման, արագության սահմանափակման եւ պահանջի չափերի վերահսկողությունը ծայրում, երբ դրանք անհրաժեշտ են տեղակայման համար:
- Միայն շրջակա միջավայրի համար անհրաժեշտ ավարտական կետերը հրապարակեք: Օպերատորների եւ հեռաչափության երթուղիները պետք է ավելի սահմանափակ լինեն, քան հանրային միայն ընթերցման երթուղները:
- Կապակցեք լսողի հասցեները հյուրընկալող-տեղական ինտերֆեյսների հետ, երբ զուգահեռները չպետք է ուղղակիորեն ընդունեն հեռավոր երթեւեկությունը:

Տես [Torii Վերջնական կետերը](/hy/reference/torii-endpoints.md) եւ [ Վիրտուալ մասնավոր ցանցեր ](/hy/guide/security/vpn.md).

## Համաձայնություն եւ հզորություն {#consensus-and-capacity}

- Համաձայնության ժամացույցները հարմարեցնելուց առաջ չափեք տեղադրումը: Ավելի ցածր ժամանակահատվածները կարող են նվազեցնել ուշացումը միայն այն ժամանակ, երբ ցանցի, պահեստավորման եւ կատարման շերտերը հետեւում են.
- Պահպանեք հերթի ուղղությունը, ոչ թե պարզապես թողունակության կարճ նմուշները: Այն հերթը, որը աճում է կայուն լիցքավորման ընթացքում նշանակում է, որ ցանցը գերբեռնված է:
- Տեղեկացրեք Sumeragi արդյունավետ պարամետրերը, հեռաչափության պրոֆիլը, վավերացնողների թիվը, ցանցը RTT, աշխատանքային բեռնվածության ձեւը եւ յուրաքանչյուր ստանդարտի համար սարքավորման մանրամասները:
- Բարձրացնել հավաքիչի ֆանոուտը միայն լատենցիայի, երթեւեկության եւ հետընթաց ճնշման ազդանշանների համեմատելուց հետո:

Նայեք [Ապահողության եւ չափանիշների ցուցանիշները ](/hy/guide/advanced/metrics.md).

## Պարզ մետաղների եւ գործընթացների կառավարումը {#bare-metal-and-process-management}

- Պահեք յուրաքանչյուր զուգընկերոջ `config.toml`, գաղտնի բանալին, պահեստային அடைը եւ նավահանգիստները առանձին:
- Օգտագործեք գործընթացների կառավարիչներ, ինչպիսիք են systemd ՝ բացարձակ վերսկսման, գրանցման եւ ռեսուրսային քաղաքականության հետ:
- Պահպանել ստեղծված README եւ սկսել հրամանները Kagami localnet փաթեթներից, երբ թարգմանում է փորձարկման տոպոլոգիան կառավարվող հյուրընկալողներ.

Նայեք [Գործողություն Iroha Bare Metal](/hy/guide/advanced/running-iroha-on-bare-metal.md)
