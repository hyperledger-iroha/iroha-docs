# Գործարքներ {#transactions}

Գործարքը ստորագրված խնդրանք է բլոկչեյնի վրա աշխատանք կատարելու համար: Գործադրելի օգտակար բեռը կարող է լինել [ հրահանգների կարգավորված հաջորդականություն ](./instructions.md), պայմանագրի զանգ, IVM բայթ կոդ կամ ապացուցված IVM գործարկում: [Հիմնական պայմանագրերի կատարման մոդելի համար դիտարկեք ](./smart-contracts.md):

Գործարքները կատարում են վիճակը փոխող կամ իրականացվող աշխատանքներ: Միայն ընթերցված ստուգումը օգտագործում է ստորագրված հարցումներ կամ հանրային ընթերցման վերջ կետեր եւ չի ստեղծում գործարք:

Պայմանավորված բլոկի մեջ ընդունված գործարքը պահվում է իր կատարման արդյունքով, ներառյալ կատարման մերժումը: Բլոկի մուտքագրումից առաջ մերժված դիմումները, ինչպիսիք են անվավեր փաթեթը կամ հերթով մերժված գործարքն, չեն պահվում բլոկում:

Գաղտնիությունը պահպանող ակտիվների տեղաշարժի համար դիտեք [ Անանուն գործարքներ](./anonymous-transactions.md). Անանուն փոխանցումները օգտագործում են պաշտպանված ակտիվներ, պարտավորություններ, չեղյալ հայտարարիչներ եւ զրոյական գիտելիքների ապացույցներ, փոխարենը հանրային հաշիվ-հաշվի մնացորդի փոփոխությունները։

Ընտրված թափանցիկ կատարման արդյունքների ապացույցների համար տես [FastPQ](./fastpq.md)-ը։ FastPQ-ն սովորական գործարքի կատարումից հետո օգտագործում է կատարման վկաները և աջակցվող վիճակի անցումների համար կազմում deterministic proof batch-եր։

## Փորձեք այն Taira {#try-it-on-taira}

Օգտագործեք Explorer երթուղիները՝ առանց ստորագրման հաշիվի վերջին հանրային Taira բլոկների եւ գործարքների կարգավիճակի ստուգման համար.

```bash
curl -fsS 'https://taira.sora.org/v1/explorer/blocks?page=1&per_page=3' \
  | jq '{pagination, blocks: [.items[] | {height, hash, transactions_total, transactions_rejected}]}'

curl -fsS 'https://taira.sora.org/v1/explorer/transactions?page=1&per_page=5' \
  | jq '{pagination, txs: [.items[] | {hash, block, status, executable}]}'
```

Որպեսզի հետեւեք ձեր հավելվածի ավելի վաղ ներկայացրած գործարքին, պատճենեք `hash` ցուցակից եւ ստուգեք Explorer- ի մանրամասն երթուղին.

```bash
TX_HASH='<transaction-hash>'

curl -fsS "https://taira.sora.org/v1/explorer/transactions/$TX_HASH" \
  | jq '{hash, block, status, authority, executable}'
```

Սա դեռ միայն ընթերցման գործողություն է։ Գործարք ուղարկելը պահանջում է ստորագրված Norito ծրար, ճիշտ շղթայի ID և ցանցի ID, բացահայտ վճարող և փորձնական միջոցների տրամադրման ծառայությամբ ֆինանսավորված Taira հաշիվ։

Taira-ում վճարովի օրինակների համար ֆինանսավորեք ստորագրող հաշիվը [Ստանալ փորձնական XOR Taira-ում](/hy/get-started/sora-nexus-dataspaces.md#_4-get-testnet-xor-on-taira) բաժնի նախապես պատրաստվող միջոցների ստացման հոսքով, ապա ստուգեք վճարային ակտիվի մնացորդը․

```bash
export TAIRA_ACCOUNT_ID='<TAIRA_I105_ACCOUNT_ID>'
export TAIRA_FEE_ASSET="$(
  curl -fsS https://taira.sora.org/v1/accounts/faucet/policy \
    | jq -er '.asset_definition_id'
)"

iroha --config ./taira.client.toml ledger asset get \
  --definition "$TAIRA_FEE_ASSET" \
  --account "$TAIRA_ACCOUNT_ID"
```

Եթե փորձնական միջոցների տրամադրման երթուղին վերադարձնում է `502`, սպասեք և կրկին փորձեք՝ մինչև բուն գործարքի վրիպակները փնտրելը։

Այնուհետև գործարքն ուղարկելիս ընտրեք վճարողին։ `--fee-payer authority`-ի դեպքում վճարում է ստորագրող հաշիվը, իսկ CLI-ն ստորագրելուց առաջ հաշվարկում և ցույց է տալիս ճշգրիտ վճարը՝ Taira-ի վճարային ակտիվով․

```bash
iroha --config ./taira.client.toml \
  --fee-payer authority \
  tx ping --msg "faucet-funded taira transaction"
```

## Անցանց գործարքներ {#offline-transactions}

Iroha ունի երկու անջատված գործարքների աշխատանքային հոսք.

- Offline ստորագրումը ստեղծում է սովորական ստորագրված գործարք, մինչ ստորագրող սարքը անջատված է: Գործարքը չի մշակվում, քանի դեռ առցանց հաճախորդը ստորագրված փաթեթը չի ներկայացրել Torii, այնպես որ այն դեռ պետք է ճիշտ շղթան ID, լիազորություն, թույլտվություններ, վճարներ եւ գործարքի կյանքի տեւողությունը:
- **Kagemusha անցանց կանխիկը** առցանց եղած գրանցված, ապարատային պաշտպանությամբ դրամապանակում բեռնում է արժեք, աջակցում է դրամապանակների միջև վճարումներին, երբ երկուսն էլ անցանց են, և դրամապանակը կրկին առցանց դառնալիս մնացած արժեքը բեռնաթափում է գրանցամատյանի հաշվի վրա։

Torii-ն տրամադրում է մեկ Kagemusha երթուղի՝ `POST /v1/kagemusha/enrollment`։ Այն ընդունում է հաշվով նույնականացված `application/x-norito` գրանցման շրջանակներ և վերադարձնում է մասնավոր պատասխաններ, որոնք չպետք է քեշավորվեն։ Կյանքի ցիկլի գրանցամատյանի կողմն օգտագործում է սովորական ստորագրված գործարքներ, որոնք կրում են `KagemushaWalletLedgerV1` հրահանգ․

| Գործողություն | Նպատակ |
| --- | --- |
| `Activate` | Ակտիվացնել գրանցված դրամապանակը․ հարթակի բնիկ սկզբնապատրաստման ստուգումը պարտադիր է |
| `IssueLoad` | Գումարը հանել վճարողից և ատոմային կերպով գրանցել դրամապանակի հաջորդ Load-ը |
| `Unload` | Ամբողջական Unload պահանջը վճարել դրան կապված հաշվին՝ առավելագույնը մեկ անգամ |
| `ClaimFee` | Ամբողջական վճարի պահանջը վճարել դրա ֆիքսված շահառուին |
| `Abandon` | Հրաժարվել չօգտագործված գրանցումից |

Տիպիկ հոսքը հետեւյալն է.

1. Տիպավորված միջերեսով Swift կամ Android դրամապանակով գրանցվեք `/v1/kagemusha/enrollment`-ի միջոցով, ապա ակտիվացրեք դրամապանակը։
2. Ուղարկեք `IssueLoad` գործարք։ Կատարումը ստուգում է սպասվող հաջորդ Load-ի հերթական համարը և ոչ զրոյական հարցման ID-ն, ուստի հնացած կամ փոփոխված կրկնակի փորձը ձախողվում է։ Պատասխանի կորստից հետո կարդացեք սկզբնական Load անդորրագիրը՝ այլ Load ստորագրելու փոխարեն։
3. Դրամապանակները անցանց եղած ժամանակ տեղում փոխանակեք և ստուգեք դրանց միջև վճարումները, իսկ յուրաքանչյուր փոխանցումը հաստատելուց առաջ կայուն պահեք դրամապանակի վիճակը։
4. Երբ դրամապանակը կրկին առցանց է, ուղարկեք դրա Unload պահանջը և սպասեք վերջնականացմանը։

Մատյանը չի կարող հայտնաբերել հակասող անցանց փոխանցումը, մինչև նոտայի վիճակը չվերադառնա առցանց կյանքի ցիկլով։ Ուստի դրամապանակի և օպերատորի քաղաքականությունը պետք է կիրառի արժեքի սահմանաչափեր, ժամկետներ, ընդունելի թողարկողների ցանկ, հուսալի տեղային պահեստավորում և հաշտեցման ժամանակային պատուհաններ։

Ահա նոր գործարքի ստեղծման օրինակ՝ `Grant` հրահանգով: Այս գործարքում Mouse-ը տալիս է Alice-ին նշված դերը (`role_id`): Ստուգեք [համապատասխան օրինակը](./permissions.md#register-a-new-role).

```rust
let grant_role = Grant::account_role(role_id, alice_id);
let grant_role_tx = TransactionBuilder::new(chain_id, mouse_id)
    .with_instructions([grant_role])
    .sign(mouse_private_key);
```
