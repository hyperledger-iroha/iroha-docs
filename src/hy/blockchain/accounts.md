# հաշվետվություններ {#accounts}

Հաշիվը մարմին է, որը կարող է ստորագրել գործարքներ եւ սեփական գրառման վիճակը: Ներկայիս Iroha 3 տվյալների մոդելում, `AccountId` կանոնիկ է եւ առանց տիրույթի. այն բխում է հաշիվի կառավարողից եւ կոդավորվում է որպես [I105](/hy/reference/i105.md): Մարդու համար ընթերցելի տիրույթի եւ տվյալների տարածքի համատեքստը պատկանում է առանձին հաշիվ-անուն կապի:

## Կազմակերպություն {#structure}

Գրանցված `Account` պարունակում է:

- `id`: կանոնական `AccountId`
- `metadata`: հաշվառման կամայական մետադատները
- `label`: ընտրական կայուն կեղծանուն
- `uaid`: ընտրական համընդհանուր հաշիվ ID, որը օգտագործվում է Nexus հոսքերի համար
- `opaque_ids`: հաշիվի UAID բաժնետոմսերի հետ կապված անբացատրելի նույնականացուցիչներ

Հաշվի ստեղծման համար օգտագործվող գործարքի օգտակար բեռը `NewAccount` է: Այն կրում է նույն ինքնության, մետադատայի, տեքստի, UAID եւ ոչ թափանցիկ ID դաշտերը, որոնք օգտագործվում են գրանցված հաշիվում:

`uaid` լրացնում է կանոնական `AccountId`; այն չի փոխարինում այն: Օգտագործեք այն, երբ Nexus ծառայությունները պահանջում են կայուն օգտագործողի կամ կազմակերպության կառավարման տվյալների տարածքներում, գաղտնիությունը պահպանող գրանցումը, կամ ծառայության ունակությունների որոնումը: Runtime պահում է մեկ-մեկ UAID- հաշիվային ինդեքս, պահանջում է ոչ թափանցիկ նույնականացնողներ միացնել UAID, եւ մերժում է կրկնակի կամ բախվող անբացատրելի նույնականացուցիչներ: Տես [FHE եւ UAID](/hy/blockchain/sora-nexus-services.md#fhe-and-uaid) համար Nexus ծառայության շերտային հոսքը:

## հաշիվների վերահսկողներ {#account-controllers}

Կառավարիչը սահմանում է, թե ինչպես է հաշիվը թույլատրում գործողությունները: Սովորական հաճախորդի հոսքը օգտագործում է Ed25519 կոդային զույգ, բայց տվյալների մոդելը նաեւ աջակցում է ավելի հարուստ վերահսկիչներին, ինչպիսիք են բազմակի ստորագրության քաղաքականության վերահսկիչները:

Հաճախորդի կոնֆիգուրացիան պահում է ստորագրման իրավունքը զուգընկերների կոնֆիგուրացիայից առանձին.

```toml
[account]
public_key = "ed0120..."
private_key = { digest_function = "ed25519", payload = "..." }
```

Նայեք [ հաճախորդի կարգավորումը](/hy/guide/configure/client-configuration.md) եւ [ առանցքային սերունդը](/hy/guide/security/generating-cryptographic-keys.md) ՝ ներկայիս առանցքային ձեւաչափերի համար:

## Փորձեք այն Taira {#try-it-on-taira}

Տեղեկացրեք որոշ կանոնիկ հաշիվներ IDs հանրային Taira փորձարկման ցանցից:

```bash
curl -fsS 'https://taira.sora.org/v1/accounts?limit=5' \
  | jq -r '.items[] | [.id, (.primary_alias // "-")] | @tsv'
```

Հաշվետու ակտիվները ստուգելու համար նախորդ զանգից ID հաշիվը կրկնօրինակեք եւ այն URL կոդավորեք, նախքան այն տեղադրելը ուղին: Այս Python հատվածը անում է դա առաջին ցուցակագրված հաշիվի համար.

```bash
python3 - <<'PY'
import json
import urllib.parse
import urllib.request

root = "https://taira.sora.org"
accounts = json.load(urllib.request.urlopen(f"{root}/v1/accounts?limit=1"))["items"]
account_id = accounts[0]["id"]
encoded = urllib.parse.quote(account_id, safe="")
assets = json.load(
    urllib.request.urlopen(f"{root}/v1/accounts/{encoded}/assets?limit=5")
)

print(json.dumps({"account_id": account_id, "assets": assets["items"]}, indent=2))
PY
```

Հաշիվի ստեղծումը կամ թարմացումը ստորագրված գործարք է եւ պահանջում է Taira ֆունկցիայի կողմից ֆինանսավորվող կարգավորում, որը նկարագրվում է [ Կապակցեք SORA Nexus տվյալների տիրույթներին](/hy/get-started/sora-nexus-dataspaces.md).

## Գրանցում եւ թույլտվություններ {#registration-and-permissions}

Հաշիվները գրանցվում են եւ չեն գրանցվել [`Register` եւ `Unregister`](/hy/blockchain/instructions.md#un-register) հրահանգների միջոցով: Ակտիվ վավերացնողը որոշում է, թե ով կարող է ստեղծել հաշիվներ եւ որ թույլտվության տոնիկներ կամ դերակատարություններ են անհրաժեշտ:

գրանցվելուց հետո հաշիվը կարող է.

- ստորագրել գործարքներ
- պահեստային ակտիվներ
- սեփական տիրույթները
- ստանձնել դեր եւ թույլտվության նշաններ
- պահեստային մետադատա
- մասնակցել alias, rekey, վերականգնման եւ Nexus ինքնության հոսքներին, երբ այդ հատկությունները հնարավորություն են տալիս:

## Անունության խնդիրների լուծում {#troubleshooting-identity-issues}

Եթե գործարքը անսպասելի կերպով մերժվում է, ստուգեք, որ

- հաճախորդի հանրային բանալին համապատասխանում է ստորագրման համար օգտագործված մասնավոր բանալի
- հաշիվը գրանցվել է գեներիզմում կամ պարտավորեցված գործարքի միջոցով
- իշխանությունը ունի հրահանգի համաձայն պահանջվող թույլտվությունները
- խիստ հաշիվների դաշտերը օգտագործում են I105 վարկային հաշիվը ID, մինչդեռ ընթերցելի անունները լուծվում են ակտիվ հաշիվ-անունի միջոցով:
