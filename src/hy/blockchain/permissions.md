# թույլտվություններ {#permissions}

Հաշվետիկները պահանջում են թույլտվության տոմսեր բլոկչեյնի վրա տարբեր գործողությունների համար, օրինակ՝ ակտիվների մինթման կամ այրելու համար।

Հասարակական եւ մասնավոր բլոկչենների միջեւ տարբերություն կա օգտվողներին տրված թույլտվությունների առումով: Հանրային բլոկշեններում հաշիվների մեծ մասը ունեն նույն թույլտվությունները: Անձնական բլոկչեյնում հաշիվների մեծ մասը ենթադրվում է, որ չի կարող որեւէ բան անել նրանց տրված լիազորությունից դուրս, եթե բացարձակապես թույլատրված չէ համապատասխան թույլտվությունը:

Ինչ-որ բան կատարելու թույլտվություն ունենալը նշանակում է, որ հաշիվն ունի համապատասխան `Permission`: թույլտվությունները կարող են տրվել ուղղակիորեն կամ [`Role`](#permission-groups-roles), որը խմբավորում է մի շարք թույլտվություններ. թույլտվությունների տրամադրումը տրվում է `Grant` հրահանգով: թույլտվությունները եւ դերերը չեն ավարտվում: Հեռացրեք դրանք `Revoke` հրահանգով:

## Թույլտվության տոքեր {#permission-tokens}

Թույլտվության տոքերն ակտիվ կատարողի կողմից սահմանված տիպավորված օբյեկտներ են: Որոշ տոքերներ գլոբալ են, ինչպիսիք են `CanManagePeers`, իսկ մյուսները նախատեսված են հատուկ գրասենյակային առարկայի համար, ինչպիսիք են հաշիվը, ակտիվը, ակտիվի սահմանումը, դոմեյնը, NFT, դերը կամ գործիչը.

Ահա մի քանի պարամետրերի օրինակներ, որոնք օգտագործվում են տարբեր թույլտվությունների տոքերների համար.

- Տեղեկագրություն, որը թույլ է տալիս կոնկրետ հաշիվի համար մետադատա փոփոխել, պարունակում է `account` դաշտ.

  ```json
  {
    "account": "<AccountId>"
  }
  ```

- Տոկեն, որը տրամադրում է ակտիվների փոխանցման թույլտվություն հատուկ ակտիվի սահմանման համար, պարունակում է `asset_definition` դաշտ.

  ```json
  {
    "asset_definition": "<AssetDefinitionId>"
  }
  ```

- Գլոբալ տոքեր, ինչպիսիք են `CanManagePeers`, չունեն դաշտեր.

  ```json
  {}
  ```

### Նախապես կոնֆigurված թույլտվության տոքեր {#pre-configured-permission-tokens}

Դուք կարող եք գտնել նախապես կոնֆigurված թույլտվության տոքերների ցանկը [Reference](/hy/reference/permissions) բաժնում:

## թույլտվությունների խմբեր (ռոլներ) {#permission-groups-roles}

Թույլտվությունների հավաքածուն կոչվում է դեր: Նմանապես թույլտվության տոնիկների հետ, դերը կարող են տրվել ՝ օգտագործելով `Grant` հրահանգը եւ չեղյալ հայտարարվել ՝ օգտագործելու `Revoke` հրահանգը:

Նախքան հաշիվին դեր տալը, դերը պետք է առաջին հերթին գրանցվի:

Պաշտոնները օգտակար են, երբ մի քանի հաշիվներ պետք է ստանան նույն թույլտվությունների հավաքածու. Գրանցեք դերը մեկ անգամ, տրամադրեք թույլտվություններ դերի համար եւ ապա տրեք կամ հանեք դերը առանձին հաշիվների համար:

### Գրանցիր նոր դերակատարություն {#register-a-new-role}

Եկեք գրանցենք նոր դերակատարություն, որը, երբ տրվի, թույլ կտա մեկ այլ հաշիվ մուտք գործել Mouse-ի հաշվում գտնվող [մետադատային](/hy/blockchain/metadata.md):

```rust
let role_id = RoleId::from_str("ACCESS_TO_MOUSE_METADATA")?;
let role = iroha_data_model::role::Role::new(role_id.clone(), mouse_id.clone())
    .add_permission(CanModifyAccountMetadata {
        account: mouse_id.clone(),
    });
let register_role = Register::role(role);
```

### Պատվիրեք դեր: {#grant-a-role}

Երբ դերը գրանցվի, Mouse-ը կարող է այն տալ Alice-ին.

```rust
let grant_role = Grant::account_role(role_id, alice_id);
// `network_id` is the target network's `NetworkId`; the fee intent is bound
// into the signature (use the intent returned by a fee quote).
let grant_role_tx = TransactionBuilder::new(
    network_id,
    mouse_id,
    FeePaymentIntent::authority(Vec::new(), None),
)
.with_instructions([grant_role])
.sign(&mouse_private_key);
```

## թույլտվությունների հավաստիչներ {#permission-validators}

Թույլտվությունները գոյություն ունեն, որպեսզի պաշտպանված գործողություն կարողանան կատարել միայն պահանջվող թույլտվության տոկեն ունեցող հաշիվները։ Լռելյայն կատարողը թույլտվությունները ստուգում է գործարքների և հրահանգների կատարման, ինչպես նաև հարցումների վավերացման ընթացքում։

Սովորական վավերացողի մակերեսը խմբավորվում է գլխավոր գրքի տարածքով.

- հանգույցների կառավարումը
- դոմեյններ եւ հաշիվներ
- ակտիվներ, NFTs, եւ վարկային գրավումներ
- գործարկիչներ
- դեր եւ թույլտվություններ
- կատարող/կատարման միջավայր, ապացույցներ, կամուրջներ և SORA Nexus-ի մոդուլներ

Հստակ տոքերների ցուցակը հաստատված է աղբյուրի կողմից [Permission Tokens հղումով ](/hy/reference/permissions.md).

### Գործընթացային ժամանակահատվածի հաստատիչներ {#runtime-validators}

Թույլտվությունների ստուգումները իրականացվում են ակտիվ կատարողի կողմից: Նախնական կատարողը տրամադրում է ներկառուցված թույլտվության հավաստագրիչները եւ տոկենների սահմանումները, եւ ցանցը կարող է քաղաքականությունը փոխել այն գործադրողին թարմացնելով, որը օգտագործում է.

Կատարողը կամ թույլատրում է գործողությունը, կամ մերժում է այն `ValidationFail` պատճառով։ Մերժված հրահանգը մերժում է իր գործարքը, իսկ մերժված հարցումը սխալը վերադարձնում է կանչողին։

## Աջակցված հարցումներ {#supported-queries}

թույլտվությունների տոքերն ու դերերը կարող են հարցում կատարել:

Դասերի վերաբերյալ հարցումներ.

- [`FindRoles`](/hy/reference/queries.md#accounts-and-permissions)
- [`FindRoleIds`](/hy/reference/queries.md#accounts-and-permissions)
- [`FindRolesByAccountId`](/hy/reference/queries.md#accounts-and-permissions)

թույլտվության տոքերների հարցումները.

- [`FindPermissionsByAccountId`](/hy/reference/queries.md#accounts-and-permissions)
