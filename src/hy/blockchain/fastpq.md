# FastPQ {#fastpq}

FastPQ-ն Iroha-ի STARK ապացուցման ուղին է կատարման ընտրված ազդեցությունների համար։ Այն չի փոխարինում գործարքների սովորական կատարումը կամ կոնսենսուսը։ Գործարքները, ինչպես միշտ, անցնում են ISI-ի, IVM-ի և Sumeragi-ի միջով․ FastPQ-ն աջակցվող ազդեցություններն ապացուցում է դրանից հետո՝ այն սկզբնաղբյուր գրառման հիման վրա, որը գրանցել է բլոկի կատարումը։

Հոսթի ներկայիս ինտեգրումն ունի երկու հիմնական ուղի.

- վերջնականացված բլոկների թվային ակտիվների ազդեցությունները, որոնք ապացուցում է հանգույցի ապացուցիչի գոտին
- SORA Nexus AXT ապացույցի ծրարներ, որոնց `fastpq_binding`-ը կրում է FastPQ կապ

## Փոխանցման վկաների ուղի {#transfer-witness-path}

Թափանցիկ թվային փոխանցումները ստեղծում են փոխանցման կառուցվածքավորված տրանսկրիպտ, երբ հրահանգը փոփոխում է մնացորդները։ Տրանսկրիպտը գրանցում է․

- աղբյուր հաշիվը, նպատակային հաշիվը, ակտիվի սահմանումը և գումարը
- ուղարկողի եւ ստացողի մնացորդը փոխանցումից առաջ եւ հետո
- գործարքի մուտքային կետի հեշը, որն օգտագործվում է որպես խմբաքանակի հեշ
- լիազորության դայջեստ՝ ստացված ներկայացնող հաշվից
- Poseidon դայջեստ մեկ դելտայով տրանսկրիպտների համար
- նոսր Merkle ծառի թարմացման վկաներ ուղարկողի և ստացողի մնացորդների համար

Խմբաքանակային փոխանցումներն օգտագործում են մեկ տրանսկրիպտ՝ մի քանի դելտայով։ Այդ դեպքում մեկ դելտայի Poseidon դայջեստը բացակայում է։

Բլոկի կատարումը տրանսկրիպտները խմբավորում է ըստ այն կատարման կանչի, որը դրանք ստեղծել է, և պահում է դրանք բլոկի FastPQ սկզբնաղբյուր գրառման հետ։ AXT փոխանցման դրույթում փոխանցման յուրաքանչյուր դելտա դառնում է անցման երկու տող․

| Տող | Բանալի | Նախորդ արժեք | Հետագա արժեք |
| --------------- | --------------------------------------------------------------------- | ----------------------- | ---------------------- |
| Ուղարկողի դեբետ | `FastpqBalanceKeyV1` ակտիվի սահմանման և աղբյուր հաշվի համար | ուղարկողի մնացորդը առաջ | ուղարկողի մնացորդը հետո |
| Ստացողի կրեդիտ | `FastpqBalanceKeyV1` ակտիվի սահմանման և նպատակային հաշվի համար | ստացողի մնացորդը առաջ | ստացողի մնացորդը հետո |

Յուրաքանչյուր բանալի `FastpqBalanceKeyV1`-ի կանոնական Norito շրջանակն է, որը `transfer_balance_key`-ը կառուցում է տիպավորված ակտիվի սահմանումից և առանց տիրույթի հաշվից։ Հաշիվների այլանունները և ցուցադրման ձևերը երբեք բանալու նյութ չեն։

## Կատարման ազդեցություններ {#execution-effects}

Ապացուցիչի գոտին ապացուցում է կատարման ազդեցությունների ամբողջական դրույթներ։ Յուրաքանչյուր դրույթ ընդգրկում է կատարման մեկ գրառման բոլոր քանակական ազդեցությունները՝ կատարման հերթականությամբ․

| Ազդեցություն | Թարմացվող արժեքներ | Կանոն |
| -------- | ------------------------------ | ------------------------------------------------------------------- |
| Փոխանցում | աղբյուր և նպատակային մնացորդներ | գումարը տեղափոխվում է մեկ ակտիվի երկու մնացորդների միջև |
| Թողարկում | մնացորդ և ընդհանուր քանակ | երկուսն էլ աճում են նույն ոչ զրոյական չափով |
| Այրում | մնացորդ և ընդհանուր քանակ | երկուսն էլ նվազում են նույն չափով |
| Շրջանառությունից հանում | ընդհանուր քանակ և կյանքի ցիկլ | ընդհանուր քանակը մնում է զրո, իսկ ակտիվի առկայությունը մեկից փոխվում է զրոյի |

Ընդհանուր քանակը երբեք չի իջնում որևէ մնացորդից ցածր։ Յուրաքանչյուր բանալի կազմված է `iroha:fastpq:execution-quantity-key:v1` տիրույթից, մեկ NUL բայթից և `FastpqExecutionQuantityKeyV1` մնացորդի, ընդհանուր քանակի կամ կյանքի ցիկլի բանալու Norito կոդավորումից։ Դերերի շնորհումները, դերերի հետկանչումները և այլ գործողություններ չեն ապացուցվում։

Կատարման ազդեցությունների և AXT փոխանցման դրույթներում արժեքները ակտիվի տասնորդական մասշտաբով ճշգրիտ ոչ բացասական ամբողջ միավորներ են (`FastpqQuantityUnits`), ուստի դրանք սահմանափակված չեն `u64`-ով։ Դրույթի կառուցումը մերժում է մասշտաբի անհամապատասխանությունը, բացասական տարբերությունը և ցանկացած թվաբանական կամ դասավորության անհամապատասխանություն․ այն երբեք չի ուղղում հանրային արժեքը։

## Հանրային մուտքեր {#public-inputs}

Յուրաքանչյուր FastPQ դրույթ կրում է հանրային մուտքեր, որոնք ապացույցը կապում են բլոկին և կատարման համատեքստին․

| Մուտք | Նշանակություն |
| ------------- | ------------------------------------------------------------------------------------ |
| `dsid` | Տվյալների տարածքի նույնացուցիչ․ դրա `u64` արժեքը՝ կրտսեր բայթից սկսվող կարգով, որին հաջորդում են ութ զրոյական բայթ |
| `slot` | Բլոկի ստեղծման ժամանակը նանովայրկյաններով՝ միլիվայրկյանի ճշգրտությամբ |
| `old_root` | Դրույթի շոշափած բանալիների նոսր Merkle ծառի արմատը մինչև դրույթը |
| `new_root` | Դրույթի շոշափած բանալիների նոսր Merkle ծառի արմատը դրույթից հետո |
| `perm_root` | Պարտավորություն կատարող վիճակի դերերի և թույլտվությունների աղյուսակի նկատմամբ |
| `tx_set_hash` | Պարտավորություն բլոկի գործարքների փոխանցման ձևաչափով ներկայացումների նկատմամբ՝ բլոկի հերթականությամբ |

`old_root`-ը և `new_root`-ը ընդգրկում են միայն այն բանալիները, որոնց շոշափում է դրույթը։ Դրանք աշխարհի վիճակի պահպանված արմատը չեն։

`perm_root`-ը Iroha-ի 32-բայթանոց `Hash`-ն է՝ հաշվարկված `fastpq:v1:permission-table:blake2b-256` տիրույթի, կրտսեր բայթից սկսվող `u64` տեսքով գրառումների քանակի և դասավորված գրառումների վրա։ Յուրաքանչյուր գրառում կազմված է դերի ID-ի հեշից, այդ դերի թույլտվություններից մեկի հեշից և այդ թույլտվության դարաշրջանից՝ կրտսեր բայթից սկսվող `u64` տեսքով։ Դատարկ աղյուսակն ամրագրվում է որպես 32 զրոյական բայթ։ Սա միայն դերերի և թույլտվությունների համատեքստ է․ այն չի ապացուցում հաշվի անդամակցությունը կամ լիազորումը։

`tx_set_hash`-ը Iroha-ի `Hash`-ն է՝ հաշվարկված `iroha:axt:ordered-transaction-wire-set:v1` տիրույթի, մեկ NUL բայթի, գործարքների քանակի և, բլոկի հերթականությամբ յուրաքանչյուր գործարքի համար, դրա փոխանցման ձևաչափի երկարության ու փոխանցման ձևաչափի ամբողջական բայթերի վրա։ Քանակը և երկարությունները կրտսեր բայթից սկսվող `u64` արժեքներ են։ Գործարքները չեն դասավորվում, և դրանց կրկնօրինակները չեն հեռացվում, իսկ ստորագրությունները մնում են նախապատկերում։

Iroha-ի `Hash`-ը Blake2b-256 է, որի վերջին բայթի ամենացածր բիթը հավասարեցված է մեկի։ Դրույթը կրում է նաև դասավորության հեշ և իր ամբողջական կանոնական տողերն ու սկզբնաղբյուր փաստերը․ ապացույցը կապում է դրանք բոլորը։

## Ապացույցի արձանագրություն {#proof-protocol}

FastPQ-ի կանոնական արտեֆակտները քողարկված DEEP ապացույցներ են Goldilocks դաշտի վրա՝ 4-րդ աստիճանի ընդլայնմամբ։ Դրանց ճշգրիտ առնչությունը, տրանսկրիպտը և հարցումների երկրաչափությունը սահմանված են ամրագրված [FastPQ DEEP արձանագրության պայմանագրում](https://github.com/hyperledger-iroha/iroha/blob/c8c872461e92f04325c350cdd952f4276e96f9dc/specs/fastpq_deep_protocol_contract.md)։

Կանչողներն ընտրում են սովորական կամ AXT դրույթ և ռեսուրսների սահմանաչափեր։ Նրանք չեն ընտրում սխեմաներ, ստուգման բանալիներ, հարցումների քանակ կամ տրանսկրիպտի ներքին մանրամասներ։ Սովորական երթուղին `offline_compact::prove_quantity_ordinary_artifact`-ն է․ AXT երթուղին `offline_compact::prove_quantity_axt_artifact`-ն է, որի շուրջ `prove_axt_bound_batch`-ը թաղանթ է ծառայում կապված խմբաքանակների համար։ Թափանցիկ `Prover`, `Proof` և վերարտադրման `verify` API-ն գոյություն ունի միայն թեստերում և `dev-tools` կառուցումներում։

## Ինչ է ստուգում ապացույցը {#what-the-proof-checks}

Ցանկացած գաղտնի աշխատանքից առաջ արտադրողը պատրաստում է հանրային դրույթը։ Այն ստուգում է հաշիվները, գումարները, արժեքները, դեպքերի քանակները, բանալիների կայուն կարգը և բանալիների բաշխումը, և մերժում է այն դրույթը, որի հանրային փաստերը միմյանց չեն համապատասխանում։ Այնուհետև կնքված առնչությունը յուրաքանչյուր հատվածում ապացուցում է մեկ ազդեցության կամ փոխանցման մեկ դեպքի երկու ամբողջական 32-մակարդականի նոսր Merkle թարմացումները։ Լռելյայն սահմանաչափերը թույլ են տալիս մեկ արտեֆակտում առավելագույնը երկու հատված։

Յուրաքանչյուր հետք ունի 65,536 տող։ Արտադրողն ամրագրում է 301 գաղտնի սյունակ, իսկ ստուգիչն ինքնուրույն վերակառուցում է 41 հանրային սյունակ։ Թարմ կրիպտոգրաֆիական էնտրոպիան քողարկում է հետքի սյունակները, քանորդը և ինքնուրույն ամրագրված կոմպոզիցիոն բազմանդամը։ Քանորդի բաժանումը պետք է ճշգրիտ լինի։ Արտադրողը ստուգում է իր սեփական արտեֆակտը՝ նախքան այն վերադարձնելը։

Դրույթի հանրային արժեքները թաքցված չեն։ Գործողության առկայությունը փոխանցման ձևաչափում այն ընդունելի չի դարձնում․ առնչություններ ունեն միայն վերևում թվարկված ազդեցությունները, և AXT դրույթներն ընդունում են միայն վկայված փոխանցումներ։

## Ապացուցիչի գոտի {#prover-lane}

`iroha3d`-ը հանգույցի գործարկման ընթացքում, նախքան Torii-ն կսկսի ընդունել ներկայացումները, գործարկում է FastPQ ապացուցիչի մեկ աշխատող պրոցես, եթե Kura-ն չի գործարկվում `init_mode = "fast"`-ով։ Աշխատող պրոցեսն իր բեքենդը սկզբնավորում է ֆոնային ռեժիմում, ուստի սկզբնավորման ձախողման դեպքում գործարկումը շարունակվում է․ այդ դեպքում գոտին մնում է անջատված։

Աշխատող պրոցեսը պարբերաբար ստուգում է հանգույցի վերջնականացված վիճակը և Kura-ի պահոցը։ Յուրաքանչյուր վերջնականացված բլոկի համար այն ստանում է իսկորոշված սկզբնաղբյուրը՝ վերարտադրելով բնիկ կատարումը, երբ սկզբնաղբյուրը պահված չէ, և բլոկի ամբողջական դրույթները հերթով ապացուցում է սովորական երթուղով։ Վերագործարկումից հետո այն վերակառուցում է իսկորոշված նախածանցը ամրագրված ստորագրված ծագման բլոկից։ Այն յուրաքանչյուր արտեֆակտ պահում է Kura-ի սահմանափակ ծավալով FastPQ պահոցում։ Պահված արտեֆակտը ընդամենը հայտարարություն է․ նախքան առաջ անցնելը արտադրողն իսկորոշում է սկզբնաղբյուրը և կրկին ստուգում արտեֆակտը։

Ապացույցների արտադրությունը հանգույցի տեղային գործընթաց է։ Այն գործարքների ընդունման կամ կոնսենսուսի դարպաս չէ․ կատարումը, ամրագրումը և վերջնականությունը չեն սպասում ապացույցին։ Կրկնելի ձախողումը աշխատանքը թողնում է հետագա փորձի համար, և յուրաքանչյուր պրոցեսում աշխատում է մեկ արտադրող։

## Ստուգում {#verification}

Ստուգիչը ստուգում է արտեֆակտը այն ակնկալիքների համեմատ, որոնք ստանում է իր սեփական իսկորոշված դրույթից, և երբեք՝ ստուգվող արտեֆակտից։ Ստուգումը յուրաքանչյուր հատված վերծանում է մեկ անգամ՝ սահմանափակումների ներքո, AIR-ը գնահատում է մեկ անգամ տիրույթից դուրս կետում, ամրագրված արմատների նկատմամբ իսկորոշում է յուրաքանչյուր բացված տող, քանորդի տերև և FRI մանրաթել, ինչպես նաև ամբողջական FRI վերջնական շերտը, և կատարում է առավելագույնը 385 ծալման ստուգում։ Այն չի կառուցում գաղտնի վկա, հետք կամ ամբողջական ցածր աստիճանի ընդլայնում։

Հաջողությունը հաստատում է համապատասխանությունը կանչողի ակնկալիքներին։ Այն չի տրամադրում կատարման լիազորություն, սկզբնաղբյուրի վերջնականություն, վերարտադրման ընդունում կամ AXT ծախսի լիազորում։

Լռելյայն սահմանաչափերը `offline_compact::VerificationLimits`-ից, որոնք օգտագործում է նաև սովորական երթուղին․

| Սահմանաչափ | Լռելյայն արժեք |
| ------------------------------- | ------------: |
| Հատվածներ մեկ արտեֆակտում | 2 |
| Արտեֆակտի բայթերը փոխանցման ձևաչափում | 1 MiB |
| Դուստր ապացույցի շրջանակ | 500,084 բայթ |
| Դրույթի բայթերը բոլոր հատվածներում | 512 KiB |
| Հարցումներ մեկ հատվածում | 77 |
| Հարցումներ բոլոր հատվածներում | 154 |

Հանգույցի գոտին արտեֆակտի բայթերը փոխանցման ձևաչափում լրացուցիչ սահմանափակում է `zk.fastpq.proof_sidecar_max_bytes`-ով և Kura-ի FastPQ օբյեկտի սահմանաչափով։ Մինչև վերծանումը AXT ապացույցի բլոբը կարող է պարունակել առավելագույնը 2 MiB, իսկ դրանում ներդրված FastPQ օգտակար բեռը՝ առավելագույնը 1 MiB։

## SORA Nexus AXT ապացույցի ծրարներ {#sora-nexus-axt-proof-envelopes}

SORA Nexus AXT ապացույցի ծրարները կարող են ներառել `AxtFastpqBinding`։ AXT ծրարների բլոկային վավերացումը, IVM հոսթի AXT ծրարի ստուգումները և `RegisterVerifiedFeeSponsorVaultAllocation`-ը պահանջում են ծրարի `fastpq_binding`-ը, այն ստուգում են ակնկալվող պնդման համեմատ և կանչում են FastPQ ստուգիչը ծրարի և դրանում ներդրված ապացույցի վրա։ Կապի բացակայությունը կամ ձախողված ստուգումը մերժում է գործողությունը։

Ստուգիչն ընդունում է միայն վկայված փոխանցման պնդումներ՝ `tx_predicate` և `value_conservation`։ `authorization` և `compliance` պնդման տեսակները ազդեցության անթափանց կրողներ են՝ առանց փոխանցման առնչության, և ստուգումը մերժում է դրանք։ Բլոկի վավերացումը նաև մերժում է հեռավոր ծախսեր կրող ծրարները, իսկ IVM հոսթը մերժում է `AXT_VERIFY_DS_PROOF`-ի ինքնուրույն ընդունումը։ Երկուսն էլ անհասանելի են մնում այնքան ժամանակ, քանի դեռ հնարավոր չէ իսկորոշել վերջնականացված սկզբնաղբյուր արմատները, գործարքների հավաքածուն և թողարկողի լիազորումը։

### AXT կապ {#axt-binding}

SORA Nexus AXT ծրարների համար `AxtFastpqBinding`-ը բերվում է կանոնական ձևի նախքան ապացուցումը և ստուգումը․

- `parameter`, `source_dataspace`, `source_receipt_id` և `verified_effect_type` արժեքներից հեռացվում են եզրային բացատները, և դրանք չպետք է դատարկ լինեն
- `source_tx_commitment`, `claim_digest`, `witness_commitment` և `policy_commitment` արժեքները փոխարկվում են փոքրատառի և պետք է լինեն 32 բայթի տասնվեցական կոդավորումներ
- `verifier_id`-ը պետք է լինի `fastpq`, իսկ `verifier_version`-ը՝ `v1`
- `claim_type`-ից հեռացվում են եզրային բացատները, այն փոխարկվում է փոքրատառի և պետք է անվանի վերևում նշված չորս պնդման տեսակներից մեկը
- `target_dsids`-ը չպետք է դատարկ լինի և պետք է լինի խիստ աճող
- `remote_spend_intent_commitments`-ը պետք է լինի խիստ աճող և չգերազանցի առաջին թողարկման սահմանաչափը

Ստուգումը պահանջում է ճշգրիտ կանոնական ձև․ այն կանչողի փոխարեն կապը չի նորմալացնում։

Կապը միանում է խմբաքանակին, որն արդեն գրանցել է բլոկի կատարումը․ այն անցումներ չի ստեղծում։ Խմբաքանակը պետք է պարունակի առնվազն մեկ վիճակի անցում և անվանի կապի պարամետրերի հավաքածուն՝ `fastpq-state-transition-stark-v1`։ Դրա `entry_hash` մետատվյալը պետք է հավասար լինի `source_tx_commitment`-ին, իսկ դրա հանրային `dsid`-ը պետք է կոդավորի կապի `source_dsid`-ը։ Փոխանցման պնդումը պետք է կրի առնվազն մեկ փոխանցման տրանսկրիպտ, և յուրաքանչյուր տրանսկրիպտի խմբաքանակի հեշը պետք է հավասար լինի `source_tx_commitment`-ին։

Այնուհետև կապը խմբաքանակում գրում է ապացույցին կապված մետատվյալներ․ կանոնական կապը, դրա չորս դայջեստները, `source_receipt_id`-ը, `target_dsids`-ը, `verified_effect_type`-ը, ոչ դատարկ `corridor`-ը, ոչ զրոյական մանիֆեստի արմատը, ընտրովի DA պարտավորությունը, ընտրովի ոչ զրոյական ամրագրված գումարը և ժամկետի ավարտի սլոտը, որտեղ զրոն նշանակում է, որ ժամկետ չկա։ Վերջում այն ավելացնում է կնիք կապի և առանց կնիքի խմբաքանակի վրա․

$$
\operatorname{seal} =
\operatorname{Hash}(
\texttt{fastpq:axt:batch-seal:v1}\|
E(\operatorname{binding})\|
E(\operatorname{batch})
)
$$

Այստեղ $E$-ն կանոնական Norito կոդավորումն է։ Կապելուց հետո խմբաքանակի, կապի կամ ապացույցին կապված որևէ արժեքի փոփոխությունը հանգեցնում է ստուգման ձախողման։ Ստուգիչը նաև համեմատում է ծրարի տվյալների տարածքը, մանիֆեստի արմատը, DA պարտավորությունը, ամրագրված գումարը և ժամկետի ավարտը ապացույցին կապված արժեքների հետ։

Ստուգված ծրարը հաղորդում է իր ապացուցված `old_root`-ը, `new_root`-ը և `tx_set_hash`-ը, ինչպես նաև դրույթի դայջեստը։ Դայջեստն ընդգրկում է ծրարի տվյալների տարածքը՝ կրտսեր բայթից սկսվող `u64` տեսքով, դրա մանիֆեստի արմատը, DA պարտավորությունը, եթե այն առկա է, կապը և դրույթը․

$$
\operatorname{statement\_digest} =
\operatorname{Hash}(
\texttt{fastpq:axt:statement:v1}\|
\operatorname{le64}(\operatorname{dsid})\|
\operatorname{manifest\_root}\|
\operatorname{da\_commitment}\|
E(\operatorname{binding})\|
E(\operatorname{statement})
)
$$

AXT խմբաքանակի մանիֆեստի դայջեստը SHA-256-ն է՝ հաշվարկված կանոնական կապի Norito կոդավորման վրա․

$$
\operatorname{manifest\_digest} =
\operatorname{SHA256}(E(\operatorname{canonical\_binding}))
$$

## Պարամետրերի հավաքածուներ {#parameter-sets}

Առաջին թողարկումն ունի ճիշտ մեկ պարամետրերի հավաքածու՝ `fastpq-state-transition-stark-v1`։ Խմբաքանակներն ու AXT կապերը նշում են այն, և AXT ապացուցումը մերժում է ցանկացած այլ անուն։ DEEP արձանագրության պայմանագիրն ամրագրում է թողարկված արտեֆակտի երկրաչափությունը․

| Տարր | Արժեք |
| -------------------------- | ----------------------------------------------------- |
| Դաշտ | Goldilocks `p = 2^64 - 2^32 + 1`, ընդլայնում `u^4 - 7` |
| Հետքի տողեր | 65,536 |
| Գնահատման տողեր | 8,388,608 (ընդլայնման գործակից 128) |
| FRI ծալման արիտետներ | `[16, 16, 8, 8, 4]` |
| Հարցումներ | 77 տարբեր դիրք |
| Գրայնդինգ | չկա |
| Պարտավորություններ և տրանսկրիպտ | SHA3-256 և SHAKE256 |

Արտադրական որակավորումը հասանելի չէ։ Այս կառուցվածքի հուսալիության, թաքցման և Fiat-Shamir-ի անկախ վերանայումները դեռ չեն իրականացվել, և ամրագրված [արտադրական պատրաստվածության գրառումը](https://github.com/hyperledger-iroha/iroha/blob/c8c872461e92f04325c350cdd952f4276e96f9dc/specs/fastpq_production_readiness.md) աշխատանքով նորմալացված անվտանգության որևէ պնդում չի անում։

## Կազմաձևում {#configuration}

FastPQ կարգավորումը տեղադրված է `zk.fastpq` ներքեւում:

```toml
[zk.fastpq]
execution_mode = "cpu"
poseidon_mode = "cpu"
proof_sidecar_queue_cap = 1024
proof_sidecar_max_retries = 16

# Optional telemetry labels.
device_class = "apple-m4"
chip_family = "m4"
gpu_kind = "integrated"

# Optional Metal backend tuning.
metal_queue_fanout = 3
metal_queue_column_threshold = 24
metal_max_in_flight = 5
metal_threadgroup_width = 128
metal_trace = false
metal_debug_enum = false

[zk.fastpq.producer]
poll_interval_ms = 1000
step_timeout_ms = 30000
max_native_steps = 16
max_source_entries = 65536
max_source_statements = 16384
```

Երկու ռեժիմներն էլ ընդունում են միայն `cpu` կամ `gpu`, և լռելյայն արժեքը `cpu` է։ Դրանցից որևէ մեկը `gpu` դնելու դեպքում ապացույցի հեշավորման համար պահանջվում է սարք՝ macOS-ում Metal, այլ համակարգերում՝ CUDA։ Եթե GPU-ի աջակցությունը ներառված չէ կոմպիլյացիայում կամ սարքը չի անցնում նախնական ստուգումը, ապացուցիչի գոտին մնում է անջատված․ այն երբեք պահեստային տարբերակով չի անցնում CPU-ի։ Սարքը կատարում է Merkle-ի տերևների և ստորին ծնող հանգույցների զանգվածային հեշավորումը․ տրանսկրիպտը, դասավորված վերին ծառը և հետքի թվաբանությունը մնում են CPU-ի վրա։ `poseidon_mode = "gpu"`-ի դեպքում հանգույցը նաև տրանսկրիպտի Poseidon դայջեստները խմբաքանակներով մշակում է GPU-ի վրա, երբ առանձին նախնական ստուգումը հաջողվում է․ հակառակ դեպքում այն դրանք հաշվարկում է CPU-ի վրա։

`proof_sidecar_max_bytes`-ը սահմանափակում է կոդավորված արտեֆակտը, որը հանգույցը պահպանում և ստուգում է, և լռելյայն հավասար է ապացուցիչի ապացույցի առավելագույն շրջանակին։ `producer` աղյուսակը սահմանափակում է ապացուցման յուրաքանչյուր փորձ․ դրա ստուգման միջակայքը, ժամանակային բյուջեն, բնիկ վերարտադրման քայլերը (1-ից 64) և մինչև հիշողության հատկացումն ընդունվող սկզբնաղբյուր գրառումներն ու դրույթները։ `metal_queue_fanout`-ն ընդունում է 1-ից 4 արժեքներ։

Ռեժիմի և հեռաչափության պիտակների կարգավորումները կարող են նաև վերասահմանվել `iroha3d`-ից․

```shell
iroha3d --fastpq-execution-mode gpu
iroha3d --fastpq-poseidon-mode cpu
iroha3d --fastpq-device-class apple-m4
iroha3d --fastpq-chip-family m4
iroha3d --fastpq-gpu-kind integrated
```

`iroha3d`-ը կազմաձևման ֆայլ կարդալիս անտեսում է միջավայրի փոփոխականները, ուստի այս արժեքները սահմանեք TOML-ում կամ վերևում նշված տարբերակներով։

## Մետրիկներ {#metrics}

Երբ հեռաչափությունը միացված է, FastPQ-ն արտահանում է մետրիկներ բեքենդի ընտրության, ապացույցների պահպանման և Metal-ի կատարման միջավայրի վարքի վերաբերյալ․

| Մետրիկ | Նշանակություն |
| ----------------------------------- | --------------------------------------------------------------------------- |
| `fastpq_execution_mode_total` | Պահանջված և փաստացի ընտրված կատարման ռեժիմը՝ ըստ բեքենդի և սարքի պիտակների |
| `fastpq_poseidon_pipeline_total` | Պահանջված և փաստացի ընտրված Poseidon հոսքագծի ուղին |
| `fastpq_gpu_disable_total` | GPU արագացուցչի անջատման իրադարձություններ՝ ըստ արագացուցչի, պատճառի և սարքի պիտակների |
| `fastpq_gpu_parity_failure_total` | GPU-ի համարժեքության ընտրանքային ստուգման ձախողումներ՝ ըստ արագացուցչի, պատճառի և սարքի պիտակների |
| `fastpq_proof_sidecar_queue_depth` | Հերթում սպասող FastPQ ապացույցի ուղեկցող կցորդներ |
| `fastpq_proof_sidecar_events_total` | Ապացույցի ուղեկցող ֆայլի պահպանման իրադարձություններ՝ ըստ իրադարձության |
| `fastpq_metal_queue_depth` | Metal-ի հերթի սահմանաչափը, միաժամանակ ընթացող առաջադրանքների առավելագույն քանակը, ուղարկումների քանակը և նմուշառման պատուհանը |
| `fastpq_metal_queue_ratio` | Metal-ի հերթի զբաղվածության և փոխծածկման հարաբերակցությունները |
| `fastpq_zero_fill_duration_ms` | Հոսթի զրոյական լրացման տևողությունը Metal-ի գործարկումների համար |
| `fastpq_zero_fill_bandwidth_gbps` | Զրոյական լրացման հաշվարկված թողունակությունը |

Ռեժիմի, GPU-ի, Metal-ի հերթի և զրոյական լրացման մետրիկներին անհրաժեշտ է `extended` կամ `full` հեռաչափության պրոֆիլ, և դրանք չեն արտահանվում, երբ Kura-ն գործարկվում է `init_mode = "fast"`-ով։ Metal-ի հերթի և զրոյական լրացման մետրիկներին նաև անհրաժեշտ է `fastpq-gpu` կառուցում macOS-ում։

Ընդհանուր կատարողականի դասակարգման համար օգտագործեք դրանք [Կատարողական և մետրիկներ](/hy/guide/advanced/metrics.md) էջում թվարկված կոնսենսուսի և հերթի ազդանշանների հետ։
