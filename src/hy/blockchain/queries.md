# Հարցումներ {#queries}

Միջոցառման բաժանորդները եւ ֆիլտրերը կարող են հետեւել blockchain վիճակի փոփոխությունների. Օգտագործեք հարցում, երբ դուք պետք է ուղղակիորեն դիտել ընթացիկ վիճակը:

Հարցումները փոքր-ինչ հրահանգներ են. ուղարկեք մեկը Iroha հանգույցի, որպեսզի ստանաք մանրամասներ նրա ներկայիս աշխարհային վիճակի վերաբերյալ տեսանկյունից:

Ցանցը կարող է տրամադրել նաև այլ տեղեկություններ։ Հարցման ենթակա համաշխարհային վիճակի տեղեկությունն այն միակ տեսակն է, որի հասանելիությունը երաշխավորված է յուրաքանչյուր Iroha ցանցում։

Յուրաքանչյուր տեղակայման համար Iroha, կարող են լինել նաեւ այլ տեղեկատվություն: Օրինակ, հեռաչափության տվյալների առկայությունը կախված է ցանցի կառավարիչներից: Դա ամբողջությամբ նրանց որոշումն է, թե արդյոք նրանք ցանկանում են վերամշակման հզորությունը հատկացնել աշխատանքը հետեւելու փոխարեն այն օգտագործելու համար: Բացի այդ, որոշ գործառույթներ միշտ պահանջվում են, օրինակ՝ մուտք ունենալ ձեր հաշիվի մնացորդի:

Հարցումների արդյունքները կարող են միանգամից լինել [սորտիֆիկացված](#sorting), [կապված](#pagination) եւ հանգույցի կողմից [ֆիլտրված ](#filters): Սորտինգը կատարվում է բառագիտականորեն մեթադատա կոճակների վրա: Ֆիլտրումը կարող է կատարվել տարբեր սկզբունքների հիման վրա, սկսած դոմեյնային հատուկ (մեկ առանձին IP հասցեային ֆիլտրային դիմակներ) մինչեւ ենթատառերի մեթոդներ, ինչպիսիք են `begins_with` ՝ օգտագործելով տրամաբանական գործողություններ:

## Փորձեք այն Taira {#try-it-on-taira}

Taira բացատրում է միայն ընթերցման հարցումների օգնականները ավելի քան JSON ընդհանուր ռեսուրսների համար: Օգտագործեք դրանք, որպեսզի փորձեք էջավորումը եւ պատասխանների կառավարումը, նախքան միացնել SDK:

```bash
TAIRA_ROOT=https://taira.sora.org

curl -fsS "$TAIRA_ROOT/v1/accounts?limit=3" \
  | jq '{total, ids: [.items[].id]}'

curl -fsS "$TAIRA_ROOT/v1/domains?limit=3" \
  | jq '{total, domains: [.items[].id]}'

curl -fsS "$TAIRA_ROOT/v1/assets/definitions?limit=3" \
  | jq '{total, assets: [.items[] | {id, name, total_quantity}]}'
```

Հավելվածների ախտորոշման համար պահեք այս ծխի ստուգումները ստորագրված գործարքների փորձարկումներից առանձին: Միայն ընթերցման հարցման ձախողումը սովորաբար ցույց է տալիս վերջնական կետերի մատչելիությունը, ցանցի հասանելիությունը կամ երթուղու համատեղելիությունը նախքան այն ցույց է տալիս ստորագրողի կարգավորումը:

## Ստեղծել հարցում {#create-a-query}

Օգտագործեք SDK կամ CLI տիպված հարցման ստեղծողներ: Օրինակ, ներկայիս տվյալների մոդելը ցուցակում գրանցվող հաշիվների համար բաց է թողնում `FindAccounts`:

```rust
let query = FindAccounts;
```

Ահա հարցման մի օրինակ, որը հայտնաբերում է Alice-ի ակտիվները.

```rust
let alice_id = load_canonical_account_id_from_client_config()?;
let query = FindAssetsByAccountId::new(alice_id);
```

## Գլխավոր էջեր {#pagination}

Միավոր հարցումների եւ կրկնվող փոքր հարցումների համար կարող եք օգտագործել `client.request` ՝ հարցում ուղարկելու եւ արդյունքը ստանալ միանգամից:

Այնուամենայնիվ, լայն կրկնվող հարցումները, ինչպիսիք են `FindAccounts`, `FindAssets` կամ `FindBlocks` կարող են վերադարձնել մեծ արդյունքների հավաքածուներ: Օգտագործեք էջավորումը ՝ հանգույցների եւ հաճախորդների վրա բեռը նվազեցնելու համար:

`Pagination` կառուցելու համար անհրաժեշտ է զանգահարել `client.request_with_pagination(query, pagination)`, որտեղ `pagination`-ը կառուցված է հետեւյալ կերպ.

```rust
let starting_result: u32 = _;
let limit: u32 = _;
let pagination = Pagination::new(Some(starting_result), Some(limit));
```

## Ֆիլտրեր {#filters}

Երբ ստեղծում եք հարցումը, դուք կարող եք օգտագործել ֆիլտրը միայն այն արդյունքների վերադարձնելու համար, որոնք համապատասխանում են նշված ֆիլտրին:

Ֆիլտրերը հատուկ են հարցումների համար: Օրինակ, հաշիվների հարցումները կարող են կրճատվել հաշիվի ինքնության կամ մետադատայի միջոցով, մինչդեռ ակտիվների հարցումները կարելի է կրճատել ակտիվով: Definition, holder account կամ domain projection. Օգտագործեք SDK- ի տիպված հարցման ստեղծողները հնարավորության դեպքում, որպեսզի ֆիլտրի տեսակը համապատասխանի հարցման արտադրանքի տեսակին:

## Սորտիֆիկացում {#sorting}

Iroha-ը կարող է դասակարգել տարրերը [ մետադատայով](/hy/blockchain/metadata.md) բառապաշարային, եթե դուք տրամադրեք հարցման կառուցման ընթացքում կարգավորելու բանալին: Տիպիկ օգտագործման դեպքում հաշիվները պետք է ունենան `registered-on` մետադատա մուտք, որը, երբ դասակարգվում են, թույլ է տալիս դիտել հաշիվի գրանցման պատմությունը.

Տեսակավորումը կիրառվում է միայն [մետադատա](/hy/blockchain/metadata.md) ունեցող էություններին, քանի որ հարցման արդյունքները դասավորելու համար օգտագործվում է մետադատայի բանալի։

Դուք կարող եք համատեղել դասակարգումը էջայնացման եւ ֆիլտրերի հետ: Հիշեք, որ դասակարգումը ընտրանքային հատկություն է, էջայնացման հարցումների մեծ մասը դրա կարիք չի ունենա.
