# Iroha 3-ի գործարկում {#launch-iroha-3}

Մասնավոր միջավայրում ինտեգրումը փորձարկելու համար Linux-ի մեկ վիրտուալ մեքենայում (VM) գործարկեք Iroha 3-ի չորս վավերացնող հանգույց։ Ուղարկեք ստորագրված գործարք, կանգնեցրեք հանգույցներից մեկը և ստուգեք, որ մյուս երեքը հաստատում են երկրորդ գործարքը։ Այս կերպ ստեղծվում է անկախ գրանցամատյան, որին մասնակցելու համար թույլտվություն է պահանջվում։ Այն որպես կառավարվող տվյալների տարածք SORA Nexus-ին միացնելու համար անհրաժեշտ է առանձին կարգավորում։

## Վիրտուալ մեքենայի (VM) պատրաստում {#prepare-the-vm}

Օգտագործեք Linux x86_64՝ Docker Engine, Buildx, Compose v2, Python 3.8 կամ ավելի նոր տարբերակ և `unzip`։ Ձեր հաշվին անհրաժեշտ է Docker-ի օգտագործման թույլտվություն։ Առաջին կազմարկման համար անհրաժեշտ է ելքային HTTPS կապ դեպի GitHub, Docker Hub, Debian-ի փաթեթների հայելային սերվերներ և crates.io։

Հավաքակազմը կազմարկել և փորձարկել ենք վեց vCPU և 32 GiB RAM օպերատիվ հիշողություն ունեցող վիրտուալ մեքենայում (VM)՝ մի քանի արհեստական գործարքներով։ Պահեստի ծավալն ընտրեք ըստ ծանրաբեռնվածության և տվյալների պահպանման ժամկետի։ Docker Engine-ի յուրաքանչյուր օրինակի համար օգտագործեք հավաքակազմի մեկ պատճեն և տեղային միջերեսի 18080–18083 պորտերը թողեք ազատ։

[Ներբեռնեք չորս հանգույցի հավաքակազմը](/downloads/iroha-trade-poc.zip)։ Այն ներառում է գործարկման ծրագիրը, կախվածությունների հաստատված տարբերակների ցանկը և ուղղումները, որոնց միջոցով վավերացնող հանգույցն ու հաճախորդը կազմարկվում են Iroha-ի նույն ամրագրված տարբերակից։ Ներբեռնման պանակում ստուգեք արխիվի ստուգիչ գումարը և ապա ապասեղմեք այն։

```sh
echo 'b12d450f9f15c0126dfe5eca83cdfad8bc420c779a78f916d374f433a2b3da0e  iroha-trade-poc.zip' | sha256sum --check
unzip iroha-trade-poc.zip
cd iroha-trade-poc
```

## Չորս հանգույցների գործարկում և ստուգում {#start-and-verify-all-four-validators}

```sh
python3 poc.py up
python3 poc.py verify
```

Առաջին գործարկման ժամանակ ծրագիրը կառուցում է կոնտեյների պատկերը և վիրտուալ մեքենայում (VM) ստեղծում շղթայի նույնացուցիչը, բանալիներն ու ստորագրված սկզբնական բլոկը։ Յուրաքանչյուր հանգույց ունի իր մշտական պահեստը։ Ստուգման ծրագիրը ստորագրում է փորձնական գործարք և սպասում, մինչև չորս հանգույցներից յուրաքանչյուրը հայտնի երեք միացված հանգույցների և նոր բլոկի միևնույն հեշի մասին։ Սկզբնական բլոկը պարունակում է օրինակելի հաշիվներ։ Օգտագործեք արհեստական տվյալներ և APIs-ն հասանելի դարձրեք միայն տեղային միջերեսից։

Վիրտուալ մեքենայի (VM)ց առաջին հանգույցի վիճակը ստանալու համար բացահայտ նշեք պատասխանի JSON ձևաչափը։

```sh
curl -fsS -H 'Accept: application/json' http://127.0.0.1:18080/status
```

## Մեկ հանգույցի խափանման փորձարկում {#test-a-validator-failure}

```sh
python3 poc.py failover
```

Փորձարկումը կանգնեցնում է մեկ հանգույց, ուղարկում նոր գործարք և համեմատում հաստատված բլոկի հեշը գործող երեք հանգույցներում։ Այնուհետև այն վերագործարկում է չորրորդ հանգույցը և սպասում, մինչև վերջինս հասնի նույն բլոկին։ Վիրտուալ մեքենայի (VM) խափանման դեպքում բոլոր չորս հանգույցները կանգ են առնում։ Մեկ ֆիզիկական հոսթի խափանումը փորձարկելու համար օգտագործեք չորս անկախ հոսթ՝ յուրաքանչյուրում մեկ վավերացնող հանգույց։

## Կանգնեցում և աշխատանքի վերսկսում {#stop-and-resume}

```sh
python3 poc.py down
python3 poc.py up
```

Երկու հրամաններն էլ գործարկեք այն պանակից, որտեղ ապասեղմել եք հավաքակազմը։ `state/` պանակը պահեք Docker-ի բոլոր չորս հատորների հետ միասին, որպեսզի վերագործարկումից հետո հանգույցները կարողանան բացել նույն գրանցամատյանը։ Եթե գործարկումը կանգ է առնում, նույն պանակում գործարկեք `python3 poc.py logs`։

## Հանրային API-ի փորձարկում {#try-the-public-endpoint}

Հավելվածը կարող է կարդալ SORA Nexus-ի համընդհանուր տվյալների տարածքը Taira ցանցում՝ առանց գրանցամատյանի համար վիրտուալ մեքենա (VM) գործարկելու։ `curl` և `jq` ունեցող աշխատանքային կայանից փորձնական ցանցին ուղարկեք հետևյալ հարցումը՝ միայն ընթերցման համար։

```sh
curl -fsS -H 'Accept: application/json' https://taira.sora.org/status \
  | jq '{peers, blocks, txs_approved, queue_size}'
```

Պատասխանը հայտնում է հարցումն ընդունող հանգույցին միացած հանգույցների, հաստատված բլոկների, հավանության արժանացած և հերթում գտնվող գործարքների քանակը։ Տեղակայումը պլանավորելու համար տես [Ցանցի տեղակայում](/hy/guide/best-practices/network-deployment.md)։
