# Torii Վերջնական կետեր {#torii-endpoints}

Torii է HTTP, SSE, եւ WebSocket դարպասային Iroha 3. Այն սպասարկում է երկու ledger-ն ուղղված APIs եւ օպերատորի վերջային կետերը:

Գործող արձանագրության կանոնները հետեւյալն են.

- քանոնական երկկողմ ձեւաչափը Norito
- շատ վերջնական կետեր նույնպես աջակցում են JSON, երբ ուղարկում եք `Accept: application/json`
- չափանիշները ներկայացված են Prometheus ձեւաչափով

Ֆորմատի մանրամասների, բովանդակության բանակցությունների, դասակարգման դրոշների, սխեմայի շիշերի եւ Norito RPC ուղեցույցի համար տես [Norito հղումը](/hy/reference/norito.md):

## Համանախագահական կետեր {#common-endpoints}

|Վերջնական կետ |ձեւաչափ |Նպատակ|
| --- | --- | --- |
|`POST /v1/pipeline/transactions` |Norito |Ներկայացրեք ստորագրված գործարք |
|`POST /v1/query` |Norito |Ներկայացնել ստորագրված հարցում |
|`GET /v1/events/ws` |WebSocket |Գրանցվեք իրադարձությունների հոսքներին |
|`GET /v1/events/sse` |SSE |Գրանցվեք SSE-ից ավելի իրադարձությունների հոսքներին|
|`GET /v1/blocks/stream` |WebSocket |Պայմանավորված բլոկների հոսք|
|`GET /v1/peers` |JSON |Torii կողմից բացված զուգընկերների ցուցակ |
|`GET /livez` |Տեքստ |Միայն գործընթացային կենսունակություն. դա չի նշանակում արձանագրության պատրաստակամություն |
|`GET /readyz` |JSON |Լիարժեք բջիջների պատրաստությունը, ներառյալ պարտադիր առցանց կանխիկ ստուգումները|
|`GET /health` |JSON |Պատրաստության հետաքննություն նույն անփոխարինելի առցանց կանխիկով |
|`GET /v1/api/version` |Տեքստ |Բլոկային վերնագրերի ներկայիս տարբերակը |
|`GET /status` |Norito կամ JSON |Բարձր մակարդակի ախտորոշման կարգավիճակ; հստակ պահանջ JSON |
|`GET /metrics` |Պրոմետեոս |Պրոմետեուսի սրբման վերջակետը |
|`GET /v1/schema` |JSON |Տվյալների մոդելային սխեմանայի ակնթարթային նկարը , որը մատուցվում է հանգույցի կողմից , երբ ակտիվացված է |
|`GET /openapi` կամ `GET /openapi.json` |JSON |OpenAPI փաստաթուղթ ակտիվ Torii HTTP երթեւեկության համար |
|`GET /v1/parameters` |JSON |Նոդի պարամետրերի ակնթարթային նկար|
|`GET /v1/node/capabilities` |JSON |Նոդի կարողությունը եւ տվյալների մոդելի մետադատները |
|`GET /v1/time/now` |JSON |Կոդի պատային ժամացույցի լուսանկար |
|`GET /v1/time/status` |JSON |Ժամանակային համաժամեցման վիճակը |

SSE պահանջի համար գովազդեք բնային հոսքը գումարած տիպված հետընթացը.

```http
Accept: text/event-stream, application/json
```

Torii-ը նախ բանակցում է խնդրանքային շերտում JSON կամ Norito ներկայացումը, այնուհետեւ հավաստիացնում է բնիկ `text/event-stream` պատասխանը: Հետեւաբար միայն `text/event-stream` ուղարկելը մերժվում է `406`-ով; [-stream իրադարձությունների բաղադրատոմսը](/hy/cookbook/stream-events.md) օգտագործում է ամբողջական գլուխը:

`/openapi` սխեմանում ներկայացված երթուղիների համար հիմնական ստեղծված պայմանագիրն է, այլ ոչ թե ամբողջական շահագործման հետաքննության ինվենտարի: Ներկայիս փաստաթղթում բացակայում են `/livez` եւ `/readyz`, եւ դրա `/health` նկարագրությունը կարող է ուշանալ պատրաստության կառավարիչին: Ստեղծեք երթուղային հաճախորդներ կենդանի փաստաթղթից, բայց հավաստիացրեք ակտիվությունն ու պատրաստվածությունը անմիջապես գործող հանգույցի եւ փակված հյուրերի դեմ: Ճշգրիտ մակերեսը դեռ կախված է կառուցման առանձնահատկություններից եւ վազման ժամանակի կազմաձեւումից: Օգտագործեք [Torii API կոնսոլը ](/hy/reference/torii-api-console.md) ՝ այդ կենդանի փաստաթղթը բեռնելու, փորձարկելու JSON երթուղիները, կոպիացնել curl պահանջները եւ ներկայիս սխեմանից հաճախորդի կոդ ստեղծելու համար:

## Փորձեք կենդանի Taira երթուղիներ {#try-live-taira-routes}

Հասարակական Taira փորձարկման ցանցը բացահայտում է նույն Torii JSON մակերեսը, որը կիրառման հաճախորդները օգտագործում են միայն ընթերցման համար: Այս հրամանները չեն պահանջում բանալիներ.

```bash
TAIRA_ROOT=https://taira.sora.org

curl -fsS -H 'Accept: application/json' "$TAIRA_ROOT/status" \
  | jq '{blocks, txs_approved, txs_rejected, queue_size, peers}'

curl -fsS "$TAIRA_ROOT/openapi.json" \
  | jq -r '.paths | keys[]' \
  | grep '^/v1/' \
  | head -n 20

curl -fsS -H 'Accept: application/json' \
  "$TAIRA_ROOT/v1/node/capabilities" \
  | jq '{abi_version, data_model_version, query: .query.aggregate.supported_resources}'
```

Փորձեք ռեսուրսների ընթերցումը ներկայիս համաշխարհային վիճակի վերաբերյալ.

```bash
curl -fsS "$TAIRA_ROOT/v1/domains?limit=5" \
  | jq -r '.items[].id'

curl -fsS "$TAIRA_ROOT/v1/assets/definitions?limit=5" \
  | jq -r '.items[] | [.id, .name, .total_quantity] | @tsv'
```

Եթե հանրային փորձարկման ցանցի երթուղին վերադարձնում է `502`, ժամանակներ դուրս, կամ հայտնում է հագեցած հերթը, դա վերաբերվում է որպես վերջնական կետերի մատչելիության խնդիր եւ կրկին փորձել հետագայում նախքան debugging ձեր հաճախորդի կոդը:

## App եւ SORA երթուղի ընտանիքները {#app-and-sora-route-families}

Երբ Torii-ը կառուցվում է հավելվածի դեմ ուղղված առանձնահատկությունների հավաքածուով, այն բացահայտում է լրացուցիչ JSON ընտանիքներ հետազոտողների համար, SORA ծառայություններ, կամուրջային հոսքներ, ապացույցներ եւ պահեստավորում: Այս ընտանիքները չեն կարողացված յուրաքանչյուր ցանցի պրոֆիլում.

|Ճանապարհային ընտանիք |Նպատակ|
| --- | --- |
|`/v1/accounts/`, `/v1/domains/`, `/v1/assets/*` |JSON ընթերցում, հարցման օգնականներ, ներբեռնումի օգնականներ եւ պորտֆելի կամ տիրողների դիտումներ |
|`/v1/nfts/`, `/v1/rwas/`, `/v1/confidential/*` |NFT, իրական աշխարհի ակտիվները եւ գաղտնի ակտիվների տեսանկյունից |
|`/v1/aliases/`, `/v1/assets/aliases/`, `/v1/sns/`, `/v1/identifiers/` |Անունը, կեղծանունները եւ նույնականացողի լուծումը|
|`/v1/explorer/*` |Explorer- ի կողմնորոշված հաշիվ, ակտիվ, բլոկ, գործարք, հրահանգներ, չափանիշներ եւ հոսքի դիտումները |
|`/v1/transactions/`, `/v1/pipeline/`, `/v1/iso20022/*` |Գործարքի պատմությունը, խողովակաշարի վերականգնումը կամ վիճակը եւ ISO 20022 օգնականներ |

## Հաշվի հավաստագրման, տեսանելիության եւ Explorer- ի կուրսերները {#account-authentication-visibility-and-explorer-cursors}

Օգտագործման առնչվող գլխավոր գրքի ընթերցումները օգտագործում են ընտրական մեկ կանոնիկ հաշիվի ստորագրության սահման: Ոչ ստորագրված պահանջը ստանում է միայն ակտիվ հանրային տվյալների տիրույթներ: Վավերացված ստորագրված խնդրանք ավելացնում է զանգահարողի ընթացիկ UAID եւ տվյալների տողերի ճշգրիտ ուղիները, որոնք նշված են այդ հաշվի `CanReadRestrictedDataspace` թույլտվություններով. `CanReadAllLedgerData`-ը տրամադրում է տեսանելիություն յուրաքանչյուր տվյալների տարածքում: Պատվիրելով միայն `X-Iroha-Account`, կամ ցանկացած ոչ ամբողջական կամ սխալ ձեւավորված ստորագրման գլխավորության հավաքածու, վերադարձնում է `401 Unauthorized`; այն չի վերադառնում անանուն տեսանելիությանը:

Նույն տեսանելիության օբյեկտները ֆիլտրում են հաշիվը, տիրույթը, ակտիվի սահմանումը, ակտիվը, NFT, RWA, պահողը եւ Explorer- ը կարդում է: Գոյություն չունեցող առարկա եւ օբյект, որը գտնվում է զանգահարողի տեսանելի երթուղներից դուրս, միտումնավոր անհնար է տարբերել. Գործարքի կատարման եւ հրահանգների պատմությունը ցուցադրվում է միայն այն դեպքում, երբ գործարքի համար գրանցված յուրաքանչյուր երթուղի հատակ տեսանելի է: Միավորված տվյալների տարածքի գործարքը հետեւաբար թաքնված է, երբ նույնիսկ մեկ մասնակիցի ոտքը հեռանում է զանգահարողի շրջանակից. բացակայող, հնացած կամ սխալ ձեւավորված երթեւեկության համատեքստը տեսանելի է միայն գլոբալ ընթերցողի համար:

Torii կիրառում է այս շրջանակը, նախքան օգտագործողի ֆիլտրները, էջավորումը, հաշվարկները կամ կանխատեսումները SSE, WebSocket, պայմանագրային իրադարձության եւ կրկնօրինակման ուղիների վրա: Երկարատեւ հոսքերը վերագնահատում են նույն թույլտվությունը, քանի որ գլխավոր գրասենյակի թույլտվությունները փոխվում են եւ ավարտվում են ընդհանուր թույլտվության ձախողմամբ մուտքի արդյունքում: հետաձգվել է:

Աշխարհի աջակցությամբ վեց Explorer հավաքածուներում օգտագործվում են անբացատրելի կանոնիկ base64url բանալիրների դասիչներ: Նախնական էջի սահմանը 25 է, առավելագույնը 100 եւ մեկ էջը ստուգում է առավելագույնը 512 թեկնածու բանալիները: Յուրաքանչյուր կուրսոր կապված է իր հավաքածուի, ֆիլտրների, քանոնիկ վերջին բանալիների եւ զանգահարողի տեսանելի երթուղային դիջեսի հետ, այնպես որ այն չի կարող կրկնվել մեկ այլ հարցում կամ զանգահարողի երեւակայության փոփոխությունից հետո:

Բլոկի, գործարքի, վերջին գործարքների, հրահանգների եւ վերջին հրահանգների պատմության կուրսորները լրացուցիչ նշում են պարտավորված ակնթարթի բարձրությունը եւ բլոկի хэշը: Պատասխանները բացահայտում են `pagination.limit`, `pagination.snapshot_height`, `pagination.snapshot_hash`, `pagination.next_cursor` եւ `pagination.has_more` Մեկ այլ երթուղու կամ ֆիլտրի հավաքածուի կուրսորը, փոփոխված տեսանելիության դիեզեսը կամ մի ակնթարթային լուսանկար, որը հանգույցն այլեւս չի կարող հաստատել, փակվում է: Պատմական սկանինգը մնում է Torii- ի հարցման մուտքագրման թույլտվության ներսում, մինչ արգելափակող աշխատողը գործում է:

Explorer WebSocket հոսքերը արտանետում են ֆիլտրված ամփոփումներ եւ վերաքննում են տեսանելիությունը, երբ փոփոխվում են գրախանութի թույլտվությունները: Տարօրինակ `GET /v1/blocks/stream` երթուղին տարբեր է. այն արտահանում է ամբողջական ստորագրված բլոկներ, պահանջում է `CanReadAllLedgerData` ձեռքի սեղմման ընթացքում, եւ փակվում է, եթե այդ թույլտվությունը հետագայում չեղյալ է հայտարարվել: Մի օգտագործեք տվյալների տարածք-սկանդվող հետազոտողի համար բնօրինակ հոսքը:

Live `GET /v1/sumeragi/status/sse` կոնսենսուս-դiagnostic հոսքը նույնպես անանուն տվյալների տարածքի սնունդ չէ: Այն պահանջում է օպերատորի ստորագրության ամբողջական գլխավոր վառասյունը յուրաքանչյուր կապի փորձի ժամանակ: Հաճախորդները նոր ստորագրություն են ստեղծում ճշգրիտ հոսքի համար URI եւ չեն հետեւում վերակառուցմանը կամ ավտոմատ փոխադրման հետագա փորձի միջոցով կրկնում ստորագրված փորձը:

## ISO 20022 կամուրջ {#iso-20022-bridge}

Torii-ը բաց է թողնում ISO 20022 կամուրջը `/v1/iso20022/*`-ի տակ, երբ հավելվածին ուղղված API եւ կամրջի գործնական ժամանակը ակտիվ են: կամուրջը դիտավորյալ նպատակային է. այն ոչ թե ընդհանուր նպատակով ISO 20022 հաշվարկային մուտք է գործում, այլ աջակցվող ենթակազմ, որը ընտրված վճարային հաղորդագրությունները վերածում է ստորագրված Iroha փոխանցումների եւ դրանց գլխավոր գրքի կարգավիճակի հետապնդման համար:

|`POST /v1/iso20022/camt056` |Ներկայացրեք originator- ի կողմից վճարման չեղյալ հայտարարելու խնդրանք |
|`POST /v1/iso20022/sese023` |Ներկայացնել արժեթղթերի հաշվարկի հրահանգ |
|`POST /v1/iso20022/sese024` |Ներկայացրեք հակառակորդի սեփականության արժեթղթերի կարգավորման վիճակի հաղորդագրություն |
|`POST /v1/iso20022/sese025` |Ներկայացրեք հակառակորդի սեփականության արժեթղթերի կարգավորման հաստատում |
|`POST /v1/iso20022/colr012` |Ներկայացնել երաշխիքային փոխարինման հաղորդագրություն |
|`GET /v1/iso20022/messages/{msg_id}` |Կարդացեք կանոնիկ կամուրջի արձանագրությունը մեկ հաղորդագրության համար:|

|`GET /v1/iso20022/messages/{msg_id}/camt029` |Ներկայիս չեղարկման բանաձեւը ներկայացրեք որպես `camt.029` XML |
|`GET /v1/iso20022/messages/{msg_id}/sese024` |Հաշվարկի ընթացիկ կարգավիճակը վերադարձնել `sese.024` XML |
|`GET /v1/iso20022/messages/{msg_id}/sese025` |Գործնական կարգավորման հաստատումը ներկայացրեք որպես `sese.025` XML |

`pacs.008` ներկայացումները պետք է պարունակեն հաղորդագրությունը ID, բանկային փոխհատուցման գումարը, արժույթը, կարգավորման ամսաթիվը, պարտավորն ու վարկատուին IBANs, եւ պարտավորին եւ վարկատուին՝ BICs. Հաշվետու տվյալների կազմաձեւման ժամանակ կամուրջը նաեւ ստուգում է BIC, IBAN եւ ISO 4217 արժույթի անցումները, նախքան ստեղծված գործարքը մուտք է գործում խողովակաշարի:

`pacs.009` ներկայացումները պետք է պարունակեն բիզնես հաղորդագրությունը ID, հաղորդագրության սահմանումը ID, ստեղծման ժամանակը, բանկային փոխհատուցման գումարը, արժույթը, հաշվարկման ամսաթիվը, հանձնարարականներ տրամադրող գործակալ BICs, պարտավոր եւ վարկատու IBANs: Եթե հաղորդագրությունը ներառում է `Purp`, կամուրջը ներկայումս ընդունում է միայն արժեթղթերի նպատակով ֆինանսավորում. `Purp=SECU`

`pacs.008` եւ `pacs.009` ներկայացման վերջային կետերը ընդունում են XML ISO փաթեթները կամ կամուրջի փորձարկումների ժամանակ օգտագործվող հարթ դաշտի ձեւաչափը: Ընտրական`SplmtryData` դաշտերը կարող են տեղադրել նպատակային Iroha գլխավոր գրքում, աղբյուրի եւ թիրախային հաշիվ IDs կամ հասցեներ, ինչպես նաեւ ակտիվների սահմանումը ID: Պատասխանը `202 Accepted` է ՝ `message_id`, `transaction_hash`, `status`, `pacs002_code`, եւ լուծված գլխավոր / հաշիվ / ակտիվի համատեքստով:

### Մասնակիցների թույլտվություն եւ կյանքի շրջանի սեփականությունը {#participant-authorization-and-lifecycle-ownership}

Յուրաքանչյուր ակտիվացված կամուրջ ունի մասնակիցների կատալոգ: Յուրաքանչյուր մասնակիցի մուտք ունեն եզակի մասնակից ID, մեկ կամ մի քանի օպերատորների հանրային բանալիներ, մեկ կամ ավելի ֆինանսական նույնականացումներ, թույլատրված պրոֆիլների հավաքածու եւ `originator`, `counterparty` կամ երկուսն էլ դերակատարներ: Օպերատորի բանալիները եւ ֆինանսական նույնականացումները չեն կարող պատկանել ավելի քան մեկ մասնակիցին: Կազմակերպեք `audit_admin_keys` առանձին. Audit-admin բանալին չի կարող լինել նաեւ մասնակիցների մուտացիոն բանալին:

Բոլոր ISO երթուղիները պահանջում են նոր օպերատորի ստորագրություն: `pacs.008`, `pacs.009`, `sese.023` կամ `colr.012` նախնական ներկայացման համար հավատարմագրված օպերտորը պետք է պատկանի հայտի գլխավոր `From` ֆինանսական ինքնության կողմից հայտնաբերված մասնակիցին: `To` ինքնությունը պետք է անվանի մեկ այլ կոնֆիգուրացված մասնակից, եւ ընտրված պրոֆիլը պետք է թույլատրվի երկու կողմերի համար: Մշտական մուտքագրումը գրանցում է հեղինակին, հակառակորդին, ընդունող մասնակիցն ու օպերատորի բանալին, ինչպես նաեւ բնօրինակ պրոֆիլին եւ ներմուծված ստորագրության քաղաքականությունը:

Կյանքի շրջանի թույլտվությունը բխում է այդ անփոփոխ արձանագրությունից, այլ ոչ թե զանգահարողի կողմից ընտրված արժեքներից.

|Կյանքի շրջանի հաղորդագրություն |Պահանջվող մասնակից |
| --- | --- |
|`pacs.002`, `pacs.004`, `sese.024`, `sese.025` |`counterparty` դերակատարության օրիգինալ հակառակորդը |
|`camt.056` |Օրիգինալ հեղինակ ՝ `originator` դերի հետ |

Օրիգինալ պրոֆիլը եւ ստորագրության քաղաքականությունը մնացել է փակ ամբողջ կյանքի ցիկլով, այնպես որ զանգահարողը չի կարող ընտրել ավելի թույլ պրոֆիլի թարմացման համար: A `pacs.002` կոդ, որը ներկայացնում է կարգավորումը (`ACSC`, `ACCP`, `SETT` կամ `SETTLED`) փոխում է սկզբնական արձանագրությունը կարգավորվելով միայն այն դեպքում, երբ Torii-ը պարտավորեցրել է գործարքի ապացույցներ:

Հաշվարկի վերջային կետը վերադարձնում է միայն այն գրառումները, որոնցում վավերացված մասնակիցն է հեղինակ կամ հակամարտող։ Հատկապես կոմֆիգուրացված աուդիտորային կառավարիչը ստանում է գլոբալ միայն ընթերցվող աուդիտի տեսանկյուն եւ չի կարող ուղարկել կամ փոխել հաղորդագրություններ: Անհայտ մասնակիցները եւ չկապակցված հաղորդագրությունների նույնականացնողները չեն բացահայտվում:

### Հավերժական կրկնօրինակման ինքնությունը եւ ստորագրված արտահերթ տուփային փաստաթղթերը {#durable-replay-identity-and-signed-outbox-documents}

ISO ձայնագրության խանութները ընդունում են միայն սխեման V3 արձանագրություններ եւ կրկնօրինակում գերեզմանային քարեր: Torii անհաջողություն է առաջացնում բացասական համատեղելիության սխալով, երբ մնում են տվյալները չեն համապատասխանում այդ սխեմային, Այսպիսով, առաջին թողարկման խանութները եւ սարքավորումները պետք է վերականգնվեն: Յուրաքանչյուր հարուստ ձայնագրություն պահում է Մասնակիցների անփոխարինելի ծագումը: Հատուկ մշտական գերեզմանային քար պահում է հաղորդագրությունը ID, payload hash, բիզնես հաղորդագրություն ID, եւ UETR ամբողջական կրճատման համար TTL նույնիսկ այն բանից հետո, երբ հարուստ փաստաթղթերի մանրամասները կտրված են:

Torii-ը շարունակում է կրկնօրինակելու մուտքը մինչեւ կյանքի շրջանի հաղորդագրության ստորագրումը կամ մշակումը: Այն երբեք չի հեռացնում չավարտված կրկնօրինակման ինքնությունը: Եթե կոնֆիգուրացված ձայնագրական հզորությունը պարունակում է միայն TTL-ով պաշտպանված մուտքեր, ներկայացումները ստանում են կրկնօրինակելի `503 Service Unavailable` ՝ առանց կենսաշրջանի կամ հաշվապահական վիճակի փոփոխության:

Յուրաքանչյուր ստեղծված `pacs.002`, `pacs.004`, `camt.029`, `sese.024`, կամ `sese.025` փաստաթուղթը վերադարձվում է որպես `application/xml` այս պատասխանների գլխավորագրերով.

|Գլխավոր |Նշում |
| --- | --- |
|`X-Iroha-Iso-Signature-Domain` |Միշտ `iroha.iso20022.outbound.v2` |
|`X-Iroha-Iso-Signer` |Կոնոնիկ հանրային բանալին կոնֆիգուրացված կամուրջի ստորագրման համար |
|`X-Iroha-Iso-Signature` |Base64 ստորագրությունը XML բայթների վրա, որոնք բաժանված են տիրույթից |

Ստուգեք ստորագրությունը UTF-8 բայթերի հաջորդականության վրա `iroha.iso20022.outbound.v2`, մեկ զրոյական բայտ եւ ճշգրիտ արձագանքային մարմինը: Նախքան ստուգումը մի վերաֆորմատացրեք կամ կարգավորեք XML:

### Լրացուցիչ Parser եւ քարտեզագրման աջակցություն {#additional-parser-and-mapping-support}

IVM ISO օգնականը հավաստիացնում է եւ իրականացնում է նաեւ հետեւյալ հաղորդագրությունների ընտանիքները փաթեթների հավաստիացման, կարգավորման քարտեզավորման կամ իջեցող հաշտեցման համար: Նրանք չունեն ինքնուրույն Torii երթուղիներ:

## Kaigi Հանդիպումներ {#kaigi-sessions}

Kaigi ապահովում է վճարված, իրական ժամանակի աուդիո / տեսահոլովակի սենյակներ SORA Nexus: Օգտագործեք այն, երբ ծրագիրը պահանջում է գրասենյակի աջակցությամբ նստաշրջանների ստեղծումը, ցուցակային փոփոխությունները, ռելեյի մանիֆեսները, կոդավորված ազդանշանը եւ օգտագործման հաշվարկը, փոխարենը պահելով բոլոր կոնֆերենցիաների վիճակը հեռու շղթայից:

Գլխավոր գրասենյակային կյանքի ցիկլը հետեւյալն է.

- `CreateKaigi`: ստեղծել զանգի տիրույթի ներքո եւ պահել դրա քաղաքականությունը, ժամանակացույցը, մետադատները եւ ընտրանքային ռեալի մանիֆեսը:
- `JoinKaigi` եւ `LeaveKaigi`: թարմացրեք զանգերի ցուցակը: Անձնական ռեժիմում մասնակիցները օգտագործում են պարտավորություններ, չեղյալ հայտարարողներ եւ ցուցակի ապացույցներ, այլ ոչ թե ուղղակիորեն բացահայտում են մասնակիցների հաշիվը IDs:
- `RecordKaigiUsage`: ավելացրեք հաշվարկված տեւողությունը եւ գազի ընդհանուր թիվը:
- `EndKaigi`: փակել է նստաշրջանը եւ գրանցել վերջնական ժամադրությունը:

Torii բացատրում է Relay հեռաչափություն `/v1/kaigi/relays`, `/v1/kaigi/relays/{relay_id}`, `/v1/kaigi/relays/health`, եւ `/v1/kaigi/relays/events` երբ ծրագիրը API Հանդիպման վիճակը արտացոլվում է: Kaigi տիրույթի իրադարձություններ, ինչպիսիք են `KaigiRosterSummary`, `KaigiRelayManifestUpdated`, `KaigiRelayHealthUpdated`, եւ `KaigiUsageSummary`.

### CLI Ծխի փորձարկում {#cli-smoke-test}

Սկսեք `iroha kaigi` CLI-ից, երբ ցանկանում եք ստուգել, որ Torii վերջային կետը ընդունում է Kaigi գործարքները, նախքան միացնել UI: Quickstart հրամանը ստեղծում է ժամանակավոր սենյակ ակտիվ Torii վերջային կետի դեմ եւ տպագրում է ամփոփում ՝ զանգի նույնականացմամբ, միանալ հրամանով եւ SoraNet սցենարի ակնարկով:

```bash
iroha kaigi quickstart --auto-join-host --summary-out kaigi-summary.json
```

Սկրիպտային հոսքերի համար բացարձակապես կառավարեք սենյակի կյանքի ցիկլը.

```bash
iroha kaigi create \
  --domain streaming \
  --call-name daily \
  --host <i105-account-id> \
  --privacy-mode transparent \
  --room-policy authenticated

iroha kaigi join --domain streaming --call-name daily --participant <i105-account-id>
iroha kaigi leave --domain streaming --call-name daily --participant <i105-account-id>

iroha kaigi record-usage \
  --domain streaming \
  --call-name daily \
  --duration-ms 120000 \
  --billed-gas 1500

iroha kaigi end --domain streaming --call-name daily
```

Օգտագործեք `--room-policy public` այն սենյակների համար, որոնք ռելեյները կարող են բաց թողնել առանց դիտորդի տոմսերի կամ `--room-policy authenticated`, երբ ելքերը պետք է պահանջեն դիտորդի հավաստագրումը: Օգտագործիր `--privacy-mode zk-roster-v1` միայն հետո ցանցում կազմված է Kaigi ցուցակի եւ օգտագործման ստուգման բանալիները. հակառակ դեպքում միացումները, թերթերը եւ անձնական օգտագործման արձանագրությունները ձախողվում են դետերմինիստիկ ստուգման ընթացքում:

### Փորձարկում JavaScript ապացույցի միջոցով {#testing-with-the-javascript-demo}

Օգտագործեք [soramitsu/iroha-demo-javascript](https://github.com/soramitsu/iroha-demo-javascript) աշխատասեղանի դեմոն վերջից մինչեւ վերջ թեստի համար: Դեմոն էլեկտրոնային եւ Vue ծրագիր է, որը ուղղակիորեն խոսում է Torii ՝ տեղական `@iroha/iroha-js` կապման միջոցով եւ ներառում է բրաուզերների բնիկ մեկ-մեկ մեդիայի համար `/kaigi` երթուղին:

Օգտագործեք դեմոն [`@iroha/iroha-js`](https://github.com/hyperledger-iroha/iroha/tree/main/javascript/iroha_js) ՝ Iroha աղբյուրի պահեստից: Դեմոն փինները SDK -ից մինչեւ `file:../iroha/javascript/iroha_js`, այնպես որ պահպանեք երկու ստուգումները այս եղբայրական դասակարգման մեջ.

```bash
mkdir iroha-wallet-workspace
cd iroha-wallet-workspace
git clone https://github.com/hyperledger-iroha/iroha.git
git clone https://github.com/soramitsu/iroha-demo-javascript.git

cd iroha/javascript/iroha_js
npm install
npm run build:native
npm run build:dist

cd ../../../iroha-demo-javascript
npm install
npm run dev
```

Օգտագործեք Node.js 20 կամ ավելի նոր եւ Rust գործիքային շղթա, որպեսզի տեղական `iroha_js_host` մոդուլը կարողանա կառուցել: Վերակառուցեք SDK- ը հարազատների Iroha ստուգման մեջ դրա աղբյուրը փոխելուց հետո; մաքուր փաթեթավորման դասակարգումը չի պարունակում բեռի աշխատանքային տարածքը, որը անհրաժեշտ է `npm run build:native`:

Կառավարված փորձարկման համար ցուցադրությունը ուղղեք Kaigi-ի կարողության Torii վերջային կետին.

1. Սկսեք Iroha կոճակը ՝ բացելով SORA/Kaigi հավելվածը, որը դիմում է APIs կամ օգտագործեք հանրային ավարտական կետ, որը բացահայտում է ձեզ անհրաժեշտ Kaigi մակերեսները:
2. Ստուգեք հիմնական հասանելիությունը `/health`, ապա ստուգեք կենդանի երթուղու մակերեսը `/openapi` կամ `/openapi.json`: Որոշ տեղակայումներ նույնպես բացահայտում են `/v1/health`, բայց `/health` -ն է պորտալ կենսունակության ստուգումը:
3. Բաժանորդագրություն TAIRA, փորձել ռեալի հեռաչափության երթուղիները կենդանի հանդիպումից առաջ:

   ```bash
   TAIRA=https://taira.sora.org
   curl -fsS "$TAIRA/health"
   curl -fsS "$TAIRA/v1/kaigi/relays"
   curl -fsS "$TAIRA/v1/kaigi/relays/health"
   ```

Այս ստուգումները ապացուցում են, որ Torii եւ Kaigi ռեալի հեռահամաչափությունը հասանելի են: Նրանք չեն ստեղծում հանդիպում. `CreateKaigi` եւ `JoinKaigi` դեռեւս պետք է ֆինանսավորվող դրամապանակներ եւ ստորագրված գործարքների ներկայացումը:
4. Բացեք ցուցադրությունը, գնացեք Կարգավորումների, սահմանեք Torii URL, եւ թույլ տվեք հավելվածին բեռնել շղթան ID եւ ցանցի նախանշանը վերջնական կետից:
5. Ստեղծեք կամ վերականգնել երկու տեղական դրամապանակը ցուցադրության մեջ: Օգտագործեք առանձին հավելվածների պատուհաններ, պրոֆիլներ կամ մեքենաներ, որպեսզի հյուրընկալողն ու հյուրը ունենան առանձին դրամապանակի վիճակ.

Kaigi UI թեստավորման համար՝

1. Հյուրընկալող պատուհանում բացեք Kaigi, ընտրեք Սկսել հանդիպումը, սահմանեք տիտղոս եւ ընտրեք մասնավոր հրավիրում կամ թափանցիկ հրավիրություն:
2. Ընտրեք Սեղմեք տեսախցիկը եւ միկրոֆիլը, որպեսզի WebRTC ունենա տեղական լրատվամիջոցներ:
3. Ընտրեք Հանդիպման հղումը ստեղծեք: Կենդանի դրամապանակը ներկայացնում է `CreateKaigi`; այնուհետեւ հավելվածը ցույց է տալիս `iroha://kaigi/join?call=...&secret=...` հրավիրում եւ `#/kaigi?...` հետադարձ ուղին:
4. Բաց պահեք հյուրընկալող պատուհանը եւ կիսվեք հրավիրմամբ հյուրի հետ:
5. Հյուրերի պատուհանում բացեք հրավիրումը կամ սեղմեք այն Միացեք հանդիպմանը, միացրեք տեղական մեդիա եւ ընտրեք Միացեք հանդիպում: Կենդանի դրամապանակը վերցնում է կոդավորված հյուրընկալող առաջարկը Torii-ից եւ ներկայացնում է `JoinKaigi` ՝ կոդավորված պատասխանի մետադատայով:
6. Հյուրընկալողը պետք է ավտոմատ կերպով կիրառի առաջին պատասխանը ՝ հոսելով կամ քվեարկելով Kaigi զանգային ազդանշանները: Երկու պատուհաններում էլ պետք է ցուցադրվեն միացված մեդիա եւ թարմացված կապի մանրամասներ:
7. Հանդիպման ավարտը հյուրընկալողից, կամ նույն զանգի համար օգտագործեք CLI `iroha kaigi end` հրամանը ID.

Անհատական Kaigi կարիքները պաշտպանված են XOR ՝ մասնավոր մուտքի կետի վճարը վճարելու համար: Եթե ապացուցումը հայտնում է, որ մասնավոր Kaigi կարիքները պաշտպանվում են XOR , օգտագործեք ծրագրում ինքնակառավարման հրահանգը եւ կրկին փորձեք ստեղծել կամ միանալ գործողությանը։ Եթե ապացույցների ստեղծումը, մասնավոր ֆինանսավորումը կամ կենդանի ազդանշանները հասանելի չեն, ապա ցուցադրությունը կարող է վերադառնալ թափանցիկ / ձեռնական հոսք: Այդ դեպքում բացեք առաջադեմ ազդանշանը, պատճենեք կաթվածային առաջարկը կամ պատասխան փաթեթը եւ տեղցրեք այն մյուս պատուհանում:

Demo repo- ի ավտոմատ ստուգումների համար գործարկեք:

```bash
npm test -- tests/kaigiView.spec.ts tests/preloadKaigiBridge.spec.ts
npm run e2e:ui
npm run verify
```

## Պաշտոն եւ չափանիշներ {#status-and-metrics}

Ստատուսի եւ չափանիշների վերջային կետերը առաջին բանն են, որոնք ներմուծվում են դաշբորդերում.

- `/status` բացահայտում է բարձր մակարդակի զուգընկերների, բլոկների, հերթի եւ համաձայնության դաշտերը
- `/metrics` բացահայտում է Prometheus հաշվիչները, չափիչները եւ հիստոգրամները

Nexus օժտված հանգույցներում, վիճակի արտադրանքը ներառում է նաեւ երթուղի եւ տվյալների տարածքի գիտակցող հատվածներ: Երբ `nexus.enabled = false`, այդ հատվածները բաց թողնվում են:

## JSON vs. Norito {#json-vs-norito}

Բազմաթիվ օպերատորների վերջնական կետերը վերադարձնում են Norito որպես նախապայման: Երբ վերջային կետը աջակցում է JSON, ուղարկեք՝

```http
Accept: application/json
```

Սա հատկապես օգտակար է հետեւյալ դեպքերում.

- `/v1/sumeragi/status`
- `/v1/sumeragi/qc`
- `/v1/sumeragi/commit_qc/{hash}`

Երբ վերջնական կետը ընդունում է կամ ուղղակիորեն վերադարձնում է Norito տիպի, օգտագործեք `application/x-norito` որպես բովանդակության տեսակ կամ նախընտրված `Accept` արժեք: Գտեք [Norito](/hy/reference/norito.md#torii-and-norito-rpc) փոխադրման մանրամասները.

## CLI Փակ ճանապարհներ {#cli-shortcuts}

`iroha` CLI-ը արդեն ներառում է հետեւյալ վերջային կետերի շատերը.

```bash
iroha --config ./localnet/client.toml --output-format text ops sumeragi status
iroha --config ./localnet/client.toml --output-format text ops sumeragi phases
iroha --config ./localnet/client.toml ops sumeragi params
iroha --config ./localnet/client.toml --output-format text ops sumeragi telemetry
```
