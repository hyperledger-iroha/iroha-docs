# Torii Վերջնական կետեր {#torii-endpoints}

Torii է HTTP, SSE, եւ WebSocket դարպասային Iroha 3. Այն սպասարկում է երկու ledger-ն ուղղված APIs եւ օպերատորի վերջային կետերը:

Գործող արձանագրության կանոնները հետեւյալն են.

- քանոնական երկկողմ ձեւաչափը Norito
- շատ վերջնական կետեր նույնպես աջակցում են JSON, երբ ուղարկում եք `Accept: application/json`
- չափանիշները ներկայացված են Prometheus ձեւաչափով

Ֆորմատի մանրամասների, բովանդակության բանակցությունների, դասակարգման դրոշների, սխեմայի շիշերի եւ Norito RPC ուղեցույցի համար տես [Norito հղումը](/hy/reference/norito.md):

## Համանախագահական կետեր {#common-endpoints}

|Վերջնական կետ |ձեւաչափ |Նպատակ|
| --- | --- | --- |
|`POST /transaction` |Norito |Ներկայացրեք ստորագրված գործարք |
|`POST /query` |Norito |Ներկայացնել ստորագրված հարցում |
|`GET /events` |WebSocket |Գրանցվեք իրադարձությունների հոսքներին |
|`GET /block/stream` |WebSocket |Պայմանավորված բլոկների հոսք|
|`GET /peers` |JSON |Torii կողմից բացված զուգընկերների ցուցակ |
|`GET /health` |JSON |Հեշտ կենսունակության վերջակետ |
|`GET /api_version` |JSON |Պաշտոնական API տարբերակը |
|`GET /status` |JSON |Բարձր մակարդակի օպերատորների վիճակագրության ամփոփում |
|`GET /metrics` |Պրոմետեոս |Պրոմետեուսի սրբման վերջակետը |
|`GET /schema` |JSON |Տվյալների մոդելային սխեմանայի ակնթարթային նկարը , որը մատուցվում է հանգույցի կողմից |
|`GET /openapi` կամ `GET /openapi.json` |JSON |OpenAPI փաստաթուղթ ակտիվ Torii HTTP երթեւեկության համար |
|`GET /v1/parameters` |JSON |Նոդի պարամետրերի ակնթարթային նկար|
|`GET /v1/node/capabilities` |JSON |Նոդի կարողությունը եւ տվյալների մոդելի մետադատները |
|`GET /v1/api/versions` |JSON |Աջակցված Torii API տարբերակները |
|`GET /v1/events/sse` |SSE |Միջոցառման հոսքը երկարատեւ հաճախորդների համար |
|`GET /v1/time/now` |JSON |Կոդի պատային ժամացույցի լուսանկար |
|`GET /v1/time/status` |JSON |Ժամանակային համաժամեցման վիճակը |

`/openapi` -ը վավերական ավարտային կետերի ցուցակն է վազող հանգույցի համար: Ճշգրիտ մակերեսը կախված է կառուցման առանձնահատկություններից եւ վազման ժամանակի կարգավորումից, այնպես որ ստեղծված հաճախորդները պետք է նախընտրեն կենդանի OpenAPI փաստաթուղթը ձեռքով կոպեացված երթեւեկության ցուցակի փոխարեն: Օգտագործեք [Torii API կոնսոլը ](/hy/reference/torii-api-console.md) ՝ այդ կենդանի փաստաթղթի բեռնելու համար, փորձարկելու JSON երթուղիները, կոպիացնել curl պահանջները եւ ներկայիս սխեմայից հաճախորդի կոդ ստեղծելու համար:

## Փորձեք կենդանի Taira երթուղիներ {#try-live-taira-routes}

Հասարակական Taira փորձարկման ցանցը բացահայտում է նույն Torii JSON մակերեսը, որը կիրառման հաճախորդները օգտագործում են միայն ընթերցման համար: Այս հրամանները չեն պահանջում բանալիներ.

```bash
TAIRA_ROOT=https://taira.sora.org

curl -fsS "$TAIRA_ROOT/status" \
  | jq '{blocks, txs_approved, txs_rejected, queue_size, peers}'

curl -fsS "$TAIRA_ROOT/openapi.json" \
  | jq -r '.paths | keys[]' \
  | grep '^/v1/' \
  | head -n 20

curl -fsS "$TAIRA_ROOT/v1/node/capabilities" \
  | jq '{abi_version, data_model_version, query: .query.aggregate.supported_resources}'
```

Փորձեք ռեսուրսների ընթերցումը ներկայիս համաշխարհային վիճակի վերաբերյալ.

```bash
curl -fsS "$TAIRA_ROOT/v1/domains?limit=5" \
  | jq -r '.items[].id'

curl -fsS "$TAIRA_ROOT/v1/assets/definitions?limit=5" \
  | jq -r '.items[] | [.id, .name, .total_quantity] | @tsv'
```

Եթե հանրային փորձարկման ցանցի երթուղին վերադարձնում է `502`, ժամանակներ դուրս, կամ հայտնում է հագեցած հերթը, դա վերաբերվում է որպես վերջնական կետերի մատչելիության խնդիր եւ կրկին փորձել հետագայում նախքան debugging ձեր հաճախորդի կոդը:

## App եւ SORA երթուղի ընտանիքները {#app-and-sora-route-families}

Երբ Torii-ը կառուցվում է հավելվածի դեմ ուղղված առանձնահատկությունների հավաքածուով, այն բացահայտում է լրացուցիչ JSON ընտանիքներ հետազոտողների համար, SORA ծառայություններ, կամուրջային հոսքներ, ապացույցներ եւ պահեստավորում: Այս ընտանիքները չեն կարողացված յուրաքանչյուր ցանցի պրոֆիլում.

|Ճանապարհային ընտանիք |Նպատակ|
| --- | --- |
|`/v1/accounts/`, `/v1/domains/`, `/v1/assets/*` |JSON ընթերցում, հարցման օգնականներ, ներբեռնումի օգնականներ եւ պորտֆելի կամ տիրողների դիտումներ |
|`/v1/nfts/`, `/v1/rwas/`, `/v1/confidential/*` |NFT, իրական աշխարհի ակտիվները եւ գաղտնի ակտիվների տեսանկյունից |
|`/v1/aliases/`, `/v1/assets/aliases/`, `/v1/sns/`, `/v1/identifiers/` |Անունը, կեղծանունները եւ նույնականացողի լուծումը|
|`/v1/explorer/*` |Explorer- ի կողմնորոշված հաշիվ, ակտիվ, բլոկ, գործարք, հրահանգներ, չափանիշներ եւ հոսքի դիտումները |
|`/v1/transactions/`, `/v1/pipeline/`, `/v1/iso20022/*` |Գործարքի պատմությունը, խողովակաշարի վերականգնումը կամ վիճակը եւ ISO 20022 օգնականներ |
|`/v1/contracts/*` |Պայմանագրի կոդը, տեղակայումը, փաթեթը, զանգը, տեսքը, իրադարձությունը, գործունեությունը, rollup- ը եւ պետական երթուղիները |
|`/v1/multisig/`, `/v1/controls/` |Multisig առաջարկները, հաստատումները եւ փոխանցման վերահսկողության օգնականները |
|`/v1/bridge/`, `/v1/ledger/`, `/v1/proofs/*` |Վերջնականություն, վիճակի ապացույց, արգելափակման ապացույց, ապացույցների պահպանումը եւ ապացույցի հարցումների ուղիները |
|`/v1/da/*` |Տվյալների մատչելիության ներբեռնումը, մանիֆեսները, ապացույցի քաղաքականությունները, պարտավորությունները եւ հստակ մտադրությունները |
|`/v1/zk/*` |ZK արմատները, ապացույցների ստուգումը, IVM ապացուցում, քվեների հաշվարկը, ստուգման բանալիները, ապացույցի արձանագրությունները եւ հավելվածները |
|`/v1/gov/`, `/v1/ministry/` |Կառավարման առաջարկներ, քվեաթերթիկներ, խորհրդային պետություն, պաշտպանված անվան տարածքներ, օրակարգի առաջարկություններ, օրենք ընդունում եւ վերջնականացում |

## ISO 20022 կամուրջ {#iso-20022-bridge}

Torii-ը բաց է թողնում ISO 20022 կամուրջը `/v1/iso20022/*`-ի տակ, երբ հավելվածին ուղղված API եւ կամրջի գործնական ժամանակը ակտիվ են: կամուրջը դիտավորյալ նպատակային է. այն ոչ թե ընդհանուր նպատակով ISO 20022 հաշվարկային մուտք է գործում, այլ աջակցվող ենթակազմ, որը ընտրված վճարային հաղորդագրությունները վերածում է ստորագրված Iroha փոխանցումների եւ դրանց գլխավոր գրքի կարգավիճակի հետապնդման համար:

`pacs.008` ներկայացումները պետք է պարունակեն հաղորդագրությունը ID, բանկային փոխհատուցման գումարը, արժույթը, կարգավորման ամսաթիվը, պարտավորն ու վարկատուին IBANs, եւ պարտավորին եւ վարկատուին՝ BICs. Հաշվետու տվյալների կազմաձեւման ժամանակ կամուրջը նաեւ ստուգում է BIC, IBAN եւ ISO 4217 արժույթի անցումները, նախքան ստեղծված գործարքը մուտք է գործում խողովակաշարի:

`pacs.009` առաջադրանքները պետք է ներկայացնեն բիզնեսի հաղորդագրությունը ID, հաղորդագրության սահմանումը ID, ստեղծման ժամանակը, միջբանկային կարգավորման գումարը, արժույթը, կարգավորման ամսաթիվը, հանձնարարականներ տալու եւ պատվիրված գործակալը BICs, եւ պարտավորն ու վարկատու IBANs. Եթե հաղորդագրությունը ներառում է `Purp`, կամուրջը ներկայումս ընդունում է միայն արժեթղթերի նպատակով ֆինանսավորում. `Purp=SECU`.

`pacs.008` եւ `pacs.009` ներկայացման վերջային կետերը ընդունում են XML ISO փաթեթները կամ կամուրջի փորձարկումների ժամանակ օգտագործվող հարթ դաշտի ձեւաչափը: Ընտրական `SplmtryData` դաշտերը կարող են տեղադրել նպատակային Iroha գլխավոր գրասենյակը, աղբյուրը եւ նպատակային հաշիվը IDs կամ հասցեները, ինչպես նաեւ ակտիվների սահմանումը ID: Պատասխանը `202 Accepted` է, որը կազմում է `message_id`, `transaction_hash`, `status`, `pacs002_code`, եւ լուծված գրքի/հաշվի/աակտիվի համատեքստը։

## Kaigi Հանդիպումներ {#kaigi-sessions}

Kaigi ապահովում է վճարված, իրական ժամանակի աուդիո / տեսահոլովակի սենյակներ SORA Nexus: Օգտագործեք այն, երբ ծրագիրը պահանջում է գրասենյակի աջակցությամբ նստաշրջանների ստեղծումը, ցուցակային փոփոխությունները, ռելեյի մանիֆեսները, կոդավորված ազդանշանը եւ օգտագործման հաշվարկը, փոխարենը պահելով բոլոր կոնֆերենցիաների վիճակը հեռու շղթայից:

Գլխավոր գրասենյակային կյանքի ցիկլը հետեւյալն է.

- `CreateKaigi`: ստեղծել զանգի տիրույթի ներքո եւ պահել դրա քաղաքականությունը, ժամանակացույցը, մետադատները եւ ընտրանքային ռեալի մանիֆեսը:
- `JoinKaigi` եւ `LeaveKaigi`: թարմացրեք զանգերի ցուցակը: Անձնական ռեժիմում մասնակիցները օգտագործում են պարտավորություններ, չեղյալ հայտարարողներ եւ ցուցակի ապացույցներ, այլ ոչ թե ուղղակիորեն բացահայտում են մասնակիցների հաշիվը IDs:
- `RecordKaigiUsage`: ավելացրեք հաշվարկված տեւողությունը եւ գազի ընդհանուր թիվը:
- `EndKaigi`: փակել է նստաշրջանը եւ գրանցել վերջնական ժամադրությունը:

Torii բացատրում է Relay հեռաչափություն `/v1/kaigi/relays`, `/v1/kaigi/relays/{relay_id}`, `/v1/kaigi/relays/health`, եւ `/v1/kaigi/relays/events` երբ ծրագիրը API Հանդիպման վիճակը արտացոլվում է: Kaigi տիրույթի իրադարձություններ, ինչպիսիք են `KaigiRosterSummary`, `KaigiRelayManifestUpdated`, `KaigiRelayHealthUpdated`, եւ `KaigiUsageSummary`.

### CLI Ծխի փորձարկում {#cli-smoke-test}

Սկսեք `iroha kaigi` CLI-ից, երբ ցանկանում եք ստուգել, որ Torii վերջային կետը ընդունում է Kaigi գործարքները, նախքան միացնել UI: Quickstart հրամանը ստեղծում է ժամանակավոր սենյակ ակտիվ Torii վերջային կետի դեմ եւ տպագրում է ամփոփում ՝ զանգի նույնականացմամբ, միանալ հրամանով եւ SoraNet սցենարի ակնարկով:

```bash
iroha kaigi quickstart --auto-join-host --summary-out kaigi-summary.json
```

Սկրիպտային հոսքերի համար բացարձակապես կառավարեք սենյակի կյանքի ցիկլը.

```bash
iroha kaigi create \
  --domain streaming \
  --call-name daily \
  --host <i105-account-id> \
  --privacy-mode transparent \
  --room-policy authenticated

iroha kaigi join --domain streaming --call-name daily --participant <i105-account-id>
iroha kaigi leave --domain streaming --call-name daily --participant <i105-account-id>

iroha kaigi record-usage \
  --domain streaming \
  --call-name daily \
  --duration-ms 120000 \
  --billed-gas 1500

iroha kaigi end --domain streaming --call-name daily
```

Օգտագործեք `--room-policy public` այն սենյակների համար, որոնք ռեալիները կարող են բացել առանց դիտորդի տոմսերի կամ `--room-policy authenticated`, երբ ելքերը պետք է պահանջեն դիտորդի հավաստագրումը: Օգտագործիր `--privacy-mode zk-roster-v1` միայն այն բանից հետո, երբ ցանցը ունի Kaigi ցուցակի եւ օգտագործման հաստատման կոճակները կազմված; հակառակ դեպքում միավորումները, թերթերը եւ անձնական օգտագործման արձանագրությունները ձախողվում են դետերմինիստական ստուգման ընթացքում:

### Փորձարկում JavaScript ապացույցի միջոցով {#testing-with-the-javascript-demo}

Օգտագործեք [soramitsu/iroha-demo-javascript](https://github.com/soramitsu/iroha-demo-javascript) աշխատասեղանի դեմոն վերջից մինչեւ վերջ թեստի համար: Դեմոն էլեկտրոնային եւ Vue ծրագիր է, որը ուղղակիորեն խոսում է Torii ՝ տեղական `@iroha/iroha-js` կապման միջոցով եւ ներառում է բրաուզերների բնիկ մեկ-մեկ մեդիայի համար `/kaigi` երթուղին:

Օգտագործեք դեմոն [`@iroha/iroha-js`](https://github.com/hyperledger-iroha/iroha/tree/main/javascript/iroha_js) ՝ Iroha աղբյուրի պահեստից: Դեմոն փինները SDK -ից մինչեւ `file:../iroha/javascript/iroha_js`, այնպես որ պահպանեք երկու ստուգումները այս եղբայրական դասակարգման մեջ.

```bash
mkdir iroha-wallet-workspace
cd iroha-wallet-workspace
git clone https://github.com/hyperledger-iroha/iroha.git
git clone https://github.com/soramitsu/iroha-demo-javascript.git

cd iroha/javascript/iroha_js
npm install
npm run build:native
npm run build:dist

cd ../../../iroha-demo-javascript
npm install
npm run dev
```

Օգտագործեք Node.js 20 կամ ավելի նոր եւ Rust գործիքային շղթա, որպեսզի տեղական `iroha_js_host` մոդուլը կարողանա կառուցել: Վերակառուցեք SDK- ը հարազատների Iroha ստուգման մեջ դրա աղբյուրը փոխելուց հետո; մաքուր փաթեթավորման դասակարգումը չի պարունակում բեռի աշխատանքային տարածքը, որը անհրաժեշտ է `npm run build:native`:

Կառավարված փորձարկման համար ցուցադրությունը ուղղեք Kaigi-ի կարողության Torii վերջային կետին.

1. Սկսեք Iroha կոճակը ՝ բացելով SORA/Kaigi հավելվածը, որը դիմում է APIs կամ օգտագործեք հանրային ավարտական կետ, որը բացահայտում է ձեզ անհրաժեշտ Kaigi մակերեսները:
2. Ստուգեք հիմնական հասանելիությունը `/health`, ապա ստուգեք կենդանի երթուղու մակերեսը `/openapi` կամ `/openapi.json`: Որոշ տեղակայումներ նույնպես բացահայտում են `/v1/health`, բայց `/health` -ն է պորտալ կենսունակության ստուգումը:
3. Բաժանորդագրություն TAIRA, փորձել ռեալի հեռաչափության երթուղիները կենդանի հանդիպումից առաջ:

   ```bash
   TAIRA=https://taira.sora.org
   curl -fsS "$TAIRA/health"
   curl -fsS "$TAIRA/v1/kaigi/relays"
   curl -fsS "$TAIRA/v1/kaigi/relays/health"
   ```

Այս ստուգումները ապացուցում են, որ Torii եւ Kaigi ռեալի հեռահամաչափությունը հասանելի են: Նրանք չեն ստեղծում հանդիպում. `CreateKaigi` եւ `JoinKaigi` դեռեւս պետք է ֆինանսավորվող դրամապանակներ եւ ստորագրված գործարքների ներկայացումը:
4. Բացեք ցուցադրությունը, գնացեք Կարգավորումների, սահմանեք Torii URL, եւ թույլ տվեք հավելվածին բեռնել շղթան ID եւ ցանցի նախանշանը վերջնական կետից:
5. Ստեղծեք կամ վերականգնել երկու տեղական դրամապանակը ցուցադրության մեջ: Օգտագործեք առանձին հավելվածների պատուհաններ, պրոֆիլներ կամ մեքենաներ, որպեսզի հյուրընկալողն ու հյուրը ունենան առանձին դրամապանակի վիճակ.

Kaigi UI թեստավորման համար՝

1. Հյուրընկալող պատուհանում բացեք Kaigi, ընտրեք Սկսել հանդիպումը, սահմանեք տիտղոս եւ ընտրեք մասնավոր հրավիրում կամ թափանցիկ հրավիրություն:
2. Ընտրեք Սեղմեք տեսախցիկը եւ միկրոֆիլը այնպես որ WebRTC ունի տեղական լրատվամիջոցներ:
3. Ընտրեք Հանդիպման հղումը ստեղծեք: Կենդանի դրամապանակը ներկայացնում է `CreateKaigi`; այնուհետեւ հավելվածը ցույց է տալիս `iroha://kaigi/join?call=...&secret=...` հրավիրում եւ `#/kaigi?...` հետադարձ ուղին:
4. Բաց պահեք հյուրընկալող պատուհանը եւ կիսվեք հրավիրմամբ հյուրի հետ:
5. Հյուրերի պատուհանում բացեք հրավիրումը կամ սեղմեք այն Միացեք հանդիպմանը, միացրեք տեղական մեդիա եւ ընտրեք Միացեք հանդիպում: Կենդանի դրամապանակը վերցնում է կոդավորված հյուրընկալող առաջարկը Torii-ից եւ ներկայացնում է `JoinKaigi` ՝ կոդավորված պատասխանի մետադատայով:
6. Հյուրընկալողը պետք է ավտոմատ կերպով կիրառի առաջին պատասխանը ՝ հոսելով կամ քվեարկելով Kaigi զանգի ազդանշանները: Երկու պատուհաններում պետք է ցուցադրվեն միացված մեդիա եւ թարմացված կապի մանրամասներ:
7. Հանդիպման ավարտը հյուրընկալողից, կամ նույն զանգի համար օգտագործեք CLI `iroha kaigi end` հրամանը ID.

Անհատական Kaigi կարիքները պաշտպանված են XOR ՝ մասնավոր մուտքի կետի վճարը վճարելու համար: Եթե ապացուցումը հայտնում է, որ մասնավոր Kaigi կարիքները պաշտպանվում են XOR , օգտագործեք ծրագրում ինքնակառավարման հրահանգը եւ կրկին փորձեք ստեղծել կամ միանալ գործողությանը։ Եթե ապացույցների ստեղծումը, մասնավոր ֆինանսավորումը կամ կենդանի ազդանշանները հասանելի չեն, ապա ցուցադրությունը կարող է վերադառնալ թափանցիկ / ձեռնական հոսք: Այդ դեպքում բացեք առաջադեմ ազդանշանը, պատճենեք կաթվածային առաջարկը կամ պատասխան փաթեթը եւ տեղցրեք այն մյուս պատուհանում:

Դեմո repo- ի ավտոմատ ստուգումների համար գործարկեք:

```bash
npm test -- tests/kaigiView.spec.ts tests/preloadKaigiBridge.spec.ts
npm run e2e:ui
npm run verify
```

Կենտրոնացված Vitest սվիթները ընդգրկում են Kaigi հանդիպման հղումների ստեղծումը, համապարփակ հրավիրման բեռնումը, մասնավոր ստեղծել / միանալ / ավարտել կամուրջի զանգերը, ինքնահսկողության հրահանգներ, ձեռքով fallbacks եւ պատասխանների հարցումներ: UI ծխի թեստը ներառում է `/kaigi` երթուղին աշխատասեղանի եւ շարժական չափի տեսարաններում: Երկու դրամապանակի միջեւ կենդանի մեդիա դեռեւս անհրաժեշտ է ձեռնական երկու պատուհանների փորձարկում, քանի որ բրաուզերային տեսախցիկի / միկրոֆոնի թույլտվությունները եւ զուգահեռ մեդիայի հոսքերը բնապահպանական հատուկ են:

Նմուշի ինտեգրման կոդի համար դիտեք [ներմուծված Kaigi a-ում JavaScript App- ը](/hy/guide/tutorials/kaigi.md).

## Պաշտոն եւ չափանիշներ {#status-and-metrics}

Ստատուսի եւ չափանիշների վերջային կետերը առաջին բանն են, որոնք ներմուծվում են դաշբորդներում.

- `/status` բացահայտում է բարձր մակարդակի զուգընկերների, բլոկների, հերթի եւ համաձայնության դաշտերը
- `/metrics` բացահայտում է Prometheus հաշվիչները, չափիչները եւ հիստոգրամները

Nexus օժտված հանգույցներում, վիճակի արտադրանքը ներառում է նաեւ երթուղի եւ տվյալների տարածքի գիտակցող հատվածներ: Երբ `nexus.enabled = false`, այդ հատվածները բաց թողնվում են:

## JSON vs. Norito {#json-vs-norito}

Բազմաթիվ օպերատորների վերջնական կետերը վերադարձնում են Norito որպես նախապայման: Երբ վերջային կետը աջակցում է JSON, ուղարկեք՝

```http
Accept: application/json
```

Սա հատկապես օգտակար է հետեւյալ դեպքերում.

- `/v1/sumeragi/status`
- `/v1/sumeragi/qc`
- `/v1/sumeragi/commit_qc/{hash}`

Երբ վերջնական կետը ընդունում է կամ ուղղակիորեն վերադարձնում է Norito տիպի, օգտագործեք `application/x-norito` որպես բովանդակության տեսակ կամ նախընտրված `Accept` արժեք: Գտեք [Norito](/hy/reference/norito.md#torii-and-norito-rpc) փոխադրման մանրամասները.
