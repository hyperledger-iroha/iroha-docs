# 監控欺诈行為 {#fraud-monitoring}

監控欺诈行為 Iroha 部署是一種建立在
在本帳事件,查詢,權限和應用背景下. Iroha 記錄了什麼
您的監控系統決定
您的經營過程有哪些疑似模式以及這些案例的路徑
檢查者或自動反應控制.

請把欺騙監控視為一個獨立的服務,
這項服務應加入本帳活動,
沒有連鎖的風險背景,存在證據,並只提交回應交易
透過有明顯授權的帳戶.

## 監控模式 {#monitoring-model}

有用的監控管道有四個階段:

1. **收藏** 數據簿和運行者訊息 Torii 活動流,查詢,
   數據與數值.
2. **豐富自己的生活** 沒有連鎖背景的事件,例如客戶狀況,
   應用程序會議識別子,預期限制,
   該案件 IDs.
3. **檢測** 沒有任何疑似行為,
   沒有任何問題.
4. **回答我們** 警告運營商,暫停應用端工作流程;
   撤回不必要的許可證,或提交補償交易
   當您的管理過程允許時.

除非每位核實者都必須重複使用
執行時間驗證應實行權限和交易
監控欺诈應說明風險,保存證據,
運營商迅速行動.

## 需要收集的訊號 {#signals-to-collect}

開始使用僅限的訂閱,

| 訊號 | 來源 | 使用 |
| --- | --- | --- |
| 交易狀況 | 管道事件 | 檢測重複拒絕,未能授權試驗和不尋常的提交模式 |
| 帳戶生命周期和元數據 | 數據事件和帳戶查詢 | 檢測新的帳戶,姓名變更,身份更新以及意外的元數據編輯 |
| 資產餘額和轉讓 | 資產數據事件和資產查詢 | 檢測高價值的動作,快速風,平衡排水以及不尋常的對方 |
| 角色和權限 | 角色及許可查詢,角色數據事件 | 檢測特權升級,緊急援助和高風險的使用情況 |
| 引發器和合同的變化 | 引發,合同和執行事件 | 發現新的自動化,改變執行路徑以及可疑的升級活動 |
| 配置和同行變化 | 設定與同行活動 | 檢測影響驗證,網絡或運營者可視性的治理變化 |
| 運營商的健康 | `/metrics` 及其他 Sumeragi 狀況路線 | 隔離可疑的使用者行為與節點過載,排隊壓力或網絡故障 |

使用 [事件過濾器](/zh-hant/blockchain/filters.md) 避免整個事件的處理
當一個規則只需要帳戶,資產,角色或配置變更時,
透過連結,將流程與頁面化相結合
[詢問問題](/zh-hant/blockchain/queries.md) 顯示器可以在停電時間後恢復.

## 檢測規則 {#detection-rules}

常見的規則家庭包括:

| 規則家族 | 範例條件 | 典型的反應 |
| --- | --- | --- |
| 速度 | 帳戶在短時間內轉移超過預期金額或數量 | 預告審核人員和暫停該帳戶的申請側提款 |
| 傳輸方式 | 資金從一個帳戶轉移到許多新發現的帳戶 | 在允許額外轉移之前需要手動批准 |
| 排水平衡 | 密碼,稱或元數據變更後不久, | 盡可能增加收購額度 |
| 增加特權 | 在更改窗口之外,授予高風險的許可或角色 | 警示經營者及審核補助交易 |
| 拒絕的爆發 | 一位簽約者或客戶進行了反復拒絕的交易 | 檢查是否使用信用證,整合錯誤或調查 |
| 自動化改變 | 引擎,合同或執行器相關的對象突然變化 | 暫停依賴工作流程,直到修改審核 |
| 對治理敏感的變化 | 在沒有批准的票票的情况下發生同行,配置或運行時間狀態變化 | 比較管理紀錄與事件過程 |

他們需要的證據,
該組織或組織可以關閉
根據客戶的風險,資產類型或管轄權而設的值
而不是在專用脚本中.

## 應對控制 {#response-controls}

在啟動警報之前設計應對行動.
必須有從檢測到封鎖的記錄路徑:

- 通知安全,運營和負責人
  影響域名或資產定義
- 保存事件導覽器,區塊哈希,交易哈希,權威,有效載荷,
  檢測規則使用的查詢快照
- 暫停應用端行動,
  撤回,簽署,橋渡或和解工作流程
- 取消因事件不再合理的角色或許可
  應對計畫
- 只有在積極治理政策下,才提交跟蹤帳號交易
  並允許他們使用
- 如果證據顯示簽名者妥协,

避免讓監控服務有廣泛的寫入.
提供最少需要回應的權限的技術帳戶
人的承認應該仍然是任何
可移动資產,更改權限或改變驗證器面向的工作流程
這樣的裝置.

## 證據與保存 {#evidence-and-retention}

存儲監控證據在獨立的附件系統中,
核准器資料庫. 每個警告應包含:

- 事件流名稱和導覽器
- 區塊高度或可用時區塊哈希
- 交易 hash 和權威
- 影響的帳戶,域名,資產,角色,引擎或配置 ID
- 原始事件的有效載荷或它的一種法典化量
- 查詢快照使用來加強警報
- 規則名稱,版本,值,分數和評審決定

沒有公開帳號的傳統資料,
如果您需要連結一個網站,
在外鎖狀態上,更喜歡一個案例識別碼,簽署的證書,
或是沒有披露私人細節的哈希承諾.

## 實施檢查列表 {#implementation-checklist}

- 啟動所需的遠隔測量圖像 `/metrics` 並提供運營者路線.
- 註冊使用 Torii 透過微小的濾網,
  顯示器.
- 保持事件導向,以便顯示器可以在沒有空隙的情况下重新啟動.
- 在常規時間表上,
- 保持風險值,並允許版本控制配置中的列表.
- 檢測預警規則與歷史區塊,
- 應對行動使用專屬的技術帳戶.
- 定期審核的角色和許可授予.
- 在應對事件過程中包括監控欺騙的警報.
