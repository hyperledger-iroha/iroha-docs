# שאלות {#queries}

למרות שרוב המידע על מצב blockchain יכול להיות
ניתן להשיג, כפי שהראינו קודם לכן, באמצעות מועתק אירוע ופילטר
לצמצם את טווח האירועים לאלו של עניין, לפעמים אתה צריך
קח גישה ישירה יותר. _שאלות_.

שאלונות הם אובייקטים קטנים דומים להוראות אשר, כאשר נשלח Iroha
חבר'ה, הזמינו תגובה עם פרטים על המצב העולמי הנוכחי.

זה לא בהכרח הסוג היחיד של מידע זמין
הרשת, אבל זה הסוג היחיד של מידע _מובטח_ ל
להיות זמין בכל הרשתות.

עבור כל פיקוח של Iroha, ייתכן שיש מידע נוסף זמין.
לדוגמה, זמינות הנתונים הטלמטריים תלויה ברשת
מנהלים. זה לגמרי ההחלטה שלהם אם הם רוצים או לא
להקצות כוח עיבוד לעקוב אחר העבודה במקום להשתמש בו כדי לעשות את
לעומת זאת, תפקוד מסוים תמיד נדרש, למשל
גישה לבריאות החשבון שלך.

התוצאות של שאלות יכולות להיות [סגורה](#sorting), [דף](#pagination)
ו [מסנן](#filters) צמד-צד בבת אחת. הסורטינג נעשה
בדיקת הנתונים מובנים על ידי רשימת הנתונים.
עקרונות, ממחלק ספציפי (פרטי IP מסכות פילטר כתובת) ל
שיטות של כושרת רצועות `begins_with` משולבים באמצעות פעולות לוגיות.

## נסה את זה. Taira {#try-it-on-taira}

Taira חושף רק קריאה עזר חיפוש מעל JSON למשאבים משותפים.
להתאמן בעמודי עמודים וניהול תגובות לפני חיבור SDK:

```bash
TAIRA_ROOT=https://taira.sora.org

curl -fsS "$TAIRA_ROOT/v1/accounts?limit=3" \
  | jq '{total, ids: [.items[].id]}'

curl -fsS "$TAIRA_ROOT/v1/domains?limit=3" \
  | jq '{total, domains: [.items[].id]}'

curl -fsS "$TAIRA_ROOT/v1/assets/definitions?limit=3" \
  | jq '{total, assets: [.items[] | {id, name, total_quantity}]}'
```

עבור אבחון אפליקציה, לשמור על בדיקות עשן אלה נפרדות מהעסקה חתומה
ניסויים. כישלון בקשת קריאה בלבד בדרך כלל מצביע על זמינות נקודת הסיום,
גישה לרשת, או תואמת מסלול לפני שהיא מצביע על הגדרת חותם.

## ליצור בקשה {#create-a-query}

השתמשו בפתוח חישושים מ- SDK או CLI. לדוגמה, הנתונים הנוכחיים
חשיפה מודל `FindAccounts` עבור חשבונות רשימות:

```rust
let query = FindAccounts;
```

הנה דוגמא של חיפוש שמוצא את נכסי אליס:

```rust
let alice_id = load_canonical_account_id_from_client_config()?;
let query = FindAssetsByAccountId::new(alice_id);
```

## דף {#pagination}

עבור שאילות ייחודיות ושאילויות קטנות חוזרות, אתה יכול להשתמש `client.request`
להגיש בקשה ולקבל את התוצאה במקצת.

עם זאת, שאלות רחבות שניתן לחזור עליהן כגון `FindAccounts`, `FindAssets`, או
`FindBlocks` ניתן להחזיר קבוצות גדולות של תוצאות.
השותף והלקוח.

כדי לבנות `Pagination`, אתה צריך להתקשר.
`client.request_with_pagination(query, pagination)`, איפה `pagination`
הוא מבוסס כך:

```rust
let starting_result: u32 = _;
let limit: u32 = _;
let pagination = Pagination::new(Some(starting_result), Some(limit));
```

## פילטרים {#filters}

כאשר אתה יוצר בקשה, אתה יכול להשתמש במעשן כדי להחזיר רק את התוצאות
שמתאימים למעשן הנקרא.

פילטרים הם ספציפיים עבור בקשת. לדוגמה, בקשות חשבונות ניתן לצמצם על ידי
זהות חשבון או מטא נתונים, בעוד שאילת נכסים יכולה להיות מצטמצמת על ידי נכס
הגדרה, חשבון בעלת, או תחזית דומיין. SDK יש תשומת לב כפופה
בונים ככל האפשר כדי שהסוג של הגלוי יתאים לסוג ההוצאת של החיפוש.

## סורטינג {#sorting}

Iroha יכול לסדר פריטים עם [נתונים](/he/blockchain/metadata.md)
מבחינה לקסיקוגרפית אם אתה מספק מפתח לסדר במהלך הבנייה
מקרה שימוש טיפוסי הוא עבור חשבונות שיש `registered-on`
הכניסה של מטא-מנתונים, אשר, כאשר מסורג, מאפשר לך להציג את החשבון
היסטוריה של הרישום.

הסורטציה חל רק על יחידות
[נתונים](/he/blockchain/metadata.md), כמו שפתור הנתונים המטא
לסדר את תוצאות החיפוש.

אתה יכול לשלב סורטינג עם דף ופילטרים.
תכונה אופציונלית, רוב השאלות עם דף לא יצטרכו את זה.
