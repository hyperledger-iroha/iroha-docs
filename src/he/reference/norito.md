# Norito {#norito}

Norito הוא Iroha זה שכבת סיריאליזציה קנוני.
כאשר עמיתים, SDKs, CLI כלים, Torii, Kura, והארטיפקטים שנוצרו צריכים להסכים.
בדיוק באותו מטען.

שימוש Norito כאשר הנתונים הם חלק מההסכמה, חתימה, חישוי, עמידה,
או צומת-SDK אינטרופערביות. JSON כאשר נקודת סוף מציעה במפורש
תצפית קריאה אנושית למפעילים, לוחי הנתונים או תיקון חירום מהיר.

## איפה? Norito מופיע {#where-norito-appears}

| פני השטח | איך? Norito משמש |
| --- | --- |
| עסקאות ושאלות | מטענים שימושיים של עסקאות ושישואיות חתומים שנשלחו באמצעות Torii הם מקודדים כ Norito. |
| בראשית | `kagami genesis sign` יוצר חותם `.nrt` לחסום את הדוגמאות המוטלות בהתחלה. |
| Torii תגובות מדבקות | נקודות קצה שתומכים בשימוש בתגובות בינאריות `Accept: application/x-norito`. |
| SDKs | Rust, Python, JavaScript, Kotlin ג'אווה, Swift, ו Android הלקוחות משתמשים Norito בונים או קשורים במקום בייטים שנאספו ידנית. |
| Kura אחסון | מטענים פועלים של כמות, מכוניות צדדית התאוששות, רוסטרים ומוצרי מחויבות מאוחסנים כ Norito-נתונים מעוצבים. |
| מוניפסטים | Nexus, זמינות הנתונים, SoraFS, זרימה, ו-מניפסטים פונה אפליקציה שימוש Norito כאשר המוניפסט חייב להיחתם או להש. |
| זרימה | Norito שימושי הזרם Norito מניפסטים, כותרות של קטעים, מסדרות בקרון ומגדלים תאימות. |

Norito זה לא שפה של חוזים חכמים.
קודק שמכניס עסקאות, שיחות חוזות, מוניפסטים ומטייפים API
מטענים.

## מודל המטען הפועל {#payload-model}

כל רשת או דיסק Norito המטען הפועל הוא מסגרת על ידי כותרת בעקבותיה
מטענים מועילים ללא כותרות או עירומים, מוקדשים עבור
חישוב, מדדלי דף, ועוזר APIs אשר מיידית מסובבת את התוצאה
כותרת לפני התחבורה.

| שדה כותרת | גודל | מטרה |
| --- | ---: | --- |
| קסם | 4 בייטים | ASCII `NRT0`, שימשו לדחות לא-Norito נתונים מוקדם. |
| מייג'ור. | 1 בייט | תבנית גרסה מרכזית. משמשת מטענים מועילים הנוכחיים `0`. |
| מינוור | 1 בייט | רמז פתיחה v1 קבוע. עומס נוח הנוכחי להשתמש `0x00`; אפשרויות תכנון חיים בדגלים. |
| הסכמה | 16 בייטים | זהות סוג משמשת על ידי דקודרים מדופסים כדי לדחות מטענים מועילים בלתי צפויים. |
| דחיפה | 1 בייט | `0 = None`, `1 = Zstd`. ערכים לא ידועים נדחו. |
| אורך המטען | 8 בייטים | אורך המטען הפועל ללא סיבוב כמיטב יכולתו `u64`. |
| CRC64 | 8 בייטים | CRC64-XZ סכום הבדיקה של המטען הפועל הלא מחומץ. |
| דגלים | 1 בייט | דגלי תארים עבור אורך קומפקטי, רצפים ארוזים וסטריקות ארוזות. |

הכותרת היא 40 בייטים. דקודרים מאשרים את הקסם, הגרסה, דגל תומך
מסכה, אורך המטען הפועל, סכום בדיקה, ושיש של הסקמה לפני
ערך טופס.

## דגלי תכנון {#layout-flags}

Norito מחזיק בחירות תכנון בביט כותרת הסופית.
שפיץ `COMPACT_LEN` (`0x02`) עבור מקדמות קצרות של אורך לפי ערך.
קישורים של אורך ברוח הקבועה נשארים קריאים כאשר מתקשרים מקודדים
`flags = 0x00`.

| דגל | ג'יקס | מצב | השפעה |
| --- | ---: | --- | --- |
| `PACKED_SEQ` | `0x01` | תמיכה | מקודד קבוצות בגודל משתנה עם טבלה של ההשוואה ועוד בלוק נתונים קבוע. |
| `COMPACT_LEN` | `0x02` | דפוס | משתמשת בערינטות קנוניקות לא חתומות עבור מקדימות אורך לפי ערך. |
| `PACKED_STRUCT` | `0x04` | תמיכה | קודים מנגנים-מובילים structs כמו חומרי נוח של שדה ארוזים. |
| `VARINT_OFFSETS` | `0x08` | מחוזים | דחוף ב v1; ההשלכות של רצף ארוזים הן ברוחב קבוע `u64`. |
| `COMPACT_SEQ_LEN` | `0x10` | מחוזים | דחוף ב v1; ראשי אורך רצף ברמה העליונה הם רוחב קבוע `u64`. |
| `FIELD_BITSET` | `0x20` | תמיכה בדרישות | מוסיף קבוצת ביטים לתרשמות ארוזות כך רק השדות שצריכים גדלים מפורשים יש מקבילים בגודל. `PACKED_STRUCT` ו `COMPACT_LEN`. |

הדגלים הם מפורשים.
גרסה מינית, או הורסטיקה. שילובים לא ידועים או לא חוקיים נדחו
שכל עמיתיכם מתארים מטען מועיל באותו אופן.

## חוקי קודינג {#encoding-rules}

Norito משתמשת בהצגות דטרמיסטיות לצורות הנתונים הנפוצות המופיעות ב
ה- Iroha מודל נתונים:

- חוטים הם `[len][utf8-bytes]`; `len` עונה: `COMPACT_LEN` כאשר זה אפשרי.
- אורך לפי הערך משתמש בווארינטים קומפקטיים כאשר `COMPACT_LEN` היא מוגדרת, אחרת
  קבוע 8 בייטים קטנטן-אנדיאן `u64`.
- כותרות אורך רצף קבועות 8 בייטים קטנטן-endian `u64` ב v1.
- `Vec<u8>` הוא מקודד כ `[len_u64][raw-bytes]` במקום אורך אחד באייט.
- השתמשת רצף ארוז `(len + 1)` מונוטוני `u64` ההשלכות, בעקבותיה:
  מטענים מועילים של אלמנטים מקושרים.
- המפות מקודדים את מספר הכניסה עם קבוע `u64` ושימש סדר מפתח דטרמיניסטי.
  `HashMap` רשומות מסורגות לפי מפתח לפני הקוד; `BTreeMap` משמש את
  סדר טבעי.
- `BigInt` משתמש באייטים משלים של 2 עם `u32` אורך בייטים
  ו512-ביט קופסה.
- `Numeric` הוא מקודד כ `(mantissa, scale)`, איפה המנטיסה מאחסן את
  הערך של מספרים מלאים וסולם מאחסנים את מספר המספרים החלקיקים.

החוקים האלה חשובים לחתימות והשיש. SDKs שקים את אותו
העסקה הגיונית חייבת לייצר את אותם בייטים קנוניים.

## סימנים של הסכמה {#schema-hashes}

דפוס Norito מטענים מועילים יש 16 בייט של שכימה האש בעמוד הראשים.
האש נגזר מהשם הטייפ המוגבל לחלוטין.
ההשינג של התוכנית המבנית מייצרת את ה-hash מהתכנית הקנוניקה במקום.

הדקודרים המוצגים דוחים חוסר התאמה של סקימה. זה מגן על הלקוחות
פתיחת קוד חובה Norito קישור כסוג לא נכון והוא מצב ההפלה הרגיל
כאשר SDK חבורת התקן מתעוררת ממודל הנתונים של הערך.

## דחיפה ומהירות {#compression-and-acceleration}

Norito תומך בהחץ מפורש ואדפטיבי מבלי לשנות את ההיגיון
מטען מועיל:

| תכונה | מטרה |
| --- | --- |
| `to_bytes` | קובץ מטען מועיל ללא כותרת. |
| `to_compressed_bytes` | קוד עם Zstd ולהקליט את תווית ההלחץ בעמוד הראשי. |
| `to_bytes_auto` | השתמשו בהאוריסטיקה דטרמיניסטית כדי להחליט אם לחץ שווה את זה. |
| CRC64 מאיץ | שימוש נייד CRC64-XZ בכל מקום, CLMUL על x86_64 או PMULL על aarch64 כאשר זמין. |
| GPU CRC64 וחיסום | מתכת או CUDA עוזרים עשויים להאיץ מטענים פועלים גדולים, ואז נופל בחזרה CPU דרכים. |

האימה של החומרה אף פעם לא משנה את התוכן המפורסם. CRC ו JSON
המאיצים חייבים להתאים את התוצאת הנחברת ביט-ל-ביט.
הבדלים בין CPU ו GPU קודרים, אבל המטען הפועל המפורסם Norito כותרת
מטא-מנתונים נשארים דטרמיסטיים עבור אישור.

## JSON תמיכה {#json-support}

Norito כולל ילידי JSON תוספת עבור נקודות קצה וכלים הנדרשים JSON
בלי לעזוב את Norito מערכת סוג.

| JSON תכונה | מקרה שימוש |
| --- | --- |
| `norito::json::{to_json, from_json}` | דטרמיניסטית JSON קוד/קוד. |
| עוזרים יפים וסופרים. | CLI תוצא, ציוד ושידור `std::io` אינטגרציה. |
| DOM הערכים | מניפולציה בתוכנה באמצעות Norito אני... JSON מודל ערך. |
| כתיבת מהירה JSON | קובץ/קוד על בסיס טייפ מבנה עבור חם DTO דרכים. |
| קורא עותק אפס | סריקת סימן שמשלמת חוטים מהכניסה ככל האפשר. |
| מאופצים שלב 1 | בחופשי AVX2, NEON, מתכת, או CUDA אינדקס סטרוקטורלי עם נסיגה סקאלית. |

Iroha הקוד צריך להעדיף `norito::json` עוזרים לטיפוס API מטענים מועילים.
פשוטה `serde_json` למסלול הייצור סיכונים שמתפרדים מהסכמה
התנהגות ניהול המגרש צפויה SDKs ו Torii מוצרים.

## תמיכה משוררת {#derive-support}

Rust סוגים של נתונים בדרך כלל משתמשים במקרו נגזרים במקום בקוד קודי ידני.
שכבת ההשוואה יכולה לייצר Norito קודקים בינריים, סכמים ו JSON עוזרים.

תכונות השדה הנפוצות הן:

| תכונה | השפעה |
| --- | --- |
| `#[norito(rename = "other")]` | משתמש שם סטבלטי סדרתי עבור סקימה ו JSON התאמה. |
| `#[norito(skip)]` | מחסיר את השדה וממלא אותו `Default` תוך כדי פתיחת קוד. |
| `#[norito(default)]` | השימוש `Default` כאשר מטען מועיל מפורסם לא נושא את השדה. |
| `#[norito(skip_serializing_if = "...")]` | מחסיר את השדות JSON כאשר הדרישה מתאימה, תוך שמירה על קובץ דטרמיניסטית מקובל. |

נגזרים גם חושפים סימנים של אורך מוצפן וחישובים של אורך מדויק כאשר
מקודרים משתמשים ברמזים האלה כדי לשמור על מאגר חסינות ולמנוע עותקים נוספים.

## משפחות בעלות תכונות ארון {#crate-feature-families}

בעת בנייה Iroha או SDK חיבורים ממקור, Norito תכונות בחרו
יש סיועות ומאיצים:

| משפחה תכונות | מה זה מאפשר |
| --- | --- |
| `derive` | מאקרו תהליכיים שנשלחו מחדש עבור שערות בינאריות, סכמות ו JSON תוצרת. |
| `compression` | תמיכת Zstd עבור מטענים מועילים עם קישור כותרת. |
| `packed-seq` | תארים של אוסף עם שולחנות מקצבות. |
| `packed-struct` | תכנון מבנה המוצא של מוצרים. |
| `compact-len` | תצוגת Varint לכל ערך של אורך. |
| `columnar` | Norito בלוקי עמוד, מתאימים AoS/NCB קודקים בשורה, ותצפיות משואות עבור מסלולים כבדים בסריקה; כוללים בדפוס הפתיחה `node-codec` מערכת תכונות. |
| `strict-safe` | מעבירים פאניקה של מסלולים שגויים לתשובות מבוססות. |
| `simd-accel` | CPU גיכוז, אם קיים, עם נסיגה דטרמינסטית. |
| `json` | ילידי JSON חוקר, סופר, DOM, תוצרת טופית, וסלולים מהירים. |
| `json-std-io` | עוזרים לקור ולכותב שכבות על JSON תריס. |
| `metal-stage1`, `cuda-stage1` | בחופשי GPU JSON תוצאות אחורה של מדד מבנה. |
| `metal-stage2` | תיאור מטאטאליות אופציונלי עבור JSON קלטת מבנה. |
| `metal-crc64`, `cuda-crc64` | בחופשי GPU CRC64 עוזרים לטענים גדולים. |
| `gpu-compression` | מתכת או CUDA זסטד מאיץ עבור מטענים גדולים. |
| `stage1-validate` | אישור תיקון שמשוות מהיר JSON אינדיקסים סטרקטורליים על פי יצירת סקאלה. |

זמינות התכונות עשויה להיות שונה בין SDKs והפרופילים לשחרר.
פורמט נשאר נשלט על ידי הכותרת והשקעה, לא על ידי דגלי הבנייה המקומיים.

## Torii ו Norito RPC {#torii-and-norito-rpc}

Torii חשיפה JSON עבור מסלולים רבים של המפעילים, אך מסלולים בינריים מקובלים משתמשים
Norito. סוג התקשורת עבור זרימת טופס Norito HTTP גופים הם
`application/x-norito`.

השתמשו בכותרות אלה כאשר נקודת סוף מקבלת או חוזרת בטייפ Norito:

```http
Content-Type: application/x-norito
Accept: application/x-norito
```

כאשר נקודת סוף תומכת בשני ההצגות, הלקוחות יכולים לשלוח
רשימת העדפות:

```http
Accept: application/x-norito, application/json
```

כשלונות פתיחה מופיעות כפי שנכתב. Torii טעויות ומספרות בטלמטריה.
סיבות נפוצות כוללות קסם לא חוקי, גרסה לא תומכת, תכונה לא תומכת
דגל, סכום הצ'ק לא מתאים, פגום UTF-8, טוג enum לא חוקי, ואי התאמה של תוכנית.

Norito RPC תחבורה נבחרת באמצעות תיקון התחבורה.
לוח המעקב צריך לעקוב אחר איחור בקשות, כשלונות, חיבורים פעילים,
בייטים תגובה, ו `torii_norito_decode_failures_total` בנפרד מ JSON
תנועה.

## Norito זרימה {#norito-streaming}

Norito סטרימינג מגדיר את אותה גישה דטרמיסטית לתקשורת ובזמן אמת
שטחי תחבורה. החלקים המרכזיים שלה הם:

| תכונה זרימה | מטרה |
| --- | --- |
| מוניפסטים | הצהירו על מחויבות של קטגוריות, דרכים פרטיות, יכולות, פרופיל קודק, קבוצת ההצפנה ונתונים מטא-מפתח לתוכן. |
| כותרות קטעים | קבל מספר שלקטן, משך זמן, ספירת חתיכות, זמנים, מצב אנטרופיה, סיכום אוודיו ושורשים מרקל. |
| התחייבויות קטנות | תנו לצופים ולתקשורת לבדוק חתיכות מטען מועיל מול המניפסט לפני שימשו או יפורקו. |
| מסדרות הבקרה | תישא הודעות מפורסמות, תגובות, עדכונים מרכזיים ומושא ומתן על יכולות. |
| HPKE עדכונים מרכזיים | תסתובבו בסודות התחבורה באמצעות הסוויטה המשא ומתן ומספרים גדלים באופן מונוטוני. |
| משא ומתן על היכולת | מחברים נתמכים ביטים של תכונות, גבולות דטאגראם, קדנציה תגובה ותחומי פרטיות. |
| FEC ותגובה | משתמשת באחזיות קבלן דטרמיסטיות ובתפקידי שוויון עבור נתיבי אובדן בזמן אמת. |
| וקטורים של תאימות | ציוד שפות שונות מוכיח SDKs לפענח את אותם מוניסטים, קטעים וזרמי אנטרופיה. |

קודקים ופרופילים של אנטרופיה ספציפיים לסטרימינג נפרדים מהבניין
Norito צורת העסקה/השאלה, אך המניפסטים והנתונים של הבקרה שלהם עדיין משתמשים
Norito כך שהראיות של מסלול, חשבונאות, שיחזור והמחקר יישארו ניתן לשכפל.

## הדרכה לפעילות {#operational-guidance}

- אני מעדיף. SDK בונים וביצועים של קישורים על ידי יד Norito בייטים.
- להתייחס לא התאמה של הסקמה כבעיה בגרסה או בתקן, ולא כבעיה עברה
  כשל רשת.
- שמרו `.nrt`, `.norito`, ומוצרים מופנים עם השחרור או התקרית
  חבילה שהייתה יוצרת אותם.
- שימוש JSON תחזיות עבור לוחי המקרה והבדיקת ידנית, אבל לשמור Norito כמו
  המקור של האמת עבור נתונים חתומים, הושים או נותרו.
- כאשר מוסיפים טופס חדש Torii נקודת סוף, מסמך אם היא מקבלת JSON,
  Norito, או שניהם, ולחשוף את סוגי התוכן המומלצים `/openapi`.
- בעת הפעלת האקסלרטורים, תפעילו בדיקות שוויון נגד יצירת סקלר לפני
  התכווצות. כישלונות האקסלרייטור צריכים להיפסק בחזרה בצורה נקייה במקום להשתנות
  סימנטיקה של עומס תועלת.
