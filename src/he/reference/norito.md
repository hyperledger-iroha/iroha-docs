# Norito {#norito}

Norito היא שכבת הסריאליזציה הקנונית של Iroha. זהו פורמט הבתים המשמש עמיתים, SDKs, כלי CLI, ‏Torii, ‏Kura וארטיפקטים שנוצרו כאשר כולם צריכים להסכים על מטען נתונים זהה בדיוק.

השתמשו ב־Norito כאשר הנתונים משתתפים בקונצנזוס, בחתימה, בגיבוב, באחסון מתמשך או בתאימות בין SDK. השתמשו ב־JSON כאשר נקודת קצה מציעה במפורש תצוגה קריאה לאדם עבור מפעילים, לוחות מחוונים או איתור תקלות מהיר.

## היכן Norito משמש {#where-norito-appears}

| משטח | אופן השימוש ב־Norito |
| --- | --- |
| עסקאות ושאילתות | מטעני נתונים חתומים של עסקאות ושאילתות הנשלחים דרך Torii מקודדים ב־Norito. |
| Genesis | הפקודה `kagami genesis sign` יוצרת בלוק `.nrt` חתום שהעמיתים טוענים בעת האתחול. |
| תגובות בעלות טיפוס של Torii | נקודות קצה התומכות בתגובות בינאריות בעלות טיפוס משתמשות ב־`Accept: application/x-norito`. |
| SDKs | לקוחות Rust, ‏Python, ‏JavaScript, ‏Kotlin/Java, ‏Swift ו־Android משתמשים בבונים או בכריכות של Norito במקום להרכיב בתים ידנית. |
| אחסון Kura | מטעני בלוקים, קובצי צד לשחזור, רשימות עמיתים וסמני commit נשמרים כנתונים הממוסגרים ב־Norito. |
| מניפסטים | מניפסטים של Nexus, זמינות נתונים, SoraFS, הזרמה וממשקי אפליקציה משתמשים ב־Norito כאשר יש לחתום על המניפסט או לגבב אותו. |
| הזרמה | Norito Streaming משתמש במניפסטים של Norito, בכותרות מקטעים, במסגרות בקרה ובנתוני בדיקה לתאימות. |

Norito אינה שפה לחוזים חכמים. זוהי המעטפת הדטרמיניסטית וה־codec הנושאים עסקאות, קריאות לחוזים, מניפסטים ומטעני API בעלי טיפוס.

## מודל מטען הנתונים {#payload-model}

כל מטען Norito המועבר ברשת או נשמר בדיסק ממוסגר בכותרת שאחריה בתי המטען המקודד. מטענים ללא כותרת, או מטענים גולמיים, שמורים לגיבוב פנימי, למדדי ביצועים ול־APIs מסייעים שעוטפים מיד את התוצאה בכותרת לפני העברתה.

| שדה בכותרת | גודל | מטרה |
| --- | ---: | --- |
| Magic | 4 בתים | ASCII `NRT0`, המשמש לדחייה מוקדמת של נתונים שאינם Norito. |
| Major | בית אחד | הגרסה הראשית של הפורמט. המטענים הנוכחיים משתמשים ב־`0`. |
| Minor | בית אחד | רמז פענוח עבור v1. הערך הנוכחי הוא `0x00`. הדגלים מתארים את הפריסה. |
| גיבוב סכמה | 16 בתים | זהות הטיפוס, שבעזרתה מפענחים בעלי טיפוס דוחים מטענים בלתי צפויים. |
| דחיסה | בית אחד | `0 = None`, ‏`1 = Zstd`. ערכים לא מוכרים נדחים. |
| אורך המטען | 8 בתים | אורך המטען הלא־דחוס כ־`u64` בסדר בתים little-endian. |
| CRC64 | 8 בתים | סכום הביקורת CRC64-XZ של המטען הלא־דחוס. |
| דגלים | בית אחד | דגלי פריסה עבור אורכים קומפקטיים, רצפים ארוזים ומבנים ארוזים. |

אורך הכותרת הוא 40 בתים. לפני שחזור הערך בעל הטיפוס, המפענחים מאמתים את ערך ה־magic, הגרסה, מסכת הדגלים הנתמכת, אורך המטען, סכום הביקורת וגיבוב הסכמה.

## דגלי פריסה {#layout-flags}

Norito שומר את בחירות הפריסה בבית האחרון של הכותרת. מסייעי ברירת המחדל של v1 מפיקים `COMPACT_LEN` (`0x02`) עבור קידומות אורך קומפקטיות לכל ערך. קידומות אורך מפורשות ברוחב קבוע נשארות קריאות כאשר הקוראים מקודדים באמצעות `flags = 0x00`.

| דגל | הקסדצימלי | מצב | השפעה |
| --- | ---: | --- | --- |
| `PACKED_SEQ` | `0x01` | נתמך | מקודד אוספים בגודל משתנה באמצעות טבלת היסטים ובלוק נתונים רציף. |
| `COMPACT_LEN` | `0x02` | ברירת מחדל | משתמש ב־varint קנוני ללא סימן עבור קידומת האורך של כל ערך. |
| `PACKED_STRUCT` | `0x04` | נתמך | מקודד מבנים שנוצרו באמצעות derive כמטעני שדות ארוזים. |
| `VARINT_OFFSETS` | `0x08` | שמור | נדחה ב־v1; ההיסטים של רצפים ארוזים הם `u64` ברוחב קבוע. |
| `COMPACT_SEQ_LEN` | `0x10` | שמור | נדחה ב־v1; כותרות האורך של רצפים ברמה העליונה הן `u64` ברוחב קבוע. |
| `FIELD_BITSET` | `0x20` | נתמך בכפוף לדרישות | מוסיף מפת סיביות למבנים ארוזים, כך שרק שדות הזקוקים לגדלים מפורשים נושאים קידומות גודל. דורש `PACKED_STRUCT` ו־`COMPACT_LEN`. |

הדגלים מפורשים. מפענחים אינם מסיקים את הפריסה מצורת המטען, מגרסת ה־minor או מהיוריסטיקות. שילובים לא מוכרים או לא חוקיים נדחים, כדי שכל העמיתים יפרשו את המטען באותו אופן.

## כללי קידוד {#encoding-rules}

Norito משתמש בפריסות דטרמיניסטיות עבור צורות הנתונים הנפוצות במודל הנתונים של Iroha:

- מחרוזות מקודדות כ־`[len][utf8-bytes]`; כאשר `COMPACT_LEN` מופעל, `len` פועל לפיו.
- כאשר `COMPACT_LEN` מוגדר, האורך של כל ערך משתמש ב־varint קומפקטי.
- כאשר `COMPACT_LEN` אינו קיים, האורך של כל ערך הוא `u64` בן 8 בתים בסדר little-endian.
- כותרות האורך של רצפים הן `u64` קבוע בן 8 בתים בסדר little-endian ב־v1.
- `Vec<u8>` מקודד כ־`[len_u64][raw-bytes]`, ולא עם אורך נפרד לכל בית.
- רצפים ארוזים משתמשים ב־`(len + 1)` היסטי `u64` מונוטוניים, שאחריהם מטעני האיברים המשורשרים.
- מפות מקודדות את מספר הרשומות באמצעות `u64` קבוע ומשתמשות בסדר מפתחות דטרמיניסטי. רשומות `HashMap` ממוינות לפי מפתח לפני הקידוד; `BTreeMap` משתמש בסדר הטבעי שלו.
- `BigInt` משתמש בבתי משלים ל־2 בסדר little-endian, עם אורך בתים מסוג `u32` ומגבלה של 512 סיביות.
- `Numeric` מקודד כ־`(mantissa, scale)`: ה־mantissa שומר את הערך השלם, וה־scale שומר את מספר הספרות אחרי הנקודה.

כללים אלה חשובים לחתימות ולגיבובים. שני SDKs הבונים אותה עסקה לוגית חייבים להפיק את אותם בתים קנוניים.

## גיבובי סכמה {#schema-hashes}

מטעני Norito בעלי טיפוס נושאים בכותרת גיבוב סכמה בן 16 בתים. גיבוב ברירת המחדל נגזר מהשם המלא של הטיפוס. גרסאות build המפעילות גיבוב סכמה מבני גוזרות במקום זאת את הגיבוב מהסכמה הקנונית.

מפענחים בעלי טיפוס דוחים אי־התאמה בסכמה. כך נמנע מלקוחות לפענח בטעות מסגרת Norito תקפה כטיפוס שגוי; זהו מצב הכשל הרגיל כאשר חבילת נתוני הבדיקה של SDK סוטה ממודל הנתונים של הצומת.

## דחיסה והאצה {#compression-and-acceleration}

Norito תומך בדחיסה מפורשת ומסתגלת בלי לשנות את המטען הלוגי:

| תכונה | מטרה |
| --- | --- |
| `to_bytes` | מקודד כותרת שאחריה מטען לא־דחוס. |
| `to_compressed_bytes` | מקודד באמצעות Zstd ורושם בכותרת את תג הדחיסה. |
| `to_bytes_auto` | מפעיל היוריסטיקות דטרמיניסטיות כדי להחליט אם הדחיסה משתלמת. |
| האצת CRC64 | משתמש ב־CRC64-XZ נייד בכל מקום, וב־CLMUL ב־x86_64 או ב־PMULL ב־aarch64 כאשר הם זמינים. |
| CRC64 ודחיסה ב־GPU | מסייעי Metal או CUDA אופציונליים יכולים להאיץ מטענים גדולים, ולחזור למסלולי CPU בעת הצורך. |

האצת חומרה לעולם אינה משנה את התוכן המפוענח. מאיצי CRC ו־JSON חייבים להתאים לפלט הנייד סיבית אחר סיבית. בתי מסגרת Zstd עשויים להיות שונים בין מקודדי CPU ו־GPU, אך המטען המפוענח ומטא־הנתונים בכותרת Norito נשארים דטרמיניסטיים לצורכי אימות.

## תמיכה ב־JSON {#json-support}

Norito כולל מחסנית JSON מובנית עבור נקודות קצה וכלים הזקוקים ל־JSON בלי לצאת ממערכת הטיפוסים של Norito.

| תכונת JSON | שימוש |
| --- | --- |
| `norito::json::{to_json, from_json}` | קידוד ופענוח דטרמיניסטיים של JSON בעל טיפוס. |
| מסייעי pretty ו־writer | פלט CLI, נתוני בדיקה ושילוב הזרמה עם `std::io`. |
| ערכי DOM | עיבוד תכנותי באמצעות מודל ערכי ה־JSON של Norito. |
| JSON מהיר בעל טיפוס | פענוח וקידוד המבוססים על structural tape עבור מסלולי DTO עמוסים. |
| קורא ללא העתקה | סריקת אסימונים השואלת מחרוזות מהקלט במידת האפשר. |
| מאיצי שלב 1 | אינדוקס מבני אופציונלי באמצעות AVX2, ‏NEON, ‏Metal או CUDA, עם נסיגה ליישום scalar. |

קוד Iroha צריך להעדיף את המסייעים `norito::json` עבור מטעני API בעלי טיפוס. הוספת `serde_json` רגיל למסלולי ייצור עלולה לסטות מהסכמה ומהטיפול בשדות המצופים על ידי SDKs והמחלצים של Torii.

## תמיכה ב־derive {#derive-support}

טיפוסי נתונים ב־Rust משתמשים בדרך כלל במאקרו derive במקום בקוד codec ידני. שכבת ה־derive יכולה ליצור codec בינארי של Norito, סכמות ומסייעי JSON.

מאפייני השדות הנפוצים הם:

| מאפיין | השפעה |
| --- | --- |
| `#[norito(rename = "other")]` | משתמש בשם סריאלי יציב לצורך תאימות סכמה ו־JSON. |
| `#[norito(skip)]` | המקודד משמיט את השדה. המפענח מספק את ערך ה־`Default` שלו. |
| `#[norito(default)]` | משתמש ב־`Default` כאשר המטען המפוענח אינו מכיל את השדה. |
| `#[norito(skip_serializing_if = "...")]` | משמיט שדות מ־JSON כאשר התנאי מתקיים, תוך שמירה על ערכי ברירת מחדל דטרמיניסטיים בפענוח. |

נגזרות derive חושפות גם רמזים לאורך המקודד וחישובי אורך מדויקים כאשר הדבר אפשרי. מקודדים משתמשים ברמזים אלה כדי להקצות מראש מאגרים ולהימנע מהעתקות נוספות.

## משפחות תכונות של crate {#crate-feature-families}

בעת בניית Iroha או כריכות SDK מקוד המקור, תכונות Norito קובעות אילו מסייעים ומאיצים יהיו זמינים:

| משפחת תכונות | מה היא מאפשרת |
| --- | --- |
| `derive` | מאקרו פרוצדורלי שמיוצא מחדש עבור נגזרות בינאריות, סכמה ו־JSON. |
| `compression` | תמיכת Zstd במטענים הממוסגרים בכותרת. |
| `packed-seq` | פריסות אוספים ארוזות באמצעות טבלאות היסטים. |
| `packed-struct` | פריסות ארוזות של מבנים שנוצרו באמצעות derive. |
| `compact-len` | קידומות אורך varint לכל ערך. |
| `columnar` | בלוקים עמודתיים של Norito, רכיבי codec מסתגלים לשורות AoS/NCB ותצוגות שואלות עבור מסלולים עתירי סריקה; כלול בקבוצת תכונות ברירת המחדל `node-codec`. |
| `strict-safe` | ממיר panic בפענוח במסלולים העשויים להיכשל לשגיאות מובנות. |
| `simd-accel` | האצת CPU כאשר היא זמינה, עם נסיגה דטרמיניסטית. |
| `json` | מנתח JSON מובנה, writer, ‏DOM, נגזרות בעלות טיפוס ומסלולים מהירים. |
| `json-std-io` | מסייעי reader ו־writer הבנויים מעל מחסנית JSON. |
| `metal-stage1`, `cuda-stage1` | מנועי GPU אופציונליים לאינדקס המבני של JSON. |
| `metal-stage2` | סיווג מטא־נתונים אופציונלי באמצעות Metal עבור ה־structural tape של JSON. |
| `metal-crc64`, `cuda-crc64` | מסייעי GPU אופציונליים ל־CRC64 עבור מטענים גדולים. |
| `gpu-compression` | האצת Zstd אופציונלית באמצעות Metal או CUDA עבור מטענים גדולים. |
| `stage1-validate` | אימות debug המשווה אינדקסים מבניים מואצים של JSON לפלט scalar. |

זמינות התכונות עשויה להשתנות בין SDKs ובין פרופילי הפצה. פורמט התעבורה נשלט בידי הכותרת והסכמה, ולא בידי דגלי בנייה מקומיים.

## Torii ו־Norito RPC {#torii-and-norito-rpc}

Torii חושף JSON עבור נתיבי מפעיל רבים, אך נתיבים בינאריים בעלי טיפוס משתמשים ב־Norito. סוג המדיה עבור גופי HTTP נוכחיים בעלי טיפוס Norito הוא `application/x-norito`.

השתמשו בכותרות הבאות כאשר נקודת קצה מקבלת או מחזירה Norito בעל טיפוס:

```http
Content-Type: application/x-norito
Accept: application/x-norito
```

כאשר נקודת קצה תומכת בשני הייצוגים, לקוחות יכולים לשלוח רשימת העדפות מפורשת:

```http
Accept: application/x-norito, application/json
```

כשלי פענוח מוחזרים כשגיאות Torii בעלות טיפוס ונספרים בטלמטריה. סיבות נפוצות כוללות ערך magic לא חוקי, גרסה לא נתמכת, דגל תכונה לא נתמך, אי־התאמה בסכום הביקורת, UTF-8 פגום, תג enum לא חוקי ואי־התאמה בסכמה.

תעבורת Norito RPC נבחרת באמצעות הגדרת התעבורה. לוחות מחוונים למפעילים צריכים לעקוב אחר השהיית בקשות, כשלים, חיבורים פעילים, בתי תגובה ו־`torii_norito_decode_failures_total` בנפרד מתעבורת JSON.

## הזרמת Norito {#norito-streaming}

Norito Streaming מרחיב את אותה גישה דטרמיניסטית למדיה ולמשטחי תעבורה בזמן אמת. רכיביו העיקריים הם:

| תכונת הזרמה | מטרה |
| --- | --- |
| מניפסטים | מצהירים על התחייבויות מקטעים, נתיבי פרטיות, יכולות, פרופיל codec, חבילת הצפנה ומטא־נתונים של מפתח התוכן. |
| כותרות מקטעים | קושרות את מספר המקטע, המשך, מספר הנתחים, התזמון, מצב האנטרופיה, תקציר השמע ושורשי Merkle. |
| התחייבויות נתחים | מאפשרות לצופים ולממסרים לאמת נתחים של המטען מול המניפסט לפני הגשה או פענוח. |
| מסגרות בקרה | נושאות הכרזות מניפסט, משוב, עדכוני מפתחות ומשא ומתן על יכולות. |
| עדכוני מפתח HPKE | מסובבים סודות תעבורה באמצעות החבילה שסוכמה ומונים הגדלים באופן מונוטוני. |
| משא ומתן על יכולות | מבצע חיתוך של סיביות תכונה נתמכות, מגבלות datagram, תדירות משוב ודרישות פרטיות. |
| FEC ומשוב | משתמש בדוחות מקלט דטרמיניסטיים ובהחלטות parity עבור נתיבי זמן אמת עם אובדן. |
| וקטורי תאימות | נתוני בדיקה חוצי־שפות מוכיחים ש־SDKs מפענחים את אותם מניפסטים, מקטעים וזרמי אנטרופיה. |

רכיבי codec ופרופילי אנטרופיה הייחודיים להזרמה נפרדים מפורמט הליבה של עסקאות ושאילתות ב־Norito, אך המניפסטים ונתוני הבקרה שלהם עדיין משתמשים ב־Norito, כדי שניתוב, חיוב, שידור חוזר וראיות ביקורת יישארו ניתנים לשחזור.

## הנחיות תפעוליות {#operational-guidance}

- העדיפו בוני SDK וכריכות שנוצרו אוטומטית על פני בתי Norito שנבנו ידנית.
- התייחסו לאי־התאמה בסכמה כאל בעיית גרסה או נתוני בדיקה, ולא כאל כשל רשת זמני.
- שמרו בארכיון את הארטיפקטים `.nrt`, ‏`.norito` והמניפסטים יחד עם חבילת ההפצה או האירוע שיצרה אותם.
- השתמשו ב־Norito כמקור האמת לנתונים חתומים, מגובבים או שמורים. השתמשו בתצוגות JSON ללוחות מחוונים ולבדיקה ידנית.
- בעת הוספת נקודת קצה חדשה בעלת טיפוס ל־Torii, תעדו אם היא מקבלת JSON, ‏Norito או את שניהם, וחשפו את סוגי התוכן הנתמכים ב־`/openapi.json`.
- לפני הפעלת מאיץ, הריצו בדיקות שוויון מול הפלט ה־scalar. אם המאיץ נכשל, השתמשו בנסיגה ה־scalar הדטרמיניסטית. משמעות המטען חייבת להישאר ללא שינוי.
