# الشبكات الخاصة الافتراضية {#virtual-private-networks}

الـ <abbr title="Virtual Private Network">VPN</abbr> هو تحكم في الشبكة يحد من يمكنه الوصول إلى خدمات Iroha. إنه أكثر فائدة للعمليات الخاصة والتعاونيات حيث يجب أن يتواصل المُصَدِّقون ونُظم خلفية التطبيقات والمشغلون عبر عناوين خاصة بدلاً من طرق الإنترنت المفتوحة.

لا يستبدل VPN مفاتيح نظير الشبكة Iroha أو مفاتيح الحساب أو الأذونات أو قواعد الجدار الناري أو المراقبة أو تخزين المفاتيح الآمن. اعتبره كطبقة واحدة في حدود النشر: يقيد VPN نطاق الوصول إلى الشبكة، بينما تحدد تكوين Iroha والحوكمة الأقران والحسابات الشبكية الموثوق بها.

## متى تستخدم VPN {#when-to-use-a-vpn}

استخدم VPN عندما:

- يتم تشغيل المدققين بواسطة منظمات مختلفة أو في بيئات استضافة مختلفة
- Torii يجب أن يكون قابلاً للوصول فقط بواسطة خلفيات التطبيقات أو المشغلين أو العملاء الموثوق بهم
- يجب أن تبقى المقاييس والسجلات و SSH أو نقاط النهاية الإدارية الأخرى API على شبكة مشغل خاصة
- يجب أن تشبه شبكة الاختبار أو المرحلة ضوابط الوصول للإنتاج دون كشف نقاط النهاية العامة API

لا يُطلب VPN لكل نشر. قد تقوم الشبكات العامة بقصد تعريض Torii من خلال بوابة عامة أو موازن تحميل أو وكيل عكسي. حتى في هذه الحالة، احتفظ بحركة مرور النظراء للمصادِق ونقاط نهاية إدارة API على شبكة مقيدة كلما أمكن ذلك.

::: tip

متصفح VPN يحمي حركة المرور من ذلك المتصفح فقط. لا يحمي `iroha3d`، CLI، SDK، SSH، المقاييس، أو حركة النسخ الاحتياطي ما لم يتم توجيه تلك العمليات عبر نفس الشبكة الخاصة.

:::

## نمط النشر {#deployment-pattern}

لشبكة التحقق الخاصة، امنح كل مدقق عنوان VPN ثابت أو اسم خاص DNS. قم بتكوين نظراء الشبكة بحيث تكون عناوينهم المعلنة لنظام الند للند قابلة للوصول من المدققين الآخرين عبر تلك الشبكة:

```toml
trusted_peers = [
  "PUBLIC_KEY_1@10.20.0.11:1337",
  "PUBLIC_KEY_2@10.20.0.12:1337",
  "PUBLIC_KEY_3@10.20.0.13:1337",
  "PUBLIC_KEY_4@10.20.0.14:1337",
]

[network]
address = "10.20.0.11:1337"
public_address = "10.20.0.11:1337"

[torii]
address = "10.20.0.11:8080"
```

استخدم العنوان المخصص لنظير الشبكة الحالي في `network.address` و `network.public_address`. يجب أن يسرد كل نظير شبكة نفس هويات نظراء الشبكة الموثوقين، ولكن بالعناوين التي يمكن الوصول إليها من جدول مسارات VPN الخاص به.

ينبغي أن تشير إعدادات العميل و CLI إلى نقطة نهاية Torii API يمكن الوصول إليها من خلال VPN أو من خلال بوابة داخلية محكمة التحكم:

```toml
torii_url = "http://10.20.0.11:8080"
```

إذا كان يجب أن يكون Torii متاحًا خارج VPN، فضعه خلف وكيل عكسي أو موازن تحميل يوفر TLS، المصادقة، تحديد المعدل، وتسجيل الدخول. تجنب كشف منافذ نظير إلى نظير خام أو نقاط نهاية API الإدارية مباشرة للإنترنت العام.

## قواعد الجدار الناري {#firewall-rules}

استخدم قواعد جدار الحماية على المضيف والسحابة حتى عند وجود VPN:

|خدمة|الوصول الموصى به|
| --- | --- |
|منفذ من نظير إلى نظير|عنوان مصدق آخر VPN فقط|
| Torii |واجهات خلفية للتطبيقات، أو المشغلون، أو النطاقات الموثوقة للعميل VPN|
|المقاييس وفحوصات الصحة|أنظمة المراقبة على شبكة المشغل|
| SSH والإدارة |مضيف الحصن، المشغل المميز VPN النطاق، أو عملية كسر الزجاج|
|النسخ الاحتياطية وتكرار التخزين|أنظمة النسخ الاحتياطي على شبكة خاصة|

قواعد الرفض الافتراضية أسهل في التدقيق من قواعد السماح الواسعة. عندما ينضم نظير شبكة جديد إلى الشبكة، قم بتحديث عضوية VPN، وقائمة السماح لجدار الحماية، وتكوين نظير الشبكة الموثوق Iroha كتغيير منسق واحد.

## قائمة التحقق التشغيلية {#operational-checklist}

- اختر تنفيذ VPN الذي تم تدقيقه ويخضع للصيانة النشطة، مثل WireGuard، IPsec، أو شبكة خاصة مُدارة معتمدة من المنظمة.
- استخدم بيانات اعتماد فريدة VPN لكل مضيف ومشغل. لا تشارك مفاتيح VPN بين المدققين.
- احتفظ بأوراق اعتماد VPN منفصلة عن مفاتيح Iroha الخاصة ومواد توقيع التأسيس للبلوكشين.
- راقب تأخر VPN وفقدان الحزم وإعادة الاتصال وتغيرات المسار. الإجماع حساس لعدم استقرار الشبكة المستمر.
- اختبر MTU الفعال. يمكن أن تظهر تجزئة الحزمة مثل انقطاع الشبكة المتقطع للأقران أو فشل Torii.
- المستند الذي تُسمح فيه نطاقات VPN بالوصول إلى نقاط النظراء، Torii، المقاييس، SSH، ونقاط النسخ الاحتياطي API.
- قم بتدوير بيانات اعتماد VPN عندما يغادر مضيف أو حساب مشغّل أو منظمة الشبكة.
- تجنب استخدام بوابة VPN واحدة كالمسار الوحيد بين المحققين. خطط لبوابات احتياطية أو مسارات من موقع إلى موقع لشبكات الإنتاج.
- قم بتضمين فشل VPN في تدريبات الاستجابة للحوادث حتى يعرف المشغلون متى يميزون بين تقسيم الشبكة وفشل عملية Iroha.
