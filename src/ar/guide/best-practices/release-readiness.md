# جاهزية الإصدار {#release-readiness}

قبل الترويج لتطبيق Iroha أو تغيير الشبكة، يجب إثبات السلوك في أصغر بيئة يمكن أن تكشف عن المخاطر ذات الصلة، ثم الانتقال من خلال شبكة الاختبار المشتركة وبوابات الإنتاج بشكل متعمد.

## بوابة الشبكة المحلية {#localnet-gate}

- إطلاق شبكة محلية قابلة للتخلص منها بنفس مسار Iroha وأقرب عدد عملي من المحققين.
- تشغيل اختبارات الوحدة لبناة المعاملات، تحليل الاستعلامات، معالجة الرفض، وتحميل الإعدادات.
- مرن أصغر مسارات قراءة وكتابة ناجحة من خلال نفس الشكل SDK أو CLI الذي سيستخدمه التطبيق لاحقًا.
- التقاط تجزئات التشفير المتوقعة للمعاملات، والحالات، والأحداث، وقراءات الحالة في عناصر اختبار.

انظر [إطلاق Iroha 3](/ar/get-started/launch-iroha.md) و [SDK دروس](/ar/guide/tutorials/).

## بوابة الشبكة الاختبارية المشتركة {#shared-testnet-gate}

- استخدم Taira أو شبكة اختبار مشتركة أخرى لسلوك نقطة النهاية API والرسوم وتمويل الحسابات والكمون والبروفات التشغيلية.
- اجعل كتابة شبكة الاختبار الحية اختيارية حتى لا تعتمد الاختبارات العادية على توفر الشبكة أو تنفق أموال شبكة الاختبار.
- تحقق من تمويل الموقّع التشفيري وبيانات أصول الرسوم وأذونات الكيان المخوّل والحالة المتوقعة قبل تقديم كل معاملة اختبار مباشرة.
- انتظر حتى تصل الحالة إلى حالة نهائية، ثم تحقق من الحالة الناتجة باستخدام استعلام للقراءة فقط.

انظر [البناء على SORA 3: Taira و Minamoto](/ar/get-started/sora-nexus-dataspaces.md).

## الشبكة الرئيسية أو بوابة الإنتاج {#mainnet-or-production-gate}

- استخدم مواقع توقيع تشفير إنتاجية منفصلة، وتمويلًا، ونطاقات، ومسارات تكوين. لا تروّج لمفاتيح الشبكة التجريبية أو افتراضات خدمة تمويل الشبكة التجريبية.
- تأكيد السيناريوهات العابرة المطلوبة SDK مع [مصفوفة التوافق](/ar/reference/compatibility-matrix.md). قم بشكل منفصل بتثبيت واختبار CLI الدقيق، والنسخة الثنائية لنظير الشبكة، والتكوين، وإصدار الشبكة المستخدم في النشر.
- راجع الأذونات، رعاية الرسوم، حدود المعدل، المراقبة، حالة النسخ الاحتياطي، ومعايير التراجع قبل نافذة الإصدار.
- يتطلب خطة مكتوبة للمعاملات أو الهجرة للكتابات عالية التأثير.

## التراجع والاسترداد {#rollback-and-recovery}

- حدد أي التغييرات يمكن التراجع عنها بواسطة نشر الشيفرة، وأيها يتطلب معاملة على السلسلة، وأيها لا يمكن التراجع عنه مباشرة.
- بالنسبة لتغييرات البيانات على السلسلة، حضّر معاملات تعويضية أو نصوص ترحيل قبل أول كتابة للإنتاج.
- بالنسبة لتغييرات الشبكة، احتفظ بالنسخة الثنائية السابقة وحزمة الإعدادات وبلوكشين التأسيس الموقعة ودليل التشغيل متاحة خلال الإصدار.
- حدد نقطة قرار لإيقاف النشر بناءً على مؤشرات موضوعية مثل معدل الرفض، نمو الطابور، التأخر، أو صحة نظراء الشبكة.

## قائمة التحقق النهائية {#final-checklist}

- التكوين محدد بالبيئة ولا يحتوي على أسرار خاصة بالاختبار فقط.
- سلوك إعادة محاولة المعاملة متسق أو محدود بشكل صريح.
- يمكن للتطبيق التمييز بين الرفض، وانتهاء الصلاحية، وانقضاء المهلة، وفشل توفر نقطة النهاية API.
- يشمل المراقبة معدل النقل، الكمون، عمق الطابور، الرفض، تغييرات العرض، والأحداث التجارية ذات الصلة.
- للمشغلين كتب تشغيل للأنماط المتوقعة للفشل.
- غطي المراجعة الأمنية الاحتجاز الأساسي والصلاحيات، والتعرض للشبكة، والمبادئ المصرح بها للأتمتة.
