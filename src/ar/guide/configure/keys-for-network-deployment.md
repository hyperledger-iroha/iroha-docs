# مفاتيح نشر الشبكة {#keys-for-network-deployment}

كل شبكة تحتاج إلى مواد مفتاح مميزة للعملاء، نظراء الشبكة، توقيع التأسيس للبلوكتشين، ولكل من ملفات تعريف NPoS أو Nexus، هويات المدققين BLS.

## أين تُستخدم المفاتيح {#where-keys-are-used}

- تُخزن مفاتيح توقيع العميل في `client.toml` تحت `[account]`.
- يتم تخزين مفاتيح هوية نظير الشبكة في كل نظير شبكة `config.toml` كـ `public_key` و `private_key`.
- يستخدم اكتشاف نظراء الشبكة المفتاح العام لكل نظير في الشبكة في `trusted_peers`.
- BLS تُخزَّن إثباتات الحيازة الخاصة بالمدقق في `trusted_peers_pop` لملفات NPoS.
- تستخدم توقيع بداية البلوكتشين `[genesis].public_key` في تكوين نظير الشبكة والمفتاح الخاص المطابق عند توقيع البيان الفني.

للنشر المحلي أو التجريبي، دع Kagami يولد كل هذه الملفات معًا:

```bash
cargo run --bin kagami -- localnet --peers 4 --out-dir ./localnet
```

بالنسبة لشبكة أو ملف شخصي موجود، استخدم التدفق الإرشادي:

```bash
cargo run --bin kagami -- wizard
```

## إنشاء أزواج مفاتيح فردية {#generate-individual-key-pairs}

استخدم `kagami keys` لمواد المفتاح المستقلة:

```bash
cargo run --bin kagami -- keys --algorithm ed25519 \
  --out-dir ./client-key
```

لمواد المُصدّق BLS، قم بتضمين إثبات الملكية:

```bash
cargo run --bin kagami -- keys --algorithm bls_normal --pop \
  --out-dir ./validator-key
```

استخدم `--seed-hex` فقط مع قيمة سرية سداسية عشرية بطول 32 بايت بالضبط لإنشاء بيانات اختبار تطويرية قابلة لإعادة الإنتاج. عند النشر في الإنتاج، احذف هذا الخيار كي يستخدم Kagami عشوائية نظام التشغيل، ثم انقل تصدير المفتاح الخاص غير المشفّر إلى نطاق الحفظ المعتمد. لا يطبع الأمر المفاتيح الخاصة مطلقًا.

## اتساق النظراء في الشبكة {#peer-consistency}

يجب أن يوافق جميع المدققين على نفس معاملة البداية للبلوكتشين، والطوبولوجيا، ومفاتيح الشبكة العامة للأقران الموثوقين، و PoPs الخاص بالمدقق. يمكن لمفتاح قرين واحد مفقود أو غير متطابق أن يمنع الشبكة من البدء أو الوصول إلى الإجماع.

لنشر يتحمل الأعطال البيزنطية على الأقل، استخدم أربعة نظراء شبكة على الأقل. يجب أن يكون لكل نظير شبكة مفتاحه الخاص، ولكن كل تكوين نظير شبكة يحتاج إلى نفس مجموعة النظراء الموثوقين.

## حسابات العملاء {#client-accounts}

يجب أن يكون حساب العميل في `client.toml` موجودًا بالفعل على السلسلة. يمكن تسجيله بواسطة بيان التقنية التأسيسي للبلوكتشين أو بواسطة معاملة لاحقة. تجنب استخدام هوية توقيع التكوين الأصلي للبلوكتشين كحساب تطبيق طويل الأمد؛ صلاحيات التكوين الأصلي للبلوكتشين تنطبق فقط خلال جولة التكوين الأصلي، ويجب على عملاء الإنتاج استخدام حساباتهم وأدوارهم الخاصة.
