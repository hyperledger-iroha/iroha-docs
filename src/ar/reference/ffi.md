# واجهات الوظائف الأجنبية (FFI) {#foreign-function-interfaces-ffi}

يوفر حزمة البرمجيات `iroha_ffi` وحدات ماكرو وسمات لإنشاء روابط C ABI من Rust APIs. يتم استخدامها عندما تحتاج أنواع Iroha إلى عبور حدود FFI، على سبيل المثال بواسطة روابط SDK أو تكاملات المضيف.

## لماذا FFI {#why-ffi}

الدالة هي كيان مجرد إلى حد ما، وبينما تتفق معظم اللغات على ما يجب أن تفعله الدالة، فإن الطريقة التي يتم بها تمثيل الدوال تختلف كثيراً. علاوة على ذلك، في بعض اللغات، مثل Rust، تكون عواقب استدعاء دالة وما يُسمح لها فعله مختلفة أيضًا. عندما Rust APIs يحتاج إلى أن يُستدعى من لغة أخرى أو بيئة مضيف مختلفة، Iroha يستخدم واجهة دوال أجنبية (FFI) لتسوية المسرح.

المعيار الرئيسي المستخدم اليوم هو واجهة ثنائية لتطبيقات C. إنه بسيط، متوفر على نطاق واسع، ومستقر. من الناحية النظرية، يمكنك القيام بكل شيء يدويًا، لكن Iroha يوفر حزمة البرامج `iroha_ffi` لإنشاء دوال متوافقة مع FFI من API Rust الموجودة.

بالطبع، يمكنك القيام بذلك بطريقتك. حزمة البرمجيات `iroha_ffi` ببساطة تولد الكود الذي ستحتاج إلى توليده على أي حال. كتابة الكود القوالبي المتكرر اللازم يتطلب قدراً كبيراً من الاجتهاد والانضباط. كل استدعاء دالة عبر حدود FFI يكون `unsafe` مع احتمال التسبب بسلوك غير معرف. الطريقة التي تمكنّا بها من حلها تدور حول استخدام أنواع `repr(C)` قوية.

::: info

الاستثناء الوحيد هو المؤشرات. لا يمكن فرض التحقق من القيمة الخالية وصلاحية المؤشر بشكل عام، لذلك تُستخدم المؤشرات الخام (كما هو الحال دائمًا) فقط في الحالات الاستثنائية. نظرًا لأننا نوفر واجهات برمجية تقريبية حول كل مثيل تقريبًا لكائن في نموذج البيانات Iroha، فلا ينبغي أن تحتاج إلى استخدام المؤشرات الأولية على الإطلاق.

:::

## مثال {#example}

إليك مثال على إنشاء ربط:

```rust
#[derive(FfiType)]
struct DaysSinceEquinox(u32);

#[ffi_export]
impl DaysSinceEquinox {
    pub fn update_value(&mut self, a: &u8) {
        self.0 = *a as u32;
    }
}
```

المثال أعلاه سينتج الربط التالي مع تمثيل `DaysSinceEquinox` كمؤشر غير شفاف:

```rust
pub extern fn DaysSinceEquinox__update_value(handle: *mut DaysSinceEquinox, a: *const u8) -> FfiReturn {
    // function implementation
}
```

## FFI توليد الربط {#ffi-binding-generation}

يُستخدم حزمة البرمجيات `iroha_ffi` لتوليد الدوال التي يمكن استدعاؤها عبر FFI. بالنظر إلى الهياكل والأساليب `Rust`، فإنها تولد الكود `unsafe` الذي ستحتاجه لعبور حدود الربط.

يتم تحويل نوع Rust إلى نوع قوي `repr(C)` يمكن أن يعبر حدود FFI مع `FfiType::into_ffi`. ويحدث العكس أيضًا: يتم تحويل نوع FFI `ReprC` إلى نوع `Rust` عبر `FfiType::try_from_ffi`.

::: warning

لاحظ أن التحويل المعاكس قابل للخطأ ويمكن أن يسبب سلوكًا غير محدد. بينما يمكننا بذل قصارى جهدنا لتجنب أكثر الأخطاء وضوحًا، يجب عليك التأكد من صحة البرنامج من جانبك.

:::

السمات الرئيسية التي تمكّن توليد الروابط هي `ReprC`، `FfiType`، و`FfiConvert`.

|سمة|الوصف|
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ReprC`      |تمثل هذه الصفة نوعًا قويًا يتوافق مع C ABI. يمكن مشاركة النوع بأمان عبر حدود FFI.|
|`FfiType`|تحدد هذه السمة نوع `ReprC` المطابق لنوع `Rust` المحدد. يتم استخدام النوع `ReprC` المحدد بدلاً من النوع `Rust` في API للدالة FFI المولدة.|
| `FfiConvert` |تحدد هذه الخاصية طريقتين `into_ffi` و `try_from_ffi` اللتين تُستخدمان لأداء تحويل نوع `Rust` إلى أو من نوع `ReprC`.|

يرجى ملاحظة أنه لا يوجد نقل ملكية على FFI باستثناء أنواع المؤشرات الغامضة. جميع الأنواع الأخرى التي تحمل الملكية، مثل `Vec<T>`، يتم نسخها.

### تحريف الأسماء {#name-mangling}

لاحظ استخدام الشرطة السفلية المزدوجة في الأسماء المولدة للكائنات FFI:

- بالنسبة لطريقة `inherent_fn` المعرفة على البنية `StructName`، فإن اسم FFI سيكون `StructName__inherent_fn`.
- بالنسبة للطريقة `MethodName` من السمة `TraitName` في البنية `StructName`، سيكون الاسم FFI هو `StructName__TraitName__MethodName`.
- لتعيين حقل `field_name` في البنية `StructName`، سيكون اسم الدالة FFI هو `StructName__set_field_name`.
- للحصول على الحقل `field_name` في الهيكل `StructName`، سيكون اسم الدالة FFI هو `StructName__field_name`.
- للحصول على الحقل القابل للتغيير `field_name` في البنية `StructName`، سيكون اسم الدالة FFI هو `StrucuName__field_name_mut`.
- بالنسبة لـ `module_name::fn_name` المستقل، سيكون اسم FFI هو `module_name::__fn_name`.
- بالنسبة للسمات التي ليست عامة وتسمح بمشاركة تنفيذها في FFI (انظر `Clone` أدناه)، سيكون اسم FFI هو `module_name::__clone`.

  ```rust
  impl Clone for Type1 {
      fn clone(&self) -> Self;
  }
  impl Clone for Type2 {
      fn clone(&self) -> Self;
  }
  ```
