# واجهات الوظائف الخارجية (FFI) {#foreign-function-interfaces-ffi}

(الـ) `iroha_ffi` الصندوق يوفر الكليات والخصائص لتوليد C ABI
الالتزامات من Rust APIs. يتم استخدامها في Iroha أنواع تحتاج إلى عبور FFI
الحدود، على سبيل المثال SDK الارتباطات أو تكاملات المضيف.

## لماذا؟ FFI {#why-ffi}

وظيفة هي كيان مجرد إلى حد ما، وفي حين أن معظم اللغات تتفق على
ما يجب أن تفعله الوظيفة، الطريقة التي تمثل بها الوظائف هي
وبالإضافة إلى ذلك، في بعض اللغات، مثل Rust, العواقب
من دعوة وظيفة والأشياء التي يسمح لها القيام بها هي أيضا
مختلفة. Rust APIs يجب أن تكون من لغة أخرى أو
بيئة مضيفة مختلفة، Iroha يستخدم واجهة وظيفة خارجية (FFI)
لتسوية المجال.

المعيار الرئيسي المستخدم اليوم هو واجهة التطبيقات الثنائية C.
بسيطة، متوفرة على نطاق واسع، ومستقرة.
كل شيء يدوياً، لكن Iroha يقدم `iroha_ffi` الصندوق لتوليد
FFI- وظائف متوافقة خارج من وظيفة موجودة Rust API.

يمكنك، بالطبع، القيام بذلك بطريقتك `iroha_ffi` الصندوق فقط
يخلق الشفرة التي ستحتاج إلى إنتاجها على أي حال. كتابة
ويتطلب ذلك الكثير من الحرص والانضباط.
كل مكالمة وظيفة على FFI الحدود هي `unsafe` مع القدرة على
سبب سلوك غير محدد. الطريقة التي تمكنا من حلها،
يدور حول استخدام **قوية** `repr(C)` النوع.

::: info

الاستثناء الوحيد هو المؤشرات.
يتم تطبيقها على الصعيد العالمي، لذلك لا يستخدم المؤشرات الخامة (كما هو الحال دائما) إلا في حالات استثنائية
حالياً، نظراً لأننا نقدم ملفات حول كل حالة تقريباً من
الموضوع في Iroha نموذج البيانات، لا يجب عليك استخدام المؤشرات الخام في
كل شيء

:::

## مثال {#example}

وهنا مثال على توليد الالتزام:

```rust
#[derive(FfiType)]
struct DaysSinceEquinox(u32);

#[ffi_export]
impl DaysSinceEquinox {
    pub fn update_value(&mut self, a: &u8) {
        self.0 = *a as u32;
    }
}
```

النموذج المذكور أعلاه سيؤدي إلى الارتباط التالي مع
`DaysSinceEquinox` تمثل كمؤشر غير مرئي:

```rust
pub extern fn DaysSinceEquinox__update_value(handle: *mut DaysSinceEquinox, a: *const u8) -> FfiReturn {
    // function implementation
}
```

## FFI جيل ملزم {#ffi-binding-generation}

(الـ) `iroha_ffi` يتم استخدام صندوق لتوليد وظائف يمكن استدعاءها عبر
FFI. تم إعطائها `Rust` الهياكل والطرق، فإنها تولد `unsafe` الرمز الذي
ستحتاجين لعبور الحدود المرتبطة.

(أ) Rust يتم تحويل النوع إلى قوي `repr(C)` النوع الذي يمكن أن يعبر
FFI الحدود مع `FfiType::into_ffi`. هذا يذهب في الاتجاه الآخر حول
حسناً FFI `ReprC` يتم تحويل النوع إلى `Rust` النموذج عبر
`FfiType::try_from_ffi`.

::: warning

لاحظ أن التحويل المعاكس خاطئ ويمكن أن يسبب غير محدد
في حين أننا نستطيع أن نبذل قصارى جهدنا لتجنب
أخطاء، يجب أن تأكد من صحة البرنامج في نهاية.

:::

The السمات الرئيسية التي تمكن من توليد الالتزام هي: `ReprC`, `FfiType`, و
`FfiConvert`.

| السمة        | وصف                                                                                                                                                                     |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ReprC`      | هذه الصفة تمثل نوع قوي يتوافق مع C ABI. يمكن توزيع النوع بأمان بين FFI الحدود                                                                |
| `FfiType`    | هذه الصفة تعريف المقابلة `ReprC` النموذج المحدد `Rust` النوع المحدد `ReprC` يتم استخدام النموذج بدلا من `Rust` النموذج في API من الناتج FFI الوظيفة |
| `FfiConvert` | هذه الصفة تعريف طريقتين `into_ffi` و `try_from_ffi` التي تستخدم لتنفيذ تحويل `Rust` النموذج إلى أو من `ReprC` النوع                                |

لاحظ أنه لا توجد نقل ملكية على FFI باستثناء المؤشر غير الشفاف
جميع الأنواع الأخرى التي تحمل الملكية، مثل `Vec<T>`, تم تجميعها.

### اسم (مانجلينغ) {#name-mangling}

لاحظ استخدام علامات التأكيد المزدوجة في الأسماء التي تم إنشاؤها FFI الأشياء:

- لـ `inherent_fn` الطريقة المحددة على `StructName` الهيكلية FFI
  الاسم سيكون `StructName__inherent_fn`.
- لـ `MethodName` طريقة من `TraitName` سمة في
  `StructName` الهيكلية FFI الاسم سيكون
  `StructName__TraitName__MethodName`.
- لتحديد `field_name` في المجال `StructName` الهيكلية FFI
  اسم الوظيفة سيكون `StructName__set_field_name`.
- للحصول على `field_name` في المجال `StructName` الهيكلية FFI
  اسم الوظيفة سيكون `StructName__field_name`.
- للحصول على المتحول `field_name` في المجال `StructName` الهيكلية FFI
  اسم الوظيفة سيكون `StrucuName__field_name_mut`.
- للاستقلاليين `module_name::fn_name`, الموقع FFI الاسم سيكون
  `module_name::__fn_name`.
- للخصائص التي ليست عامة وتسمح بمشاركة
  التنفيذ في FFI (انظر) `Clone` أدناه) FFI الاسم سيكون
  `module_name::__clone`.

  ```rust
  impl Clone for Type1 {
      fn clone(&self) -> Self;
  }
  impl Clone for Type2 {
      fn clone(&self) -> Self;
  }
  ```
