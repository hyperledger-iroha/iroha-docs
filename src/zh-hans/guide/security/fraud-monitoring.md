# 欺诈监测 {#fraud-monitoring}

欺诈监测 Iroha 部署是一个围绕
总体事件,查询,权限和应用背景. Iroha 记录了什么
您的监控系统决定
哪些模式对您的业务流程有疑问,以及这些案件的路线
对审查人员或自动响应控制.

处理欺诈监控作为一个独立的服务,而不是嵌入在
证实器. 该服务应订阅本书活动,
在链外风险背景下,持有证据,仅提交响应交易
通过有明确许可的帐户.

## 监控模式 {#monitoring-model}

一个有用的监控管道有四个阶段:

1. **收藏** 账本和操作符的信号 Torii 事件流,查询,
   它们的数量和数据.
2. **丰富** 在链外的事件,例如客户状态
   应对方列表,申请会话标识符,预期限制,
   案例 IDs.
3. **检测** 具有确定性规则,审查员队列或
   风险评分.
4. **回答** 通过警告运营商,暂停应用程序侧工作流程,
   撤销不必要的许可证或提交补偿交易
   在您的治理过程允许的时候.

除非每个验证者都必须重复
运行时间验证应该强制授权和交易
监控欺诈应解释风险,保存证据并帮助
运营商迅速行动.

## 收集的信号 {#signals-to-collect}

开始使用狭窄的订阅,然后只为调查添加更广泛的流程:

| 信号 | 来源 | 使用 |
| --- | --- | --- |
| 交易状态 | 管道事件 | 检测重复拒绝,未能授权尝试和不寻常的提交模式 |
| 账户生命周期和元数据 | 数据事件和账户查询 | 检测新帐户,姓名变更,身份更新和意想不到的元数据编辑 |
| 资产余额和转账 | 资产数据事件和资产查询 | 检测高价值运动,快速缩,平衡排水和不寻常的对方 |
| 角色和权限 | 角色和许可查询,角色数据事件 | 检测特权升级,紧急补贴和过时高风险的访问 |
| 触发器和合同变化 | 触发,合同和执行事件 | 检测到新的自动化,改变执行路径和可疑的升级活动 |
| 配置和同行变化 | 配置和同行活动 | 检测影响验证,网络或运营商可见性的治理变化 |
| 运营商健康 | `/metrics` 并且 Sumeragi 状态路线 | 从节点过载,队列压力或网络故障中分离可疑用户行为 |

使用 [事件过器](/zh-hans/blockchain/filters.md) 避免处理整个事件
当一个规则只需要账户,资产,角色或配置变化时.
为了定期调整,将流和页面化组合在一起
[查询](/zh-hans/blockchain/queries.md) 显示器可以在停机后恢复.

## 检测规则 {#detection-rules}

常见规则家庭包括:

| 规则家族 | 举例条件 | 典型的反应 |
| --- | --- | --- |
| 速度 | 一个账户在短时间内转移超过预期的金额或计数 | 报警审查员和暂停申请方提款对该账户 |
| 扩展 | 资金从一个账户转移到许多新出现的帐户 | 在允许额外转移之前需要手动批准 |
| 均衡排水 | 密钥,别名或元数据变更后不久就会留下大量的账户余额 | 尽可能扩大账户收购 |
| 升级特权 | 在变更窗口之外,给予高风险许可或角色 | 警告运营商并审查补助交易 |
| 拒绝爆发 | 一个签署者或客户进行了反复拒绝的交易 | 检查证书滥用,整合错误或探究 |
| 自动化变更 | 一个触发器,合同或执行器相关的对象发生了意想不到的变化 | 暂停依赖工作流程,直到修改审查 |
| 对治理敏感的变化 | 在未经批准的门票的情况下发生同行,配置或运行时间状态变化 | 与管理记录和事件过程进行比较 |

规则应该明确说明他们需要的证据,
评估,他们采取的行动以及能够关闭
根据客户风险,资产类型或司法管辖范围的门值
在您的监控服务配置中,而不是在临时脚本中.

## 响应控制 {#response-controls}

在启动警报之前设计应对行动.
必须有记录的路径,从检测到控制:

- 通知负责安全,运营和企业所有者
  被影响的域名或资产定义
- 保存事件标记,区块哈希,交易哈希,权威,有效载荷,
  和检测规则所使用的查询快照
- 暂停在本书之外的应用程序侧操作,例如收取账单,
  撤销,签署,桥梁或结算工作流程
- 撤销因事件不再合理的角色或许可
  应对计划
- 只有在积极治理政策下,才能提交后续账本交易
  允许他们
- 当证据表明签署者妥协时旋转键

避免给监控服务提供广泛的写入.
技术账户,具有响应所需的最小权限集
人类批准应继续成为任何
可以移动资产,更改权限或改变验证器面向的工作流程
配置.

## 证据和保留 {#evidence-and-retention}

存储监测证据在单独的附录系统中,
验证器数据目录.每个报警应包括:

- 事件流名称和标记
- 区块高度或可用时区块哈希
- 交易哈希和权威
- 被影响的帐户,域名,资产,角色,触发器或配置 ID
- 原始事件有效载荷或其正规的哈希
- 查询快照用于丰富报警
- 规则名称,版本,门,分数和审查员的决定

除非在公开账本中存储敏感调查记录,
网络的数据管理政策明确允许.
在链外的案例,而不是在链上状态,更喜欢一个案例标识符,签署的证书,
或是不披露私人细节的哈希承诺.

## 执行检查列表 {#implementation-checklist}

- 启用所需的远程测量资料 `/metrics` 运营商的路线.
- 订阅 Torii 与你对象的狭窄过器的事件流
  监视器
- 保持事件缓冲器,以便显示器可以在没有缺口的情况下恢复.
- 调整频道和页面化查询.
- 保持风险门值,并允许版本控制配置中的列表.
- 在启动自动操作之前,测试对历史区块的警报规则.
- 为应对行动使用专门的技术账户.
- 审查角色和许可授予时间表.
- 在应对事件过程中包括欺诈监测警报.
