# Сұрақтар {#queries}

Блокчейннің жай-күйі туралы ақпараттың көп бөлігін біз бұрын көрсеткендей, оқиғаларға жазылушы мен сүзгі арқылы қызықты оқиғалардың ауқымын қысқарту үшін алуға болады. Кейде сізге одан да тікелей көзқарас қажет. Сұрау салуларды енгізу.

Сұрақтар - бұл Iroha әріптесіне жіберілген кішкентай нұсқаулық тәрізді нысандар, олар қазіргі заманғы әлем жағдайына қатысты нақты мәліметтермен жауап береді.

Бұл міндетті түрде желіде қол жетімді жалғыз ақпарат емес, бірақ бұл барлық желілерде қолжетімді болуы кепілдендірілген бірден-бір ақпарат.

Iroha орналасуы үшін басқа да ақпараттар болуы мүмкін. Мысалы, телеметриялық деректердің қол жетімділігі желі әкімшілеріне байланысты. Бұл толықтай олардың шешімі, олар жұмыс істеу үшін оны пайдаланудың орнына жұмысты бақылау үшін өңдеу қуатын бөлуді қалайды ма немесе жоқ па. Керісінше, кейбір функциялар әрдайым қажет, мысалы, сіздің шоттың балансына қол жеткізу.

Сұрау салулардың нәтижелері: [сұрыпталған](#sorting), [бетбелгісі](#pagination) және [сүзгіленген](#filters) Метадеректер кілттері бойынша лексикографиялық түрде сұрыптау жүргізіледі. IP address filter masks) және substring әдістері сияқты `begins_with` логикалық операциялар арқылы біріктіріледі.

## Taira арқылы сынап көріңіз. {#try-it-on-taira}

Taira тек оқуға арналған сұраныс көмекшілерін ашу JSON ортақ ресурстар үшін оларды пайдалан. SDK:

```bash
TAIRA_ROOT=https://taira.sora.org

curl -fsS "$TAIRA_ROOT/v1/accounts?limit=3" \
  | jq '{total, ids: [.items[].id]}'

curl -fsS "$TAIRA_ROOT/v1/domains?limit=3" \
  | jq '{total, domains: [.items[].id]}'

curl -fsS "$TAIRA_ROOT/v1/assets/definitions?limit=3" \
  | jq '{total, assets: [.items[] | {id, name, total_quantity}]}'
```

Қолданбаларды диагностикалау үшін бұл түтін тексерулерді қол қойылған транзакция сынақтарынан бөлек ұстаңыз. Тек оқуға арналған сұрау қатесі әдетте қолтаңбалаушы орнатуды көрсетуден бұрын аяқтық нүктелердің қол жетімділігіне, желіге қол жеткізуіне немесе маршрут үйлесімділігіне сілтейді.

## Сұрау салуды құру {#create-a-query}

Тіркелген сұрау салу жасаушыларын пайдалан SDK немесе CLI. Мысалы, қазіргі деректер моделі `FindAccounts` тізілімге енгізілетін шоттар үшін:

```rust
let query = FindAccounts;
```

Мұнда Алистің активтерін табатын сұраудың мысалы бар:

```rust
let alice_id = load_canonical_account_id_from_client_config()?;
let query = FindAssetsByAccountId::new(alice_id);
```

## Беттесу {#pagination}

Жалғызбасты сұраулар мен шағын қайталанатын сұраулар үшін `client.request` көмегімен сұрау салуды тапсырып, нәтижені бірден ала аласыз.

Алайда, кеңірек қайталанатын сұрақтар: `FindAccounts`, `FindAssets`, немесе `FindBlocks` үлкен нәтижелер жиынтығын қайтаруға болады. Пайдалануды пайдаланып, әріптестер мен клиенттер жүктемесін азайта аласыз.

Құрылыс үшін `Pagination`, Сіз шақыру керек `client.request_with_pagination(query, pagination)`, мұнда `pagination` төмендегідей құрылымдалған:

```rust
let starting_result: u32 = _;
let limit: u32 = _;
let pagination = Pagination::new(Some(starting_result), Some(limit));
```

## Сүзгілер {#filters}

Сұрау салуды пайдаланғанда, көрсетілген сүзгіге сәйкес келетін нәтижелерді ғана қайтаруға сүзгі пайдалана аласыз.

Сүзгілер сұрау салуға тән. Мәселен, шот сұраныстарын есептің сәйкестігі немесе метамәліметтері арқылы қысқартуға болады, ал актив сұраныстарын активтердің анықтамасы, иеленуші есебі немесе домен проекциясы арқылы қысқартуы мүмкін. Мүмкіндігінше SDK түрленген сұрау салу жасаушыларын пайдаланыңыз, сондықтан сүзгі түрі сұрау салудың шығыс үлгісіне сәйкес келеді.

## Тарыптау {#sorting}

Iroha элементтерін сұрыптау [метадеректер](/kk/blockchain/metadata.md) Сұрау салуды құру кезінде сұрыптау үшін кілті келтірсеңіз, лексикографиялық түрде. `registered-on` метамәдени деректер кіруі, ол сұрыпталған кезде тіркелгі тіркеу тарихын көрсетуге мүмкіндік береді.

Тарыптау тек [ метадеректері](/kk/blockchain/metadata.md) бар субъектілерге қолданылады, өйткені метадеректер кілті сұраныс нәтижелерін сұрыптау үшін пайдаланылады.

Сіз сұрыптауды парақтандыру және сүзгілермен біріктіре аласыз. Сорттаудың ерікті функциясы екенін ескеріңіз, парақтандырумен байланысты сұранымдардың көпшілігі оған мұқтаж емес.
