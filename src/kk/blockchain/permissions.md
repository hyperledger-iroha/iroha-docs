# Рұқсаттар {#permissions}

Есептік жазбаларға блокчейнде әртүрлі әрекеттерді орындау үшін рұқсат токендері қажет, мысалы, активтерді шығару немесе жою үшін.

Қолданушыларға берілетін рұқсаттар тұрғысынан ашық және жабық блокчейн арасында айырмашылық бар. Ашық блокчейнде, есептік жазбалардың көбісі бірдей рұқсаттар жиынтығына ие болады. Жеке блокчейнде, көп есептік жазбаларға тікелей тиісті рұқсат берілмейінше, оларға берілген уәкілетті субъектініен тыс ештеңе жасау мүмкіндігі жоқ деп есептеледі.

Өзгелерге бір нәрсе жасауға рұқсат алу есептік жазбаның сәйкес құқығы бар екенін білдіреді `Permission`. Рұқсаттар тікелей немесе арқылы берілуі мүмкін [`Role`](#permission-groups-roles), құқықтардың жиынтығын топтастыратын. Құқықтар берілетін `Grant` нұсқау. Рұқсаттар мен рөлдер мерзімі өтіп кетпейді; оларды мына арқылы алып тастаңыз `Revoke` нұсқаулық.

## Рұқсат белгішелері {#permission-tokens}

Рұқсат хаттары белсенді орындаушы арқылы анықталған түрленген объектілер болып табылады. Кейбір хаттар жаһандық, мысалы `CanManagePeers`, ал басқалары белгілі бір блокчейн есептік жазбасы объектісіне шектелген, мысалы есептік жазба, актив, актив анықтамасы, домен, NFT, рөл немесе триггер.

Мұнда әртүрлі рұқсат токендерінде қолданылатын параметрлердің бірнеше мысалы келтірілген:

- Белгілі бір аккаунттың метадеректерін өзгертуге рұқсат беретін токенде `account` өрісі бар:

  ```json
  {
    "account": "<AccountId>"
  }
  ```

- Белгілі бір активтің анықтамасы бойынша активтерді аударуға рұқсат беретін токенде `asset_definition` өрісі бар:

  ```json
  {
    "asset_definition": "<AssetDefinitionId>"
  }
  ```

- `CanManagePeers` сияқты әлемдік токеннің ешқандай өрісі жоқ:

  ```json
  {}
  ```

### Алдын ала бапталған рұқсат токендері {#pre-configured-permission-tokens}

Сіз алдын ала бапталған рұқсат белгілерінің тізімін [Сілтеме](/kk/reference/permissions) тарауында таба аласыз.

## Рұқсат топтары (Рөлдер) {#permission-groups-roles}

Рұқсаттар жиынтығы рөл деп аталады. Рұқсат токендері сияқты, рөлдер `Grant` нұсқаулығын қолданып беріліп, `Revoke` нұсқаулығын қолданып қайтарып алынуы мүмкін.

Есептік жазбаға рөл бермес бұрын, рөл алдымен тіркелуі керек.

Рөлдер бірнеше есептік жазба бірдей рұқсат жинағын алуы қажет болғанда пайдалы. Рөлді бір рет тіркеп, рөлге рұқсаттарды беріп, содан кейін жеке есептік жазбаларға рөлді беру немесе қайтару керек.

### Жаңа рөлді тіркеу {#register-a-new-role}

Қолданыла бастағанда басқа есептік жазбаға Mouse есептік жазбасындағы [метадеректер](/kk/blockchain/metadata.md)-ке кіруге мүмкіндік беретін жаңа рөлді тіркейік:

```rust
let role_id = RoleId::from_str("ACCESS_TO_MOUSE_METADATA")?;
let role = iroha_data_model::role::Role::new(role_id.clone(), mouse_id.clone())
    .add_permission(CanModifyAccountMetadata {
        account: mouse_id.clone(),
    });
let register_role = Register::role(role);
```

### Рөлді беру {#grant-a-role}

Рөл тіркелгеннен кейін, Mouse оны Alice-ге бере алады:

```rust
let grant_role = Grant::account_role(role_id, alice_id);
let grant_role_tx = TransactionBuilder::new(chain_id, mouse_id)
    .with_instructions([grant_role])
    .sign(mouse_private_key);
```

## Рұқсатты тексерушілер {#permission-validators}

Құқықтар тек қажет рұқсат белгішесі бар есептік жазбалар қорғалатын әрекетті орындау үшін бар. Стандартты орындаушы нұсқаулық, сұрау және өрнекті орындау кезінде құқықтарды тексереді.

Әдепкі валидация беті блокчейн жазбасы аймағы бойынша топтастырылған:

- торап серіктестерін басқару
- домендер және есептік жазбалар
- активтер, NFTs, және кепілдіктер
- қоздырғыштар
- рөлдер және рұқсаттар
- орындаушы/жүру уақыты, дәлелдер, көпірлер және SORA/Nexus модульдері

Дәл токендер тізімі [Рұқсат қағаздарына сілтеме](/kk/reference/permissions.md) дереккөзімен қамтамасыз етілген.

### бағдарламалық қамтамасыз ету орындау ортасы Валидаторлар {#runtime-validators}

Рұқсаттарды тексеру белсенді орындаушы арқылы жүзеге асырылады. Әдепкі орындаушы кіріктірілген рұқсат тексерушілерін және токен анықтамаларын ұсынады, ал желі пайдаланатын орындаушысын жаңарту арқылы саясатты өзгерте алады.

Тексерушілер тексеру шешімін қайтарады. Тексеруші операцияны рұқсат ете алады, себебін көрсетіп бас тарта алады немесе операция тексерушінің ауқымынан тыс болса, оны өткізіп жібере алады. Таңдалған сот шешімдерді біріктіріп, нұсқаулықтың, сұраудың немесе өрнектің орындала ала ма, жоқ па, соны шешеді.
