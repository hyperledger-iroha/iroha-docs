# Есепшоттар {#accounts}

Тіркелгі - бұл транзакцияларға қол қоюға және өз бухгалтерлік жазбасын жазуға қабілетті орган. Қазіргі Iroha 3 дерек үлгісінде, `AccountId` каноникалық және доменсіз: ол шот бақылаушысынан шығарылады және каноникалық түрде [I105](/kk/reference/i105.md) ретінде кодталады. Адамға оқуға болатын домен мен деректер кеңістігінің контексі бөлек шот-алтын байланыстарға жатады.

## Құрылымы {#structure}

Тіркелген `Account` құрамында:

- `id`: каноникалық `AccountId`
- `metadata`: кездейсоқ шоттың метамәдени деректері
- `label`: таңдаулы тұрақты аты-жөні
- `uaid`: Nexus ағымдары пайдаланатын жалпы шотты ID
- `opaque_ids`: шоттың UAID сәйкестендіруіне байланысты ашық емес идентификаторлар.

Есепшотты құру үшін пайдаланылатын транзакцияның пайдалы жүктемесі `NewAccount` болып табылады. Ол тіркелген шотта қолданылатын бірдей сәйкестік, метамәліметтер, таңба, UAID және мөлдір емес ID өрістерді қамтиды.

`uaid` каноникалық мазмұнды толықтырады `AccountId`; оны алмастыруға болмайды. Nexus қызметтерге деректер кеңістігінде тұрақты пайдаланушы немесе ұйым басқаруы қажет, құпиялылықты сақтайтын тіркелу, жұмыс істеу уақыты бір-бірден UAID- есептік көрсеткіш, мөлдір емес сәйкестендірушілерді UAID, және екі рет немесе бір-бірімен ұшыраған ашық емес идентификаторларды қабылдамайды. қараңыз [FHE және UAID](/kk/blockchain/sora-nexus-services.md#fhe-and-uaid) үшін Nexus қызметтік қабаттың ағыны.

## Тіркелгі бақылаушылары {#account-controllers}

Бақылаушы есептің әрекеттерге қалай рұқсат беруін анықтайды. Әдетті клиент ағыны Ed25519 кілті жұптарын пайдаланады, бірақ деректер моделі сондай-ақ көп қолтаңбалы саясат бақылаушылары сияқты бай басқарушыларды қолдайды.

Клиенттің конфигурациясы қолтаңбалау билігін әріптестердің конфигурациясынан бөлек сақтайды:

```toml
[account]
public_key = "ed0120..."
private_key = { digest_function = "ed25519", payload = "..." }
```

Назардағы кілт форматтары үшін [клиент конфигурациясы](/kk/guide/configure/client-configuration.md) және [кілті генерациясы](/kk/guide/security/generating-cryptographic-keys.md) қараңыз.

## Taira арқылы сынап көріңіз. {#try-it-on-taira}

Қоғамдық Taira тестілеу желісінің кейбір каноникалық есептерін IDs келтіріңіз:

```bash
curl -fsS 'https://taira.sora.org/v1/accounts?limit=5' \
  | jq -r '.items[] | [.id, (.primary_alias // "-")] | @tsv'
```

Есепшот активтерін тексеру үшін есепшоттың көшірмесін жасаңыз ID алғашқы шақырудан бастап және URL-Сол жолға қойылмай тұрып кодтау. Python Сниппетте бірінші тізімделген шот үшін осылай жасалады:

```bash
python3 - <<'PY'
import json
import urllib.parse
import urllib.request

root = "https://taira.sora.org"
accounts = json.load(urllib.request.urlopen(f"{root}/v1/accounts?limit=1"))["items"]
account_id = accounts[0]["id"]
encoded = urllib.parse.quote(account_id, safe="")
assets = json.load(
    urllib.request.urlopen(f"{root}/v1/accounts/{encoded}/assets?limit=5")
)

print(json.dumps({"account_id": account_id, "assets": assets["items"]}, indent=2))
PY
```

Бұл қоғамдық оқылымдар. Есепшотты құру немесе жаңарту қол қойылған транзакция болып табылады және краннан қаржыландырылған Taira параметрлері [Қосылу SORA Nexus Деректер базасы](/kk/get-started/sora-nexus-dataspaces.md).

## Тіркеу және рұқсаттар {#registration-and-permissions}

Есепшоттар жалпы [`Register` және `Unregister`](/kk/blockchain/instructions.md#un-register) нұсқаулықтарымен тіркеледі және тіркелмейді. Белсенді жұмыс уақытын растаушы есептерді кім жасай алатынын және қандай рұқсат белгілері немесе рөлдер талап етілетінін анықтайды.

Тіркеуден кейін шот:

- транзакцияларды қолтаңбалау
- активтерді ұстау
- меншікті домендер
- рөлдерді және рұқсат белгілерін алу
- сақтау метамәдени деректері
- осы функциялар қосылған кезде аты-жөн, рекей, қалпына келтіру және Nexus сәйкестік ағындарына қатысу;

## Құпиялылық мәселелерін шешу {#troubleshooting-identity-issues}

Егер транзакция күтпеген жерден қабылданбаса, мыналарды тексеріңіз:

- клиенттің мемлекеттік кілті қолтаңбалау үшін пайдаланылатын жеке кілтіне сәйкес келеді
- шот генезисте тіркелді немесе кепілдендірілген транзакция бойынша
- уәкілетті органның нұсқаулық бойынша қажетті рұқсаттары бар
- қатаң шоттар өрістерінде I105 каноникалық ID есепті пайдаланады, ал оқуға болатын атаулар активтік шот-алмаш байланысы арқылы шешеді.
