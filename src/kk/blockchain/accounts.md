# Шоттар {#accounts}

Есептік жазба – транзакцияларға қол қоя алатын және блокчейн хаттама күйін басқара алатын уәкілетті субъект. Қазіргі Iroha 3 деректер моделінде, `AccountId` бір протокол-стандартты және доменсіз болып табылады: Бұл есеп шот контроллерінен алынған және [I105](/kk/reference/i105.md) ретінде бір протокол стандартты формада кодталған. Адам оқи алатын домен және деректер кеңістігі контексті бөлек есеп-шот лақап аттарымен байланыстырылған.

## Құрылым {#structure}

Тіркелген `Account` мыналарды қамтиды:

- `id`: бір ғана протокол-стандарт `AccountId`
- `metadata`: кездейсоқ есеп жазбасының метадеректері
- `label`: міндетті емес тұрақты лақап ат
- `uaid`: Nexus ағындарында қолданылатын ерікті Универсалды Есептік жазба ID
- `opaque_ids`: есептік жазбаға байланған мөлдір емес идентификаторлар UAID

Есепшотты жасау үшін қолданылатын транзакция жүктемесі `NewAccount` болып табылады. Ол тіркелген есепшот қолданатын сол идентификаторды, метадеректерді, таңбаны, UAID және мөлдір емес ID өрістерін тасымалдайды.

`uaid` жеке протокол стандарты `AccountId`-ді толықтырады; оны алмастырмайды. Nexus қызметтері деректер кеңістігінде тұрақты пайдаланушы немесе ұйымдық идентификаторды, құпиялылықты сақтай отырып тіркелуді немесе қызмет мүмкіндіктерін іздеуді қажет ететін кезде оны қолданыңыз. Бағдарламалық қамтамасыз ету орындалу ортасы бір-біріне сәйкес келетін UAID-тіркелгі индексін сақтайды, UAID арқылы жасырын идентификаторларды қосуды талап етеді және қайталанатын немесе соқтығысатын жасырын идентификаторларды қабылдамайды. Nexus қызметтік деңгей ағыны үшін [FHE және UAID](/kk/blockchain/sora-nexus-services.md#fhe-and-uaid)-ге қараңыз.

## Есеп-шот бақылаушылары {#account-controllers}

Басқару құрылғысы есептік жазбаның әрекеттерді қалай рұқсат ететінін анықтайды. Әдеттегі клиент ағыны Ed25519 кілт жұбын пайдаланады, бірақ деректер моделі мультиқолтаңба саясаты сияқты бай басқарушыларды да қолдайды.

Клиент конфигурациясы қол қою құқығын желілік серіктес конфигурациясынан бөлек сақтайды:

```toml
[account]
public_key = "ed0120..."
private_key = { digest_function = "ed25519", payload = "..." }
```

Ағымдағы кілт пішімдері үшін [клиент конфигурациясы](/kk/guide/configure/client-configuration.md) және [кілт жасау](/kk/guide/security/generating-cryptographic-keys.md) қараңыз.

## Осы жұмыс ағынын Taira бойынша іске қосыңыз {#try-it-on-taira}

Қоғамдық Taira тест желісінен бірнеше бір протокол-стандартты есептік жазба идентификаторларын тізімдеңіз:

```bash
curl -fsS 'https://taira.sora.org/v1/accounts?limit=5' \
  | jq -r '.items[] | [.id, (.primary_alias // "-")] | @tsv'
```

Есептік жазба активтерін тексеру үшін, бірінші техникалық шақырудан есептік жазбаның идентификаторын көшіріп, оны жолға қоюдан бұрын URL бойынша кодтаңыз. Бұл Python үзінді бірінші көрсетілген есептік жазба үшін осылай жасайды:

```bash
python3 - <<'PY'
import json
import urllib.parse
import urllib.request

root = "https://taira.sora.org"
accounts = json.load(urllib.request.urlopen(f"{root}/v1/accounts?limit=1"))["items"]
account_id = accounts[0]["id"]
encoded = urllib.parse.quote(account_id, safe="")
assets = json.load(
    urllib.request.urlopen(f"{root}/v1/accounts/{encoded}/assets?limit=5")
)

print(json.dumps({"account_id": account_id, "assets": assets["items"]}, indent=2))
PY
```

Бұл жалпы оқулар. Есептік жазбаны жасау немесе жаңарту - қол қойылған транзакция болып табылады және [SORA Nexus Деректер кеңістіктеріне қосылу](/kk/get-started/sora-nexus-dataspaces.md)-де сипатталған testnet-қаржыландырылған Taira баптауды қажет етеді.

## Тіркеу және рұқсаттар {#registration-and-permissions}

Есептік жазбалар жалпыға тіркелген және тіркелмеген [`Register` және `Unregister`](/kk/blockchain/instructions.md#un-register) нұсқаулар. Белсенді бағдарламалық қамтамасыз ету орындалу ортасын тексеруші шешеді кім есепшоттар жасай алатынын және қандай рұқсат белгілері немесе рөлдер қажет екенін.

Тіркелгеннен кейін есептік жазба мыналарды жасай алады:

- транзакцияларға қол қою
- активтерді ұстау
- меншікті домендер
- рөлдер мен рұқсат белгілерін алу
- метадеректерді сақтау
- сол мүмкіндіктер қосылған кезде, лақап ат, қайта кілттеу, қалпына келтіру және Nexus тұлға ағындарына қатысу

## Жеке бас мәселелерін шешу {#troubleshooting-identity-issues}

Егер транзакция күтпеген жерден қабылданбаса, мыны тексеріңіз:

- клиенттің ашық кілті қол қою үшін қолданылған жеке кілтпен сәйкес келеді
- есеп шоты блокчейн генезисінде немесе аяқталған транзакция арқылы тіркелді
- уәкілетті субъектіде нұсқауда көрсетілген құқықтар бар
- қатаң есептік жазба өрістері бір протокол-стандартты I105 есептік жазба идентификаторын пайдаланады, ал оқылымды атаулар белсенді есептік жазба-аттас байланыстыру арқылы шешіледі
