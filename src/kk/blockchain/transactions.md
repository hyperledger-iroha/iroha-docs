# Келісім-шарттар {#transactions}

Транзакция — блокчейнде жұмыс істеуді орындауға арналған қол қойылған сұраныс. Орындауға болатын жүктеме [нұсқаулар](./instructions.md) реттелген реттілік, келісімшарттың техникалық шақыруы, IVM байткод немесе дәлелденген IVM орындау болуы мүмкін. Ағымдағы келісімшарт орындау моделін көру үшін [Ақылды келісімшарттар](./smart-contracts.md)-ге қараңыз.

Транзакциялар күйді өзгерту немесе орындалатын жұмыстарды орындау үшін қолданылады. Тек оқу үшін тексеру қол қоюлы сұраныстарды немесе жалпы оқу API нүктелерін пайдаланады және транзакция жасамайды.

Аяқталған блокқа қабылданған транзакция оның орындалу нәтижесімен бірге сақталады, оның ішінде орындалу қабылдамауы да болады. Блокқа қабылдаудан бұрын қабылданбаған сұраныстар, мысалы, жарамсыз деректер контейнері немесе кезек арқылы қабылданбаған транзакция, блокта сақталмайды.

Жеке өмірді сақтау үшін активтерді жылжыту туралы қараңыз [Анонимдік транзакциялар](./anonymous-transactions.md). Анонимді транзакциялар жалпы есеп-шот арасындағы баланс өзгерістері орнына қорғалған активтік жазбаларды, криптографиялық міндеттемелер мәндерін, нөлдік белгілеушілерді және нөл-білімді дәлелдерді пайдаланады.

Таңдалған мөлдір орындау әсерлеріне дәлел ретінде қарау үшін [FastPQ](./fastpq.md) қараңыз. FastPQ қалыпты транзакция орындалуынан кейін орындау куәліктерін тұтынады және қолдау көрсетілетін күй ауысулары үшін детерминирленген дәлел топтарын құрады.

## Осы жұмыс ағынын Taira бойынша іске қосыңыз {#try-it-on-taira}

Соңғы жарияланған Taira блоктар мен транзакциялардың жағдайларын қолтаңба тіркелгісіз тексеру үшін шолушы маршруттарын пайдаланыңыз:

```bash
curl -fsS 'https://taira.sora.org/v1/explorer/blocks?page=1&per_page=3' \
  | jq '{pagination, blocks: [.items[] | {height, hash, transactions_total, transactions_rejected}]}'

curl -fsS 'https://taira.sora.org/v1/explorer/transactions?page=1&per_page=5' \
  | jq '{pagination, txs: [.items[] | {hash, block, status, executable}]}'
```

Алдыңғы кезде қосымшаңыз жіберген транзакцияны қадағалау үшін тізімнен `hash` көшіріп, эксплорердің толық бағытын тексеріңіз:

```bash
TX_HASH='<transaction-hash>'

curl -fsS "https://taira.sora.org/v1/explorer/transactions/$TX_HASH" \
  | jq '{hash, block, status, authority, executable}'
```

Бұл әлі де тек оқу үшін ғана. Транзакцияны жіберу үшін қол қоюлы Norito деректер контейнері, дұрыс тізбек идентификаторы, төлем метадеректері және тест желісімен қаржыландырылған Taira есептік жазба қажет.

Төлемақы төлейтін мысалдар үшін Taira бойынша, тест желісі қаржыландыру қызметінің көмекшісін [Taira сайтынан XOR тест желісін алыңыз](/kk/get-started/sora-nexus-dataspaces.md#_4-get-testnet-xor-on-taira)-ден `taira_faucet_claim.py` ретінде сақтаңыз, содан кейін криптографиялық қол қоюшыны алдымен қоғамдық тест желісі қаржыландыру қызметі арқылы қаржыландырыңыз:

```bash
export TAIRA_ACCOUNT_ID='<TAIRA_I105_ACCOUNT_ID>'
export TAIRA_FEE_ASSET=6TEAJqbb8oEPmLncoNiMRbLEK6tw

curl -fsS https://taira.sora.org/v1/accounts/faucet/puzzle | jq .
python3 taira_faucet_claim.py "$TAIRA_ACCOUNT_ID"

iroha --config ./taira.client.toml ledger asset get \
  --definition "$TAIRA_FEE_ASSET" \
  --account "$TAIRA_ACCOUNT_ID"
```

Егер testnet қаржыландыру қызметінің жұмбағы немесе талап ету маршруты `502` қайтарса, транзакцияны өзі жөндеуге кіріспей тұрып, күтіп, қайта әрекет жасаңыз.

Содан кейін транзакцияны жібергенде Taira төлем активінің метадеректерін тіркеңіз:

```bash
printf '{"gas_asset_id":"%s"}\n' "$TAIRA_FEE_ASSET" > taira.tx-metadata.json

iroha --config ./taira.client.toml \
  --metadata ./taira.tx-metadata.json \
  ledger transaction ping --msg "faucet-funded taira transaction"
```

## Офлайн транзакциялар {#offline-transactions}

Iroha екі офлайн транзакция жұмыс процестеріне ие:

- Офлайн қол қою құрылғысы қосылмаған кезде қалыпты қол қойылған транзакция жасайды. Транзакция онлайн клиент қол қойылған деректер контейнерін Torii жібермейінше өңделмейді, сондықтан әлі де дұрыс тізбектің идентификаторы, рұқсат беру уәкілетті субъект, рұқсаттар, төлемдер қажет. және транзакцияның өмір сүру ұзақтығы.
- Kagemusha офлайн ақша онлайн болған кезде әмиянға толтырады, екі әмиян да офлайн болғанда қабылдаушы бастамасымен әмияннан әмиянға ауыстыруларды қолдайды және қабылдаушы онлайнға оралған кезде нәтижесінде алынған ескертпе күйін пайдаланады.

Torii `/v1/offline/*` аясында Kagemusha толық өмірлік циклін көрсетеді:

|Әдіс және API ұш нүктесі|Мақсат|
| --- | --- |
| `GET /v1/offline/readiness` |Kagemusha-ның `asset_definition_id` үшін дайындығын бағалаңыз|
| `POST /v1/offline/receiver-lineage` |Қолтаңбаланған қабылдаушы сұранысы үшін дәлелді тіркелген белсенді тіркеу тізбегін шешу|
| `POST /v1/offline/top-up` |Қол қойылған онлайннан офлайнға толтыру операциясын жіберу|
| `POST /v1/offline/redeem` |Қол қою арқылы офлайн айырбастау операциясын жіберіңіз|
| `GET /v1/offline/operations/{operation_id}` |Толтыру немесе шығару жағдайының бір ғана протокол-стандартты күйін оқыңыз|

Офлайн операциясын құру алдында активтің дайын екенін тексеріңіз:

```bash
curl -fsS --get https://taira.sora.org/v1/offline/readiness \
  --data-urlencode 'asset_definition_id=<canonical_asset_definition_id>' \
  | jq '{ready, blockers, artifact_set}'
```

Дайындық әмиянды белсенді көпірге ABI 21 және расталған V4 артефакт жиынына байланыстырады. Топология, толықтыру және өтеу сұраныстары типтелген `application/x-norito` архивтерді пайдаланады. Толтыру және айырбастау қайтарымы `202 Accepted` `Location` тақырыбымен операция ресурсына бағытталған; кіріктірілген нөлден өзгеше операция идентификаторы идемпотенттік кілтін береді.

Қалыпты ағыны мынадай:

1. Сұрау дайындығын тексеріңіз және егер `ready` дұрыс болмаса немесе кез келген кедергіні қолданса, тоқтатыңыз.
2. Сингл протокол стандартты толықтыру архивін жасау үшін терілген Swift немесе JVM әмиянды пайдаланыңыз, оны жіберіңіз және операция соңғы тізбекті күйге жеткенге дейін енгізілген ескерту күйін және операция идентификаторын сақтаңыз.
3. Қажет болған жағдайда қабылдағышты тіркеу тізбегін шешіңіз, әр желілік әріптеске беруді жергілікті түрде құрыңыз және тексеріңіз, және тасымалдауды растаудан бұрын шифрланған ескертпе күйін сақтаңыз.
4. Алушы онлайн болған кезде, бір протокол стандартты қайта алу архивін құрыңыз, оны жіберіңіз және оның операциялық ресурсын соңына дейін бақылаңыз.

Блокчейн тізілімі онлайн өмірлік цикл арқылы жазба күйі қайтқанға дейін қарама-қарсы офлайн берілуін бақылай алмайды. Сол себепті әмиян мен оператор саясаты құн шектеулерін, жарамдылық мерзімін, қабылданған шығарушыларды, тұрақты жергілікті сақтау мен есеп айырысу терезелерін қолдануды қамтамасыз етуі тиіс.

Мұнда `Grant` нұсқаулығымен жаңа транзакция жасаудың мысалы берілген. Бұл транзакцияда Mouse Alice көрсетілген рөлді (`role_id`) беріп отыр. [толық мысал](./permissions.md#register-a-new-role)-ні тексеріңіз.

```rust
let grant_role = Grant::account_role(role_id, alice_id);
let grant_role_tx = TransactionBuilder::new(chain_id, mouse_id)
    .with_instructions([grant_role])
    .sign(mouse_private_key);
```
