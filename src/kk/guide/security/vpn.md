# Виртуалды Жеке Желілер {#virtual-private-networks}

<abbr title="Virtual Private Network">VPN</abbr> — бұл Iroha қызметтеріне кім кіре алатынын шектейтін желіні басқару құралы. Ол ең тиімді жеке және консорциумдық орналастыруларда, онда валидациялаушылар, қолданба серверлері және операторлар ашық интернет маршруттары арқылы емес, жеке мекенжайлар арқылы байланысуы қажет.

A VPN Iroha желілік әріптес кілттерін, есеп шот кілттерін, рұқсаттарды, брандмауэр ережелерін, мониторингті немесе қауіпсіз кілт сақтауын алмастыра алмайды. Оны бір қабат ретінде қарастырыңыз орнату шекарасы: VPN желіге қол жеткізуді тарылтады, ал Iroha конфигурациясы мен басқаруы қай желі әріптестері мен есептік жазбаларына сенуге болатынын шешеді.

## VPN қашан қолдану керек {#when-to-use-a-vpn}

Қолданған кезде VPN:

- валидаторларды әртүрлі ұйымдар немесе әртүрлі хостинг орталарында басқарады
- Torii тек қолданба серверлері, операторлар немесе сенімді клиенттер арқылы қолжетімді болуы керек
- метрикалар, журналдар, SSH немесе басқа әкімшілендіру API түйіндері жеке оператор желісінде қалуы қажет
- тестілеу немесе сахналық желі өндірістік кіру бақылауларына ұқсас болуы керек, бірақ қоғамдық API соңғы нүктелерді ашпау керек

Әрбір орналастыру үшін VPN қажет емес. Қоғамдық желілер әдейі Torii қоғамдық шлюз, жүктемені теңестіруші немесе кері прокси арқылы қолжетімді етуі мүмкін. Сол жағдайда да, валидатордың теңме-тең трафигін және әкімшілік API соңғы нүктелерін мүмкіндігінше шектеулі желіде ұстаңыз.

::: tip

Браузер VPN тек сол браузерден өтетін трафикті қорғайды. Ол `iroha3d`, CLI, SDK, SSH, метрикаларды немесе резервтік трафикті қорғамайды, егер сол процестер бірдей жеке желі арқылы бағытталмаса.

:::

## Орнату үлгісі {#deployment-pattern}

Жеке валидатор желісі үшін әр валидаторға тұрақты VPN мекенжайын немесе жеке DNS атауын беріңіз. Желідегі әріптестерді конфигурациялай отырып, олардың жарнамаланған тең-достарға арналған мекенжайлары басқа валидаторлардан сол желі арқылы қолжетімді болатындай етіп орнатыңыз:

```toml
trusted_peers = [
  "PUBLIC_KEY_1@10.20.0.11:1337",
  "PUBLIC_KEY_2@10.20.0.12:1337",
  "PUBLIC_KEY_3@10.20.0.13:1337",
  "PUBLIC_KEY_4@10.20.0.14:1337",
]

[network]
address = "10.20.0.11:1337"
public_address = "10.20.0.11:1337"

[torii]
address = "10.20.0.11:8080"
```

Ағымдағы желідегі серіктеске тағайындалған мекенжайды `network.address` және `network.public_address` қолдану. Әр желі серіктесі бірдей сенімді желі серіктесінің идентификаторларын көрсетуі керек, бірақ өзінің VPN маршрут кестесінен қол жетімді мекенжайлармен.

Клиент пен CLI конфигурациялары VPN арқылы немесе басқарылатын ішкі шлюз арқылы қолжетімді Torii API ұш нүктесіне нұсқауы керек:

```toml
torii_url = "http://10.20.0.11:8080"
```

Егер Torii VPN сыртында қол жетімді болуы керек болса, оны TLS, аутентификация, жылдамдықты шектеу және журнал жүргізуді қамтамасыз ететін кері прокси немесе жүктемені теңдестіргіштің артында орналастырыңыз. Шикі P2P порттарын немесе әкімшілік API нүктелерін тікелей қоғамдық интернетке ашудан аулақ болыңыз.

## Брандмауэр ережелері {#firewall-rules}

Қонақта және бұлттық брандмауэр ережелерін VPN болса да пайдаланыңыз:

|Қызмет|Ұсынылатын қол жеткізу|
| --- | --- |
|Теңдестірілген порт|Басқа валидатор VPN тек осыған арналған|
| Torii |Қосымша тіректерінің артқы бөліктері, операторлар немесе сенімді клиент VPN ауқымдары|
|Метрикалар және денсаулық жағдайын тексеру|Оператор желісіндегі бақылау жүйелері|
| SSH және әкімшілік |Бастион хосты, артықшылықты оператор VPN ауқымы, немесе апаттық кіру процесі|
|Сақтық көшірмелер және сақтау репликациясы|Жеке желідегі резервтік жүйелер|

Әдепкі бойынша тыйым салу ережелерін кең ауқымды рұқсат ережелеріне қарағанда тексеру жеңілірек. Жаңа желі серігі желіге қосылғанда, VPN мүшелік, брандмауэр рұқсат тізімі және Iroha сенімді желі серіктері конфигурациясын бірлескен өзгеріс ретінде жаңартыңыз.

## Операциялық тексеру тізімі {#operational-checklist}

- Тексерілген және белсенді түрде қолдау көрсетілетін VPN іске асыруын таңдаңыз, мысалы, WireGuard, IPsec немесе ұйым бекіткен басқарылатын жекеменшік желі.
- Әрбір хост және оператор үшін бірегей VPN тіркелгі деректерін пайдаланыңыз. VPN кілттерін валидаторлар арасында бөліспеңіз.
- VPN тіркелгі деректерін Iroha жеке кілттерінен және блокчейн бастау материалынан бөлек сақтаңыз.
- Кешігу уақытын, пакеттік жоғалтуларды, қайта қосылуларды және маршрут өзгерістерін бақылаңыз VPN. Консенсус тұрақты желі мәселелеріне сезімтал.
- Тиімді MTU-ді тексеріңіз. Пакетті бөлу кейде желідегі әріптес немесе Torii ақаулар сияқты көрінуі мүмкін.
- Құжат, онда VPN диапазонының peer-to-peer, Torii, метрикалар, SSH, және резервтік API нүктелерге жетуге рұқсаты бар екені көрсетілген.
- Желіден шыққан хост, оператор аккаунты немесе ұйым үшін VPN тіркелгі деректерін ауыстырыңыз.
- Валидаторлар арасындағы жалғыз VPN өткелді жалғыз маршрут ретінде пайдаланудан аулақ болыңыз. Өндірістік желілер үшін артық өткелдер немесе сайттар арасындағы маршруттарды жоспарлаңыз.
- Операторларға желі бөлу мен Iroha процессінің сәтсіздігін ажырата білетінін білу үшін инцидентке жауап беру жаттығуларына VPN сәтсіздіктерін қосыңыз.
