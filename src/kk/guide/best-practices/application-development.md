# Қолданбаларды әзірлеу {#application-development}

Iroha қосымшалары транзакция мінез-құлқын айқын етіп, қолтаңбалау күйін сақтап қалуы және сұраулар мен оқиғаларды өндірісте байқауға оңай тәсілмен пайдалануы керек.

## Клиентті орнату {#client-setup}

- Клиенттің конфигурациясын қолданбаның бастапқы кодынан тыс сақтау. ID, Torii URL тізбектерін, қолтаңбалау тіркелгісін және мәміле параметрлерін қоршаған ортаға байланысты баптаудан жүктеңіз.
- Localnet, Taira, Minamoto және жеке желілер үшін `client.toml` файлдарды бөлек сақтаңыз.
- Транзакция уақытын және мәртебелі уақыттарды қасақана орнату. Өте қысқа өмір сүру мерзімі қалыпты желідегі ырғақ кезінде аяқталуы мүмкін, ал өте ұзақ мерзім қайталанбаған ұсыныстарды дәлелдеуді қиындата алады.
- `nonce = true` қайталанған транзакциялардың әртүрлі хештары болуы тиіс кезде ғана қолданылады. Идемпотентті бизнес операциялары үшін қосымша сұрау салуды сақтау және қайта пайдалану ID, сондықтан қайтадан жасалатын сынақтарды қадағалауға болады.

Ағымдағы TOML өрістер үшін [Клиент конфигурациясы](/kk/guide/configure/client-configuration.md) дегенді қараңыз.

## Транзакциялар {#transactions}

- Мүмкіндігінше шикі JSON немесе жіппен жинақталған пайдалы жүктемелер орнына SDK түрленген нұсқаулықтардан операцияларды жасау.
- Preflight маңызды тек оқуға арналған сұраулармен жазады: шоттың бар болуы, активтердің балансы, рұқсат ету жағдайы, алым активтерінің қолжетімділігі және мақсатты нысанның жағдайы.
- Тапсырманы тапсырудан бұрын транзакция хэшін, уәкілеттілік тіркелгісін, нұсқаулардың жиынтығын және күтiлетiн жай-күй өзгерiсiн жазыңыз.
- `Rejected`, `Expired`, және уақыт үзіліс нәтижелері әртүрлі. Уақыт үзіліс клиенттің түпкілікті мәртебесін сақтамағандығын білдіреді; бұл желі транзакцияны елемегенін дәлелдемейді.
- Жазудың сәтті аяқталғаннан кейін, нәтижелі жағдайды бизнес-операцияға сәйкес келетін сұрау салу немесе оқиға бақылау нүктесімен тексеріңіз.

Транзакция механикасы үшін [Транзакциялар ](/kk/blockchain/transactions.md) дегенді қараңыз.

## Сұрақтар мен оқиғалар {#queries-and-events}

- Өзгерістер туралы хабарламалар үшін ағымдағы жай-күй және оқиға ағындары бойынша сұрауларды пайдаланыңыз.
- Тіркелгі, актив және блок тізімдері сияқты кең қайталанатын сұрауларды баптаңыз.
- Абоненттер мен триггерлер үшін тар сүзгілерді артық көреміз. Кең сүзгілер диагностикаға пайдалы, бірақ қажетсіз орындау және клиент тарапынан өңдеуді қоса алады.
- Тек оқуға арналған түтінді тексерулерді қол қойылған транзакциялық тестілерден бөлек ұстаңыз, сондықтан соңғы нүктелердің болуы диагностикалау оңай болады.

Қараңыз [Сұрақтар](/kk/blockchain/queries.md), [Оқиғалар](/kk/blockchain/events.md) және [Фильтерлер](/kk/blockchain/filters.md).

## Агенттік көмегімен даму {#agent-assisted-development}

- Агенттерден транзакция кодын жазуды сұрамас бұрын құжаттарын, SDK кодты және тек оқуға арналған желілік жағдайды тексерсін.
- Тікелей желілік тестілеулерді `TAIRA_LIVE=1` сияқты қоршаған орта байрағының артында өткізуге рұқсат етіңіз.
- Жеке кілттерді, шоттарды қалпына келтіру материалдарын, API токендерін немесе жіберілген авторлық атауларды сұрау салуларға орналастыруға болмайды.
- Кез келген агенттің тікелей тест-нет транзакциясын тапсыру алдында транзакциялық жоспарды талап ету.

Бұл үшін Taira MCP жұмыс барысы, қараңыз [Бастану SORA 3: Taira және Minamoto](/kk/get-started/sora-nexus-dataspaces.md#taira-mcp-for-agents).

## SDK Гигиена {#sdk-hygiene}

- Пин SDK және бинарлық нұсқалар [ үйлесімділік матрицасын пайдалана отырып, бірге ](/kk/reference/compatibility-matrix.md).
- Келтірілген клиент коды, үзінділері мен мысалдарды алдыңғы қатардағы жұмыс кеңістігін тексерумен синхрондаңыз.
- Транзакция жасау коды мен интеграциялық тесттер үшін бірлік сынақтарды қосу сіздің қолданбаңыздың ең кішкентай оқу-жазу жолдары үшін байланысты.
