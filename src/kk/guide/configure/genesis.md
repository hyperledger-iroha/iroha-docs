## Файлдар {#files}

Негізгі репозиторий әдепкі бастапқы үлгіні `defaults/genesis.template.json` ішінде береді. Үлгі толық емес: `kagami genesis materialize` оны манифестке айналдырғанша оны тексеруге, оған қол қоюға немесе түйінде пайдалануға болмайды. Kagami жасаған желілер өз манифесті мен қол қойылған транзакциясын шығыс каталогына жазады:

```bash
cargo run --bin kagami -- localnet generate --peers 4 --out-dir ./localnet
```

Сол каталогта жасалған `README.md` таңдалған профиль үшін нақты файлдар мен іске қосу командаларын тіркейді.

## торап әріптесін баптау {#peer-configuration}

Тораптар `config.toml` файлының `[genesis]` бөлімінде қол қойылған генезис транзакциясын көрсетіп, оның күтілетін хэшін бөлек файлда бекітеді:

```toml
[genesis]
file = "./genesis.signed.nrt"
public_key = "ed0120..."
expected_hash_file = "./genesis.expected_hash"
```

Желідегі барлық торапта қол қойылған генезис транзакциясы мен генезис ашық кілті бірдей болуы тиіс. Күтілетін хэш файлы алғаш іске қосқанда да, қайта іске қосқанда да қажет; оны `kagami genesis sign --expected-hash-out` жазады.

## Блокчейн генерациясын қол қою {#signing-genesis}

Егер сіз техникалық манифесті қолмен өңдесеңіз, желі серіктестерін бастамас бұрын оны тексеріп, қол қойыңыз:

```bash
cargo run --bin kagami -- genesis validate ./genesis.json
cargo run --bin kagami -- genesis sign ./genesis.json \
  --private-key-file "$GENESIS_PRIVATE_KEY_FILE" \
  --out-file ./genesis.signed.nrt \
  --expected-hash-out ./genesis.expected_hash
```

`GENESIS_PRIVATE_KEY_FILE` иеленуші ұстаған режим-`0600`, бір ғана протокол стандартты жеке кілт мультихешін және соңғы жаңа жолды қамтитын бір сілтемелі тұрақты файл болуы керек. Kagami символдық сілтемелерді қабылдамайды және командалық жолда ешқашан таза блокчейн генезис жеке кілтін қабылдамайды.

NPoS не SORA Nexus профильдері үшін жасалған профиль талап ететін топологияны және BLS иелік дәлелдерін қосыңыз. Kagami құралындағы `localnet generate`, `wizard` және `sora-network generate` пәрмендері мұны автоматты түрде орындайды.

## Блокчейннің бастамасын қайта міндеттеу {#recommitting-genesis}

Жаңа желі өзінің қолтаңбамен бекітілген бастапқы блогынан іске қосылады. Уақытша жергілікті желіде басқа бастапқы блокты сынау үшін құрдас тораптарды тоқтатып, олардың жасалған күй каталогын жойыңыз да, жаңа қолтаңбалы бастапқы блокпен іске қосыңыз. Жұмыс істеп тұрған желі бастапқы блокты ауыстыруды жаңарту тетігі ретінде ешқашан қолданбауы тиіс. Хаттама анықтамаларының өзгерістері басқару арқылы бекітілетін таңдау ауысуларын және таңдалған анықтамалар мен міндеттемелерге қатысты біліктілік тексерулерін талап етеді.
