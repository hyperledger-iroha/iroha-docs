# Желіні енгізу кілттері {#keys-for-network-deployment}

Әрбір желіде клиенттер, желі әріптестері, блокчейннің бастау жазбасын қол қою және NPoS немесе Nexus профильдері үшін BLS валидатор сәйкестендірулері сияқты әртүрлі кілт материалдары қажет.

## Пернетақтаны қашан қолданады {#where-keys-are-used}

- Клиенттің қолтаңба кілттері `[account]` астында `client.toml` ішінде сақталады.
- Желі әріптесі идентификатор кілттері әрбір желі әріптесінде `config.toml` ретінде `public_key` және `private_key` сақталады.
- желілік тең құрылымдарды анықтау әр желілік тең құрылымның `trusted_peers` ішіндегі ашық кілтін пайдаланады.
- BLS тексерушінің Possession-дәлелдері NPoS профильдері үшін `trusted_peers_pop` сақталады.
- Генезиске қол қою кезінде желі түйінінің конфигурациясындағы `[genesis].public_key` және манифестке қол қоятын сәйкес жеке кілт пайдаланылады.

Жергілікті немесе тестілік орналастырулар үшін Kagami барлық осы файлдарды бірге жасауы керек:

```bash
cargo run --bin kagami -- localnet --peers 4 --out-dir ./localnet
```

Бар желі немесе профиль үшін нұсқаулық ағынын пайдаланыңыз:

```bash
cargo run --bin kagami -- wizard
```

## Жеке кілт жұптарын жасау {#generate-individual-key-pairs}

Тәуелсіз кілт материалы үшін `kagami keys` пайдаланыңыз:

```bash
cargo run --bin kagami -- keys --algorithm ed25519 \
  --out-dir ./client-key
```

BLS валидатор материалы үшін, Меншіктеу дәлелін қосыңыз:

```bash
cargo run --bin kagami -- keys --algorithm bls_normal --pop \
  --out-dir ./validator-key
```

Қайта өндіруге болатын әзірлеу сынақ деректерін жасау үшін `--seed-hex` параметрін дәл 32 байттық он алтылық құпиямен ғана пайдаланыңыз. Өндірістік орналастыруда оны алып тастаңыз: сонда Kagami операциялық жүйенің кездейсоқтық көзін пайдаланады. Одан кейін шифрланбаған жеке кілт экспортын бекітілген сақтау шекарасына көшіріңіз. Команда жеке кілттерді ешқашан басып шығармайды.

## желілік әріптестік сәйкестік {#peer-consistency}

Барлық валидаторлар бірдей блокчейннің алғашқы транзакциясына, топологиясына, сенімді желілік серіктестердің ашық кілттеріне және валидаторға PoPs келісуі қажет. Бір ғана жетіспейтін немесе сәйкес келмейтін желілік серіктес кілті желінің басталуына немесе консенсусқа жетуіне кедергі болуы мүмкін.

Минималды Византиялық ақауға төзімді орналастыру үшін ең аз дегенде төрт желілік әріптесті қолданыңыз. Әрбір желілік әріптестің өзінің жеке кілті болуы керек, бірақ әрбір желілік әріптестің конфигурациясында бірдей сенімді желілік әріптестер жиынтығы болуы қажет.

## Клиент шоттары {#client-accounts}

`client.toml` ішіндегі клиенттік шот енді блок тізбегінде болуы керек. Ол блокчейннің генезис техникалық манифесті арқылы немесе кейінгі транзакция арқылы тіркелуі мүмкін. Блокчейннің генезис қол қою идентификаторын ұзақ мерзімді қолданба есептік жазбасы ретінде пайдаланбаңыз; блокчейн генезис артықшылықтары тек блокчейн генезис кезеңінде ғана қолданылады, ал өндірістік клиенттер өздерінің есептік жазбаларын және рольдерін пайдалануы керек.
