# Torii Аяқ нүктелері {#torii-endpoints}

Torii болып табылады HTTP, SSE, және WebSocket кіреберісі Iroha 3. Бұл кітапшаға қарасты екіге тең қызмет етеді APIs және оператордың соңғы нүктелері.

Қолданыстағы хаттама ережелері:

- каноникалық бинарлық форматы Norito
- JSON жіберу кезінде көптеген соңғы нүктелер `Accept: application/json` қолдауын көрсетеді.
- өлшемі Prometheus форматында көрсетіледі

Форматтың егжей-тегжейі, мазмұн келіссөздері, орналасу таңбалары, схема хашилері және Norito RPC нұсқаулығы үшін [Norito сілтемесін қараңыз ](/kk/reference/norito.md).

## Ортақ мақсаттар {#common-endpoints}

|Қорытындысы |Форматтау |Мақсаты |
| ------------------------------------- | -------------- | ---------------------------------------------------------------- |
|`POST /v1/pipeline/transactions` |Norito |Қолтаңбаланған операцияны тапсыру |
|`POST /v1/query` |Norito |Қолтаңбаланған сұрау салуды жіберу |
|`GET /v1/events/ws` |WebSocket |Іс-шараға жазылу |
|`GET /v1/events/sse` |SSE |SSE бойынша оқиғалар ағынына жазылыңыз |
|`GET /v1/blocks/stream` |WebSocket |Ағынды қосылған блоктар |
|`GET /v1/peers` |JSON |Torii бойынша шығарылған әріптестер тізімі |
|`GET /livez` |Мәтін |Тек процестермен қамтамасыз етілуі; бұл протоколға дайын болуды білдірмейді |
|`GET /readyz` |JSON |Оффлайн қолма-қол ақшаны тексеруді қоса алғанда, түйіндердің толық дайындығы |
|`GET /health` |JSON |Дайындық சோндасы бірдей офлайн қолма-қол ақша инвариантпен |
|`GET /v1/api/version` |Мәтін |Блок басының ағымдағы нұсқасы |
|`GET /status` |Norito немесе JSON |Жоғары деңгейдегі диагностикалық жағдай; JSON айқын сұрау салу |
|`GET /metrics` |Прометей |Prometheus кесу аяқ нүктесі |
|`GET /v1/schema` |JSON |Белгіленген кезде түйін қызмет ететін дерек үлгі схемасы сұлбасын кескіндеу |
|`GET /openapi` немесе `GET /openapi.json` |JSON |OpenAPI активті Torii HTTP бағыттары үшін құжат |
|`GET /v1/parameters` |JSON |Нод параметрінің кескіндемесі |
|`GET /v1/node/capabilities` |JSON |Нодтың қабілеті және деректер үлгісінің метамәдени деректері |
|`GET /v1/time/now` |JSON |Бүйірдің қабырғалық сағатын кескін түсіру |
|`GET /v1/time/status` |JSON |Уақыт синхрондалу жағдайы |

SSE сұранысы үшін түпкiлiктi ағынды және түрленген қайтуды жарнамалаңыз:

```http
Accept: text/event-stream, application/json
```

Torii алдымен сұраныс қабатында JSON немесе Norito бейнелеуді келіседі, содан кейін түпкілікті `text/event-stream` жауапты бекітеді. Сондықтан тек `text/event-stream` жіберу `406` арқылы қабылданбайды; [ ағымдық оқиғалар рецепті](/kk/cookbook/stream-events.md) толық бағанды пайдаланады.

`/openapi` схемада көрсетілген маршруттар үшін негізгі жасалған келісімшарт, Ағымдағы құжатта толық операциялық зондтар тізілімі жоқ. `/livez` және `/readyz`, және оның `/health` сипаттама дайындық менеджерін артта қалдыра алады. Тікелей құжаттан маршрут клиенттерін құру, Бірақ тірілік пен дайындықты тікелей жұмыс істеп тұрған түйінге және тығылған басқарушыларға қарсы растаңыз. Дұрыс бет әлі де құрылыстың ерекшеліктері мен жұмыс уақытын конфигурациясына байланысты. [Torii API консоль](/kk/reference/torii-api-console.md) тіршілік ететін құжатты жүктеу үшін тест JSON жолдар, көшірме curl өтiнiштер, және ағымдағы схемадан клиент кодын тудыру.

## Тікелей Taira жолдарын сынап көріңіз {#try-live-taira-routes}

Қоғамдық Taira тестілеу желісі қолданба клиенттері тек оқуға арналған барлау үшін пайдаланатын бірдей Torii JSON бетін көрсетеді. Бұл командаларға кілттер қажет емес:

```bash
TAIRA_ROOT=https://taira.sora.org

curl -fsS -H 'Accept: application/json' "$TAIRA_ROOT/status" \
  | jq '{blocks, txs_approved, txs_rejected, queue_size, peers}'

curl -fsS "$TAIRA_ROOT/openapi.json" \
  | jq -r '.paths | keys[]' \
  | grep '^/v1/' \
  | head -n 20

curl -fsS -H 'Accept: application/json' \
  "$TAIRA_ROOT/v1/node/capabilities" \
  | jq '{abi_version, data_model_version, query: .query.aggregate.supported_resources}'
```

Қазіргі әлемдегі жағдайға қатысты ресурс оқиды:

```bash
curl -fsS "$TAIRA_ROOT/v1/domains?limit=5" \
  | jq -r '.items[].id'

curl -fsS "$TAIRA_ROOT/v1/assets/definitions?limit=5" \
  | jq -r '.items[] | [.id, .name, .total_quantity] | @tsv'
```

Егер қоғамдық тестілеу желісі жолы `502`, уақыт шығып, немесе толы кезек туралы хабарласа, оны аяқтық нүктелердің қолжетімділігі мәселесі ретінде қараңыз және клиент кодыңызды ақаусыздандырудан бұрын кейін қайталап көріңіз.

## App және SORA маршрут отбасылары {#app-and-sora-route-families}

Torii қосымшаға қарасты мүмкіндіктер жиынтығымен құрылған кезде, ол зерттеушілер үшін қосымша JSON отбасыларын, SORA қызметтерін, көпір ағындарын, дәлелдемелерді және сақтауды ашады. Бұл отбасылардың барлығы да әрбір желі профиліне қосылмаған.

`/openapi` құрылған app-API каталогында тіркелген бағыттарды сипаттайды; ол құрамында орналасқан жазулар үшін емес, орнатылған барлық маршруттар үшін заңды болып табылады Атап айтқанда, қоғамдық жергілікті SoraFS CID және белгілі бағыттар осы шығарылған құжаттың сыртында орнатылған және тікелей тексерілуі тиіс.

| ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |

## Тіркелгі аутентификациясы, көрінетіндігі және Explorer cursors {#account-authentication-visibility-and-explorer-cursors}

### Қолданба тіркелгісі туралы сұрау салу хаттамасы {#app-account-request-protocol}

Қолданбаға қарасты маршруттарда аутентификация бағандары жоқ, бір тікелей бір кілтілік дәлелдеме немесе бір көп белгілі куәлікті қабылдауға болады.

Тікелей дәлелдеу үшін төрт тақырыпты бірге жіберіңіз:

- `X-Iroha-Account`: нақты каноникалық кіші әріпті `0x` шоттың мекенжайы шешесі немесе белсенді каноникалық ASCII есептің аты-жөні. I105 мәтіні HTTP өрісінің мәні ретінде қауіпсіз емес; сол шот үшін каноникалық шеше орфографиясын қолданыңыз.
- `X-Iroha-Signature`: қатаң таңбаланған Base64 қолтаңбалық жүк.
- `X-Iroha-Timestamp-Ms`: конфигурацияланған бұрмалау терезесінде миллисекундтардағы каноникалық қолтаңбаланбаған ондық Unix уақыт маркасы.
- `X-Iroha-Nonce`: 1 - 256 басып шығарылатын ASCII байт (`0x21`-ден `0x7e`-ге дейін), қайта ойнау терезесінде бірегей.

Тіркелген бір кілтілік контроллер дәл осы байттерге қол қояды:

```text
iroha.app.request.network.v1\0 || <genesis-derived network_id[32]> ||
<UPPERCASE_METHOD>\n
<exact request path>\n
<canonical query>\n
<lowercase hex SHA-256 of the raw body>\n
<canonical timestamp_ms>\n
<nonce>
```

Каноникалық сұрау салу құрылымы шикі сұранысты `application/x-www-form-urlencoded` ретінде зерттейді (`+` кеңістікті білдіреді), оның жұптарын пайыздық кодтайды, оларды `(key, value)` бойынша сұрыптайды және нысанды қайта кодтайды. Протокол ең көп дегенде 64 декодталған жұп пен 64 KiB шикі сұраныс мәтінін қабылдайды. Дене байттарын дәл жіберілгендей меңгеріңіз. Тұрақты 32-байттік желі ID мен үлкен әріп әдісі арасында бөлгіш кірмеңіз.

V1 тексерушісі сондай-ақ әдіс белгісін 32 байтқа, пайыздық кодталған сұрау салу жолын 64 KiB деп шектейді. және талдаудан бұрын 36 KiB нөмірінде тікелей шоттың сәйкестігі. Тіркелiк атаулары үш атау сегменттерiнiң және олардың бөлiгiштерiнiнгi қатаң құрылымдық шегiне ие. Тақырыбынан асып кету қолтаңбаларды тексеруден немесе бастапқы өлшемімен бөлінуден бұрын куәландыруда сәтсіздік туғызады.

Мултисиг контроллері керісінше жіберу керек `X-Iroha-Witness` қатаң толтырылған-база64 каноникалық ретінде Norito және қалдыру `X-Iroha-Signature`, `X-Iroha-Timestamp-Ms`, және `X-Iroha-Nonce`. `X-Iroha-Account` осы нысанда ерікті болып табылады; ол болған кезде куәгерге тең болуы тиіс `subject_account`. Қауымдастық `CanonicalRequestWitnessV1` қамтыған `schema_version`, `subject_account`, `timestamp_ms`, `nonce`, бір Iroha `Hash` нақты желісі сұранысы байттар арқылы дене терісінен, бірақ Жаңалық өрістері, және ең көп 64 мүшелердің қолтаңбалары. Norito Қолтаңбалар массивінсіз дәл сол пайдалы жүктемені кодтау. Құжатталған куәліктің шегі 1 болып белгіленеді. MiB.

Аутентификация бағандарын ұсынбау анонимдік қолжетімділікті таңдайды. Кез келген ішінара, аралас, қайталанатын, бұзылған, ескірген немесе қайта ойналған дәлелді беру аутентификацияны сәтсіз етеді; ол ешқашан анонимдік көрінетіндігіне қайтып келеді.

### Оператордың сұрау салу хаттамасы {#operator-request-protocol}

Оператор куәландырған деп белгіленген бағыттар үшін төрт жеке бағанды қажет етеді:

- `x-iroha-operator-public-key`: каноникалық Iroha көпқашықтықтан ашық кілт.
- `x-iroha-operator-timestamp-ms`: каноникалық қолтаңбаланбаған ондық Unix уақыт таңбасы миллисекундта.
- `x-iroha-operator-nonce`: 1 - 256 басып шығарылатын ASCII байт, қайта ойнау терезесіндегі кілті үшін бірегей.
- `x-iroha-operator-signature`: қатаң таңбаланған Base64 қолтаңбалық жүк.

Бапша мәндері қоршаған ақ кеңістікті қамтуы тиіс емес. Оператордың негізгі белгілері:

```text
iroha.operator.http-request.network.v1\0 || <genesis-derived network_id[32]> ||
<UPPERCASE_METHOD>\n
<exact request path>\n
<canonical query>\n
<lowercase hex SHA-256 of the raw body>\n
<canonical timestamp_ms>\n
<nonce>
```

Жол, сұраныс, дене, уақыт мөрі және нонс ережелері - бұл қосымша протоколында қолданылатын бірдей каноникалық ережелер. Кілтті сондай-ақ `[torii.operator_signatures]`: тізімдесін `allowed_public_keys`, немесе айрықша рұқсат ету `allow_node_key` Node кілтін пайдаланғанда. Қайта ойнау кеші толы болған кезде, Torii өтiнiшiне қарсы `503 Service Unavailable`. Міндетті WebAuthn немесе mTLS операторының аутентификациясы қосымша фактор болып табылады және бұл нақты өтініштің қолтаңбасын ешқашан ауыстыруға болмайды.

ISO 20022 маршруттары екі тәуелсіз тексеруді жүзеге асырады. Сұраныс алдымен осы оператордың рұқсаттар тізімін және қолтаңбалау протоколын тапсыруы керек; ISO басқарушы төмендегі нақты қатысушы немесе аудит рөлін атқару үшін сол кілтті талап етеді.

### Леджердің көрінетіндігі және Explorer cursors {#ledger-visibility-and-explorer-cursors}

Қолданбаға қарасты бас кітапшаны оқу жоғарыдағы таңдаулы қосымша тіркелгі шегін пайдаланады. қолтаңбаланбаған сұрау салу тек ашық деп конфигурацияланған деректер қорын алады. жарамды қол қойылған сұрау салу қосылады шақырушының ағымдағы UAID жүйесіне байланысты деректер кеңістіктері, әрқайсысы нақты `CanReadRestrictedDataspace { dataspace }` рұқсатымен аталатын шектелген деректер кеңістігі немесе шотта `CanReadAllLedgerData` бар барлық бағыттар.

Бірдей көрінетін нысанды сүзгілер тіркелгі, домен, актив-дефинициясы, актив, NFT, RWA, ұстаушы және Explorer оқылады. Транзакция үшін тіркелген әрбір бағыт аяғы көрінетін кезде ғана жасалған транзакциялар мен нұсқаулар тарихы көрсетіледі. Сондықтан, тіпті бір қатысушының аяғы шақырушыдан тыс жерде болған кезде жасырылады; жоғалған, ескірген немесе бұзылып кеткен маршруттық контекст тек жаһандық оқырман үшін ғана көрінеді.

Дүниежүзілік қолдау тапқан алты Explorer коллекциялары мөлдір емес каноникалық base64url кілттер жиынтығының курсорларын пайдаланады. Әдеттегі бетінің шегі - 25, ең жоғарысы - 100, ал бір бетте ең көп дегенде 512 кандидат кілттерді тексереді. Әрбір курсор өзінің жинағы, сүзгілері, каноникалық соңғы кілті және шақырушының көрінетін маршрут белгісімен байланысты, сондықтан ол басқа сұрау салуда немесе шақырушының көзқарасы өзгергеннен кейін қайта ойнатылмауы мүмкін.

Блок, транзакция, соңғы транзакциялар, нұсқаулар және соңғы нұсқаулардың тарихы курсорлар сондай-ақ тапсырылған слайдтың биіктігін белгілейді және хешты бөледі. Жауаптар ашық `pagination.limit`, `pagination.snapshot_height`, `pagination.snapshot_hash`, `pagination.next_cursor`, және `pagination.has_more`. Torii басқа маршрут немесе сүзгі жиынтығы үшін курсорды қабылдамайды, көріністі өзгерткен дигесті; немесе түйіннің бұдан былай растай алмайтын шұғыл кескін. Torii Блокіруші жұмысшы жүгіріп бара жатқан кезде сұрау салуға рұқсат беру.

Эксплорер WebSocket ағымдар сүзгіленген қорытындыларды шығарады және кітапша рұқсаттары өзгерген сайын көріністі қайта есептеу. `GET /v1/blocks/stream` жол басқаша: ол толық қолтаңбаланған блоктарды шығарады, талап етеді `CanReadAllLedgerData` қол тигізу кезінде және егер бұл рұқсат кейіннен кері қайтарып алынса, жабылады. Деректер кеңістігін зерттейтін зерттеуші үшін түпкүлдік ағынды қолданбаңыз.

## ISO 20022 Көпір {#iso-20022-bridge}

Torii ISO 20022 көпірін `/v1/iso20022/*` астына шығарады, егер қолданбаға бағдарланған API және көпірдің жұмыс істеу уақыты рұқсат етілсе. Көпір мақсатты түрде: ол жалпы мақсаттағы ISO 20022 клиринг шлюзі емес, таңдалған төлем хабарламаларын қол қойылған Iroha аударымдарға айналдыру және олардың бухгалтерлік кітапшасының жай-күйін бақылау үшін қолданатын кіші жиынтық.

Кез келген тапсыруды қабылдамас бұрын тұрақты жергілікті `torii.iso_bridge.store_dir` баптау. Конфигурация өрісі тек оқуға ғана немесе диагностикалық пайдалануға бастау үшін ғана ерікті: әрбір куәландырылған ISO тапсырысы каталогты қажет етеді және қайтарылуы мүмкін `503 Service Unavailable` қайтарады, егер тұрақтылық жоқ болса немесе реплей-мазар ташы не бай жазба жазуы сәтсіздікке ұшыраса.

`pacs.008` ұсыныстар хабарламаны беруі тиіс ID, Банкаралық есеп айырысу сомасы, валюта, есеп айырысу күні, борышкер мен кредитор IBANs, және борышкер мен кредитор BICs. Анықтама деректерін баптау кезінде көпір сондай-ақ BIC, IBAN, және ISO Алынған транзакция құбыр желісіне енгенге дейін 4217 валюталық өтпе.

`pacs.009` ұсыныстарда бизнес хабарламасы ID, хабарламаның анықтамасы ID, құрылу уақыты, банктер арасындағы есеп айырысу сомасы, валюта, есеп айырысу күні көрсетілуі тиіс. тапсырма беру және тапсыру агенті BICs, ал борышкер мен кредитор IBANs. Егер хабарламада `Purp` бар болса, көпір қазіргі уақытта тек бағалы қағаздар мақсатында қаржыландыруды қабылдайды: `Purp=SECU`.

Қауымдастық `pacs.008` және `pacs.009` тапсырудың соңғы нүктелері қабылданды XML ISO көпірлік сынақтарда қолданылатын конверттер немесе тегіс дала форматы. `SplmtryData` өрістер нысананы тіркей алады Iroha бухгалтерлік есеп, көз және нысаналы шот IDs немесе мекен-жайлар және активтердің анықтамасы ID. Жауап: `202 Accepted` қосылған `message_id`, `transaction_hash`, `status`, `pacs002_code`, және шешілген бухгалтерлік есеп/есеп/актив контекстi.

### Қатысушылардың рұқсаты және өмірлік циклдің иелігі {#participant-authorization-and-lifecycle-ownership}

Әрбір рұқсат етілген көпірде қатысушылардың каталогы бар. Әр қатысушыға ID бірегей қатысушы, бір немесе бірнеше оператордың қоғамдық кілттері, бір немесе одан көп қаржылық идентификаторлар, рұқсат етілген профиль жиынтығы және `originator`, `counterparty` немесе екі рөлдері болады. Оператор кілттері мен қаржылық идентификаторлар бірден көп қатысушыға тиесілі бола алмайды. `audit_admin_keys` жеке баптау; аудиторлық әкімші кілті де қатысушының мутация кілті болуы мүмкін емес.

Барлығы ISO жолдарға жаңа оператордың қолтаңбасы қажет. `pacs.008`, `pacs.009`, `sese.023`, немесе `colr.012` тапсыру, куәландырылған оператор өтінім басында көрсетілген қатысушыға тиесілі болуы тиіс `From` Қаржылық сәйкестік. `To` сәйкестігін конфигурацияланған қатысушыға шешу керек `counterparty` Ұзақ мерзімді қабылдау деректері бастаушы, контрагент; қатысушы мен оператор кілтін қабылдау, сондай-ақ түпнұсқа профилі және кіріктірілген қолтаңба саясаты.

Өмірлік циклінің рұқсаты шақырушының таңдап алған мәндерінен емес, осы өзгермейтін жазбадан алынған:

|Өмірлік цикл туралы хабар |Қажетті қатысушы |
| ---------------------------------------------- | -------------------------------------------------- |
|`pacs.002`, `pacs.004`, `sese.024`, `sese.025` |`counterparty` рөлін атқаратын бастапқы контрагент |
|`camt.056` |`originator` рөлін атқаратын түпнұсқа авторы |

Бастапқы профиль және қолтаңба саясаты барлық үшін бекітіледі өмірлік цикл, сондықтан шақырушы жаңарту үшін әлсіз профильді таңдай алмайды. `pacs.002` есеп айырысуды білдіретін код (`ACSC`, `ACCP`, `SETT`, немесе `SETTLED`) бастапқы тіркелімді есептелгенге тек қана Torii транзакция дәлелдемесін жасады.

Бастапқы тараптың әрқайсысы өзінің хабарламалар жазбасын және шығарылған аутбокс құжаттарын оқи алады. Аудит соңғы нүктесі тек куәландырылған қатысушы автор немесе қарсы тұлға болып табылатын жазбаларды қайтарады. Ерекше конфигурацияланған аудит әкімшісі жалпы тек оқуға арналған аудит көрінісін алады және хабарламаны тапсыра алмайды немесе өзгерте алмайды. Белгісіз қатысушылар мен байланысты емес хабарламалар идентификаторы ашылмайды.

### Тұрақты қайта ойнау идентификациясы және қолтаңбаланған аутбокс құжаттары {#durable-replay-identity-and-signed-outbox-documents}

Torii оқуға жарамсыз, тым үлкен, бұзылған, дұрыс аталмаған, қайшылықты немесе айқын сәйкес келмейтін қабырға ташы үшін стартап жасайды. Ол сондай-ақ нақты сәйкес келмейтін схема нұсқасы, қатысушы, профиль немесе қолтаңба саясаты жоқ қазіргі конфигурация, немесе жоғалған немесе сәйкессіз тірі қабір ташы бар бай жазба үшін abortes.

Басқа бай жазбалардың зақымданулары әртүрлі түрде жүргізіледі: оқуға келмейтін немесе үлкен файлдар, жарамсыз JSON, жарамсыз ағымдағы схемалар деректері, каноникалық емес файл атаулары және қайшылықты қайталау сәйкестіктер тіркеледі немесе өткізіледі. Оқуға келмейтін немесе жарамсыз ағымдағы нұсқа аудит индексі сақталған жазбалардан қалпына келтіріледі; тек айқын сәйкессіз аудит индексінің нұсқасы іске қосуды тоқтата тұрады. Бастапқы журналды бақылау және әрбір бұзылған бай жазба файлы түйінді қызмет көрсетуден сақтайды деп болмай, қалпына келтірілген аудит манифесін үйлестіру.

Әр сақталған бай жазба қатысушылардың өзгермейтін шығу тегін сақтайды. Жеке берік қабырға ташы хабарламаны ID, пайдалы жүктеме хэшін, бизнес хабарламасын ID және UETR толық дедубликация үшін сақтайды TTL тіпті бай жазба деректері кесілгеннен кейін де.

Torii өмірлік цикл хабарламасын қолтаңбалаудан немесе өңдеуден бұрын қайта ойнауға рұқсат беруді жалғастырады. Ол ешқашан аяқталмаған қайта ойнау сәйкестігін жояды. Егер конфигурацияланған қуаты толықтай қорғалған жазбалар немесе мерзімі өткен қайталау сәйкестіктерімен орналастырылған болса, тапсырыстар өмір циклін немесе есептік жағдайды өзгертпестен қайтарылуға болатын `503 Service Unavailable` алады.

Әрбір пайда болған `pacs.002`, `pacs.004`, `camt.029`, `sese.024`, немесе `sese.025` құжат қайтарылады `application/xml` мынадай жауап атауларымен:

|Басты бет |Мағынасы |
| ------------------------------ | ----------------------------------------------------- |
|`X-Iroha-Iso-Signature-Domain` |Әрқашанда `iroha.iso20022.outbound.v2` |
|`X-Iroha-Iso-Signer` |Конфигурацияланған көпірдің қолтаңбалаушысы үшін каноникалық қоғамдық кілті |
|`X-Iroha-Iso-Signature` |Доменге бөлінген XML байттардағы Base64 қолтаңбасы |

Қолтаңбаны тексеру UTF-8 байт реттілігі `iroha.iso20022.outbound.v2`, бір нөл байт, және нақты жауап дене. қайта форматтамаңыз немесе қалыпқа келтірмеңіз XML тексеруден бұрын.

### Қосымша талдау және карта жасау көмегі {#additional-parser-and-mapping-support}

IVM ISO көмекшісі сондай-ақ конвертті растау, елді мекендерді карталау немесе төменгі ағыстағы келісу үшін келесі хабарлама отбасыларын бекітеді және іске асырады. Олардың дербес Torii бағыттары жоқ.

|Хаттар отбасы |Ағымдағы қолдау |
| --- | --- |
|`head.001` | Кәсіпорындық өтінімнің басына сәйкестендіру ISO конверттер, оның ішінде: `BizMsgIdr`, `MsgDefIdr`, құру уақыты және таңдаулы жіберуші/алушы BIC өрістері |
|`pacs.007`, `pacs.028`, `pacs.029` |Төлемдерді кері қайтару, status сұрату және тергеуді шешу/status parsing |

|`camt.052`, `camt.053`, `camt.054` |Есепті есеп, есептілік және хабарламаны бекіту |

## Kaigi Отырыстар {#kaigi-sessions}

Kaigi SORA Nexus желісінде ақылы, нақты уақыт аудио/видео бөлмелерін ұсынады. Оны қолданба барлық конференцияның күйін тізбектен тыс сақтаудың орнына кітапшаға негізделген сессия жасауды, рестрді өзгертуді, релелік манифесттерді, шифрланған сигнал беруді және пайдалану өлшемін қажет ететін кезде қолданыңыз.

Кітаптық кітапқа қарасты өмірлік цикл:

- `CreateKaigi`: доменнің астында шақыру жасаңыз және оның саясатын, кестесін, метамәліметтерін және релелік манифесті сақтаңыз.
- `JoinKaigi` және `LeaveKaigi`: шақыру тізімін жаңарту. Жеке режимде қатысушылар қатысушылардың тіркелгісін тікелей ашудың орнына міндеттемелерді, күшін жоймаушыларды және тізімді дәлелдеушілерді пайдаланады IDs.
- `RecordKaigiUsage`: өлшемінен өткен ұзақтықты және газдың жалпы санын қоса беріңіз.
- `EndKaigi`: сессияны аяқтап, соңғы уақыт таңбасын жаздырып алу.

Torii эстафеталық телеметрияны `/v1/kaigi/relays`, `/v1/kaigi/relays/{relay_id}`, `/v1/kaigi/relays/health`, және `/v1/kaigi/relays/events` қолданба кезінде API және телеметриялық мүмкіндіктер қосылған. Kaigi домен оқиғалары, мысалы: `KaigiRosterSummary`, `KaigiRelayManifestUpdated`, `KaigiRelayHealthUpdated`, және `KaigiUsageSummary`.

### CLI Түсі сынағы {#cli-smoke-test}

Алдымен: `iroha kaigi` CLI егер сіз а Torii аяқталу нүктесі қабылдайды Kaigi қосылу алдындағы операциялар UI. Тез бастау командасы белсендіге қарсы уақытша бөлме жасайды . Torii аяқтық нүкте және шақыру идентификаторымен жиынтықты басып шығарады, командаға қосылады және SoraNet Скульдің нұсқасы:

```bash
iroha kaigi quickstart --auto-join-host --summary-out kaigi-summary.json
```

Сценарийлі ағымдар үшін бөлменің өмірлік циклін айқын басқару:

```bash
iroha kaigi create \
  --domain streaming \
  --call-name daily \
  --host <i105-account-id> \
  --privacy-mode transparent \
  --room-policy authenticated

iroha kaigi join --domain streaming --call-name daily --participant <i105-account-id>
iroha kaigi leave --domain streaming --call-name daily --participant <i105-account-id>

iroha kaigi record-usage \
  --domain streaming \
  --call-name daily \
  --duration-ms 120000 \
  --billed-gas 1500

iroha kaigi end --domain streaming --call-name daily
```

Пайдалану `--room-policy public` шолушы билеттері жоқ бөлмелер үшін релелер ашық болуы мүмкін немесе `--room-policy authenticated` шығу үшін қараушы аутентификациясы қажет болған кезде. `--privacy-mode zk-roster-v1` Тек желіде Kaigi тізімді және пайдалануды тексеру кілттерін конфигурациялаған; басқаша қосылады, жапырақтары, және жеке пайдалану жазбалары детерминистік тексеру кезінде сәтсіздікке ұшырайды.

### JavaScript демомен сынақ жүргізу {#testing-with-the-javascript-demo}

[soramitsu/iroha-demo-javascript](https://github.com/soramitsu/iroha-demo-javascript) үстел демосын аяқтан аяққа қапсық тестілеу үшін қолданыңыз. Демо электрон және Vue қосымшасы болып табылады, ол жергілікті `@iroha/iroha-js` байланысы арқылы тікелей Torii сөйлеседі және браузерде туған бір-бір медиа үшін `/kaigi` бағытын қамтиды.

Демоны пайдалану [`@iroha/iroha-js`](https://github.com/hyperledger-iroha/iroha/tree/0010c5a70039eac101a4846499ba9ceaf43eb65c/javascript/iroha_js) Қазақстан Республикасы Iroha Көз қоймасы. демо пиндер SDK арқылы `file:../iroha/javascript/iroha_js`, Сонымен , екі кассаны да осы ағайын-туыс орналасуда сақтаңыз:

```bash
mkdir iroha-wallet-workspace
cd iroha-wallet-workspace
git clone https://github.com/hyperledger-iroha/iroha.git
git clone https://github.com/soramitsu/iroha-demo-javascript.git

cd iroha/javascript/iroha_js
npm install
npm run build:native
npm run build:dist

cd ../../../iroha-demo-javascript
npm install
npm run dev
```

Node.js 20 немесе одан жаңасын және Rust құралдар тізбекін пайдаланыңыз, сондықтан түпкілікті `iroha_js_host` модулін құрастыруға болады. Шығармасын өзгерткеннен кейін ағайынды Iroha кассасында SDK қайта құру; таза пакет орналасуында `npm run build:native` үшін қажетті жүк жұмыс кеңістігі жоқ.

Бақыланатын сынақ үшін демонстрацияны Kaigi-қа қабілетті Torii соңғы нүктеге бағыттаңыз:

1. SORA/Kaigi қолданбасына қараған APIs қосылған Iroha түйінді бастаңыз немесе сізге қажетті Kaigi беттерін жария ететін қоғамдық аяқ нүктесін қолданыңыз.
2. Негізгі қол жетімділікті `/health` арқылы тексеріңіз, содан кейін тірі маршрут беті `/openapi` немесе `/openapi.json` арқылы тексеріңіз. Кейбір орналасуларда `/v1/health` де анықталады, бірақ `/health` портативті өмір сүруді тексеру болып табылады.
3. TAIRA үшін тікелей кездесуді орындаудан бұрын эстафеталық телеметриялық маршруттарды тексеру:

   ```bash
   TAIRA=https://taira.sora.org
   curl -fsS "$TAIRA/health"
   curl -fsS "$TAIRA/v1/kaigi/relays"
   curl -fsS "$TAIRA/v1/kaigi/relays/health"
   ```

Бұл тексерулер Torii және Kaigi релелік телеметрияның қолжетімді екенін дәлелдейді. Олар кездесу құруға мүмкіндік бермейді; `CreateKaigi` мен `JoinKaigi` әлі де қаржыландырылған қоршаулар мен қол қойылған транзакцияларды ұсыну қажет.
4. Демонстрацияны ашу, баптауларға өту, Torii URL, және қосымшаны тізбекті жүктеуіне рұқсат етіңіз ID және соңғы нүктеден бастап желі префиксі.
5. Демода екі жергілікті қапшықты құру немесе қалпына келтіру. Хост пен қонақ жеке қапшық күйіне ие болу үшін бөлек қосымша терезелерін, профильдерін немесе машиналарды қолдану.

Kaigi UI тестілеуі үшін:

1. Үйлестіруші терезесінде Kaigi ашу, кездесуді бастауды таңдау, атауын орнату және Жеке шақыру немесе Ашық шақыруды таңдау.
2. Камера мен микрофонды қосуды таңдаңыз, WebRTC жергілікті медиасы бар.
3. Отырыс сілтемесін құруды таңдаңыз. Тікелей әмиян `CreateKaigi` береді; онда қолданба `iroha://kaigi/join?call=...&secret=...` шақыруын және `#/kaigi?...` кері жолдарын көрсетеді.
4. Қонақжайдың терезесін ашық ұстап, шақыруды қонақпен бөлісіңіз.
5. Қонақ терезесінде шақыруды ашыңыз немесе кездесуге қосылыңыз, жергілікті БАҚ-ты қосу және кездесуге қосылуды таңдаңыз. Тікелей қоршау Torii -ден шифрланған хост ұсынысын алып, шифрланған жауап метамәліметтерімен `JoinKaigi` тапсырады.
6. Ұйымдастырушы бірінші жауапты Kaigi шақыру сигналдарын трансляциялау немесе дауыс беру арқылы автоматты түрде қолдануы керек. Екі терезеде де қосылған медиа және жаңартылған байланыс деректері көрсетілуі тиіс.
7. Сессияны хосттан аяқтаңыз немесе CLI `iroha kaigi end` дәл осы шақыру үшін команда ID.

Жеке Kaigi мұқтаждықтары қорғалған XOR жеке кіріс нүктесі ақысын төлеу үшін. Kaigi мұқтаждықтары қорғалған XOR, қолданбадағы өзін-өзі қорғайтын сұрауды пайдаланыңыз және құру немесе қосылу әрекеттерін қайталап көріңіз. Егер дәлелдеме шығару, жеке қаржыландыру немесе тікелей сигнал беру мүмкін болмаса, демонстрация ашық / қолма-қол ағымға қайта оралуы мүмкін. Бұл жағдайда Advanced сигнализациясын ашу, шикі ұсынысты немесе жауап пакетін көшіріп алып, екінші терезеге жабыңыз.

Демо реподағы автоматтандырылған тексерулер үшін:

```bash
npm test -- tests/kaigiView.spec.ts tests/preloadKaigiBridge.spec.ts
npm run e2e:ui
npm run verify
```

Vitest суиттері Kaigi кездесу сілтемелерін құруды, компактты шақыруларды жүктеуді, жеке құру / қосылу / аяқталу көпірлік шақырылымдарды, өзін-өзі қорғау сұрауларын, қолма-қол қайту және жауап сауалнамасын қамтиды. UI түтін сынағында үстел және ұялы өлшемі бар көріністердегі `/kaigi` бағыты қамтылады. Екі қапшықтың арасындағы тікелей медиа әлі де екі терезелік тестілеуді қажет етеді, өйткені браузер камерасы / микрофонға рұқсаттар және ортаға тән медиа ағымдары ерекшеленеді.

Үлгілік интеграциялық код үшін [Біріктірілген Kaigi JavaScript App](/kk/guide/tutorials/kaigi.md) қараңыз.

## Статус және метрикалар {#status-and-metrics}

Статус және өлшемі соңғы нүктелері бірінші нәрселер параметрлік тақталарға қосу:

- `/status` жоғары деңгейдегі теңгерім, блок, кезек және консенсус өрістерін ашады
- `/metrics` Prometheus санағыштарын, өлшегіштерін және гистограммаларын анықтайды

Орындау Nexus-белгіленген түйіндер, жай-күй шығысы сондай-ақ жолақ және деректер кеңістігін білетін бөлімдерді қамтиды. `nexus.enabled = false`, Бұл бөлімдер алынып тасталды.

## JSON мен Norito {#json-vs-norito}

Бірнеше оператордың аяқтық нүктелері әдеттегідей Norito қайтарады. Аяқтық нүкте JSON-ді қолдаған кезде:

```http
Accept: application/json
```

Бұл мынадай жағдайларда аса пайдалы:

- `/v1/sumeragi/status`
- `/v1/sumeragi/qc`
- `/v1/sumeragi/commit_qc/{hash}`

Қорытынды нүкте Norito түрін тікелей қабылдағанда немесе қайтарғанда, мазмұн түрі ретінде `application/x-norito` немесе артықшылықты `Accept` мәні ретінде қолданыңыз. Тасымалдаудың егжей-тегжейі үшін [Norito](/kk/reference/norito.md#torii-and-norito-rpc) қараңыз.
