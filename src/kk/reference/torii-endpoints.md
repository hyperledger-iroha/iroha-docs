# Torii Аяқ нүктелері {#torii-endpoints}

Torii болып табылады HTTP, SSE, және WebSocket кіреберісі Iroha 3. Бұл кітапшаға қарасты екіге тең қызмет етеді APIs және оператордың соңғы нүктелері.

Қолданыстағы хаттама ережелері:

- каноникалық бинарлық форматы Norito
- JSON жіберу кезінде көптеген соңғы нүктелер `Accept: application/json` қолдауын көрсетеді.
- өлшемі Prometheus форматында көрсетіледі

Форматтың егжей-тегжейі, мазмұн келіссөздері, орналасу таңбалары, схема хашилері және Norito RPC нұсқаулығы үшін [Norito сілтемесін қараңыз ](/kk/reference/norito.md).

## Ортақ мақсаттар {#common-endpoints}

|Қорытындысы |Форматтау |Мақсаты |
| --- | --- | --- |
|`POST /transaction` |Norito |Қол қойылған операцияны тапсыру |
|`POST /query` |Norito |Қолтаңбаланған сұрау салуды жіберу |
|`GET /events` |WebSocket |Іс-шараға жазылу |
|`GET /block/stream` |WebSocket |Ағынды қосылған блоктар |
|`GET /peers` |JSON |Torii бойынша шығарылған әріптестер тізімі |
|`GET /health` |JSON |Жеңіл өмір сүрудің соңғы нүктесі |
|`GET /api_version` |JSON |API әдетті нұсқасы |
|`GET /status` |JSON |Операторлар үшін жоғары деңгейдегі мәртебе резюмесі |
|`GET /metrics` |Прометей |Prometheus скрап соңғы нүктесі |
|`GET /schema` |JSON |Жүйелік қызмет көрсететін дерек үлгі схемасы кескінін |
|`GET /openapi` немесе `GET /openapi.json` |JSON |OpenAPI активті Torii HTTP бағыттары үшін құжат |
|`GET /v1/parameters` |JSON |Нод параметрінің кескіндемесі |
|`GET /v1/node/capabilities` |JSON |Нодтың қабілеті және деректер үлгісінің метамәдениі |
|`GET /v1/api/versions` |JSON |Қолданылған Torii API нұсқалары |
|`GET /v1/events/sse` |SSE |Ұзақ өмір сүретін клиенттер үшін оқиғалар ағыны |

|`GET /v1/time/status` |JSON |Уақыт синхрондалу жағдайы |

`/openapi` - жұмыс істеп тұрған түйіннің авторитетті аяқтық нүктелер тізімі. Дұрыс беті құрылыстың ерекшеліктеріне және жұмыс уақытының конфигурациясына байланысты, сондықтан құрылған клиенттер қолмен көшірілген маршрут тізімінен тікелей OpenAPI құжатты артық көрулері керек. Тірі құжатты жүктеу үшін [Torii API консольін ](/kk/reference/torii-api-console.md) қолданыңыз, JSON бағыттарын сынаңыз, curl сұрауларды көшіріп алыңыз және ағымдағы схемадан клиент кодын пайдаланыңыз.

## Тікелей Taira жолдарын сынап көріңіз {#try-live-taira-routes}

Қоғамдық Taira тестілеу желісі қолданба клиенттері тек оқуға арналған барлау үшін пайдаланатын бірдей Torii JSON бетін көрсетеді. Бұл командаларға кілттер қажет емес:

```bash
TAIRA_ROOT=https://taira.sora.org

curl -fsS "$TAIRA_ROOT/status" \
  | jq '{blocks, txs_approved, txs_rejected, queue_size, peers}'

curl -fsS "$TAIRA_ROOT/openapi.json" \
  | jq -r '.paths | keys[]' \
  | grep '^/v1/' \
  | head -n 20

curl -fsS "$TAIRA_ROOT/v1/node/capabilities" \
  | jq '{abi_version, data_model_version, query: .query.aggregate.supported_resources}'
```

Қазіргі әлемдегі жағдайға қатысты ресурс оқиды:

```bash
curl -fsS "$TAIRA_ROOT/v1/domains?limit=5" \
  | jq -r '.items[].id'

curl -fsS "$TAIRA_ROOT/v1/assets/definitions?limit=5" \
  | jq -r '.items[] | [.id, .name, .total_quantity] | @tsv'
```

Егер қоғамдық тестілеу желісі жолы `502`, уақыт шығып, немесе толы кезек туралы хабарласа, оны аяқтық нүктелердің қолжетімділігі мәселесі ретінде қараңыз және клиент кодыңызды ақаусыздандырудан бұрын кейін қайталап көріңіз.

## ISO 20022 Көпір {#iso-20022-bridge}

Torii ISO 20022 көпірін `/v1/iso20022/*` астына шығарады, егер қолданбаға бағдарланған API және көпірдің жұмыс істеу уақыты рұқсат етілсе. Көпір мақсатты түрде: ол жалпы мақсаттағы ISO 20022 клиринг шлюзі емес, таңдалған төлем хабарламаларын қол қойылған Iroha аударымдарға айналдыру және олардың бухгалтерлік кітапшасының жай-күйін бақылау үшін қолданатын кіші жиынтық.

### Torii ISO 20022 Аяқтық нүктелер {#torii-iso-20022-endpoints}

|Әдіс және мақсат |Мақсаты |
| --- | --- |
|`POST /v1/iso20022/pacs008` |FI-ден-FI клиентке кредиттік аударымды тапсыру және сәйкес келетін Iroha активтерді аудару |
|`POST /v1/iso20022/pacs009` |FI-ден-FI-ге PvP немесе бағалы қағаздармен байланысты қолма-қол ақшалай қаржыландыру үшін пайдаланылған кредиттік аударымды табыс ету |
|`POST /v1/iso20022/pacs002` |Төлемнің жай-күйі туралы есеп беру |
|`POST /v1/iso20022/pacs004` |Төлем декларациясын табыс ету |
|`POST /v1/iso20022/camt056` |Төлемнің күшін жою туралы өтінішті тапсыру |
|`POST /v1/iso20022/sese023` |Бағалы қағаздар бойынша есеп айырысу нұсқауларын тапсыру |
|`POST /v1/iso20022/sese024` |Бағалы қағаздар бойынша есеп айырысудың жай-күйі туралы хабарламаны жіберу |
|`POST /v1/iso20022/sese025` |Бағалы қағаздар бойынша есеп айырысу растамасын тапсыру |
|`POST /v1/iso20022/colr012` |Кепілдіктерді ауыстыру туралы хабарламаны тапсыру |
|`GET /v1/iso20022/messages/{msg_id}` |Бір хабар үшін кананикалық көпір жазбасын оқыңыз .|
|`GET /v1/iso20022/audit/messages` |Тексеру манифесті оқыңыз .|
|`GET /v1/iso20022/messages/{msg_id}/pacs002` |Ағымдағы төлем мәртебесін `pacs.002` XML деп қайтару.|
|`GET /v1/iso20022/messages/{msg_id}/pacs004` |Ағымдағы төлем декларациясын `pacs.004` XML ретінде қайтару.|
|`GET /v1/iso20022/messages/{msg_id}/camt029` |Ағымдағы күшін жою шешімі `camt.029` XML деп келтірілсін. |
|`GET /v1/iso20022/messages/{msg_id}/sese024` |Ағымдағы есеп айырысу мәртебесін `sese.024` XML деп қайтару. |
|`GET /v1/iso20022/messages/{msg_id}/sese025` |Ағымдағы есеп айырысу растауын `sese.025` XML деп қайтару. |

`pacs.008` ұсыныстар хабарламаны беруі тиіс ID, Банкаралық есеп айырысу сомасы, валюта, есеп айырысу күні, борышкер мен кредитор IBANs, және борышкер мен кредитор BICs. Анықтама деректерін баптау кезінде көпір сондай-ақ BIC, IBAN, және ISO Алынған транзакция құбыр желісіне енгенге дейін 4217 валюталық өтпе.

`pacs.009` ұсыныстарда бизнес хабарламасы ID, хабарламаның анықтамасы ID, құрылу уақыты, банкаралық есеп айырысу сомасы, валюта, есеп айырысу күні, тапсырма берген және тапсырылған агент BICs, ал борышкер мен кредитор IBANs болуы тиіс. Егер хабарламада `Purp` болса, көпір қазіргі уақытта тек бағалы қағаздар мақсатындағы қаржыландыруды ғана қабылдайды: `Purp=SECU`.

Қауымдастық `pacs.008` және `pacs.009` тапсырудың соңғы нүктелері қабылданды XML ISO көпірлік сынақтарда қолданылатын конверттер немесе тегіс дала форматы. `SplmtryData` өрістер нысананы тіркей алады Iroha бухгалтерлік есеп, көз және нысаналы шот IDs немесе мекен-жайлар және активтердің анықтамасы ID. Жауап: `202 Accepted` қосылған `message_id`, `transaction_hash`, `status`, `pacs002_code`, және шешілген бухгалтерлік есеп/есеп/актив контекстi.

### Қосымша талдау және карта жасау көмегі {#additional-parser-and-mapping-support}

IVM ISO көмекшісі сондай-ақ конвертті растау, елді мекендерді карталау немесе төменгі ағыстағы келісу үшін келесі хабарлама отбасыларын бекітеді және іске асырады. Олардың дербес Torii бағыттары жоқ.

|Хаттар отбасы |Ағымдағы қолдау |
| --- | --- |
|`head.001` | Кәсіпорындық өтінімнің басына сәйкестендіру ISO конверттер, оның ішінде: `BizMsgIdr`, `MsgDefIdr`, құру уақыты және таңдаулы жіберуші/алушы BIC өрістері |
|`pacs.007`, `pacs.028`, `pacs.029` |Төлемдерді кері қайтару, status сұрату және тергеуді шешу/status parsing |
|`pain.001`, `pain.002` |Клиенттің төлемді бастауы және төлем жағдайы туралы баяндаманы бекіту |
|`camt.052`, `camt.053`, `camt.054` |Есепті есеп, есептілік және хабарламаны бекіту |

## Kaigi Отырыстар {#kaigi-sessions}

Kaigi SORA Nexus желісінде ақылы, нақты уақыт аудио/видео бөлмелерін ұсынады. Оны қолданба барлық конференцияның күйін тізбектен тыс сақтаудың орнына кітапшаға негізделген сессия жасауды, рестрді өзгертуді, релелік манифесттерді, шифрланған сигнал беруді және пайдалану өлшемін қажет ететін кезде қолданыңыз.

Кітаптық кітапқа қарасты өмірлік цикл:

- `CreateKaigi`: доменнің астында шақыру жасаңыз және оның саясатын, кестесін, метамәліметтерін және релелік манифесті сақтаңыз.
- `JoinKaigi` және `LeaveKaigi`: шақыру тізімін жаңарту. Жеке режимде қатысушылар қатысушылардың тіркелгісін тікелей ашудың орнына міндеттемелерді, күшін жоюшыларды және тізімді дәлелдеушілерді пайдаланады IDs.
- `RecordKaigiUsage`: өлшемінен өткен ұзақтықты және газдың жалпы санын қоса беріңіз.
- `EndKaigi`: сессияны аяқтаңыз және соңғы уақыт таңбасын тіркеңіз.

Torii эстафеталық телеметрияны `/v1/kaigi/relays`, `/v1/kaigi/relays/{relay_id}`, `/v1/kaigi/relays/health`, және `/v1/kaigi/relays/events` қолданба кезінде API және телеметриялық мүмкіндіктер қосылған. Kaigi домен оқиғалары, мысалы: `KaigiRosterSummary`, `KaigiRelayManifestUpdated`, `KaigiRelayHealthUpdated`, және `KaigiUsageSummary`.

### CLI Түсі сынағы {#cli-smoke-test}

Алдымен: `iroha kaigi` CLI егер сіз а Torii аяқталу нүктесі қабылдайды Kaigi қосылу алдындағы операциялар UI. Тез бастау командасы белсендіге қарсы уақытша бөлме жасайды . Torii аяқтық нүкте және шақыру идентификаторымен жиынтықты басып шығарады, командаға қосылады және SoraNet Скульдің нұсқасы:

```bash
iroha kaigi quickstart --auto-join-host --summary-out kaigi-summary.json
```

Сценарийлі ағымдар үшін бөлменің өмірлік циклін айқын басқару:

```bash
iroha kaigi create \
  --domain streaming \
  --call-name daily \
  --host <i105-account-id> \
  --privacy-mode transparent \
  --room-policy authenticated

iroha kaigi join --domain streaming --call-name daily --participant <i105-account-id>
iroha kaigi leave --domain streaming --call-name daily --participant <i105-account-id>

iroha kaigi record-usage \
  --domain streaming \
  --call-name daily \
  --duration-ms 120000 \
  --billed-gas 1500

iroha kaigi end --domain streaming --call-name daily
```

`--room-policy public` релелері көргіш билеттері жоқ бөлмелер үшін немесе `--room-policy authenticated` шығыстары көргішін аутентификациялауды қажет еткен кезде қолданылсын. `--privacy-mode zk-roster-v1` желіде Kaigi тізім және пайдалану тексеру кілттері конфигурацияланғаннан кейін ғана қолданылады; басқаша қосылады, парақтар және жеке пайдалану жазбалары детерминистік тексеру кезінде сәтсіздікке ұшырады.

### JavaScript демомен сынақ жүргізу {#testing-with-the-javascript-demo}

[soramitsu/iroha-demo-javascript](https://github.com/soramitsu/iroha-demo-javascript) үстел демосын аяқтан аяққа қапсық тестілеу үшін қолданыңыз. Демо электрон және Vue қосымшасы болып табылады, ол жергілікті `@iroha/iroha-js` байланысы арқылы тікелей Torii сөйлеседі және браузерде туған бір-бір медиа үшін `/kaigi` бағытын қамтиды.

Демоны пайдалану [`@iroha/iroha-js`](https://github.com/hyperledger-iroha/iroha/tree/main/javascript/iroha_js) Қазақстан Республикасы Iroha Көз қоймасы. демо пиндер SDK арқылы `file:../iroha/javascript/iroha_js`, Сонымен , екі кассаны да осы ағайын-туыс орналасуда сақтаңыз:

```bash
mkdir iroha-wallet-workspace
cd iroha-wallet-workspace
git clone https://github.com/hyperledger-iroha/iroha.git
git clone https://github.com/soramitsu/iroha-demo-javascript.git

cd iroha/javascript/iroha_js
npm install
npm run build:native
npm run build:dist

cd ../../../iroha-demo-javascript
npm install
npm run dev
```

Node.js 20 немесе одан жаңасын және Rust құралдар тізбекін пайдаланыңыз, сондықтан түпкілікті `iroha_js_host` модулін құрастыруға болады. Шығармасын өзгерткеннен кейін ағайынды Iroha кассасында SDK қайта құру; таза пакет орналасуында `npm run build:native` үшін қажетті жүк жұмыс кеңістігі жоқ.

Бақыланатын сынақ үшін демонстрацияны Kaigi-қа қабілетті Torii соңғы нүктеге бағыттаңыз:

1. SORA/Kaigi қолданбасына қараған APIs қосылған Iroha түйінді бастаңыз немесе сізге қажетті Kaigi беттерін жария ететін қоғамдық аяқ нүктесін қолданыңыз.
2. Негізгі қол жетімділікті `/health` арқылы тексеріңіз, содан кейін тірі маршрут беті `/openapi` немесе `/openapi.json` арқылы тексеріңіз. Кейбір орналасуларда `/v1/health` де анықталады, бірақ `/health` портативті өмір сүруді тексеру болып табылады.
3. TAIRA үшін тікелей кездесуді орындаудан бұрын эстафеталық телеметриялық маршруттарды тексеру:

   ```bash
   TAIRA=https://taira.sora.org
   curl -fsS "$TAIRA/health"
   curl -fsS "$TAIRA/v1/kaigi/relays"
   curl -fsS "$TAIRA/v1/kaigi/relays/health"
   ```

Бұл тексерулер Torii және Kaigi релелік телеметрияның қолжетімді екенін дәлелдейді. Олар кездесу құруға мүмкіндік бермейді; `CreateKaigi` мен `JoinKaigi` әлі де қаржыландырылған қоршаулар мен қол қойылған транзакцияларды ұсыну қажет.
4. Демонстрацияны ашу, баптауларға өту, Torii URL, және қосымшаны тізбекті жүктеуіне рұқсат етіңіз ID және соңғы нүктеден бастап желі префиксі.
5. Демода екі жергілікті қапшықты құру немесе қалпына келтіру. Хост пен қонақ жеке қапшық күйіне ие болу үшін бөлек қосымша терезелерін, профильдерін немесе машиналарды қолдану.

Kaigi UI тестілеуі үшін:

1. Үйлестіруші терезесінде Kaigi ашу, кездесуді бастауды таңдау, атауын орнату және Жеке шақыру немесе Ашық шақыруды таңдау.
2. Камера мен микрофонды қосуды таңдаңыз, WebRTC жергілікті медиасы бар.
3. Отырыс сілтемесін құруды таңдаңыз. Тікелей әмиян `CreateKaigi` береді; онда қолданба `iroha://kaigi/join?call=...&secret=...` шақыруын және `#/kaigi?...` кері жолдарын көрсетеді.
4. Қонақжайдың терезесін ашық ұстап, шақыруды қонақпен бөлісіңіз.
5. Қонақ терезесінде шақыруды ашыңыз немесе кездесуге қосылыңыз, жергілікті БАҚ-ты қосу және кездесуге қосылуды таңдаңыз. Тікелей қоршау Torii -ден шифрланған хост ұсынысын алып, шифрланған жауап метамәліметтерімен `JoinKaigi` тапсырады.
6. Ұйымдастырушы бірінші жауапты Kaigi шақыру сигналдарын трансляциялау немесе дауыс беру арқылы автоматты түрде қолдануы керек. Екі терезеде де қосылған медиа және жаңартылған байланыс деректері көрсетілуі тиіс.
7. Сессияны хосттан аяқтаңыз немесе CLI `iroha kaigi end` дәл осы шақыру үшін команда ID.

Жеке Kaigi мұқтаждықтары қорғалған XOR жеке кіріс нүктесі ақысын төлеу үшін. Kaigi мұқтаждықтары қорғалған XOR, қолданбадағы өзін-өзі қорғайтын сұрауды пайдаланыңыз және құру немесе қосылу әрекеттерін қайталап көріңіз. Егер дәлелдеме шығару, жеке қаржыландыру немесе тікелей сигнал беру мүмкін болмаса, демонстрация ашық / қолма-қол ағымға қайта оралуы мүмкін. Бұл жағдайда Advanced сигнализациясын ашу, шикі ұсынысты немесе жауап пакетін көшіріп алып, екінші терезеге жабыңыз.

Демо реподағы автоматтандырылған тексерулер үшін:

```bash
npm test -- tests/kaigiView.spec.ts tests/preloadKaigiBridge.spec.ts
npm run e2e:ui
npm run verify
```

Vitest суиттері Kaigi кездесу сілтемелерін құруды, компактты шақыруларды жүктеуді, жеке құру / қосылу / аяқталу көпірлік шақырылымдарды, өзін-өзі қорғау сұрауларын, қолма-қол қайту және жауап сауалнамасын қамтиды. UI түтін сынағында үстел және ұялы өлшемі бар көріністердегі `/kaigi` бағыты қамтылады. Екі қапшықтың арасындағы тікелей медиа әлі де екі терезелік тестілеуді қажет етеді, өйткені браузер камерасы / микрофонға рұқсаттар және ортаға тән медиа ағымдары ерекшеленеді.

Үлгілік интеграциялық код үшін [Біріктірілген Kaigi JavaScript App](/kk/guide/tutorials/kaigi.md) қараңыз.

## Статус және метрикалар {#status-and-metrics}

Статус және өлшемі соңғы нүктелері бірінші нәрселер параметрлік тақталарға қосу:

- `/status` жоғары деңгейдегі теңгерім, блок, кезек және консенсус өрістерін ашады
- `/metrics` Prometheus санағыштарын, өлшегіштерін және гистограммаларын анықтайды

Орындау Nexus-белгіленген түйіндер, жай-күй шығысы сондай-ақ жолақ және деректер кеңістігін білетін бөлімдерді қамтиды. `nexus.enabled = false`, Бұл бөлімдер алынып тасталды.

## JSON мен Norito {#json-vs-norito}

Бірнеше оператордың аяқтық нүктелері әдеттегідей Norito қайтарады. Аяқтық нүкте JSON-ді қолдаған кезде:

```http
Accept: application/json
```

Бұл мынадай жағдайларда аса пайдалы:

- `/v1/sumeragi/status`
- `/v1/sumeragi/qc`
- `/v1/sumeragi/commit_qc/{hash}`

Қорытынды нүкте Norito түрін тікелей қабылдағанда немесе қайтарғанда, мазмұн түрі ретінде `application/x-norito` немесе артықшылықты `Accept` мәні ретінде қолданыңыз. Тасымалдаудың егжей-тегжейі үшін [Norito](/kk/reference/norito.md#torii-and-norito-rpc) қараңыз.
