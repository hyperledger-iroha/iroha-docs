# Сыртқы функция интерфейстері (FFI) {#foreign-function-interfaces-ffi}

`iroha_ffi` бағдарламалық пакеті Rust APIs-дан C ABI байланыстарын жасау үшін макростар мен қасиеттерді ұсынады. Бұл Iroha типтері FFI шекарасын кесіп өтуі қажет болған жерлерде, мысалы SDK байланыстар немесе хост интеграциялары арқылы қолданылады.

## Неге FFI {#why-ffi}

Функция – бұл салыстырмалы түрде абстрактілі ұғым, және көптеген тілдер функцияның не істеуі керектігіне келіссе де, функцияларды көрсету тәсілі өте әртүрлі. Сонымен қатар, кейбір тілдерде, мысалы, Rust, функцияны шақырудың салдары және оның жасауға рұқсат етілген нәрселері де әртүрлі болады. Rust кезінде APIs басқа тілден немесе басқа хост ортасынан шақырылуы қажет, Iroha тең мүмкіндіктерді қамтамасыз ету үшін шетелдік функция интерфейсін (FFI) пайдаланады.

Бүгінгі күні қолданылатын негізгі стандарт – C қолданбалы бинарлы интерфейсі. Ол қарапайым, кең таралған және тұрақты. Негізінде, бәрін қолмен жасауға болады, бірақ Iroha бар `iroha_ffi` бағдарламалық пакетін қолданыстағы Rust API-дан FFI-қа сай функцияларды жасау үшін ұсынады.

Әрине, сіз бұл істі өз жолыңызбен жасауға болады. `iroha_ffi` бағдарламалық пакеті тек сізге anyway жасау қажет болатын кодты генерациялайды. Қажетті қайталанатын шаблондық кодты жазу үшін көп зейін мен тәртіп қажет. Әрбір функцияның техникалық шақыруы FFI шекарасында анықталмаған мінез-құлық тудыру мүмкіндігімен `unsafe`. Біз оны шешудің әдісі мықты `repr(C)` түрлерін қолдануға негізделген.

::: info

Бірінші ерекшелік – көрсеткіштер. Нөлдік тексеру мен жарамдылықты жаһандық деңгейде мәжбүрлеуге болмайды, сондықтан шикі көрсеткіштер (әрдайымғыдай) тек ерекше жағдайларда ғана пайдаланылады. Біз Iroha деректер моделіндегі объектінің дерлік әрбір данасына арналған бағдарламалық адаптерлерді ұсынамыз, сондықтан сізге таза көрсеткіштерді қолданудың қажеті жоқ.

:::

## Мысал {#example}

Міне, байлауды құрудың мысалы:

```rust
#[derive(FfiType)]
struct DaysSinceEquinox(u32);

#[ffi_export]
impl DaysSinceEquinox {
    pub fn update_value(&mut self, a: &u8) {
        self.0 = *a as u32;
    }
}
```

Жоғарыдағы мысал келесі байлауды туындатып, онда `DaysSinceEquinox` мөлдір емес көрсеткіш ретінде көрсетіледі:

```rust
pub extern fn DaysSinceEquinox__update_value(handle: *mut DaysSinceEquinox, a: *const u8) -> FfiReturn {
    // function implementation
}
```

## FFI Байланыс Жасалу {#ffi-binding-generation}

`iroha_ffi` бағдарламалық пакеті FFI арқылы шақырылатын функцияларды жасау үшін қолданылады. `Rust` құрылымдары мен әдістері берілген кезде, олар сізге байланыс шекарасын кесіп өту үшін қажет болатын `unsafe` кодын жасайды.

Rust түрі `FfiType::into_ffi` арқылы FFI шекарасын кесіп өте алатын мықты `repr(C)` түріне айналдырылады. Бұл керісінше де болады: FFI `ReprC` түрі `FfiType::try_from_ffi` арқылы `Rust` түріне айналады.

::: warning

Керісінше түрлендіру қателігі мүмкін екенін және анықталмаған мінез-құлықты тудыруы мүмкін екенін ескеріңіз. Біз ең айқын қателіктерден аулақ болуға бар күшімізді салсақ та, бағдарламаның дұрыстығын өз тараптан қамтамасыз етуіңіз керек.

:::

Байланыс генерациясын мүмкіндік беретін негізгі қасиеттер `ReprC`, `FfiType` және `FfiConvert`.

|Сипат|Сипаттама|
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ReprC`      |Бұл қасиет C ABI сәйкес келетін берік типті білдіреді. Бұл типті FFI шекараларында қауіпсіз түрде бөлісуге болады.|
| `FfiType`    |Бұл қасиет берілген `Rust` түрі үшін сәйкес `ReprC` типін анықтайды. Анықталған `ReprC` типі генерацияланған FFI функциясының API ішінде `Rust` типінің орнына қолданылады.|
| `FfiConvert` | Бұл қасиет екі әдісті анықтайды `into_ffi` және `try_from_ffi` өкінішке орай осының конверсиясын орындау үшін қолданылатын `Rust` жазу немесе қабылдау үшін `ReprC` түрі.                                |

Ескеріңіз, FFI үшін меншік құқықтарының берілуі болмайды, тек мөлдір емес көрсеткіш түрлері ғана ерекшеленеді. Меншікті өзімен бірге тасымалдайтын басқа барлық түрлер, мысалы `Vec<T>`, көшіріледі.

### Атының өзгеруі {#name-mangling}

Жасалған FFI объектілерінің атауларында қос астын сызықтарды қолдануды ескеріңіз:

- `StructName` құрылымында анықталған `inherent_fn` әдісі үшін FFI атауы `StructName__inherent_fn` болар еді.
- `StructName` құрылымындағы `TraitName` қасиетінен `MethodName` әдісі үшін, FFI атауы `StructName__TraitName__MethodName` болар еді.
- `StructName` құрылымындағы `field_name` өрісін орнату үшін FFI функциясының атауы `StructName__set_field_name` болады.
- `StructName` құрылымындағы `field_name` өрісті алу үшін FFI функциясының аты `StructName__field_name` болады.
- `StructName` құрылымындағы өзгермелі `field_name` өрісін алу үшін FFI функциясының атауы `StrucuName__field_name_mut` болады.
- Тәуелсіз `module_name::fn_name` үшін, FFI атауы `module_name::__fn_name` болар еді.
- Generic емес және олардың жүзеге асырылуын FFI-да бөлісуге мүмкіндік беретін қасиеттер үшін (төмендегі `Clone`-ны қараңыз), FFI атауы `module_name::__clone` болар еді.

  ```rust
  impl Clone for Type1 {
      fn clone(&self) -> Self;
  }
  impl Clone for Type2 {
      fn clone(&self) -> Self;
  }
  ```
