# Ұйымдастыру мәселелерін шешу {#troubleshooting-deployment-issues}

Бұл бөлімде Iroha 3 орнатулары үшін ақауларды шешу кеңестері ұсынылады. Егер сіз кездесетін мәселе осы жерде сипатталмаған болса, бізге [Telegram](https://t.me/hyperledgeriroha) арқылы хабарласыңыз.

## Жаратылған артефакттардан бастаңыз . {#start-with-generated-artifacts}

Жергілікті және сынақ орнату үшін Kagami арқылы құрылған артефакттерді қолмен жазылған теңгерім файлдардың орнына таңдаңыз:

```bash
cargo run --bin kagami -- localnet --peers 4 --out-dir ./localnet
```

Жаратылған каталогта теңгерімдік конфигурациялар, генезис материалы, бастапқы скрипттер және README құрылымы үшін Iroha 3 желісі бар.

## Жақсылық басталмайды {#peer-does-not-start}

Алдымен мына элементтерді тексеріңіз:

- `iroha3d --config <path>` теңгерімшiлiктiң өзiнiң TOML құжаты бойынша белгiлер.
- `public_key` және `private_key` теңгерімдік конфигурацияда бірдей кілттер жұпқа жатады.
- `genesis.public_key` генез операциясына қол қою үшін пайдаланылған кілтімен сәйкес келеді.
- куәландырушы теңгерімдік сәйкестіктер BLS-Әдеттегі кілттерді пайдаланады, ал `trusted_peers_pop` жергілікті кілттің және сенімді теңгерімдердің иелігіне дәлелді жазуларды қамтиды.
- Torii және P2P порттары басқа процеспен байланысты емес.
- Kura дүкен каталогы бір тізбекке жатады және басқа желілік профилден көшірілмеген.

Даemon бірден астам TOML қабатты оқыған кезде конфигурацияны анықтауды қолдану:

```bash
cargo run -p irohad --bin iroha3d -- --config ./config.toml --trace-config
```

## Docker және Композиция {#docker-and-compose}

Жарату Ағымдағы Kagami жергілікті желі шығысынан жазыңыз, сондықтан команда сызығының аргументтері мен конфигурациялық файлдар тексерілген кодқа сәйкес келеді:

```bash
cargo run --bin kagami -- localnet --peers 4 --out-dir ./localnet
cargo run --bin kagami -- docker --peers 4 --config-dir ./localnet --image hyperledger/iroha:dev --out-file ./docker-compose.yml --force
docker compose -f ./docker-compose.yml up
```

Егер композ орналасуы басталса, содан кейін тоқтаса, демондар журналдарын тексеріңіз:

- сәйкес келмейтін `chain`
- басқа генез операцияларын немесе манифесттерді пайдаланатын бір теңгерім
- тек контейнерлік желіде ғана жұмыс істейтін P2P жарнамаланған мекенжайлар
- жергiлiктi көлемдi регенерациялық генезден кейiн қайта пайдалану

Жаңа генезисті сынау кезінде, ұяшықты қайта бастаудан бұрын ескі Kura көлемдерді алып тастаңыз. Ескі блоктарды жаңа генезмен сақтау қайта ойнауды сәтсіздікке ұшыратады.

## Кубернеттер {#kubernetes}

Kubernetes үшін әрбір растаушыны мемлекеттік инфрақұрылым ретінде қараңыз:

- Әрбір теңгерімге тұрақты сәйкестік кілті және тұрақты тұрақты көлемді беру
- P2P басқа әріптестердің топтаманың ішінен шеше алатын адрестерін ашу
- орнату конфигурациясы және генез файлдарды жылжыту үшін өзгеріссіз конфигурация ретінде
- барлық генезис немесе топология өзгерістерін автоматты түрде жаңарту ретінде емес, қасақатта іске асыру;

Егер модуль бірнеше рет қайта басталса, модульдегі берілген конфигурацияны күтпеген [`peer.template.toml`](/kk/reference/peer-config/index.md#template)мен салыстырып көріңіз және теңгерімнің ескі Kura деректерді қайта ойнауын тексеріңіз.

## Сора профилі {#sora-profile}

Nexus, SoraFS немесе көп жолдық ағымдарды пайдаланатын Iroha 3 орналасулар демонды Sora профилі қосылғанда бастауы керек:

```bash
cargo run -p irohad --bin iroha3d -- --config ./config.toml --sora
```

Бір желідегі валидаторлардың арасында бірдей профильді жүйелі түрде қолдану.
