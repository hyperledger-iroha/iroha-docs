# Криптография с открытым ключом {#public-key-cryptography}

Криптография с открытым ключом использует связанный открытый и закрытый ключи. Открытый ключ можно распространять. Закрытый ключ должен оставаться под контролем уполномоченного лица. Безопасность зависит от использования поддерживаемого алгоритма, генерации ключей с использованием надежной случайности и защиты закрытого ключа.

## Цифровые подписи {#digital-signatures}

Криптографический подписант создает цифровую подпись с помощью закрытого ключа. Проверяющий проверяет подпись с помощью соответствующего открытого ключа.

Действительная подпись показывает, что подписанные байты не были изменены и что владелец приватного ключа их одобрил. Она сама по себе не идентифицирует человека. Идентичность зависит от того, как был зарегистрирован и управляем публичный ключ или контроллер аккаунта.

Подписи обеспечивают целостность и доказательство авторизации. Они не шифруют подписанное содержимое.

## Шифрование с открытым ключом {#public-key-encryption}

Некоторые схемы публичного ключа шифруют данные для публичного ключа получателя. Получатель расшифровывает эти данные с помощью соответствующего приватного ключа. Шифрование и подписи являются отдельными операциями и могут использовать разные ключи или алгоритмы.

Iroha Подписание транзакции не делает данные публичного распределенного реестра блокчейна конфиденциальными. Используйте утвержденный механизм конфиденциальности развертывания, когда содержимое полезной нагрузки должно оставаться приватным.

## Ключи на стороне клиента {#keys-on-the-client-side}

Каждая транзакция должна соответствовать настроенной политике контроллера аккаунта. Простой аккаунт может использовать один ключ подписи. Управляемый аккаунт может использовать более сложную политику контроллера.

Клиентское программное обеспечение должно защищать приватные ключи и другие материалы контроллера. Конфигурация клиента в открытом виде подходит только для локальной разработки и контролируемых тестов. Производственные интеграции должны использовать менеджер секретов, аппаратно-защищенное хранилище ключей, изолированную службу подписи или другую проверенную границу подписи.

Используйте отдельные ключи для разных сред и целей. Повторное использование одного ключа связывает эти использования и увеличивает воздействие при раскрытии.
