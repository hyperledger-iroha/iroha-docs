# Сохранение криптографических ключей {#storing-cryptographic-keys}

Ваши конфиденциальные данные остаются частными только в том случае, если вы придерживаетесь методов <abbr title="Operational Security">OPSEC</abbr> для защиты криптографических ключей. Всегда будьте осторожны и избегайте делиться своим личным ключом, обращаясь с ним так, как бы вы хранили ключи от своей квартиры только для доверенных лиц.

Дополнительная информация о <abbr title="Operational Security">OPSEC</abbr> и его передовых практиках приведена в [Операционная безопасность ](./operational-security).

## Сохранение криптографических ключей в цифровом виде {#storing-cryptographic-keys-digitally}

Когда дело доходит до цифровой защиты криптографических ключей, в основном доступны только два подхода: [SSH](https://www.ssh.com/) и [GPG](https://www.gnupg.org/). Эти методы обеспечивают слои безопасности для предотвращения несанкционированного доступа к вашим криптографическим ключам.

На многие архитектурные решения Iroha повлияли принципы протокола Secure Shell (`SSH`, поэтому в данном разделе основное внимание уделяется подходу `SSH`, предоставление инструкций о том, как эффективно внедрять протокол для хранения ваших криптографических ключей в экосистеме Iroha.

### Использование агента SSH и SSH {#using-ssh-and-ssh-agent}

Secure Shell Protocol (`SSH`) - криптографический сетевой протокол, который служит виртуальным шлюзом, позволяющим безопасный доступ к удаленным машинам через потенциально не так безопасные сети с использованием ключей SSH доступных аккредитаций. Он обеспечивает эффективный способ удаленного взаимодействия с системами без необходимости физического присутствия. В этом контексте `SSH` предлагает два основных механизма аутентификации: традиционный подход на основе пароля и более безопасный метод пары ключей государственно-частного сектора .

Для получения дополнительной информации о `SSH` см. [связанная тема Академии SSH ](https://www.ssh.com/academy/ssh).

Чтобы упростить процесс входа и обойти необходимость повторного ввода, можно соединить ключи `SSH` с агентом SSH (`ssh-agent`) - помощницей программы, которая запоминает ваши ключи и/или пароль `SSH` в течение сеанса. Такая установка позволяет шлюзу `SSH` легко получить доступ к ключам, когда он подключается к другим машинам.

Рабочий процесс здесь следующий: вы храните свой публичный ключ в удаленной системе и держите свой частный ключ в безопасности. Когда вы хотите получить доступ к удаленной системе, `ssh-agent` Затем удаленная система отправляет обратную запись, чтобы передать ключ. [вызов](https://en.wikipedia.org/wiki/Challenge%E2%80%93response_authentication) На что может ответить только ваш частный ключ. `ssh-agent` решает эту задачу с помощью вашего частного ключа и отправляет правильный ответ обратно на удаленную систему. Если ответ совпадает с ожиданиями системы, вы получите доступ.

Красота `ssh-agent` заключается в том, что он сохраняет ваш частный ключ во время сеанса, поэтому вам не нужно постоянно вводить пароль или пароль с частным ключем каждый раз, когда вы подключаетесь к удаленной системе.

Дополнительная информация по теме `ssh-agent` см. [связанная тема SSH Академии](https://www.ssh.com/academy/ssh/agent).

::: info Примечание

Для подробного обзора `SSH` Протокол и `ssh-agent` инструмент, см. следующее [SSH Академия](https://www.ssh.com/academy) Темы:

  - [Что это? SSH (Secure Shell)?](https://www.ssh.com/academy/ssh)
  - [ssh-agent: Как настроить ssh-агента, передачу агента и протокол агента](https://www.ssh.com/academy/ssh/agent)

:::

### Добавление программы управления паролями {#adding-a-password-manager-program}

Рекомендуется повысить безопасность ключей `SSH`, защищая их паролем, который служит дополнительным препятствием для вредоносных сторон, стремящихся получить вашу конфиденциальную информацию.

Для временного хранения паролей пользователей и ключей `SSH` можно использовать различные менеджеры паролей. В целях ясности, [KeePass](https://keepass.info/) используется в качестве примера менеджера паролей, в частности, порт [KeePassXC](https://keepassxc.org/) на операционных системах Linux.

Для инструкций о том, как установить KeePassXC см. раздел [Конфигурирование KeePassXC](#configuring-keepassxc) ниже.

![KeePassXC: экран `Main` UI](../../../img/KeePassXC.png)

KeePassXC предлагает повышенную безопасность, гибкость и контроль. Он хранит не только пароли, но и ключи `SSH`. Когда он используется для хранения ключей, этот менеджер паролей обеспечивает сохраненные ключи `ssh-agent`. которые незамедлительно удаляются из памяти после закрытия окна KeePassXC.

::: чаша

Теоретически, любой из KeePass порты [размещен на официальном сайте](https://keepass.info/download.html) Мы рекомендуем использовать любой из следующих способов: [KeePassX](https://www.keepassx.org/) или [KeePassXC](https://keepassxc.org/).

:::

#### Конфигурация KeePassXC {#configuring-keepassxc}

Для настройки KeePassXC выполнять следующие шаги:

1. Запустить KeePassXC, затем перейдите к инструментам > Настройки, или выберите кнопку Gear с верхней панели UI.

2. В вкладке "Настройки приложений", которая отображается, выберите агент SSH из левого меню, а затем выберите ящик для проверки интеграции агента SSH включить.

   ::: info Показывать скриншоты ссылки

   ![В таблице KeePassXC `SSH Agent`: Умение использовать SSH Агент](../../../img/keepassxc_ssh_agent.png)

   :::

3. Создание новой базы данных KeePassXC. Для получения инструкций см. Руководство пользователя [KeePassXC > Создание своей первой базы информации](https://keepassxc.org/docs/KeePassXC_UserGuide#_creating_your_first_database).

4. Для каждого ключа, который вы хотите сохранить в создаваемой вами базе данных KeePassXC, выполните следующие шаги:

   - Добавить новый ввод в базу данных. Для получения инструкций см. Руководство пользователя [KeePassXC > Создание своей первой базы данных ](https://keepassxc.org/docs/KeePassXC_UserGuide#_creating_your_first_database).

   - При добавлении нового входа прикрепите файл, содержащий ключ, выполняя следующее: выберите Advanced из левого меню, затем выберите Добавить в разделе Прикрепления, выберите требуемый файл в окне Выбрать файлы, которое появляется.

   - При добавлении нового входа выберите агент SSH из левого меню, затем выберите файл ключа, который вы добавили из меню "Присоединение" в разделе Частный ключ. Затем выберите следующие ящики для отбора:

      - Добавьте ключ к агенту при открытии/отключении базы данных

      - Удалить ключ от агента, когда база данных закрыта/заперта.

      - Требуется подтверждение пользователя при использовании этого ключа

   - В случае необходимости вносить другие изменения в запись.

   - При подготовке выберите OK для сохранения записи.

##### Ожидаемые результаты {#expected-results}

- Ключи для криптографии и `shh` хранятся в качестве записей в базе данных KeePassXC, к которой можно получить доступ, пока окно KeePassXC открыто.

- Сохраненные криптографические и ключи `ssh` могут быть использованы в любое время, когда они требуются для разрешения.

- Сохранившиеся криптографические и ключи `ssh` удаляются из `ssh-agent` после закрытия окна KeePassXC.

::: info Примечание

Если `ssh-agent` не включает в действие опцию запросить подтверждение пользователя при использовании этого ключа, он может не контролировать процесс, который предоставил ему ключ. В случае прекращения процесса управления паролями вредоносным ПО или системной службой через сигнал `SIGKILL`, Ключ, скорее всего, останется в `ssh-agent`, поскольку программы системы Unix не могут перехватить `SIGKILL`.

:::

## Сохранение физических криптографических ключей {#storing-cryptographic-keys-physically}

Для тех, кто стремится к высочайшему уровню офлайн-безопасности, вариант хранения криптографических ключей физически гарантирует, что ключи остаются полностью отключены от цифровых сетей, таким образом минимизируя риск несанкционированного доступа. Признание физического варианта подчеркивает нашу приверженность удовлетворению различных потребностей в безопасности.

### Используя аппаратный ключ {#using-a-hardware-key}

Наша команда считает, что аппаратные ключи являются одной из лучших мер безопасности. Аппаратный ключ - компактное устройство, которое подключается через порт USB и имеет размер типичного флэш-накопителя. Это позволяет легко отключить устройство в случае нарушения безопасности, или просто подключить его к другой машине, когда это необходимо.

Тем не менее, поскольку существует множество брендов аппаратных ключей, каждый со своим уникальным APIs, важно исследовать рынок для поиска ключа, который наиболее подходит вашим потребностям.

До сих пор наша команда провела внутренние тесты на аппаратный ключ [YubiKey 5C](https://www.yubico.com/il/product/yubikey-5c/), который оказался обладательным многих положительных функций, включая универсальную функциональность API.

Однако существует потенциальный недостаток, который следует учитывать. Внедрение аутентификации [HMAC вызов-ответ](https://en.wikipedia.org/wiki/Challenge%E2%80%93response_authentication) и хранение соответствующего частного ключа для этого ответа могут создать уязвимость. Эта настройка может непреднамеренно позволить злоумышленникам делать образованные догадки о информации, хранящейся в памяти YubiKey 5C, тем самым нарушая общую безопасность.

К счастью, эта уязвимость может быть смягчена путем принятия альтернативного подхода к использованию YubiKey 5C. Идея состоит в том, чтобы использовать YubiKey 5C для безопасного доступа к базе данных KeePassXC, где хранятся ваши криптографические и `SSH` ключи. Этот метод может даже считаться полезным, поскольку он превосходит безопасность большинства паролей и делает необходимым для вредоносной стороны иметь в своем распоряжении аппаратный ключ в случае утечки базы данных KeePassXC.

::: Информация

Чтобы узнать больше о вышеперечисленном методе, см. ответ одного из KeePassXC разработчики[Янек Бевендорф](https://github.com/phoerious) к следующим StackExchange Вопрос:

[Справедливо ли использовать KeePassXC вместе с YubiKey?](https://security.stackexchange.com/questions/201345/is-it-reasonable-to-use-keepassxc-with-yubikey/258414#258414)

:::

### Использование фразы "мнемонический" {#using-a-mnemonic-phrase}

В качестве альтернативы, вы можете запомнить частный ключ в виде серии слов, известной как мнемоническая фраза. Этот метод, используемый во многих кошельках, требует запоминания около 25 конкретных слов. Большинство менеджеров паролей, включая ранее обсужденные KeePassXC, предлагают генерирование мнемонических паролей.
