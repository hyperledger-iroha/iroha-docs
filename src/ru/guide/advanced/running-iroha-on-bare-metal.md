# Запуск Iroha на «голом железе» {#running-iroha-on-bare-metal}

Используйте этот рабочий процесс, когда вы хотите запускать сетевых узлов прямо на хостах, а не через Docker Compose. Текущая исходная ветка предоставляет генераторы Kagami, которые создают соответствующие файлы genesis блокчейна, конфигурации сетевых узлов, конфигурацию клиента, а также скрипты запуска и остановки.

## 1. Сборка бинарных файлов {#_1-build-the-binaries}

Из вышеуровневого рабочего пространства Iroha:

```bash
cargo build --release \
  -p irohad --bin iroha3d \
  -p iroha_cli --bin iroha \
  -p iroha_kagami --bin kagami
```

Это даёт:

- `target/release/iroha3d` для демона сетевого пира
- `target/release/iroha` для CLI
- `target/release/kagami` для ключа, генезиса блокчейна и генерации локальной сети

## 2. Создать локальную сеть {#_2-generate-a-local-network}

Создайте четырёхпировую Iroha 3 локальную сеть:

```bash
target/release/kagami localnet --peers 4 --out-dir ./localnet
```

Каталог вывода содержит сгенерированные файлы `genesis.json`, `genesis.signed.nrt`, узла сети `config.toml`, `client.toml`, вспомогательные скрипты и сгенерированный `README.md` с точными командами для этого пакета.

## 3. Запустить сетевые узлы {#_3-start-peers}

Для сгенерированной одноразовой локальной сети используйте сгенерированный скрипт:

```bash
./localnet/start.sh
```

Если вам нужно подключить каждого сетевого участника к менеджеру процессов, такому как systemd, используйте команду запуска, записанную в `./localnet/README.md`, для каждого сетевого участника. Сохраняйте `config.toml`, приватный ключ, каталог хранения и порты каждого сетевого участника отдельно.

## 4. Управлять сетью {#_4-operate-the-network}

Используйте сгенерированную конфигурацию клиента:

```bash
target/release/iroha --config ./localnet/client.toml ledger domain list all
target/release/iroha --config ./localnet/client.toml --output-format text ops sumeragi status
```

Остановите сгенерированную локальную сеть с помощью:

```bash
./localnet/stop.sh
```

## 5. Примечания по производству {#_5-production-notes}

- Создайте новые приватные ключи для производства и храните их вне репозитория.
- Добейтесь того, чтобы каждый узел сети согласился с одной и той же подписанной транзакцией генезиса блокчейна, топологией, доверенными узлами сети и валидатором PoPs.
- Привязывайте адреса прослушивания только к локальным интерфейсам хоста, если сетевой узел не должен быть доступен с других машин.
- Используйте обратный прокси или брандмауэр для защиты Torii, базовой аутентификации, TLS и ограничения частоты запросов.
- Рассматривайте изменения в генезисе блокчейна или топологии консенсуса как координированные миграции, а не как редактирование файлов одним узлом.

Для контейнеризированной локальной разработки используйте рабочий процесс [Запуск Iroha 3](../../get-started/launch-iroha.md) Docker Compose.
