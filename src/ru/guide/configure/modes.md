# Публичные и частные блокчейн {#public-and-private-blockchains}

Iroha может работать в различных конфигурациях. Как администратор собственной сети, вы решаете, какой исполнитель и политика разрешений определяет, принимается ли транзакция.

Общие профили - это частные разрешенные сети и более открытые общественные сети. Оба конфигурируются посредством положения генезиса и политики исполнения, а не через отдельные бинарные узлы.

Ниже приведены основные различия в этих двух случаях применения.

## Разрешения {#permissions}

В публичной блокчейне большинство учетных записей имеют один и тот же набор разрешений. В частной блокчейне считается, что большинство аккаунтов не могут делать ничего за пределами предоставленного им полномочий, если не будет прямое разрешение.

::: Информация

Для получения дополнительной информации см. раздел [ посвященный разрешениям](/ru/blockchain/permissions.md).

:::

## Сверстники {#peers}

В общественном блокчейн, введение сверстников является частью политики цепочки. Для частного блокчейна, развертывания обычно зафиксируют доверительный сверстник настройки и генезиса.

::: Информация

Подробная информация приведена в [ peer management ](peer-management.md).

:::

## Регистрационные счета {#registering-accounts}

В зависимости от того, как вы решите настроить свой [генезисный блок (`genesis.json`)](genesis.md), процесс регистрации учетной записи может идти одним из двух путей. Чтобы понять почему, давайте сначала поговорим о разрешении.

Выбранный исполнитель определяет, какие проверки разрешений применяются. Вы можете предоставить дефолтные токены разрешения [](/ru/blockchain/permissions.md) в генезисе для формирования частной, управляемой администратором сети или более открытой сети. После того, как эти разрешения активированы, процесс регистрации учетных записей отличается.

Когда дело доходит до регистрации счетов, у публичных и частных блокчейнов есть следующие различия:

- Таким образом, теоретически все, что вам нужно - это подходящий клиент, способ генерировать частный ключ для поддерживаемого алгоритма и политику разрешений, которая принимает регистрацию.

- В частной блокчейне можно иметь любой процесс создания учетной записи: это может быть то, что инструкция по регистрации должна быть представлена конкретной учетной записью или умным контрактом, который просит другие детали. Может быть, в частной блокчейне регистрация новых счетов возможна только на конкретные даты или ограничена неопределенным (ограниченным) токеном.

- В типичной частной блокчейне, т.е. в блокчейне без каких-либо уникальных процессов регистрации счетов, вам нужна учетная запись для регистрации другой учетной записи.

По умолчанию валидаторы разрешений охватывают типичный частный случай использования блокчейна.

::: Информация

Публичные и частные режимы - это профили политики, а не отдельные бинарные узлы. Перед запуском открытой сети проверьте разрешения исполнителя и генезиса.

:::

Для получения дополнительной информации о инструкциях `Register<Account>` см. раздел по инструкции [](/ru/blockchain/instructions.md#un-register).

[^1]: `Register<Account>` создает состояние бухгалтерского учета для канонического, бездоменного `AccountId`; маршрутизация доменов и прозвища управляются отдельно.
