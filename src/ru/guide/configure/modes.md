# Публичные и частные блокчейны {#public-and-private-blockchains}

Iroha может работать в различных конфигурациях. В качестве администратора вашей собственной сети вы решаете, какой исполнитель и политика разрешений определяют, будет ли транзакция принята.

Обычные профили — это частные разрешённые сети и более открытые публичные сети. Обе конфигурируются через состояние генезиса блокчейна и политику исполнителя, а не через отдельные бинарные файлы узлов.

Ниже мы излагаем основные различия в этих двух вариантах использования.

## Разрешения {#permissions}

В публичном блокчейне у большинства аккаунтов одинаковый набор разрешений. В частном блокчейне каждый аккаунт получает только свои явные разрешения.

::: info

Обратитесь к [специальный раздел о разрешениях](/ru/blockchain/permissions.md) для получения подробной информации.

:::

## сети равноправные узлы {#peers}

В публичном блокчейне допуск сетевых узлов является частью политики цепочки. Для приватного блокчейна развертывания обычно фиксируют набор доверенных сетевых узлов в конфигурации и генезисе блокчейна.

::: info

Обратитесь к [управление сетевыми узлами](peer-management.md) для получения дополнительной информации.

:::

## Регистрация аккаунтов {#registering-accounts}

В зависимости от того, как вы решите настроить ваш [генезисный блок блокчейна (`genesis.json`)](genesis.md), Процесс регистрации аккаунта может идти одним из двух способов. Чтобы понять, почему, давайте сначала поговорим о разрешениях.

Выбранный исполнитель определяет, какие проверки разрешений применяются. Вы можете предоставить стандартный [токены разрешений](/ru/blockchain/permissions.md) в генезисе блокчейна, чтобы сформировать частную сеть, управляемую администраторами, или более открытую сеть. После того как эти разрешения активны, процесс регистрации аккаунтов отличается.

Политики публичной и частной регистрации обычно различаются:

- Политика публичной регистрации принимает регистрацию аккаунтов от любого подходящего пользователя[^1]. Пользователю необходим подходящий клиент, приватный ключ для поддерживаемого алгоритма и запрос на регистрацию, принятой политикой.

- Политика приватной регистрации может авторизовать один аккаунт или один смарт-контракт для подачи регистраций. Пользовательская политика может ограничивать регистрацию определённым временным окном. Она также может требовать от отправителя потратить токен, количество которого фиксировано, так как ни один уполномоченный субъект не имеет разрешения выпускать больше.

- С шаблоном частной сети по умолчанию существующая учетная запись отправляет регистрацию для каждой новой учетной записи.

Стандартные валидаторы разрешений охватывают типичный сценарий использования частного блокчейна.

::: info

Публичные и частные режимы являются выбором политики исполнителя и генезиса блокчейна. Оба используют один и тот же бинарный файл узла. Проверьте выбранные разрешения исполнителя и генезиса блокчейна перед запуском открытой сети.

:::

Обратитесь к разделу [инструкции](/ru/blockchain/instructions.md#un-register) для получения дополнительной информации о инструкциях `Register<Account>`.

[^1]: `Register<Account>` создаёт распределённое блокчейн-реестрное состояние для канонического, бездоменного `AccountId`; маршрутизация домена и псевдонимы управляются отдельно.
