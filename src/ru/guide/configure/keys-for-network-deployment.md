# Ключи к развертыванию сети {#keys-for-network-deployment}

Каждая сеть нуждается в отдельном ключевом материале для клиентов, сверстников, подписания генезиса,
и, для NPoS или Nexus профили, BLS идентификации валидатора.

## Где используются ключи {#where-keys-are-used}

- Ключи для подписи клиента хранятся в `client.toml` под `[account]`.
- Ключи для идентификации сверстников хранятся в каждом сверстнике `config.toml` как `public_key` и
  `private_key`.
- Обнаружение сверстников использует общественный ключ каждого сверстника в `trusted_peers`.
- BLS Валидатор Доказательства владения хранятся в `trusted_peers_pop` для NPOS
  Профили.
- Подпись в Бытии использует `[genesis].public_key` в конфигурации сверстников и
  совпадает с частным ключом при подписании манифеста.

Для локальных или испытательных развертываний Kagami генерировать все эти файлы вместе:

```bash
cargo run --bin kagami -- localnet --build-line iroha3 --peers 4 --out-dir ./localnet
```

Для существующей сети или профиля используйте управляемый поток:

```bash
cargo run --bin kagami -- wizard --profile nexus
```

## Создать отдельные пары ключей {#generate-individual-key-pairs}

Использование `kagami keys` для отдельного ключевого материала:

```bash
cargo run --bin kagami -- keys --algorithm ed25519 --json
```

Для BLS материалы-валидаторы, включая удостоверение владения:

```bash
cargo run --bin kagami -- keys --algorithm bls_normal --pop --json
```

## Совместимость с другими {#peer-consistency}

Все валидаторы должны согласиться на одну и ту же генезисную транзакцию, топологию, доверенность
общедоступные ключи и валидатор PoPs. Один недостающий или несовместимый ключ
предотвращать запуск сети или достижение консенсуса.

Для минимального развертывания византийской толерантности к ошибкам используйте по меньшей мере четыре партнера.
Peer должен иметь свой собственный частный ключ, но каждая конфигурация peer должна быть одинаковой.

## Счета клиентов {#client-accounts}

Счет клиента в `client.toml` Должно уже существовать в цепочке.
В случае, если вы не можете получить разрешение на регистрацию в генезисном манифесте или последующей транзакции.
генезис подписывает идентификацию как долгосрочный учетный запись; привилегии генезиса
применяются только во время раунда генезиса, и производственные клиенты должны использовать свои собственные
счета и роли.
