# генезис блокчейна {#genesis}

Генезис блокчейна определяет начальное состояние цепочки. Редактируемый источник является JSON техническим манифестом, а Iroha 3 узел потребляет подписанный Norito файл транзакции.

## Файлы {#files}

Исходный репозиторий поставляет стандартный технический манифест по адресу `defaults/genesis.json`. Сети, сгенерированные с помощью Kagami, записывают свой собственный технический манифест и подписанную транзакцию в выходной каталог:

```bash
cargo run --bin kagami -- localnet --peers 4 --out-dir ./localnet
```

Сгенерированный `README.md` в этом каталоге записывает точные файлы и команды запуска для выбранного профиля.

## Конфигурация сетевого узла {#peer-configuration}

сетевые узлы указывают на подписанную транзакцию генезиса блокчейна в разделе `[genesis]` `config.toml`:

```toml
[genesis]
file = "./genesis.signed.nrt"
public_key = "ed0120..."
```

Все сетевые узлы в сети должны согласовать подписанную транзакцию генезиса блокчейна и публичный ключ генезиса блокчейна.

## Подписание генезиса блокчейна {#signing-genesis}

Если вы редактируете технический манифест вручную, проверьте его и подпишите перед запуском сетевых узлов:

```bash
cargo run --bin kagami -- genesis validate ./genesis.json
cargo run --bin kagami -- genesis sign ./genesis.json \
  --private-key-file "$GENESIS_PRIVATE_KEY_FILE" \
  --out-file ./genesis.signed.nrt
```

`GENESIS_PRIVATE_KEY_FILE` должен быть файлом обычного типа с одной ссылкой, находящимся в режиме, удерживаемом владельцем-`0600`, содержащим один канонический мультихэш приватного ключа и завершающий перенос строки. Kagami отклоняет символические ссылки и никогда не принимает сырой приватный ключ genesis блокчейна через командную строку.

Для профилей NPoS или Nexus включайте топологию и BLS доказательства владения, требуемые сгенерированным профилем. Kagami `localnet`, `wizard` и команды генерации профиля автоматически обрабатывают эти детали.

## Повторное подтверждение генезиса блокчейна {#recommitting-genesis}

Узел сети завершает создание генезиса блокчейна только тогда, когда его хранилище пусто. Чтобы протестировать новый генезис блокчейна в временной локальной сети, остановите узлы сети, удалите их сгенерированную директорию состояния и начните с нового подписанного генезиса блокчейна. Не заменяйте генезис блокчейна в работающей сети, если каждый валидатор не координирует одну и ту же миграцию.
