# генезис блокчейна {#genesis}

Генезис блокчейна определяет начальное состояние цепочки. Редактируемый источник является JSON техническим манифестом, а Iroha 3 узел потребляет подписанный Norito файл транзакции.

## Файлы {#files}

Исходный репозиторий содержит стандартный исходный шаблон `defaults/genesis.template.json`. Шаблон неполон: его нельзя проверить, подписать или использовать на узле, пока `kagami genesis materialize` не преобразует его в манифест. Сети, создаваемые Kagami, записывают собственный манифест и подписанную транзакцию в выходной каталог:

```bash
cargo run --bin kagami -- localnet generate --peers 4 --out-dir ./localnet
```

Сгенерированный `README.md` в этом каталоге записывает точные файлы и команды запуска для выбранного профиля.

## Конфигурация сетевого узла {#peer-configuration}

Узлы указывают подписанную транзакцию генезиса в разделе `[genesis]` файла `config.toml`, а её ожидаемый хеш закрепляют в отдельном файле:

```toml
[genesis]
file = "./genesis.signed.nrt"
public_key = "ed0120..."
expected_hash_file = "./genesis.expected_hash"
```

Все узлы сети должны использовать одинаковые подписанную транзакцию генезиса и открытый ключ генезиса. Каждый запуск, первый или повторный, требует ожидаемого хеша: настройте ровно один из параметров — `expected_hash_file` или встроенный `expected_hash`. Файл записывает `kagami genesis sign --expected-hash-out`.

## Подписание генезиса блокчейна {#signing-genesis}

Если вы редактируете технический манифест вручную, проверьте его и подпишите перед запуском сетевых узлов:

```bash
cargo run --bin kagami -- genesis validate ./genesis.json
cargo run --bin kagami -- genesis sign ./genesis.json \
  --private-key-file "$GENESIS_PRIVATE_KEY_FILE" \
  --out-file ./genesis.signed.nrt \
  --expected-hash-out ./genesis.expected_hash
```

`GENESIS_PRIVATE_KEY_FILE` должен быть файлом обычного типа с одной ссылкой, находящимся в режиме, удерживаемом владельцем-`0600`, содержащим один канонический мультихэш приватного ключа и завершающий перенос строки. Kagami отклоняет символические ссылки и никогда не принимает сырой приватный ключ genesis блокчейна через командную строку.

Каждый подписанный генезис, как в режиме с разрешениями, так и в NPoS, должен включать топологию ровно из `3f + 1` валидаторов с доказательством владения ключом BLS для каждого валидатора. Команды Kagami `localnet generate`, `wizard` и `sora-network generate` выполняют это автоматически.

## Повторное подтверждение генезиса блокчейна {#recommitting-genesis}

Новая сеть запускается из своего подписанного генезиса. Чтобы проверить другой генезис в одноразовой локальной сети, остановите узлы, удалите созданный каталог состояния и запустите сеть из нового подписанного генезиса. В работающей сети никогда нельзя заменять генезис в качестве способа обновления. Изменения определений протокола требуют переходов выбора по правилам управления сетью и проверки пригодности выбранных определений и обязательств.
