# управление сетевыми узлами {#peer-management}

Если вы следовали любому из руководств для конкретного языка, теперь у вас есть хорошо функционирующая сеть, к которой люди захотят присоединиться.

## Публичный блокчейн {#public-blockchain}

В открытой сети допуск сетевого узла все еще является решением политики цепочки. Узел может запускать правильное программное обеспечение и подключаться к Torii, но он участвует в консенсусе только после того, как сеть примет его сетевую идентичность.

## Частный блокчейн {#private-blockchain}

В банковской среде разрешение каждому присоединяться по своему усмотрению представляет собой угрозу безопасности. Для обеспечения безопасности частные развертывания Iroha обычно закрепляют топологию сетевых узлов в конфигурации и генезисе блокчейна, вместо того чтобы полагаться на открытое обнаружение.

### Регистрация сетевых узлов {#registering-peers}

Чтобы добавить сетевого узла в сеть, его необходимо зарегистрировать вручную. Давайте обсудим шаги, которые следует предпринять, чтобы завершить этот процесс.

#### 1. Предоставьте пользователю разрешения {#_1-grant-the-user-permissions}

Учетная запись, которая регистрирует сетевой узел, должна иметь соответствующий `Permission`. Это может быть предоставлено через `Role` или как прямое предоставление разрешения.

Предоставьте роль, когда учетная запись будет управлять сетевыми узлами со временем. Используйте прямое предоставление разрешений для одноразовой регистрации учетной записи, которая в противном случае не управляет сетевыми узлами.

::: info

Исполнитель по умолчанию использует маркер разрешений `CanManagePeers` для регистрации и снятия с регистрации сетевых узлов.

:::

Мы обсуждаем разрешения и роли более подробно в [отдельная глава](/ru/blockchain/permissions.md).

#### 2. Настройте сетевого узла {#_2-set-up-a-peer}

После того как новому сетевому узлу были предоставлены права, его необходимо настроить.

Запросите текущую конфигурацию сетевого узла перед его подключением. Torii предоставляет параметры узла и возможности API для этой цели. Начальная настройка сетевого узла-пиринга не согласует эти значения автоматически: операторы должны проверить, чтобы тайм-ауты, размер пакетов и другие настройки, имеющие значение для консенсуса, соответствовали сети.

Чтобы упростить процесс, вы можете попросить сетевого администратора предоставить отредактированную версию `config.toml`, которая исключает привилегированную информацию, такую как приватные ключи сетевых узлов.

#### 3. Подайте инструкцию {#_3-submit-the-instruction}

После того как ваш сетевой узел будет запущен, вам следует отправить инструкцию регистрации узла. Сетевой узел пройдет процесс рукопожатия и начнет общение с сетью.

::: tip

Отправка инструкции регистрации сетевого узла не создаёт (и не может создать) новый процесс сетевого узла.

:::

### Отмена регистрации сетевых узлов {#unregistering-peers}

Как насчёт отмены регистрации сетевых узлов? По соображениям безопасности этот процесс односторонний. Сеть приходит к консенсусу, что хочет удалить сетевой узел, но сам сетевой узел мало что знает о том, почему с ним никто не общается.

В большинстве случаев, если вы хотите отписать сетевого узла, вы хотите сделать это потому, что это византийская ошибка. Просто «исчезновение» этого сетевого узла усложняет жизнь злоумышленнику в сети.
