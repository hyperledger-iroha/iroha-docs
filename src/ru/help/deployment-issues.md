# Решение проблем с развертыванием {#troubleshooting-deployment-issues}

В данном разделе приведены советы по решению неполадок Iroha 3 В случае возникновения проблемы
Вы переживаете не описывается здесь,
свяжитесь с нами через [Телеграмм](https://t.me/hyperledgeriroha).

## Начните с генерируемых артефактов . {#start-with-generated-artifacts}

Для локальных и испытательных развертываний предпочтительнее артефакты, созданные Kagami Вместо этого
из ручно написанных файлов сверстников:

```bash
cargo run --bin kagami -- localnet --build-line iroha3 --peers 4 --out-dir ./localnet
```

В генерируемом каталоге содержится конфигурация сверстников, материалы по генезису, начало
Сценарии, а также README для Iroha 3 строительная линия.

## Сверстник не начинается {#peer-does-not-start}

Сначала проверьте эти предметы:

- `irohad --config <path>` Показатели на собственный счет TOML Досье.
- `public_key` и `private_key` в конфигурации сверстников принадлежат к тому же ключу
  Пару.
- `genesis.public_key` совпадает с ключом, использованным для подписания сделки генезиса.
- использование идентификационных данных сверстников-валидаторов BLS- Нормальные ключи, и `trusted_peers_pop`
  содержит записи, подтверждающие владение местным ключом и доверенными партнерами.
- порты для Torii и P2P уже не связаны другим процессом.
- в) Kura Справочник магазина относится к той же цепочке и не был скопирован из
  различный профиль сети.

Используйте конфигурационный отслеживание , когда демона читает более одного TOML слой:

```bash
cargo run --bin irohad -- --config ./config.toml --trace-config
```

## Docker и составить {#docker-and-compose}

Составлять из текущего Kagami localnet выход так командная линия
Аргументы и конфигурационные файлы совпадают с выведенным кодом:

```bash
cargo run --bin kagami -- localnet --build-line iroha3 --peers 4 --out-dir ./localnet
cargo run --bin kagami -- docker --peers 4 --config-dir ./localnet --image hyperledger/iroha:dev --out-file ./localnet/docker-compose.yml --force
docker compose -f ./localnet/docker-compose.yml up
```

Если развертывание композиции начинается, а затем останавливается, проверьте журналы демонов на:

- несовместимые `chain`
- один партнер, использующий другую генезисную транзакцию или манифест
- объявленные P2P адресы, которые работают только в сети контейнеров
- повторное использование местного объема после регенерации генезиса

При тестировании нового генезиса удалите старый Kura объемы перед перезагрузкой
Сохранение старых блоков с новым генезисом сделает воспроизведение неудачным.

## Кубернеты {#kubernetes}

Для Kubernetes, рассматривать каждый валидатор как государственная инфраструктура:

- дать каждому партнеру стабильный ключ идентичности и стабильный постоянный объем
- разоблачать P2P адресы, которые другие коллеги могут решить изнутри кластера
- монтировать конфигурацию и файлы генезиса как неизменную конфигурации для развертывания
- Все изменения в генезисе или топологии осуществляются преднамеренно, а не как автоматическое
  обновление конфигурационной карты

Если капсула возобновляется неоднократно, сравнить представленную конфигурацию в капсуле с
ожидаемое [`peer.template.toml`](/ru/reference/peer-config/index.md#template) и
проверить , что реверс воспроизводит старый Kura данные.

## Профиль Соры {#sora-profile}

Iroha 3 развертывания, которые используют Nexus, SoraFS, или должны начаться многополосные потоки
дэймон с профилем Sora включен:

```bash
cargo run --bin irohad -- --config ./config.toml --sora
```

Используйте один и тот же профиль последовательно для validators в одной сети.
