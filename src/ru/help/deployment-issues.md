# Устранение неполадок развертывания {#troubleshooting-deployment-issues}

Этот раздел предлагает советы по устранению неполадок для развертываний Iroha 3. Если описанная проблема не соответствует вашей, свяжитесь с нами через [Телеграм](https://t.me/hyperledgeriroha).

## Начните с сгенерированных артефактов {#start-with-generated-artifacts}

Для локальных и тестовых развертываний предпочтительно использовать артефакты, сгенерированные Kagami, вместо вручную написанных файлов узлов сети:

```bash
cargo run --bin kagami -- localnet --peers 4 --out-dir ./localnet
```

Созданный каталог содержит конфигурации сетевых узлов, материалы генезиса блокчейна, стартовые скрипты и README для сборочной линии Iroha 3.

## сетевой узел не запускается {#peer-does-not-start}

Сначала проверьте эти пункты:

- `iroha3d --config <path>` указывает на собственный файл TOML сетевого узла.
- `public_key` и `private_key` в конфигурации сетевого узла принадлежат одной и той же паре ключей.
- `genesis.public_key` соответствует ключу, использованному для подписи транзакции генезиса блокчейна.
- Идентификаторы участников сети валидаторов используют ключи BLS-Normal, а `trusted_peers_pop` содержит записи о доказательствах владения для локального ключа и доверенных участников сети.
- порты для Torii и P2P еще не заняты другим процессом.
- Каталог магазина Kura принадлежит той же сети и не был скопирован с другого сетевого профиля.

Используйте трассировку конфигурации, когда демон читает более одного слоя TOML:

```bash
cargo run -p irohad --bin iroha3d -- --config ./config.toml --trace-config
```

## Docker и Compose {#docker-and-compose}

Сгенерируйте Compose из текущего вывода локальной сети Kagami, чтобы аргументы командной строки и файлы конфигурации соответствовали выкачанному коду:

```bash
cargo run --bin kagami -- localnet --peers 4 --out-dir ./localnet
cargo run --bin kagami -- docker --peers 4 --config-dir ./localnet --image hyperledger/iroha:dev --out-file ./docker-compose.yml --force
docker compose -f ./docker-compose.yml up
```

Если развертывание Compose начинается, а затем останавливается, проверьте журналы демона на наличие:

- несовпадающий `chain`
- один сетевой узел использует другую генезис-транзакцию блокчейна или технический манифест
- рекламируемые P2P адреса, которые работают только внутри сети контейнера
- повторное использование локального тома после восстановления генезиса блокчейна

При тестировании нового блока генезиса блокчейна удалите старые тома Kura перед перезапуском стека. Сохранение старого хранилища блоков с новым генезисом блокчейна приведет к сбою воспроизведения.

## Kubernetes {#kubernetes}

Для Kubernetes рассматривайте каждого валидатора как инфраструктуру с сохранением состояния:

- дать каждому сетевому узлу стабильный идентификационный ключ и стабильный постоянный том
- раскрывать P2P адреса, которые другие участники сети могут разрешать изнутри кластера
- монтировать файлы конфигурации и генезиса блокчейна как неизменяемую конфигурацию для развертывания
- разворачивать все изменения генезиса или топологии блокчейна намеренно, а не как автоматическое обновление конфигурационной карты

Если под перезапускается неоднократно, сравните сгенерированную конфигурацию в паде с ожидаемой [`peer.template.toml`](/ru/reference/peer-config/index.md#template) и проверить, воспроизводит ли сетевой узел старые данные Kura данные.

## Профиль Соры {#sora-profile}

Частные или локальные развертывания Iroha 3, которые используют Nexus, SoraFS или многополосные потоки, должны запускать стандартный демон с включенным профилем Sora:

```bash
cargo run -p irohad --bin iroha3d -- --config ./config.toml --sora
```

Используйте один и тот же профиль последовательно на всех валидаторах в одной сети.

Публичные валидаторы Taira используют специальный модуль запуска, который обеспечивает точное соответствие цепочке Taira, составу участников, профилю с отключённым встроенным хранилищем SoraFS и профилю криптографического подписанта среды выполнения. Перед запуском проверьте сформированную конфигурацию Taira:

```bash
iroha3d_taira --sora \
  --config /etc/iroha/taira/config.toml \
  --check-config
```

Не начинайте публичное Taira валидатор с дженериком `iroha3d`; смотреть на [`iroha3d` CLI ссылка](/ru/reference/iroha3d-cli.md) для принудительного профиля.
