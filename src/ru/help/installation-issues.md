# Проблемы с установкой {#troubleshooting-installation-issues}

В данном разделе приведены советы по решению неполадок Iroha 3 установки.
Проблема, с которой вы столкнулись, не описана здесь.

## Быстрые проверки {#quick-checks}

Большинство неисправностей при установке происходят из одного из четырех мест:

- а) Rust цепь инструментов старше версии, закрепленной на рабочем пространстве вверх потока
- `cargo` или `rustc` на установку, отличную от `rustup`
- отсутствующие инструменты по созданию системы, такие как компилятор C, `pkg-config`, или CMake
- устаревшие выдержки или локальные артефакты после изменения источника
  Ревизии

От: Iroha исходная касса, начиная с:

```bash
rustup show
cargo --version
rustc --version
cargo metadata --no-deps
```

Если `cargo metadata` не удается, исправить локальную цепочку инструментов перед запуском
`pnpm refresh:iroha --source /path/to/iroha`, потому что обновление может вызвать
Kagami для создания текущей схемы модели данных.

### Проверка Rust версия {#check-rust-version}

В интересах сохранения вашего и нашего здравого смысла, убедитесь, что вы
иметь правильную версию `cargo` в паре с правильной версией `rustc`.
Текущее рабочее пространство вверх потока заявляет `rust-version = "1.92"` и запёрки
канал инструментальной цепи в `rust-toolchain.toml`. Чтобы показать версии, сделать

```bash
$ cargo -V
$ cargo 1.93.1 (...)
```

И потом

```bash
$ rustc --version
$ rustc 1.93.1 (...)
```

Если у вас есть более высокие версии, вы в порядке.
может запустить следующую команду для обновления:

```bash
$ rustup toolchain update stable
```

### Проверяйте место установки {#check-installation-location}

Если вы получите более низкие номера версии **и** Вы обновили цепочку инструментов и она
не сработало... скажем, это общая проблема, но у нее нет
общее решение.

Во-первых, вы должны установить, где версия, которую вы хотите использовать
установлены:

```bash
$ rustup which rustc
$ rustup which cargo
```

Пользовательские установки цепей инструментов: _обычно_ в
`~/.rustup/toolchains/stable-*/bin/`. Если это так, то вы должны быть
умеют бегать

```bash
$ rustup toolchain update stable
```

и это должно решить твои проблемы.

### Проверьте дефолт Rust версия {#check-the-default-rust-version}

Другой вариант - иметь обновленную информацию `stable` инструментальной цепи, но это
не установлено по умолчанию.

```bash
$ rustup default stable
```

Это может произойти, если вы установили `nightly` версии, или устанавливает конкретный
Rust Версия, но забыл отремонтировать.

### Проверьте, есть ли другие Rust версии {#check-if-there-are-other-rust-versions}

Продолжая искать проблему в кроличьей дыре, мы могли бы получить снаряд
прозвища:

```bash
$ type rustc
$ type cargo
```

Если они указывают на другие места, кроме тех, которые вы видели во время бега
`rustup which *`, В этом случае у вас возникнет проблема.
Просто...

```bash
$ alias rustc "~/.rustup/toolchains/stable-*/bin/rustc"
$ alias cargo "~/.rustup/toolchains/stable-*/bin/cargo"
```

потому что есть внутренняя логика, которая может сломаться, независимо от того, как вы
Переоборудовать свои псевдонимы.

Проще всего удалить не используемые версии.

Это проще. _сказал_ более чем _Сделано_, Однако, поскольку это влечет за собой отслеживание всех
версии rustup Обычно, есть только
Второй вариант: система менеджера пакетов и тот, который был установлен в
стандартное местоположение в домашней папке, когда вы запустили команду в
Для первого, ознакомьтесь с вашим (Linux)
Руководство по распределению (`apt remove rust`В случае последнего, выполните:

```bash

```

И тогда, за каждое `<toolchain>` (без угловых скобков, конечно):

```bash

```

После этого убедитесь, что

```

```

## Устранение проблем Python цепь инструментов {#troubleshooting-python-toolchain}

Когда вы устанавливаете Python Пакет колес с использованием трубки во время [Python настройка клиента](/ru/guide/tutorials/python.md), Вы можете столкнуться с такой ошибкой:
"Ироха_Питон...*.whl не является подкрепленным колесом на этой платформе".

Эта ошибка означает, что pip устарела, поэтому вам нужно обновить его.
Прежде всего, рекомендуется проверить OS для обновлений и осуществления модернизации системы.

Если это не сработает, попробуйте обновить `pip` для вашего каталога пользователей.

`python -m pip install --upgrade pip`

Убедись, что `pip` Для этого запустите `whereis pip` и проверить, `/home/username/.local/bin/pip` В противном случае, обновьте свой снаряд. `PATH` переменная.

Если проблема продолжается, пожалуйста. [свяжитесь с нами](/ru/help/) и сообщать о результатах.

```
python --version
python3 --version
pip --version
pip3 --version
```
