# Устранение проблем с установкой {#troubleshooting-installation-issues}

Этот раздел предлагает советы по устранению неполадок при установке Iroha 3. Если описанная здесь проблема не соответствует вашей, свяжитесь с нами через [Телеграм](https://t.me/hyperledgeriroha).

## Быстрые проверки {#quick-checks}

Большинство сбоев при установке происходят по одной из четырёх причин:

- цепочка инструментов Rust старее версии, закрепленной в верхнеуровневом рабочем пространстве
- `cargo` или `rustc`, разрешающие на другую установку, чем `rustup`
- отсутствуют системные инструменты сборки, такие как компилятор C, `pkg-config` или CMake
- устаревшие сгенерированные фрагменты или локальные артефакты сборки после изменения версий исходного кода

Из рабочей копии исходного кода Iroha начните с:

```bash
rustup show
cargo --version
rustc --version
cargo metadata --no-deps
```

Если `cargo metadata` не удается, исправьте локальную цепочку инструментов перед запуском `pnpm refresh:iroha --source /path/to/iroha`, потому что обновление может вызвать Kagami для генерации текущей схемы модели данных.

## Устранение неполадок Rust цепочки инструментов {#troubleshooting-rust-toolchain}

Иногда всё идёт не по плану. Особенно если некоторое время назад у вас была `rust` на системе, но вы не обновили её. Похожая проблема может возникнуть в Python: у XKCD есть известный пример того, как это может выглядеть:

### Проверьте версию Rust {#check-rust-version}

В интересах сохранения как вашего, так и нашего рассудка, убедитесь, что у вас правильная версия `cargo`, совмещенная с правильной версией `rustc`. Текущее исходное рабочее пространство объявляет `rust-version = "1.92"` и фиксирует канал инструментов в `rust-toolchain.toml`. Чтобы показать версии, выполните

```bash
$ cargo -V
$ cargo 1.93.1 (...)
```

а затем

```bash
$ rustc --version
$ rustc 1.93.1 (...)
```

Если у вас более новые версии, всё в порядке. Если у вас более старые версии, вы можете выполнить следующую команду для их обновления:

```bash
$ rustup toolchain update stable
```

### Проверьте место установки {#check-installation-location}

Если у вас появляются более низкие номера версий, и вы обновили набор инструментов, и это не сработало… скажем так, это распространённая проблема, но у неё нет распространённого решения.

Во-первых, вы должны определить, где установлена версия, которую вы хотите использовать:

```bash
$ rustup which rustc
$ rustup which cargo
```

Пользовательские установки наборов инструментов обычно находятся в `~/.rustup/toolchains/stable-*/bin/`. Если это так, вы должны иметь возможность запустить

```bash
$ rustup toolchain update stable
```

и это должно решить ваши проблемы.

### Проверьте версию по умолчанию Rust {#check-the-default-rust-version}

Другой вариант заключается в том, что у вас есть актуальный набор инструментов `stable`, но он не установлен по умолчанию. Выполните:

```bash
$ rustup default stable
```

Установка версии `nightly` или установка конкретной версии Rust без последующего снятия этой установки может вызвать эту проблему.

### Проверьте, есть ли другие версии Rust {#check-if-there-are-other-rust-versions}

Продолжая углубляться в устранение неполадок, у нас могут быть алиасы оболочки:

```bash
$ type rustc
$ type cargo
```

Если они указывают на другие места, отличные от того, которое вы видели при запуске `rustup which *`, то у вас проблема. Обратите внимание, что добавление таких псевдонимов недостаточно:

```bash
$ alias rustc "~/.rustup/toolchains/stable-*/bin/rustc"
$ alias cargo "~/.rustup/toolchains/stable-*/bin/cargo"
```

Внутренняя логика всё равно может сломаться, независимо от того, как вы расположите свои алиасы оболочки.

Самым простым решением было бы удалить версии, которыми вы не пользуетесь.

Однако это легче сказать, чем сделать, так как это подразумевает отслеживание всех версий rustup, установленных и доступных вам. Обычно их всего две: версию системного менеджера пакетов и ту, которая была установлена в стандартное место в вашей домашней папке, когда вы выполнили команду в начале этого руководства. Для первого случая обратитесь к руководству вашей (Linux) дистрибуции, (`apt remove rust`). Для второго выполните:

```bash
$ rustup toolchain list
```

А затем, для каждого `<toolchain>` (без угловых скобок, конечно):

```bash
$ rustup remove <toolchain>
```

После удаления наборов инструментов эта команда должна выдавать ошибку «команда не найдена»:

```bash
$ cargo --help
```

Эта ошибка подтверждает, что ни одна активная сборочная цепочка Rust больше не установлена. Затем выполните:

```bash
$ rustup toolchain install stable
```

## Устранение неполадок цепочки инструментов Python {#troubleshooting-python-toolchain}

Когда вы устанавливаете пакет Python Wheel с помощью pip во время [Python настройка клиента](/ru/guide/tutorials/python.md), вы можете столкнуться с такой ошибкой: "iroha_python-*.whl не является поддерживаемым wheel на этой платформе".

Эта ошибка означает, что pip устарел, поэтому его необходимо обновить. Прежде всего рекомендуется проверить ваши OS на наличие обновлений и выполнить обновление системы.

Если это не сработает, вы можете попробовать обновить `pip` для вашего пользовательского каталога.

`python -m pip install --upgrade pip`

Убедитесь, что `pip` установлен в вашем домашнем каталоге. Для этого выполните `whereis pip` и проверьте, находится ли `/home/username/.local/bin/pip` среди путей. Если нет, обновите переменную `PATH` вашей оболочки.

Если проблема сохраняется, пожалуйста, [свяжитесь с нами](/ru/help/) и сообщите результаты.

```
python --version
python3 --version
pip --version
pip3 --version
```
