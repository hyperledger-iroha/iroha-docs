# Torii Конечные точки {#torii-endpoints}

Torii Это HTTP, SSE, и WebSocket шлюз для Iroha 3. Это служит обоим.
с учетной записью APIs и конечных точек оператора.

Действующие правила протокола:

- канонический бинарный формат **Norito**
- многие конечные точки также поддерживают JSON когда вы отправляете `Accept: application/json`
- показатели выставлены в формате Prometheus

Для деталей формата, обсуждения контента, флагов макетов, хэши схемы и
Norito RPC руководство, см. [Norito ссылка](/ru/reference/norito.md).

## Общие цели {#common-endpoints}

| Окончательный пункт | Формат | Цель |
| --- | --- | --- |
| `POST /transaction` | Norito | Представление подписанной сделки |
| `POST /query` | Norito | Подать подписанный запрос |
| `GET /events` | WebSocket | Подписаться на потоки событий |
| `GET /block/stream` | WebSocket | Поток обязательных блоков |
| `GET /peers` | JSON | Список сверстников, выявленных Torii |
| `GET /health` | JSON | Конечная точка легкой жизненности |
| `GET /api_version` | JSON | По умолчанию API версия |
| `GET /status` | JSON | Сокращение состояния на высоком уровне для операторов |
| `GET /metrics` | Прометей | Конечная точка скреп-прометей |
| `GET /schema` | JSON | Снимок схемы модели данных , обслуживаемый узлом |
| `GET /openapi` или `GET /openapi.json` | JSON | OpenAPI документ для активного Torii HTTP маршруты |
| `GET /v1/parameters` | JSON | Снимок параметров узла |
| `GET /v1/node/capabilities` | JSON | Возможности узлов и метаданные модели данных |
| `GET /v1/api/versions` | JSON | Поддержка Torii API версии |
| `GET /v1/events/sse` | SSE | Поток событий для долгоживущих клиентов |
| `GET /v1/time/now` | JSON | Снимок узлового стенового часа |
| `GET /v1/time/status` | JSON | Состояние синхронизации времени |

`/openapi` является авторитетным списком конечных пунктов для запущенного узла.
поверхность зависит от функций построения и конфигурации времени запуска, таким образом генерируется
Клиенты должны предпочитать живое OpenAPI документ о списке маршрутов, скопированном вручную.
Используйте [Torii API консоль](/ru/reference/torii-api-console.md) чтобы загрузить это вживую
документ, испытание JSON маршруты, копии curl запросы, и генерировать клиентский код из
текущей схемы.

## Попробуй жить Taira Маршруты {#try-live-taira-routes}

Общественность Taira тестовая сеть раскрывает то же самое Torii JSON поверхность применения
Клиенты используют для изучения только для чтения.

```bash
TAIRA_ROOT=https://taira.sora.org

curl -fsS "$TAIRA_ROOT/status" \
  | jq '{blocks, txs_approved, txs_rejected, queue_size, peers}'

curl -fsS "$TAIRA_ROOT/openapi.json" \
  | jq -r '.paths | keys[]' \
  | grep '^/v1/' \
  | head -n 20

curl -fsS "$TAIRA_ROOT/v1/node/capabilities" \
  | jq '{abi_version, data_model_version, query: .query.aggregate.supported_resources}'
```

Попробуйте ресурс читает против нынешнего состояния мира:

```bash
curl -fsS "$TAIRA_ROOT/v1/domains?limit=5" \
  | jq -r '.items[].id'

curl -fsS "$TAIRA_ROOT/v1/assets/definitions?limit=5" \
  | jq -r '.items[] | [.id, .name, .total_quantity] | @tsv'
```

В случае возвращения маршрута общественного тестирования `502`, время, или сообщает насыщенный
В очереди, рассматривайте это как вопрос о доступности конечных пунктов и попробуйте снова позже
Дебгурируя код клиента.

## ISO Мост 20022 {#iso-20022-bridge}

Torii разоблачает ISO 20022 мост под `/v1/iso20022/*` при обращении в приложение
API Мост преднамеренно определяется:
не для общего назначения ISO 20022 клиринговый шлюз, но поддерживаемый подмножество для
превращение выбранных платежных сообщений в подписанные Iroha перечисления и для отслеживания
их статус в регистре.

### Torii ISO 20022 Конечные точки {#torii-iso-20022-endpoints}

| Метод и конечная точка | Цель |
| --- | --- |
| `POST /v1/iso20022/pacs008` | Подача заявки FI- к...FI перечисление кредитов клиентов и создание совпадения Iroha перечисление активов |
| `POST /v1/iso20022/pacs009` | Подача заявки FI- к...FI кредитный трансферт, используемый для PvP или денежное финансирование, связанное с ценными бумагами |
| `POST /v1/iso20022/pacs002` | Представление отчета о состоянии платежей |
| `POST /v1/iso20022/pacs004` | Подача платежной декларации |
| `POST /v1/iso20022/camt056` | Заявление о отмене платежа |
| `POST /v1/iso20022/sese023` | Подача инструкции по расчету ценных бумаг |
| `POST /v1/iso20022/sese024` | Подача сообщения о состоянии расчета ценных бумаг |
| `POST /v1/iso20022/sese025` | Подача подтверждения расчетов с ценными бумагами |
| `POST /v1/iso20022/colr012` | Подача сообщения о замене гарантий |
| `GET /v1/iso20022/messages/{msg_id}` | Прочитайте запись канонического моста для одного сообщения |
| `GET /v1/iso20022/audit/messages` | Прочитайте манифест аудита сообщений с нарушениями . |
| `GET /v1/iso20022/messages/{msg_id}/pacs002` | Передача текущего состояния платежа как `pacs.002` XML |
| `GET /v1/iso20022/messages/{msg_id}/pacs004` | Выдача текущей платежной декларации как `pacs.004` XML |
| `GET /v1/iso20022/messages/{msg_id}/camt029` | Выдача текущего разрешения на отмену как `camt.029` XML |
| `GET /v1/iso20022/messages/{msg_id}/sese024` | Предоставлять текущий статус расчетов как `sese.024` XML |
| `GET /v1/iso20022/messages/{msg_id}/sese025` | Подача подтверждения текущего расчета как `sese.025` XML |

`pacs.008` в заявлении должно быть сообщение ID, межбанковские расчеты
сумма, валюта, дата расчета, должник и кредитор IBANs, и должника и
кредитор BICs. При настройке справочных данных мост также проверяет
BIC, IBAN, и ISO 4217 валютных переходов до создаваемой транзакции
входит в трубопровод.

`pacs.009` представления должны содержать бизнес-сообщение ID, определение сообщения
ID, время создания, сумма межбанковского расчета, валюта, дата расчета;
инструктор и уполномоченный агент BICs, и должник и кредитор IBANs. Если
сообщение включает `Purp`, мост в настоящее время принимает финансирование для целей ценных бумаг
только: `Purp=SECU`.

Сборник `pacs.008` и `pacs.009` окончательные пункты подачи принимают XML ISO конверты или
формат плоского поля, используемый при испытаниях мостов. `SplmtryData` поля
может застрять на цели Iroha бухгалтерский учет, источник и целевой счет IDs или адреса,
и определение активов ID. Ответ: `202 Accepted` с `message_id`,
`transaction_hash`, `status`, `pacs002_code`, и решенные
контекст бухгалтерского учета/счета/актива.

## Kaigi Заседания {#kaigi-sessions}

Kaigi предоставляет платные аудио/видео комнаты в режиме реального времени SORA Nexus. Используйте его, когда
приложение нуждается в создании сеансов, поддерживаемых реестрами, изменении списка, передаче
манифестации, шифрованная сигнализация и измерение использования вместо того, чтобы хранить все
конференции вне государственной цепи.

Животный цикл, ориентированный на бухгалтерский учет:

- `CreateKaigi`: создать звонок под доменом и хранить его политику,
  график, метаданные и релевый манифест.
- `JoinKaigi` и `LeaveKaigi`: обновлять список звонков.
  участники используют обязательства, аннулирующие и доказательства списка вместо
  учетные записи участников IDs прямо.
- `RecordKaigiUsage`: прибавить измеренную продолжительность и объемы газа.
- `EndKaigi`: Закройте сессию и запишите окончательную часовую печать.

Torii выявляет телеметрию эстафеты под `/v1/kaigi/relays`,
`/v1/kaigi/relays/{relay_id}`, `/v1/kaigi/relays/health`, и
`/v1/kaigi/relays/events` когда приложение API и функции телеметрии включены.
Состояние сессии отражается в Kaigi Доменные события, такие как
`KaigiRosterSummary`, `KaigiRelayManifestUpdated`,
`KaigiRelayHealthUpdated`, и `KaigiUsageSummary`.

### CLI Тест на дым {#cli-smoke-test}

Начнем с `iroha kaigi` CLI когда вы хотите проверить, что Torii конечная точка
принимает Kaigi транзакции до подключения UI. Команда быстрого запуска
создает временную комнату против активных Torii конечная точка и печатает сводку
с идентификатором вызова, присоединяйтесь к команде и SoraNet Напряжение катушки:

```bash
iroha kaigi quickstart --auto-join-host --summary-out kaigi-summary.json
```

Для сценарийных потоков, управлять жизненным циклом комнаты явно:

```bash
iroha kaigi create \
  --domain streaming \
  --call-name daily \
  --host <i105-account-id> \
  --privacy-mode transparent \
  --room-policy authenticated

iroha kaigi join --domain streaming --call-name daily --participant <i105-account-id>
iroha kaigi leave --domain streaming --call-name daily --participant <i105-account-id>

iroha kaigi record-usage \
  --domain streaming \
  --call-name daily \
  --duration-ms 120000 \
  --billed-gas 1500

iroha kaigi end --domain streaming --call-name daily
```

Использование `--room-policy public` для помещений, которые могут быть открыты без зрителя
билеты, или `--room-policy authenticated` когда выходы должны требовать зрителя
аутентификация. `--privacy-mode zk-roster-v1` только после того, как сеть
в) Kaigi Ключи для проверки списка и использования конфигурированы; в противном случае соединения, листы,
и частные записи использования не выполняются во время детерминистической проверки.

## Статус и показатели {#status-and-metrics}

Окончательные точки статуса и показателей являются первыми, которые вводятся в панели управления:

- `/status` раскрывает поля сверстников, блоков, очередей и консенсуса высшего уровня
- `/metrics` выявляет счетчики, метры и гистограммы Прометея

На Nexus- включенные узлы, выход состояния также включает в себя ленту и знание пространства данных
раздел. `nexus.enabled = false`, Эти разделы выпущены.

## JSON В противном случае. Norito {#json-vs-norito}

Некоторые конечные точки оператора возвращаются Norito По умолчанию. Когда конечная точка поддерживает
JSON, отправлять:

```http
Accept: application/json
```

Это особенно полезно для:

- `/v1/sumeragi/status`
- `/v1/sumeragi/qc`
- `/v1/sumeragi/commit_qc/{hash}`

Когда конечный пункт принимает или возвращает запечатанное Norito непосредственно, использование
`application/x-norito` как тип содержания или предпочтительный `Accept` ценность.
[Norito](/ru/reference/norito.md#torii-and-norito-rpc) для деталей перевозки.
