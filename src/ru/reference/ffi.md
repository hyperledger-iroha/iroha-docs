# Иностранные интерфейсы функций (FFI) {#foreign-function-interfaces-ffi}

Сборник `iroha_ffi` ящик обеспечивает макросы и черты для создания C ABI
обязательства от Rust APIs. Используется, когда Iroha типы должны пересечь FFI
границы, например SDK связывания или интеграции хоста.

## Почему ? FFI {#why-ffi}

Функция - это довольно абстрактная единица, и хотя большинство языков соглашаются на
что должна делать функция, способ, которым представлены функции
Кроме того, на некоторых языках, таких как Rust, последствия
Именно поэтому мы должны быть готовы к тому, что это может быть.
- Когда? Rust APIs необходимо быть вызванным из другого языка или
различная среда приема, Iroha использует внешний функциональный интерфейс (FFI)
чтобы выравнить условия.

Основной стандарт, используемый сегодня, - это бинарный интерфейс приложений C.
Простые, широко доступные и стабильные.
Все ручно, но Iroha обеспечивает `iroha_ffi` коробка для генерации
FFI- соответствующие функции из существующих Rust API.

Вы можете сделать это по-своему. `iroha_ffi` ящик только
создает код, который вам нужно будет генерировать.
Необходимая котельная плитка требует довольно мало усердия и дисциплины.
Каждый функционный звонок по FFI Граница `unsafe` с потенциалом
способ, которым мы смогли решить эту проблему.
обращается вокруг **прочный** `repr(C)` Типы.

::: info

Единственное исключение - указатели.
При этом, как и всегда, сырые указатели используются только в исключительных случаях.
Принимая во внимание, что мы предоставляем обложки почти в каждом случае
объекта в Iroha данные модели, вы не должны использовать сырые указатели на
Все это.

:::

## Пример {#example}

Вот пример создания связывания:

```rust
#[derive(FfiType)]
struct DaysSinceEquinox(u32);

#[ffi_export]
impl DaysSinceEquinox {
    pub fn update_value(&mut self, a: &u8) {
        self.0 = *a as u32;
    }
}
```

В приведенном выше примере будет создано следующее связывание с
`DaysSinceEquinox` представленный в виде непрозрачного указателя:

```rust
pub extern fn DaysSinceEquinox__update_value(handle: *mut DaysSinceEquinox, a: *const u8) -> FfiReturn {
    // function implementation
}
```

## FFI Связывающее поколение {#ffi-binding-generation}

Сборник `iroha_ffi` ящик используется для генерации функций, которые могут быть вызваны через
FFI. Указанные `Rust` Строки и методы, они создают `unsafe` код, который
Вам понадобится, чтобы пересечь границу.

А Rust тип превращается в прочный `repr(C)` тип, который может пересечь
FFI границы с `FfiType::into_ffi`. Это происходит наоборот, как
Что ж: FFI `ReprC` тип преобразуется в `Rust` тип через
`FfiType::try_from_ffi`.

::: warning

Обратите внимание, что противоположное преобразование является ошибочным и может вызвать неопределенное
В то время как мы можем сделать все возможное, чтобы избежать наиболее очевидных
Если вы ошибаетесь, вы должны убедиться в правильности программы.

:::

The основные характеристики, которые позволяют создавать связь `ReprC`, `FfiType`, и
`FfiConvert`.

| Традиция        | Описание                                                                                                                                                                     |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ReprC`      | Эта черта представляет собой прочный тип, который соответствует C ABI. Тип можно безопасно разделить между FFI границы.                                                                |
| `FfiType`    | Эта черта определяет соответствующую `ReprC` тип для данного `Rust` тип. `ReprC` тип используется вместо `Rust` тип в API из генерируемого FFI функции. |
| `FfiConvert` | Эта черта определяет два метода `into_ffi` и `try_from_ffi` которые используются для осуществления преобразования `Rust` тип к или от `ReprC` Тип.                                |

Обратите внимание, что нет передачи собственности на FFI за исключением непрозрачного указателя
Все другие типы, которые несут собственность, например: `Vec<T>`, Клонируются.

### Название Манглинг {#name-mangling}

Обратите внимание на использование двойных подсказок в генерируемых названиях FFI объекты:

- Для `inherent_fn` метод, определенный в `StructName` Структура, FFI
  название будет `StructName__inherent_fn`.
- Для `MethodName` Метод из `TraitName` особенности в
  `StructName` Структура, FFI название будет
  `StructName__TraitName__MethodName`.
- Чтобы установить `field_name` поле в `StructName` Структура, FFI
  название функции будет `StructName__set_field_name`.
- Чтобы получить `field_name` поле в `StructName` Структура, FFI
  название функции будет `StructName__field_name`.
- Чтобы получить изменчивое `field_name` поле в `StructName` Структура, FFI
  название функции будет `StrucuName__field_name_mut`.
- Для самостоятельных `module_name::fn_name`, в) FFI название будет
  `module_name::__fn_name`.
- Для особенностей, которые не являются общими и позволяют делиться их
  реализация в FFI (см. `Clone` (далее) FFI название будет
  `module_name::__clone`.

  ```rust
  impl Clone for Type1 {
      fn clone(&self) -> Self;
  }
  impl Clone for Type2 {
      fn clone(&self) -> Self;
  }
  ```
