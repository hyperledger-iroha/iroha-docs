# Интерфейсы внешних функций (FFI) {#foreign-function-interfaces-ffi}

Пакет программного обеспечения `iroha_ffi` предоставляет макросы и трейты для генерации C ABI привязок из Rust APIs. Он используется там, где типы Iroha должны пересекать границу FFI, например, с помощью SDK привязок или интеграций с хостом.

## Почему FFI {#why-ffi}

Функция — это довольно абстрактная сущность, и хотя большинство языков согласны с тем, что функция должна делать, способ, которым функции представлены, сильно различается. Более того, в некоторых языках, таких как Rust, последствия вызова функции и то, что ей разрешено делать, также различаются. Когда Rust APIs необходимо вызывать из другого языка или другой хост-среды, Iroha использует интерфейс внешних функций (FFI), чтобы уравнять условия игры.

Основным стандартом, используемым сегодня, является бинарный интерфейс приложений C. Он прост, широко доступен и стабилен. В принципе, можно было бы делать всё вручную, но Iroha предоставляет программный пакет `iroha_ffi` для генерации функций, соответствующих FFI, из существующего Rust API.

Разумеется, это можно реализовать самостоятельно. Крейт `iroha_ffi` лишь генерирует код, который иначе пришлось бы писать вручную. Создание необходимого шаблонного кода требует большой аккуратности и дисциплины. Каждый вызов функции через границу FFI является `unsafe` и потенциально способен вызвать неопределённое поведение. Мы решаем эту задачу с помощью безопасных типов `repr(C)`.

::: info

Единственным исключением являются указатели. Проверку на null и проверку корректности нельзя применять глобально, поэтому сырые указатели (как всегда) используются только в исключительных случаях. Учитывая, что мы предоставляем программные адаптеры практически для каждого экземпляра объекта в модели данных Iroha, вам вообще не нужно использовать сырые указатели.

:::

## Пример {#example}

Вот пример создания привязки:

```rust
#[derive(FfiType)]
struct DaysSinceEquinox(u32);

#[ffi_export]
impl DaysSinceEquinox {
    pub fn update_value(&mut self, a: &u8) {
        self.0 = *a as u32;
    }
}
```

Пример выше создаст следующую привязку с `DaysSinceEquinox`, представленным в виде непрозрачного указателя:

```rust
pub extern fn DaysSinceEquinox__update_value(handle: *mut DaysSinceEquinox, a: *const u8) -> FfiReturn {
    // function implementation
}
```

## FFI Генерация привязки {#ffi-binding-generation}

Программный пакет `iroha_ffi` используется для генерации функций, которые можно вызывать через FFI. Учитывая структуры и методы `Rust`, они генерируют код `unsafe`, который вам потребуется для пересечения границы связывания.

Тип Rust преобразуется в надежный тип `repr(C)`, который может пересекать границу FFI с помощью `FfiType::into_ffi`. Это работает и в обратную сторону: тип FFI `ReprC` преобразуется в тип `Rust` через `FfiType::try_from_ffi`.

::: warning

Обратите внимание, что обратное преобразование ненадежно и может вызвать неопределённое поведение. Несмотря на то что мы можем приложить максимум усилий, чтобы избежать наиболее очевидных ошибок, вы должны самостоятельно обеспечить правильность работы программы.

:::

Основными чертами, которые позволяют генерировать привязку, являются `ReprC`, `FfiType` и `FfiConvert`.

|Черта|Описание|
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ReprC`      |Эта характеристика представляет собой надежный тип, который соответствует C ABI. Этот тип можно безопасно использовать через границы FFI.|
| `FfiType`    |Это свойство определяет соответствующий тип `ReprC` для данного типа `Rust`. Определённый тип `ReprC` используется вместо типа `Rust` в API сгенерированной функции FFI.|
| `FfiConvert` |Этот трейд определяет два метода `into_ffi` и `try_from_ffi`, которые используются для выполнения преобразования типа `Rust` в тип `ReprC` или из него.|

Обратите внимание, что передача права собственности на FFI не осуществляется, за исключением непрозрачных указателей. Все другие типы, которые несут право собственности, такие как `Vec<T>`, клонируются.

### Искажение имен {#name-mangling}

Обратите внимание на использование двойного подчеркивания в сгенерированных именах объектов FFI:

- Для метода `inherent_fn`, определённого в структуре `StructName`, имя FFI будет `StructName__inherent_fn`.
- Для метода `MethodName` из трейта `TraitName` в структуре `StructName`, имя FFI будет `StructName__TraitName__MethodName`.
- Чтобы установить поле `field_name` в структуре `StructName`, имя функции FFI будет `StructName__set_field_name`.
- Чтобы получить поле `field_name` в структуре `StructName`, имя функции FFI будет `StructName__field_name`.
- Чтобы получить изменяемое поле `field_name` в структуре `StructName`, имя функции FFI будет `StrucuName__field_name_mut`.
- Для отдельно стоящего `module_name::fn_name` имя FFI будет `module_name::__fn_name`.
- Для черт, которые не являются общими и позволяют совместное использование их реализации в FFI (см. `Clone` ниже), имя FFI будет `module_name::__clone`.

  ```rust
  impl Clone for Type1 {
      fn clone(&self) -> Self;
  }
  impl Clone for Type2 {
      fn clone(&self) -> Self;
  }
  ```
