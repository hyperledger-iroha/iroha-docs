# Norito {#norito}

Norito является Iroha Канонический слой сериализации.
когда они будут сверстниками SDKs, CLI инструменты, Torii, Kura, и генерируемые артефакты должны согласиться
на той же полезной нагрузке.

Использование Norito когда данные являются частью консенсуса, подписания, хэширования, упорства;
или перекрестный SDK совместимость. JSON когда конечный пункт явно предлагает
человекочитаемая проекция для операторов, панелей управления или быстрой дебюгировки.

## Где Norito Появляется {#where-norito-appears}

| Поверхность | Как? Norito используется |
| --- | --- |
| Транзакции и запросы | Подписанные транзакции и полезные загрузки запросов, представленные через Torii Кодируются как Norito. |
| Бытие | `kagami genesis sign` производит подписанный `.nrt` блокируйте загрузку сверстников при запуске. |
| Torii Ответы в типе | Конечные точки, которые поддерживают использование типовых бинарных ответов `Accept: application/x-norito`. |
| SDKs | Rust, Python, JavaScript, Kotlin/Java, Swift, и Android клиенты используют Norito конструкторы или связы вместо ручно сборных байтов. |
| Kura хранение | Блоковые полезные нагрузки, боковые машины для восстановления, списки и маркеры обязательств хранятся как Norito-Фрамовые данные. |
| Манифесты | Nexus, доступность данных, SoraFS, использование потоковых и ориентированных на приложение манифестов Norito когда манифест должен быть подписан или расширен. |
| Поток | Norito Использование потоковой передачи Norito манифесты, заголовки сегментов, кадра управления и устройства соответствия. |

Norito Это не умный контрактный язык.
Кодекс, который содержит транзакции, контрактные звонки, манифестирует и печатается API
полезные грузы.

## Модель полезного груза {#payload-model}

Каждый провод или диск Norito полезная нагрузка закреплена заголовком, за которым следует
Загрузки без заголовка или голые, предназначены для внутренних
хэширование, эталоны и помощник APIs которые немедленно завершают результат в
заголовок перед транспортировкой.

| Поле заголовка | Размер | Цель |
| --- | ---: | --- |
| Магия | 4 байта | ASCII `NRT0`, используется для отказа от Norito У нас есть ранние данные |
| Майор | 1 байт | Формат основного варианта. `0`. |
| Маленький | 1 байт | Фиксированный v1 декодирующий намек. `0x00`; Выбор дизайна живет в флагах. |
| Схема гаширования | 16 байтов | Идентификация типа, используемая для отвержения неожиданных полезных нагрузок. |
| Сжатие | 1 байт | `0 = None`, `1 = Zstd`. Неизвестные значения отвергаются. |
| Длина полезной нагрузки | 8 байтов | Некомпрессированная длина полезной нагрузки как миниатюрная `u64`. |
| CRC64 | 8 байтов | CRC64-XZ контрольная сумма несжатого полезного груза. |
| Флаги | 1 байт | Лейтенантные знаки для компактных длин, упакованных последовательностей и упакованной строчки. |

Заголовок 40 байтов. Декодеры подтверждают магию, версию, поддерживаемый флаг
Маска, длина полезной нагрузки, сумма проверки и хэш схемы перед реконструкцией
типовое значение.

## Флаги расположения {#layout-flags}

Norito Сохраняет варианты расположения в последнем байте заголовка.
выпускают `COMPACT_LEN` (`0x02`) для компактных префиксов длины на значение.
Префиксы с фиксированной шириной длины остаются читаемыми, когда звонки кодируют
`flags = 0x00`.

| Флаг | Хекс | Статус | Влияние |
| --- | ---: | --- | --- |
| `PACKED_SEQ` | `0x01` | Поддержка | Кодирует коллекции переменного размера с таблицей оффсета плюс сопутствующим блоком данных. |
| `COMPACT_LEN` | `0x02` | По умолчанию | Использует канонические неподписанные варинты для префиксов длины на значение. |
| `PACKED_STRUCT` | `0x04` | Поддержка | Кодируются производные структуры как упакованные полевые нагрузки. |
| `VARINT_OFFSETS` | `0x08` | Ограниченные | Отклоняется в v1; компенсации упакованной последовательности являются фиксированной шириной `u64`. |
| `COMPACT_SEQ_LEN` | `0x10` | Ограниченные | Отклоняется в v1; заголовки высокого уровня длины последовательности являются фиксированной шириной `u64`. |
| `FIELD_BITSET` | `0x20` | Поддержка требованиями | Добавляет набор битов для упакованных строков, поэтому только поля, которые требуют выраженного размера, имеют префиксы размера. `PACKED_STRUCT` и `COMPACT_LEN`. |

Декодеры не делают выводы из формы полезной нагрузки.
Неизвестные или недействительные комбинации отклоняются таким образом.
что все сверстники интерпретируют полезную нагрузку одинаково.

## Правила кодирования {#encoding-rules}

Norito использует детерминистические макеты для общих форм данных, которые появляются в
в) Iroha модель данных:

- Струнки `[len][utf8-bytes]`; `len` следующее `COMPACT_LEN` когда это возможно.
- Длинные значения используют компактные варинты, когда: `COMPACT_LEN` установлен, в противном случае
  фиксированный 8-байтный маленький эндиан `u64`.
- Заголовки длины последовательности фиксируются 8-байтным небольшим эндианом `u64` в V1.
- `Vec<u8>` кодируется как `[len_u64][raw-bytes]` вместо одной длины на байт.
- Использование упакованных последовательностей `(len + 1)` монотонные `u64` компенсации, за которыми следует
  конкатенированные элементы полезных нагрузок.
- Карты кодируют учетные записи с фиксированными `u64` и использовать детерминистический порядок ключей.
  `HashMap` записки сортируются по ключам перед кодированием; `BTreeMap` использует свои
  естественный порядок.
- `BigInt` использует небольшие эндианские 2's-дополнительные байты с `u32` длина байтов
  и 512-битная крышка.
- `Numeric` кодируется как `(mantissa, scale)`, где мантисса хранит
  Целые числа и масштабы хранят количество фракционных цифр.

Эти правила важны для подписей и хэши. SDKs которые строят то же самое
логическая транзакция должна производить те же канонические байты.

## Схема шейхов {#schema-hashes}

Типовые Norito полезные нагрузки имеют 16-байтный хэш схемы в заголовке.
hash происходит от полностью квалифицированного названия типа.
структурная схема хэшинг получает хэш из канонической схемы вместо этого.

Типовые декодеры отвергают несоответствия схемы.
расшифровка действительной Norito рама как неправильный тип и является обычным режимом неисправности
когда SDK фиксированный пакет дифференцируется от модели данных узлов.

## Сжатие и ускорение {#compression-and-acceleration}

Norito поддерживает выраженное и адаптивное сжатие без изменения логического
полезная нагрузка:

| Особенность | Цель |
| --- | --- |
| `to_bytes` | Зашифровать некомпрессированную полезную нагрузку с заголовками. |
| `to_compressed_bytes` | Зашифровать с помощью Zstd и записать тег на сжатие в заголовке. |
| `to_bytes_auto` | Применяйте детерминистическую эвристику, чтобы определить, стоит ли сжатие. |
| CRC64 ускорение | Использование портативных устройств CRC64-XZ везде, с CLMUL на x86_64 или PMULL на aarch64 при наличии. |
| GPU CRC64 и сжатие | Выборный металл или CUDA помощники могут ускорить большие полезные нагрузки, а затем упасть обратно CPU Пути. |

Ускорение оборудования никогда не меняет декодированное содержание. CRC и JSON
акселераторы должны соответствовать портативному выходу бит-за-битом.
различаются между CPU и GPU кодировщики, но декодированная полезная нагрузка и Norito заголовок
метаданные остаются детерминирующими для валидации.

## JSON Поддержка {#json-support}

Norito включает в себя родного JSON накладка для конечных пунктов и инструментов, которые необходимы JSON
без выхода из Norito типная система.

| JSON особенность | Случай использования |
| --- | --- |
| `norito::json::{to_json, from_json}` | Детерминистический тип JSON кодирование/декодирование. |
| Красивые и писательские помощники | CLI выходные, фиксаторы и потоковые `std::io` интеграции. |
| DOM ценности | Программная манипуляция через Norito Я ... JSON модель стоимости. |
| Быстрый типограф JSON | Декодирование/кодирование на основе структурной ленты для горячего DTO Пути. |
| Читатель нулевой копии | Сканирование токена, которое заимствует строки из ввода, когда это возможно. |
| Ускорители стадии 1 | По умолчанию AVX2, NEON, Металл, или CUDA структурная индексация с скалярным отступлением. |

Iroha код должен быть предпочтительным `norito::json` помощники для типов API полезные нагрузки
простые `serde_json` для производственных путей риски, отличающиеся от схемы и
поведение в области обработки, ожидаемое SDKs и Torii экстракторы.

## Поддержка по производству {#derive-support}

Rust типы данных обычно используют производные макро вместо ручного кодекса.
Степень производных может генерировать Norito двойные кодеки, схемы и JSON Помощники.

Общие атрибуты поля:

| Атрибут | Влияние |
| --- | --- |
| `#[norito(rename = "other")]` | Использует стабильное сериализированное название для схемы и JSON совместимость. |
| `#[norito(skip)]` | Опускает поле и заполняет его от `Default` во время декодирования. |
| `#[norito(default)]` | Использование `Default` когда декодированная полезная нагрузка не несет поля. |
| `#[norito(skip_serializing_if = "...")]` | Выключает поля из JSON при совпадении предиката, при сохранении детерминистического декодирования. |

Производы также раскрывают подсказки кодированной длины и расчеты точной длины, где
Кодировщики используют эти подсказки для резервирования буферов и избегания дополнительных копий.

## Torii и Norito RPC {#torii-and-norito-rpc}

Torii экспозиции JSON для многих маршрутов операторов, но используются типовые бинарные маршруты
Norito. Тип средств массовой информации для типового тока Norito HTTP Тела
`application/x-norito`.

Используйте эти заголовки, когда конечный пункт принимает или возвращает напечатанные Norito:

```http
Content-Type: application/x-norito
Accept: application/x-norito
```

Когда конечный пункт поддерживает оба представления, клиенты могут отправить
перечень предпочтений:

```http
Accept: application/x-norito, application/json
```

Ошибки декодирования обнаружены как указано Torii ошибки и подсчет по телеметрии.
Общие причины включают недействительную магию, не поддерживаемую версию, не подкрепленную функцию
флаг, несовместимость сумм проверки, неправильная форма UTF-8, недействительный код и несоответствие схемы.

Norito RPC транспорт выбирается через конфигурацию транспорта.
панели управления должны отслеживать задержку запросов, неисправности, активные подключения;
ответные байты, и `torii_norito_decode_failures_total` отдельно от JSON
- Проезд.

## Norito Поток {#norito-streaming}

Norito Стриминг расширяет тот же детерминистический подход к медиа и реального времени
Транспортные поверхности.

| Устройство потоковой передачи | Цель |
| --- | --- |
| Манифесты | Заявление обязательств сегмента, маршрутов конфиденциальности, возможностей, профиля кодека, комплекта шифрования и метаданных ключевого содержания. |
| Заголовки сегментов | Бинд номер сегмента, длительность, количество частей, время, энтропия режим, аудио резюме и корни Меркель. |
| Обязательства на части | Пусть зрители и релеи проверят части полезной нагрузки против манифеста перед подачей или расшифровкой. |
| Управляющие кадры | Сопровождать объявления, обратную связь, ключевые обновления и переговоры о возможностях. |
| HPKE ключевые обновления | Переключите транспортные секреты с помощью согласованного аппарата и монотонно увеличивающихся счетчиков. |
| Переговоры о возможностях | Пересекает поддерживаемые биты функций, границы датграммы, каденцию обратной связи и требования к конфиденциальности. |
| FEC и обратная связь | Использует детерминистические отчеты получателей и решения о паритете для траекторий потери в режиме реального времени. |
| Векторы соответствия | Различные языковые устройства доказывают SDKs Декодировать те же манифесты, сегменты и энтропические потоки. |

Кодеки для потоковых передач и профили энтропии отделены от ядра
Norito формат транзакции/запроса, но их манифесты и контрольные данные все еще используются
Norito так что маршрутизация, расчет, повторное воспроизведение и аудит доказательств остаются воспроизводимыми.

## Руководство по эксплуатации {#operational-guidance}

- Я предпочитаю . SDK строительные и генерируемые связы над ручными Norito Байты.
- Обращайтесь с несовместимостью схемы как с проблемой версии или фиксации, а не как с проходящей
  сбой сети.
- Держи . `.nrt`, `.norito`, и манифестующие артефакты с освобождением или происшествием
  сборник, который их создал.
- Использование JSON проекции для приборных панелей и ручной проверки, но держать Norito как
  источник правды для подписанных, хэшированных или сохранившихся данных.
- При добавлении нового типового Torii конечный пункт, документ о том, принимает ли JSON,
  Norito, или обоих, и раскрыть поддерживаемые типы контента в `/openapi`.
- При включении ускорителей выполняйте испытания паритета против скалярного выхода до
  Ускорители должны отключаться, а не изменяться.
  Семантика полезной нагрузки.
