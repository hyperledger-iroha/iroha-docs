# Счета {#accounts}

Счет - это орган, который может подписывать транзакции и иметь собственный бухгалтерский учет.
В настоящее время Iroha 3 модель данных, `AccountId` является каноническим и бездоменным:
он происходит от контролера счета и кодируется канонически как I105.
Контекст человекочитаемого домена и пространства данных относится к отдельным именным аккаунтам
связывания.

## Структура {#structure}

Зарегистрированная `Account` содержит:

- `id`: Канонический `AccountId`
- `metadata`: метаданные произвольных счетов
- `label`: факультативный стабильный псевдоним
- `uaid`: необязательный универсальный счет ID используется Nexus потоки
- `opaque_ids`: непрозрачные идентификаторы, связанные с учетными записями UAID

Нагрузка транзакций, используемая для создания счета: `NewAccount`. Он несет
одинаковая идентичность, метаданные, этикетка; UAID, и непрозрачный ID поле, используемое
зарегистрированный счет.

`uaid` дополняет канонический `AccountId`; Это не заменяет его.

## Контролеры счетов {#account-controllers}

Контроллер определяет, как учетная запись разрешает действия.
flow использует пару ключей Ed25519, но модель данных также поддерживает более богатую
контроллеры, такие как контроллеры полис многоподписей.

Конфигурация клиента хранит авторитет подписания отдельно от Peer
конфигурация:

```toml
[account]
public_key = "ed0120..."
private_key = { digest_function = "ed25519", payload = "..." }
```

Посмотрите. [конфигурация клиента](/ru/guide/configure/client-configuration.md) и
[ключевое поколение](/ru/guide/security/generating-cryptographic-keys.md) для
текущие ключевые форматы.

## Попробуй . Taira {#try-it-on-taira}

Перечисли несколько канонических рассказов IDs от общественности Taira тестовая сеть:

```bash
curl -fsS 'https://taira.sora.org/v1/accounts?limit=5' \
  | jq -r '.items[] | [.id, (.primary_alias // "-")] | @tsv'
```

Для проверки активов счета копируйте счет ID с первого звонка и URL- кодировать
Это было бы лучше, чем поставить его на дорогу. Python Сниppet делает это для первого
зарегистрированный счет:

```bash
python3 - <<'PY'
import json
import urllib.parse
import urllib.request

root = "https://taira.sora.org"
accounts = json.load(urllib.request.urlopen(f"{root}/v1/accounts?limit=1"))["items"]
account_id = accounts[0]["id"]
encoded = urllib.parse.quote(account_id, safe="")
assets = json.load(
    urllib.request.urlopen(f"{root}/v1/accounts/{encoded}/assets?limit=5")
)

print(json.dumps({"account_id": account_id, "assets": assets["items"]}, indent=2))
PY
```

Создание или обновление счета - это подписанная транзакция.
и требует финансирования из крана Taira установка, описанная в
[Подключить к SORA Nexus Данные](/ru/get-started/sora-nexus-dataspaces.md).

## Регистрация и разрешения {#registration-and-permissions}

Счета зарегистрированы и не зарегистрировались в общей форме
[`Register` и `Unregister`](/ru/blockchain/instructions.md#un-register)
Инструкции. Активный валидатор времени запуска решает, кто может создавать учетные записи
и какие знаки разрешения или роли требуются.

После регистрации счет может:

- подписывать сделки
- держать активы
- собственные домены
- получать роли и знаки разрешения
- хранить метаданные
- участвовать в псевдонимах, рекей, восстановлении и Nexus Идентичность протекает, когда эти
  функции включены

## Устранение проблем с идентичностью {#troubleshooting-identity-issues}

Если сделка неожиданно отклоняется, проверьте:

- публичный ключ клиента соответствует частному ключу, используемому для подписания
- счет был зарегистрирован в генезисе или путем обязательной сделки
- у органа имеются разрешения, требуемые инструкцией
- строгие учетные поля используют канонический I105 учетный счет ID, при чтении
  Имена решаются с помощью активной подписи под именем "активный счет"
