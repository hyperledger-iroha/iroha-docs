# Запросы {#queries}

Подписчики событий и фильтры могут отслеживать изменения состояния блокчейна. Используйте запрос, когда вам нужен прямой взгляд на текущее состояние.

Запросы — это небольшие объекты, похожие на инструкции. Отправьте один из них сетевому узлу Iroha, чтобы получить информацию о его текущем представлении состояния мира.

Сеть может раскрывать другую информацию. Информацию о состоянии мира, доступную для запросов, — это единственный вид информации, который гарантированно доступен в каждой сети Iroha.

Для каждого развертывания Iroha может быть доступна дополнительная информация. Например, наличие телеметрических данных зависит от сетевых администраторов. Полностью их решение, хотят они выделять вычислительные ресурсы для отслеживания работы или использовать их для выполнения самой работы. Напротив, некоторые функции всегда необходимы, например, доступ к балансу вашего счета.

Результаты запросов могут быть [отсортировано](#sorting), [постраничный](#pagination) и [фильтрованный](#filters) с другой стороны одновременно. Сортировка выполняется лексикографически по ключам метаданных. Фильтрация может выполняться на различных принципах, от специфичных для области (индивидуальные IP маски фильтров адресов) до методов подстрок, таких как `begins_with`, объединённых с использованием логических операций.

## Запустите этот рабочий процесс на Taira {#try-it-on-taira}

Taira предоставляет вспомогательные функции только для чтения над JSON для общих ресурсов. Используйте их, чтобы попрактиковаться в постраничной выдаче и обработке ответов перед подключением SDK:

```bash
TAIRA_ROOT=https://taira.sora.org

curl -fsS "$TAIRA_ROOT/v1/accounts?limit=3" \
  | jq '{total, ids: [.items[].id]}'

curl -fsS "$TAIRA_ROOT/v1/domains?limit=3" \
  | jq '{total, domains: [.items[].id]}'

curl -fsS "$TAIRA_ROOT/v1/assets/definitions?limit=3" \
  | jq '{total, assets: [.items[] | {id, name, total_quantity}]}'
```

Для диагностики приложения держите эти проверочные тесты отдельно от тестов подписанных транзакций. Ошибка только для чтения обычно указывает на доступность конечной точки API, достижимость сети или совместимость маршрута, прежде чем указывать на настройку криптографической подписи.

## Создать запрос {#create-a-query}

Используйте типизированные конструкторы запросов из SDK или CLI. Например, текущая модель данных предоставляет `FindAccounts` для перечисления аккаунтов:

```rust
let query = FindAccounts;
```

Вот пример запроса, который находит активы Alice:

```rust
let alice_id = load_canonical_account_id_from_client_config()?;
let query = FindAssetsByAccountId::new(alice_id);
```

## Нумерация страниц {#pagination}

Для одиночных запросов и небольших итерируемых запросов вы можете использовать `client.request`, чтобы отправить запрос и получить результат за один раз.

Однако широкие запросы с возможностью итерации, такие как `FindAccounts`, `FindAssets` или `FindBlocks`, могут возвращать большие наборы результатов. Используйте пагинацию, чтобы снизить нагрузку на сетевого узла и клиент.

Чтобы построить `Pagination`, необходимо вызвать `client.request_with_pagination(query, pagination)`, где `pagination` строится следующим образом:

```rust
let starting_result: u32 = _;
let limit: u32 = _;
let pagination = Pagination::new(Some(starting_result), Some(limit));
```

## Фильтры {#filters}

Когда вы создаете запрос, вы можете использовать фильтр, чтобы возвращались только результаты, соответствующие указанному фильтру.

Фильтры специфичны для запроса. Например, запросы по аккаунту можно сузить по идентификатору аккаунта или метаданным, в то время как запросы по активам можно сузить по активу определение, счет держателя или проекция домена. Используйте конструкторы типизированных запросов SDK, где это возможно, чтобы тип фильтра соответствовал типу вывода запроса.

## Сортировка {#sorting}

Iroha может сортировать элементы с [метаданные](/ru/blockchain/metadata.md) лексикографически, если вы предоставите ключ для сортировки при создании запроса. Типичный случай использования — это когда у аккаунтов есть запись метаданных `registered-on`, которая при сортировке позволяет просматривать историю регистрации аккаунта.

Сортировка применяется только к объектам, которые имеют [метаданные](/ru/blockchain/metadata.md), так как ключ метаданных используется для сортировки результатов запроса.

Вы можете объединять сортировку с пагинацией и фильтрами. Обратите внимание, что сортировка является необязательной функцией, большинству запросов с пагинацией она не потребуется.
