## Попробуй . Taira {#try-it-on-taira}

Taira раскрывает только для чтения помощники запросов JSON Для общих ресурсов.
для практики pagination и ответной обработки перед прокладкой SDK:

```bash
TAIRA_ROOT=https://taira.sora.org

curl -fsS "$TAIRA_ROOT/v1/accounts?limit=3" \
  | jq '{total, ids: [.items[].id]}'

curl -fsS "$TAIRA_ROOT/v1/domains?limit=3" \
  | jq '{total, domains: [.items[].id]}'
```

доступность сети или совместимость маршрута до того, как она указывает на установку подписи.

## Создать запрос {#create-a-query}

Используйте встроенные поисковые запросы из SDK или CLI. Например, текущие данные
экспозиции модели `FindAccounts` для учетных записей:

```rust
let query = FindAccounts;
```

Вот пример запроса, который обнаруживает активы Алисы:

```rust
let alice_id = load_canonical_account_id_from_client_config()?;
let query = FindAssetsByAccountId::new(alice_id);
```

## Страничная страница {#pagination}

Для сингулярных запросов и небольших повторяемых запросов вы можете использовать `client.request`
чтобы отправить запрос и получить результат за один раз.

Тем не менее, широкие повторяемые запросы, такие как `FindAccounts`, `FindAssets`, или
`FindBlocks` Используйте pagination, чтобы уменьшить загрузку на
- Сверстник и клиент.

Для создания `Pagination`, Ты должен позвонить
`client.request_with_pagination(query, pagination)`, где `pagination`
выполняется следующим образом:

```rust
let starting_result: u32 = _;
let limit: u32 = _;
let pagination = Pagination::new(Some(starting_result), Some(limit));
```

## Фильтрации {#filters}

Когда вы создаете запрос, вы можете использовать фильтр для возвращения только результатов
которые соответствуют указанному фильтру.

Фильтри являются специфическими для запросов.
идентификация счета или метаданные, в то время как запросы активов могут быть сокращены по активам
Определение, аккаунт владельца или проекция домена. SDK Запрос напечатанный
Builders, где это возможно, чтобы тип фильтра соответствовал типу выхода запроса.

## Сортировка {#sorting}

Iroha может сортировать элементы с [метаданные](/ru/blockchain/metadata.md)
лексикографически, если вы предоставили ключ для сортировки во время строительства
Типичный случай использования для учетных записей должен иметь `registered-on`
вход метаданных, который при сортировке позволяет просматривать учетную запись
историю регистрации.

Классификация применяется только к организациям, которые имеют
[метаданные](/ru/blockchain/metadata.md), как используется ключ метаданных для
сортировать результаты запроса.

Вы можете сочетать сортировку с pagination и фильтры.
опциональная функция, большинство запросов с pagination не будут нуждаться в ней.
