# Iroha 3 ကို စတင်ခြင်း {#launch-iroha-3}

သီးသန့်ပတ်ဝန်းကျင်တွင် စနစ်များ ချိတ်ဆက်အလုပ်လုပ်ပုံကို စမ်းသပ်ရန် Linux VM တစ်လုံးပေါ်၌ Iroha 3 အတည်ပြုနိုဒ် လေးခုကို စတင်ပါ။ လက်မှတ်ထိုးထားသော လုပ်ဆောင်ချက်တစ်ခုကို ပေးပို့ပြီး နိုဒ်တစ်ခုကို ရပ်ပါ။ ကျန်သုံးခုက နောက်ထပ်လုပ်ဆောင်ချက်တစ်ခုကို အတည်ပြုနိုင်ကြောင်း စစ်ဆေးပါ။ ဤလုပ်ငန်းစဉ်က ခွင့်ပြုချက်ရှိသူများသာ ပါဝင်နိုင်သည့် သီးခြားစာရင်းမှတ်တမ်းကို ဖန်တီးပေးသည်။ ယင်းကို စီမံအုပ်ချုပ်မှုအောက်ရှိ ဒေတာနယ်ပယ်အဖြစ် SORA Nexus သို့ ချိတ်ဆက်ရန် သီးခြား ပြင်ဆင်သတ်မှတ်ရမည်။

## VM ကို ပြင်ဆင်ခြင်း {#prepare-the-vm}

Linux x86_64 တွင် Docker Engine၊ Buildx၊ Compose v2၊ Python 3.8 သို့မဟုတ် ပိုသစ်သောဗားရှင်းနှင့် `unzip` ကို အသုံးပြုပါ။ သင့်အကောင့်တွင် Docker ကို အသုံးပြုခွင့် ရှိရမည်။ ပထမဆုံး တည်ဆောက်ချိန်တွင် GitHub၊ Docker Hub၊ Debian ပက်ကေ့ချ်များ၏ မိတ္တူဆာဗာများနှင့် crates.io သို့ HTTPS ဖြင့် ချိတ်ဆက်နိုင်ရမည်။

ဤကိရိယာအစုံကို vCPU ခြောက်ခုနှင့် RAM 32 GiB ရှိသည့် VM တစ်လုံးပေါ်တွင် တည်ဆောက်ပြီး စမ်းသပ်ရန် ဖန်တီးထားသော လုပ်ဆောင်ချက်အနည်းငယ်ဖြင့် စစ်ဆေးခဲ့သည်။ သိုလှောင်မှုပမာဏကို လုပ်ငန်းဝန်နှင့် ဒေတာသိမ်းဆည်းမည့် ကာလအလိုက် သတ်မှတ်ပါ။ Docker Engine တစ်ခုစီအတွက် ကိရိယာအစုံတစ်စုံသာသုံးပြီး စက်တွင်းရှိ loopback ပေါက် 18080–18083 ကို အခြားလုပ်ငန်းများအတွက် မသုံးဘဲထားပါ။

[အတည်ပြုနိုဒ်လေးခုအတွက် ကိရိယာအစုံကို ဒေါင်းလုဒ်ရယူပါ](/downloads/iroha-trade-poc.zip)။ ယင်းတွင် စတင်ပေးသည့် ပရိုဂရမ်၊ ဗားရှင်းအတိအကျ သတ်မှတ်ထားသော လိုအပ်သည့်ဆော့ဖ်ဝဲစာရင်းနှင့် အတည်ပြုနိုဒ်၊ ကလိုင်းယင့် နှစ်မျိုးလုံးကို Iroha ရင်းမြစ်ကုဒ်၏ တူညီသောဗားရှင်းမှ တည်ဆောက်ရန် သုံးသည့် ပြင်ဆင်ချက်များ ပါဝင်သည်။ ဒေါင်းလုဒ်ဖိုင်ရှိသော လမ်းညွှန်ထဲတွင် ဖိုင်၏ စစ်ဆေးတန်ဖိုးကို အတည်ပြုပြီး ဖိုင်ကို ဖြည်ပါ။

```sh
echo 'b12d450f9f15c0126dfe5eca83cdfad8bc420c779a78f916d374f433a2b3da0e  iroha-trade-poc.zip' | sha256sum --check
unzip iroha-trade-poc.zip
cd iroha-trade-poc
```

## အတည်ပြုနိုဒ်လေးခုလုံးကို စတင်၍ စစ်ဆေးခြင်း {#start-and-verify-all-four-validators}

```sh
python3 poc.py up
python3 poc.py verify
```

ပထမဆုံး စတင်သောအခါ ကွန်တိန်နာအတွက် လိုအပ်သော image ကို တည်ဆောက်ပြီး VM ပေါ်တွင် ကွင်းဆက်အမှတ်၊ သော့များနှင့် လက်မှတ်ထိုးထားသော ပထမဘလောက်ကို ဖန်တီးသည်။ အတည်ပြုနိုဒ်တိုင်းတွင် ကိုယ်ပိုင်အမြဲတမ်းသိုလှောင်နေရာ ရှိသည်။ စမ်းသပ်ပရိုဂရမ်က လုပ်ဆောင်ချက်တစ်ခုကို လက်မှတ်ထိုးပြီး နိုဒ်လေးခုလုံးက ချိတ်ဆက်နေသည့် အခြားနိုဒ် သုံးခုစီရှိကြောင်းနှင့် ဘလောက်သစ်အတွက် တူညီသော ဟက်ရှ်တန်ဖိုးကို ပြန်ပေးကြောင်း စောင့်စစ်သည်။ ပထမဘလောက်တွင် နမူနာအကောင့်များ ပါဝင်သည်။ အတုဖန်တီးထားသော စမ်းသပ်ဒေတာကို သုံးပြီး APIs များကို စက်တွင်း loopback လိပ်စာ၌သာ ဖွင့်ထားပါ။

VM မှ ပထမအတည်ပြုနိုဒ်၏ အခြေအနေကို ဖတ်ရှုရာတွင် JSON ဖြင့် ပြန်ပေးရန် အတိအကျ တောင်းဆိုပါ။

```sh
curl -fsS -H 'Accept: application/json' http://127.0.0.1:18080/status
```

## အတည်ပြုနိုဒ်တစ်ခု ရပ်သွားခြင်းကို စမ်းသပ်ခြင်း {#test-a-validator-failure}

```sh
python3 poc.py failover
```

စမ်းသပ်ပရိုဂရမ်က နိုဒ်တစ်ခုကို ရပ်၍ လုပ်ဆောင်ချက်အသစ်တစ်ခုကို ပေးပို့ပြီး ကျန်နိုဒ်သုံးခုတွင် အတည်ပြုပြီးသည့် ဘလောက်၏ ဟက်ရှ်တန်ဖိုးကို စစ်ဆေးသည်။ ထို့နောက် စတုတ္ထနိုဒ်ကို ပြန်စတင်ပြီး ကျန်နိုဒ်များနှင့် တူညီသောဘလောက်သို့ ရောက်သည်အထိ စောင့်သည်။ VM ပျက်သွားပါက နိုဒ်လေးခုလုံး ရပ်သွားမည်။ ရုပ်ပိုင်းဆိုင်ရာ ကွန်ပျူတာတစ်လုံး ပျက်သည့်အခါ အလုပ်ဆက်လုပ်နိုင်ကြောင်း စမ်းသပ်ရန် သီးခြားကွန်ပျူတာ လေးလုံးပေါ်တွင် နိုဒ်တစ်ခုစီ တင်ပါ။

## ရပ်နားခြင်းနှင့် ပြန်လည်စတင်ခြင်း {#stop-and-resume}

```sh
python3 poc.py down
python3 poc.py up
```

အမိန့်နှစ်ခုလုံးကို ကိရိယာအစုံ ဖြည်ထားသည့် လမ်းညွှန်ထဲမှ လုပ်ဆောင်ပါ။ ပြန်လည်စတင်သည့်နိုဒ်များက ယခင်စာရင်းမှတ်တမ်းကို ပြန်ဖွင့်နိုင်ရန် `state/` လမ်းညွှန်နှင့် Docker သိုလှောင်နေရာ လေးခုလုံးကို တွဲ၍ထိန်းထားပါ။ စတင်ခြင်း ရပ်တန့်နေပါက ထိုလမ်းညွှန်ထဲတွင် `python3 poc.py logs` ကို လုပ်ဆောင်ပါ။

## အများသုံး API ကို စမ်းသပ်ခြင်း {#try-the-public-endpoint}

အက်ပ်တစ်ခုသည် စာရင်းမှတ်တမ်းအတွက် ကိုယ်ပိုင် VM ကို မဖွင့်ဘဲ Taira တွင် SORA Nexus ၏ အများသုံး ဒေတာနယ်ပယ်ကို ဖတ်ရှုနိုင်သည်။ `curl` နှင့် `jq` ပါသော စက်တစ်လုံးမှ စမ်းသပ်ကွန်ရက်သို့ ဖတ်ရှုရန်အတွက်သာ အောက်ပါအတိုင်း တောင်းဆိုပါ။

```sh
curl -fsS -H 'Accept: application/json' https://taira.sora.org/status \
  | jq '{peers, blocks, txs_approved, queue_size}'
```

ပြန်ကြားချက်တွင် မေးမြန်းလိုက်သည့်နိုဒ်နှင့် ချိတ်ဆက်ထားသော အခြားနိုဒ်အရေအတွက်၊ အတည်ပြုပြီးသည့် ဘလောက်အရေအတွက်၊ အတည်ပြုခံရသော လုပ်ဆောင်ချက်အရေအတွက်နှင့် တန်းစီစောင့်ဆိုင်းနေသော လုပ်ဆောင်ချက်အရေအတွက်တို့ကို ဖော်ပြသည်။ စနစ်ချထားရန် စီစဉ်ရာတွင် [ကွန်ရက်ချထားခြင်း](/my/guide/best-practices/network-deployment.md) ကို ကြည့်ပါ။
