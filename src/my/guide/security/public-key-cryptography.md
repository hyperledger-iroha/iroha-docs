# အများပြည်သူသော့စာဝှက်ချက် {#public-key-cryptography}

Public key cryptography သည် public key နှင့် private key တို့ကို အသုံးပြုသည်။ အများပိုင် key ကို မျှဝေနိုင်ပါသည်။ Private key သည် authorization principal ၏ ထိန်းချုပ်မှုအောက်တွင်ရှိနေရမည်ဖြစ်သည်။ လုံခြုံရေးသည်ထောက်ပံ့သောအယ်လ်ဂိုရစ်သမ်တစ်ခုအသုံးပြုခြင်း၊ ဘေးကင်းသော randomness ဖြင့် key များထုတ်လုပ်ခြင်းနှင့် private key ကိုကာကွယ်ခြင်းအပေါ်မူတည်သည်။

## ဒစ်ဂျစ်တယ် လက်မှတ်များ {#digital-signatures}

cryptographic signer သည် private key ဖြင့် digital signature ကိုဖန်တီးသည်။ verifier ကမူ public key ဖြင့် လက်မှတ်ကိုစစ်ဆေးသည်။

လက်မှတ်လက်မှတ်တစ်ခုသည် လက်မှတ်ထိုးထားသော ဘိုင်တာများကို မပြောင်းလဲခဲ့ကြောင်း၊ ပုဂ္ဂလိက သော့ပိုင်ရှင်က ခွင့်ပြုခဲ့ကြောင်း ပြသသည်။ ၎င်းသည် မည်သူမဆိုကိုယ်၌ကို ဖော်ထုတ်ခြင်းမရှိပေ။ ကိုယ်ပိုင်လက္ခဏာသည် အများသုံး သော့ သို့မဟုတ် အကောင့်ထိန်းချုပ်ရေးမှူး၏ မှတ်ပုံတင်ခြင်းနှင့် စီမံခန့်ခွဲမှုအပေါ် မူတည်သည်။

လက်မှတ်တွေဟာ ဂုဏ်သိက္ခာနဲ့ ခွင့်ပြုချက် အထောက်အထားကို ပေးပါတယ်။ လက်မှတ်ထိုးထားတဲ့ အကြောင်းအရာတွေကို ကုဒ်မသွင်းပါဘူး။

## အများသုံးသော့ ကုဒ်သွင်းခြင်း {#public-key-encryption}

အများသုံးသော့စနစ်တစ်ချို့က လက်ခံသူ၏ အများသုံးသော key အတွက်ဒေတာကို encrypt လုပ်ကြသည်။ လက်ခံသူသည် ထိုအချက်အလက်များကို သက်ဆိုင်ရာ ပုဂ္ဂလိကသော့ဖြင့် decrypt လုပ်သည်။ Encryption နှင့် လက်မှတ်များသည် သီးခြားလုပ်ဆောင်ချက်များဖြစ်ပြီး မတူညီသော သော့များ သို့မဟုတ် အယ်လ်ဂိုရစ်သမ်များ အသုံးပြုနိုင်ပါသည်။

Iroha ငွေပေးချေမှု လက်မှတ်ရေးထိုးခြင်းသည် အများပြည်သူ blockchain ledger ဒေတာကို လျှို့ဝှက်မဖြစ်စေပါ။ အသုံးဝင်ဝန်ဆောင်မှုအပြည့်အစုံက သီးသန့်နေရန်လိုအပ်ပါက ဖြန့်ဖြူးခြင်း၏ ခွင့်ပြုထားသောလျှို့ဝှက်မှု ယန္တရားကိုအသုံးပြုပါ။

## ဝယ်သူဘက်က သော့များ {#keys-on-the-client-side}

ငွေပေးချေမှုတိုင်းမှာ ဖွဲ့စည်းထားသော အကောင့်ထိန်းချုပ်ရေး မူဝါဒကို ဖြည့်ဆည်းဖို့လိုပါတယ်။ ရိုးရှင်းတဲ့ အကောင့်တစ်ခုက လက်မှတ်ထိုးခလုတ်တစ်လုံးကို အသုံးပြုနိုင်သည်။ အုပ်ချုပ်ထားတဲ့ အကောင့်တစ်ခုဟာ ပိုရှုပ်ထွေးတဲ့ ထိန်းချုပ်ရေးမူဝါဒတစ်ခုကို သုံးနိုင်တယ်။

Client Software က Private Key တွေနဲ့ Controller ပစ္စည်းတွေကို ကာကွယ်ပေးဖို့လိုပါတယ်။ Plain-text client ဖွဲ့စည်းမှုက ဒေသတွင်းဖွံ့ဖြိုးမှု နဲ့ ထိန်းချုပ် စမ်းသပ်မှုတွေ အတွက်သာ သင့်တော်ပါတယ်။ ထုတ်လုပ်ရေး ပေါင်းစည်းမှုတွေမှာ လျှို့ဝှက် စီမံခန့်ခွဲသူ၊ Hardware ထောက်ပံ့ထားတဲ့ သော့ သိုလှောင်မှု၊ သီးခြား လက်မှတ်ထိုး ဝန်ဆောင်မှု (သို့) အခြား စစ်ဆေးတဲ့ လက်မှတ်ထိုး နယ်နိမိတ်ကို သုံးသင့်ပါတယ်။

သီးခြား ပတ်ဝန်းကျင်များနှင့် ရည်ရွယ်ချက်များအတွက် သီးခြားသော့များကို အသုံးပြုပါ။ တစ်ခုတည်းသောသော့ကို ပြန်လည်အသုံးပြုခြင်းသည် ထိုသုံးစွဲမှုတွေကို ချိတ်ဆက်ပေးပြီး ထိတွေ့မှုသက်ရောက်မှုကို မြှင့်တင်သည်။
