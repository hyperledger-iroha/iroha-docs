# အများပြည်သူသော့စာဝှက်ချက် {#public-key-cryptography}

Public key cryptography ဟာ လုံခြုံတဲ့ ဆက်သွယ်ရေးနဲ့ ဒေတာကာကွယ်ရေးအတွက် နည်းလမ်းတွေ ဖြစ်စေပြီး အွန်လိုင်းမှာ လုံခြုံတဲ့ ငွေပေးချေမှုတွေ၊ လျှို့ဝှက်ထားတဲ့ အီးမေးလ်ဆက်သွယ်မှုတွေ စတာတွေ လုပ်နိုင်အောင် လုပ်ပေးပါတယ်။

Public key cryptography သည် အွန်လိုင်းကွန်ရက်များမှတစ်ဆင့် သတင်းအချက်အလက်လွှဲပြောင်းခြင်း၏ အလွန်လုံခြုံသောနည်းလမ်းတစ်ခု ဖန်တီးရန်အတွက် public key နှင့် private key များကို အသုံးပြုသည်။

ပုဂ္ဂလိက သော့ကနေ အများသုံး သော့ကို ဖန်တီးဖို့ လွယ်ကူပေမဲ့ ဆန့်ကျင်ဘက်ကတော့ ခက်ခဲတယ်၊ မဖြစ်နိုင်ဘူးဆိုရင်ပေါ့။ ဒါက အရာတွေကို ဘေးကင်းအောင် ထိန်းထားတယ်။ ကိုယ်ပိုင် သော့ကို အန္တရာယ်မပေးပဲ လွတ်လပ်စွာ မျှဝေလို့ရပါတယ်။ ဒါက လုံခြုံနေတုန်းပါ။

## ကုဒ်သွင်းခြင်းနှင့် လက်မှတ်ထိုးခြင်း {#encryption-and-signatures}

ပြည်သူ့ဆော့ဝဲ ကုဒ်သွင်းခြင်းသည် လူပုဂ္ဂိုလ်များအနေဖြင့် ၎င်းတို့၏ သက်ဆိုင်ရာ ပုဂ္ဂလိက ဆော့ဝဲကို ပိုင်ဆိုင်ထားသော ရည်ရွယ်ချက်ရှိ လက်ခံရရှိသူမှသာ ဖေါ်ထုတ်နိုင်သည့် လျှို့ဝှက်သတင်းစကားများနှင့် ဒေတာများကို ပေးပို့ရန် ခွင့်ပြုပေးသည်။ တစ်နည်းပြောရရင် အများသုံး သော့က ပိတ်ချချက်အဖြစ် လုပ်ဆောင်ပြီး ပုဂ္ဂလိက သော့က ကုဒ်သွင်းထားတဲ့ ဒေတာကို ဖွင့်ပေးတဲ့ တကယ့် ထူးခြားတဲ့ သော့တစ်ခုအဖြစ် လုပ်ဆောင်တယ်။

ဒီကုဒ်သွင်းခြင်း လုပ်ငန်းစဉ်က အာရုံခံ အချက်အလက်တွေရဲ့ သီးသန့်လွတ်လပ်မှုနဲ့ လျှို့ဝှက်မှုကို အာမခံရုံတင်မက ပေးပို့သူရဲ့ စစ်မှန်မှုကိုလည်း တည်ငြိမ်စေပါတယ်။ ပေးပို့သူ၏ ပုဂ္ဂလိက သော့နဲ့ အများပိုင် သော့ကို ပေါင်းစပ်ခြင်းအားဖြင့် ဒစ်ဂျစ်တယ် လက်မှတ်တစ်ခု ဖန်တီးတယ်။ ဒီလက်မှတ်က လက်ခံရရှိသူရဲ့ ကိုယ်ပိုင်လက္ခဏာနဲ့ လွှဲပြောင်းထားတဲ့ ဒေတာတွေရဲ့ သက်ရောက်မှုကို စစ်ဆေးတဲ့ ဒီဂျစ်တယ် အတည်ပြု တံဆိပ်အဖြစ် လုပ်ဆောင်ပါတယ်။ သင့်ရဲ့ အများသုံး သော့ကို ပိုင်ဆိုင်ထားသူတိုင်းဟာ ငွေပေးချေမှု စတင်သူက သင့်ရဲ့ ပုဂ္ဂလိက သော့ကို သုံးခဲ့တာကို စစ်ဆေးနိုင်ပါတယ်။

## ဝယ်သူဘက်က သော့များ {#keys-on-the-client-side}

ငွေပေးချေမှုတိုင်းမှာ အကောင့်အာဏာပိုင်က လက်မှတ်ရေးထိုးဖို့လိုပါတယ်။ အဲဒီအာဏာပိုင်အတွက် ပုဂ္ဂလိက သော့ (သို့) ထိန်းချုပ်ရေး ပစ္စည်းဟာ လျှို့ဝှက်နေဖို့ လိုတယ်၊ ဒီတော့ ဖောက်သည် ဆော့ဖ်ဝဲဟာ လုံခြုံတဲ့ သိုလှောင်မှုနဲ့ လက်မှတ်ရေးကို တာဝန်ယူတယ်။

::: သတိပေးချက်

Client တွေအားလုံးဟာ မတူကြပေမဲ့ Plain-Text client ကို ဖွဲ့စည်းပုံက Development နဲ့ Controlled Test Networks အတွက်သာ သင့်တော်ပါတယ်။ Production Integrations တွေမှာ Secret Manager, Hardware backed key storage (သို့) အခြား Audited Signing Boundary တွေကို သုံးသင့်ပါတယ်။

:::

အကောင့်သစ်တစ်ခုကို မှတ်ပုံတင်ခြင်းမှာ Ed25519 သော့စုံလို ထိန်းချုပ်ရေးပစ္စည်းကို ဖန်တီးပြီး အများပြည်သူအစိတ်အပိုင်းကိုကွန်ရက်သို့ တင်သွင်းခြင်း ပါဝင်သည်။ ထိုစာရင်းမှ နောက်ပိုင်း ငွေကြေးဆောင်ရွက်မှုများကို လိုက်ဖက်သော ပုဂ္ဂလိကသော့ (သို့) ဖွဲ့စည်းထားသည့် စာရင်းထိန်းချုပ်ရေးမူဝါဒဖြင့် လက်မှတ်ထိုးရန်လိုအပ်သည်။

Public key cryptography ကို ထိရောက်စွာ အလုပ်လုပ်စေဖို့ Key အသစ်တစ်ခု သတ်မှတ်ဖို့လိုတဲ့အခါ Key တွေကို ပြန်သုံးတာ ရှောင်ရှားပါ။ ဒါကိုလုပ်တာကို တားဆီးတာ ဘာမှမရှိပေမဲ့ Public keys တွေက Public ပါ။ ဆိုလိုတာက တိုက်ခိုက်သူက တူညီတဲ့ Public key ကို သုံးနေတာကို မြင်ရင် သူတို့ဟာ ပုဂ္ဂလိက သော့တွေလည်း တူတာကို သိကြမှာပါ။

ပုဂ္ဂလိက သော့တွေဟာ စကားဝှက်တွေထက် နည်းနည်းလေး ခြားနားတဲ့ မူဝါဒတွေနဲ့ လုပ်ဆောင်ပေမဲ့ ဖြစ်နိုင်သလောက် ကြုံရာရအောင် လုပ်ဖို့ အကြံပြုချက်ကတော့ ဘယ်တော့မှ မကုဒ်မသွင်းဘဲ သိမ်းဆည်းဖို့နဲ့ ဘယ်အခြေအနေမှာမဆို ဘယ်သူ့ကိုမှ မျှဝေဖို့ မလိုအပ်ပါဘူး။
