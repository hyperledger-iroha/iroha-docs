# စကားဝှက်လုံခြုံမှု {#password-security}

Blockchain လုံခြုံမှု နယ်ပယ်မှာ စကားဝှက်တွေကို ကာကွယ်ခြင်းဟာ အရေးပါပါတယ်။ သင့်ရဲ့ ဒေတာနဲ့ ကိုယ်စားပြုတဲ့ အရာတိုင်းဟာ ခွင့်မပြုထားတဲ့ ဝင်ရောက်မှုကို ခံနိုင်ရည်မရှိနေအောင် သေချာစေဖို့ စကားဝှက်လုံခြုံမှုရဲ့ အရိပ်အယောင်တွေကို နက်ရှိုင်းစွာ လေ့လာကြည့်ရအောင်။

## စကားဝှက်အားကောင်းမှု {#password-strength}

သင်ဟာ ခိုင်မာတဲ့ စကားဝှက်ကို ဘယ်လို ဖန်တီးရမလဲဆိုတဲ့ အကြံပြုချက်တွေကို အရင်က တွေ့ခဲ့လောက်ပါတယ်။ ဒါတွေက အနည်းဆုံး စကားဝှက်အရှည်၊ အထူးစာလုံးတွေ ထပ်ဖြည့်ခြင်း စတာတွေလို အကြံပေးချက်တွေ ပါဝင်နိုင်ပါတယ်။ ဒီလို အကြံပြုချက်တွေဟာ entropy ကို အခြေခံတဲ့ သင့်ရဲ့ စကားဝှက်ရဲ့ အားသာမှုကို မြှင့်တင်ဖို့ ရည်ရွယ်တာပါ။ စကားဝှက်ရဲ့ ကျပန်းမှုပါ။

ဒီတော့ ခိုင်မာတဲ့ စကားဝှက်ကို ဘာကသတ်မှတ်လဲ။ ခိုင်မာသော စကားဝှက်ဆိုတာ အင်ထရိုပီမြင့်တဲ့ စကားဝိုင်းပါ။

စကားဝှက်တစ်ခုရဲ့ entropy ကို တွက်ချက်ဖို့ Entropy ပုံသေနည်းကို လိုက်နာနိုင်ပါတယ်။

::: tip Entropy ပုံသေနည်း

$L$  စကားဝှက်အလျား၊ စကားဝှက်ထဲက သင်္ကေတအရေအတွက်။\ $S$  စာလုံးစု၊ ထူးခြားတဲ့ ဖြစ်နိုင်ခြေရှိတဲ့ သင်္ကေတစ်စုရဲ့ အရွယ်အစား။\ $S^L$  ဖြစ်နိုင်ခြေရှိတဲ့ ပေါင်းစပ်မှု အရေအတွက်။

$$Entropy=log_2(S^L)$$

ရလာတဲ့ နံပါတ်က စကားဝှက်ထဲက entropy bits တွေရဲ့ အရေအတွက်ပါ။ ကိန်းဂဏန်းဟာ ပိုမြင့်လေ၊ စကားဝှက်ကို ခဲယဉ်းလေ ဖြစ်မှာပါ။

entropy value ကိုသိပြီး entropy password တစ်ခုကို brute-force လုပ်ဖို့ လိုအပ်တဲ့ ကြိုးပမ်းမှုအရေအတွက်ကို အောက်ပါ ပုံသေနည်းကို အသုံးပြုခြင်းဖြင့် ရယူနိုင်ပါတယ်။

$$S^L=2^Entropy$$

စကားဝှက် entropy ဘယ်လောက်မြင့်မားသင့်သလဲဆိုတာအတွက် အထွေထွေအဖြေမရှိပါဘူး။ ငွေရေးကြေးအဖွဲ့အစည်းတွေအတွက် Password entropy ကို `64` ကနေ `127` bits အထိထားဖို့အကြံပြုပါတယ်။ (`128` bits သို့မဟုတ် ပိုများတာကို Overkill လို့ယူဆပါတယ်။) သို့သော်လည်း <abbr title="Graphics Processing Unit">GPU</abbr>s သည်အမြဲတမ်းပြောင်းလဲနေဆဲဖြစ်ပြီး စကားဝှက်ဖောက်ခွဲမှုအတွက်လိုအပ်သော အချိန်သည်အချိန်နှင့်အတူလျင်မြန်စွာကျဆင်းနေသည်ကို သတိပြုပါ။

:::

entropy ပုံသေနည်းကိုလိုက်ပြီး အောက်ပါဥပမာ နှစ်ခုကို နှိုင်းယှဉ်ကြည့်ရအောင်-

  1. လက်ရှိ အင်္ဂလိပ်အက္ခရာစာလုံး (၂၆ စာလုံး) ၏ အက္ခရာငယ်များကိုသာ အသုံးပြုသည့် စာလုံးစုနှင့်အတူ ၁၆ စာလုံးသော စကားဝှက်က ဖြစ်နိုင်ချေရှိတဲ့ ပေါင်းစပ်မှုပေါင်း ၄၃ sextillion ($43*10^21$) ခန့်ကို ရရှိစေသည်။

$$Entropy=log_2(26^{16})=log_2(43,608,742,899,428,874,059,776)=75.20703...$$

  2. စာလုံးပေါင်း ၁၆ လုံးပါတဲ့ စကားဝှက်က ၉၆ လုံးအထိ တိုးချဲ့ထားပြီး အက္ခရာအကြီးတွေနဲ့ အထူး သင်္ကေတတွေပါ ၀ င်ကာ ဖြစ်နိုင်ခြေရှိတဲ့ ပေါင်းစပ်မှုအရေအတွက်ကို အံ့သြစရာ ၅၂ မီလီယံ ($52*10^30$) အထိ မြှင့်တင်ပေးပြီး entropi ကို သိသိသာသာတိုးတက်စေပါတယ်။

$$Entropy=log_2(96^{16})=log_2(52,040,292,466,647,269,602,037,015,248,896)=105.35940... $$

မြင်ရတဲ့အတိုင်း၊ သင်္ကေတစုကို ၂၆ ကနေ ၉၆ အထိသာ တိုးချဲ့ခြင်းဖြင့်တောင်မှ မကောင်းဆိုးဝါးပါတီတစ်ခုက bruteforce လုပ်ဖို့ လိုအပ်တဲ့ ဖြစ်နိုင်ခြေရှိတဲ့ ပေါင်းစပ်မှုအရေအတွက်ဟာ $1.1933*10^9$ အကြိမ်အထိ တိုးချဲ့ထားတာပါ။

စကားဝှက်ရဲ့အရှည်ကို တိုးချဲ့ပေးခြင်းက ဖြစ်နိုင်ခြေရှိတဲ့ ပေါင်းစပ်မှုအရေအတွက်ကို ပိုတိုးစေပြီး ဒါကြောင့် စကားဝှက်၏ entropy strength ကို မြှင့်တင်ပေးမှာပါ။

ဒါပေမဲ့ ရှုပ်ထွေးမှုတွေနဲ့ ရုန်းကန်မယ့်အစား စကားဝှက် စီမံခန့်ခွဲရေး ပရိုဂရမ်ကို သုံးဖို့ အကြံပြုပါတယ်။ [KeePassXC](https://keepassxc.org/) (အသေးစိတ်အတွက် ကြည့်ပါ) [Password Manager Program ကိုထည့်သွင်းခြင်း](./storing-cryptographic-keys.md#adding-a-password-manager-program) နှင့် [ဖွဲ့စည်းခြင်း KeePassXC](./storing-cryptographic-keys.md#configuring-keepassxc)) သင်၏ စကားဝှက်များကို ဖန်တီးရန်နှင့် လုံခြုံစွာ သိုလှောင်ရန်။

::: အလှူငွေ

တစ်ချို့ ဝက်ဘ်ဆိုက်တွေဟာ စကားဝှက်တွေရဲ့ အမြင့်ဆုံး ဖြစ်နိုင်ခြေရှိတဲ့ အင်ထရိုပီကို ကန့်သတ်တယ်၊ ဆိုလိုတာက အများဆုံး စကားဝှက်အလျား (သို့) လက်ခံတဲ့ စာလုံးစု (သို့) နှစ်ခုစလုံးကို ကန့်သတ်တယ်။

ဤကဲ့သို့သော ဝက်ဘ်ဆိုဒ်များကို အသုံးပြုရာတွင် ဤအချက်ကို သတိရ၍ မိမိ၏ စကားဝှက်များအား ပုံမှန်ပြုပြင်ရန် ရည်ရွယ်ပါ။

:::

## စကားဝှက် အားနည်းချက်များ {#password-vulnerabilities}

စကားဝှက်တွေဟာ အကြမ်းဖက် တိုက်ခိုက်မှုတွေရဲ့ သားကောင်ဖြစ်လာနိုင်ပြီး အများအားဖြင့် စွမ်းအားရှိတဲ့ GPUs ကို အဘိဓာန်တွေနဲ့ ပေါင်းစပ်ပြီး လုပ်ဆောင်တာ (သို့) ဖြစ်နိုင်ခြေအားလုံးကနေ အပြည့်အဝ ထပ်ကျော့ခြင်းပါ။ ဒီလိုကြိုးပမ်းမှုတွေကို တားဆီးဖို့ မွေးနေ့တွေ၊ လိပ်စာတွေ၊ ဖုန်းနံပါတ်တွေလို ကိုယ်ရေးကိုယ်တာ အချက်အလက်တွေ မရှိတဲ့ ထူးခြားတဲ့ စကားဝှက်ကို ဖန်တီးပါ။ (သို့) လူမှုဖူလုံရေး နံပါတ်များ။ တိုက်ခိုက်သူတွေကို လွယ်ကူစွာ မှန်းဆနိုင်တဲ့ အချက်ပြမှုတွေကို မပေးပါနဲ့။

ဒီတော့ ခေတ်သစ် စကားဝှက်ကို ဖောက်ခွဲဖို့ ဘယ်လောက်ခက်ခဲလဲ။ ဒါက ဘယ်သူ့ကို မေးလဲဆိုတာ တကယ်ပဲ မူတည်တယ်။

ဒီလို ဖွဲ့စည်းမှုတွေနဲ့ [Kevin Mitnick](https://en.wikipedia.org/wiki/Kevin_Mitnick)ဒါက [cluster setup](https://twitter.com/kevinmitnick/status/1649421434899275778?s=20) အိမ်ခြံမြေ 24 NVIDIA® GeForce RTX ၄၀၉၀ နဲ့ ၆ NVIDIA® GeForce RTX ၂၀၈၀ နှစ်တွေက သူတို့အားလုံး ပြေးနေတယ်။ [ဟတ်စတိုပိုလီစ်](https://github.com/hashtopolis) ဆော့ဖ်ဝဲကို သုံးပြီး လဝက်လောက်မှာ တစ်နှစ်ကြာတဲ့ စကားဝှက်တွေကို ဖောက်ခွဲနိုင်ခဲ့တယ်။

ဒါပေမဲ့ ဒါကို တစ်ပုဒ်နဲ့ ယှဉ်ကြည့်ရအောင်။ RTX ၄၀၉၀၊ ၃၀၀ အထိ ပြုပြင်နိုင်သော <abbr title="Hashes per second">H/s</abbr> အသုံးပြုခြင်း [`NTLM`](https://www.tarlogic.com/cybersecurity-glossary/ntlm-hash) 200 နှင့် <abbr title="Hashes per second">H/s</abbr> အသုံးပြုခြင်း [`bcrypt`](https://en.wikipedia.org/wiki/Bcrypt), ပြဌာန်းထားသလို [ဒီ tweet ကို](https://twitter.com/Chick3nman512/status/1580712040179826688).

ကျွန်တော်တို့ရဲ့ ယခင် entropy တွက်ချက်မှုတွေရဲ့ ဖြန့်ဖြူးမှုအနေနဲ့ အောက်ပါ ပြတ်တောက်ချိန်တွေကို လေ့လာကြည့်ရအောင်။

  1. ဒါတွေရှိတယ်။ $31,540,000$ ပုံမှန် ကျော့ကွင်းမဟုတ်တဲ့ နှစ်တစ်နှစ်မှာ စက္ကန့်ပါ။ အဆိုးဆုံးဖြစ်ရပ်က `NTLM`, အမြန်နှုန်းနဲ့ $300*10^9$ <abbr title="Hashes per second">H/s</abbr>, ဒါက တစ်ပုဒ်ပဲ လိုပါလိမ့်မယ်။ RTX ၄၀၉၀ ခန့် $4,608.83$ ခေတ်သစ် အင်္ဂလိပ် အက္ခရာရဲ့ စာလုံး ၂၆ လုံးပါတဲ့ စာလုံးစုနဲ့ စကားဝှက် ၁၆ လုံးကို ဖောက်ခွဲဖို့ နှစ်တွေကြာခဲ့တယ်။

  2. `NTLM` အစား `bcrypt` ကိုသုံးပြီး အပြန်အလှန်မြန်နှုန်းကို $200*10^3$ <abbr title="Hashes per second">H/s </abbr> သို့ လျှော့ချလိုက်ပါက၊ စာလုံးစုကို ၉၆ အထိ တိုးချဲ့ပေးခြင်းနှင့်အတူ ကြီးမားသောစာလုံးများနှင့် အထူး သင်္ကေတများကိုပါ ၀ င်ထားပါက၊ ကျိုးဖောက်မှု အချိန်သည် $8,249,887,835,549,662,270.456$ နှစ်ခန့်အထိ မြင့်တက်လာသည်။ စကြ၀ဠာရဲ့ သက်တမ်းထက် အများကြီးပိုပါတယ်။

ဒီတော့ ပိုမြင့်မားတဲ့ entropy ကို ရွေးရုံနဲ့ စကားဝှက်ကို မဖေါ်ထုတ်နိုင်တဲ့ ကိန်းဂဏန်းတွေအထိ crack လုပ်ဖို့ လိုတဲ့ အချိန်ကို တိုးမြှင့်ခဲ့တယ်။ ဟုတ်ကဲ့၊ များပြားလှတဲ့ ကိရိယာတွေကို သုံးခြင်းဖြင့် ဖြစ်စဉ်ကို အရှိန်မြှင့်နိုင်ပါတယ် GPUs, ဒါပေမယ့် ဒီနည်းလမ်းက [XKCD ချဉ်းကပ်မှု](https://xkcd.com/538/).

ရှည်လျားသော စာလုံးစုတစ်ခုသည် entropy မြင့်မားမှုသို့ရောက်ရှိရန်အမြဲတမ်းလိုအပ်ခြင်းမဟုတ်သည်ကို သတိထားမိဖို့အရေးကြီးသည်။ ၎င်းကို multi-word စကားဝှက်များ (သို့) အထူးသဖြင့် ဝါကျရှည်များကိုအသုံးပြု၍ရရှိနိုင်သည်။ ဂန္ထဝင် [XKCD ကာတွန်း ](https://xkcd.com/936/) သည်ဤသဘောတရားကိုကောင်းမွန်စွာသရုပ်ဖော်သည်။

Password ကို ဘယ်နေရာမှာမဆို ရေးမထားပါ။ password recovery phrase ကို လုံခြုံစွာ သိမ်းဆည်းပါ။ စကားစုက အရမ်းရှည်တယ်ဆိုရင် စာလုံးကိုရေးပြီး နောက်ပိုင်း ဖတ်နိုင်အောင် ရိုက်ထည့်နိုင်ပါတယ်။ စကားစုရဲ့ ရုပ်ပိုင်းမူကွဲကို ဘေးကင်းတဲ့နေရာနဲ့ (သို့) ကွန်တိန်နာမှာ သိမ်းဆည်းလိုက်ပါ။
