# လုပ်ငန်းလုံခြုံရေး {#operational-security}

Operational Security (OPSEC) သည် လုံခြုံရေးနှင့် အရဲစွန့်မှု စီမံခန့်ခွဲမှုအတွက် စနစ်တကျ ချဉ်းကပ်မှုတစ်ခုဖြစ်ပြီး အဓိကအားဖြင့် ခွင့်ပြုချက်မရှိသော ဝင်ရောက်မှုနဲ့ ဒေတာသွေးကြွမှုကို တားဆီးရန် ရည်ရွယ်ပြီး သီးခြားအသုံးပြုမှုကိစ္စရပ်များအတွက် ကျင့်သုံးသည့် နည်းဗျူဟာများနှင့် အကြံပေးချက်များကို စုစည်းထားခြင်းဖြစ်သည်။

<abbr title="Operational Security">OPSEC</abbr>သည် အများစုကုမ္ပဏီများ၏ အရင်းအမြစ်များ၏ရရှိနိုင်မှုနှင့် တည်ငြိမ်မှုကို အာမခံရန်အတွက် ပုံမှန်လေ့ကျင့်ခန်းဖြစ်သည်။ ဤသို့ဆိုသည်မှာ ရုပ်ပိုင်းလုံခြုံရေးကဲ့သို့သော အကြောင်းရင်းများကို ထည့်သွင်းစဉ်းစားခြင်း (ဥပမာ၊ စောင့်ကြည့်မထားသည့် post-it မှတ်တမ်းများသည် ထိခိုက်လွယ်သော ဒေတာကို မပါဝင်စေရန် သေချာအောင်လုပ်ခြင်း) ။ လုံခြုံတဲ့ ဆက်သွယ်ရေး ပရိုတိုကောတွေ (ဥပမာ၊ လျှို့ဝှက်မထားတဲ့ SMS ကနေ အာရုံခံ အချက်အလက်တွေကို မပို့ပေးခြင်း၊ ခြိမ်းခြောက်မှု ဆန်းစစ်ခြင်းများ (ဥပမာ။ အလားအလာရှိတဲ့ အန္တရာယ်ရှိသူများကို ဖော်ထုတ်ခြင်း၊ နောက်ဆုံးသော တိုက်ခိုက်မှု နည်းစနစ်များအကြောင်း သိရှိခြင်း) ၊ ဝန်ထမ်း သင်တန်းများ (ဥပဒေအရ <abbr title="Operational Security">OPSEC</abbr>) ကို လိုက်နာမှုမရှိဘဲ၊ ဒါတွေဟာ အမြန်ဆုံး ဒါမှမဟုတ် နောက်ပိုင်းမှာ ထိရောက်မှုမရှိဘူးဆိုတာ သက်သေပြပြီး အရဲစွန့်မှုကို လျှော့ချပေးမှာပါ။ (ဥပမာ Hard Drive နဲ့ USB ကိရိယာတွေကို ကုဒ်သွင်းခြင်း)

Iroha ကို ငွေရေးကြေးစာရင်းအဖြစ် အသုံးပြုနိုင်သောကြောင့် <abbr title="Operational Security">OPSEC</abbr> အစီအစဉ်များနှင့် လုပ်ငန်းစဉ်များကို အလေးအနက်ထားရန် လိုအပ်သည်။ ဤဆောင်းပါးတွင် Iroha ကိုအသုံးပြုသည့် ပုဂ္ဂိုလ်များနှင့် အဖွဲ့အစည်းများသည် ၎င်းတို့၏ လုပ်ငန်းများတွင် ပါဝင်မှုတစ်ခုအဖြစ် စဉ်းစားသင့်သော နည်းဗျူဟာများနှင့် ချဉ်းကပ်မှုများအား ဖော်ပြထားပါသည်။ ကျယ်ပြန့်တဲ့ လုံခြုံရေး အစီရင်ခံစာပါ။

[Security](./index.md) အပိုဒ်အနှံ့မှာ ပိုမိုသိရှိလိုပါက သင့်လုံခြုံမှုကို ပိုကောင်းမွန်စေရန်နှင့် အထူးသဖြင့် အောက်ပါအကြောင်းအရာများကို သိရှိပါ။

## အကြံပြုချက်များ OPSEC {#recommended-opsec-measures}

- သတိထားပါ။ [ အများဆုံး ဖြစ်နိုင်ခြေရှိတာက ](https://arxiv.org/pdf/2209.08356.pdf) blockchain ထဲက သူတို့ရဲ့ အရင်းအမြစ်တွေကို ဆုံးရှုံးနိုင်တဲ့ နည်းလမ်းက သူတို့ရဲ့ အာရုံသိပ်တဲ့ အသေးစိတ်တွေ ပေးခြင်းပါ။

- ဒစ်ကာတွေကို ကုဒ်သွင်းပါ။ boot device တွေကို encrypt လုပ်ခြင်းက တိုက်ခိုက်သူက Hardware ကို ဝင်ရောက်ခွင့်ရခဲ့တောင်မှ သင့်ဒေတာကို ကာကွယ်နိုင်စေပါတယ်။ ဒါကို portable devices တွေအတွက်လုပ်ခြင်းဟာ နှစ်ဆ ပိုအရေးကြီးပါတယ်။

- ယုံကြည်ရတဲ့ ဆော့ဝဲကို သုံးပါ။ ပြန်လည်ဖန်တီးနိုင်တဲ့ ဘိုင်နရီ တည်ဆောက်မှုတွေကနေ သယ်ဆောင်တဲ့ ဆော့၀ဲနဲ့ အရင်းအမြစ်ကနေ ဆောက်လုပ်တာက အယုံအကြည်ဆုံးပါ။ ပိုင်ဆိုင်ထားတဲ့ (သို့) မစစ်ဆေးသေးတဲ့ Open-Source Software ဟာ အလေးထားသင့်တဲ့ အလားအလာရှိတဲ့ စွန့်စားမှုတစ်ခုပါ။

- ထိခိုက်လွယ်တဲ့ အချက်အလက်တွေပါတဲ့ မိုဘိုင်း ကိရိယာတွေကို ဘယ်တော့မှ စောင့်ကြည့်မှုမရှိဘဲ မထားပါနဲ့။

- Iroha အတွင်းမှာ အသုံးပြုတဲ့ အများသုံး သော့ဝှက်စာပေနဲ့ သိပ်မခြားနားပါဘူး။

- သင့်လက်ပ်တော့ (သို့) ကွန်ပြူတာကို စောင့်ကြည့်မှုမရှိဘဲ ထားတဲ့အခါမှာ ခွင့်ပြုချက်မရတဲ့ ဝင်ရောက်မှုကို တားဆီးဖို့ အမြဲလုံခြုံပါ။ ခိုင်မာတဲ့ စကားဝှက်တွေသုံးပြီး ဖန်သားပြင်ကို ပိတ်ထားပြီး သင့်ကိရိယာတွေကို လုံခြုံဖို့ အကောင်းဆုံးနည်းလမ်းတွေကို လိုက်နာလိုက်ပါ။

- Key များအတွက် လုံခြုံသော [ air-gaped](https://en.wikipedia.org/wiki/Air_gap_(networking) နေရာကိုတည်ဆောက်ပါ။ ပထမဦးဆုံးအားဖြင့် key များကို encrypt လုပ်ပြီးနောက်အွန်လိုင်းမှသာ device တစ်ခုတွင် သိမ်းဆည်းထားပါ။ အကောင်းဆုံးက လျှပ်စစ်သံလိုက်ကာကွယ်ရေးတပ်ဆင်ထားသည်။ [Hardware keys](./storing-cryptographic-keys.md#using-a-hardware-key) ကိုဤရည်ရွယ်ချက်အတွက် အထူးဒီဇိုင်းထုတ်လုပ်ထားပါတယ်။

- ကွန်ပျူတာနှင့်ဖုန်းများအပါအဝင် ကိရိယာအားလုံးတွင် မိမိ၏ ဆော့ဝဲကို နောက်ဆုံးပေါ်ဗားရှင်းသို့ အမြဲတမ်း မွမ်းမံထားပါ။ ပုံမှန် update များက vulnerabilities ကို patch လုပ်ရန်ကူညီပေးပြီး သက်တမ်းကုန်ဆုံးသော software နှင့်စပ်လျဉ်းသည့် ဖြစ်နိုင်ချေရှိသောခြိမ်းခြောက်မှုများကို အနည်းဆုံးအထိ လျှော့ချပေးနိုင်သည်။

- စကားဝှက်များနှင့် cryptographic key များကို အကြိမ်ကြိမ် update လုပ်ရန်အတွက် ပုံမှန်စီမံကိန်းတစ်ခုကို ပြုစုပါ။ ဤ proactive ချဉ်းကပ်မှုက လှုပ်ရှားနေသော ပစ်မှတ်ကို ထိခိုက်ဖို့ ပိုခက်ခဲတာကြောင့် ယေဘုယျလုံခြုံရေးအနေအထားကို မြှင့်တင်ရာမှာ သိသိသာသာ ကူညီပေးသည်။

## Browser များကို အသုံးပြုခြင်း {#using-browsers}

Iroha သို့ ချိတ်ဆက်ထားသော အက်ပ်တစ်ခုတွင် UI ဝက်ဘ်ဆိုက်ရှိပါက သင်၏ browser သည်လုံခြုံမှုကိုကူညီနိုင်သည် (သို့မဟုတ်) အလားအလာရှိသော ခြိမ်းခြောက်မှုဖြစ်စေသည်။ သင်တပ်ဆင်ရန်ရွေးချယ်သည့် plugins များအတွက် အထူးသဖြင့်သတိထားမိရန်လိုအပ်ပါသည်။

သင့်ရဲ့ ရှာဖွေရေး လုံခြုံမှုကို မြှင့်တင်ဖို့ အောက်ပါ နည်းလမ်းတွေကို စဉ်းစားကြည့်ပါ။

- လုံခြုံရေးမကောင်းတဲ့ မော်ဒယ်တွေရှိပြီး သုံးစွဲသူတွေရဲ့ ဒေတာတွေကို စိမ့်ဝင်စေတာလို့သိကြတဲ့ ရှာဖွေရေးကိရိယာတွေကို ရှောင်ရှားပါ။ ဥပမာ၊ [ ဒီ Browser Privacy](https://www.unixsheikh.com/articles/choose-your-browser-carefully.html) အကြောင်း ဆောင်းပါးမှာ ရှာဖွေရေး ကိရိယာအမျိုးမျိုးနဲ့ ၎င်းတို့ ဘယ်လောက်လုံခြုံတယ်ဆိုတာကို ဆွေးနွေးထားပါတယ်။ မှတ်သားပါ မူပိုင် Browser များ ( Chrome, Safari, Opera, Vivaldi, Edge နှင့်အခြားများ) သည် အများပြည်သူထံမှ ပုန်းကွယ်နေသောကုဒ်ကြောင့် စစ်ဆေးရန် အင်မတန်ခက်ခဲသည်၊ ဆိုလိုသည်မှာ ၎င်းတို့၏ လုံခြုံမှု ဘယ်လောက်ရှိသည်ကို သင်မသိနိုင်ခြင်းပါ။

- သုံးစွဲသူတွေရဲ့ သီးသန့်ဘဝနဲ့ လုံခြုံရေးကို တန်ဖိုးထားကာ ကာကွယ်မှု မှတ်တမ်းကောင်းရှိတဲ့ ရှာဖွေရေးစနစ်တွေကို ဦးစားပေးပါ။
  - [Librewolf](https://librewolf.net/), [Icecat](https://www.gnu.org/software/gnuzilla/), [Firedragon](https://github.com/dr460nf1r3/firedragon-browser), စသည်တို့ကို Mozilla Firefox ၏ ကောင်းမွန်စွာတည်ထောင်ထားသော fork များတွင် လုံခြုံရေးအပိုဆုများပါဝင်သည်။
  - [Unoogled chromium ](https://github.com/ungoogled-software/ungoogled-chromium)  သည် Google Chrome ၏ အလွန်စစ်ဆေးထားသော Open-Source ဗားရှင်းတစ်ခုဖြစ်ပြီး လုံခြုံရေးဆိုင်ရာ ထပ်မံဆောင်ရွက်ချက်များဖြင့် တိုးမြှင့်ထားပြီး Google နှင့်သက်ဆိုင်သော ဝက်ဘ်ဝန်ဆောင်မှုအားလုံးကို ဖယ်ရှားထားသည်။
  - [သတ္တိရှိတယ်](https://brave.com/)  အင်မတန်ကို စစ်ဆေးထားသော Open Source ဗားရှင်းတစ်ခု [Google Chromium](https://www.chromium.org/Home/) နောက်ထပ် လုံခြုံရေး အစီအစဉ်များဖြင့် တိုးမြှင့်ပေးထားပြီး တည်ဆောက်ထားသည့် <abbr title="Virtual Private Network">VPN</abbr> ပြီးတော့ ကြော်ငြာပိတ်စက် လုပ်ဆောင်ချက်ပါ။
  - [Falkon](https://www.falkon.org/)  open-source Qt အခြေပြု web browser ကို (တည်ဆောက်ထားသည်) `QtWebEngine`, ပုံးတစ်လုံး [Google Chromium](https://www.chromium.org/Home/)) တွင် လုံခြုံမှုရှိကြောင်း သိထားသော မှတ်တမ်းရှိသည်; ၎င်း၏ [KDE ဆိုင် စာမျက်နှာ](https://store.falkon.org/browse/).
  - [Qutebrowser](https://qutebrowser.org/)  open-source Qt အခြေပြု web browser ကို (တည်ဆောက်ထားသည်) `QtWebEngine`, ပုံးတစ်လုံး [Google Chromium](https://www.chromium.org/Home/)) မှာ လုံခြုံမှု မှတ်တမ်းရှိပြီး ကီးဘုတ်ကို အာရုံစိုက်တဲ့ ထူးခြားတဲ့ ချဉ်းကပ်မှုကို minimalist တွေနဲ့ GUI; လုံခြုံရေးဆိုင်ရာ ကျွမ်းကျင်သူ အများအပြားအတွက် ရွေးချယ်စရာ ရှာဖွေရေးကိရိယာအဖြစ် သတ်မှတ်ထားတယ်။

- လိုအပ်ရင် `JavaScript` ကို မဖွင့်ပါနဲ့။

- Plugins တွေအတွက် browser ရဲ့ built-in confinement mechanism ကိုသုံးပြီး install လုပ်ထားတဲ့ plugins တွေမှာရှိတဲ့ access rights တွေကို ကန့်သတ်ပေးပါ။

- အရေးကြီးတဲ့ လုပ်ငန်းတွေ မလုပ်ခင်နဲ့ ပြီးရင် ကွတ်ကီတွေကို ရှင်းလင်းပါ။ ကျွန်မကို မှတ်ပုံတင်ထားပါ (သို့) မှတ်မိပါ feature ကို မဖွင့်ပါနဲ့။ ဝက်ဘ်ဆိုဒ်တစ်ချို့မှာ ဒီ feature ကို အလိုအလျောက် ဖွင့်ထားတာကို သတိပြုပါ။

- ကြော်ငြာပိတ်စက်ကို အသုံးပြုပါ။ ဒါတွေက ကြော်ငြားတွေကို ပိတ်လိုက်ရုံတင်မက ဝက်ဘ်ဆိုဒ် ခြေရာခံမှု လုပ်ဆောင်ချက်တွေကိုလည်း ပိတ်ထားတယ်။ သင်သုံးတဲ့ ရှာဖွေရေးကိရိယာအပေါ် မူတည်ပြီး ကြော်ငြାပိတ်စက်ဟာ ထည့်သွင်းထားတဲ့ လုပ်ဆောင်ချက်မဟုတ်လောက်ပါဘူး။

- တူညီတဲ့ ဇာတ်ကောင်တွေကို သတိထားပါ။ (ဥပမာ `0`, `θ`, `O`, `О`, `ዐ` နှင့် `߀` ဒီလို အသေးစိတ်အချက်အလက်တွေကို အာရုံစိုက်ခြင်းက သင်ဟာ Phishing တိုက်ခိုက်မှုကနေ ကယ်တင်နိုင်မှာပါ။

- UI ဝက်ဘ်အီးမေးလ် client များကို desktop clients များအတွက်သာ ရှောင်ရှားပါ။ မသုံးခင်မှာ GPG key signatures တွေကို လက်မှတ်ထိုးပြီး စစ်ဆေးဖို့ သင့် desktop email client ကို set up လုပ်ပါ။

- အွန်လိုင်းအခြေခံ သတင်းပို့ဆောင်ရေး ဝန်ဆောင်မှုများကို ရှောင်ရှားပါ။ ဥပမာ Discord (အသိဆိုးဝါးသော `electron` ဖွဲ့စည်းပုံနှင့် တည်ဆောက်ထားသည်) သည် Diskord ၏ ဝက်ဘ်ဗားရှင်းဖွင့်ထားသည့် Google Chromium ပြူတင်းပေါက်ကဲ့သို့သော တိုက်ခိုက်မှုများစွာကို ခံနိုင်ရည် ရှိသည်။

- သင့် browser ကို တတ်နိုင်သလောက် နောက်ဆုံးပေါ်ဗားရှင်းကို update လုပ်ပါ။ Update တွေမှာ vulnerabilities တွေကို ဖြေရှင်းတဲ့ critical security patches တွေလည်း ပါဝင်ပါတယ်။

- သင် install လုပ်တဲ့ browser extension တွေကို သတိပြုပါ။ နာမည်ကြီး အရင်းအမြစ်တွေကနေ နာမည်ကျော်ပြီး ယုံကြည်ရတဲ့ extension တွေပဲ အသုံးပြုပါ။ Rogue extension တွေက သင့်ရဲ့ data နဲ့ privacy ကို ထိခိုက်စေနိုင်ပါတယ်။

- နေ့စဉ်ရှာဖွေမှုအတွက် သီးခြား ရှာဖွေရေး ပရိုဖိုင်များကိုဖန်တီးပါ။ နေ့စဉ် ရှာဖွေရေးအတွက် တစ်ပရိုဖိုင်းကိုသုံးပြီး လုံခြုံမှုမြင့်မားနှင့် သိမ်မွေ့သောဒေတာများပါဝင်တဲ့ လုပ်ဆောင်ချက်များအတွက်တစ်ခုခုကိုအသုံးပြုပါ။ ဤနည်းဖြင့်၊ နေ့စဉ် ရှာကြည့်ခြင်းအတွက် ပရိုဖိုင်းပေါ်တွင်တပ်ဆင်ထားသည့် ဖြန့်ဖြူးမှုများသည်လုံခြုံသောတစ်ခုမှသိမ်မွေ့သောအချက်အလက်သို့ ဝင်ရောက်မရနိုင်ပါ။

- USB flash drive သို့ ကူးယူထားသော သင်၏ browser ၏ portable version ကို အသုံးပြုပါ။ ဤနည်းလမ်းသည် လုံခြုံရေးအမှားတစ်ခုက တပ်ဆင်ထားတဲ့ plugins တစ်ခုကို profile များအကြား ဒေတာသို့ ဝင်ရောက်ခွင့်ပေးသော်လည်း၊ လုံခြုံမှုနှင့်သက်ဆိုင်သည့် profil သည် သီးခြားပြီး ဖယ်ရှားနိုင်သော ကိရိယာတွင်ရှိနေဆဲဖြစ်သည်ကို သေချာစေသည်။

- သင့်ကိရိယာမှာ မတော်တဆ သိမ်းဆည်းထားနိုင်တဲ့ ထိခိုက်လွယ်တဲ့ ဒေတာတွေကို ဖယ်ရှားဖို့ သင်၏ ရှာဖွေရေးကိရိယာရဲ့ cache နဲ့ cookie တွေကို ပုံမှန်ရှင်းလင်းပါ။

## ပြန်လည်ထူထောင်ရေး အစီအစဉ် {#recovery-plan}

အရေးပေါ်အခြေအနေတွင်၊ ဥပမာ သော့တစ်ချောင်း ဆုံးရှုံးခြင်း (သို့) လုံခြုံရေး ချိုးဖောက်မှုတစ်ခု ကြုံတွေ့နေရပါက ကောင်းမွန်စွာဖွဲ့စည်းထားပြီး ကြိုတင်ပြင်ဆင်ထားသော ပြန်လည်ထူထောင်ရေး အစီအစဉ်သည် အရေးကြီးသော အသက်ရှင်ရေး လမ်းကြောင်းဖြစ်သည်။ လိုက်နာရမည့် ရှင်းလင်းတဲ့ အဆင့်သတ်မှတ်ချက်များကို ဖန်တီးခြင်းက ဖြစ်နိုင်ခြေရှိတဲ့ ပျက်စီးမှုကို လျော့ပါးစေရန်နှင့် လုံခြုံရေးကို အမြန်ပြန်လည် ထူထောင်ပေးရန် ကူညီနိုင်သည်။

အဖွဲ့အစည်းတွေဟာ သူတို့ရဲ့ ပြန်လည်ထူထောင်ရေး အစီအစဉ်ကို ပြုစုရာတွင် အောက်ပါ အဓိက ရှုထောင့်တွေကို ထည့်တွက်သင့်ပါတယ်။

- Key ဆုံးရှုံးမှု (သို့) အခြားလုံခြုံရေးဖြစ်ရပ်များတွင် လိုက်နာရမည့် အဆင့်ဆင့် လုပ်ငန်းစဉ်များကို ဖော်ပြပါ။ အသုံးပြုသူများနှင့်/သို့မဟုတ် ဝန်ထမ်းများအတွက် ဒီအဆင့်များ အလွယ်တကူရရှိနိုင်ပြီး နားလည်လွယ်စေရန် သေချာစေပါ။

- လုံခြုံရေး ချိုးဖောက်မှုတွေနဲ့ လစ်လပ်သွားတဲ့ (သို့) ပျောက်ဆုံးသွားတဲ့ သော့နဲ့ စကားဝှက်လို ဖြစ်နိုင်ခြေရှိတဲ့ ခြိမ်းခြောက်မှုတွေကို ချက်ချင်း အစီရင်ခံဖို့ သုံးနိုင်တဲ့ ဆက်သွယ်ရေး လမ်းကြောင်းတစ်ခု တည်ဆောက်ပါ။

- [YubiKey](https://www.yubico.com/products/) (သို့) [SoloKeys Solo](https://solokeys.com/collections/all)) တို့ကို လုံခြုံရေးအစီအစဉ်တစ်ခုအဖြစ်အသုံးပြုပါက redundancy နည်းဗျူဟာကိုသုံးစွဲရန် စဉ်းစားပါ။ တစ်လုံးနေ့စဉ် အသုံးပြုရန်နှင့်တစ်လုံးကိုလုံခြုံသောနေရာတွင် သိမ်းဆည်းထားရန်အတွက် သော့နှစ်ခုကို ထိန်းသိမ်းပါ။ ဒီကြိုတင်ကာကွယ်ချက်က အဓိက သော့ကို ထိခိုက်ခံရ (သို့) ပျောက်ဆုံးသွားရင်တောင် ဝင်ရောက်မှုကို အာမခံပေးတယ်။

- လုံခြုံရေး ချိုးဖောက်မှု (သို့) ပေါက်ကြားမှု အစီရင်ခံတဲ့အခါ ထိခိုက်ခံရတဲ့ သော့တွေနဲ့ စကားဝှက်တွေကို အစားထိုးပြီး ပိတ်လိုက်ခြင်းဖြင့် ချက်ချင်း တုံ့ပြန်ပါ။ ဒီအလုပ်က ဖြစ်နိုင်ခြေရှိတဲ့ အန္တရာယ်နဲ့ ပျက်စီးမှုကို အနိမ့်ဆုံးအထိ လျှော့ချပါတယ်။

- သင့်ရဲ့ ပြန်လည်ထူထောင်ရေး အစီအစဉ်ကို အချိန်နဲ့တပြေးညီ စစ်ဆေးပြီး မွမ်းမံပေးပါ။ ဒါက သင့်ရဲ့ လုံခြုံရေး ရှုခင်း ပြောင်းလဲလာတာနဲ့အမျှ အစီအစဉ်ဟာ သက်ရောက်မှုရှိပြီး ထိရောက်မှုရှိနေတာကို သေချာစေတယ်။

ပြန်လည်ထူထောင်ရေး အစီအစဉ်ဟာ နောက်ထပ် စာရွက်စာတမ်းတစ်ခုတင်မဟုတ်ပဲ မျှော်လင့်မထားတဲ့ စိန်ခေါ်မှုတွေကို ကျော်လွှားဖို့ ကူညီတဲ့ အသက်ရှင်မှု လမ်းကြောင်းတစ်စင်းဆိုတာ သတိရပါ။ ဖြစ်နိုင်ခြေရှိတဲ့ ဇာတ်လမ်းတွေကို ကြိုတင်ခန့်မှန်းခြင်းနဲ့ လုပ်ဆောင်ချက်အတွက် ရှင်းလင်းတဲ့ လမ်းညွှန်ချက်ကို သတ်မှတ်ခြင်းအားဖြင့်၊ သင့်ရဲ့ လုပ်ငန်းလုံခြုံမှုကို ခိုင်မာစေပြီး လုံခြုံရေးဖြစ်ရပ်တိုင်းကို ထိရောက်စွာ တုံ့ပြန်ဖို့ အသင့်ရှိမှု မြှင့်တင်ပေးတယ်။
