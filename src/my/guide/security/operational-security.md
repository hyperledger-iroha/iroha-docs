# လုပ်ငန်းလုံခြုံရေး {#operational-security}

လုပ်ငန်းလုံခြုံရေးသည် Iroha ဖြန့်ချိမှုတစ်ရပ်ပတ်ဝန်းကျင်ကလူတွေ၊ အိမ်ရှင်များ၊ ခွင့်ပြုချက်များနှင့်လုပ်ငန်းစဉ်များကိုကာကွယ်သည်။ blockchain ledger မှတ်တမ်းများသည်အခြေအနေအပြောင်းအလဲများကိုလက်ခံထားသည်။ အော်ပရေတာများသည်သူတို့၏အလုပ်ရုံများ၊ လက်မှတ်ထိုးခြင်းသော့များနှင့်ဖြစ်စဉ်တုံ့ပြန်မှုလုပ်ငန်းစဉ်တို့ကို သီးခြားကာကွယ်ရမည်ဖြစ်သည်။

အောက်ပါ ထိန်းချုပ်မှုကို ဖြန့်ချိမှုအခြေခံလိုင်းအဖြစ် အသုံးပြုပါ။ အန္တရာယ်ရှိတန်ဖိုးနဲ့ သင့်အဖွဲ့အစည်းရဲ့ လိုအပ်ချက်တွေကို လိုက်ဖက်အောင် ပြင်ဆင်လိုက်ပါ။

## စီမံခန့်ခွဲမှု အခြေခံအဆင့်ကို ချမှတ်ရန် {#establish-an-operational-baseline}

- validator host များ၊ peer အထောက်အထားများ၊ authority အကောင့်များ၊ လက်မှတ်ထိုးကိရိယာများ၊ အများသုံး endpoint များနှင့် တာဝန်ခံပုဂ္ဂိုလ်များ၏ စာရင်းကို ထိန်းသိမ်းပါ။
- ဖွံ့ဖြိုးရေး၊ စမ်းသပ်ရေးနှင့် တကယ့်လုပ်ငန်းသုံးအတွက် သီးခြားအထောက်အထားများကို အသုံးပြုပါ။ လက်မှတ်ထိုးသူ၊ bearer တိုကင်နှင့် ကိုယ်ပိုင်ကီးတစ်ခုချင်းစီကို ပတ်ဝန်းကျင်တစ်ခုတည်းတွင်သာ သုံးပါ။
- ပြင်ဆင်သတ်မှတ်မှုနှင့် deployment အလိုအလျောက်လုပ်ဆောင်မှုကို သုံးသပ်နိုင်သော ဗားရှင်းထိန်းချုပ်မှုတွင် ထားပါ။ လည်ပတ်ချိန်၌ အတည်ပြုထားသော လျှို့ဝှက်တန်ဖိုးသိုလှောင်ရုံ သို့မဟုတ် လက်မှတ်ထိုးကိရိယာမှ လျှို့ဝှက်တန်ဖိုးများကို ထည့်သွင်းပါ။
- ရောင်းချမှုမတိုင်မီမှာ ကြိုတင်မှတ်တမ်းတင်ထားသော cryptographic hashes သို့မဟုတ် လက်မှတ်များကို မှတ်တမ်းတင်ပါ။ ဘိုင်နရီများ၊ blockchain မျိုးဆက်ပစ္စည်းများ၊ ဖွဲ့စည်းပုံများ သို့မဟုတ် ဝန်ဆောင်မှု အဓိပ္ပါယ်ဖွင့်ဆိုချက်များကို ဘယ်သူက အစားထိုးနိုင်သည်ကို ကန့်သတ်။
- Operating System Account များ၊ Iroha ခွင့်ပြုချက်များနှင့် Network Administration များအတွက် အနည်းဆုံး အခွင့်အရေးများကို အသုံးချပါ။ Role တစ်ခုစီကို ၎င်း၏ အလုပ်လိုအပ်သည့် ခွင့်ပြုမှု မူဝါဒကိုသာ ပေးပါ။
- ထုတ်လုပ်မှုကို မစတင်ခင် စမ်းသပ်မှု Backup, Restore, Key-Replacement နဲ့ Peer Recovery လုပ်ငန်းစဉ်များ။

မူလတန်းကို သတ်မှတ်ရာတွင် [လုံခြုံရေး မူဝါဒများ](./security-principles.md) နှင့် [လွတ်မြောက်ရန် အသင့်ရှိခြင်း](../best-practices/release-readiness.md) ကို ပြန်လည်သုံးသပ်ပါ။

## Key များနှင့် cryptographic signers တို့ကို ကာကွယ်ပါ။ {#protect-keys-and-signers}

- ပုဂ္ဂလိက သော့တွေ၊ မျိုးစေ့ပစ္စည်းတွေ၊ သယ်ဆောင်သူ လိပ်စာတွေ၊ ခွင့်ပြုချက် ခေါင်းစဉ်တွေနဲ့ ပြန်လည်ထူထောင်ရေး လျှို့ဝှက်ချက်တွေကို အရင်းအမြစ် ထိန်းချုပ်မှုကနေ ဖယ်ရှားထားပါ၊ ခြေရာခံကိရိယာတွေကို ထုတ်ပေးပါ၊ စကားပြော အသံထွက်၊ ဖန်သားပြင်ပုံတွေ၊ အများပြည်သူ မှတ်တမ်းတွေပါ။
- တန်ဖိုးမြင့် authority အကောင့်များအတွက် ဟာ့ဒ်ဝဲအခြေပြု သို့မဟုတ် သီးခြားခွဲထားသော လက်မှတ်ထိုးမှုကို အသုံးပြုပါ။ client က လက်မှတ်ထိုးခြင်းကို လွှဲအပ်နိုင်လျှင် ကီးဒေတာအကြမ်းကို ဘရောက်ဇာများနှင့် ယေဘုယျသုံးအက်ပ်လုပ်ငန်းစဉ်များ၏ ပြင်ပတွင် ထားပါ။
- ပုံမှန် ငွေပေးချေမှုတွေ၊ အုပ်ချုပ်ရေး၊ ဖြန့်ဖြူးမှု၊ ပြန်လည်ထူထောင်ရေးအတွက် သီးခြား ခွင့်ပြုချက် မူဝါဒတွေကို သုံးပါ။
- လျှို့ဝှက်တန်ဖိုးသိုလှောင်ရုံနှင့် ၎င်း၏ အရန်မိတ္တူများကို စာဝှက်ပါ။ လက်ရှိသုံးကီးအတွက် ဝင်ရောက်မှုထိန်းချုပ်ချက်များကို ကိုယ်ပိုင်ကီးအရန်မိတ္တူအတွက်လည်း အတူတူအသုံးပြုပါ။
- စစ်ဆေးထားတဲ့ အစားထိုးခြင်း (သို့) ပြန်လည်သိမ်းဆည်းခြင်း လုပ်ငန်းစဉ်ကို ထိန်းသိမ်းပါ။ မူဝါဒက တောင်းဆိုတဲ့အခါ သို့မဟုတ် ထိတွေ့မှု သံသယရှိတဲ့အခါ သော့တစ်ခုကို အစားထိုးပါ။
- အတည်ပြုသူအဖွဲ့ဝင်၊ အခွင့်ထူးခံတာဝန်များ (သို့) တန်ဖိုးမြင့် အရင်းအမြစ်များကို ပြောင်းလဲမှုအတွက် လွတ်လပ်စွာ စစ်ဆေးရန် တောင်းဆိုပါ။

[Cryptographic Key များကို ထုတ်လုပ်ခြင်း](./generating-cryptographic-keys.md) နှင့် [Cryptographic Key ကို သိုလှောင်ခြင်း](./storing-cryptographic-keys.md) တို့ကို ကြည့်ရှုပါ။

## Harden Nodes နှင့် Operator Access များ {#harden-nodes-and-operator-access}

- လက်ရှိမှာ ပေးသွင်းသူက ထောက်ပံ့တဲ့ စနစ်တွေမှာ node တွေနဲ့ operator tool တွေကို run လုပ်ပါ။ မလိုလားအပ်တဲ့ ဝန်ဆောင်မှုတွေ Disable လုပ်ပါ။
- အမည်တပ်ထားတဲ့ လုပ်ငန်းရှင်တွေကို စစ်ဆေးပြီး ကုဒ်သွင်းထားတဲ့ လမ်းကြောင်းတွေကနေသာ စီမံခန့်ခွဲရေးဝင်ရောက်ခွင့်ပေးပါ။
- ပုဂ္ဂလိက ကွန်ရက် (သို့) [VPN](./vpn.md) ပေါ်တွင် အများပြည်သူမဟုတ်သော ကြားခံစနစ်များကို ထည့်သွင်းပါ။
- Torii, စောင့်ကြည့်ခြင်းနှင့် အသုံးချမှု လမ်းကြောင်းများသာ ဖြန့်ဖြူးရန် လိုအပ်သည်။
- ပတ်ဝန်းကျင်အတွက် သင့်တော်တဲ့နှုန်းသတ်မှတ်ချက်တွေနဲ့ ပို့ဆောင်ရေး လုံခြုံမှုဖြင့် အများပြည်သူ ဝင်ရောက်ခွင့်တိုင်းကို ကာကွယ်ပါ။
- ကန့်သတ်ထားတဲ့ ဖိုင် ခွင့်ပြုချက်တွေနဲ့ ကွန်ဖူဂရေးရှင်း ဖိုင်များနဲ့ ဝန်ဆောင်မှု ခွင့်ပြုချက်ကို ကာကွယ်ပါ။ အမိန့်တန်းတွေ၊ လုပ်ငန်းစဉ် စာရင်းတွေနဲ့ shell သမိုင်းမှာ လျှို့ဝှက်ချက်တွေကို ရှောင်ရှားလိုက်ပါ။
- အန္တရာယ်မော်ဒယ်က သီးခြားထိန်းချုပ်မှု လိုအပ်လျှင် validator၊ client၊ စောင့်ကြည့်ရေးနှင့် အရန်သိမ်းဆည်းရေး လုပ်ငန်းများကို ခွဲခြားပါ။
- ယုံကြည်စိတ်ချရတဲ့ အရင်းအမြစ်တွေကနေ အချိန်ကို နှိုင်းယှဉ်ပါ။ စုံစမ်းနိုင်ဖို့ စနစ်၊ ဝန်ဆောင်မှုနဲ့ ကွန်ရက်မှတ်တမ်းတွေ လုံလောက်စွာ ထိန်းသိမ်းပါ။

## လုံခြုံသော Browser နှင့် Admin Workflows များ {#secure-browser-and-admin-workflows}

Web interface ကိုသုံးတဲ့ operator အတွက်:

- လက်ရှိမှာ ရောင်းသူက ထောက်ပံ့ပေးပြီး အပြည့်အဝ မွမ်းမံထားတဲ့ အလုပ်ရုံမှာ ရှာဖွေရေးကိရိယာကို သုံးပါ။
- လိုအပ်သော တိုးချဲ့ပရိုဂရမ်များသာ ပါသည့် သီးသန့်အော်ပရေတာပရိုဖိုင် သို့မဟုတ် ကိရိယာကို အသုံးပြုပါ။
- လျှောက်လွှာကို အတည်ပြုမပေးခင် မူလနေရာနဲ့ လက်မှတ်ကို စစ်ဆေးပါ။
- ဆင်တူယိုးမှား domain များ၊ မမျှော်လင့်သော ပြန်ညွှန်းမှုများနှင့် ကီးဒေတာအကြမ်းတောင်းဆိုမှုများကို လုံခြုံရေးဖြစ်ရပ်များအဖြစ် သတ်မှတ်ပါ။
- Active operator session ကနေ ဆက်စပ်မှုမရှိတဲ့ site တွေနဲ့ extension တွေကို ပိတ်ထားပါ။
- ခဏကြာတဲ့ အစည်းအဝေးတွေကို သုံးပါ။ အခွင့်ထူးခံ လုပ်ဆောင်ချက်တွေအတွက် ပြန်လည် စစ်ဆေးဖို့ လိုအပ်တယ်။
- ငွေပေးချေမှု အသေးစိတ်ကို cryptographic လက်မှတ်ရေးထိုးသူအားပြပါ။ လုပ်ငန်းရှင်သည် ခွင့်ပြုချက်အရင်းအမြစ်၊ ကွန်ရက်၊ ညွှန်ကြားချက်များ၊ အရင်းအမြစ်များနှင့် အခွန်များကို ခွင့်ပြုမပြုမီမှာ စစ်ဆေးနိုင်ရမည်။

Browser isolation က exposure ကို လျှော့ချပေးပါတယ်။ Operator တွေက Transaction တွေကို ပြန်လည်စစ်ဆေးပြီး Secure Signing ကို အသုံးပြုဖို့လိုတယ်။

## စောင့်ကြည့်ပြီး တုံ့ပြန်ခြင်း {#monitor-and-respond}

ဒီအချက်ပြမှုတွေကို စောင့်ကြည့်ပါ။

- validator နှင့် peer အဖွဲ့ဝင် ပြောင်းလဲမှုများ
- အထပ်ထပ် ခွင့်ပြုချက် ကျရှုံးမှု (သို့) ပုံမှန်မဟုတ်သော အခွင့်ထူးခံ ညွှန်ကြားချက်များ
- မမျှော်လင့်တဲ့ ဆော့ဝဲ၊ ဖွဲ့စည်းပုံ (သို့) လမ်းကြောင်း ပြောင်းလဲမှု
- ပုံမှန်အခြေခံအတိုင်းအတာထက်ကျော်သော လက်မှတ်ထိုးမှု၊ query နှင့် transaction ချို့ယွင်းမှုများ
- ရင်းမြစ်ကုန်ဆုံးမှု၊ သဘောတူညီချက် ရပ်တန့်ခြင်း သို့မဟုတ် မျှော်မှန်းထားသော ကွန်ရက် အဖော်များ ဆုံးရှုံးမှု
- ငွေလှည့်စားမှု စည်းမျဉ်းတွေနဲ့ ကိုက်ညီတဲ့ အရင်းအမြစ်၊ ခွင့်ပြုချက်နဲ့ အကောင့် ပြောင်းလဲမှု

သက်ရောက်မှုရှိသော host နှင့် သီးခြားဖြစ်သော ချန်နယ်သို့ သတိပေးချက်များ ပို့ပါ။ သက်ဆိုင်ရာမှတ်တမ်းများ၊ ပြင်ဆင်သတ်မှတ်မှု snapshot များ၊ လယ်ဂျာဖြစ်ရပ်များနှင့် transaction ဟက်ရှ်များကို အချိန်အမှတ်အသားများနှင့်အတူ ထိန်းသိမ်းပါ။ [လိမ်လည်မှုစောင့်ကြည့်ရေး](./fraud-monitoring.md) နှင့် [စွမ်းဆောင်ရည်နှင့် တိုင်းတာချက်များ](../advanced/metrics.md) ကို ကြည့်ပါ။

## ပြန်လည်ထူထောင်ရေး အစီအစဉ် {#recovery-plan}

ထုတ်လုပ်မှုကို မစတင်ခင် ပြန်လည်ထူထောင်ရေး အစီအစဉ်ကို ပြင်ဆင်ပါ။ ပြန်လည်ထူထပ်ရေး အစီအစဉ်မှာ

- အဖြစ်အပျက်ကို ကြေညာပြီး ညှိနှိုင်းနိုင်သူ
- အတည်ပြုသူများ၊ အခြေခံအဆောက်အအုံစီမံခန့်ခွဲသူများ၊ အက်ပ်ပိုင်ရှင်များနှင့် သက်ရောက်သော အသုံးပြုသူများနှင့် ဆက်သွယ်ရန် နည်းလမ်းများ
- ဘယ် ခွင့်ပြုချက် မူဝါဒတွေက ခွင့်ပြုချက်ကို ရုပ်သိမ်းနိုင်တယ်၊ သော့တွေကို အစားထိုးနိုင်တယ်၊ (သို့) ကွန်ရက် တူညီတဲ့ အဖွဲ့ဝင်အဖြစ် ပြောင်းလဲနိုင်ပါတယ်။
- ယုံကြည်စိတ်ချရတဲ့ ဘိုင်နရီတွေ၊ ဖွဲ့စည်းပုံ၊ blockchain ဗီဇမှတ်တမ်းတွေ၊ Backup တွေနဲ့ Key Inventory တွေကို သိမ်းဆည်းထားတယ်။
- ပြန်လည်ထူထောင်ပြီးနောက်ကွန်ရက်နဲ့ မှီခိုတဲ့ အက်ပ်တွေကို ဘယ်လို validate လုပ်ရမလဲ

မတော်တဆမှုတစ်ခုဖြစ်တဲ့အခါ

1. သက်ရောက်မှုရှိသော host၊ အထောက်အထား၊ လမ်းကြောင်း သို့မဟုတ် authority အကောင့်ကို သီးခြားခွဲထားပါ။ အထောက်အထားများကို ထိန်းသိမ်းပါ။
2. မှတ်တမ်းများနှင့် blockchain ledger ကို ရည်ညွှန်းချက်များကို သိမ်းဆည်းပါ။ ပြန်လည်ထူထောင်ရေးလုပ်ဆောင်မှုတိုင်းကို မှတ်တမ်းတင်ပါ။
3. အသိအမှတ်ပြုသော အုပ်ချုပ်ရေးလုပ်ငန်းစဉ်မှတစ်ဆင့် ဖွင့်ဟထားသည့် ခွင့်ပြုချက်များနှင့် ခွင့်ပြုချက်ကို ပယ်ဖျက်ခြင်း သို့မဟုတ် အစားထိုးခြင်း။
4. စစ်ဆေးထားတဲ့ လက်ရာတွေကနေ ဆော့ဖ်ဝဲနဲ့ ဖွဲ့စည်းမှုကို ပြန်လည်ထူထောင်ပါ။
5. peer အဖွဲ့ဝင်ဖြစ်မှု၊ သဘောတူညီမှုလုပ်ငန်းစဉ် အခြေအနေ၊ အများသုံးလမ်းကြောင်းများ၊ စောင့်ကြည့်မှုနှင့် အက်ပ်ဖတ်ရှုမှုတို့ကို အတည်ပြုပါ။ ဤစစ်ဆေးမှုများ အောင်မြင်ပြီးမှသာ ရေးသားမှုများကို ပြန်စပါ။
6. အဓိက အကြောင်းရင်းကို မှတ်တမ်းတင်ပါ။ ထိန်းချုပ်မှုတွေ၊ အလိုအလျောက်လုပ်ခြင်းနဲ့ လေ့ကျင့်ခန်းတွေကို မွမ်းမံလိုက်ပါ။

::: warning

မပြန်လည်နိုင်သော blockchain ledger လုပ်ဆောင်ချက်များအတွက် ကြိုတင်စစ်ဆေးထားသည့် လုပ်ငန်းစဉ်များကို လိုက်နာပါ။ သက်ရောက်မှုရှိသည့် ခွင့်ပြုချက် အရင်းအမြစ်နှင့် ပိုင်ဆိုင်မှုများအတွက် သင့်လျော်သော ခွင့်ပြုချက်ကို တောင်းဆိုပါ။

:::
