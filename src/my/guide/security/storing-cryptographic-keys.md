# Cryptographic Key များကို သိမ်းဆည်းခြင်း {#storing-cryptographic-keys}

သင့်ရဲ့ အာရုံခံအချက်အလက်တွေဟာ ကိုယ်စားပြုမှုရှိရင်ပဲ ပုဂ္ဂလိကဖြစ်နေတာပါ။ <abbr title="Operational Security">OPSEC</abbr> လူ့အဖွဲ့အစည်းဆိုင်ရာ အင်ဂျင်နီယာ ခြိမ်းခြောက်ချက်များမှာ အာဏာရှိသူတစ်ဦးအဖြစ် ကိုယ်ဟန်ဆောင်ပြီး သင့်ရဲ့ ပုဂ္ဂလိက ပရိုဂရမ် သော့ကို ပေးဖို့ သင့်ကို လှည့်စားဖို့ကြိုးပမ်းနေတာပါ။ အမြဲ သတိထားပါ၊ သင့်ရဲ့ ပုဂၢလိက သော့ကို မျှဝေခြင်းကနေ ရှောင်ရှားပါ။ ဒါကို သင့်တိုက်ခန်း သော့တွေကို ယုံကြည်မှုရှိတဲ့ပုဂ္ဂိုလ်တွေအတွက်သာ သီးသန့်ထားသလို ပြုမူပါ။

ပိုမိုသိရှိလိုပါက <abbr title="Operational Security">OPSEC</abbr> အကောင်းဆုံးကျင့်သုံးမှုများကို ကြည့်ပါ [လုပ်ငန်းလုံခြုံရေး](./operational-security).

## လျှို့ဝှက်ချက်များကို ဒစ်ဂျစ်တယ်နည်းဖြင့် သိမ်းဆည်းခြင်း {#storing-cryptographic-keys-digitally}

သော့တွေကို ဒစ်ဂျစ်တယ်နည်းနဲ့ ကာကွယ်ဖို့ဆိုရင် အဓိကအားဖြင့် နည်းလမ်းနှစ်ခုပဲရှိပါတယ်[SSH](https://www.ssh.com/) နှင့် [GPG](https://www.gnupg.org/)ဒီနည်းလမ်းတွေက သင့်ရဲ့ cryptographic key တွေကို ခွင့်ပြုချက်မဲ့ ဝင်ရောက်ခွင့်ကို တားဆီးဖို့ လုံခြုံမှု အလွှာတွေပေးတယ်။

အများအပြား Iroha ဗိသုကာဆိုင်ရာ ဆုံးဖြတ်ချက်များကို အခြေခံမူများက လွှမ်းမိုးထားသည်။ **လုံခြုံသော Shell** (`SSH`) ပရိုတိုကောလဟာကို အဓိကထား၍ ဤအခန်းတွင် `SSH` သင်ရဲ့ cryptographic key တွေကို Iroha ဂေဟစနစ်။

### အသုံးပြုခြင်း SSH နှင့် SSH Agent ကို {#using-ssh-and-ssh-agent}

**လုံခြုံသော Shell Protocol** (`SSH`) သည် cryptographic network protocol တစ်ခုဖြစ်ပြီး virtual gateway အဖြစ်ဆောင်ရွက်ပြီး အဝေးပြေးစက်များသို့ လုံခြုံစွာဝင်ရောက်နိုင်ရန်အတွက် အလားအလာနည်းသော လုံခြုံမှုရှိတဲ့ကွန်ရက်များမှတစ်ဆင့် SSH keyaccess ခွင့်ပြုချက်များ။ ဤအခြေအနေတွင် ရုပ်ပိုင်းဆိုင်ရာ တည်ရှိမှုလိုအပ်ခြင်းမရှိဘဲ စနစ်များနှင့်ဝေးမှ တုံ့ပြန်ဆက်သွယ်ရန် ထိရောက်သောနည်းလမ်းကိုပေးသည်။ `SSH` အဓိက စစ်ဆေးရေး ယန္တရား နှစ်ခုကို ပေးထားပါတယ်- အစဉ်အလာ စကားဝှက် အခြေခံတဲ့ ချဉ်းကပ်နည်းနဲ့ ပိုလုံခြုံတဲ့ အများပြည်သူနဲ့ ပုဂ္ဂလိက သော့စုံ နည်းပါ။

ပိုမိုသိရှိလိုပါက `SSH`, ကြည့်ပါ [ဆက်စပ်သော SSH ပညာရေးဆိုင်ရာ အကြောင်းအရာ](https://www.ssh.com/academy/ssh).

Login ဖြစ်စဉ်ကို ချောမွေ့စေရန်နှင့် ထပ်တလဲလဲ ဝင်ရောက်မှုလိုအပ်ချက်ကို ရှောင်ရှားနိုင်ရန် `SSH` သော့များ **SSH Agent ကို** (`ssh-agent`)သင်ရဲ့ မှတ်ဉာဏ်ကို မှတ်မိစေတဲ့ အကူအကူ အစီအစဉ် `SSH` session တစ်ခုရဲ့ သက်တမ်းအတွက် key နဲ့/သို့မဟုတ် password တွေကို အသုံးပြုနိုင်ပါတယ်။ `SSH` အခြားစက်တွေနဲ့ ချိတ်ဆက်နေစဉ် ခလုတ်တွေကို အလွယ်တကူ ဝင်ရောက်နိုင်ဖို့ ဂိတ်တံခါးပါ။

အဝေးပြေးစနစ်မှာ အများသုံး သော့ကို သိမ်းထားပြီး ကိုယ်ရေးကိုယ်တာ သော့ကို လုံခြုံစွာ ထိန်းသိမ်းထားပါ။ `ssh-agent` သင့်ရဲ့ ဆက်သွယ်ရေးအတွက် လုပ်ဆောင်ချက်များ _အများပြည်သူ_ အဲဒီနောက်မှာ remote system က [စိန်ခေါ်မှု](https://en.wikipedia.org/wiki/Challenge%E2%80%93response_authentication) ဒါက သင့်အတွက်သာ _ပုဂ္ဂလိက_ သော့က သင့်တော်တဲ့ တုံ့ပြန်မှုကို ပေးနိုင်မှာပါ။ `ssh-agent` ဒီစိန်ခေါ်မှုကို သင့် _ပုဂ္ဂလိက_ Key က Remote System ကို မှန်ကန်တဲ့ တုံ့ပြန်မှုကို ပြန်ပို့ပေးပါတယ်။ ဒီတုံ့ပြန်မှုက စနစ်က မျှော်မှန်းခဲ့တာနဲ့ ကိုက်ညီတယ်ဆိုရင် ခင်ဗျားကို Access ပေးထားပါတယ်။

အလှတရားက `ssh-agent` session အတွင်းမှာ သင့်ရဲ့ private key ကို ထိန်းထားလို့ remote system နဲ့ ချိတ်ဆက်တိုင်း password (သို့) private key passphrase ကို ထပ်ပြီးထည့်ဖို့ မလိုပါဘူး။

ပိုမိုသိရှိလိုပါက `ssh-agent`, ကြည့်ပါ [ဆက်စပ်သော SSH ပညာရေးဆိုင်ရာ အကြောင်းအရာ](https://www.ssh.com/academy/ssh/agent).

::: info မှတ်ချက်

အသေးစိတ်အမြင်တစ်ခုအတွက် `SSH` ပရိုတိုကောလနှင့် `ssh-agent` tool ကို အောက်ပါအတိုင်း ကြည့်ပါ။ [SSH အကယ်ဒမီ](https://www.ssh.com/academy) အကြောင်းအရာများ:

  - [ဘာလဲ SSH (Secure Shell) ဆိုရင်ရော။](https://www.ssh.com/academy/ssh)
  - [ssh-agent: ssh-agen, agent forwarding, & agent protocol ကိုဘယ်လို configure လုပ်ရမလဲ](https://www.ssh.com/academy/ssh/agent)

:::

### Password Manager Program ကိုထည့်သွင်းခြင်း {#adding-a-password-manager-program}

သင့်ရဲ့ လုံခြုံမှုကို မြှင့်တင်ဖို့ အကြံပြုပါတယ်။ `SSH` သော့တွေကို စကားဝှက်နဲ့ ကာကွယ်ပေးခြင်းဖြင့်၊ အဲဒါဟာ သင့်ရဲ့ အာရုံခံ အချက်အလက်ကို ရယူရန် ရည်ရွယ်တဲ့ မကောင်းဆိုးဝါးများအတွက် နောက်ထပ် အတားအဆီးတစ်ခု ဖြစ်တယ်။

Password Manager အမျိုးမျိုးကို အသုံးပြုသူရဲ့ Passwords တွေကို သိမ်းဆည်းဖို့ သုံးနိုင်ပါတယ်။ `SSH` ခလုတ်တွေကို ယာယီပါ။ ရှင်းလင်းမှုအတွက် [KeePass](https://keepass.info/) ဥပမာ စကားဝှက် စီမံခန့်ခွဲသူအဖြစ် အသုံးပြုထားသည် [KeePassXC](https://keepassxc.org/) Linux အခြေပြု operating system တွေမှာ running port ပါ။

ဘယ်လို တပ်ဆင်ရမယ် ဆိုတာကို ညွှန်ကြားချက်များအတွက် KeePassXC ကြည့်ပါ [ဖွဲ့စည်းခြင်း KeePassXC](#configuring-keepassxc) အောက်က အပိုင်း။

![KeePassXC: `Main` မျက်နှာပြင် UI](../../../img/KeePassXC.png)

KeePassXC လုံခြုံမှု၊ ပျော့ပျောင်းမှု၊ ထိန်းချုပ်မှု တိုးမြှင့်ပေးပါတယ်။ `SSH` Key တွေကို key storage အတွက် အသုံးပြုတဲ့အခါ ဒီ password manager က `ssh-agent` သိုလှောင်ထားသော သော့များနှင့်အတူ ၎င်း၏မှတ်ဉာဏ်မှ ချက်ချင်းဖယ်ရှားခြင်း KeePassXC ပြတင်းပေါက်ပိတ်ထားတယ်။

::: tip

သီအိုရီအရတော့ KeePass ဆိပ်ကမ်းများ [တရားဝင် ဝက်ဘ်ဆိုဒ်မှာ ဖော်ပြထားပါတယ်](https://keepass.info/download.html) အဓိက သိုလှောင်မှု ရည်ရွယ်ချက်အတွက် အသုံးပြုနိုင်ပါတယ်။
အောက်ပါအချက်တွေထဲက တစ်ခုကို အကြံပြုပါတယ်။ [KeePassX](https://www.keepassx.org/) ဒါမှမဟုတ် [KeePassXC](https://keepassxc.org/).

:::

#### ဖွဲ့စည်းခြင်း KeePassXC {#configuring-keepassxc}

ဖွဲ့စည်းရန် KeePassXC, အောက်ပါအတိုင်း လုပ်ပါ။

1. လွှတ်တင်ခြင်း KeePassXC, အဲဒီနောက် သွားပါ **ကိရိယာများ** > **Settings များ**, (သို့) **စက်ပစ္စည်းများ** အပေါ်က ခလုတ် UI panel ကို။

2. အထဲမှာ **Application Settings များ** ပေါ်လာတဲ့ tab ကို select လုပ်ပါ။ **SSH Agent ကို** ဘယ်ဘက်စာရင်းထဲကနေပြီး **Activate လုပ်ပေးပါ SSH ကိုယ်စားလှယ် ပေါင်းစပ်ခြင်း** စစ်ဆေးရေးသေတ္တာ။

   ::: info ရည်ညွှန်းသော ဖန်သားပြင်ပုံများကို ပြ

   ![KeePassXC `SSH Agent` tab: enable လုပ်ခြင်း SSH Agent ကို](../../../img/keepassxc_ssh_agent.png)

   :::

3. အသစ်တစ်ခု ဖန်တီးပါ။ KeePassXC ဒေတာဘေ့စ်၊ ညွှန်ကြားချက်များအတွက် [KeePassXC အသုံးပြုသူ လမ်းညွှန် > ပထမဦးဆုံး ဒေတာဘေ့စ်ကို ဖန်တီးခြင်း](https://keepassxc.org/docs/KeePassXC_UserGuide#_creating_your_first_database).

4. သော့တိုင်းအတွက် KeePassXC ဖန်တီးထားတဲ့ ဒေတာဘေ့စ်ကို အောက်ပါအတိုင်း လုပ်ပါ။

   - ဒေတာဘေ့စ်ထဲတွင် စာရင်းအသစ်တစ်ခု ထည့်ပါ။ ညွှန်ကြားချက်များအတွက် [KeePassXC အသုံးပြုသူ လမ်းညွှန် > ပထမဦးဆုံး ဒေတာဘေ့စ်ကို ဖန်တီးခြင်း](https://keepassxc.org/docs/KeePassXC_UserGuide#_creating_your_first_database).

   - စာရင်းသစ်တစ်ခု ထည့်သွင်းတဲ့အခါ Key ပါတဲ့ ဖိုင်ကို အောက်ပါအတိုင်းလုပ်ပြီး ချိတ်ဆက်ပါ။ **အဆင့်မြင့်** ဘယ်ဘက်က Menu ကနေ ရွေးလိုက်ပါ **ပေါင်းထည့်ခြင်း** အထဲမှာ **ချိတ်ဆက်ချက်များ** ကဏ္ဍမှာ လိုအပ်တဲ့ ဖိုင်ကို ရွေးပါ။ **ဖိုင်များကို ရွေးချယ်ပါ** ပြူတင်းပေါက် ပေါ်လာပါတယ်။

   - စာရင်းသစ်တစ်ခုထည့်တဲ့အခါ ရွေးပါ။ **SSH Agent ကို** ဘယ်ဘက်စာရင်းကနေ key ဖိုင်ကိုရွေးချယ်ပါ။ **ချိတ်ဆက်ခြင်း** စာရင်းမှာ **ပုဂ္ဂလိက သော့** Section ကိုရွေးပြီးနောက် အောက်ပါ checkbox တွေကို ရွေးပါ။

      - **ဒေတာဘေ့စ်ဖွင့်/ပိတ်တဲ့အခါ Agent ကို Key ထည့်သွင်းပါ။**

      - **ဒေတာဘေ့စ် ပိတ်ထား/ပိတ်ထားတဲ့အခါ Agent က Key ကို ဖယ်ရှားပါ။**

      - **ဤသော့ကို အသုံးပြုသည့်အခါ အသုံးပြုသူအား အတည်ပြုရန် လိုအပ်သည်**

   - လိုအပ်ရင် စာရင်းကို အခြားအပြောင်းအလဲတွေ လုပ်ပါ။

   - အဆင်သင့်ဖြစ်တဲ့အခါ ရွေးပါ။ **OK** ဝင်ရောက်မှုကို ကယ်တင်ဖို့ပါ။

   ::: details ရည်ညွှန်းသော ဖန်သားပြင်ပုံများကို ပြသပါ

   ![KeePassXC `Advanced` tab: Private key ကို ချိတ်ဆက်ခြင်း](../../../img/keepassxc_private_key.png)

   ![KeePassXC `SSH Agent` tab: Private key ကို ချိတ်ဆက်ခြင်း](../../../img/keepassxc_pk_agent.png)

   :::

##### မျှော်လင့်ထားသော ရလဒ်များ {#expected-results}

- ပရိုဂရမ်နှင့် `shh` key တွေကို entry အဖြစ် stored လုပ်ထားပါတယ် KeePassXC ဒေတာဘေ့စ်ကို Access လုပ်နိုင်ပြီး KeePassXC ပြတင်းပေါက် ဖွင့်ထားတယ်။

- သိုလှောင်ထားသော cryptographic နှင့် `ssh` ခွင့်ပြုချက်အတွက် လိုအပ်တဲ့ အချိန်တိုင်း သော့တွေကို အသုံးပြုနိုင်ပါတယ်။

- သိုလှောင်ထားသော cryptographic နှင့် `ssh` သော့တွေကို `ssh-agent` တစ်ကြိမ်မှာ KeePassXC ပြတင်းပေါက်ပိတ်ထားတယ်။

::: info မှတ်ချက်

မပြုလုပ်ဘဲနဲ့ **ဤသော့ကို အသုံးပြုသည့်အခါ အသုံးပြုသူအား အတည်ပြုရန် လိုအပ်သည်** ရွေးချယ်မှု `ssh-agent` Key ကိုပေးထားတဲ့ လုပ်ငန်းစဉ်ကို စောင့်ကြည့်မနေနိုင်ပါဘူး။ Password Manager လုပ်ငန်းစဉ်ဟာ malware (သို့) system service တစ်ခုကနေ `SIGKILL` အချက်ပြချက်က သော့ဟာ `ssh-agent`, Unix စနစ် အစီအစဉ်တွေက ကြားဖြတ်လို့မရတော့ဘူး `SIGKILL`.

:::

## သော့တွေကို ရုပ်ပိုင်းအရ သိုလှောင်ခြင်း {#storing-cryptographic-keys-physically}

Offline လုံခြုံမှု အဆင့်မြင့်ဆုံးကို ရှာဖွေသူများအတွက် crypto keys တွေကို သိမ်းဆည်းထားခြင်းသည် ဒစ်ဂျစ်တယ်ကွန်ရက်များနှင့် လုံးဝဆက်သွယ်မှုမရှိဘဲ ကျန်ရှိနေစေရန် ရုပ်ပိုင်းအရ အာမခံပေးပြီး ထို့ကြောင့် ခွင့်ပြုချက်မဲ့ဝင်ရောက်မှုအန္တရာယ်ကို အနည်းဆုံးအထိ လျှော့ချပေးသည်။ ရုပ်ပိုင်းရွေးချယ်မှုကို အသိအမှတ်ပြုခြင်းက မတူညီသောလုံခြုံရေးလိုအပ်ချက်များကို ဖြည့်စွက်ရန် ကျွန်ုပ်တို့၏ ရည်မှန်းချက်ကို ထောက်ပြသည်။

### Hardware Key ကို အသုံးပြုခြင်း {#using-a-hardware-key}

ကျွန်တော်တို့အဖွဲ့က Hardware Key တွေကို အကောင်းဆုံး လုံခြုံရေး အကောင်အထည်တွေထဲက တစ်ခုလို့ ယူဆပါတယ်။ USB အော်တိုဖုန်းများတွင်အော်တိုဖိုင်များရှိပြီး ပုံမှန် flash drive အရွယ်အစားရှိသည်

သို့သော် Hardware Key များ၏ Brand များစွာရှိသည် APIs သင်ရဲ့ လိုအပ်ချက်တွေကို အကောင်းဆုံး လိုက်ဖက်တဲ့ သော့ကို ရှာဖွေဖို့ စျေးကွက်ကို သုတေသနပြုခြင်းဟာ အရေးကြီးပါတယ်။

အခုထိ ကျွန်တော်တို့အဖွဲ့က အတွင်းပိုင်းမှာ စမ်းသပ်ထားပါတယ် [YubiKey 5C](https://www.yubico.com/il/product/yubikey-5c/) hardware key များစွာသောအပြုသဘောဆောင်ချက်များရှိကြောင်း သက်သေပြခဲ့သည် API လုပ်ဆောင်မှု။

ဒါပေမဲ့ စဉ်းစားစရာ ရှိနိုင်တဲ့ အားနည်းချက်တစ်ခုရှိပါတယ်။ [HMAC စိန်ခေါ်မှု-တုံ့ပြန်မှု စစ်ဆေးခြင်း](https://en.wikipedia.org/wiki/Challenge%E2%80%93response_authentication) နောက်ပြီး ဆက်စပ်တဲ့ စာရွက်စာတမ်းကို သိုလှောင်ပေးခြင်း _ပုဂ္ဂလိက_ ဒီတုံ့ပြန်မှုအတွက် အဓိကအချက်က အားနည်းချက်တစ်ခု ဖန်တီးနိုင်လောက်တယ်။ ဒီအခြေအနေက တိုက်ခိုက်သူတွေကို မတော်တဆပဲ YubiKey 5C ရဲ့ မှတ်ဉာဏ်ကို ထိခိုက်စေပြီး လုံခြုံမှုကို ထိခိုက်စေပါတယ်။

ကံကောင်းချင်တော့ ဒီအားနည်းချက်ကို အသုံးချဖို့ အခြားနည်းလမ်းတစ်ခုခုကိုသုံးပြီး လျှော့ချနိုင်ပါတယ်။ YubiKey 5C. စိတ်ကူးက သုံးဖို့ပါ။ YubiKey 5C ကို လုံခြုံစွာ ဝင်ရောက်ရန် KeePassXC သင့်ရဲ့ cryptographic နဲ့ `SSH` Key တွေကိုတောင် အသုံးဝင်တယ်လို့ ယူဆနိုင်ပါတယ်၊ အကြောင်းက စကားဝှက်အများစုရဲ့ လုံခြုံမှုကို ကျော်လွှားပြီး အန္တရာယ်ရှိတဲ့ ဖက်က သင့်ရဲ့ Hardware key ကို ပိုင်ဆိုင်ဖို့ လိုအပ်စေလို့ပါ။ KeePassXC ဒေတာဘေ့စ်က စိမ့်ဝင်နေတယ်။

### Mnemonic ဝါကျကို အသုံးပြုခြင်း {#using-a-mnemonic-phrase}

အခြားနည်းတစ်ခုအနေနဲ့ ပုဂ္ဂလိက သော့ကို စကားလုံးတစ်သီကြီးအဖြစ် မှတ်သားနိုင်ပါတယ် _mnemonic စကားစု_. ဒီနည်းလမ်းကို Wallet များစွာမှာ အသုံးပြုပြီး စကားလုံး ၂၅ လုံးလောက် မှတ်မိဖို့ လိုအပ်ပါတယ်။ KeePassXC, Mnemonic Passphrase Generation ကို ပေးနိုင်ပါတယ်။
