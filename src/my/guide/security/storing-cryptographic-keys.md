# Cryptographic Key ကို သိုလှောင်ခြင်း {#storing-cryptographic-keys}

<abbr title="Operational Security">OPSEC</abbr> သော့တွေကို ကာကွယ်ဖို့ အလေ့အထတွေ အကောင်အထည်ဖော်ရင်သာ သင့်ရဲ့ အာရုံခံအချက်အလက်တွေဟာ ပုဂ္ဂလိကအဖြစ် ကျန်ရစ်မှာပါ လူမှုရေး အင်ဂျင်နီယာ ခြိမ်းခြောက်မှုတွေ၊ အာဏာရှိသူတစ်ယောက်အနေနဲ့ ကိုယ်ဟန်ဆောင်ပြီး သင့်ကို လှည့်စားပေးပြီး သင့်ကိုယ်ပိုင် သော့ကို ပေးဖို့ ကြိုးစားတဲ့အခါတွေက တကယ့်ပါ။ သင့်ရဲ့ ပုဂ္ဂလိက သော့ကို အမြဲသတိထားပြီး မျှဝေခြင်း ရှောင်ရှားပါ၊ ဒါကို သင့်တိုက်ခန်း သော့တွေကို ယုံကြည်မှုရှိသူတွေအတွက်သာ သိမ်းဆည်းထားသလို ဆက်ဆံပါ။

<abbr title="Operational Security">OPSEC</abbr> နှင့် ၎င်း၏အကောင်းဆုံးကျင့်သုံးမှုများနှင့် ပတ်သက်၍ ပိုမိုသိရှိလိုပါက [စီမံခန့်ခွဲရေးလုံခြုံရေး ](./operational-security) ကို ကြည့်ပါ။

## လျှို့ဝှက်သော့များကို ဒစ်ဂျစ်တယ်နည်းဖြင့် သိမ်းဆည်းခြင်း {#storing-cryptographic-keys-digitally}

Cryptographic keys များကို ဒစ်ဂျစ်တယ်နည်းဖြင့်ကာကွယ်ရာတွင် အဓိကအားဖြင့် [SSH](https://www.ssh.com/) [ GPG ](https://www.gnupg.org/)  ကိုသာ အသုံးပြုနိုင်သည်။ ဤနည်းစနစ်များသည် သင်၏ cryptographic key များသို့ ခွင့်ပြုချက်မရှိသော ဝင်ရောက်မှုကို တားဆီးရန် လုံခြုံမှု အလွှာများကိုပေးသည်။

Iroha ဗိသုကာဆိုင်ရာ ဆုံးဖြတ်ချက်များစွာကို Secure Shell (`SSH`) မူဝါဒများက လွှမ်းမိုးထားပြီး ဒါကြောင့် ဒီပိုင်းမှာ အဓိကအားဖြင့် `SSH` ချဉ်းကပ်မှုကို အာရုံစိုက်တာပါ။ Iroha ဂေဟစနစ်အတွင်းမှာ သင်ရဲ့ cryptographic key တွေကို သိုလှောင်ဖို့ ပရိုတိုကောကို ဘယ်လို ထိရောက်စွာ အကောင်အထည်ဖော်ရမလဲဆိုတဲ့ ညွှန်ကြားချက်တွေကို ပေးပို့တယ်။

### SSH နှင့် SSH Agent များကို အသုံးပြုခြင်း {#using-ssh-and-ssh-agent}

လုံခြုံသော Shell Protocol (`SSH`) သည် virtual gateway အဖြစ် လုပ်ဆောင်သော cryptographic network protocol တစ်ခုဖြစ်သည်။ အဝေးပြေးစက်များသို့ လုံခြုံမှုနည်းပါးသော ကွန်ရက်များမှတဆင့် လုံခြုံစွာ ဝင်ရောက်နိုင်စေရန်၊ SSH key  access credentials. ၎င်းသည် ရုပ်ပိုင်းဆိုင်ရာ လိုအပ်ချက်မရှိဘဲ စနစ်များနှင့် အဝေးမှ တုံ့ပြန်ဆက်သွယ်နိုင်ရန် ထိရောက်သောနည်းလမ်းကိုပေးသည်။ ဒီအခြေအနေမှာ `SSH` အဓိက စစ်ဆေးရေး ယန္တရား နှစ်ခုကို ပေးထားပါတယ် - အစဉ်အလာ စကားဝှက်အခြေခံ ချဉ်းကပ်မှု နဲ့ ပိုလုံခြုံတဲ့ အများပြည်သူနဲ့ ပုဂ္ဂလိက သော့ စုံတွဲနည်း။

`SSH` နှင့် ပတ်သက်ပြီး ပိုမိုသိရှိလိုပါက [နှင့် ဆက်စပ်သော SSH Academy အကြောင်းအရာ](https://www.ssh.com/academy/ssh) ကို ကြည့်ရှုပါ။

SSH Agent (`ssh-agent`) နဲ့အတူ `SSH` ခလုတ်တွေကို ပေါင်းစပ်နိုင်ပြီး session တစ်ခုအတွင်းမှာ သင့်ရဲ့ `SSH` ခလုတ်နဲ့/သို့မဟုတ် စကားဝှက်ကို မှတ်မိစေတဲ့ အကူအကူပရိုဂရမ်ကို သုံးနိုင်ပါတယ်။ `SSH` Gateway သည် အခြားစက်များနှင့် ချိတ်ဆက်နေသည့် အချိန်တိုင်း သော့များကို အလွယ်တကူ ဝင်ရောက်နိုင်ရန် ဤစနစ်က ခွင့်ပြုသည်။

`ssh-agent` ကတော့ သင့်ရဲ့ အများသုံး သော့ကို ဝေးလံတဲ့ စနစ်မှာ သိမ်းထားပြီး သင့်ရဲ့ ပုဂ္ဂလိက သော့ကို လုံခြုံစွာ ထိန်းသိမ်းပါတယ်။ ဝေးလမ်တဲ့ စနစ်တစ်ခုကို ဝင်ရောက်ချင်တဲ့အခါတိုင်း သင့်ရဲ့ အများပိုင် သော့ကို ဝင်ရောက်နေတဲ့ စနစ်ဆီ ဆက်သွယ်ဖို့ လုပ်ဆောင်တယ်။ [စိန်ခေါ်မှု](https://en.wikipedia.org/wiki/Challenge%E2%80%93response_authentication) ကို Remote System ကပြန်ပို့ပေးပြီး သင့်ရဲ့ Private Key ကသာ မှန်ကန်စွာ တုံ့ပြန်နိုင်တာပါ။ သင့်ရဲ့ `ssh-agent` သည် ဒီစိန်ခေါ်မှုကို သင့်ရဲ့ Private key ကို အသုံးပြုပြီး သင့်အမှန်ကန်တုံ့ပြန်မှုကို Remote System သို့ ပြန်ပို့တယ်။ တုံ့ပြန်မှုက စနစ်ရဲ့ မျှော်လင့်ချက်နဲ့ ကိုက်ညီတယ်ဆိုရင် ခင်ဗျားကို ဝင်ခွင့်ပေးထားပါတယ်။

`ssh-agent` ရဲ့ အလှတရားက ၎င်းဟာ သင့်ရဲ့ session အတွင်းမှာ သင့်ရဲ့ private key ကို ထိန်းထားတာပါ။ ဒီတော့ ဝေးလံတဲ့စနစ်နဲ့ ချိတ်ဆက်တိုင်း password (သို့) private key passphrase ကို ထပ်ပြီးထည့်ဖို့ မလိုပါဘူး။

`ssh-agent` နှင့် ပတ်သက်၍ ပိုမိုသိရှိလိုပါက [နှင့် ဆက်စပ်သော SSH Academy အကြောင်းအရာကို ](https://www.ssh.com/academy/ssh/agent) ကိုကြည့်ပါ။

::: info မှတ်ချက်

`SSH` အစီရင်ခံစာနှင့် `ssh-agent` ကိရိယာကို အသေးစိတ်ကြည့်ရှုရန်၊ အောက်ပါ [SSH Academy ](https://www.ssh.com/academy) အကြောင်းအရာများကို ကြည့်ပါ။

  - [ဘာလဲ SSH (Secure Shell) ဆိုပါစို့။](https://www.ssh.com/academy/ssh)
  - [ssh-agent: ssh-agen, agent forwarding, & agent protocol](https://www.ssh.com/academy/ssh/agent) ကိုဘယ်လို configure လုပ်ရမလဲ

:::

### Password Manager Program ကိုထည့်သွင်းခြင်း {#adding-a-password-manager-program}

`SSH` သော့တွေကို စကားဝှက်နဲ့ ကာကွယ်ပြီး လုံခြုံမှုကို မြှင့်တင်ဖို့ အကြံပြုထားတယ်၊ ဒါက သင့်ရဲ့ အာရုံခံသိသာတဲ့ အချက်အလက်တွေ ရယူဖို့ ရည်ရွယ်တဲ့ မကောင်းဆိုးဝါးဘက်တွေရဲ့ လမ်းကြောင်းမှာ နောက်ထပ် အတားအဆီးတစ်ခုအဖြစ် လုပ်ဆောင်ပါတယ်။

အသုံးပြုသူ စကားဝှက်များနှင့် `SSH` သော့များကို ယာယီသိမ်းဆည်းရန် password manager အမျိုးမျိုးအသုံးပြုနိုင်သည်။ ရှင်းလင်းမှုအတွက် [KeePass](https://keepass.info/) ကိုဥပမာစကားဝှက် စီမံခန့်ခွဲသူအဖြစ်အသုံးပြုသည်၊ အထူးသဖြင့် Linux အခြေပြု operating systems များတွင်ပြေးဆွဲနေသော [KeePassXC](https://keepassxc.org/) ဆိပ်ကမ်းဖြစ်သည်။

KeePassXC ကိုဘယ်လိုတပ်ဆင်ရမလဲဆိုတဲ့ ညွှန်ကြားချက်များအတွက် အောက်ပါ [Configuring KeePassXC](#configuring-keepassxc) အပိုင်းကို ကြည့်ပါ။

![KeePassXC: `Main` screen UI ](../../../img/KeePassXC.png)

KeePassXC သည်တိုးတက်သောလုံခြုံမှု၊ ပျော့ပျောင်းမှုနှင့်ထိန်းချုပ်မှုကိုပေးသည်။ ၎င်းသည် စကားဝှက်များသာမက `SSH` သော့များကိုလည်း သိမ်းဆည်းထားသည်။ အဓိကအချက်အလက် သိုလှောင်ရန်အသုံးပြုသောအခါ၊ ဤစကားဝှက် စီမံခန့်ခွဲသူသည် `ssh-agent` ကိုသိမ်းဆည်းထားသော သော့များနှင့်အတူ ပေးသည်။ KeePassXC ပြတင်းပေါက်ပိတ်လိုက်တာနဲ့ ၎င်းရဲ့ မှတ်ဉာဏ်ကနေ ချက်ချင်း ဖယ်ရှားခံရတယ်။

::: အလှူငွေ

သီအိုရီအရတော့ KeePass ဆိပ်ကမ်း [တရားဝင် ဝက်ဘ်ဆိုက်မှာ ဖော်ပြထားပါတယ်](https://keepass.info/download.html) အဓိက သိုလှောင်ရေး ရည်ရွယ်ချက်များအတွက် အသုံးပြုနိုင်ပါသည်။ အောက်ပါအချက်များတွင် မည်သည့်အရာကိုမဆို အကြံပြုပါသည်။ [KeePassX](https://www.keepassx.org/) ဒါမှမဟုတ် [KeePassXC](https://keepassxc.org/).

:::

#### KeePassXC ကို ဖွဲ့စည်းခြင်း {#configuring-keepassxc}

KeePassXC ကို Configure လုပ်ဖို့ အောက်ပါ အဆင့်တွေကို လိုက်လုပ်ပါ။

1. KeePassXC ကိုစတင်ပြီး Tools > Settings သို့သွားပါ (သို့) အထက်ပိုင်း UI panel မှ Gear ခလုတ်ကိုရွေးပါ။

2. ပေါ်လာတဲ့ Application Settings tab မှာ ဘယ်ဘက်က menu ကနေ SSH Agent ကို ရွေးပြီး နောက်မှာ Enable SSH Agent ပေါင်းစပ်မှု စစ်ဆေးချက်ခွက်ကိုရွေးပါ။

   ::: info Reference Screenshot ကို ပြပါ

   ![KeePassXC `SSH Agent` tab: enable လုပ်ခြင်း SSH အရာရှိ။](../../../img/keepassxc_ssh_agent.png)

   :::

3. KeePassXC ဒေတာဘေ့စ်အသစ်တစ်ခု ဖန်တီးပါ။ ညွှန်ကြားချက်များအတွက် [KeePassXC အသုံးပြုသူ လမ်းညွှန် > သင့်ရဲ့ပထမဦးဆုံးဒေတာဘေ့စ်ကိုဖန်တီးခြင်း ](https://keepassxc.org/docs/KeePassXC_UserGuide#_creating_your_first_database) ကိုကြည့်ပါ။

4. ဖန်တီးထားတဲ့ KeePassXC ဒေတာဘေ့စ်မှာ သိမ်းထားချင်တဲ့ သော့တိုင်းအတွက် အောက်ပါအတိုင်း လုပ်ပါ။

   - ဒေတာဘေ့စ်ထဲတွင် စာရင်းအသစ်တစ်ခု ထည့်သွင်းပါ။ ညွှန်ကြားချက်များအတွက် [KeePassXC User Guide > Your First Database](https://keepassxc.org/docs/KeePassXC_UserGuide#_creating_your_first_database) ကို ဖန်တီးရန် ကြည့်ပါ။

   - စာရင်းအသစ်တစ်ခုထည့်တဲ့အခါ အောက်ပါအတိုင်းလုပ်ခြင်းဖြင့် သော့ပါတဲ့ ဖိုင်ကို ချိတ်ဆက်ပါ။ ဘယ်ဘက်စာအုပ်ထဲက Advanced ကိုရွေးပြီး Attachments အပိုင်းမှာ Add ကို ရွေးပြီး ပေါ်လာတဲ့ Select files ပြတင်းပေါက်က လိုအပ်တဲ့ဖိုင်ကို ရွေးပါ။

   - စာရင်းအသစ်တစ်ခုထည့်တဲ့အခါ ဘယ်ဘက်စာအုပ်ထဲက SSH Agent ကိုရွေးပါ၊ ပြီးရင် Private key အပိုင်းက Attachment ကနေထည့်ထားတဲ့ သော့ဖိုင်ကို ရွေးပါ။ နောက်ပြီး အောက်ပါ စစ်ဆေးမှုအကွက်တွေကို ရွေးပါ။

      - ဒေတာဘေ့စ်ဖွင့်/ပိတ်တဲ့အခါ Agent ကို Key ထည့်သွင်းပါ။

      - ဒေတာဘေ့စ် ပိတ်ထား/ပိတ်ထားတဲ့အခါ Agent က Key ကို ဖယ်ရှားပါ။

      - ဤခလုတ်ကို အသုံးပြုသည့်အခါ အသုံးပြုသူအား အတည်ပြုရန် လိုအပ်သည်

   - လိုအပ်ရင် စာရင်းမှာ အခြားအပြောင်းအလဲတွေ လုပ်ပေးပါ။

   - အဆင်သင့်ဖြစ်တဲ့အခါ OK ကိုရွေးပြီး စာရင်းကို သိမ်းထားပါ။

   :::

##### မျှော်လင့်ထားသော ရလဒ်များ {#expected-results}

- KeePassXC ဒေတာဘေ့စ်မှာ စာဝှက်ချက်နဲ့ `shh` သော့တွေကို ထည့်သွင်းထားပြီး KeePassXC ပြူတင်းပေါက်ဖွင့်နေတုန်း ဝင်ရောက်နိုင်တာပါ။

- သိုလှောင်ထားတဲ့ cryptographic နဲ့ `ssh` key တွေကို ခွင့်ပြုချက်အတွက် လိုအပ်တဲ့ အချိန်တိုင်း သုံးနိုင်ပါတယ်။

- သိုလှောင်ထားတဲ့ cryptographic နှင့် `ssh` သော့တွေကို ဖယ်ရှားလိုက်တယ် `ssh-agent` တစ်ကြိမ်မှာ KeePassXC ပြတင်းပေါက်ပိတ်ထားတယ်။

::: info မှတ်ချက်

`ssh-agent` သည် ဤသော့ကိုအသုံးပြုသည့်အခါ Require user confirmation ကိုဖွင့်မထားဘဲ ၎င်းအားသော့ပေးခဲ့သော လုပ်ငန်းစဉ်ကို စောင့်ကြည့်ခြင်းမရှိနိုင်ပါ။ စကားဝှက် စီမံခန့်ခွဲရေးလုပ်ငန်းစဉ်သည် `SIGKILL` အချက်ပြမှုမှတစ်ဆင့် မော်လ်ဝဲ သို့မဟုတ် စနစ်ဝန်ဆောင်မှုတစ်ခုမှ ရပ်ဆိုင်းပါက၊ Key ကို `ssh-agent` ထဲမှာ ကျန်ရစ်ဖို့ အလားအလာရှိတယ်၊ အကြောင်းက Unix စနစ် အစီအစဉ်တွေက `SIGKILL` ကို ကြားဖြတ်လို့မရလို့ပါ။

:::

## Cryptographic Key များကို ရုပ်ပိုင်းအရ သိမ်းဆည်းခြင်း {#storing-cryptographic-keys-physically}

အွန်လိုင်းမှာ လုံခြုံမှု အမြင့်ဆုံးအဆင့်ကို ရှာဖွေသူတွေအတွက် crypto keys တွေကို သိမ်းဆည်းဖို့ ရွေးချယ်မှုက key တွေဟာ ဒစ်ဂျစ်တယ်ကွန်ရက်တွေကနေ လုံးဝဖြတ်တောက်ထားတာကို ရုပ်ပိုင်းအရ အာမခံပေးပြီး ဒီလိုနဲ့ ခွင့်ပြုချက်မရှိတဲ့ ဝင်ရောက်မှုအန္တရာယ်ကို လျော့နည်းစေတယ်။ ရုပ်ပိုင်း ရွေးချယ်မှုကို အသိအမှတ်ပြုခြင်းဟာ မတူညီတဲ့ လုံခြုံရေး လိုအပ်ချက်တွေကို ဖြည့်ဆည်းဖို့ ကျွန်မတို့ရဲ့ ကတိကဝတ်ကို ထောက်ပြတယ်။

### Hardware Key ကို အသုံးပြုခြင်း {#using-a-hardware-key}

ကျွန်ုပ်တို့၏အဖွဲ့သည် Hardware Key ကိုအကောင်းဆုံးလုံခြုံရေးတိုင်းတာမှုတစ်ခုအဖြစ် သတ်မှတ်သည်။ Hardware key သည် USB ဆိပ်ကမ်းမှတစ်ဆင့် ချိတ်ဆက်ပြီး ပုံမှန် flash drive အရွယ်အစားရှိသည့် အသေးစားကိရိယာတစ်ခုဖြစ်ပြီး စက်နှင့် ချိတ်ဆက်ထားသောအခါသာ လုံခြုံရေးဆိုင်ရာဖြစ်ရပ်များကို စီမံခန့်ခွဲနိုင်သည်။ ဒါက လုံခြုံရေး ချိုးဖောက်မှုတစ်ခုရှိရင် ကိရိယာကို အလွယ်တကူ ဖြတ်တောက်ဖို့ (သို့) လိုအပ်တဲ့ အချိန်တိုင်း အခြားစက်နဲ့ ပြန်လည်ဆက်သွယ်ဖို့ ခွင့်ပြုတယ်။

သို့သော် Hardware Key များအတွက် Brand များစွာရှိပြီး တစ်ခုစီသည် ၎င်း၏ထူးခြားသော APIs သို့ဖြစ်၍ သင့်လိုအပ်ချက်များနှင့်အကောင်းဆုံး key ကိုရှာဖွေရန် စျေးကွက်ကို သုတေသနပြုရန် အရေးကြီးသည်။

လက်ရှိအချိန်အထိ ကျွန်တော်တို့အဖွဲ့က [YubiKey 5C](https://www.yubico.com/il/product/yubikey-5c/) Hardware Key ကို အပြည်ပြည်ဆိုင်ရာ စမ်းသပ်ထားပြီး ၎င်းမှာ အများအပြားပါဝင်တဲ့ API လုပ်ဆောင်ချက်တွေပါ ၀ င်သော အပြုသဘောဆောင်မှုများစွာ ရှိကြောင်း သက်သေပြထားပါတယ်။

[HMAC challenge-response authentication](https://en.wikipedia.org/wiki/Challenge%E2%80%93response_authentication) ကို အကောင်အထည်ဖော်ပြီး ဒီတုံ့ပြန်မှုအတွက် သက်ဆိုင်ရာ ပုဂ္ဂလိက သော့ကို သိုလှောင်ခြင်းက အားနည်းချက်တစ်ခု ဖန်တီးနိုင်သည်။ YubiKey 5C ရဲ့ မှတ်ဉာဏ်ထဲမှာ သိုလှောင်ထားတဲ့ အချက်အလက်တွေအကြောင်း ကျွမ်းကျင်တဲ့ ခန့်မှန်းချက်တွေ လုပ်ဖို့ တိုက်ခိုက်သူတွေကို မရည်ရွယ်ဘဲ ဒီစနစ်က ခွင့်ပြုနိုင်ပြီး ဒီနည်းနဲ့ ယေဘုယျ လုံခြုံရေးကို ထိခိုက်စေနိုင်ပါတယ်။

ကံကောင်းချင်တော့ YubiKey 5C ကို အသုံးပြုခြင်းအတွက် အခြားနည်းလမ်းတစ်ခုကို သုံးပြီး ဒီအားနည်းချက်ကို လျှော့ချနိုင်တာပါ။ စိတ်ကူးက သင့်ရဲ့ cryptographic နဲ့ `SSH` သော့တွေကို သိမ်းထားတဲ့ KeePassXC ဒေတာဘေ့စ်ဆီ လုံခြုံစွာ ဝင်ရောက်ဖို့ YubiKey 5C ကိုသုံးဖို့ပါ။ ဒီနည်းလမ်းကို အကျိုးရှိတယ်လို့တောင် ယူဆနိုင်တယ်၊ အကြောင်းက စကားဝှက်အများစုရဲ့ လုံခြုံမှုကို ကျော်လွှားပြီး KeePassXC ဒေတာဘေ့စ်က စိမ့်ဝင်သွားရင် မကောင်းဆိုးဝါးပါတီအတွက် သင့် Hardware Key ကို ပိုင်ဆိုင်ဖို့ လိုအပ်စေလို့ပါ။

### Mnemonic ဝါကျကို အသုံးပြုခြင်း {#using-a-mnemonic-phrase}

အခြားနည်းလမ်းတစ်ခုအနေနဲ့ mnemonic phrase လို့ခေါ်တဲ့ စကားလုံးတစ်သီကြီးအဖြစ် ပုဂ္ဂလိက သော့ကို မှတ်မိနိုင်ပါတယ် Wallet များစွာမှာ အသုံးပြုတဲ့ ဒီနည်းလမ်းဟာ သီးခြားစကားလုံး ၂၅ လုံးလောက် မှတ်မိဖို့လိုအပ်ပါတယ်။ အရင်ဆုံး ဆွေးနွေးခဲ့တဲ့ KeePassXC အပါအဝင် password manager အများစုက mnemonic passphrase generation ကိုပေးတယ်။
