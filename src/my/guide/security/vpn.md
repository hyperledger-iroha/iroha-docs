# Virtual Private Networks များ {#virtual-private-networks}

A ကို <abbr title="Virtual Private Network">VPN</abbr> ကွန်ရက်ထိန်းချုပ်မှုတစ်ခုဖြစ်သည်
ရနိုင်တဲ့ အကန့်အသတ်တွေကို Iroha ဝန်ဆောင်မှုအတွက် အများဆုံး အသုံးဝင်ပါတယ်။
validator တွေ၊ application backends တွေနဲ့ operator တွေကို အသုံးပြုတဲ့ consortium deployments
ဖွင့်ထားတဲ့ အင်တာနက်လမ်းကြောင်းတွေအစား ပုဂ္ဂလိကလိပ်စာတွေကနေ ဆက်သွယ်သင့်ပါတယ်။

A ကို VPN အစားထိုးမပေးပါ။ Iroha peer keys များ၊ account key များ၊ ခွင့်ပြုချက်များ၊ firewall များ
စည်းမျဉ်းများ၊ စောင့်ကြည့်ခြင်း၊ သို့မဟုတ် လုံခြုံသော သော့ သိုလှောင်ခြင်း။
နေရာချထားမှု နယ်နိမိတ်: VPN ကွန်ယက်ချိတ်ဆက်နိုင်မှုကို ကျဉ်းမြောင်းစေပြီး Iroha
ဘယ်အဖော်တွေနဲ့ အကောင့်တွေကို ယုံကြည်ရမလဲဆိုတာ ဖွဲ့စည်းပုံနဲ့ အုပ်ချုပ်ရေးက ဆုံးဖြတ်တယ်။

## A ကို ဘယ်အချိန်သုံးရမလဲ VPN {#when-to-use-a-vpn}

A ကိုသုံးပါ VPN ဘယ်အချိန်မှာ

- validator တွေကို အဖွဲ့အစည်းအမျိုးမျိုး (သို့) မတူညီတဲ့ hosting မှာ လည်ပတ်ပါတယ်။
  ပတ်ဝန်းကျင်
- Torii အသုံးပြုသူများ၊ သုံးစွဲသူများ သို့မဟုတ် ယုံကြည်မှုရှိသူများမှသာ ရယူနိုင်ရန် လိုအပ်ပါသည်။
  ဖောက်သည်များ
- မက်ထရစ်များ၊ မှတ်တမ်းများ SSH, (သို့) အခြားစီမံခန့်ခွဲမှုအဆုံးသတ်မှတ်ချက်တွေဟာ ပုဂ္ဂလိက
  လုပ်ငန်းရှင်ကွန်ရက်
- စမ်းသပ်မှု (သို့) အဆင့်သတ်မှတ်ရေးကွန်ရက်တစ်ခုဟာ ထုတ်လုပ်မှုဝင်ရောက်မှု ထိန်းချုပ်ချက်တွေနဲ့ မတူသင့်ပါ။
  အများပြည်သူအဆုံးသတ်မှတ်ချက်များကို ဖော်ထုတ်ခြင်း

A ကို VPN အများပြည်သူကွန်ရက်များမှာ ရည်ရွယ်ချက်ရှိပြီး
ပွင့်လင်းမြင်သာမှု Torii အများသုံးဂိတ်တံခါး၊ ဝန်ဆောင်မှု ဟန်ချက်ညီစက် (သို့) ပြန်လည်အထောက်အကူပေးစနစ်ကနေပါ။
ဒီကိစ္စမှာ validator peer-to-peer traffic နဲ့ အုပ်ချုပ်ရေး endpoint တွေကို
ဖြစ်နိုင်ခြေရှိတိုင်း ကန့်သတ်ထားတဲ့ ကွန်ရက်ပါ။

::: tip

ရှာဖွေရေးစနစ် VPN Browser ကနေ Traffic ကိုသာ ကာကွယ်ပေးပါတယ်။
`irohad`, CLI, SDK, SSH, မက်ထရစ်များ (သို့) backup traffic များကို ဒီလုပ်ငန်းစဉ်များက
အလားတူ ပုဂ္ဂလိက ကွန်ရက်ကနေ လမ်းညွှန်ပေးတယ်။

:::

## တပ်ဆင်မှု ပုံစံ {#deployment-pattern}

ပုဂ္ဂလိက validator mesh အတွက် validator တစ်ခုစီကို stable ပေးပါ။ VPN လိပ်စာ သို့မဟုတ်
ပုဂ္ဂလိက DNS peer-to-peer address တွေကို ကြော်ငြာပေးကြဖို့ peers ကို Configure လုပ်ပါ။
အခြား validator တွေကနေ ဒီကွန်ရက်ကနေ ဆက်သွယ်နိုင်တယ်

```toml
trusted_peers = [
  "PUBLIC_KEY_1@10.20.0.11:1337",
  "PUBLIC_KEY_2@10.20.0.12:1337",
  "PUBLIC_KEY_3@10.20.0.13:1337",
  "PUBLIC_KEY_4@10.20.0.14:1337",
]

[network]
address = "10.20.0.11:1337"
public_address = "10.20.0.11:1337"

[torii]
address = "10.20.0.11:8080"
```

လက်ရှိ peer ကို သတ်မှတ်ထားသောလိပ်စာကို အသုံးပြုပါ။ `network.address` နှင့်
`network.public_address`. တူညီတဲ့ ယုံကြည်မှုရှိတဲ့ တူညီတဲ့ ကိုယ်ပိုင်လက္ခဏာတွေကို တူညီတဲ့ တူတူချင်းစာရင်းတစ်ခုစီမှာ ရေးသင့်တယ်။
ဒါပေမဲ့ ကိုယ်ပိုင်နေရာကနေ ရောက်ရှိနိုင်တဲ့လိပ်စာတွေနဲ့ပါ။ VPN လမ်းကြောင်းဇယား။

ဖောက်သည်နှင့် CLI configurations တွေက A ကို ညွှန်ပြသင့်ပါတယ်။ Torii အဆုံးအဖြတ်ကို ဖြတ်ပြီး ရောက်ရှိနိုင်တယ်
ကော်မတီ VPN ဒါမှမဟုတ် ထိန်းချုပ်ထားတဲ့ အတွင်းရေးဂိတ်တစ်ခုမှတစ်ဆင့်:

```toml
torii_url = "http://10.20.0.11:8080"
```

(သို့) Torii နိုင်ငံခြားမှာ ရယူနိုင်ဖို့ လိုအပ်ပါတယ်။ VPN, ဒါကို နောက်ပြန်ရုံးမှာ ထားလိုက်၊
ဝန်ဆောင်မှု ဟန်ချက်ညီစက် TLS, အတည်ပြုချက်၊နှုန်းသတ်မှတ်ချက်နဲ့ မှတ်တမ်းတင်ခြင်း။
Peer-to-peer raw ports (သို့) administration endpoints တွေကို တိုက်ရိုက်
အများပြည်သူ အင်တာနက်။

## Firewall စည်းမျဉ်းများ {#firewall-rules}

host နဲ့ cloud firewall စည်းမျဉ်းတွေကို အသုံးပြုပါ VPN ရှိပါသည်-

| ဝန်ဆောင်မှု | အကြံပြုချက်များ |
| --- | --- |
| အချင်းချင်းဆန့်ကျင်ရေး ဆိပ်ကမ်း | အခြား validator VPN လိပ်စာများသာ |
| Torii | Application backends များ၊ operator များ သို့မဟုတ် ယုံကြည်သော client များ VPN ကန့်သတ်ချက်များ |
| မက်ထရစ်များနှင့် ကျန်းမာရေး စစ်ဆေးမှုများ | လုပ်ငန်းရှင်ကွန်ရက်ပေါ်ရှိ စောင့်ကြည့်ရေးစနစ်များ |
| SSH စီမံခန့်ခွဲမှု | Bastion အိမ်ရှင်၊ အခွင့်ထူးခံ လုပ်ငန်းရှင် VPN ရောင်စဉ် (သို့) ဖန်သားချိုးခြင်းလုပ်ငန်းစဉ် |
| Backup များနှင့် သိုလှောင်ခြင်း | သီးသန့်ကွန်ရက်ပေါ်တွင် Backup စနစ်များ |

Default denial စည်းမျဉ်းတွေကို ကျယ်ပြန့်တဲ့ ခွင့်ပြုချက်စည်းမျဉ်းတွေထက် စစ်ဆေးဖို့ ပိုလွယ်ပါတယ်။
ကွန်ရက်ကို ဝင်လာပြီး VPN အဖွဲ့ဝင်၊ firewall ခွင့်ပြုချက်စာရင်းနဲ့ Iroha
ကိုော်ဒင်းတင်ထားတဲ့ အပြောင်းအလဲတစ်ခုအဖြစ် ယုံကြည်မှုရှိတဲ့ တူညီတဲ့ ဖွဲ့စည်းပုံပါ။

## လုပ်ငန်းစစ်ဆေးမှု စာရင်း {#operational-checklist}

- စစ်ဆေးပြီး တက်ကြွစွာ ထိန်းသိမ်းထားသော တစ်ခုကို ရွေးချယ်ပါ။ VPN အကောင်အထည်ဖော်ခြင်း
  WireGuard, IPsec (သို့) အဖွဲ့အစည်းက ခွင့်ပြုထားတဲ့ စီမံခန့်ခွဲမှု သီးသန့်ကွန်ရက်ပါ။
- ထူးခြားသော အသုံးပြုမှု VPN host နဲ့ operator တစ်ခုစီအတွက် credentials တွေကို မမျှဝေပါနဲ့ VPN သော့များ
  validator တွေကြားမှာ
- ဆက်ထားပါ။ VPN ကွဲပြားတဲ့ ခွင့်ပြုချက်များ Iroha ပုဂ္ဂလိက သော့များနှင့် Genesis လက်မှတ်ရေးထိုးခြင်း
  ပစ္စည်း။
- မော်နီတာ VPN နောက်ဆုတ်မှု၊ ပိတ်ကက် ဆုံးရှုံးမှု၊ ပြန်လည်ဆက်သွယ်ခြင်း၊ လမ်းကြောင်းပြောင်းလဲခြင်းတို့ပါ။
  ရေရှည်တည်တံ့တဲ့ ကွန်ရက် မတည်ငြိမ်မှုအတွက် ထိခိုက်လွယ်ပါတယ်။
- ထိရောက်မှုကို စမ်းသပ်ပါ။ MTU. Package fragmentation က intermittent peer လိုမျိုး ထင်နိုင်ပါတယ်။
  ဒါမှမဟုတ် Torii ကျရှုံးမှု။
- မှတ်တမ်း VPN ကန့်သတ်ချက်များမှာ peer-to-peer ကို ရောက်ရှိခွင့်ပြုထားသည် Torii, မက်ထရစ်များ
  SSH, ပြီးတော့ ထောက်ပံ့တဲ့ အဆုံးအသတ်တွေပေါ့။
- လည်ပတ်ခြင်း VPN host, operator account သို့မဟုတ် အဖွဲ့အစည်းက ထွက်သွားတဲ့အခါ သရုပ်ဖော်ချက်များ
  ကွန်ရက်ကိုပါ။
- တစ်ယောက်တည်းကို ရှောင်ကြဉ်ပါ။ VPN Gateway ဟာ validator တွေကြားက တစ်ခုတည်းသော လမ်းကြောင်းပါ။
  ထုတ်လုပ်ရေးကွန်ရက်များအတွက် လျှော့ချထားသော gateways သို့မဟုတ် site to site routes များ။
- ပါဝင်ပါ VPN ဖြစ်စဉ် တုံ့ပြန်မှု လေ့ကျင့်ခန်းတွေမှာ ကျရှုံးမှုတွေရှိတယ် ဒီတော့ လုပ်ငန်းရှင်တွေက ဘယ်အချိန်မှာ လုပ်ရမှန်းသိဖို့
  Network partition ကို network partition ကနေ ခွဲခြားဖို့ Iroha လုပ်ငန်းစဉ် ပျက်ကွက်မှု။
