# လှည့်စားမှု စောင့်ကြည့်ခြင်း {#fraud-monitoring}

လိမ်လည်မှု စောင့်ကြည့်ခြင်း Iroha deployment ဆိုတာ operating control တစ်ခုပါ။
Ledger ဖြစ်ရပ်များ၊ မေးမြန်းချက်များ၊ ခွင့်ပြုချက်များနှင့် အသုံးချမှု အခြေအနေများ။ Iroha မှတ်တမ်းတင်
သင့်ရဲ့ စောင့်ကြည့်ရေးစနစ်က ဆုံးဖြတ်ချက်ချတယ်။
သင့်လုပ်ငန်းစဉ်အတွက် သံသယရှိတဲ့ ပုံစံတွေရှိပြီး ဒီကိစ္စတွေကို လမ်းညွှန်ပေးတယ်။
စစ်ဆေးသူ (သို့) အလိုအလျောက် တုံ့ပြန်မှု ထိန်းချုပ်သူတွေကိုပါ။

လှည့်စားမှု စောင့်ကြည့်မှုကို ရင်းမြစ်ထားတဲ့ ဆင်ခြင်တုံတရားအစား သီးခြား ဝန်ဆောင်မှုအဖြစ် ဆက်ဆံပါ။
ဝန်ဆောင်မှုသည် လက်မှတ်ထိုးထားသော စာရင်းအင်းလုပ်ငန်းကို လက်မှတ်ထိုး၍
Off-chain အရဲစွန့်မှု အခြေအနေများ၊ သက်သေခံချက်များကို ဆက်လက်တည်ရှိခြင်း၊ တုံ့ပြန်မှု ငွေကြေးကိုသာ တင်ပြခြင်း
ရှင်းလင်းတဲ့ ခွင့်ပြုချက်တွေရှိတဲ့ အကောင့်တွေကနေပါ။

## စောင့်ကြည့်မှုပုံစံ {#monitoring-model}

အသုံးဝင်တဲ့ စောင့်ကြည့်မှု ပိုက်လိုင်းမှာ အဆင့်လေးဆင့်ရှိပါတယ်။

1. **ကောက်ယူခြင်း** စာရင်းအင်းနဲ့ operator အချက်ပြမှု Torii ဖြစ်ရပ်စီးကြောင်းများ၊ မေးမြန်းချက်များ
   မက်ထရစ်တွေပေါ့။
2. **ချမ်းသာစေခြင်း** ဖောက်သည်အခြေအနေလို ချိတ်ဆက်မှုအပြင် အခြေအနေရှိဖြစ်ရပ်များ၊
   ငွေလဲလှယ်နှုန်းသမိုင်း
   ကိစ္စ IDs.
3. **ရှာဖွေခြင်း** စိစစ်သူတန်းတွေ၊ သတ်မှတ်တဲ့ စည်းမျဉ်းတွေနဲ့ သံသယရှိတဲ့ အပြုအမူ၊
   အရဲစွန့်မှတ်ချက်။
4. **တုံ့ပြန်ပါ** လုပ်ငန်းရှင်တွေကို သတိပေးခြင်းနဲ့ လျှောက်လွှာဘက်က အလုပ်ဖြစ်စဉ်တွေကို ရပ်ဆိုင်းခြင်းဖြင့်၊
   မလိုလားအပ်တဲ့ ခွင့်ပြုချက်တွေကို ရုပ်သိမ်းခြင်း၊ ဒါမှမဟုတ် လျော်ကြေးပေးချေမှုများကို တင်ပြခြင်း
   သင့် အုပ်ချုပ်ရေး လုပ်ငန်းစဉ်က ခွင့်ပြုတဲ့အခါမှာပေါ့။

မူဝါဒ ဆုံးဖြတ်ချက်တွေကို သဘောတူညီမှုမရှိဘဲ ထိန်းသိမ်းထားပါ။
Runtime validation ကတော့ ခွင့်ပြုချက်တွေနဲ့ ငွေကြေးပူးပေါင်းမှုတွေကို အကောင်အထည်ဖော်ဖို့ လိုပါတယ်။
လိမ်လည်မှု စောင့်ကြည့်မှုဟာ အရဲစွန့်မှုကို ရှင်းပြဖို့၊ အထောက်အထားတွေကို ထိန်းသိမ်းဖို့နဲ့ ကူညီဖို့ လိုပါတယ်။
လုပ်ငန်းရှင်တွေဟာ အမြန် လုပ်ဆောင်ကြမယ်။

## အချက်ပြမှုများကို စုစည်းရန် {#signals-to-collect}

သေးငယ်တဲ့ subscriptions နဲ့စပြီး စုံစမ်းရေးအတွက်သာ ပိုကျယ်ပြန့်တဲ့ stream တွေကို ထည့်ပါ။

| အချက်ပြချက် | မူရင်း | အသုံးပြုခြင်း |
| --- | --- | --- |
| ငွေပေးချေမှုအခြေအနေ | ရေငွေ့လိုင်းဖြစ်စဉ်များ | ထပ်တလဲလဲ ပယ်ချခြင်းတွေ၊ မအောင်မြင်တဲ့ ခွင့်ပြုမှု ကြိုးပမ်းမှုတွေ နဲ့ ထူးဆန်းတဲ့ တင်ပြမှု ပုံစံတွေကို ရှာဖွေပါ။ |
| အကောင့်သက်တမ်း စက်ဝန်းနှင့် မီတာဒေတာများ | ဒေတာဖြစ်ရပ်များနှင့် အကောင့်မေးမြန်းမှုများ | အကောင့်သစ်များ၊ အမည်မပြောင်းခြင်းများ၊ ကိုယ်စားလှယ်လက္ခဏာ အသစ်များကို ရှာဖွေခြင်း၊ မမျှော်လင့်ဘဲ metadata ကို ပြင်ဆင်ခြင်း |
| အရင်းအမြစ်စာရင်းများနှင့် ငွေလွှဲပြောင်းမှုများ | အရင်းအမြစ်ဒေတာဖြစ်ရပ်များနှင့်အရင်းအမြစ်မေးမြန်းမှုများ | တန်ဖိုးမြင့် လှုပ်ရှားမှုတွေ၊ မြန်မြန်ပျံထွက်မှု၊ ဟန်ချက်ညီတဲ့ ရေစီးဆင်းမှုတွေနဲ့ ထူးဆန်းတဲ့ လက်တွဲပစ္စည်းတွေကို ရှာဖွေပါ။ |
| အခန်းကဏ္ဍနှင့် ခွင့်ပြုချက်များ | အခန်းကဏ္ဍနှင့် ခွင့်ပြုချက် မေးမြန်းမှုများ၊ အခန်းကန့် အချက်အလက်များ ဖြစ်ရပ်များ | အခွင့်အရေး တိုးပွားမှု၊ အရေးပေါ် ထောက်ပံ့ငွေများနဲ့ အန္တရာယ်မြင့်တဲ့ ဝင်ရောက်ခွင့်ကို ရှာဖွေပါ။ |
| ကြိုးပမ်းမှုနှင့် စာချုပ်ပြောင်းလဲမှုများ | Trigger၊ Contract နဲ့ Executor အဖြစ်အပျက်များ | အလိုအလျောက်လုပ်မှု အသစ်တွေ၊ အကောင်အထည်ဖော်ရေး လမ်းကြောင်းတွေ ပြောင်းလဲတာတွေနဲ့ သံသယရှိတဲ့ အဆင့်မြှင့်တင်မှု လှုပ်ရှားမှုတွေကို ရှာဖွေပါ။ |
| ဖွဲ့စည်းပုံနှင့် တူညီသူများ၏ ပြောင်းလဲမှုများ | ဖွဲ့စည်းပုံနှင့် တူညီသောဖြစ်ရပ်များ | Validation, networking သို့မဟုတ် operator ရဲ့ မြင်နိုင်မှုကို သက်ရောက်စေတဲ့ အုပ်ချုပ်မှုအပြောင်းအလဲတွေကို ရှာဖွေပါ။ |
| လုပ်ငန်းရှင် ကျန်းမာရေး | `/metrics` နှင့် Sumeragi အခြေအနေလမ်းကြောင်းများ | node overload၊ queue pressure (သို့) network fault တွေကနေ သံသယရှိတဲ့ user behavior ကို ခွဲခြားပါ။ |

အသုံးပြုခြင်း [ဖြစ်ရပ် စစ်ဆေးချက်များ](/my/blockchain/filters.md) ဖြစ်ရပ်တစ်ခုလုံးကို စီမံခန့်ခွဲမှု ရှောင်ရှားဖို့
စည်းမျဉ်းတစ်ခုအတွက် အကောင့်များ၊ အရင်းအမြစ်များ၊ အခန်းကဏ္ဍများ သို့မဟုတ် ဖွဲ့စည်းမှု ပြောင်းလဲမှုများသာ လိုအပ်ပါက Stream လုပ်ပါ။
အခါအားလျော်စွာ ညှိနှိုင်းရန်အတွက် stream ကို pageed နှင့် ပေါင်းစပ်ပါ။
[မေးခွန်းများ](/my/blockchain/queries.md) ဒီတော့ Monitor ဟာ Downtime ကနေ ပြန်လည်ထူထောင်နိုင်မှာပါ။

## ရှာဖွေရေး စည်းမျဉ်းများ {#detection-rules}

ပုံမှန် စည်းမျဉ်းမိသားစုများမှာ အောက်ပါတို့ ပါဝင်ပါတယ်။

| စည်းမျဉ်းမိသားစု | ဥပမာ အခြေအနေ | ပုံမှန် တုံ့ပြန်မှု |
| --- | --- | --- |
| အမြန်နှုန်း | အကောင့်တစ်ခုက အချိန်တိုအတွင်း မျှော်မှန်းထားသော ပမာဏ (သို့) ရေတွက်မှုထက်ပိုပြီး လွှဲပြောင်းပေးသည် | အဆိုပါစာရင်းအတွက် သတိပေးချက်စစ်ဆေးသူများနှင့် လျှောက်ထားမှုဘက်မှ ငွေထုတ်ယူမှုကို ရပ်ဆိုင်းခြင်း |
| ပျံ့နှံ့မှု | ငွေကြေးဟာ အကောင့်တစ်ခုကနေ အသစ်တွေ့ရတဲ့ အကောင့်များစွာကို ရွှေ့သွားပါတယ်။ | ထပ်မံလွှဲပြောင်းခွင့်မပြုခင် လက်စွဲလက်မှတ်ကို တောင်းဆိုပါ။ |
| ဟန်ချက်ညီမှု စွန့်လွှတ်ခြင်း | Key (သို့) alias (သို့) metadata ပြောင်းလဲပြီး မကြာခင်မှာ account balance ရဲ့ ကြီးမားတဲ့ အစိတ်အပိုင်းတစ်ခု ထွက်သွားတယ် | အကောင့်သိမ်းယူမှု ဖြစ်နိုင်သမျှ တိုးတက်စေရန် |
| အခွင့်အရေးများ တိုးတက်လာခြင်း | အပြောင်းအလဲ ပြတင်းပေါက်ပြင်ပမှာ အရဲစွန့်ခွင့် (သို့) ရာထူးကို ပေးအပ်ခြင်း | ထောက်ပံ့မှုလုပ်ငန်းရှင်များကို သတိပေးခြင်း၊ ငွေကြေးထောက်ပံ့မှု လုပ်ငန်းကို ပြန်လည်သုံးသပ်ခြင်း |
| ငြင်းပယ်ခြင်း ပေါက်ကွဲမှု | လက်မှတ်ရေးထိုးသူ (သို့) ဖောက်သည်တစ်ဦးက ထပ်တလဲလဲ ပယ်ချခံရတဲ့ ငွေကြေးမှုများကို ထုတ်ပြန် | ခွင့်ပြုချက် ချိုးဖောက်မှု၊ ပေါင်းစပ်ခြင်းအမှားများ သို့မဟုတ် စစ်ဆေးမှုများ ရှိမရှိကို စစ်ဆေးပါ။ |
| အလိုအလျောက်ပြောင်းလဲခြင်း | trigger၊ contract သို့မဟုတ် executor နဲ့ဆိုင်တဲ့ အရာဝတ္ထုတစ်ခုဟာ မမျှော်လင့်ဘဲ ပြောင်းလဲနေပါတယ် | ပြောင်းလဲမှုကို ပြန်လည်သုံးသပ်မချင်း သက်ဆိုင်ရာ လုပ်ငန်းခွင်တွေကို ရပ်တန့်ပါ။ |
| အုပ်ချုပ်မှုဆိုင်ရာ အပြောင်းအလဲများ | Peer၊ configuration သို့မဟုတ် runtime status ပြောင်းလဲမှုများသည် ခွင့်ပြုထားသောလက်မှတ်မရှိဘဲ ဖြစ်ပေါ်သည်။ | အုပ်ချုပ်မှု မှတ်တမ်းနှင့် ဖြစ်စဉ်ဖြစ်စဉ်ကို နှိုင်းယှဉ်ကြည့်ပါ |

စည်းမျဉ်းတွေဟာ သူတို့လိုအပ်တဲ့ အထောက်အထားတွေ၊ အချိန်ပြတင်းပေါက်တွေကို ရှင်းလင်းစွာ ဖော်ပြသင့်ပါတယ်။
အကဲဖြတ်ခြင်း၊ သူတို့လုပ်တဲ့ လုပ်ဆောင်ချက်တွေ၊
Customer Risk၊ Asset Type (သို့) Jurisdiction မှီခိုသော thresholds များ
သင့်ရဲ့ စောင့်ကြည့်ရေး ဝန်ဆောင်မှု ဖွဲ့စည်းပုံထဲမှာ ပါဝင်တယ်၊ ad hoc script တွေမှာ မဟုတ်ဘူး။

## တုံ့ပြန်မှု ထိန်းချုပ်ချက်များ {#response-controls}

သတိပေးချက်များ မပြုလုပ်မီ တုံ့ပြန်မှုများကို စီမံခန့်ခွဲပါ။
ရှာဖွေမှုကနေ ထိန်းချုပ်မှုအထိ မှတ်တမ်းတင်ထားတဲ့ လမ်းကြောင်းရှိသင့်ပါတယ်။

- လုံခြုံရေး၊ လုပ်ငန်းများနှင့် စီးပွားရေးလုပ်ငန်းရှင်များအတွက် တာဝန်ရှိသူများကို အသိပေးခြင်း၊
  သက်ရောက်မှုရှိသည့် ဒိုမင် သို့မဟုတ် အရင်းအမြစ် သတ်မှတ်ချက်
- ဖြစ်ရပ်ညွှန်ပြချက်၊ ဘလော့ကတ် ဟက်ရှ်၊ ငွေကြေး ရယူမှု ဟက်ရှစ်၊ အာဏာ၊ အသုံးဝင်မှု
  ပြီးတော့ ရှာဖွေရေး စည်းမျဉ်းက သုံးတဲ့ query snapshot ကို
- စာရင်းအင်းပြင်မှာရှိတဲ့ application-side actions တွေကို pause လုပ်ပါ။ checkout လိုမျိုးပေါ့။
  ထုတ်ယူခြင်း၊ လက်မှတ်ရေးထိုးခြင်း၊ တံတားချိုးခြင်း (သို့) ငွေပေးချေမှု လုပ်ငန်းစဉ်များ
- ဖြစ်ရပ်ကြောင့် အကြောင်းပြချက်မရှိတော့တဲ့ အခန်းကဏ္ဍ (သို့) ခွင့်ပြုချက်တွေကို ပယ်ဖျက်ပါ။
  တုံ့ပြန်မှု အစီအစဉ်
- တက်ကြွတဲ့ အုပ်ချုပ်မှု မူဝါဒရှိရင်သာ နောက်ဆက်တွဲ စာရင်းအင်း ငွေလဲလှယ်မှုကို တင်ပြပါ။
  ခွင့်ပြုချက်ပုံစံက သူတို့ကို
- လက်မှတ်ရေးထိုးသူက ချုပ်ဆိုချက်ချတယ်လို့ အထောက်အထားတွေရှိတဲ့အခါ ခလုတ်တွေကို လှည့်ပါ။

Monitoring service ကို broad write access ပေးတာ ရှောင်ပါ။
အဖြေအတွက် လိုအပ်တဲ့ ခွင့်ပြုချက် အနည်းဆုံးအစုနဲ့ နည်းပညာ အကောင့်
လူ့ထောက်ခံချက်ဟာ
အရင်းအမြစ်တွေကို ရွေ့ရှားနိုင်၊ ခွင့်ပြုချက်တွေကို ပြောင်းလဲနိုင် (သို့) validator ကို မျက်နှာမူပြောင်းလဲနိုင်တဲ့ အလုပ်ခွင်
ဖွဲ့စည်းမှု။

## အထောက်အထားနှင့် ထိန်းသိမ်းခြင်း {#evidence-and-retention}

Monitoring Evidence ကို Append-only စနစ်တစ်ခုမှာ သိမ်းထားပါ။
validator data directory တစ်ခုစီမှာ:

- Event stream အမည်နှင့် cursor
- Block height သို့မဟုတ် block hash ရှိပါက
- ငွေပေးချေမှု hash နှင့် အာဏာ
- သက်ရောက်တဲ့ အကောင့်၊ ဒိုမင်၊ အရင်းအမြစ်၊ အခန်းကဏ္ဍ၊ trigger သို့မဟုတ် ဖွဲ့စည်းမှု ID
- raw event payload (သို့) ၎င်းရဲ့ canonical hash တစ်ခု
- alert ကို ချမ်းသာစေရန် အသုံးပြုသော query snapshots များ
- စည်းမျဉ်းအမည်၊ မူကွဲ၊ တံခါးခေါက်၊ အမှတ်များနှင့် အတည်ပြုသူ ဆုံးဖြတ်ချက်

သိမ်မွေ့တဲ့ စုံစမ်းရေး မှတ်စုတွေကို အများပြည်သူစာအုပ်ကြီးရဲ့ metadata အဖြစ် မသိုလှောင်ပါနဲ့
ကွန်ရက်ရဲ့ ဒေတာ အုပ်ချုပ်ရေး မူဝါဒက ရှင်းလင်းစွာ ခွင့်ပြုပါတယ်။
ချိတ်ဆက်မှုအပြင်မှာ ချိတ်ဆက်ထားသော အခြေအနေကို ချိတ်ဆက်ပေးရန်၊ ချိတ်ဆက်ချက်အမှတ်တံဆိပ်၊ လက်မှတ်ရေးထိုးထားသော သက်သေခံစာတမ်းကို ပိုနှစ်သက်ပါ။
(သို့) ပုဂ္ဂလိက အချက်အလက်တွေကို မဖော်ထုတ်တဲ့ hash ကတိပါ။

## အကောင်အထည်ဖော်မှု စစ်ဆေးစာရင်း {#implementation-checklist}

- လိုအပ်တဲ့ telemetry profile ကို enable လုပ်ပေးပါ။ `/metrics` လုပ်ငန်းရှင် လမ်းကြောင်းတွေလည်း ရှိပါတယ်။
- လက်မှတ်ထိုးပါ Torii event streams တွေကို သင်ရှာတဲ့ အရာဝတ္ထုတွေအတွက် သေးငယ်တဲ့ filter တွေနဲ့
  Monitor ကို ကြည့်ပါ။
- Monitor ဟာ အပေါက်တွေမရှိဘဲ ပြန်လည်စတင်နိုင်အောင် Event Cursors တွေကို တည်ငြိမ်ထားပါ။
- အစဉ်အလာ အစီအစဉ်တစ်ခုမှာ စာမျက်နှာဖြန့်ထားတဲ့ မေးခွန်းတွေနဲ့ စီးကြောင်းတွေကို ညှိနှိုင်းပါ။
- အရဲစွန့်အဆင့်တွေကို ထိန်းထားပြီး ဗားရှင်းထိန်းချုပ်ထားတဲ့ ဖွဲ့စည်းမှုမှာ စာရင်းတွေခွင့်ပြုပါ။
- အလိုအလျောက် လုပ်ဆောင်မှု မပြုလုပ်ခင် သမိုင်းဝင် ဘလော့တွေကို စစ်ဆေးတဲ့ သတိပေးချက် စည်းမျဉ်းတွေ။
- တုံ့ပြန်မှု လုပ်ဆောင်ချက်များအတွက် သီးသန့် နည်းပညာ အကောင့်များကို အသုံးပြုပါ။
- ပြန်လည်သုံးသပ်မှု အခန်းကဏ္ဍနှင့် ခွင့်ပြုချက်ပေးချေမှုများအား ထပ်တလဲလဲ ပြုလုပ်ခြင်း။
- အလိမ်အညာ စောင့်ကြည့်ရေး သတိပေးချက်များကို ဖြစ်စဉ် တုံ့ပြန်မှု လုပ်ငန်းစဉ်ထဲ ထည့်သွင်းပါ။
