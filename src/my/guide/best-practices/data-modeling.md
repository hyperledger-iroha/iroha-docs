# ဒေတာပုံစံထုတ်ခြင်း {#data-modeling}

Ledger ဒေတာကို ပိုင်ဆိုင်မှု၊ လွှဲပြောင်းမှု အပေါ် မူတည်ပြီး ပုံစံထုတ်သင့်ပါတယ်။
ခွင့်ပြုချက် နယ်နိမိတ်များနှင့် မေးမြန်းမှုပုံစံများကို ရွေးချယ်ပါ။
စစ်ဆေးနိုင်မှုနှင့် သတ်မှတ်ချက်ဆိုင်ရာ အကောင်အထည်ဖော်မှုကို ထောက်ပံ့နိုင်တဲ့ ကိုယ်စားပြုမှု။

## ဒိုမင်များနှင့် အကောင့်များ {#domains-and-accounts}

- အုပ်ချုပ်ရေးနဲ့ မူဝါဒ နယ်နိမိတ်တွေကို ကိုယ်စားပြုဖို့ ဒိုမီနာတွေ သုံးပါ။
  ဒိုမင်နာမည်တွေဟာ အကောင့်နဲ့ အရင်းအမြစ်အသိမှတ်ချက်တွေမှာ ပေါ်လာတာကြောင့် တည်ငြိမ်ပါတယ်။
- Account တစ်ခုတည်းကို ဆက်စပ်မှုမရှိတဲ့ တာဝန်တွေနဲ့ overload လုပ်တာ ရှောင်ပါ။
  အသုံးပြုသူများ၊ ဝန်ဆောင်မှုများ၊ trigger များ၊ operator များနှင့် အခွန်များအတွက် သီးခြားစာရင်းများ
  ပံ့ပိုးသူတွေပါ။
- Config နဲ့ Test တွေမှာ Canonical Account နဲ့ Domain ID ကို သုံးပါ။ Iroha
  နာမည်တွေဟာ Canonical Parsing လုပ်ပြီးနောက် ကိစ္စကို အာရုံခံပါတယ်။
- စမ်းသပ်မှုနှင့်ထုတ်လုပ်ရေးအမည်များကို နာမည်များ၊ ဒိုမင်များတွင် ထင်ရှားစွာ ခွဲခြားထားပါ။
  configuration file လမ်းကြောင်းတွေ

ကြည့်ပါ။ [ဒိုမင်များ](/my/blockchain/domains.md), [စာရင်းများ](/my/blockchain/accounts.md),
နှင့် [အမည်ပေးခြင်း](/my/reference/naming.md).

## အရင်းအမြစ်များနှင့် NFTs {#assets-and-nfts}

- ဖောက်ထွင်းနိုင်သော ငွေကြေးကျန်ငွေများနှင့် လွှဲပြောင်းနိုင်သော အရေအတွက်များအတွက် ကိန်းဂဏန်းအရင်းအမြစ်များကို အသုံးပြုပါ။
- အသုံးပြုခြင်း NFTs (သို့) သီးခြားပိုင်ဆိုင်မှု မှတ်တမ်းများအတွက် ဒိုမင်အထူးပစ္စည်းများ။
- Value-bearing state ကို metadata တွေထဲမှာသာ encoding လုပ်ဖို့ ရှောင်ရှားပါ။ NFTs
  ဘဝပတ်ဝန်းကျင်ဖြစ်ရပ်များ၊ လွှဲပြောင်းမှု အဓိပ္ပာယ်ကောက်ယူမှုနှင့် ခွင့်ပြုချက် စစ်ဆေးခြင်းများကို ပေးပို့ရန်
  metadata ကတော့ မရှိဘူး။
- တိကျမှု၊ ထောက်ပံ့ရေး မူဝါဒ၊ ထုတ်ပြန်သူ တာဝန်ရှိမှုနှင့် မီးရှို့ခြင်း/မုန်တိုင်းကို သတ်မှတ်ပါ။
  အာဏာပိုင်က အရင်းအမြစ်ကို လျှောက်လွှာများသို့ မတင်ပြမီ။

ကြည့်ပါ။ [အရင်းအမြစ်များ](/my/blockchain/assets.md), [NFTs](/my/blockchain/nfts.md), နှင့်
[RWAs](/my/blockchain/rwas.md).

## မီတာဒေတာ {#metadata}

- စာရင်းအင်းအရာဝတ္ထုတွေရဲ့ အသေးစား အရည်အသွေးတွေအတွက် metadata ကိုသုံးပါ။ ဥပမာ labels တွေ၊
  ပေါင်းစည်းခြင်း IDs, မူဝါဒ အလံတွေ၊ hashes တွေ၊ URIs, ဒါမှမဟုတ် အကြောင်းအရာနဲ့ ညွှန်ကြားချက်ပေးထားတယ်။
  ရည်ညွှန်းချက်များ။
- metadata key တွေကို တည်ငြိမ်ပြီး မှတ်တမ်းတင်ထားပါ။
  ဖောက်သည်တွေက သူတို့အပေါ် မူတည်ပြီး ရွှေ့ပြောင်းရေး ပြဿနာတစ်ခု ဖန်တီးတယ်။
- စာရွက်စာတမ်းကြီးများ၊ မှတ်ပုံတင်များ၊ ပုဂ္ဂလိက အသုံးပြုသူ ဒေတာများ (သို့) အရှိန်အဟုန် မြင့်မားသော အချက်အလက်များကို မသိမ်းဆည်းပါ
  metadata ထဲမှာ တိုက်ရိုက် အသုံးပြုတဲ့ အခြေအနေပါ။
- metadata တွေက ကွင်းဆက်ပြင်ပ ဒေတာကို ညွှန်ပြတဲ့အခါ စစ်ဆေးနိုင်တဲ့ ရည်ညွှန်းချက်ကို သိမ်းဆည်းပါ။
  အကြောင်းအရာ hash အဖြစ်၊ URI, SoraFS လမ်းကြောင်း၊ ထင်ရှားတဲ့ ရည်ညွှန်းချက် (သို့) သေးငယ်သော
  ရည်စူးမှု။

ကြည့်ပါ။
[Metadata နှင့် Ledger Storage ရွေးချယ်မှုများ](/my/guide/configure/metadata-and-store-assets.md)

## ပုံစံအလိုက် ခွင့်ပြုချက်များ {#permissions-by-model}

- စီမံကိန်းဆိုင်ရာ အခန်းကဏ္ဍသည် လုပ်ငန်းဆောင်ရွက်မှုနှင့် ပတ်သတ်၍ မဟုတ်ဘဲ အကောင်အထည်ဖော်ခြင်းနှင့်ပတ်သတ်၍ ဖြစ်သည်။
  အလုပ်တစ်ခု (သို့) ဝန်ဆောင်မှုတစ်ခုအပြီး နာမည်တပ်ထားတဲ့ ရာထူးကို စစ်ဆေးတာထက် ပိုလွယ်ပါတယ်။
  ကျယ်ပြန့်တဲ့ နည်းပညာ အရည်အချင်းတစ်ခုရဲ့ နာမည်ကို ပေးထားတဲ့ အခန်းကဏ္ဍပါ။
- Scope permission tokens တွေကို
  အလုပ်ဖြစ်စဉ်။
- ထွင်း၊ မီးရှို့၊ အထက်တန်းစား စီမံခန့်ခွဲရေး၊ အကောင်အထည်ဖော်ခွင့်ပြုချက်များ
  အပြောင်းအလဲများ၊ trigger management များနှင့် metadata mutation များအား သက်ရောက်မှုမြင့်မားသော
  ခွင့်ပြုချက်များ။
- ယာယီအတွက် ရှင်းလင်းစွာ ရုပ်သိမ်းခြင်းနှင့် လည်ပတ်မှု လုပ်ငန်းစဉ်များ ထည့်သွင်းခြင်း
  ခွင့်ပြုချက်များ။

ကြည့်ပါ။ [ခွင့်ပြုချက်များ](/my/blockchain/permissions.md) နှင့်
[ခွင့်ပြုချက် လက်မှတ်များ](/my/reference/permissions.md).

## မေးမြန်းပုံ {#query-shape}

- သင့်ရဲ့ query တွေကို ထောက်ခံတဲ့ ID နဲ့ metadata key ကို ရွေးပါ။
  မကြာခဏပဲ လျှောက်လွှာလိုအပ်ပါလိမ့်မယ်။
- စာမျက်နှာများတွင် result sets များကို ဖြည့်စွက်ပြီး user interfaces များကို ရှောင်ရှားပါ
  ပုံမှန် လုပ်ဆောင်ချက်တွေအတွက် ကန့်သတ်ချက်မရှိတဲ့ စာရင်းအင်းတစ်ခုလုံးကို စကင်လုပ်တယ်။
- လက်မှတ်ကြီး အချက်အလက်များနှင့် ဖြစ်ရပ်များမှ ပြန်လည်တည်ဆောက်နိုင်သော ကွင်းဆက်အပြင် အညွှန်းကိန်းများကို ထိန်းသိမ်းပါ။
  critical application behaviour အတွက် သုံးတဲ့အခါတိုင်းပါ။
