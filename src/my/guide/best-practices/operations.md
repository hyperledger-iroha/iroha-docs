# လုပ်ငန်းများ {#operations}

လည်ပတ်အသုံးပြုရန် အသင့်ဖြစ်ခြင်းဆိုသည်မှာ validator host များထံ ယာယီကြံဖန်ဝင်ရောက်မှုကို မမှီခိုဘဲ ကွန်ရက်ကို စောင့်ကြည့်၊ ပြောင်းလဲ၊ အရန်သိမ်းနှင့် ပြန်လည်ရယူနိုင်ခြင်းဖြစ်သည်။

## လေ့လာနိုင်မှု {#observability}

- တိုင်းတာသတင်းပို့မှု ပရိုဖိုင်များကို ရည်ရွယ်ချက်ရှိရှိ ဖွင့်ပါ။ `/metrics` လိုအပ်လျှင် `extended` ကို သုံးပါ။ အသေးစိတ် Sumeragi အော်ပရေတာလမ်းကြောင်းများ လိုအပ်သော စမ်းသပ်မှုများတွင် `full` ကို သုံးပါ။
- လက်ခံပြီး လုပ်ဆောင်နှုန်း၊ ပယ်ချနှုန်း၊ commit ကြာချိန်၊ စောင့်ဆိုင်းစာရင်းအရှည်၊ စောင့်ဆိုင်းစာရင်းပြည့်ကျပ်မှု၊ view ပြောင်းလဲမှုများ၊ ပျောက်ဆုံးသော သဘောတူညီမှုသတင်းစကားများနှင့် သိုလှောင်မှုဝန်တို့ကို ဒိုင်ခွက်တွင် ဖော်ပြပါ။
- အခြေအနေ snapshot များ၊ တိုင်းတာချက်စုဆောင်းမှုများ၊ မှတ်တမ်းများနှင့် ဖြန့်ချိတပ်ဆင်ရေးပြင်ဆင်သတ်မှတ်ချက်ကို တူညီသော ဖြစ်ရပ် သို့မဟုတ် စွမ်းဆောင်ရည်စမ်းသပ်မှု၏ အထောက်အထားအစုထဲတွင် ထားပါ။
- အတန်းတွေ ဆက်လက် ကြီးထွားလာတာ၊ မမျှော်လင့်တဲ့ ပယ်ချမှု မြင့်တက်မှု၊ ရပ်တန့်နေတဲ့ ဘလော့ အမြင့်၊ ရှုခင်း ပြောင်းလဲခြင်းနဲ့ ကွန်ရက် အဖော်တွေရဲ့ ကျန်းမာရေး အပြောင်းအလဲတွေကို သတိပေးပါ။

[စွမ်းဆောင်ရည်နှင့် မက်ထရစ်များ](/my/guide/advanced/metrics.md) ကို ကြည့်ပါ။

## လမ်းလျှောက်စာအုပ်များ {#runbooks}

- peer ပြန်စခြင်း၊ Torii စွမ်းဆောင်ရည်ကျဆင်းခြင်း၊ ကီးပေါက်ကြားခြင်း၊ ခွင့်ပြုချက်အမှားများ၊ အခကြေးငွေကိုယ်စားပေးသူ၏ ရန်ပုံငွေကုန်ခန်းခြင်း၊ စောင့်ဆိုင်းစာရင်းပိတ်မိခြင်းနှင့် ကွန်ရက်အပိုင်းခွဲမှုလက္ခဏာများအတွက် လုပ်ငန်းဆောင်ရွက်ရေးလမ်းညွှန်များ ရေးပါ။
- စာရေးခြင်း လုပ်ငန်းများမတိုင်မီ တိကျသော ဖတ်ရှုမှုသာ စစ်ဆေးမှုကို ထည့်သွင်းပါ၊ အထူးသဖြင့် ကွန်ရက် တူညီသူ မှတ်ပုံတင်မှု၊ ခွင့်ပြုချက်ပေးခြင်း၊ ပြောင်မြောက်မှု ပြောင်းလဲမှုများအတွက်ပါ။
- အရေးပေါ်ဆက်သွယ်မှုတွေနဲ့ တိုးတက်ရေး စည်းမျဉ်းတွေကို Docs repo ထဲမှာ ထည့်သွင်းထားရင် သီးသန့် လုပ်ငန်းဆိုင်ရာ ဒေတာတွေ ပါဝင်ပါက ထားပါ။
- ဖြစ်ရပ်တိုင်း၊ လေ့ကျင့်မှုတိုင်း၊ အကြီးမားဆုံး အဆင့်မြှင့်မှုတိုင်းနောက်မှာ လမ်းညွှန်စာအုပ်တွေကို စစ်ဆေးပါ။

[လုပ်ငန်းလုံခြုံရေး](/my/guide/security/operational-security.md) ကို ကြည့်ပါ။

## Backup နှင့် ပြန်လည်ထူထောင်ခြင်း {#backups-and-recovery}

- ဖြန့်ချိတပ်ဆင်မှုက လိုအပ်သော ပြန်လည်ရယူရေးအချိန်မှတ်အရ peer သိုလှောင်ဒေတာကို အရန်သိမ်းပါ။ ပြန်လည်ထည့်သွင်းမှုကို ထုတ်လုပ်သုံးစွဲရေးမဟုတ်သော host များပေါ်တွင် စစ်ဆေးအတည်ပြုပါ။
- validator ကို လုပ်ဆောင်သည့် host မရရှိနိုင်သော်လည်း လက်မှတ်ထိုးထားသော genesis၊ ထုတ်ဝေမှု metadata၊ peer ပြင်ဆင်သတ်မှတ်ချက်နှင့် ကီးထိန်းသိမ်းမှုမှတ်တမ်းများကို ပြန်လည်ရယူနိုင်အောင် ထိန်းသိမ်းပါ။
- ပြန်လည်ထူထောင်ရေး လုပ်ငန်းစဉ်တစ်ခုက blockchain မျိုးဆက်ကနေ ပြန်တည်ဆောက်တာ၊ အချိန်ကာလအတွင်း ဒေတာအမြင်ကနေ ပြန်လည်ဖန်တီးတာ (သို့) ကျရှုံးတဲ့ ကွန်ရက်တူညီသူကို ကိုယ်ပိုင်လက္ခဏာသစ်နဲ့ အစားထိုးတာဆိုတာကို မှတ်တမ်းတင်ပါ။
- ထုတ်လုပ်မှုဖြစ်စဉ်တစ်ခုအတွင်းမှာ ပထမဆုံးအကြိမ် ပြန်လည်ပြုပြင်တဲ့ လုပ်ငန်းစဉ်တွေကို ဘယ်တော့မှ မစမ်းသပ်ပါနဲ့။

## အပြောင်းအလဲ စီမံခန့်ခွဲမှု {#change-management}

- on-chain ပြင်ဆင်သတ်မှတ်ချက် ပြောင်းလဲမှုများကို ပြန်လည်သုံးသပ်မှု၊ ကြိုတင်ဖတ်ရှုစစ်ဆေးမှု၊ ခွင့်ပြုမှုနှင့် ပြောင်းလဲပြီးနောက် အတည်ပြုမှုတို့ လိုအပ်သော transaction များအဖြစ် သဘောထားပါ။
- Peer ထုတ်ဝေမှုကို မတပ်ဆင်မီ ၎င်းက ကွန်ရက်၏ စစ်မှန်ကြောင်း အတည်ပြုထားသော runtime ရွေးချယ်မှုနှင့် စတင် checkpoint အထက်ရှိ သမိုင်းကို အကောင်အထည်ဖော်နိုင်ကြောင်း စစ်ဆေးပါ။ Protocol သတ်မှတ်ချက်များ ပြောင်းလဲရန် အရည်အချင်းစစ်ပြီး အုပ်ချုပ်မှုအရ အတည်ပြုသော ရွေးချယ်မှုပြောင်းလဲမှု လိုအပ်သည်။ အသက်သွင်းပြီးနောက် ပြန်လည်ရယူမှုတွင် မကိုက်ညီသော binary ဗားရှင်းဟောင်းသို့ ပြန်ချမည့်အစား ပြင်ဆင်ပေးသည့် ရွေးချယ်မှုပြောင်းလဲမှုကို သုံးသည်။
- ပြောင်းရွှေ့ရေးအစီအစဉ်က လိုအပ်သည်မှလွဲ၍ ပြုပြင်ထိန်းသိမ်းမှုကာလတစ်ခုတည်းအတွင်း peer ချိတ်ဆက်ဖွဲ့စည်းပုံ၊ သဘောတူညီမှုအချိန်ဆက်တင်များနှင့် အက်ပ်အလုပ်ဝန်တို့ကို အတူပြောင်းခြင်းမှ ရှောင်ပါ။
- ငွေလဲလှယ်မှု cryptographic hashes တွေကို မှတ်တမ်းတင်ပြီး လုပ်ဆောင်ချက် အပြောင်းအလဲများအတွက် ဘလော့အမြင့်တွေကို မှတ်တမ်းတင်ပါ။

[အပူပြန်တင်ခြင်း](/my/guide/advanced/hot-reload.md) နှင့် [ကိုက်ညီမှု Matrix](/my/reference/compatibility-matrix.md) ကိုကြည့်ပါ။

## စွမ်းဆောင်ရည် သုံးသပ်ချက်များ {#capacity-reviews}

- validator အရေအတွက်၊ ဟာ့ဒ်ဝဲ၊ ကွန်ရက်နေရာချထားမှု၊ အလုပ်ဝန်အမျိုးအစားပေါင်းစပ်ပုံ သို့မဟုတ် သဘောတူညီမှုသတ်မှတ်ချက်များ ပြောင်းလဲသောအခါ ဝန်တင်စစ်ဆေးမှုများကို ပြန်လုပ်ပါ။
- အပူချိန်၊ တည်ငြိမ်မှုအခြေအနေနဲ့ မျှော်မှန်းထားတဲ့ အမြင့်ဆုံးဝန်ဆောင်မှုကို အတိုချိုအကောင်းဆုံးဖြစ်စဉ်ထုတ်လုပ်မှုနမူနာကို အားကိုးခြင်းအစား တိုင်းတာပါ။
- လက်ခံရရှိသော ထုတ်လွှင့်မှုများကို နောက်ဆုံးထုတ်လွှင့်မှုနှင့် အတန်းအနက်ကို နှိုင်းယှဉ်ပါ။ ပေးပို့ထားသည့် TPS သည် နောက်ဆုံးထုတ် TPS ကိုကျော်ပြီး အတန်းများ တိုးလာပါက ကွန်ရက်သည် ၎င်း၏ ရေရှည်တည်တံ့သော လုပ်ဆောင်မှု ကန့်သတ်ချက်ကို ကျော်ဖြတ်ခဲ့သည်။
