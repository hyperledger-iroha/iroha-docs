# လုပ်ငန်းများ {#operations}

အသင့်ဖြစ်မှုဆိုသည်မှာ ကွန်ရက်ကို စောင့်ကြည့်၊ ပြောင်းလဲနိုင်ခြင်း၊
backed up လုပ်ပြီး validator ကို improvised access မပြုလုပ်ဘဲ ပြန်လည်ထူထောင်
အိမ်ရှင်တွေပေါ့။

## လေ့လာနိုင်မှု {#observability}

- Telemetry Profiles တွေကို ကြံစည်ပြီး Activate လုပ်ပါ။ `extended` ဘယ်အချိန်မှာ `/metrics`
  လိုအပ်ပြီး `full` အသေးစိတ်လိုအပ်တဲ့ စမ်းသပ်မှုတွေမှာ Sumeragi
  လုပ်ငန်းရှင်လမ်းကြောင်းများ။
- Dashboard လက်ခံရရှိမှု ထုတ်ကုန်များ၊ ပယ်ချခြင်း ထုတ်ကုန်များ, commit latency, queue
  နက်ရှိုင်းမှု၊ တန်းစီပြည့်ဝမှု၊ ကြည့်ရှုမှုပြောင်းလဲမှုများ၊ သဘောတူညီချက် သတင်းစကားတွေ ကျဆင်းခြင်းများ
  သိုလှောင်ရန် ဖိအား။
- Status snapshots များ၊ metrics scrapes များ၊ logs များနှင့် deployment များကို သိမ်းထားပါ။
  အလားတူဖြစ်စဉ် (သို့) benchmark artefact set ထဲမှာ ဖွဲ့စည်းထားတာပါ။
- ဆက်လက်တိုးတက်နေတဲ့ အတန်းအတွက် သတိပေးချက်၊ မမျှော်လင့်တဲ့ ပယ်ချမှု အမြင့်ဆုံးတွေ၊ ရပ်တန့်နေ
  အရှည်၊ ရှုထောင့် ပြောင်းလဲမှု နဲ့ အဖော်တွေရဲ့ ကျန်းမာရေး ပြောင်းလဲမှုတွေပါ။

ကြည့်ပါ။ [စွမ်းဆောင်ရည်နှင့် မက်ထရစ်များ](/my/guide/advanced/metrics.md).

## လမ်းလျှောက်စာအုပ်များ {#runbooks}

- Peer restart အတွက် runbook တွေရေးပါ။ Torii အပျက်အစီး၊ အဓိက ချိုးဖောက်မှု
  ခွင့်ပြုချက်အမှားများ၊ အခွန်ထောက်ခံသူ ကုန်ဆုံးမှု၊ တန်းစီထားခြင်းနှင့် ကွန်ရက်
  ခွဲစိတ်ခြင်း ရောဂါလက္ခဏာများ။
- စာရေးခြင်း လုပ်ငန်းများမတိုင်မီ တိကျသော ဖတ်ရန်သာ စစ်ဆေးမှုများကို ထည့်သွင်းပါ။ အထူးသဖြင့်
  အတန်းတူ မှတ်ပုံတင်ခြင်း၊ ခွင့်ပြုချက်ပေးခြင်းနှင့် ပမာဏ ပြောင်းလဲမှုများ။
- အရေးပေါ်ဆက်သွယ်မှုတွေနဲ့ တိုးတက်ရေး စည်းမျဉ်းတွေကို DOCs repo အပြင်မှာ ထိန်းထားပါ။
  ၎င်းတို့တွင် ပုဂ္ဂလိက လုပ်ငန်းဆိုင်ရာ အချက်အလက်များ ပါဝင်သည်။
- ဖြစ်ရပ်တိုင်း၊ လေ့ကျင့်ခန်းတိုင်း ဒါမှမဟုတ် အကြီးမားဆုံး အဆင့်မြှင့်မှုတိုင်းနောက်မှာ ပြေးလွှားစာအုပ်တွေကို ပြန်ကြည့်ပါ။

ကြည့်ပါ။ [လုပ်ငန်းလုံခြုံရေး](/my/guide/security/operational-security.md).

## Backup နှင့် Recovery {#backups-and-recovery}

- back-up peer storage ကို recovery point ကနေ လိုအပ်တဲ့
  မထုတ်လုပ်တဲ့ အိမ်ရှင်တွေမှာ ပြန်လည်တည်ငြိမ်စေတယ်။
- လက်မှတ်ရေးထိုးထားတဲ့ ဘီဘီစီကို သိမ်းထားပါ၊ metadata ကို ထုတ်ပေးပါ။
  validator host မရှိရင်တောင် ပြန်လည်ရှာဖွေလို့ရတဲ့ မှတ်တမ်းတွေပါ။
- ပြန်လည်ထူထောင်ရေး လုပ်ငန်းစဉ်က ဘီဘီစီကနေ ပြန်လည်တည်ဆောက်တာ၊ ပြန်လည်တည်ထောင်တာ မှတ်တမ်းတင်ပါ။
  ဒါမှမဟုတ် မအောင်မြင်တဲ့ အဖော်ကို ကိုယ်ပိုင်လက္ခဏာသစ်နဲ့ အစားထိုးတယ်။
- ထုတ်လုပ်မှုတစ်ခုအတွင်း ပထမဆုံးအကြိမ် စမ်းသပ်မှု ပြန်လည်ထူထောင်ရေး လုပ်ငန်းစဉ်များကို ဘယ်တော့မှ မလုပ်ပါနဲ့
  ဖြစ်ရပ်ပါ။

## အပြောင်းအလဲ စီမံခန့်ခွဲမှု {#change-management}

- ချိတ်ဆက်မှုမှာ ပြုပြင်ပြောင်းလဲမှုကို ပြန်လည်သုံးသပ်ဖို့ လိုအပ်တဲ့ ငွေကြေးရေးလုပ်ငန်းတွေအဖြစ် සලකාကြည့်ပါ။
  preflight readings, authorization နဲ့ post-change verification တွေကို လုပ်ပေးတယ်။
- Compatibility plan နဲ့ back-up တစ်ခုနဲ့ peer binary upgrade တွေကို ဖြန့်ဝေပေးပါ။
  ဆုံးဖြတ်ချက်ချမှတ်ချက်။
- အတန်းတူ topology, သဘောတူညီချက် အချိန်ဆွဲခြင်းနှင့် application အလုပ်အကိုင်ကိုပြောင်းလဲခြင်းကို ရှောင်ရှားပါ။
  ရွှေ့ပြောင်းရေး အစီအစဉ်က မလိုအပ်ဘူးဆိုပါစို့။
- လုပ်ငန်းဆိုင်ရာ ပြောင်းလဲမှုအတွက် ငွေပေးချေမှု ဟက်ရှ်များနှင့် ဘလော့အမြင့်များကို မှတ်တမ်းတင်ပါ။

ကြည့်ပါ။ [အပူပြန်တင်ခြင်း](/my/guide/advanced/hot-reload.md) နှင့်
[ကိုက်ညီမှု Matrix](/my/reference/compatibility-matrix.md).

## စွမ်းဆောင်ရည် သုံးသပ်ချက်များ {#capacity-reviews}

- Validator count, hardware, network placement တွေကို ထပ်မံစစ်ဆေးတဲ့အခါ load checks တွေကို ပြန်လုပ်ပါ။
  Workload mix (သို့) သဘောတူညီချက် ပမာဏတွေ ပြောင်းလဲတယ်။
- အပူချိန်၊ တည်ငြိမ်မှုနှင့် မျှော်လင့်ထားသော အမြင့်ဆုံး ဝန်ဆောင်မှုကို အားကိုးခြင်းအစား တိုင်းတာပါ။
  အတိုဆုံးအကောင်းဆုံးဖြစ်ရပ်ရဲ့ ထုတ်ကုန်ထုတ်လုပ်မှု နမူနာတစ်ခုမှာပါ။
- လက်ခံတဲ့ ထုတ်လွှင့်မှုနှုန်းကို ကတိပြုထားတဲ့ ထုတ်လွှင့်မှုနဲ့ တန်းနက်နဲ့ နှိုင်းယှဉ်ပါ။
  တင်ပြထားသည် TPS ချုပ်ဆိုထားသော ငွေကြေးကို လွန် TPS အတန်းတွေ တိုးလာတယ်၊ ကွန်ရက်က ပြီးသွားပြီ။
  ၎င်းရဲ့ တည်တံ့တဲ့ အဝှမ်းပါ။
