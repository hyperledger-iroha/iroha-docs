# အသုံးချမှု ဖွံ့ဖြိုးတိုးတက်ရေး {#application-development}

Iroha Application တွေက transaction behavior ကို ရှင်းလင်းအောင်လုပ်သင့်တယ် လက်မှတ်ရေးထိုးနေပါ
စာမျက်နှာများတွင် ဖော်ပြထားသော အချက်အလက်များကို အလွယ်တကူ အသုံးပြုရန်
ထုတ်လုပ်မှုမှာ စောင့်ကြည့်ပါ။

## Client ကို Setup လုပ်ပါ {#client-setup}

- client ကို source code ကနေ ပြင်ပမှာ သိမ်းထားပါ။
  သံကြိုး ID, Torii URL, လက်မှတ်ထိုးစာရင်း၊ ငွေလဲလှယ်မှု settings မှ
  ပတ်ဝန်းကျင်ဆိုင်ရာ သတ်မှတ်ချက်
- ဆက်ထားပါ။ `client.toml` localnet အတွက် သီးခြားဖိုင်များ၊ Taira, Minamoto, နှင့်
  private network တွေ။ ကူးယူထားတဲ့ testnet လက်မှတ်ရေးထိုးသူဟာ ဘယ်တော့မှ mainnet မဖြစ်သင့်ပါဘူး။
  လက်မှတ်ရေးထိုးသူ။
- Transaction lifetimes နဲ့ status timeouts တွေကို ကြံစည်ပြီး သတ်မှတ်ပေးပါ။
  ပုံမှန် net jitter အောက်မှာ သက်တမ်းကုန်ဆုံးနိုင်ပေမဲ့ အရမ်းရှည်တဲ့
  အထပ်ထပ် တင်ပြချက်တွေကို ဆင်ခြင်ဖို့ ပိုခက်စေနိုင်ပါတယ်။
- အသုံးပြုခြင်း `nonce = true` ထပ်တလဲလဲ လုပ်တဲ့ ငွေကြေးဟာ
  မဖြစ်မနေ စီးပွားရေးလုပ်ငန်းများအတွက်
  လျှောက်ထားမှု တောင်းဆိုချက် ID ဒီတော့ ပြန်လည်စမ်းသပ်မှုတွေဟာ ခြေရာခံနိုင်တာပါ။

ကြည့်ပါ။ [Client Configuration ကို](/my/guide/configure/client-configuration.md) အတွက်
current ကို TOML ကွင်းတွေ။

## ငွေပေးချေမှု {#transactions}

- Typed ကနေ ငွေကြေးကို တည်ဆောက်ပါ။ SDK ဖြစ်နိုင်ခြေရှိရာမှာ ညွှန်ကြားချက်အစား
  အသားအရေ JSON (သို့) ကြိုးတပ်ထားတဲ့ အသုံးဝင်ဝန်ဆောင်မှု။
- Preflight အရေးပါတဲ့စာသားတွေကို ဖတ်လို့သာရတဲ့ မေးခွန်းတွေနဲ့ ရေးထားတယ်။
  အရင်းအမြစ်စာရင်း၊ ခွင့်ပြုချက်အခြေအနေ၊ အခွန်အရင်းအမြစ်ရရှိနိုင်မှုနှင့် ရည်မှန်းချက်
  အရာဝတ္ထုအခြေအနေ။
- Transaction hash ကို မှတ်တမ်းတင်ပါ၊ အာဏာပိုင်စာရင်း၊ ညွှန်ကြားချက် အကျဉ်းချုပ်နဲ့
  တင်ပြမည့်အရင် မျှော်လင့်ထားသော အခြေအနေပြောင်းလဲမှု။
- ကုသမှု `Rejected`, `Expired`, အချိန်ကာလက မတူတဲ့ ရလဒ်တွေရှိပါတယ်။
  ဆိုလိုတာက ဖောက်သည်က နောက်ဆုံးအခြေအနေကို မစောင့်ရှောက်ခဲ့ဘူးဆိုတာ သက်သေပြတာမဟုတ်ဘူး။
  ကွန်ရက်က ငွေပေးချေမှုကို လျစ်လျူရှုခဲ့တယ်။
- အောင်မြင်စွာ ရေးပြီးနောက်၊ ရလဒ်ဖြစ်ပေါ်တဲ့ အခြေအနေကို မေးမြန်းချက်တစ်ခုနဲ့ (သို့)
  စီးပွားရေး လုပ်ငန်းနဲ့ ကိုက်ညီတဲ့ ဖြစ်ရပ် စစ်ဆေးရေးဂိတ်ပါ။

ငွေပေးချေမှု မက္ကန်နစ်များအတွက် ကြည့်ပါ [ငွေပေးချေမှု](/my/blockchain/transactions.md).

## မေးခွန်းများနှင့် ဖြစ်ရပ်များ {#queries-and-events}

- အပြောင်းအလဲ အကြောင်းကြားချက်များအတွက် လက်ရှိအခြေအနေနှင့်ဖြစ်ရပ်စီးကြောင်းများကို မေးမြန်းမှုများကို အသုံးပြုပါ။
  ဖြစ်ရပ် စီမံခန့်ခွဲမှုကို ထပ်တလဲလဲ မေးမြန်းမှုတွေနဲ့ အစားထိုးဖို့ ရှောင်ပါ။
- Account, asset နှင့် block တို့လို အပြန်အလှန်မေးမြန်းနိုင်သော မေးခွန်းများကို စာမျက်နှာများတွင် တင်ပါ။
  စာရင်းများ။
- Subscriptions နဲ့ trigger တွေအတွက် သေးငယ်တဲ့ filter တွေကို ကြိုက်တယ်။ Broad Filters တွေက
  ရောဂါရှာဖွေရေးအတွက် အသုံးဝင်ပေမဲ့ မလိုလားအပ်တဲ့ အကောင်အထည်ဖော်မှုနဲ့ ဖောက်သည်ဘက်ကို ထပ်ဖြည့်နိုင်တယ်
  စီမံခန့်ခွဲမှု
- စာရင်းထိုးထားတဲ့ ငွေချေးမှု စမ်းသပ်ချက်တွေကနေ ဖတ်လို့ရတဲ့ မီးခိုးစစ်ဆေးမှုကို သီးခြားထားပါ။
  အဆုံးသတ်မှတ်ချက်တွေရှိတာ ရောဂါရှာဖွေဖို့ ပိုလွယ်ပါတယ်။

ကြည့်ပါ။ [မေးခွန်းများ](/my/blockchain/queries.md), [ဖြစ်ရပ်များ](/my/blockchain/events.md), နှင့်
[စစ်ဆေးခြင်း](/my/blockchain/filters.md).

## အေဂျင့်ကူညီသော ဖွံ့ဖြိုးတိုးတက်မှု {#agent-assisted-development}

- အရာရှိတွေ ဆေးခန်းတွေကို စစ်ကြည့်ကြပါစို့။ SDK code နဲ့ read only network state ကို အရင်က
  သူတို့ကို ငွေကြေးဆိုင်ရာ ကုဒ်ကို ရေးခိုင်းတယ်။
- Live network test တွေကို environment flag လိုမျိုး နောက်ကွယ်မှာ opt-in လုပ်ထားပါ။
  `TAIRA_LIVE=1`.
- ပုဂ္ဂလိက သော့တွေ၊ အကောင့် ပြန်လည်ထူထောင်ရေး ပစ္စည်းတွေကို မကပ်ပါနဲ့။ API လက်မှတ်များ သို့မဟုတ်
  စာရေးသူ ခေါင်းစဉ်တွေကို အမိန့်တွေဆီ ပို့ပေးတယ်။
- ဘယ်အရာရှိမဆို တိုက်ရိုက် စမ်းသပ်မှု ကွန်ရက်ကို မတင်ခင် ငွေကြေး စီမံကိန်းတစ်ခု တောင်းဆိုပါ။
  စီမံကိန်းမှာ ကွန်ရက်၊ အာဏာပိုင်၊ ညွှန်ကြားချက်တွေ၊
  အခွန်အရင်းအမြစ်၊ လေယာဉ်မောင်းမတိုင်ခင် ဖတ်စာများ၊ မျှော်လင့်ချက် ရလဒ်များနှင့် ထပ်မံစမ်းသပ်မှု အပြုအမူများ။

နိုင်ငံတကာ Taira MCP အလုပ်ဖြစ်စဉ်၊ ကြည့်ပါ
[ဆက်လက်တည်ဆောက်ပါ SORA 3: Taira နှင့် Minamoto](/my/get-started/sora-nexus-dataspaces.md#taira-mcp-for-agents).

## SDK သန့်ရှင်းရေး {#sdk-hygiene}

- ခေါက်ဆွဲ SDK ဘိုင်နရီဗားရှင်းတွေကို အတူတကွသုံးပြီး
  [ကိုက်ညီမှု Matrix](/my/reference/compatibility-matrix.md).
- ဖန်တီးထားတဲ့ Client Code, snippets နဲ့ Examples တွေကို
  အထက်ပိုင်း အလုပ်ခွင်ပြင်ဆင်ရေးကို ပိတ်ထားတယ်။
- Transaction-building code အတွက် unit testing တွေနဲ့ integration tests တွေကို ထည့်သွင်းပါ။
  သင်ရဲ့ လျှောက်လွှာကို အခြေခံတဲ့ စာဖတ်ရေးနည်းလမ်း အသေးဆုံးပါ။
