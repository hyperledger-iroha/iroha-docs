# အသုံးချမှု ဖွံ့ဖြိုးတိုးတက်ရေး {#application-development}

Iroha Applications တွေက transaction behaviour ကို ရှင်းလင်းအောင် လုပ်သင့်ပြီး Signature State ကို ထည့်သွင်းထားသင့်ပြီး Queries နဲ့ Event တွေကို ထုတ်လုပ်မှုမှာ အလွယ်တကူ လေ့လာနိုင်တဲ့ နည်းလမ်းတွေနဲ့ အသုံးပြုသင့်ပါတယ်။

## Client ကို Setup လုပ်ခြင်း {#client-setup}

- ပရိုဂရမ် အရင်းအမြစ်ကုဒ်အပြင်တွင် Client ဖွဲ့စည်းမှုကို သိမ်းဆည်းပါ။ Chain ID, Torii URL၊ လက်မှတ်ထိုးစာရင်းနှင့် ငွေချေးမှု settings များကို ပတ်ဝန်းကျင်ဆိုင်ရာ config မှထည့်သွင်းပါ။
- `client.toml` ဖိုင်များကို localnet၊ Taira, Minamoto နှင့် ပုဂ္ဂလိကွန်ရက်များအတွက် သီးခြားထားပါ။ ကူးယူထားသော testnet လက်မှတ်ရေးထိုးသူသည် mainnet လက်မှတ်ရေးဆွဲသူအဖြစ် ဘယ်တော့မှမဖြစ်သင့်ပါ။
- Transaction lifetimes နဲ့ status timeouts တွေကို ကြံစည်စွာ သတ်မှတ်ပါ။ အရမ်းတိုတဲ့ ဘဝသက်တမ်းဟာ ပုံမှန်ကွန်ရက် စိတ်လှုပ်ရှားမှုအောက်မှာ ကုန်ဆုံးနိုင်ပြီး အရမ်းရှည်တာတစ်ခုကျတော့ duplicate submissions ကို ဆင်ခြင်ဖို့ ပိုခက်ခဲစေပါတယ်။
- `nonce = true` ကို အကြိမ်ကြိမ်ပြုလုပ်သော ငွေချေးမှုများတွင် မတူညီသော hash များရှိပါကသာ အသုံးပြုပါ။ idempotent လုပ်ငန်းဆောင်ရွက်မှုများအတွက် လျှောက်လွှာတောင်းဆိုချက် ID ကို သိုလှောင်၍ ပြန်လည်အသုံးပြုခြင်းဖြင့် ထပ်မံစမ်းသပ်နိုင်သည်။

လက်ရှိ TOML ကွင်းများအတွက် [Client Configuration](/my/guide/configure/client-configuration.md) ကို ကြည့်ပါ။

## ငွေပေးချေမှု {#transactions}

- JSON သို့မဟုတ် string-assembled payload များအစား တတ်နိုင်သလောက် SDK typeed instruction များမှ ရယူရန်။
- Preflight အရေးပါသောစာသည် ဖတ်ရန်အတွက်သာ မေးမြန်းချက်များဖြင့် ရေးသားထားသည် - အကောင့်တည်ရှိမှု၊ အရင်းအမြစ်ကျန်ရစ်မှု၊ ခွင့်ပြုချက်အခြေအနေ၊ အခွန်အရင်းအမြစ်ရရှိနိုင်မှုနှင့်ရည်မှန်းချက်အရာဝတ္ထုအခြေအနေ။
- ငွေပေးချေမှု ဟက်ရှ်၊ အာဏာပိုင်အကောင့်၊ ညွှန်ကြားချက်စုဆောင်းချက်နဲ့ မျှော်မှန်းထားတဲ့ အခြေအနေ ပြောင်းလဲမှုကို တင်မတင်ခင် မှတ်တမ်းတင်ပါ။
- `Rejected`, `Expired` ကိုပြုပြင်ပြီး အချိန်ကုန်ဆုံးမှု ရလဒ်တွေက မတူပါဘူး။ အချိန်ကုန်ဆုံးခြင်းဆိုတာက ဖောက်သည်က နောက်ဆုံးအခြေအနေကို မစောင့်ရှောက်ခဲ့ဘူး၊ ကွန်ရက်က ငွေပေးချေမှုကို လျစ်လျူရှုတာ သက်သေမပြဘူး။
- အောင်မြင်စွာ ရေးပြီးနောက်၊ ရလာသော အခြေအနေကို လုပ်ငန်း လုပ်ကိုင်မှုနှင့် ကိုက်ညီတဲ့ မေးမြန်းချက် (သို့) ဖြစ်ရပ် စစ်ဆေးရေး မှတ်တိုင်ဖြင့် စစ်ဆေးပါ။

Transaction mechanics အတွက် [Transactions ](/my/blockchain/transactions.md) ကို ကြည့်ပါ။

## မေးခွန်းများနှင့် ဖြစ်ရပ်များ {#queries-and-events}

- အပြောင်းအလဲ အသိပေးချက်များအတွက် လက်ရှိအခြေအနေနှင့်ဖြစ်ရပ်စီးကြောင်းများကို မေးမြန်းမှုများကို အသုံးပြုပါ။ ဖြစ်ရပ်ကိုင်တွယ်မှုကို အထပ်ထပ်ကျယ်ပြန့်သော မေးမြန်းမှုများဖြင့် အစားထိုးခြင်းကို ရှောင်ရှားပါ။
- Account၊ asset နှင့် block listings ကဲ့သို့သော ကျယ်ပြန့်တဲ့ iterable queries များကို page လုပ်ပါ။
- စာရင်းသွင်းခြင်းများနှင့် trigger များအတွက် သေးငယ်သော filter များကို ကြိုက်သည်။ ကျယ်ပြန့်သော filter များသည် ရောဂါရှာဖွေမှုအတွက် အသုံးဝင်သော်လည်း မလိုအပ်သော execution နှင့် client-side processing ကို ထည့်သွင်းနိုင်သည်။
- Read Only ဆေးလိပ်စစ်ဆေးမှုကို လက်မှတ်ထိုးထားတဲ့ ကုန်သွယ်မှု စမ်းသပ်ချက်တွေနဲ့ ကွဲပြားအောင်လုပ်ပါ၊ ဒီတော့ အဆုံးအဖြတ် ရယူနိုင်စွမ်းကို ပိုလွယ်ကူစွာ ရှာဖွေဖို့ပါ။

ကြည့်ပါ။ [မေးခွန်းများ](/my/blockchain/queries.md), [ဖြစ်ရပ်များ](/my/blockchain/events.md), နှင့် [Filters များ](/my/blockchain/filters.md).

## ကိုယ်စားလှယ်ကူညီသော ဖွံ့ဖြိုးမှု {#agent-assisted-development}

- စာရွက်စာတမ်းတွေ၊ SDK ကုဒ်နဲ့ ဖတ်လို့သာရတဲ့ ကွန်ရက်အခြေအနေတွေကို စာချုပ်ကုဒ်ရေးဖို့ သူတို့ကို မတောင်းခင် စစ်ဆေးပေးပါ။
- `TAIRA_LIVE=1` ကဲ့သို့သော ပတ်ဝန်းကျင် အလံတစ်ခုနောက်မှ လက်ခံခွင့်ပြုရန် တိုက်ရိုက်ကွန်ရက်စမ်းသပ်ချက်များကို ထိန်းသိမ်းပါ။
- ပုဂ္ဂလိက သော့တွေ၊ အကောင့် ပြန်လည်ထူထောင်ရေး ပစ္စည်းတွေ၊ API tokens တွေ၊ ဒါမှမဟုတ် forwarded author headers တွေကို prompt ထဲမှာ မထည့်ပါနဲ့။
- ဘယ်လက်နက်ကိုင်မှ တိုက်ရိုက် testnet ငွေပေးချေမှု မတင်ခင် ကုန်သွယ်ရေး အစီအစဉ်ကို တောင်းဆိုပါ။ အစီအစဉ်မှာ ကွန်ရက်၊ အာဏာပိုင်၊ ညွှန်ကြားချက်တွေ၊ အခွန်အရင်းအမြစ်၊ လေယာဉ်မောင်းမတိုင်မီ စာဖတ်မှု၊ မျှော်လင့်ရတဲ့ ရလဒ်နဲ့ ထပ်မံစမ်းသပ်တဲ့ အပြုအမူကို သတ်မှတ်ထားသင့်တယ်။

နိုင်ငံရေးပါတီ Taira MCP Workflow ကို ကြည့်ပါ [ဆက်လက်တည်ဆောက်ပါ SORA 3: Taira နှင့် Minamoto](/my/get-started/sora-nexus-dataspaces.md#taira-mcp-for-agents).

## SDK သန့်ရှင်းရေး {#sdk-hygiene}

- Pin SDK နှင့် ဘိုင်နရီဗားရှင်းများကို [ Compatibility Matrix](/my/reference/compatibility-matrix.md) ကိုအသုံးပြု၍ အတူတကွသုံးပါ။
- ထုတ်လုပ်ထားသော Client Code, snippets နှင့် နမူနာများကို Upstream Workspace revision နှင့်အတူ synchronized ထားပါ။
- သင့်အက်ပ်လီကေးရှင်းပေါ် မူတည်တဲ့ စာဖတ်ရေး လမ်းကြောင်း အသေးဆုံးအတွက် ငွေကြေးပံ့ပိုးရေး ကုဒ်နဲ့ ပေါင်းစပ်မှု စမ်းသပ်မှုတွေအတွက် ယူနစ်စမ်းသပ်မှုတွေကို ထည့်သွင်းပါ။
