# လွတ်မြောက်ရန် အသင့်ရှိ {#release-readiness}

မကြော်ငြာခင် Iroha application (သို့) network change ကိုပြုမူမှု သက်သေပြပါ
သက်ဆိုင်ရာအန္တရာယ်ကို ဖော်ပြနိုင်တဲ့ အသေးဆုံး ပတ်ဝန်းကျင်မှာ
မျှဝေထားတဲ့ စမ်းသပ်ရေးကွန်ရက်နဲ့ ထုတ်လုပ်ရေးဂိတ်တွေကို ရည်ရွယ်ချက်ရှိပြီး သုံးပါတယ်။

## Localnet ဂိတ် {#localnet-gate}

- တစ်ကြိမ်သုံးနိုင်တဲ့ ဒေသတွင်းကွန်ရက်ကို အလားတူ Iroha track နှင့်
  အနီးဆုံး လက်တွေ့ validator ရေတွက်ချက်ပါ။
- Transaction Builders အတွက် Unit Tests Run လုပ်ခြင်း၊ Query Parsing၊ Rejection
  ကိုင်တွယ်မှုနှင့် တင်သွင်းမှုကို ညှိပေးပါ။
- အနည်းဆုံး အောင်မြင်တဲ့ စာဖတ်ခြင်းနဲ့ ရေးခြင်း လမ်းကြောင်းတွေကို လေ့ကျင့်ပါ။
  SDK ဒါမှမဟုတ် CLI နောက်ပိုင်းမှာ အသုံးပြုမယ့် ပုံစံပါ။
- မျှော်မှန်းထားသော ငွေချေးမှု hashes, အခြေအနေများ, ဖြစ်ရပ်များနှင့်အခြေအနေဖတ်ရှုချက်များကိုဖမ်းယူပါ
  စမ်းသပ်မှု လက်ရာများ။

ကြည့်ပါ။ [လွှတ်တင်ခြင်း Iroha 3](/my/get-started/launch-iroha.md) နှင့်
[SDK သင်ခန်းစာများ](/my/guide/tutorials/).

## မျှဝေသော Testnet Gate {#shared-testnet-gate}

- အသုံးပြုခြင်း Taira (သို့) Endpoint အပြုအမူ၊ အခွန်များ၊ အကောင့်များအတွက် မျှဝေထားသော အခြား testnet တစ်ခု
  ငွေကြေးထောက်ပံ့မှု၊ အချိန်ဆွဲမှုနဲ့ လုပ်ငန်းဆိုင်ရာ လေ့ကျင့်မှုတွေပါ။
- Live testnet စာသားကို opt-in လုပ်ထားပါ ပုံမှန် စမ်းသပ်မှု run တွေဟာ
  ကွန်ရက်ရရှိမှု (သို့မဟုတ်) testnet ငွေကြေးသုံးစွဲခြင်း။
- လက်မှတ်ရေးထိုးသူ၏ ငွေကြေး၊ အခွန်အရင်းအမြစ် metadata များ၊ အာဏာပိုင် ခွင့်ပြုချက်များအား စစ်ဆေးခြင်း၊
  တိုက်ရိုက်စမ်းသပ်မှုလုပ်ငန်းစဉ်တိုင်းကို မတင်မီ မျှော်လင့်ထားသော အခြေအနေ။
- terminal status ကိုစောင့်ပြီး resulting state ကို verify လုပ်ပါ။
  ဖတ်လို့သာရတဲ့ မေးမြန်းချက်

ကြည့်ပါ။
[ဆက်လက်တည်ဆောက်ပါ SORA 3: Taira နှင့် Minamoto](/my/get-started/sora-nexus-dataspaces.md).

## အဓိက ကွန်ရက် သို့မဟုတ် ထုတ်လုပ်ရေးဂိတ် {#mainnet-or-production-gate}

- သီးခြားထုတ်လုပ်ရေး လက်မှတ်ထိုးသူတွေ၊ ငွေကြေးထောက်ပံ့မှုတွေ၊ ဒိုမင်တွေနဲ့ ကွန်ဖိုင်းလမ်းကြောင်းတွေကို သုံးပါ။
  စမ်းသပ်ရေးကွန်ရက် သော့များ (သို့) faucet အယူအဆများကို မကြံ့ဖြိုးစေပါ။
- အတည်ပြုချက် SDK, CLI, peer နှင့် net compatibility ကို
  [ကိုက်ညီမှု Matrix](/my/reference/compatibility-matrix.md).
- ပြန်လည်သုံးသပ်ခွင့်ပြုချက်များ၊ အခွန်ထောက်ပံ့မှုများ၊နှုန်းသတ်မှတ်ချက်များ၊ စောင့်ကြည့်ခြင်း၊ backup
  အခြေအနေနဲ့ ပြန်လည်ဖြန့်ချိဖို့ ပြတင်းပေါက်မတိုင်ခင်က ကျင့်သုံးတဲ့ သတ်မှတ်ချက်တွေပါ။
- သက်ရောက်မှုမြင့်မားသော စာရွက်စာတမ်းများအတွက် ရေးသားထားသော ငွေကြေးဆိုင်ရာ စီမံကိန်း (သို့) ရွှေ့ပြောင်းရေး အစီအစဉ်ကို တောင်းဆိုပါ။

## ပြန်လည်ထူထောင်ခြင်း {#rollback-and-recovery}

- Code deployment ကနေ ဘယ်အပြောင်းအလဲတွေကို ပြန်လည်ဖြန့်ချိနိုင်မလဲဆိုတာ သတ်မှတ်ပါ
  ချိတ်ဆက်မှုတစ်ခုမှာ တိုက်ရိုက် ဖျက်လို့မရဘူး။
- ချိတ်ဆက်ထားသော ဒေတာပြောင်းလဲမှုအတွက် ငွေကြေးပေးချေမှု (သို့) ရွှေ့ပြောင်းခြင်းများကို ပြင်ဆင်ပါ။
  ပထမထုတ်လုပ်မှု မရေးခင် ဇာတ်ညွှန်းတွေ ရေးပါ။
- ကွန်ရက်ပြောင်းလဲမှုအတွက် အရင် Binary ကို သိမ်းထားပါ။
  genesis နဲ့ ထုတ်ဝေမှုအတွင်းမှာ ရနိုင်တဲ့ လုပ်ဆောင်ရေး runbook တွေပါ။
- ရည်ရွယ်ချက်ရှိတဲ့ အချက်ပြချက်တွေကို အခြေခံပြီး ဖြန့်ချိမှုကို ရပ်ဆိုင်းဖို့ ဆုံးဖြတ်ချက် ချမှတ်ပါ။
  ဥပမာ ပယ်ချမှုနှုန်း၊ တန်းစီတိုးတက်မှု၊ အချိန်ဆွဲခြင်း (သို့) အဖော်တွေရဲ့ ကျန်းမာရေးပါ။

## နောက်ဆုံး စစ်ဆေးစာရင်း {#final-checklist}

- အသင့်အတင့်ပြင်ဆင်ခြင်းသည် ပတ်ဝန်းကျင်ဆိုင်ရာ သီးသန့်ဖြစ်ပြီး စမ်းသပ်မှုများကိုသာ မပါဝင်ပါ။
  လျှို့ဝှက်ချက်တွေပါ။
- Transaction Re-Try အပြုအမူဟာ idempotent (သို့) ရှင်းလင်းစွာ ကန့်သတ်ထားတယ်။
- အဆိုပါ လျှောက်လွှာတွင် ငြင်းပယ်ခြင်း၊ သက်တမ်းကုန်ဆုံးခြင်း၊ အချိန်ဖြတ်ခြင်းနှင့် အဆုံးသတ်မှတ်ချက်တို့ကို ခွဲခြားနိုင်သည်။
  ရယူနိုင်မှု ပျက်ကွက်ခြင်း။
- စောင့်ကြည့်ခြင်းသည် ထုတ်ကုန်ထုတ်လုပ်မှု၊ နှောင့်နှေးမှု၊ အတန်းနက်၊ ပယ်ချချက်များ၊ ကြည့်ရှုမှုများကို ဖုံးအုပ်သည်။
  အပြောင်းအလဲများနှင့် သက်ဆိုင်သော စီးပွားရေးဖြစ်စဉ်များ။
- Operator တွေမှာ ကြိုတင်ခန့်မှန်းထားတဲ့ ပျက်ကွက်မှု mode တွေအတွက် runbooks ရှိတယ်။
- လုံခြုံရေး စစ်ဆေးမှုက အဓိက ထိန်းသိမ်းမှု၊ ခွင့်ပြုချက်တွေ၊ ကွန်ရက် ထိတွေ့မှုတွေနဲ့ ပတ်သက်တယ်။
  အလိုအလျောက် လုပ်ပိုင်ခွင့်။
