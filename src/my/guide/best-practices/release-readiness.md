# လွတ်မြောက်ရန် အသင့်ရှိခြင်း {#release-readiness}

Iroha အက်ပ် သို့မဟုတ် ကွန်ရက်ပြောင်းလဲမှုကို နောက်အဆင့်သို့ မတင်မီ သက်ဆိုင်ရာ အန္တရာယ်ကို ဖော်ထုတ်နိုင်သော အသေးဆုံးပတ်ဝန်းကျင်၌ အပြုအမူကို သက်သေပြပါ။ ထို့နောက် မျှဝေသုံး testnet နှင့် production စစ်ဆေးတံခါးများကို ရည်ရွယ်ချက်ရှိရှိ အဆင့်ဆင့် ဖြတ်သန်းပါ။

## Localnet ဂိတ် {#localnet-gate}

- တူညီသော Iroha ဖွံ့ဖြိုးရေးလမ်းကြောင်းနှင့် လက်တွေ့ဖြစ်နိုင်သမျှ အနီးစပ်ဆုံး validator အရေအတွက်ကို အသုံးပြုသော စွန့်ပစ်အစားထိုးနိုင်သည့် စက်တွင်းကွန်ရက်ကို စတင်ပါ။
- Transaction တည်ဆောက်ကိရိယာများ၊ query parse လုပ်ခြင်း၊ ငြင်းပယ်မှုကိုင်တွယ်ခြင်းနှင့် ပြင်ဆင်သတ်မှတ်မှု ဖတ်တင်ခြင်းတို့အတွက် ယူနစ်စမ်းသပ်ချက်များကို လုပ်ဆောင်ပါ။
- နောက်ပိုင်း အက်ပ်က အသုံးပြုမည့် SDK သို့မဟုတ် CLI ပုံစံတူမှတစ်ဆင့် အနည်းဆုံးလိုအပ်သော အောင်မြင်သည့် ဖတ်ရှုမှုနှင့် ရေးသားမှု လမ်းကြောင်းများကို စမ်းသပ်ပါ။
- မျှော်မှန်းထားသော transaction ဟက်ရှ်များ၊ အခြေအနေများ၊ ဖြစ်ရပ်များနှင့် အခြေအနေဖတ်ရှုမှုများကို စမ်းသပ်မှုအထောက်အထားဖိုင်များတွင် သိမ်းပါ။

[လွှတ်တင်ခြင်း Iroha 3](/my/get-started/launch-iroha.md) နှင့် [SDK သင်တန်းများ](/my/guide/tutorials/) ကိုကြည့်ပါ။

## မျှဝေသော Testnet Gate {#shared-testnet-gate}

- အဆုံးမှတ်၏ လုပ်ဆောင်ပုံ၊ အခကြေးငွေများ၊ အကောင့်ထဲသို့ ငွေဖြည့်ခြင်း၊ တုံ့ပြန်ချိန်နှောင့်နှေးမှုနှင့် လုပ်ငန်းဆောင်ရွက်မှု အစမ်းလေ့ကျင့်ခြင်းတို့အတွက် Taira သို့မဟုတ် အခြားမျှဝေသုံးစွဲသော စမ်းသပ်ကွန်ရက်တစ်ခုကို အသုံးပြုပါ။
- Keep live testnet က opt-in ကို ရေးထားတယ်ဆိုတော့ သာမန် စမ်းသပ်မှု run တွေက ကွန်ရက်ရရှိနိုင်မှုနဲ့ testnet ရင်းနှီးမြှုပ်နှံမှုအပေါ် မမှီခိုပါဘူး။
- လက်မှတ်ရေးထိုးသူအတွက် ငွေကြေးထောက်ပံ့မှု၊ အခွန်အရင်းအမြစ် metadata များ၊ ခွင့်ပြုချက် အရင်းအမြစ်ခွင့်ပြုချက်များနှင့် တိုက်ရိုက်စမ်းသပ်မှုလုပ်ငန်းစဉ်တစ်ခုစီကို မတင်မီ မျှော်လင့်ထားသောအခြေအနေများကို စစ်ဆေးပါ။
- အဆုံးသတ်အခြေအနေကို စောင့်ဆိုင်းပြီး ရရှိလာသောအခြေအနေကို ဖတ်ရှုခြင်းသက်သက် query ဖြင့် စစ်ဆေးအတည်ပြုပါ။

## အဓိကကွန်ရက် (သို့) ထုတ်လုပ်ရေးဂိတ် {#mainnet-or-production-gate}

- Production အတွက် သီးခြားလက်မှတ်ထိုးသူများ၊ ငွေဖြည့်မှု၊ domain များနှင့် ပြင်ဆင်သတ်မှတ်ဖိုင် လမ်းကြောင်းများကို သုံးပါ။ Testnet ကီးများ သို့မဟုတ် faucet အပေါ် ယူဆချက်များကို production သို့ ယူမသုံးပါနှင့်။
- လိုအပ်သော SDK အချင်းချင်း အလုပ်လုပ်မှုဖြစ်စဉ်များကို [ကိုက်ညီစွာအလုပ်လုပ်နိုင်မှုဇယား](/my/reference/compatibility-matrix.md) ဖြင့် အတည်ပြုပါ။ ဖြန့်ချိတပ်ဆင်မှုတွင် အသုံးပြုမည့် CLI၊ peer executable ဖိုင်၊ ပြင်ဆင်သတ်မှတ်ချက်နှင့် ကွန်ရက်ထုတ်ဝေမှုတို့ကို တိကျသောဗားရှင်းအတိုင်း သီးခြားသတ်မှတ်၍ စမ်းသပ်ပါ။
- ထုတ်ဝေမှုကာလ မတိုင်မီ ခွင့်ပြုချက်များ၊ အခကြေးငွေကိုယ်စားပေးမှု၊ တောင်းဆိုမှုနှုန်း ကန့်သတ်ချက်များ၊ စောင့်ကြည့်မှု၊ အရန်သိမ်းမှုအခြေအနေနှင့် နောက်ပြန်ပြောင်းရန် စံနှုန်းများကို ပြန်လည်သုံးသပ်ပါ။
- သက်ရောက်မှုမြင့်မားသော စာရွက်စာတမ်းများအတွက် ရေးသားသော ငွေပေးချေမှု သို့မဟုတ် ရွှေ့ပြောင်းရေး အစီအစဉ်ကို တောင်းဆိုပါ။

## ပြန်လည်ထူထောင်ခြင်း {#rollback-and-recovery}

- မည်သည့်ပြောင်းလဲမှုများကို ကုဒ်ဖြန့်ချိခြင်းဖြင့် နောက်ပြန်ပြောင်းနိုင်ကြောင်း၊ မည်သည့်အရာများအတွက် on-chain transaction လိုအပ်ကြောင်းနှင့် မည်သည့်အရာများကို တိုက်ရိုက်ပြန်မပြင်နိုင်ကြောင်း သတ်မှတ်ပါ။
- On-chain ဒေတာပြောင်းလဲမှုများအတွက် ပထမ production ရေးသားမှု မတိုင်မီ ပြောင်းလဲမှုကို ချေဖျက်ညှိပေးမည့် transaction များ သို့မဟုတ် ပြောင်းရွှေ့ရေး script များကို ပြင်ဆင်ထားပါ။
- ကွန်ရက်ပြောင်းလဲမှုများအတွက် ယခင် executable ဖိုင်၊ ပြင်ဆင်သတ်မှတ်ချက်အစု၊ လက်မှတ်ထိုးထားသော genesis နှင့် လုပ်ငန်းဆောင်ရွက်ရေးလမ်းညွှန်တို့ကို ထုတ်ဝေစဉ် အသင့်ထားပါ။
- ပယ်ချမှုနှုန်း၊ တန်းစီတိုးတက်မှု၊ နှောင့်နှေးမှု (သို့) ကွန်ရက် အဖော်တွေရဲ့ ကျန်းမာရေးလို ရည်ရွယ်ချက်ရှိတဲ့ အချက်ပြမှုတွေကို အခြေခံပြီး ဖြန့်ဖြူးမှုကို ရပ်ဆိုင်းဖို့ ဆုံးဖြတ်ချက် ချမှတ်ပါ။

## နောက်ဆုံး စစ်ဆေးစာရင်း {#final-checklist}

- ပြင်ဆင်သတ်မှတ်မှုသည် ပတ်ဝန်းကျင်တစ်ခုစီအတွက် သီးခြားဖြစ်ပြီး စမ်းသပ်မှုအတွက်သာ သုံးသော လျှို့ဝှက်ချက်များ မပါဝင်ရပါ။
- ရင်းနှီးမြှုပ်နှံမှု ပြန်လည်ကြိုးပမ်းခြင်း ပြုမူပုံဟာ မတတ်နိုင်တာ (သို့) ရှင်းလင်းစွာ ကန့်သတ်ထားတာပါ။
- အက်ပ်သည် ငြင်းပယ်မှု၊ သက်တမ်းကုန်ဆုံးမှု၊ စောင့်ဆိုင်းချိန်ကန့်သတ်ချက်ကျော်လွန်မှုနှင့် အဆုံးမှတ်ကို မရရှိနိုင်သည့် ပျက်ကွက်မှုတို့ကို ခွဲခြားနိုင်သည်။
- စောင့်ကြည့်မှုသည် ပမာဏ၊ နှောင့်နှေးမှု၊ အတန်းနက်၊ ငြင်းပယ်ချက်များ၊ မြင်ကွင်းပြောင်းလဲမှုများနှင့် သက်ဆိုင်ရာ လုပ်ငန်းဖြစ်ရပ်များကို ဖမ်းဆီးသည်။
- အော်ပရေတာတွေမှာ မျှော်လင့်ရတဲ့ ပျက်ကွက်မှုပုံစံတွေအတွက် Runbooks ရှိတယ်။
- လုံခြုံရေး စစ်ဆေးမှုက အဓိက ထိန်းသိမ်းမှု၊ ခွင့်ပြုချက်တွေ၊ ကွန်ရက် ထိတွေ့မှုတွေနဲ့ အလိုအလျောက် လုပ်ပိုင်ခွင့် မူဝါဒတွေကို ဖေါ်ပြခဲ့တယ်။
