# အများပြည်သူနှင့် ပုဂ္ဂလိက ဘလော့ခ်ချိုင်းများ {#public-and-private-blockchains}

Iroha ကို configurations အမျိုးမျိုးမှာ run လုပ်နိုင်ပါတယ်။ သင့်ရဲ့ ကိုယ်ပိုင်ကွန်ရက်ရဲ့ administrator အနေနဲ့ ဘယ်အကောင်အထည်ဖော်သူနဲ့ ခွင့်ပြုချက် မူဝါဒဟာ ငွေပေးချေမှုတစ်ခု လက်ခံခံရလားဆိုတာ ဆုံးဖြတ်ပါတယ်။

Common Profiles များမှာ Private Permissioned Networks နှင့် ပိုမိုပွင့်လင်းသော Public Networks တို့ဖြစ်သည်။ နှစ်ခုစလုံးသည် သီးခြား node binaries များမှမဟုတ်ဘဲ Genesis state နှင့် executor မူဝါဒများမှတစ်ဆင့် သတ်မှတ်ထားသည်။

အောက်မှာ ဒီသုံးစွဲမှု ကိစ္စနှစ်ခုရဲ့ အဓိက ကွာခြားချက်တွေကို ဖော်ပြထားပါတယ်။

## ခွင့်ပြုချက်များ {#permissions}

အများပိုင် blockchain မှာ အကောင့်အများစုမှာ ခွင့်ပြုချက်တွေ အတူတူရှိပြီး ပုဂ္ဂလိက blockchain မှာ အကောင်တိုင်းဟာ တိကျတဲ့ ခွင့်ပြုချက်တွေပဲ ရပါတယ်။

::: info

[ အထူးအခွင့်ပြုချက်များဆိုင်ရာ အပိုင်း ](/my/blockchain/permissions.md) ကို အသေးစိတ်ဖတ်ရှုပါ။

:::

## အဖော်များ {#peers}

အများပြည်သူ blockchain တွင် peer admittion သည် chain policy ၏ အစိတ်အပိုင်းဖြစ်သည်။ ပုဂ္ဂလိက blockchain အတွက် deployments များသောအားဖြင့် configuration နှင့် genesis တွင် ယုံကြည်မှုရှိ peer set ကို pin လုပ်သည်။

::: info

အသေးစိတ်အချက်အလက်များအတွက် [ peer management ](peer-management.md) ကိုကြည့်ပါ။

:::

## မှတ်ပုံတင်စာရင်းများ {#registering-accounts}

[genesis block (`genesis.json`)](genesis.md) ကို ဘယ်လို set up လုပ်မလဲဆိုတာအပေါ်မှာ မူတည်ပြီး Account တစ်ခုကို မှတ်ပုံတင်ခြင်း လုပ်ငန်းစဉ်ဟာ နှစ်မျိုးထဲမှ တစ်ခု ဖြစ်နိုင်ပါတယ်။ ဘာကြောင့်လဲဆိုတာကို နားလည်ဖို့ ပထမဆုံး ခွင့်ပြုချက် အကြောင်း ပြောကြရအောင်။

ရွေးချယ်ထားသော အကောင်အထည်ဖော်သူက မည်သည့်ခွင့်ပြုချက် စစ်ဆေးမှုများကို သတ်မှတ်သည်။ သီးသန့်၊ စီမံအုပ်ချုပ်ရေးမှူးစီမံခန့်ခွဲသောကွန်ရက် သို့မဟုတ် ပိုမိုပွင့်လင်းသောကွန်ယက်ကို ပုံသွင်းရန်အတွက် မူရင်း [ခွင့်ပြုချက် လက်မှတ်များ](/my/blockchain/permissions.md) ကိုမူရင်းအဖြစ်ပေးနိုင်ပါသည်။ ထိုခွင့်ပြုချက်များ တက်ကြွပြီးနောက်တွင်, အကောင့်များကို မှတ်ပုံတင်ခြင်းဖြစ်စဉ်သည် မတူပါ။

အများပြည်သူနဲ့ ပုဂ္ဂလိက မှတ်ပုံတင် မူဝါဒတွေဟာ ပုံမှန်အားဖြင့် ကွဲပြားပါတယ်။

- ပြည်သူ့မှတ်ပုံတင်မူဝါဒတစ်ခုသည် ဝင်ခွင့်ရှိသည့် အသုံးပြုသူတိုင်း၏ အကောင့်မှတ်ပုံတင်မှုကို လက်ခံသည်[^1]။ သုံးစွဲသူသည်သင့်တော်သောဖောက်သည်၊ ထောက်ပံ့သောအယ်လ်ဂိုရစ်သမ်အတွက် ပုဂ္ဂလိကဆော့ချက်နှင့် မူဝါဒအရလက်ခံထားသော မှတ်ပုံတင်တောင်းဆိုမှုလိုအပ်ပါသည်။

- ပုဂ္ဂလိက မှတ်ပုံတင် မူဝါဒတစ်ခုသည် မှတ်ပုံတင်များကို တင်ပြရန် အကောင့်တစ်ခုသို့မဟုတ် စမတ်စာချုပ် တစ်ခုကို ခွင့်ပြုနိုင်သည်။ အတိုင်ပင်ခံပုဂ္ဂိုလ် မူဝါဒတစ်ရပ်သည်မှတ်ပုံတင်မှုကို အချိန် ပြူတင်းပေါက်တစ်ခုအထိ ကန့်သတ်နိုင်သည်။ မည်သည့်အာဏာပိုင်မှ ထပ်မံထုတ်လုပ်ခွင့်မရှိသောအတွက် ပေးသွင်းသူအနေဖြင့် ရောင်းချထားသော tokens ကိုသုံးစွဲရန်လည်း တောင်းဆိုနိုင်သည်။

- မူရင်း ပုဂ္ဂလိက ကွန်ရက် ပုံစံမှာ ရှိနေတဲ့ အကောင့်တစ်ခုဟာ အသစ်တစ်ခုစီအတွက် မှတ်ပုံတင်ကို တင်ပေးတယ်။

Default permission validators တွေက သာမန် ပုဂ္ဂလိက blockchain သုံးစွဲမှု ကိစ္စကို ဖုံးအုပ်ပါတယ်။

::: info

Public နှင့် Private mode တို့သည် executor နှင့် genesis policy ရွေးချယ်မှုများဖြစ်သည်။ နှစ်ခုစလုံးသည် node binary တစ်ခုတည်းကိုအသုံးပြုသည်။ ဖွင့်လှစ်သောကွန်ရက်ကိုမလည်ပတ်ခင်ရွေးချယ်ထားသော executor နှင့် génesis ခွင့်ပြုချက်များကိုစစ်ဆေးပါ။

:::

[ ညွှန်ကြားချက်များ](/my/blockchain/instructions.md#un-register) အပိုင်းကို `Register<Account>` ညွှန်ပြချက်များနှင့် ပတ်သက်၍ အသေးစိတ်အချက်အလက်များအတွက် ကြည့်ပါ။

[^1]: `Register<Account>` က Canonical, domainless `AccountId` အတွက် ledger state ကိုဖန်တီးတယ်။ Domain routing နဲ့ aliases တွေကို သီးခြားစီ စီမံပါတယ်။
