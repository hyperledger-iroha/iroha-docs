# အများပြည်သူနှင့် ပုဂ္ဂလိက ဘလော့ခ်ချိုင်းများ {#public-and-private-blockchains}

Iroha ကို configurations အမျိုးမျိုးမှာ run လုပ်နိုင်ပါတယ်။ သင့်ရဲ့ ကိုယ်ပိုင်ကွန်ရက်ရဲ့ administrator အနေနဲ့ ဘယ်အကောင်အထည်ဖော်သူနဲ့ ခွင့်ပြုချက် မူဝါဒဟာ ငွေပေးချေမှုတစ်ခု လက်ခံခံရလားဆိုတာ ဆုံးဖြတ်ပါတယ်။

Common profiles တွေက Private Permissioned Networks နဲ့ Open Public Networks တို့ပါ။ နှစ်ခုစလုံးဟာ သီးခြား node binaries တွေကနေမဟုတ်ပဲ blockchain genesis state နဲ့ executor policy တွေကနေ ဖွဲ့စည်းထားတာပါ။

အောက်မှာ ဒီသုံးစွဲမှု ကိစ္စနှစ်ခုရဲ့ အဓိက ကွာခြားချက်တွေကို ဖော်ပြထားပါတယ်။

## ခွင့်ပြုချက်များ {#permissions}

အများပိုင် blockchain မှာ အကောင့်အများစုမှာ ခွင့်ပြုချက်တွေ အတူတူရှိပြီး ပုဂ္ဂလိက blockchain မှာ အကောင်တိုင်းဟာ တိကျတဲ့ ခွင့်ပြုချက်တွေပဲ ရပါတယ်။

::: info

[ခွင့်ပြုချက်များဆိုင်ရာ သီးသန့်အခန်း](/my/blockchain/permissions.md) ကို အသေးစိတ်ဖတ်ရှုရန်။

:::

## ကွန်ရက် အဖော်များ {#peers}

အများပြည်သူ blockchain တွင်, ကွန်ရက် peer admittion သည်ကွင်းဆက်မူဝါဒ၏တစ်စိတ်တစ်ပိုင်းဖြစ်သည်။ ပုဂ္ဂလိက blockchain အတွက်, deployments များသောအားဖြင့် configuration နှင့် blockchain မျိုးစေ့တွင်သတ်မှတ်ထားသောယုံကြည်မှု network peer ကို pin လုပ်သည်။

::: info

[ကွန်ရက် peer management](peer-management.md) ကို အသေးစိတ်ဖတ်ရှုပါ။

:::

## မှတ်ပုံတင်စာရင်းများ {#registering-accounts}

သင့်ရဲ့ စီမံကိန်းကို ဘယ်လိုချမှတ်မလဲဆိုတာ အပေါ် မူတည်ပြီး [blockchain ဘလော့ဂ် (`genesis.json`)](genesis.md), အကောင့်ကို မှတ်ပုံတင်ခြင်း လုပ်ငန်းစဉ်မှာ နှစ်နည်းလမ်းတစ်ခု ရှိနိုင်ပါတယ်။ ဘာကြောင့်လဲဆိုတာ နားလည်ဖို့ ခွင့်ပြုချက်အကြောင်း အရင်ပြောရအောင်။

ရွေးချယ်ထားသော အကောင်အထည်ဖော်သူက ဘယ်ခွင့်ပြုချက် စစ်ဆေးမှုများကို သတ်မှတ်သည်။ သီးသန့်၊ အုပ်ချုပ်ရေးမှူးစီမံခန့်ခွဲသည့်ကွန်ရက် (သို့) ပိုမိုပွင့်လင်းတဲ့ကွန်ရက်တစ်ခုကို ပုံသွင်းရန် blockchain မျိုးဆက်တွင် အလိုလျောက် [ခွင့်ပြုချက် လက်မှတ်များ](/my/blockchain/permissions.md) ကိုပေးနိုင်သည်။ ထိုခွင့်ပြုချက်များ တက်ကြွပြီးလျှင် အကောင့်များ မှတ်ပုံတင်ခြင်းလုပ်ငန်းစဉ်သည် မတူပါ။

အများပြည်သူနဲ့ ပုဂ္ဂလိက မှတ်ပုံတင် မူဝါဒတွေဟာ ပုံမှန်အားဖြင့် ကွဲပြားပါတယ်။

- အများပြည်သူ မှတ်ပုံတင် မူဝါဒတစ်ခုသည် ဝင်ခွင့်ရှိသည့် အသုံးပြုသူများထံမှ အကောင့်မှတ်ပုံတင်ခြင်းများကို လက်ခံသည်။[^1]. သုံးစွဲသူဟာ သင့်တော်တဲ့ ဖောက်သည်၊ ထောက်ပံ့ထားတဲ့ အယ်လ်ဂိုရစ်သမ်အတွက် ပုဂ္ဂလိက သော့နဲ့ မူဝါဒအရ လက်ခံထားတဲ့ မှတ်ပုံတင်တောင်းဆိုချက် လိုအပ်တယ်။

- ပုဂ္ဂလိက မှတ်ပုံတင် မူဝါဒတစ်ခုသည် မှတ်ပုံတင်လွှာများကို တင်ပြရန် အကောင့်တစ်ခုသို့မဟုတ် စမတ်စာချုပ်တစ်ခုကို ခွင့်ပြုနိုင်သည်။ Custom မူဝါဒတစ်ရပ်သည်မှတ်ပုံတင်မှုကို အချိန်ကာလတစ်ခုအထိ ကန့်သတ်နိုင်သည်။ စာရင်းပေးသွင်းသူသည် ပိုမိုထုတ်ဝေခွင့်မရှိသောအတွက် ရောင်းချမှု သတ်မှတ်ထားသည့် Token ကိုသုံးစွဲဖို့လည်း တောင်းဆိုနိုင်သည်။

- မူရင်း ပုဂ္ဂလိက ကွန်ရက် ပုံစံမှာ ရှိနေတဲ့ အကောင့်တစ်ခုဟာ အသစ်တစ်ခုစီအတွက် မှတ်ပုံတင်ကို တင်ပေးတယ်။

Default permission validators တွေက သာမန် ပုဂ္ဂလိက blockchain သုံးစွဲမှု ကိစ္စကို ဖုံးအုပ်ပါတယ်။

::: info

အများပြည်သူနှင့် ပုဂ္ဂလိက mode များသည် executor နှင့် blockchain genesis မူဝါဒရွေးချယ်မှုများဖြစ်သည်။ နှစ်ခုစလုံးသည်တူသော node binary ကိုသုံးသည်။ ဖွင့်လှစ်ထားသော ကွန်ရက်ကိုမဖွင့်ခင် ရွေးချယ်သည့် executor နှင့် Blockchain genesis ခွင့်ပြုချက်များကိုစစ်ဆေးပါ။

:::

[ညွှန်ကြားချက်](/my/blockchain/instructions.md#un-register) အပိုင်းကို `Register<Account>` ညွှန်ကြားချက်များနှင့် ပတ်သက်၍ အသေးစိတ်သိရှိလိုပါက။

[^1]: `Register<Account>` သည် တစ်ခုတည်းသော ပရိုတိုကော-စံညွှန်း, ဒိုမင်မဲ့ `AccountId` အတွက် blockchain ledger အခြေအနေကိုဖန်တီးသည်; ဒိုမိုင်း Routing နှင့် aliases ကို သီးခြားစီစီစီမံခန့်ခွဲသည်။
