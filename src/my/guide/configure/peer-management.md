# တန်းတူလူတန်းစား စီမံခန့်ခွဲမှု {#peer-management}

သင်ဟာ ဘာသာစကားဆိုင်ရာ လမ်းညွှန်ချက်တစ်ခုခုကို လိုက်နာခဲ့ရင် လူတွေဟာ လက်တွဲချင်တဲ့ ကောင်းမွန်စွာ အလုပ်လုပ်နေတဲ့ ကွန်ရက်တစ်ခု ရှိလာပါပြီ။

## အများပြည်သူ Blockchain {#public-blockchain}

ပွင့်လင်းသောကွန်ရက်တွင် peer admission သည်ဆက်သွယ်ရေးမူဝါဒ ဆုံးဖြတ်ချက်တစ်ခုဖြစ်သည်။ node တစ်ခုသည် မှန်ကန်သော software ကို run လုပ်နိုင်ပြီး Torii သို့ ချိတ်ဆက်နိုင်သော်လည်း ကွန်ရက်သည် peer identity ကို အသိအမှတ်ပြုပြီးနောက်မှသာ သဘောတူညီမှုထဲ ပါဝင်သည်။

## ပုဂ္ဂလိက Blockchain {#private-blockchain}

ငွေကြေးဘဏ်များတွင် လူတိုင်းသည် မိမိတို့အလိုအလျောက် ပါဝင်ခွင့်ပြုခြင်းသည် လုံခြုံရေးအန္တရာယ်တစ်ခုဖြစ်သည်။ လုံခြုံမှုအတွက်၊ ပုဂ္ဂလိက Iroha ဖြန့်ချိမှုများသည် အများအားဖြင့် ပွင့်လင်းသော ရှာဖွေတွေ့ရှိမှုအပေါ် မှီခိုခြင်းအစား အသီးသီး Topology ကို configuration နှင့် genesis တွင် pin လုပ်သည်။

### အတန်းတူများ မှတ်ပုံတင်ခြင်း {#registering-peers}

ကွန်ရက်မှာ peer ကို ထည့်သွင်းဖို့ လက်နဲ့ မှတ်ပုံတင်ဖို့လိုပါတယ်။ ဒီဖြစ်စဉ်ကို ပြီးအောင်လုပ်ဖို့ လုပ်ဆောင်သင့်တဲ့ ခြေလှမ်းတွေကို ဆွေးနွေးရအောင်။

#### (၁) သုံးစွဲသူကို ခွင့်ပြုချက်များ ပေးပါ။ {#_1-grant-the-user-permissions}

Peer ကို မှတ်ပုံတင်တဲ့စာရင်းမှာ သင့်တော်တဲ့ `Permission` ရှိဖို့လိုပါတယ်။ ဒါက `Role` ဖြင့် (သို့) တိုက်ရိုက် ခွင့်ပြုချက်ပေးခြင်းအဖြစ် ပေးအပ်နိုင်ပါတယ်။

အကောင့်တစ်ခုက အချိန်နဲ့အမျှ အဖော်တွေကို စီမံခန့်ခွဲတဲ့အခါ ကဏ္ဍတစ်ခုကို ပေးပါ။ တစ်ကြိမ်တည်း မှတ်ပုံတင်ခြင်းအတွက် အဖော်တွေကို မစီမံတဲ့ အကောင့်ကနေ တိုက်ရိုက် ခွင့်ပြုချက်ပေးမှုကို အသုံးပြုပါ။

::: info

Default executor က `CanManagePeers` ခွင့်ပြုချက် token ကို မှတ်ပုံတင်ခြင်းနှင့် မမှတ်ပုံတင်ခြင်းအတွက် သုံးပါတယ်။

:::

[ သီးခြားအခန်း ](/my/blockchain/permissions.md) တွင် ခွင့်ပြုချက်များနှင့် အခန်းကဏ္ဍများကို အသေးစိတ် ဆွေးနွေးပါမည်။

#### (၂) တူညီသူကို ဖွဲ့စည်းပေးပါ။ {#_2-set-up-a-peer}

အတန်းတူသစ်ကို ခွင့်ပြုချက်ပေးပြီးနောက် ၎င်းကို တည်ထောင်ရန် လိုပါတယ်။

node ကို admit မလုပ်ခင် peer configuration ကို request လုပ်ပါ။ Torii သည် node parameters နှင့် capability endpoints ကို expose လုပ်ပေးသည်။ Peer bootstrap ဒီတန်ဖိုးတွေကို အလိုအလျောက် ညှိနှိုင်းမပေးဘူး၊ လုပ်ငန်းရှင်တွေက timeouts၊ batch size နဲ့ သဘောတူညီချက်နဲ့ဆိုင်တဲ့ အခြား settings တွေက ကွန်ရက်နဲ့ ကိုက်ညီတာကို စစ်ဆေးဖို့လိုပါတယ်။

ဒီလုပ်ငန်းစဉ်ကို ရိုးစင်းစေဖို့ `config.toml` ရဲ့ ပြင်ဆင်ထားတဲ့ ဗားရှင်းတစ်ခုအတွက် ကွန်ရက်စီမံခန့်ခွဲရေးမှူးကို တောင်းဆိုနိုင်ပါတယ်၊ ဒါက peer private key တွေလို အခွင့်ထူးခံ အချက်အလက်တွေကို ပယ်ချတယ်။

#### (၃) ညွှန်ကြားချက်ကို တင်ပြပါ။ {#_3-submit-the-instruction}

သင့် peer က Run လုပ်ပြီးနောက် Register Peer ညွှန်ကြားချက်ကို တင်ပြသင့်ပါတယ်။ peer ဟာ လက်ဆွဲခြင်း လုပ်ငန်းစဉ်ကို ဖြတ်သန်းပြီး ကွန်ရက်နဲ့ စကားပြောစမယ်။

::: tip

အတန်းတူ မှတ်ပုံတင် ညွှန်ကြားချက်ကို တင်သွင်းခြင်းသည် အတန်းတူသစ်ဖြစ်စဉ်တစ်ခုကို ချက်ချင်းမပြုလုပ်နိုင် (သို့မဟုတ်) မပြုလုပ်နိုင်ပါ။

:::

### မှတ်ပုံတင်ခြင်းမရှိသော အဖော်များ {#unregistering-peers}

မမှတ်ပုံတင်တဲ့ တူညီသူတွေကိုရော။ လုံခြုံရေးအကြောင်းပြချက်တွေက ဒီဖြစ်စဉ်က တစ်ဘက်တည်းပါ။ ကွန်ရက်ဟာ တူညီသူကို ဖယ်ရှားချင်တယ်ဆိုတဲ့ သဘောတူညီမှုဆီ ရောက်သွားတယ်။ ဒါပေမဲ့ တူညီသူကိုယ်တိုင်က ဘာလို့ ဘယ်သူမှ စကားမပြောတာဆိုတာ သိပ်မသိဘူး။

အများဆုံးအခြေအနေတွေမှာ တူညီသူတစ်ယောက်ကို မှတ်ပုံတင်မပေးချင်ရင် ဒါဟာ ဗစ်တိုးရီးယားအမှားတစ်ခုကြောင့် လုပ်ချင်တာပါ။ ဒီတူညီသူကို "ပဉ္စလက်"လုပ်ရုံနဲ့ ကွန်ရက်က မကောင်းဆိုးဝါး သရုပ်ဆောင်ရဲ့ ဘဝကို ပိုခက်ခဲစေပါတယ်။
