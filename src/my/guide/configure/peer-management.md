# Network Peer Management {#peer-management}

သင်ဟာ ဘာသာစကားဆိုင်ရာ လမ်းညွှန်ချက်တစ်ခုခုကို လိုက်နာခဲ့ရင် လူတွေဟာ လက်တွဲချင်တဲ့ ကောင်းမွန်စွာ အလုပ်လုပ်နေတဲ့ ကွန်ရက်တစ်ခု ရှိလာပါပြီ။

## အများပြည်သူ Blockchain {#public-blockchain}

ပွင့်လင်းသောကွန်ရက်တွင်, ကွန်ရက် peer admit သည်ဆက်သွယ်ရေးမူဝါဒ ဆုံးဖြတ်ချက်တစ်ခုဖြစ်သည်။ node တစ်ခုသည်မှန်ကန်သောဆော့ဖ်ဝဲကို run လုပ်နိုင်ပြီး Torii သို့ ချိတ်ဆက်နိုင်သော်လည်းကွန်ရက်က ၎င်း၏ကွန်ရက် peer identity ကိုလက်ခံပြီးနောက်မှသာ သဘောတူညီမှုထဲ ပါဝင်သည်။

## ပုဂ္ဂလိက Blockchain {#private-blockchain}

ငွေကြေးဘဏ်များတွင် လူတိုင်း မိမိတို့အလိုအလျောက် ပါဝင်ခွင့်ပြုခြင်းသည် လုံခြုံရေးဆိုင်ရာ အန္တရာယ်တစ်ခုဖြစ်သည်။ လုံခြုံမှုအတွက်၊ ပုဂ္ဂလိက Iroha ဖြန့်ဖြူးမှုများသည် အများအားဖြင့် ဖွင့်လှစ်သော ရှာဖွေမှုအပေါ် မှီခိုခြင်းအစား ကွန်ရက် peer topology ကို ဖွဲ့စည်းပုံနှင့် blockchain ဖြစ်စဉ်တွင် ပိတ်ပင်ထားသည်။

### ကွန်ရက်တူညီသူများကို မှတ်ပုံတင်ခြင်း {#registering-peers}

Network peer တစ်ခုကို ကွန်ရက်ထဲ ထည့်သွင်းရန်အတွက် ၎င်းကို လက်နဲ့ မှတ်ပုံတင်ထားဖို့လိုပါတယ်။ ဒီလုပ်ငန်းစဉ်ကို ပြီးစီးဖို့ ဆောင်ရွက်သင့်တဲ့ အဆင့်တွေကို ဆွေးနွေးရအောင်။

#### (၁) သုံးစွဲသူကို ခွင့်ပြုချက်များ ပေးပါ။ {#_1-grant-the-user-permissions}

ကွန်ရက် peer ကို မှတ်ပုံတင်တဲ့ အကောင့်မှာ သင့်တော်တဲ့ `Permission` ရှိဖို့လိုပါတယ်။ ဒါက `Role` ဖြင့် (သို့) တိုက်ရိုက် ခွင့်ပြုချက်အထောက်အပံ့အဖြစ်ပေးနိုင်ပါတယ်။

အကောင့်တစ်ခုက Network Peers ကို အချိန်ကြာမြင့်စွာ စီမံခန့်ခွဲတဲ့အခါ Role ပေးပါ။ အခြားနည်းနဲ့ Network Peers တွေကို မစီမံခန့်ခွဲတဲ့ အကောင့်တစ်ခုကနေ တစ်ကြိမ်တည်း မှတ်ပုံတင်ဖို့ တိုက်ရိုက် ခွင့်ပြုချက်ပေးတာကို အသုံးပြုပါ။

::: info

default executor က `CanManagePeers` permission token ကို network peers တွေကို မှတ်ပုံတင်ဖို့နဲ့ မမှတ်ပုံတင်ဖို့ သုံးပါတယ်။

:::

[သီးခြားအခန်း](/my/blockchain/permissions.md) တွင် ခွင့်ပြုချက်များနှင့် အခန်းကဏ္ဍများကို အသေးစိတ် ဆွေးနွေးကြပါသည်။

#### (၂) အွန်လိုင်းတူညီသူကို တည်ဆောက်ခြင်း {#_2-set-up-a-peer}

Network peer အသစ်တစ်ခုအတွက် ခွင့်ပြုချက်ပေးပြီးနောက် ၎င်းကို setup လုပ်ရပါမယ်။

node ကို admit မလုပ်ခင် လက်ရှိ network peer configuration ကို request လုပ်ပါ။ Torii သည် node parameter နဲ့ capability API endpoint တွေကို expose လုပ်ပေးပါတယ်။ network peer bootstrap က ဒီတန်ဖိုးတွေကို အလိုအလျောက် ညှိနှိုင်းမပေးဘူး၊ operator တွေက timeouts၊ batch size နဲ့ အခြား သဘောတူညီချက်နဲ့ သက်ဆိုင်တဲ့ settings တွေဟာ ကွန်ရက်နဲ့ ကိုက်ညီတယ်ဆိုတာကို စစ်ဆေးဖို့လိုပါတယ်။

ဒီလုပ်ငန်းစဉ်ကို ရိုးစင်းအောင် လုပ်ဖို့အတွက် ကွန်ရက် အုပ်ချုပ်ရေးမှူးထံ `config.toml` ရဲ့ ပြင်ဆင်ထားတဲ့ ဗားရှင်းကို တောင်းဆိုနိုင်ပါတယ်၊ အဲဒီဗားရှင်းမှာ ကွန်ရက် အချင်းချင်း ပုဂ္ဂလိက ခလုတ်တွေလို အခွင့်ထူးခံ အချက်အလက်တွေကို ပယ်ချထားတယ်။

#### (၃) ညွှန်ကြားချက်ကို တင်ပြပါ။ {#_3-submit-the-instruction}

Network peer ကို run လုပ်ပြီးနောက် Register peer instruction ကို တင်သင့်ပါတယ်။ network peer က လက်ဆွဲခြင်း လုပ်ငန်းစဉ်ကို ဖြတ်သန်းပြီး ကွန်ရက်နဲ့ စကားပြောစတော့မယ်။

::: tip

Network peer မှတ်ပုံတင် ညွှန်ကြားချက်ကို တင်သွင်းခြင်းဟာ network peer ဖြစ်စဉ်သစ်ကို မဖြစ်ပေါ်စေ (သို့မဟုတ်) မဖြစ်စေနိုင်ပါ။

:::

### မှတ်ပုံတင်ခြင်းမရှိသော ကွန်ရက် အဖော်များ {#unregistering-peers}

Network peer တွေကို မှတ်ပုံတင်မထားဘူးဆိုရင်ရော။ လုံခြုံရေးအကြောင်းအရ ဒီလုပ်ငန်းစဉ်က တစ်ဘက်တည်းပါ။ network က network peer ကို ဖယ်ရှားချင်တယ်လို့ သဘောတူညီမှုရတယ်၊ ဒါပေမဲ့ network peer ကိုယ်တိုင်က ဘာလို့ ဘယ်သူမှ စကားမပြောတာလဲဆိုတာ အများကြီးမသိဘူး။

မကြာခဏဆိုသလို Network Peer ကို မှတ်ပုံတင်မပေးချင်ရင် Byzantine အမှားတစ်ခုကြောင့် လုပ်ချင်တာပါ။ ဒီအွန်လိုင်း peer ကို "ပဉ္စလက်" ပေးရုံနဲ့ Network မှာရှိတဲ့ မကောင်းဆိုးဝါး ဇာတ်ကောင်ရဲ့ ဘဝကို ပိုခက်ခဲစေပါတယ်။
