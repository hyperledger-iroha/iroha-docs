# တန်းတူညီမျှမှု စီမံခန့်ခွဲခြင်း {#peer-management}

သင်ဟာ ဘာသာစကားဆိုင်ရာ လမ်းညွှန်ချက်တစ်ခုခုကို လိုက်နာခဲ့ရင်
ကောင်းမွန်စွာ လုပ်ဆောင်နေတဲ့ ကွန်ရက်တစ်ခုမှာ လူတွေက ပါဝင်ချင်ကြမှာပါ။

## အများပြည်သူ Blockchain {#public-blockchain}

ပွင့်လင်းတဲ့ ကွန်ရက်တစ်ခုမှာ peer admission ဟာ အစဉ်လိုက် မူဝါဒ ဆုံးဖြတ်ချက် တစ်ခုပဲ
မှန်ကန်တဲ့ ဆော့ဝဲကို run လုပ်ပြီး Torii, ဒါပေမဲ့ ပါဝင်တာပဲ
ကွန်ရက်က ၎င်းရဲ့ တူညီတဲ့ ကိုယ်ပိုင်လက္ခဏာကို အသိအမှတ်ပြုပြီးနောက် သဘောတူညီမှုတစ်ခုမှာပါ။

## ပုဂ္ဂလိက Blockchain {#private-blockchain}

ဘဏ်တစ်ခုမှာ လူတိုင်းကို သူတို့လိုချင်တဲ့ အချိန်မှာ ပါဝင်ခွင့်ပြုတာက လုံခြုံမှုပါ။
လုံခြုံရေးအတွက် ပုဂ္ဂလိက Iroha deployments များသောအားဖြင့် peer topology ကို pin
ဖွင့်လှစ်ထားတဲ့ ရှာဖွေတွေ့ရှိမှုအပေါ် မှီခိုမယ့်အစား ဖွဲ့စည်းပုံနဲ့ ဇာတိဖြစ်စဉ်ပါ။

### တူညီသူများကို မှတ်ပုံတင်ခြင်း {#registering-peers}

ကွန်ရက်မှာ peer ကို ထည့်ဖို့ လက်နဲ့ မှတ်ပုံတင်ဖို့လိုတယ်။
ဒီလုပ်ငန်းစဉ်ကို ပြီးစီးဖို့ ဆောင်ရွက်သင့်တဲ့ အဆင့်တွေ။

#### (၁) သုံးစွဲသူကို ခွင့်ပြုချက်ပေးပါ {#_1-grant-the-user-permissions}

စာရင်းမှာ သင့်တော်တဲ့စာရင်းတွေရှိဖို့လိုတယ် `Permission`.
ဤအချက်ကို `Role` (သို့) တိုက်ရိုက် ခွင့်ပြုချက်ပေးခြင်းပါ။

အခန်းကဏ္ဍတစ်ခု ပေးအပ်ဖို့ လိုအပ်လားဆိုတာ ဘယ်လို ဆုံးဖြတ်ရမလဲ။
အသုံးပြုသူဟာ အုပ်ချုပ်ရေးမှူးအဖြစ် တာဝန်ယူရမယ်
ကွန်ယက်အတွင်းက တူညီသူများကို ရေရှည် ထိန်းသိမ်းရန် တာဝန်ရှိသည်။
ခွင့်ပြုချက်ပေးခြင်းဟာ အဖော်ကို မှတ်ပုံတင်တဲ့ ဖက်က မရှိတဲ့အခါ အသုံးဝင်ပါတယ်။
အထက်ပါအချက်အလက်များနှင့် ပတ်သက်၍
အဖော်သစ်တစ်ခု ဖန်တီးဖို့ အချိန်ကုန်ဆုံးဖို့ မလိုပါဘူး။

::: info

Default executor က `CanManagePeers` ခွင့်ပြုချက် လက်မှတ်
မှတ်ပုံတင်ခြင်းနှင့် မမှတ်ပုံတင်ခြင်း။

:::

We ခွင့်ပြုချက်များနှင့် အခန်းကဏ္ဍများကို အသေးစိတ် ဆွေးနွေးပါ
[သီးခြားအခန်း](/my/blockchain/permissions.md).

#### (၂) တူညီသူကို ဖွဲ့စည်းပေးပါ။ {#_2-set-up-a-peer}

အဖော်သစ်ကို ခွင့်ပြုချက်ပေးပြီးနောက် ဒါကို တည်ထောင်ဖို့လိုပါတယ်။

node ကို admit မလုပ်ခင် လက်ရှိ peer configuration ကို request လုပ်ပါ။ Torii ထုတ်ပြန်ချက်များ
ဤရည်ရွယ်ချက်အတွက် node parameter နှင့် capability endpoints များ။ Peer bootstrap သည်
ဒီတန်ဖိုးတွေကို အလိုအလျောက် ညှိနှိုင်းမလုပ်ပါနဲ့။ လုပ်ငန်းရှင်တွေက အချိန်ကုန်ဆုံးမှုကို စစ်ဆေးဖို့လိုတယ်။
အစုအဝေးအရွယ်အစားနဲ့ သဘောတူညီချက်နဲ့ဆိုင်တဲ့ အခြား settings တွေက ကွန်ရက်နဲ့ ကိုက်ညီတယ်။

လုပ်ငန်းစဉ်ကို ရိုးစင်းစေရန်အတွက် ကွန်ရက် အုပ်ချုပ်ရေးမှူးထံ
ပြင်ဆင်ထားသော စာမျက်နှာများ `config.toml`, အခွင့်ထူးခံ သတင်းအချက်အလက်တွေကို ပယ်ချထားတာပါ။
ဥပမာ ပုဂ္ဂလိက သော့တွေပေါ့။

#### (၃) ညွှန်ကြားချက်ကို တင်ပြပါ {#_3-submit-the-instruction}

_နောက်ပိုင်း_ သင့်အဖော်က ပြေးနေတယ်၊ သင် submit လုပ်သင့်တယ်။ _မှတ်ပုံတင်သူ_
အတန်းတူက လက်ဆွဲခြင်း လုပ်ငန်းစဉ်ကို ဖြတ်သန်းပြီး စမယ်။
ကွန်ရက်နဲ့ စကားပြောနေတာပါ။

::: tip

အထက်ပါအချက်အလက်များနှင့် ပတ်သက်၍ စာရင်းသွင်းခြင်း **မလုပ်ဘူး** (အဲဒါလည်း မဖြစ်နိုင်ဘူး)
instantiate a _အချိုးအစားသစ်များ_.

:::

### မှတ်ပုံတင်ခြင်းမရှိသော အဖော်များ {#unregistering-peers}

မှတ်ပုံတင်ခြင်းမရှိတဲ့ တူညီသူတွေကိုရော။ လုံခြုံရေးအကြောင်းပြချက်တွေနဲ့ ဒီလုပ်ငန်းစဉ်က
တစ်ဘက်တည်းပါ။ ကွန်ရက်က တူညီတဲ့ သဘောတူညီချက်ကို ရောက်ရှိလာတယ်၊ ၎င်းဟာ တူညီသူကို ဖယ်ရှားချင်တယ်။
ဒါပေမဲ့ သူ့အဖော်က သူနဲ့ ဘယ်သူမှ စကားမပြောတဲ့ အကြောင်းကို သိပ်မသိဘူး။

အခြေအနေအများစုမှာ သင့်အဖော်တစ်ယောက်ကို မှတ်ပုံတင်မှ ဖယ်ရှားချင်တယ်ဆိုရင်
ဘာလို ့လဲဆိုေတာ့ ဒါက Byzantine အျပစ္ျဖစ္တာပဲ
ကွန်ရက်ထဲက မကောင်းဆိုးဝါးတဲ့ သရုပ်ဆောင်ကို ပိုပြင်းထန်တယ်။
