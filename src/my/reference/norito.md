# Norito {#norito}

Norito ရှိသည် Iroha Canonical serialization layer ကိုသုံးတဲ့ byte format ပါ။
တူညီတဲ့လူတွေရှိတဲ့အခါမှာ SDKs, CLI ကိရိယာများ၊ Torii, Kura, ပြီးတော့ ထုတ်လုပ်ထားတဲ့ လက်ရာတွေဟာ သဘောတူဖို့လိုပါတယ်။
အလားတူ အသုံးဝင်တဲ့ ဝန်ဆောင်မှုမှာပါ။

အသုံးပြုခြင်း Norito အချက်အလက်တွေဟာ သဘောတူညီချက်၊ လက်မှတ်ရေးထိုးမှု၊ ဟက်ရှ်လုပ်ခြင်း၊ ငြိမ်သက်မှု အစိတ်အပိုင်းဖြစ်တဲ့အခါ
ဒါမှမဟုတ် cross-SDK အပြန်အလှန်ဆက်သွယ်နိုင်မှု JSON အပြီးသတ်မှတ်ချက်တစ်ခုက ရှင်းလင်းစွာ ကမ်းလှမ်းတဲ့အခါ
operator များ၊ dashboard များအတွက် လူသားဖတ်နိုင်တဲ့ projection သို့မဟုတ် မြန်မြန် debugging ကို။

| --- | --- |
| ငွေပေးချေမှုနှင့် မေးမြန်းမှုများ | လက်မှတ်ရေးထိုးထားသော ငွေကြေးပူးပေါင်းဆောင်ရွက်မှုနှင့် မေးမြန်းချက်များ Torii ကိုဒ်သွင်းထားသည်မှာ Norito. |

| Kura သိုလှောင်ခြင်း | Block payloads, recovery sidecars, rosters နဲ့ commit markers တွေကို Norito- ဖွဲ့စည်းထားတဲ့ ဒေတာ။ |

| Streaming | Norito Streaming အသုံးပြုမှု Norito မော်နီဖစ်များ၊ အပိုင်းခေါင်းစဉ်များ၊ ထိန်းချုပ်ရေး ဘောင်များနှင့် လိုက်နာမှု ကိရိယာများ။ |

Norito ဒါဟာ စမတ်ကုထုံးဘာသာစကားမဟုတ်ဘူး။ ဒါက အချိုးသတ်မှုအဖုံးနဲ့
စာချုပ်ခေါ်ဆိုမှုတွေ၊ လက်မှတ်ရေးထိုးချက်တွေနဲ့ ရိုက်နှိပ်ထားတဲ့ codec API
အသုံးဝင်တဲ့ ဝန်ဆောင်မှုတွေပါ။

## အသုံးဝင် ဝန်ဆောင်မှု ပုံစံ {#payload-model}

ကြိုးနဲ့ ဒစ်ကက်တိုင်း Norito အသုံးအဆောင် ဝန်ထုပ်ကို ခေါင်းစဉ်တစ်ခုနဲ့ ဖွဲ့စည်းထားပြီး နောက်မှာ
ကုဒ်သွင်းထားသော အသုံးဝင်ဝန်ဆောင်မှု bytes များ။ ခေါင်းစီးမဲ့ (သို့) ပိတ်ထားတဲ့ အသုံးဝင် ဝန်ဆောင်မှုများသည် အတွင်းပိုင်းအတွက် သီးသန့်သတ်မှတ်ထားသည်။
hashing, benchmarks နဲ့ အကူအညီပေးသူ APIs ရလဒ်ကို ချက်ချင်း
ပို့ဆောင်မှုမတိုင်ခင် ခေါင်းစဉ်။

| ခေါင်းစဉ် ကွင်း | အရွယ်အစား | ရည်ရွယ်ချက် |
| --- | ---: | --- |
| မှော်ဆန်မှု | ၄ ဘိုက် | ASCII `NRT0`, မသုံးဘဲ ပယ်ချဖို့ သုံးတယ်။Norito ဒေတာကို အစောကြီးပါ။ |
| ဗိုလ်မှူးကြီး | 1 byte | အဓိကဗားရှင်းကို Format လုပ်ပါ။ လက်ရှိ အသုံးဝင်ဝန်ဆောင်မှုများကို အသုံးပြုခြင်း `0`. |
| အသေးစား | 1 byte | Fixed v1 ကို decode ညွှန်ပြချက်။ လက်ရှိအကျိုးဆောင်ဝန်ပိုးများအသုံးပြု `0x00`; စီမံကိန်း ရွေးချယ်မှုတွေဟာ အလံတွေထဲမှာ သက်ရှိပါ။ |
| အစီအစဉ် hash | ၁၆ ဘိုက် | မမျှော်လင့်တဲ့ အသုံးဝင် ဝန်ဆောင်မှုတွေကို ပယ်ချဖို့ ရိုက်နှိပ်ထားတဲ့ decoders တွေက အသုံးပြုတဲ့ Type Identity ပါ။ |
| ဖိအားပေးခြင်း | 1 byte | `0 = None`, `1 = Zstd`. မသိတဲ့ တန်ဖိုးတွေကို ပယ်ချတယ်။ |
| အသုံးဝင် ဝန်ဆောင်မှု အလျား | ၈ ဘိုက် | သေးငယ်တဲ့ အန်ဒီယန်းအဖြစ် ဖိမထားတဲ့ အသုံးဝင် ဝန်ဆောင်မှုအလျား `u64`. |
| CRC64 | ၈ ဘိုက် | CRC64-XZ မညှစ်မထားတဲ့ အသုံးဝင် ဝန်ဆောင်မှုအတွက် စစ်ဆေးချက်အရေအတွက်ပါ။ |
| အလံများ | 1 byte | ရှည်လျားမှု အချိုးအစားများ၊ ထုပ်ပိုးထားတဲ့ အစဉ်များနှင့် ထုပ်ပိုးထားသော ရောင်စဉ်များအတွက် စီစဉ်ချက် အလံများ။ |

ခေါင်းစဉ်က ဘိုက် (၄၀) ပါ။ decoders တွေက မှော်ဆန်မှု၊ ဗားရှင်း၊ ထောက်ပံ့တဲ့ အလံကို အတည်ပြုတယ်။
Mask, အသုံးဝင်မှုအလျား, checksum, schema hash ကိုပြန်လည်တည်ဆောက်ခြင်းမတိုင်မီ
ရိုက်နှိပ်ထားတဲ့ တန်ဖိုး။

## အလှဆင်မှု အလံများ {#layout-flags}

Norito နောက်ဆုံး header byte မှာ layout ရွေးချယ်မှုကို သိမ်းထားတယ်။
emit `COMPACT_LEN` (`0x02`) အတွက် အချိုးအစားတိုင်းအလျား prefixes များအတွက်။
fixed-width length prefixes တွေကို ဖုန်းခေါ်ဆိုသူတွေက code လုပ်တဲ့အခါ ဖတ်လို့ရတယ်။
`flags = 0x00`.

| အလံ | ဟက်စ် | အခြေအနေ | သက်ရောက်မှု |
| --- | ---: | --- | --- |
| `PACKED_SEQ` | `0x01` | ထောက်ပံ့မှု | အပြောင်းအလဲ အရွယ်အစား ကော်လီကေးရှင်းတွေကို Offset Table နဲ့ ဆက်စပ်တဲ့ Data Block တစ်ခုနဲ့ ကုဒ်ပေးပါတယ်။ |
| `COMPACT_LEN` | `0x02` | အလိုအလျောက် | တန်ဖိုးအလိုက် အရှည် prefix များအတွက် Canonical unsigned varints ကိုအသုံးပြုသည်။ |
| `PACKED_STRUCT` | `0x04` | ထောက်ပံ့မှု | ကော်ဒေးရှင်းများမှ ထုတ်ယူသော structs များကို packed field payloads အဖြစ် encodes လုပ်ပါ။ |
| `VARINT_OFFSETS` | `0x08` | ကန့်သတ်ထားသည် | v1 မှာ ပယ်ချထားတယ်၊ packaged sequence offsets တွေဟာ fixed width ပါ။ `u64`. |
| `COMPACT_SEQ_LEN` | `0x10` | ကန့်သတ်ထားသည် | v1 မှာ ပယ်ချခံရတယ်၊ အထက်တန်းအဆင့် အစဉ်အမြစ်အလျား ခေါင်းစဉ်တွေဟာ စံကျတဲ့ ကျယ်ပြန့်မှုပါ။ `u64`. |
| `FIELD_BITSET` | `0x20` | လိုအပ်ချက်များဖြင့် ထောက်ပံ့ | အပြည့်အစုံသော struck များအတွက် bitset ကိုထည့်သည်. ထို့ကြောင့် explicit size များလိုအပ်သည့် field များသာ size prefixes များကိုပါရှိသည်။ `PACKED_STRUCT` နှင့် `COMPACT_LEN`. |

အလံတွေက ရှင်းလင်းပါတယ်။ Decoders တွေက အသုံးဝင်တဲ့ ဝန်ဆောင်မှုပုံစံကနေ layout ကို မဆုံးဖြတ်ဘူး။
မော်ဒယ် (သို့မဟုတ်) heuristics များ။ မသိသော (သို့) မတည်ငြိမ်တဲ့ ပေါင်းစပ်မှုများကို ပယ်ချခြင်း
အဖော်အားလုံးဟာ အသုံးဝင်တဲ့ ဝန်ထုပ်ကို တူညီစွာ အဓိပ္ပါယ်ဖွင့်တာပါ။

## ကုဒ်ရေးစည်းမျဉ်းများ {#encoding-rules}

Norito အသုံးပြုသည် deterministic layouts များအတွက်ပုံမှန်ဒေတာပုံစံများ
ကော်မတီ Iroha ဒေတာပုံစံ:

- ကြိုးတွေက `[len][utf8-bytes]`; `len` အောက်ပါအတိုင်း `COMPACT_LEN` လုပ်နိုင်တဲ့အခါမှာပေါ့။
- တန်ဖိုးတစ်ခုချင်းအလျားမှာ အချိုးမညီတဲ့ varints တွေကို သုံးပါတယ်။ `COMPACT_LEN` သတ်မှတ်ထားတယ်
  fixed 8-byte little-endian ကို `u64`.
- အစဉ်အမြင့် ခေါင်းစဉ်များသည် fixed 8-byte အနည်းငယ်-endian `u64` v1 မှာပါ။
- `Vec<u8>` ကိုဒ်သွင်းထားသည်မှာ `[len_u64][raw-bytes]` ဘိုက်တစ်ဘက် တစ်လုံးအစား
- Packaged sequences အသုံးပြုခြင်း `(len + 1)` တချိန်တည်း `u64` ကန့်သတ်ချက်
  ချိတ်ဆက်ထားသော ပစ္စည်းများအတွက် အသုံးဝင်ပစ္စည်းများ။
- မြေပုံများတွင် fixed ဖြင့် entry counts ကို encode လုပ်ထားသည် `u64` ပြီးတော့ deterministic key order ကို သုံးပါ။
  `HashMap` စာရွက်စာတမ်းတွေကို ကုဒ်မရေးခင် key နဲ့ sort လုပ်ပေးရပါမယ်။ `BTreeMap` ၎င်း၏
  သဘာဝ စနစ်ပါ။
- `BigInt` အသေးစား Endian နှစ်ခုအပြည့်အဝ bytes ကိုအသုံးပြုသည် `u32` byte အရှည်
  ၅၁၂-bit cap ကိုပါ သုံးပါ။
- `Numeric` ကိုဒ်သွင်းထားသည်မှာ `(mantissa, scale)`, mantissa က သိုလှောင်တဲ့
  integer value နဲ့ scale တွေဟာ fractional digits တွေရဲ့ အရေအတွက်ကို သိမ်းထားတယ်။

ဒီစည်းမျဉ်းတွေဟာ လက်မှတ်တွေနဲ့ hash တွေအတွက် အရေးပါပါတယ်။ SDKs ဒါတွေ အတူတူပဲ ဆောက်လုပ်ကြတယ်
logical transaction ကတော့ Canonical byte တွေကိုပဲ ထုတ်ပေးရပါမယ်။

## အစီအစဉ် Hashes များ {#schema-hashes}

အမျိုးအစား Norito payloads တွေမှာ 16 byte schema hash ကို ခေါင်းစဉ်ထဲမှာ ထည့်ထားတယ်။
hash ကို အပြည့်အဝ ကျွမ်းကျင်တဲ့ အမျိုးအစားအမည်ကနေ ရတာပါ။
Structural schema hashing ဟာ hash ကို Canonical schema ကနေ ရယူတာပါ။

Typed decoders တွေက schematic incompatibilities ကို ပယ်ချပါတယ်။ ဒါက client တွေကို မတော်တဆ
valid ကို decoding လုပ်ပါ Norito frame က မှားယွင်းတဲ့ပုံစံဖြစ်ပြီး ပုံမှန် ပျက်ကွက်မှု mode ဖြစ်ပါတယ်
တစ်ကြိမ်မှာ SDK Fixure bundle က node data model ကနေ drift လုပ်တယ်။

## ဖိနှိပ်ခြင်းနှင့် အရှိန်မြှင့်ခြင်း {#compression-and-acceleration}

Norito logical ကိုမပြောင်းလဲဘဲ explicit နဲ့ adaptive compression ကိုထောက်ပံ့ပါတယ်။
အသုံးဝင်မှု -

| ကဏ္ဍ | ရည်ရွယ်ချက် |
| --- | --- |
| `to_bytes` | ခေါင်းစဉ်ဖောင်ဒေးရှင်းနဲ့ မညှိနှိုင်းထားတဲ့ အသုံးဝင် ဝန်ဆောင်မှုကို ကုဒ်သွင်းပါ။ |
| `to_compressed_bytes` | Zstd နဲ့ encode လုပ်ပြီး header မှာ compression tag ကို မှတ်တမ်းတင်ပါ။ |
| `to_bytes_auto` | compression လုပ်တာ တန်ဖိုးရှိလားဆိုတာ ဆုံးဖြတ်ဖို့ deterministic heuristics ကို သုံးပါ။ |
| CRC64 အရှိန်မြှင့်ခြင်း | သယ်ယူပို့ဆောင်ရေး အသုံးပြုမှု CRC64-XZ နေရာတိုင်းမှာ CLMUL x86 မှာ_၆၄ သို့မဟုတ် PMULL aarch64 မှာရှိရင် |
| GPU CRC64 compression နဲ့ | ရွေးချယ်စရာ Metal သို့မဟုတ် CUDA အကူအညီပေးသူတွေဟာ ကြီးမားတဲ့ အသုံးဝင် ဝန်ဆောင်မှုတွေကို အရှိန်မြှင့်နိုင်ပြီး CPU လမ်းကြောင်းတွေပေါ့။ |

Hardware အရှိန်မြှင့်မှုဟာ decoded content ကို ဘယ်တော့မှ မပြောင်းလဲပါဘူး။ CRC နှင့် JSON
အရှိန်မြှင့်ကိရိယာများသည် portable output bit-for-bit ကိုက်ညီစေရန်လိုအပ်သည်။ Zstd frame bytes သည်
ကွဲပြားမှု CPU နှင့် GPU encoders များ၊ ဒါပေမဲ့ decoded payload နဲ့ Norito ခေါင်းစဉ်
metadata တွေဟာ validation အတွက် deterministic ဖြစ်နေဆဲပါ။

## JSON ထောက်ပံ့မှု {#json-support}

Norito ဒေသခံတစ်ဦး ပါဝင်သည် JSON လိုအပ်တဲ့ အဆုံးအဖြတ်နေရာများနှင့် ကိရိယာများအတွက် stack JSON
မထွက်ဘဲ Norito အမျိုးအစားစနစ်။

| JSON လက္ခဏာ | အသုံးပြုမှု ကိစ္စ |
| --- | --- |
| `norito::json::{to_json, from_json}` | သတ်မှတ်ရေး ပုံစံ JSON code/decode လုပ်ပါ။ |
| လှပပြီး စာရေးဆရာရဲ့ အကူအညီတွေ | CLI ထုတ်ကုန်၊ ကိရိယာများနှင့် စီးဆင်းမှု `std::io` ပေါင်းစည်းခြင်း။ |
| DOM တန်ဖိုးများ | Programmatic Manipulation ကို Norito ဒါက JSON တန်ဖိုးပုံစံ။ |
| အမြန်ရိုက်ခြင်း JSON | အပူချိန်အတွက် တည်ဆောက်မှုအခွံအခြေခံ decode/encode DTO လမ်းကြောင်းတွေပေါ့။ |
| သုညစာရွက်ဖတ်စက် | သွင်းချက်မှ ကြိုးများကို ချေးယူနိုင်သည့် အမှတ်တံဆိပ် စကင်လုပ်ခြင်း |
| အဆင့် (၁) အရှိန်မြှင့်စက်များ | ရွေးချယ်စရာ AVX2, NEON, သံမဏိ သို့မဟုတ် CUDA scalar fallback နဲ့ တည်ဆောက်မှု အညွှန်းကိန်းတင်ခြင်း |

Iroha code ကို prefer လုပ်သင့်ပါတယ်။ `norito::json` အထောက်အပံ့ပစ္စည်းများ API အသုံးဝင်ပစ္စည်းများ။
ပွင့်လင်း `serde_json` စီမံကိန်းနှင့် ကွဲပြားသော အန္တရာယ်များ
ကွင်းဆင်းလုပ်ကိုင်မှုဆိုင်ရာ မျှော်လင့်ချက်များ SDKs နှင့် Torii ထုတ်ယူသူ။

## ထုတ်ကုန်ထောက်ပံ့မှု {#derive-support}

Rust ဒေတာအမျိုးအစားများမှာ လက်လုပ် codec ကိုဒ်အစား derive macros များကို အသုံးပြုလေ့ရှိသည်။
Derive layer က generate လုပ်နိုင်တယ် Norito ဘိုင်နရီ codecs များ၊ schema များနှင့် JSON အကူအညီပေးသူတွေပါ။

Common field attributes တွေက

| အရည်အသွေး | သက်ရောက်မှု |
| --- | --- |
| `#[norito(rename = "other")]` | Schema အတွက် Stable serialized နာမည်ကို အသုံးပြုပြီး JSON ကိုက်ညီမှု။ |
| `#[norito(skip)]` | ကွင်းကို ပိတ်လိုက်ပြီး ဖြည့်လိုက်တယ် `Default` ကုဒ်ချိုးနေတုန်းပါ။ |
| `#[norito(default)]` | အသုံးများ `Default` decoded payload တစ်ခုက ကွင်းကို မတင်တဲ့အခါ |
| `#[norito(skip_serializing_if = "...")]` | ကွင်းတွေကို ဖယ်ရှားလိုက်ပါတယ်။ JSON Predicate တွေနဲ့ ကိုက်ညီတဲ့အခါ Deterministic decoding ကနေ မမှားတာတွေကို ထိန်းသိမ်းရင်းပါ။ |

Derives တွေဟာ encoded length အညွှန်းတွေ နဲ့ exact length calculations ကိုလည်း ဖော်ပြပါတယ်။
ဒီအချက်ပြချက်တွေကို ကုဒ်ရေးသူတွေက ဘူဖာကို သိမ်းဆည်းဖို့ သုံးပြီး ပိုမိုကူးယူမှုကို ရှောင်ရှားဖို့ သုံးပါတယ်။

## ကတ်ပြားအမှတ်တံဆိပ် မိသားစုများ {#crate-feature-families}

ဆောက်လုပ်ရာတွင် Iroha ဒါမှမဟုတ် SDK အရင်းအမြစ်မှ ချည်နှောင်မှု Norito features ကို ရွေးချယ်ပါ။
အကူများနှင့် အရှိန်မြှင့်စက်များ ရှိပါသည်-

## Torii နှင့် Norito RPC {#torii-and-norito-rpc}

Torii ထုတ်လွှင့်ချက်များ JSON operator များစွာသောလမ်းကြောင်းများအတွက်, သို့သော်လည်း typeed binary လမ်းကြောင်းများအသုံးပြု
Norito. လက်ရှိ ရိုက်နှိပ်ထားသော မီဒီယာအမျိုးအစား Norito HTTP ကိုယ်ခန္ဓာများ
`application/x-norito`.

Endpoint တစ်ခုက လက်ခံလိုက်တဲ့အခါ (သို့) ပြန်ရိုက်တဲ့အခါ ဒီခေါင်းစဉ်တွေကို သုံးပါ။ Norito:

```http
Content-Type: application/x-norito
Accept: application/x-norito
```

အဆုံးသတ်မှတ်ချက်တစ်ခုက ကိုယ်စားပြုချက် နှစ်ခုစလုံးကို ထောက်ပံ့တဲ့အခါ ဖောက်သည်တွေက ရှင်းလင်းတဲ့
ကြိုက်နှစ်သက်မှု စာရင်း:

```http
Accept: application/x-norito, application/json
```

Decode ကျရှုံးမှုများကို ရိုက်ထည့်ထားသည်အတိုင်း ပေါ်လာပါသည် Torii အမှားတွေရှိပြီး တယ်လီမီထရီနဲ့ ရေတွက်တယ်။
မကြာခဏ ဖြစ်တတ်တဲ့ အကြောင်းရင်းတွေထဲမှာ မတည်ငြိမ်တဲ့ မှော်ပညာ၊ မထောက်ပံ့တဲ့ ဗားရှင်း၊ မထောက်ခံတဲ့ Feature တို့ ပါဝင်ပါတယ်။
အလံ၊ စစ်ဆေးမှုအရေအတွက် မညီဘူး၊ အမှားရှိ UTF-8, invalid enum tag နဲ့ schema ကွဲပြားမှု

Norito RPC သယ်ယူပို့ဆောင်ရေးကို သယ်ယူ ပို့ဆောင်ရေး ဖွဲ့စည်းချက်ဖြင့် ရွေးချယ်ထားပါသည်။
Dashboards တွေက request latency, failures, active connections တွေကို ခြေရာခံသင့်တယ်
တုံ့ပြန်မှု bytes နှင့် `torii_norito_decode_failures_total` ကွဲပြားစွာ JSON
ယာဉ်ကြော။

## Norito Streaming {#norito-streaming}

Norito Streaming က မီဒီယာနဲ့ အချိန်မှန်ကို တူညီတဲ့ သတ်မှတ်ချက် ချဉ်းကပ်မှုကို ဖြန့်ချိတယ်။
သယ်ယူပို့ဆောင်ရေး မျက်နှာပြင်များ။ ၎င်း၏ အဓိက အစိတ်အပိုင်းများသည်-

| Streaming feature ကို | ရည်ရွယ်ချက် |
| --- | --- |
| ကြေညာချက်များ | Segment commitments, privacy routes, capabilities, codec profile, encryption suite နဲ့ content key metadata တွေကို ကြေညာပါ။ |
| ကဏ္ဍခေါင်းစဉ်များ | Bind segment number၊ duration, chunk count, timing, entropy mode, audio summary နဲ့ Merkle root တွေကို ချိတ်ဆက်ပါ။ |
| အစိတ်အပိုင်းပိုင်းဆိုင်ရာ ကတိပေးချက်များ | ကြည့်ရှုသူတွေနဲ့ relays တွေက ဝန်ဆောင်မှုအပိုပစ္စည်းတွေကို မန်နီဖစ်နဲ့ စစ်ဆေးပြီး ကောက်ယူမပေးခင် |
| ထိန်းချုပ်ရေးဖောင်များ | ကြေညာချက်တွေ၊ ပြန်ကြားချက်တွေ၊ အဓိက သတင်းအချက်အလက်တွေ နဲ့ စွမ်းဆောင်ရည် ညှိနှိုင်းမှုတွေ ဆောင်ရွက်ပါ။ |
| HPKE အဓိက update များ | ညှိနှိုင်းထားတဲ့ suite နဲ့ monotonously တိုးပွားနေတဲ့ counter တွေကို သုံးပြီး သယ်ယူပို့ဆောင်ရေး လျှို့ဝှက်ချက်တွေကို လှည့်ပါ။ |
| အရည်အချင်း ညှိနှိုင်းမှု | အားပေးသော feature bits များ၊ datagram ကန့်သတ်ချက်များ၊ feedback cadence နှင့် privacy လိုအပ်ချက်များကို ဖြတ်တောက်သည်။ |
| FEC အပြန်အလှန်တုံ့ပြန်မှု | ဆုံးရှုံးမှုအရှိန်လမ်းကြောင်းများအတွက် deterministic လက်ခံသူ အစီရင်ခံစာများနှင့် parity ဆုံးဖြတ်ချက်များကိုအသုံးပြုသည်။ |
| ညီညွတ်မှု vectors များ | ဘာသာစကားစုံ ကိရိယာတွေက သက်သေပြတယ် SDKs ဒီပရိုဂရမ်တွေ၊ အပိုင်းအစတွေနဲ့ entropy streams တွေကို ပြန်လည်ဖေါ်ထုတ်ဖို့ပါ။ |

Streaming အတွက် သီးသန့် codec တွေနဲ့ entropy profile တွေကို core ကနေ ခွဲခြားထားတယ်။
Norito Transaction/query format ကို အသုံးပြုနေဆဲ ဖြစ်သော်လည်း ၎င်းတို့၏ manifest များနှင့် control data တွေက
Norito ဒီတော့ လမ်းညွှန်ခြင်း၊ ငွေကြေးပေးသွင်းခြင်း၊ ပြန်လည်ဖြည့်သွင်းခြင်းနဲ့ စစ်ဆေးမှု အထောက်အထားတွေဟာ ထပ်တူဖြစ်နေဆဲပါ။

## လုပ်ငန်းဆိုင်ရာ လမ်းညွှန်ချက်များ {#operational-guidance}

- ကြိုက်တယ်။ SDK လက်နဲ့လုပ်ထားတဲ့ အချိုးအစားတွေထက် ဆောက်လုပ်ရေးပစ္စည်းတွေနဲ့ ထုတ်လုပ်တဲ့ ချည်နှောင်မှု Norito ဘိုင်တာများ။
- Schema ကွဲပြားမှုကို အပြောင်းအလဲတစ်ခုမဟုတ်ဘဲ ဗားရှင်း (သို့) ပြင်ဆင်မှု ပြဿနာအဖြစ် ကုသပါ။
  ကွန်ရက် ပျက်ကွက်မှု။
- ဆက်ထားပါ။ `.nrt`, `.norito`, လွတ်မြောက်ခြင်း (သို့) ဖြစ်စဉ်နှင့်အတူ ပြသသော လက်ရာများ
  ဒါတွေကို ထုတ်လုပ်ခဲ့တဲ့ ဘက်ဒယ်ပါ။
- အသုံးပြုခြင်း JSON ဒက်ရှ်ဘုတ်များနှင့် လက်လုပ်စစ်ဆေးမှုအတွက် ခန့်မှန်းချက်များကို ထိန်းထားပါ Norito အတိုင်း
  လက်မှတ်ထိုးထားတဲ့၊ hashed ဒါမှမဟုတ် persistent data တွေအတွက် အမှန်တရားရဲ့ အရင်းအမြစ်ပါ။
- စာလုံးသစ်ကို ရိုက်သွင်းတဲ့အခါ Torii အဆုံးသတ်မှတ်ချက်၊ လက်ခံမှု မှတ်တမ်း JSON,
  Norito, (သို့) နှစ်ခုစလုံး၊ ပြီးတော့ ထောက်ခံတဲ့ အကြောင်းအရာအမျိုးအစားတွေကို `/openapi`.
- အရှိန်မြှင့်ကိရိယာတွေကို ဖွင့်လိုက်တဲ့အခါ scalar output နဲ့ parity test တွေကို အရင်လုပ်ပါ။
  အရှိန်မြှင့်စက် ပျက်ကွက်မှုတွေဟာ ပြောင်းလဲတာအစား ရှင်းလင်းစွာ ပြန်ကျသင့်ပါတယ်။
  အသုံးဝင်တဲ့ ဝန်ဆောင်မှု အဓိပ္ပာယ်ကောက်ချက်။
