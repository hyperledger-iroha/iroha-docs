# နိုင်ငံခြား Function Interfaces (FFI) {#foreign-function-interfaces-ffi}

နိုင်ငံခြားရေး `iroha_ffi` crate က C ကို ထုတ်လုပ်ဖို့ မက်ကရိုတွေနဲ့ အရည်အသွေးတွေကို ပေးတယ်။ ABI
ကန့်သတ်ချက်များ Rust APIs. အသုံးပြုရာမှာ Iroha အမျိုးအစားတစ်ခုဖြတ်ဖို့လိုအပ်ပါတယ် FFI
နယ်နိမိတ်၊ ဥပမာ SDK ချည်နှောင်ခြင်း (သို့) အိမ်ရှင်ပေါင်းစပ်မှု

## ဘာကြောင့်လဲ FFI {#why-ffi}

လုပ်ဆောင်ချက်တစ်ခုဟာ အတော်လေး စိတ်ကူးယဉ်တဲ့ entity တစ်ခုဖြစ်ပြီး ဘာသာစကားအများစုက သဘောတူကြပေမဲ့
function တစ်ခုက ဘာလုပ်သင့်သလဲ၊ functions တွေကို ကိုယ်စားပြုပုံက
ဒါ့အပြင် ဘာသာစကားအချို့မှာ Rust, အကျိုးဆက်များ
အလုပ်တစ်ခုခေါ်ခြင်းနဲ့ လုပ်ခွင့်ပြုထားတဲ့ အရာတွေဟာလည်း
မတူပါဘူး။ Rust APIs အခြားဘာသာစကား (သို့)
မတူတဲ့ အိမ်ရှင် ပတ်ဝန်းကျင်၊ Iroha ပြင်ပ လုပ်ဆောင်ချက် ကြားခံ (FFI)
ကစားကွင်းကို တန်းတူဖို့ပါ။

ဒီနေ့သုံးနေတဲ့ အဓိကစံနှုန်းက C application binary interface ပါ။
ရိုးရှင်းပြီး အများသုံးပြီး တည်ငြိမ်ပါတယ်။ အခြေခံအားဖြင့်
အားလုံးကို လက်နဲ့လုပ်ပေးပေမဲ့ Iroha ကမ်းလှမ်းချက် `iroha_ffi` ထုတ်ပေးမယ့် သေတ္တာ
FFI- တည်ဆဲတစ်ခုမှ လိုက်နာသော လုပ်ဆောင်ချက်များ Rust API.

တကယ်တမ်းက ဒါကို သင့်နည်းနဲ့ လုပ်နိုင်တယ်။ `iroha_ffi` သေတ္တာကိုပဲ
ဒီ code ကေတာ့ ဘာလို႕မွ ေဖာ္ထုတ္ဖို႔ လိုအပ္တဲ့ code ကို ထုတ္လုပ္ေပးပါတယ္။
လိုအပ်တဲ့ ဘိုလီးယားပြားဟာ တော်တော်လေး ကြိုးစားမှုနဲ့ စည်းကမ်းကို တောင်းဆိုပါတယ်။
function တစ်ခုချင်းစီကို call လုပ်လိုက်ပါ FFI နယ်နိမိတ်က `unsafe` အလားအလာရှိပြီး
မရှင်းလင်းတဲ့ အပြုအမူကို ဖြစ်ပေါ်စေပါတယ်။ ဒါကို ဖြေရှင်းနိုင်ခဲ့တဲ့ နည်းလမ်းက
အသုံးပြုခြင်းဖြင့် လည်ပတ် **ခိုင်မာ** `repr(C)` အမျိုးအစားတွေပေါ့။

::: info

ခြွင်းချက်တစ်ခုတည်းက ညွှန်ပြသူတွေပါ။ null စစ်ဆေးခြင်းနဲ့ သက်တမ်းကို
တစ်ကမ္ဘာလုံးမှာ အကောင်အထည်ဖော်ထားလို့ အသားမပါတဲ့ ညွှန်ပြချက်တွေကို (အမြဲတမ်းလိုပဲ) ထူးခြားတဲ့ အခြေအနေတွေမှာသာ သုံးပါတယ်။
ကိစ္စရပ်တိုင်းနီးပါးကို ဖုံးအုပ်ပေးတာကြောင့်
object ကို Iroha ဒေတာပုံစံမှာ raw pointers တွေကို သုံးစရာမလိုပါဘူး။
အားလုံးပါ။

:::

## ဥပမာ {#example}

ဒီမှာ ချည်နှောင်မှုတစ်ခု ဖန်တီးခြင်းရဲ့ ဥပမာပါ။

```rust
#[derive(FfiType)]
struct DaysSinceEquinox(u32);

#[ffi_export]
impl DaysSinceEquinox {
    pub fn update_value(&mut self, a: &u8) {
        self.0 = *a as u32;
    }
}
```

အထက်ပါဥပမာက အောက်ဖော်ပြပါ ချိတ်ဆက်မှုကို ဖြစ်ပေါ်စေပါလိမ့်မယ်။
`DaysSinceEquinox` မရှင်းလင်းတဲ့ ညွှန်ပြစက်အဖြစ် ကိုယ်စားပြု:

```rust
pub extern fn DaysSinceEquinox__update_value(handle: *mut DaysSinceEquinox, a: *const u8) -> FfiReturn {
    // function implementation
}
```

## FFI ချိတ်ဆက်ပေးသော မျိုးဆက် {#ffi-binding-generation}

နိုင်ငံခြားရေး `iroha_ffi` crate ကို call လုပ်နိုင်တဲ့ function တွေကို generate လုပ်ဖို့ သုံးပါတယ်။
FFI. ပေးထားသည် `Rust` စီမံကိန်းများနှင့် နည်းစနစ်များဖြင့် `unsafe` code ကို
ဆက်သွယ်ရေး နယ်နိမိတ်ကို ဖြတ်ဖို့ လိုအပ်ပါလိမ့်မယ်။

A ကို Rust Type ကို ခိုင်မာတဲ့ `repr(C)` Type က cross လုပ်နိုင်တယ်
FFI နယ်စပ် `FfiType::into_ffi`. ဒါက နောက်တစ်ဖက်ကိုသွားပြီး
ကောင်းပြီ၊ FFI `ReprC` Type ကို convert လုပ်လိုက်တယ် `Rust` type via ကို
`FfiType::try_from_ffi`.

::: warning

ဆန့်ကျင်ဘက်ပြောင်းလဲမှုသည် မှားယွင်းနိုင်ပြီး မသတ်မှတ်နိုင်သော ဖြစ်စေနိုင်သည်ကို သတိပြုပါ။
အရှင်းဆုံးဖြစ်နေတာကို ရှောင်ရှားဖို့ အကောင်းဆုံးကြိုးစားနိုင်ပေမဲ့
အမှားတွေရှိရင် သင့်အဆုံးမှာ အစီအစဉ်ရဲ့ မှန်ကန်မှုကို သေချာအောင်လုပ်ဖို့လိုပါတယ်။

:::

The ချည်နှောင်မှုထုတ်လုပ်မှုကို ဖြစ်ပေါ်စေတဲ့ အဓိကလက္ခဏာတွေက `ReprC`, `FfiType`, နှင့်
`FfiConvert`.

| လက္ခဏာများ        | သရုပ်ဖော်ချက်                                                                                                                                                                     |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ReprC`      | ဒီလက္ခဏာက C ကိုက်ညီတဲ့ ခိုင်မာတဲ့ပုံစံကို ကိုယ်စားပြုတယ်။ ABI. Type ကို ဘေးကင်းစွာ မျှဝေနိုင်ပါတယ် FFI နယ်နိမိတ်တွေ။                                                                |
| `FfiType`    | ဒီလက္ခဏာက ကိုက်ညီတဲ့ `ReprC` သတ်မှတ်ချက်တစ်ခုအတွက် အမျိုးအစား `Rust` သတ်မှတ်ထားတဲ့အတိုင်း `ReprC` Type ကိုအစားထိုးပြီး `Rust` စာလုံးထဲထည့်ပါ API ထုတ်ကုန်များ FFI လုပ်ဆောင်ချက်။ |
| `FfiConvert` | ဒီလက္ခဏာက နည်းလမ်းနှစ်ခုကို သတ်မှတ်တယ်။ `into_ffi` နှင့် `try_from_ffi` အပြောင်းအလဲအတွက် အသုံးပြုတဲ့ `Rust` type to or from သို့ သို့မဟုတ်မှ `ReprC` အမျိုးအစားပါ။                                |

မှတ်ချက်ပြုပါ ပိုင်ဆိုင်မှု လွှဲပြောင်းခြင်းမရှိ FFI မထင်ရှားတဲ့ ညွှန်ပြစက်မှလွဲရင်
အခြားပိုင်ဆိုင်မှုရှိသည့် အမျိုးအစားအားလုံး၊ ဥပမာ `Vec<T>`, ခလုန်းလုပ်ထားတာပါ။

### နာမည် Mangling {#name-mangling}

မှတ်ချက်ပြုပါ double undercores ကိုအသုံးပြုခြင်း FFI ပစ္စည်းများ:

- နိုင်ငံတကာ `inherent_fn` အဆိုပါ နည်းလမ်းကို `StructName` Structural FFI
  နာမည်က `StructName__inherent_fn`.
- နိုင်ငံတကာ `MethodName` နည်းစနစ်မှ `TraitName` လက္ခဏာများ
  `StructName` Structural FFI နာမည်က
  `StructName__TraitName__MethodName`.
- စိစစ်ဖို့ `field_name` နယ်ပယ်တွင် `StructName` Structural FFI
  function နာမည်က `StructName__set_field_name`.
- ရယူဖို့ `field_name` နယ်ပယ်တွင် `StructName` Structural FFI
  function နာမည်က `StructName__field_name`.
- အပြောင်းအလဲဖြစ်နိုင်တဲ့ အရာကို ရယူဖို့ `field_name` နယ်ပယ်တွင် `StructName` Structural FFI
  function နာမည်က `StrucuName__field_name_mut`.
- လွတ်လပ်စွာ ရပ်တည်သူအတွက် `module_name::fn_name`, ကော်မတီ FFI နာမည်က
  `module_name::__fn_name`.
- ဗဟုသုတမရှိတဲ့ အရည်အသွေးတွေအတွက်
  အကောင်အထည်ဖော်ရေး FFI (ကြည့်ပါ) `Clone` အောက်ပါ) FFI နာမည်က
  `module_name::__clone`.

  ```rust
  impl Clone for Type1 {
      fn clone(&self) -> Self;
  }
  impl Clone for Type2 {
      fn clone(&self) -> Self;
  }
  ```
