# စမတ် ကွန်ထရက်များ {#smart-contracts}

Iroha ငွေလဲလှယ်မှု လုပ်ဆောင်ချက် `Executable` လက်ရှိ ဒေတာပုံစံ
ထောက်ပံ့ပေးသည်-

- `Executable::Instructions`: စနစ်တကျ ပြဌာန်းထားသော အစု Iroha အထူးညွှန်ကြားချက်များ
- `Executable::ContractCall`: တပ်ဆင်ထားသော စာချုပ်တစ်ခုအတွက် အပိုရည်ညွှန်းချက်ခေါ်ဆိုမှု
  ဥပမာ
- `Executable::Ivm`: Iroha VM bytecode
- `Executable::IvmProved`: Iroha VM ကြိုတင်တွက်ချက်ထားတဲ့ ညွှန်ကြားချက်ပါတဲ့ bytecode
  အချိုးအစားများနှင့် အထောက်အထားဆိုင်ရာ ကတိပေးချက်များ

Kotodama ရှိသည် Iroha အဆင့်မြင့် စမတ်ကုထုံး ဘာသာစကားပါ။ `.ko` အရင်းအမြစ်ဖိုင်
deterministic ကို compiles IVM ဘိုက်ကော့ဒ်၊ အစဉ်အလာအားဖြင့် `.to`
တပ်ဆင်ဖို့ လက်ရာပစ္စည်းပါ။ Kotodama ရည်မှန်းချက်များ IVM; ဒါက တစ်ကိုယ်တည်း မဖြစ်ဘူး။ RISC-V
ဒါမှမဟုတ် WebAssembly ရည်မှန်းချက်ပါ။

ပထမထုတ်ပြန်ချက်က ထောက်ပံ့မှုတစ်ခုတည်း ABI version 1. syscall နှင့် pointer ကိုABI
မူဝါဒကို သဘောတူစာချုပ်လက်ခံခြင်းနှင့် အကောင်အထည်ဖော်ခြင်းဖြင့် မပေးအပ်ဘဲ အပြီးသတ်ဆောင်ရွက်ရမည်။
Runtime ကို Compatibility လုပ်လို့မရဘူး။

## စမတ် စာချုပ်များကို ဘယ်အချိန် အသုံးပြုရမလဲ {#when-to-use-smart-contracts}

ရောင်းဝယ်မှုကို တိုက်ရိုက် ဖော်ပြနိုင်တဲ့အခါ ပုံမှန် ညွှန်ကြားချက်တွေကို သုံးပါ။

- မှတ်ပုံတင်ခြင်း (သို့) မှတ်ပုံတင်မပြုခြင်း
- မင်တာ၊ လောင်ကျွမ်းခြင်း သို့မဟုတ် လွှဲပြောင်းမှု အရင်းအမြစ်များ
- မီတာဒေတာကို update လုပ်ပါ။
- ခွင့်ပြုချက်များ ပေးအပ်ခြင်း သို့မဟုတ် ပယ်ဖျက်ခြင်း
- trigger ကို execute လုပ်ပါ
- ချိတ်ဆက်မှုအပေါ်မှာ parameters ကိုသတ်မှတ်

Transaction အတွက် packaged logic လိုတဲ့အခါ Smart Contract ကိုသုံးပါ။
static instruction sequence အဖြစ် ဖော်ပြဖို့ခက်ခဲတယ် ဒါမှမဟုတ် deployed
စာချုပ်အစီရင်ခံစာကို အကိုးအကားဖြင့် ခေါ်ယူသင့်ပါတယ်။

## IVM လုပ်ဆောင်ချက်များ {#ivm-executables}

`Executable::Ivm` အသားမပါဘဲ သယ်ယူထားပါတယ် IVM bytecode ကို node တွေက အဲဒီ byte code ကို အတွင်းမှာ execut
ကွင်းဆက်အတွက် သတ်မှတ်ထားတဲ့ Runtime Limit တွေကို
အတည်ပြုချက်အရ၊ စာချုပ်များသည် ငွေပေးချေမှု အကောင်အထည်ဖော်ခြင်း၏ အစိတ်အပိုင်းဖြစ်၍
သဘောတူညီချက်ပါ။

`Executable::IvmProved` အတည်ပြုမှု သယ်ဆောင်တဲ့ စီးဆင်းမှုတွေအတွက် ရည်ရွယ်ထားတာပါ။

- IVM bytecode
- deterministic instruction ကို overlay လုပ်ပေးခြင်း
- အကောင်အထည်ဖော်မှု-ဖြစ်ရပ်များဆိုင်ရာ ကတိပေးချက်
- ဓာတ်ငွေ့ မူဝါဒ ကတိပေးချက်

proof က overlay ကို executed bytecode နဲ့ ချိတ်ဆက်ပေးတယ်။ pipeline ကိုလိုက်ပြီး
မူဝါဒ, validators ကိုအထောက်အထားကိုစစ်ဆေးနိုင်ပြီးနောက်ထပ်ပြန်လည်ဖြန့်ဝေခြင်း
လုံခြုံရေး စစ်ဆေးပါ။

## အသုံးချထားသော စာချုပ်ခေါ်ဆိုချက်များ {#deployed-contract-calls}

`Executable::ContractCall` အမည်စာရင်းဖြင့် စေလွှတ်ထားသော စာချုပ်ဥပမာကို ခေါ်ယူသည်။
ဒီကုဒ်ကို Contract Code ကို သီးခြားမှတ်ပုံတင်တဲ့အခါ သုံးပြီး Transaction တွေက
ဘိုင်တာကုဒ်ကို တစ်ခါတစ်လေ သယ်ဆောင်မယ့်အစား အကိုးအကားနဲ့ခေါ်ပါ။

## လုပ်ငန်းဆိုင်ရာ လမ်းညွှန်ချက်များ {#operational-guidance}

- စာချုပ်ကို သတ်မှတ်ထားပါ။ စာချုပ်အပြုအမူက ဒေသတွင်း
  Wall-clock အချိန်၊ host ဖိုင်စနစ်အခြေအနေ၊ ကွန်ရက်ခေါ်ဆိုမှု သို့မဟုတ် အခြား peer-local
  input တွေ။
- အသုံးဝင်ဝန်ဆောင်မှုများကို ညှိထားပါ။ ဘိုင်တကုဒ်ကြီးသည် ငွေကြေးပူးပေါင်းခြင်း အရွယ်အစားနှင့် ဘလော့ကို တိုးမြှင့်ပေးသည်။
  မျိုးပွားမှု ကုန်ကျစရိတ်။
- လွယ်ကူသောစာအုပ်အပြောင်းအလဲများအတွက် ရိုက်နှိပ်ညွှန်ကြားချက်များကို ပိုနှစ်သက်သည်။
  စာရင်းစစ်ဆေးပြီး အကောင်အထည်ဖော်ဖို့ စျေးသက်သာတယ်။
- စာချုပ်တိုးတက်မှုနှင့် မှတ်ပုံတင်ခွင့်များကို အန္တရာယ်များသော သဘောထားအဖြစ် သတ်မှတ်ပါ။
  လုပ်ငန်းဆိုင်ရာ ထိန်းချုပ်မှု။
