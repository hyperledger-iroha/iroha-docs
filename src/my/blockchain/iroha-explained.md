# Iroha ရှင်းပြချက် {#iroha-explained}

Iroha 3 ပထမဆုံး ထုတ်ဝေမှုပါ။ Hyperledger Iroha တူညီတဲ့ ဗဟို
မိမိဘာသာ တည်းခိုထားသော ကွန်ရက်များကို ထောက်ပံ့ပေးသည်။ SORA Nexus အချက်အလက်များအတွက် စီမံခန့်ခွဲမှု ပုံစံ
နေရာများနှင့် လိုင်းစုံ လမ်းညွှန်ခြင်း။

## အခြေခံ အဆောက်အအုံများ {#core-building-blocks}

- **`irohad`** တူညီသူများကို ပြေးဆွဲနေသည်
- **Torii** client နဲ့ operator gateway ဖြစ်တယ်
- **Sumeragi** သဘောတူညီချက် ကိုင်တွယ်
- **Norito** အဲဒါက [ကနောနိက ဘိုင်နရီ ဖိုရမ်](/my/reference/norito.md)
- **IVM** Portable smart contracts နဲ့ bytecode တွေကို run လုပ်တယ်။
- **Kotodama** အဆင့်မြင့် ထုတ်ပြန်ချက် `.ko` စာချုပ်များ IVM `.to` bytecode
- **Kagami** သော့၊ ဇာစ်မြစ်၊ ပရိုဖိုင်များနှင့် ဒေသတွင်းကွန်ရက်များကို ပြင်ဆင်ပေးသည်။
- **SORA Nexus ဝန်ဆောင်မှု လေယာဉ်များ** ပေါင်းထည့် Soracloud, Inrou၊ SoraNet, SoraFS, နှင့်
  SoraDNS app hosting, privacy transport, storage နဲ့ naming အတွက်

## စီမံခန့်ခွဲမှုပုံစံ {#execution-model}

ကမ္ဘာ့အခြေအနေမှာ ပြောင်းလဲမှုတိုင်းဟာ ငွေကြေးဆိုင်ရာ ငွေချေးမှုကနေ ဖြစ်ပေါ်နေဆဲပါ။
ငွေလဲလှယ်မှုမှာ ညွှန်ကြားချက်တွေ ပါတယ် ဒါမှမဟုတ် IVM byte code နဲ့ Torii ဒါက အဓိကနည်းလမ်းပါ။
ဖောက်သည်တွေက တင်ပြတာ (သို့) အကျိုးဆက်တွေကို စောင့်ကြည့်တာပါ။

- Nexus- သတိထားမိတဲ့ ဖွဲ့စည်းပုံတွေက လမ်းကြောင်းများစွာကို သတ်မှတ်နိုင်တယ်။
- Data spaces တွေဟာ workload တွေကို သီးခြားခွဲထားပြီး တစ်ကိုယ်တော် ledger model ရဲ့ အစိတ်အပိုင်းအဖြစ် ဆက်ရှိနေတုန်းပါ။
- Routing policy က ဘယ် lane နဲ့ data space တွေကို အလုပ်အကိုင် အမျိုးအစားတစ်ခု ကိုင်တွယ်ဖို့ ဆုံးဖြတ်ပေးတယ်

## Multi-Data Space ဗိသုကာ {#multi-dataspace-architecture}

ဒေတာနေရာက လမ်းညွှန်ရေးနဲ့ နာမည်နေရာ နယ်စပ်တစ်ခုပါ၊ သီးခြား blockchain မဟုတ်ပါ။
Runtime မှာ တစ်ခုရှိသေးတယ် `World`, ငွေပေးချေမှုပုံစံတစ်ခုနဲ့ သဘောတူညီချက် တစ်ခု
ဘိုက်လိုင်း။ Nexus node ကို partition လုပ်နည်းကို ပြောပြတဲ့ catalogs တွေကို ထည့်ပေးတယ်။
အဝေးပြေးလမ်းကြောင်းတွေကို ဖြတ်ပြီး ဒီလမ်းကြောင်းတွေက အသုံးပြုတဲ့ ဒေတာနေရာတွေကို ဘယ်လိုအမည်ပေးရမလဲဆိုတာပါ။

Runtime မှာ data space ကို numeric နဲ့ ကိုယ်စားပြုပါတယ်။ `DataSpaceId` နှင့်
စာရင်းအင်း metadata ကို။ `DataSpaceId::UNIVERSAL` ကန့်သတ်ချက် `0`; ကြွင်းချက်
စာရင်းထဲမှာ `universal` ဒေတာအကွာအဝေးတိုင်းမှာ:

- ထူးခြားတဲ့ ကိန်းဂဏန်း ID
- ထူးခြားတဲ့ အမည်မဖော်လို `universal`, `governance`, ဒါမှမဟုတ် `zk`
- အော်ပရေတာ မျက်နှာပြင်များအတွက် ရွေးချယ်စရာ သရုပ်ဖော်ချက်
- သုညမဟုတ်သော `fault_tolerance` Relay Committee တွေကို တိုင်းတာဖို့ အသုံးပြုတဲ့ တန်ဖိုး

Lines တွေဟာ ဒီဒေတာဘေ့စ်တွေနဲ့ ချိတ်ဆက်ထားတဲ့ စီမံခန့်ခွဲမှုနဲ့ သိုလှောင်ရေး လမ်းကြောင်းတွေပါ။
လမ်းကြောင်းဝင်ပေါက်မှာ A ပါတယ် `LaneId`, ကော်မတီ `DataSpaceId` အမည်မဖော်လိုသူပါ။
မြင်နိုင်မှု (`public` ဒါမှမဟုတ် `restricted`), သိုလှောင်ရေးပုံစံ (`full_replica`,
`commitment_only`, ဒါမှမဟုတ် `split_replica`), အထောက်အထားစနစ်နဲ့ ရွေးချယ်စရာ
စီမံခန့်ခွဲမှု, settlement နှင့် scheduler metadata များ။ runtime က
ဒီစာရင်းထဲက လမ်းကြောင်းတစ်ခုစီအတွက် သိုလှောင်ခြင်း ဂျီသြမေထရီ၊ Kura အပိုင်းအခြားနာမည်များ
ပြီးတော့ deterministic key prefixes တွေပေါ့။

လမ်းညွှန်လမ်းကြောင်းက-

1. Configuration သည် validated ကို တည်ဆောက်သည် `DataSpaceCatalog`, `LaneCatalog`, နှင့်
   `LaneRoutingPolicy`. လမ်းကြောင်းများစွာ၊ ဒေတာနေရာများစွာ (သို့) အလိုအလျောက်မဟုတ်သော
   လမ်းညွှန်ပေးရန် လိုအပ်သည် `nexus.enabled = true`.
2. Transaction queue က Active Lane Router ကို
   `RoutingDecision` လမ်းကြောင်းတစ်ခုပါဝင်သောလမ်း ID ဒေတာနေရာ ID.
3. လမ်းညွှန်ရေး စည်းမျဉ်းတွေကို ခွင့်ပြုချက်/စာရင်း သို့မဟုတ် ညွှန်ကြားချက်အရ လိုက်ဖက်အောင် လုပ်နိုင်ပါတယ်။
   label. ကိုက်ညီတဲ့စည်းမျဉ်းမရှိဘဲ router က data space ကို
   နယ်ပယ် IDs, asset definition projections, data space scope permissions တွေကို အသုံးပြုပြီး
   Settlement legs (သို့) အာဏာပိုင်ရဲ့ ချုပ်ဆိုထားတဲ့ အကောင့်အကွာအဝေး
4. ပြေလည်တဲ့ လမ်းကြောင်းကို နှစ်ခုစလုံးရဲ့ စာရင်းနဲ့ စစ်ဆေးတယ်။ မသိတဲ့လမ်းကြောင်းတွေ၊
   မသိတဲ့ ဒေတာဇုန်များနှင့် lane/dataspace ကွဲပြားမှုတွေဟာ deterministic
   Routing Error များ။ ငွေပေးချေမှုတစ်ခုက မတူညီတဲ့ ဒေတာနေရာနှစ်ခုကို ရေးနေပါက
   ရည်မှန်းချက်များ၊ ပဋိပက္ခဖြစ်နေတဲ့ လမ်းကြောင်းအဖြစ် ငြင်းပယ်ခံရတယ်၊ Cross-data space DVP/PVP
   Settlement ကို Universal Coordinator Lane မှတစ်ဆင့် လမ်းညွှန်ပေးသည်။
5. Sumeragi ပြီးတော့ telemetry ကတော့ assignment ကို lane နဲ့ data space အဖြစ် မြင်နိုင်အောင် လုပ်ပေးတယ်။
   လှုပ်ရှားမှုတွေ၊ နောက်ကျနေတဲ့ပုံတွေနဲ့ ရည်စူးချက်တွေရဲ့ အရှိန်အဟုန်ကို ရိုက်ယူပါတယ်။

ဒါေၾကာင့္ Object Identifiers က အေရးႀကီးပါတယ္။ Domain ေတြမွာ Data Space alias ပါ၀င္တယ္။
သူတို့မှာ ID, ဥပမာ `payments.universal`, ဒီတော့ domain-scale ရေးသားနိုင်တယ်
Account တွေဟာ Canonical နဲ့ Domainless ဖြစ်နေတော့
၎င်းကို ပြောင်းလဲခြင်းမရှိဘဲ မတူညီသော အသုံးချမှု နယ်ပယ်များသို့ ချိတ်ဆက်နိုင်သည်
`AccountId`. Asset Definitions တွေမှာ Domain/Data Space Projection ကို ထည့်သွင်းနိုင်ပါတယ်။
ဒါက အရင်းအမြစ်လုပ်ငန်းတွေကို မှန်ကန်တဲ့ ဒေတာနေရာ လမ်းကြောင်းကို အမွေခံရခွင့်ပေးတယ်။

မပါဘဲ Nexus overrides, node က single lane ကိုသုံးပြီး `universal`
ဒေတာအကွာအဝေး။ SORA Profile က ဒါကို သုံးလမ်းကြောင်းနဲ့ အစားထိုးတယ်။
စာရင်းအင်း `core` ပြည်သူ့လမ်းကြောင်းအတွက်၊ `governance` အုပ်ချုပ်ရေးအတွက်
ယာဉ်ကြော၊ `zk` သုည အသိပညာကို ချုပ်ကိုင်ခြင်းနှင့် စာချုပ်ချိတ်ဆက်ခြင်းအတွက်
ယာဉ်ကြော။

ဒီသုံးခုက အလုပ်အကိုင် ဝန်ပိမှု အမျိုးအစားတွေကို ခွဲခြားဖို့ အလိုလျောက်ရှိပါတယ်

| ဒေတာနေရာ    | Lane ကို         | ဘာကြောင့် ရှိတာလဲ။                                                                                                                                       |
| ------------ | ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| `universal`  | `core`       | Default data space ကို ကန့်သတ်ထားသည် (`DataSpaceId::UNIVERSAL == 0`) သာမန် အများသုံးစာအုပ်များအတွက် လမ်းကြောင်းနှင့် ပြန်လည်လမ်းညွှန်ခြင်း။                                 |
| `governance` | `governance` | အုပ်ချုပ်ရေးနဲ့ လွှတ်တော် ယာဉ်ကြောအတွက် ကန့်သတ်ထားတဲ့ လမ်းကြောင်း၊ ဒီတော့ ထိန်းချုပ်မှု လေဆိပ် လှုပ်ရှားမှုကို ယေဘုယျ အသုံးချ ရေးသားချက်တွေနဲ့ ရောမနှောပါဘူး။                      |
| `zk`         | `zk`         | သုညသိမှု သက်သေခံချက်များ၊ ချိတ်ဆက်ချက်များနှင့် စာချုပ် ဖြန့်ချိရေး လမ်းညွှန်ချက်များအတွက် ကန့်သတ်ထားသောလမ်းကြောင်း၊ သက်သေခံမှုအလေးချိန်ရှိတဲ့ အလုပ်ခွင်များကို ပုံမှန်စာသားများမှ ခွဲခြားထားသည်။ |

တစ်ကိုယ်တော်ပဲ `universal` ကန့်သတ်ထားတဲ့ မူလတန်းပါ။ `governance` နှင့် `zk` ရှိသည် SORA
ဘူးပေါင်းထားတဲ့ စာရင်းနဲ့ လမ်းညွှန်ရေး မူဝါဒမှာ ကုဒ်သွင်းထားတဲ့ ကိုယ်စားလှယ်လက္ခဏာ ရွေးချယ်မှုတွေ၊
operator တွေဟာ မတူတဲ့ data space လိုတဲ့အခါမှာ ကွဲပြားတဲ့ catalog ကို သတ်မှတ်နိုင်ပါတယ်
နယ်နိမိတ်တွေ။

Sumeragi အမြဲတမ်း ဒေတာရရှိနိုင်မှုနဲ့ ယုံကြည်မှုရှိတဲ့ ထုတ်လွှင့်မှုကို သုံးပါတယ်။
အစိတ်အပိုင်း Iroha 3 သဘောတူညီချက် ပရိုတိုကောနဲ့ deployment ကနေပိတ်လို့မရဘူး။
ကိုယ်စားလှယ်လောင်း

Runtime အပြုအမူကို configuration ဖိုင်များနှင့် on-chain parameters များမှရရှိသည်။
ပတ်ဝန်းကျင်ဆိုင်ရာ ကိန်းရှင်တွေဟာ ထုတ်လုပ်ရေး လက္ခဏာ တံခါးတွေ မဟုတ်ဘူး။
