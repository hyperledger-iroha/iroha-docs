# Iroha ရှင်းပြချက် {#iroha-explained}

Iroha 3 သည်ပထမဦးဆုံးထုတ်ဝေသော Hyperledger Iroha ပလက်ဖောင်းဖြစ်သည်။ အလားတူဗဟိုသည် မိမိဘာသာ တည်းခိုထားသည့်ကွန်ရက်များနှင့် SORA Nexus ဒေတာနေရာများနှင့် multi-lane routing အတွက်လုပ်ဆောင်မှုပုံစံကိုထောက်ခံသည်။

## အခြေခံ အဆောက်အအုံများ {#core-building-blocks}

- `iroha3d` network peers ကို run လုပ်တယ်။
- Torii က client နဲ့ operator gateway ဖြစ်ပါတယ်
- Sumeragi က သဘောတူညီချက် ကိုင်တွယ်တယ်။
- Norito သည် [Single Protocol Standard ဘိုင်နရီပုံစံ](/my/reference/norito.md) ဖြစ်သည်။
- IVM ကို portable smart contracts နဲ့ byte code တွေကို run လုပ်ပေးတယ်။
- Kotodama သည် အဆင့်မြင့် `.ko` စာချုပ်များကို IVM `.to` ဘိုက်ကုဒ်သို့ စုစည်းသည်။
- Kagami ကီးတွေကို ပြင်ဆင်တယ်၊ ဘလော့ခ်ချ်ကို ဖန်တီးတယ်၊ ပရိုဖိုင်တွေ၊ ဒေသတွင်းကွန်ရက်တွေပေါ့။
- SORA Nexus ဝန်ဆောင်မှု လေယာဉ်ပေါင်း Soracloud, Inrou၊ SoraNet, SoraFS, နှင့် SoraDNS app hosting, privacy transport, storage နဲ့ name တွေအတွက်

## အကောင်အထည်ဖော်မှုပုံစံ {#execution-model}

ကမ္ဘာ့အခြေအနေ ပြောင်းလဲမှုတိုင်းဟာ ငွေကြေးလုပ်ငန်းများမှတဆင့် ဖြစ်ပေါ်နေဆဲပါ။ ငွေကြေး လုပ်ငန်းတွေမှာ ညွှန်ကြားချက် (သို့) IVM ဘိုင်တာကုဒ်ရှိပြီး Torii သည် ဖောက်သည်များက ၎င်းတို့ကို ပေးပို့ခြင်း သို့မဟုတ် ၎င်းတို့၏ သက်ရောက်မှုကို လေ့လာခြင်းအတွက် အဓိကနည်းလမ်းဖြစ်သည်။

- Nexus - အသိအမှတ်ပြုတဲ့ ဖွဲ့စည်းပုံတွေက multiple execution lanes တွေကို သတ်မှတ်နိုင်ပါတယ်။
- Data spaces တွေဟာ blockchain ledger မော်ဒယ်ရဲ့ တစ်စိတ်တစ်ပိုင်းဖြစ်နေရင်း အလုပ်အကိုင်တွေကို သီးသန့်ခြားထားတယ်။
- routing policy က ဘယ် execution lane နဲ့ data space တွေကို အလုပ်အကိုင် အမျိုးအစား ကိုင်တွယ်မလဲဆိုတာ ဆုံးဖြတ်ပေးပါတယ်။

## multi-data space ဗိသုကာ {#multi-dataspace-architecture}

Datapace ဆိုတာ Routing နဲ့ Namespace နယ်နိမိတ်တစ်ခုပါ၊ သီးခြား blockchain မဟုတ်ဘူး။ ဆော့ဖ်ဝဲ အကောင်အထည်ဖော်မှု ပတ်ဝန်းကျင်မှာ `World` တစ်ခုရှိတုန်းပဲ၊ ငွေကြေးဆိုင်ရာ ပုံစံတစ်ခု၊ Nexus က execution lanes တွေကြားက partition အလုပ်ကိုဘယ်လိုလုပ်ရမယ်ဆိုတာ node ကိုပြောပြတဲ့စာရင်းတွေထည့်ပေးပြီး executation lanes တွေမှာရှိတဲ့ ဒေတာဇုန်တွေကို ဘယ်လိုအမည်တပ်မလဲဆိုတာပါ။

ဆော့ဖ်ဝဲ အကောင်အထည်ဖော်မှု ပတ်ဝန်းကျင်တွင် ဒေတာနေရာကို ကိန်းဂဏန်း `DataSpaceId` နှင့် စာရင်းစာရင်း metadata ဖြင့် ကိုယ်စားပြုသည်။ `DataSpaceId::UNIVERSAL` ကို `0` အဖြစ်စုဆောင်းထားသည်; ကြိုတင်ညွှန်ကြားချက်စာရင်းမှာ `universal` ဒေတာနေရာ ပါဝင်သည်။ သတ်မှတ်ထားသော ဒေတာနေရာတိုင်းမှာ:

- ထူးခြားတဲ့ ကိန်းဂဏန်း ID
- `universal`, `governance` သို့မဟုတ် `zk` ကဲ့သို့သော ထူးခြားသော အမည်မဖော်လိုပါ။
- အော်ပရေတာမျက်နှာပြင်အတွက် ရွေးချယ်စရာ သရုပ်ဖော်ချက်
- ရေလွှမ်းမိုးရေးကော်မတီများအတွက် အသုံးပြုသော သုညမဟုတ်သည့် တန်ဖိုး `fault_tolerance`

အကောင်အထည်ဖော်မှုလမ်းကြောင်းများမှာ ထိုဒေတာနေရာများနှင့် ချိတ်ဆက်ထားသော အကောင်အ ထည်ဖော်ခြင်းနှင့် သိုလှောင်ရေး လမ်းကြောင်းများဖြစ်ပါသည်။ အကောင်အတန့်လမ်းကြောင်းဝင်ဆိုသည်မှာ `LaneId`, ၎င်းက ၀ င်ဆောင်သည့် `DataSpaceId`၊ အမည်မဖော်လိုသူ, မြင်နိုင်ရည် (`public` သို့မဟုတ် `restricted`), သိုလှောင်မှုပရိုဖိုင်း (`full_replica`, `commitment_only` သို့မဟုတ် `split_replica`) ၊ သက်သေပြစနစ်နှင့် ရွေးချယ်စရာ အုပ်ချုပ်မှုရှိသည်။ Kura segment နာမည်များနှင့် deterministic key prefixes တို့အပါအဝင် ဤစာရင်းမှ software စီမံခန့်ခွဲမှု ပတ်ဝန်းကျင်သည် လိုင်းတစ်ခုစီ သိုလှောင်ခြင်း ဂျီသြမေထရီကို ရယူသည်။

လမ်းညွှန်လမ်းကြောင်းက-

1. Configuration သည် validated `DataSpaceCatalog`, `LaneCatalog` နှင့် `LaneRoutingPolicy` ကိုတည်ဆောက်သည်။ multiple execution lanes, multiple data spaces သို့မဟုတ် non-default routing များအတွက် `nexus.enabled = true` လိုအပ်ပါသည်။
2. Transaction queue ကတော့ Active Execution Lane Router ကို execution lane ID နဲ့ data space ID ပါတဲ့ `RoutingDecision` တစ်ခုကို တောင်းဆိုပါတယ်။
3. ပွင့်လင်းမြင်သာသော လမ်းညွှန်စည်းမျဉ်းများသည် အာဏာ/အကောင့် သို့မဟုတ် ညွှန်ကြားချက် လက်မှတ်ဖြင့် ကိုက်ညီနိုင်သည်။ ကိုက်ညီသည့် စည်းမျဉ်းမရှိဘဲ Router သည်ဒိုမင် ID များ၊ အရင်းအမြစ်သတ်မှတ်မှု ခန့်မှန်းချက်များ၊ ဒေတာအကွာအဝေးအရ ခွင့်ပြုချက်များ၊ ဘဏ္ဍာရေးလွှဲပြောင်းမှု အစိတ်အပိုင်းများသို့မဟုတ် ခွင့်ပြုမှုဦးစီးဌာန၏ ချုပ်နှောင်ထားသော အကောင့်အဝန်းမှ ဒေတာနေရာကို ရယူနိုင်သည်။
4. ပြေလည်သောလမ်းကြောင်းကို catalog နှစ်ခုစလုံးနှင့် စစ်ဆေးသည်။ မသိသော အကောင်အထည်ဖော်မှု လမ်းကြောင်းများ၊မသိသော ဒေတာဇုန်များနှင့်လမ်းကြောင်း/ဒေတာဇုန် မညီမျှမှုများသည် deterministic routing error များဖြစ်သည်။ ငွေပေးချေမှုတစ်ခုက မတူညီတဲ့ ဒေတာနေရာ ရည်မှန်းချက် နှစ်ခုကို ရေးသားပါက ၎င်းကို ပဋိပက္ခဖြစ်နေတဲ့ လမ်းကြောင်းအဖြစ် ငြင်းပယ်ခြင်းခံထားရပြီး ဘဏ္ဍာရေးဆောင်ရွက်မှု အကုန်လုံး DVP/PVP ကို ကန့်သတ်ထားတဲ့ ဒေတာနေရာကနေ အကောင်အထည်ဖော်မှုလမ်းကြောင်းမှတစ်ဆင့် ညွှန်ကြားပေးသည်။
5. Sumeragi နှင့် telemetry တို့က လုပ်ဆောင်မှုလမ်းကြောင်းနှင့် ဒေတာနေရာ လှုပ်ရှားမှု၊ နောက်ဆုတ်ချက်များနှင့် cryptographic commitment value snapshots များအဖြစ် assignment ကို မြင်နိုင်အောင် ပြုလုပ်ပေးသည်။

ဒီအကြောင်းကြောင့် Object Identifiers တွေက အရေးပါပါတယ်။ Domain တွေဟာ သူတို့ရဲ့ ID မှာ Data Space alias ကို ထည့်သွင်းထားပါတယ် ဥပမာ `payments.universal` ဆိုတော့ domain-scoped writes တွေကို Routed လုပ်လို့ရပါတယ်။ Account တွေဟာ Single Protocol Standard နဲ့ Domainless ဖြစ်နေဆဲပါ။ `AccountId` အရင်းအမြစ်အဓိပ္ပါယ်ဖွင့်ဆိုချက်တွေဟာ ဒိုမင်/ဒေတာနေရာ စီမံကိန်းကို ဆောင်ရွက်နိုင်ပြီး အရင်းအမြစ်ကို လုပ်ဆောင်မှုတွေက မှန်ကန်တဲ့ ဒေတာနေရာ လမ်းကြောင်းကို အမွေရယူခွင့်ပေးပါတယ်။

Nexus ကို overrides မပါဘဲ node သည် single execution lane နှင့် `universal` dataspace ကိုအသုံးပြုသည်။ bundled SORA profile သည် ၃-lane catalog ဖြင့်အစားထိုးသည် - `core` အတွက် ပြည်သူလူထု အကောင်အထည်ဖော်ရေးလမ်းကြောင်း၊ `governance` အတွက် အုပ်ချုပ်မှု ယာဉ်မောင်းနှင်မှုအတွက်နှင့် `zk` အတွက် သုည အသိပညာ ချိတ်ဆက်ခြင်းနှင့် စာချုပ် ဖြန့်ချိမှု ယာဉ် မောင်းနှင်ရေးအတွက်။

အဲဒီသုံးခုဟာ အလုပ်အကိုင် ဝန်ဆောင်မှု အမျိုးအစားတွေကို ခွဲခြားဖို့ ကြံစည်ထားတာပါ။

|ဒေတာနေရာများ |အကောင်အထည်ဖော်မှုလမ်းကြောင်း |ဘာကြောင့် တည်ရှိတာလဲ။|
| ------------ | ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------- |
|`universal` |`core` |သာမန် အများသုံး blockchain ledger traffic နဲ့ fallback routing အတွက် ကြိုတင်ထိန်းသိမ်းထားသော default data space (`DataSpaceId::UNIVERSAL == 0`) ။ |
|`governance` |`governance` |အုပ်ချုပ်ရေးနှင့် လွှတ်တော် ယာဉ်ကြောအတွက် ကန့်သတ်ထားသော အကောင်အထည်ဖော်မှုလမ်းကြောင်း၊ ထို့ကြောင့် ထိန်းချုပ်မှုအဆင့် လှုပ်ရှားမှုကို ယေဘုယျ အသုံးချ ရေးသားချက်များနှင့် ရောနှောခြင်း မရှိပါ။ |
|`zk` |`zk` |သုည အသိသုတ သက်သေပြချက်များ၊ ချိတ်ဆက်ချက်များနှင့် စာချုပ် ဖြန့်ချိမှု လမ်းညွှန်ချက်များအတွက် ကန့်သတ်ထားသော အကောင်အထည်ဖော်ရေးလမ်းကြောင်း၊ အထောက်အထားပြင်းထန်တဲ့ အလုပ်ခွင်များကို ပုံမှန် ရေးသားခြင်းမှ ခွဲခြားထားသည်။ |

တစ်ခုတည်းသော `universal` ကန့်သတ်ထားတဲ့ မူလတန်းပါ။ `governance` နှင့် `zk` ရှိသည် SORA စုစည်းထားတဲ့ စာရင်းနဲ့ လမ်းညွှန်ရေး မူဝါဒမှာ ကုဒ်သွင်းထားတဲ့ ကိုယ်စားလှယ်လက္ခဏာ ရွေးချယ်မှုတွေ၊ Operator တွေဟာ မတူတဲ့ Data Space နယ်နိမိတ်တွေ လိုအပ်တဲ့အခါ ကွဲပြားတဲ့ Catalog ကို သတ်မှတ်နိုင်ပါတယ်။

Sumeragi သည် အမြဲတမ်း ဒေတာရရှိနိုင်မှုနှင့် ယုံကြည်စိတ်ချရတဲ့ ထုတ်လွှင့်မှုကို အသုံးပြုသည်။ ဤလမ်းကြောင်းများသည် Iroha 3 သဘောတူညီချက် ပရိုတိုကော၏ အစိတ်အပိုင်းဖြစ်ပြီး ဖြန့်ဖြူးရေးပရိုဖိုင်တစ်ခုမှ မပိတ်နိုင်ပါ။
