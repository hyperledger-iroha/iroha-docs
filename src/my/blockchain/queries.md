# မေးခွန်းများ {#queries}

blockchain ရဲ့အခြေအနေနဲ့ ပတ်သက်တဲ့ သတင်းအချက်အလက် အများအပြားဟာ
အရင်က ပြသခဲ့သလို ဖြစ်ရပ် subscriber နဲ့ filter ကိုသုံးပြီး ရယူထားတာပါ။
ဖြစ်ရပ်တွေရဲ့ ကျယ်ပြန့်မှုကို စိတ်ဝင်စားစရာတွေဆီ ချဉ်းကပ်ပါ။ တစ်ခါတစ်လေမှာ သင်လိုအပ်တာက
ပိုတိုက်ရိုက် ချဉ်းကပ်ပါ။ ဝင်လိုက်ပါ။ _မေးခွန်းများ_.

မေးမြန်းချက်တွေဟာ ညွှန်ကြားချက်လို အရာဝတ္ထုလေးတွေပါ၊ Iroha
တွဲဖက်တွေအနေနဲ့ လက်ရှိကမ္ဘာအခြေအနေအမြင်ကို အသေးစိတ်ဖော်ပြပြီး တုံ့ပြန်ဖို့ တိုက်တွန်းပါ။

ဒါကတော့ သတင်းအချက်အလက် တစ်ခုတည်းသာ ဖြစ်ဖို့မလိုပါဘူး။
ကွန်ယက်မှာရှိပေမဲ့ ဒါက သတင်းအချက်အလက် တစ်ခုတည်းပါ။ _အာမခံထားသည်_ သို့
ကွန်ရက်အားလုံးမှာ ရယူနိုင်ဖို့ပါ။

တပ်ဆင်မှုတစ်ခုစီအတွက် Iroha, အခြား သတင်းအချက်အလက်တွေလည်း ရှိနိုင်ပါတယ်။
ဥပမာ၊ တယ်လီမီထရီ ဒေတာရဲ့ ရယူနိုင်စွမ်းဟာ ကွန်ရက်ကို မှီခိုပါတယ်။
စီမံခန့်ခွဲသူတွေက သူတို့လုပ်ချင်မှလုပ်ချင် ဆုံးဖြတ်ချက်တစ်ခုလုံးပဲ
အလုပ်ကို ခြေရာခံဖို့ စီမံခန့်ခွဲမှု စွမ်းအင်ကို ခွဲခြားပေးပါ
တစ်ဖက်မှာတော့ အလုပ်အကိုင်တစ်ခုခု အမြဲတမ်း လိုအပ်နေပါတယ် ဥပမာ
သင့်အကောင့်ရဲ့ ငွေကြေးစာရင်းကို ဝင်ရောက်ခွင့်ရှိပါ။

မေးမြန်းချက်တွေရဲ့ ရလဒ်တွေက [အမျိုးအစား](#sorting), [စာမျက်နှာများ](#pagination)
နှင့် [စစ်ဆေးခြင်း](#filters) တစ်ချိန်တည်းမှာ တူညီတဲ့ အပိုင်းတစ်ခုစီပါ။
metadata key တွေကို lexicographically လုပ်နိုင်ပါတယ်။
မူဝါဒများ၊ ဒေသအလိုက် (ပုဂ္ဂိုလ်ချင်း) IP address filter mask များ) ကို
sub-string နည်းများ `begins_with` ယုတ္တိတန်တဲ့ လုပ်ဆောင်ချက်တွေကို သုံးပြီး ပေါင်းစပ်ထားတာပါ။

## ဒါကို စမ်းကြည့်ပါ။ Taira {#try-it-on-taira}

Taira Read Only query အကူအညီတွေကို ဖေါ်ပြပေးပါတယ်။ JSON တူညီတဲ့ အရင်းအမြစ်တွေအတွက် သုံးပါ။
ကဒ်သွင်းခြင်းမတိုင်မီ စာမျက်နှာပြုပြင်ခြင်းနှင့် တုံ့ပြန်မှု ကိုင်တွယ်မှုကိုလေ့ကျင့်ရန် SDK:

```bash
TAIRA_ROOT=https://taira.sora.org

curl -fsS "$TAIRA_ROOT/v1/accounts?limit=3" \
  | jq '{total, ids: [.items[].id]}'

curl -fsS "$TAIRA_ROOT/v1/domains?limit=3" \
  | jq '{total, domains: [.items[].id]}'

curl -fsS "$TAIRA_ROOT/v1/assets/definitions?limit=3" \
  | jq '{total, assets: [.items[] | {id, name, total_quantity}]}'
```

App ရောဂါရှာဖွေရေးအတွက် ဒီမီးခိုးစစ်ဆေးမှုကို လက်မှတ်ထိုးထားတဲ့ ငွေပေးချေမှုကနေ သီးခြားထားပါ။
စာဖတ်မှုသာ ရှိတဲ့ မေးမြန်းချက် ပျက်ကွက်မှုက အဆုံးသတ်မှတ်တိုင်ရဲ့ ရယူနိုင်မှုကို ညွှန်ပြလေ့ရှိပါတယ်။
ကွန်ရက်ရရှိနိုင်မှု (သို့) လက်မှတ်ရေးထိုးသူကို ညွှန်းမပေးခင် လမ်းကြောင်းလိုက်ဖက်မှု။

## မေးမြန်းမှု ဖန်တီးခြင်း {#create-a-query}

Typed query builders တွေကို အသုံးပြုပါ။ SDK ဒါမှမဟုတ် CLI. ဥပမာ၊ လက်ရှိ အချက်အလက်များ
မော်ဒယ်ထုတ်လွှင့်မှု `FindAccounts` စာရင်းတင်စာရင်းများအတွက်-

```rust
let query = FindAccounts;
```

ဒီမှာ Alice ရဲ့ အရင်းအမြစ်တွေကို ရှာဖွေတဲ့ မေးမြန်းမှုရဲ့ ဥပမာပါ။

```rust
let alice_id = load_canonical_account_id_from_client_config()?;
let query = FindAssetsByAccountId::new(alice_id);
```

## စာမျက်နှာများ {#pagination}

တစ်ပုဒ်တည်းမေးမြန်းချက်များနှင့် အသေးစား ထပ်မံမေးမြန်းနိုင်သော မေးခွန်းများအတွက် `client.request`
မေးမြန်းမှုတစ်ခုတင်ပြီး ရလဒ်ကို တစ်ချက်တည်းရဖို့ပါ။

ဒါပေမဲ့ ကျယ်ပြန့်တဲ့ အပြန်အလှန်မေးမြန်းနိုင်တဲ့ မေးခွန်းတွေ `FindAccounts`, `FindAssets`, ဒါမှမဟုတ်
`FindBlocks` Pageing ကိုသုံးပြီး load တွေကို လျှော့ချပေးပါ
တူညီသူနဲ့ ဖောက်သည်ပါ။

တည်ဆောက်ဖို့ `Pagination`, ဖုန်းဆက်ဖို့လိုတယ်
`client.request_with_pagination(query, pagination)`, ဘယ်နေရာက `pagination`
အောက်ပါအတိုင်း တည်ဆောက်ထားသည်-

```rust
let starting_result: u32 = _;
let limit: u32 = _;
let pagination = Pagination::new(Some(starting_result), Some(limit));
```

## စစ်ဆေးခြင်း {#filters}

မေးမြန်းချက်တစ်ခု ဖန်တီးတဲ့အခါ ရလဒ်တွေကိုသာ ပြန်ပို့ဖို့ စစ်ဆေးမှုကို သုံးနိုင်ပါတယ်။
သတ်မှတ်ထားတဲ့ filter နဲ့ ကိုက်ညီပါတယ်။

Filter တွေဟာ query specific ဖြစ်ပါတယ် ဥပမာ Account queries တွေကို
အကောင့်အမည် (သို့) metadata များ၊ အရင်းအမြစ်ဆိုင်ရာ မေးမြန်းချက်များကို အရင်းအမြတ်ဖြင့် ကျုံ့စေနိုင်သည်။
Definition, holder account (သို့) domain projection ကိုသုံးပါ။ SDK' s ရိုက်ထည့်မေးမြန်းချက်
ဖြစ်နိုင်ခြေရှိတိုင်း filter type ကို query output type နဲ့ လိုက်ဖက်အောင် build လုပ်ပေးပါ။

## အမျိုးအစားခွဲခြင်း {#sorting}

Iroha အပိုဒ်များကို [metadata များ](/my/blockchain/metadata.md)
lexicographically သင်တည်ဆောက်မှုအတွင်းမှာ sort လုပ်ဖို့ key ကိုပေးရင်
ပုံမှန် အသုံးပြုမှု ကိစ္စတစ်ခုက အကောင့်တွေမှာ `registered-on`
metadata entry ကို sort လုပ်ပြီးရင် account ကို ကြည့်လို့ရအောင်လုပ်ပေးတယ်
မှတ်ပုံတင် သမိုင်း။

အမျိုးအစားခွဲခြားမှုသည်
[metadata များ](/my/blockchain/metadata.md), metadata key ကို အသုံးပြုပြီး
မေးမြန်းချက် ရလဒ်တွေကို sort လုပ်ပါ။

Pageing နဲ့ Filters တွေကို ပေါင်းစပ်နိုင်ပါတယ်။
စာမျက်နှာပြုပြင်ခြင်းနဲ့ပတ်သက်တဲ့ မေးခွန်းအများစုမှာ မလိုပါဘူး။
