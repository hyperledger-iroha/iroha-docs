# ስምምነት {#consensus}

ግብይቶች Sumeragi በብሎክ ውስጥ ከማቅረቡ በፊት ወረፋ ውስጥ ይገባሉ። አረጋጋጮች በተናጥል ፕሮፖዛሉን ያረጋግጣሉ እና ያስፈጽማሉ፣ ከዚያም ሊባዙ የሚችሉትን የስቴት ሽግግር ብቻ ይፈርማሉ። የሚፈለገው የአረጋጋጭ ምልአተ ጉባኤ በዚያ ውጤት ላይ ከተስማማ እና ተዛማጅ ጭነት ከተገኘ በኋላ ብሎክ ይጠናቀቃል።

ሁሉም የ Iroha 3 አውታረ መረቦች የተፈረሙ RS16 የውሂብ ተገኝነት ቴክኒካል ማኒፌስቶችን እና ቁርጥራጮችን ከተረጋገጠ የውሂብ አካል ማገገሚያ ጋር ይጠቀማሉ። የውሂብ ተገኝነት የጋራ መግባባት መስፈርት እንጂ አማራጭ የማሰማራት ባህሪ አይደለም።

## Sumeragi {#sumeragi}

Sumeragi የ Iroha የባይዛንታይን-ስህተት-ታጋሽ የጋራ መግባባት ሞተር ነው። ግብይቶችን ከወረፋው ይወስዳል፣ አረጋጋጭ የአውታረ መረብ እኩዮች በተመሳሳይ ላይ ይስማማሉ የታዘዘ ብሎክ፣ እና ያንን ብሎክ የሚያጠናቅቀው በቂ አረጋጋጮች ተመሳሳይ ውጤት ካገኙ እና የጋራ መግባባት ማጠናቀቂያ ሰርተፍኬት ከፈረሙ በኋላ ብቻ ነው።

### ፕሮፖዛል እና የጋራ መግባባት የማጠናቀቂያ መንገድ {#proposal-and-commit-path}

Sumeragi መዝገቡን በአንድ ጊዜ አንድ የብሎክ ከፍታ ወደፊት ያራምዳል። በእያንዳንዱ ከፍታ ላይ አንድ አረጋጋጭ ለአሁኑ view አቅራቢ ይሆናል። አቅራቢው ብቁ ግብይቶችን ከወረፋው ያወጣል፣ እጩ ብሎክ ይገነባል፣ ለንቁ አረጋጋጮችም ሀሳቡን ያሳውቃል። ሥራ የሌላቸው ሰንሰለቶች ባዶ ብሎኮችን አያመነጩም።

ተመሳሳዩ የ Sumeragi የማስኬጃ ፍሰት በተፈቀዱ እና በተመረጡ የድርሻ ማረጋገጫ (NPoS) ማሰማራቶች ውስጥ ይጠቀማል፦

1. አረጋጋጭ ከተደረደሩ ግብይቶች ብሎክ ያቀርባል።
2. አረጋጋጮች በተመሳሳዩ የዓለም መንግስት ላይ ግብይቶችን በመፈጸም ሃሳቡን ያረጋግጣሉ።
3. አረጋጋጮች ለአሁኑ ቁመት እና እይታ ድምጾችን እና የጋራ ስምምነት ምልአተ ጉባኤ የምስክር ወረቀቶችን ይለዋወጣሉ።
4. የጋራ መግባባት ማጠናቀቂያ ምልአተ ጉባኤ ከደረሰ በኋላ የኔትወርክ እኩዮች ብሎኩን ያጠናቅቃሉ እና የአለም ሁኔታቸውን ያዘምኑ።

አረጋጋጮች በአገር ውስጥ ሊባዙ የሚችሉትን ውሂብ ብቻ ይፈርማሉ። ድምጽ ከመስጠቱ በፊት አረጋጋጭ ፕሮፖዛሉ የሚጠበቀው ሰንሰለት፣ ቁመት እና እይታ መሆኑን ያረጋግጣል። የግብይት ፊርማዎች እና ገደቦች የፕሮቶኮል ደንቦችን ያሟላሉ; የማስፈጸሚያ መስመር ማዘዋወር እና አስፈፃሚ ማረጋገጫ ዲተርሚኒስቲክ ናቸው; እና ጭነቱን ማስፈጸም የሚጠበቀውን የሁኔታ ሽግግር ያመጣል. የአካባቢው ውጤት ከተለያየ, አረጋጋጩ ለእሱ ድምጽ ከመስጠት ይልቅ ሃሳቡን ውድቅ ያደርጋል.

ድምጾች ትንሽ የተፈረሙ የጋራ ስምምነት መልዕክቶች ናቸው። የታቀደውን ብሎክ፣ ቁመቱን፣ እይታውን እና የማረጋገጫ ማንነትን ያመለክታሉ። የተረጋገጡ ፊርማዎች የጋራ መግባባት ዝግጅት እና የማጠናቀቂያ የምስክር ወረቀቶችን ይመሰርታሉ። የጋራ መግባባት የማጠናቀቂያ ሰርተፍኬት በቂ አረጋጋጮች ለተመሳሳይ ብሎክ ተመሳሳይ ውጤት እንዳስመዘገቡ ዘላቂ ማረጋገጫ ነው። እያንዳንዱ አረጋጋጭ የእሱን ይልካል ለሙሉ ኮሚቴው ድምጾችን ማዘጋጀት እና ማጠናቀቅ; ማንኛውም አረጋጋጭ የሚፈለገውን እኩል ድምጽ በማሰባሰብ የተገኘውን የምስክር ወረቀት ማሰራጨት ይችላል።

### ሸንጎ እና ታዛቢዎች {#quorum-and-observers}

የመጀመሪያው ልቀት ፕሮቶኮል ከ4 እስከ31 አረጋጋጮች ያሉትን፣ በትክክል `3f + 1` የሆነ የድምጽ ሰጪ ኮሚቴ ብቻ ይቀበላል። ስለዚህ ትክክለኛ ብዛቶች 4፣ 7፣ 10 እና በዚሁ ቅደም ተከተል እስከ31 ናቸው። ለ`n = 3f + 1`፣ የባይዛንታይን ጥፋት መቻቻል ገደብ `f` እና የcommit ምልዓተ ጉባኤ `2f + 1` ነው። የgenesis ማመንጨት እና የጅምር ማረጋገጥ ሌላ ማንኛውንም የኮሚቴ አወቃቀር ይከለክላሉ። እያንዳንዱ PrepareQC፣ CommitQC እና TimeoutCert በትክክል `q = n - f` እኩል የአረጋጋጭ ድምጾችን ይይዛል፤ ከዚህ በላይ ፈራሚዎች ያሉባቸው ስብስቦች ይከለከላሉ።

የታዛቢዎች አውታረመረብ እኩዮች የተጠናቀቁ ብሎኮችን ማመሳሰል ይችላሉ፣ ነገር ግን ወደ የጋራ መግባባት ማጠናቀቂያ ምልአተ ጉባኤ ሀሳብ አያቀርቡም፣ አይመርጡም ወይም አይቆጠሩም። ማሰማራት የአካባቢ መጠይቅ አቅም፣ መረጃ ጠቋሚ ወይም ክትትል ሲፈልግ ታዛቢዎችን ይጠቀሙ። ወይም የድምጽ መስጫ አረጋጋጮችን ቁጥር ሳይጨምሩ የክልል ብሎክ ማባዛት።

### ለውጦችን እና መልሶ ማግኛዎችን ይመልከቱ {#view-changes-and-recovery}

እይታ Sumeragi አንድ ነጠላ ቁመትን በተወሰነ ፕሮፖዛል እና የጊዜ እቅድ ለማጠናቀቅ የሚያደርገው ሙከራ ነው። ፕሮፖዛል፣ ጭነት፣ ድምጽ ወይም የጋራ መግባባት ማጠናቀቂያ ሂደት ከቆመ፣ የጋራ መግባባት የልብ ምት መቆጣጠሪያው ቁመቱን ወደ ኋለኛው እይታ ሊያንቀሳቅሰው ይችላል። የእይታ ለውጥ የተጠናቀቀውን ብሎክ እንደገና አይጽፍም። የኔትወርክ እኩዮች እርስ በርስ የሚጋጩ ብሎኮችን እንዳያጠናቅቁ አረጋጋጮች ገና ያልተጠናቀቀውን ቁመት ለማጠናቀቅ እንዴት እንደሚሞክሩ ይለውጣል።

ጭነት መልሶ ማግኛ ከመጨረሻው ውሳኔ የተለየ ነው። የአውታረ መረብ አቻ ሙሉ የብሎክ ጭነት ከማግኘቱ በፊት ምልአተ ጉባኤ ወይም የጋራ መግባባት ማጠናቀቂያ ሰርተፍኬት ሊቀበል ይችላል። እንደዚያ ከሆነ፣ የኔትወርክ አቻ ጥያቄዎች የተፈረሙ RS16 የጭነት ቁርጥራጮች ወይም የተረጋገጠ አካል፣ የተመለሱትን ባይቶች ከማስታወቂያው ምስጠራ ሃሽ ጋር ያረጋግጣል፣ እና ከዚያ በኋላ ብቻ ብሎኩን በአለም ሁኔታ እና Kura ላይ ይተገበራል።

### የጋራ መግባባት ሁነታዎች {#consensus-modes}

የተመረጠው ሁነታ የአረጋጋጮች ስብስብ እንዴት እንደሚፈጠር እና እንደሚሠራ ይወስናል። በተፈረመው genesis ውስጥ በ[`consensus_mode`](/am/reference/genesis.md) ይገለጻል፣ በእያንዳንዱ የከፍታ አውድም ሳይለወጥ ይቀመጣል። አካባቢያዊው `[sumeragi]` ውቅር የኖዱን ሚና፣ የፊርማ ቁሳቁሶች ጥበቃ፣ የደህንነት መዝገብ መንገዶች እና በሰነድ የተገለጹ የጊዜ ገደብና የማመሳሰል ለውጦችን ይመርጣል። የብሎክና ግብይት ገደቦች፣ የመግባባት ሁነታ እና ምት ከተፈረመው genesis እና commit ከተደረገው ሁኔታ ይመጣሉ። አረጋጋጮች ተመሳሳይ የተፈረመ genesis፣ አወቃቀር፣ የታመነ የአቻ ውሂብ እና ተፈጻሚ የSumeragi መለኪያዎች ያስፈልጋቸዋል።

## ባለብዙ መስመር ስምምነት {#multilane-consensus}

የውሂብ ቦታዎች ለውሂብ፣ ለፈቃድ አሰጣጥ፣ ለፖሊሲ እና ለመተግበሪያዎች አካባቢዎችን ይወስናሉ። መስመሮቻቸው የስርጭትና የማረጋገጫ አቅም ይጨምራሉ። ካታሎጎቹ የተለዩ ናቸው፤ `nexus.dataspace_catalog` የውሂብ ቦታዎችን፣ `nexus.lane_catalog` ደግሞ እያንዳንዳቸው አንድ የውሂብ ቦታ የሚጠቅሱ መስመሮችን ይወስናሉ። በርካታ መስመሮች ተመሳሳይ የውሂብ ቦታ ሊጋሩ ይችላሉ።

ለክፍት አጠቃላይ አፈጻጸም መስመር `0`ን አጠቃላዩ የSumeragi አሂድ በቅደም ተከተል ያስቀምጣል። እያንዳንዱ ሌላ ንቁ የመስመር ትውልድ የራሱን የተወሰነ ኮሚቴና የመግባባት መለኪያዎች ይዞ የተመሳሳይ Sumeragi ኮር የተለየ አሂድ ያካሂዳል። የተረጋገጠው ብሎክ commit ከተደረገ አጠቃላይ መልህቅ አንጻር ለመግባት የተፈተሸ፣ በቅደም ተከተል ያለ የግብይት ስብስብ ይይዛል። የመስመር ማረጋገጫ አጠቃላዩን State አይቀይርም።

አጠቃላዩ ሰንሰለት ከእያንዳንዱ መስመር የሚቀጥሉትን ያልተቋረጡ የተረጋገጡ ብሎኮች ያዋህዳል። የተፈጠረውን አጠቃላይ ብሎክ ማስፈጸም ግብይቶቹን በቀኖናዊ ቅደም ተከተል ይተገብራል፣ አጠቃላዩ CommitQC ደግሞ አፈጻጸሙን የመጨረሻ ያደርገዋል። ስለዚህ የመስመር ማረጋገጫ ብቻ ግብይት አጠቃላዩን State ቀይሯል ለማለት በቂ አይደለም። በመልሶ ማግኛና በአፈጻጸም ወቅት የመስመር ማንነት፣ ትውልድ፣ የመልህቅ ወቅታዊነት፣ የምንጭ ጥበቃ እና ያልተቋረጡ የውህደት ድንበሮች መፈተሻቸው ይቀጥላል።

Commit የተደረገው `sumeragi_lane_policy` ቋሚ መስመሮችን፣ መንገዶችን፣ ኮሚቴዎችን እና አውቶማቲክ ማስፋፋትን ይቆጣጠራል። የውቅር ካታሎግ ብቻ የመግባባት መስመር አያነቃም። የተወሰኑ የውሂብ ቦታ ኢላማዎች ወደ ተፈቀደ ተዛማጅ መስመር መፈታት አለባቸው፤ የማይገኝ የግል መንገድ እንደ ሁለንተናዊ ሥራ ከመፈጸም ይልቅ ይከለከላል። የካታሎግና የማንቃት ሽግግሮች እንዲቀጥሉ ሙሉ የቁጥጥር ንብርብር ስብስቦች በመስመር `0` ያልፋሉ።

በተናጠል የተፈረመ የውሂብ ቦታ ሥር የራሱ State እና አካባቢያዊ የመጨረሻነት ያለው የተለየ የአፈጻጸም ወሰን ነው። የውሂብ ቦታ ካታሎግ ግቤት መመዝገብ ያንን ሥር አይፈጥርም። በሥሮች መካከል ያለው አቶሚክ አሠራር የተለየውን AMX ፕሮቶኮል ይጠቀማል። በተወሰነው እጩ ውስጥ የዚህ መንገድ የገንዘብና የሙሉ አውታረ መረብ ብቃት ማረጋገጥ ገና አልተዘጋም።

## የውሂብ ተገኝነት እና ጭነት መልሶ ማግኛ {#data-availability-and-payload-recovery}

Sumeragi V1 በተፈረሙ RS16 `PayloadManifest` እና `PayloadChunk` መልዕክቶች አጠቃላይ የጭነት ተደራሽነት ያረጋግጣል። መሪው የተፈረመውን ማኒፌስት ለሙሉ ኮሚቴው ይልካል፣ በመጀመሪያም በተወሰነ ሕግ የሚመረጡ ቁርጥራጮችን ወደ Set A ያሰራጫል። አረጋጋጭ የPrepare ድምጽ ሊሰጥ የሚችለው ቀኖናዊውን የብሎክ አካል እንደገና ከገነባ፣ ማኒፌስቱንና የቁርጥራጭ ሃሾችን ካረጋገጠ፣ አካሉን በቋሚ ማከማቻ ካስቀመጠ እና ዲተርሚኒስቲክ ማረጋገጥን ካጠናቀቀ በኋላ ብቻ ነው። ፈጣኑ መንገድ ከቆመ መልሶ ማግኛው የቁርጥራጭ ስርጭትን ወደ Set B ያስፋፋል። አቻ የብሎክ አካሉን ከመቀበሉ በፊት የመጨረሻነት ሲያውቅ፣ የተረጋገጠ አካል መልሶ ማግኛ እና የብሎክ ማመሳሰል የተገደበ የመልሶ ማግኛ መንገድ ይሰጣሉ።

እያንዳንዱ የመስመር አሂድ የራሱን የተረጋገጠ የተደራሽነትና የማረጋገጫ አውድ ይጠቀማል። አጠቃላይ የውህደት ፍተሻዎች የተረጋገጠውን ስብስብና ዋናውን ጭነት ከሚጠበቀው ትውልድና መልህቅ ጋር ያስራሉ። አቻ አጠቃላይ የመጨረሻነትን የሚተገብረው ተዛማጁ አጠቃላይ ጭነትና ትክክለኛ CommitQC በራሱ ኖድ ሲገኙ ብቻ ነው።

ከተለየ RBC የመገናኛ ነጥብ ይልቅ የተረጋገጡ የኦፕሬተር መዳረሻዎችን ይጠቀሙ:

- `iroha --operator-private-key-file <path> --output-format text ops sumeragi status` ስልጣን ያለው ቁመት፣ እይታ፣ ደረጃ፣ የምስክር ወረቀቶች እና የህይወት ሁኔታን ሪፖርት ያደርጋል።
- `iroha --operator-private-key-file <path> --output-format text ops sumeragi diagnostics` የመስመር ጭነት ባለቤትነትን ጨምሮ የወረፋ፣ የማቀነባበሪያ ቅደም ተከተል፣ NPoS፣ መስመር እና የውሂብ ቦታ ምርመራ ውጤቶችን ያሳያል፤ እነዚህ የፈቃድ ውሳኔ ምንጭ አይደሉም።
- እንደ `sumeragi_missing_block_requests`፣ `sumeragi_missing_block_oldest_ms`፣ `sumeragi_missing_block_fetch_total`፣ `sumeragi_da_gate_block_total` እና `sumeragi_da_gate_satisfied_total` ያሉ የፕሮሜቲየስ ምልክቶች የጎደለ አካል መልሶ ማግኛ፣ የውሂብ ተገኝነት በሮች እና የመልእክት አያያዝ። [አፈጻጸም እና መለኪያዎች](/am/guide/advanced/metrics.md) ይመልከቱ።

የመስመር ብሎክ ማከማቻዎች ለውህደትና ለመልሶ ማግኛ የሚያስፈልጉ የተረጋገጡ ስብስቦችን እና የምንጭ መዝገቦችን ያቆያሉ። የሕይወት ዑደታቸው commit የተደረገውን የመስመር ትውልድ ይከተላል፤ የማከማቻ ማውጫ ስም ለአዲስ መስመር ወይም የአፈጻጸም ሥር ፈቃድ አይሰጥም።
