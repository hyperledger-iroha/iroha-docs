# ለግል የውሂብ ቦታ ክፍያዎችን በስፖንሰር ይሸፍኑ {#sponsor-fees-for-a-private-data-space}

የSORA Nexus የክፍያ ስፖንሰር ፕሮግራም ወደ ግል የውሂብ ቦታ የሚመሩ ብቁ ግብይቶችን ዓለም አቀፍ የአፈጻጸም ክፍያ ሊከፍል ይችላል። ተጠቃሚው አሁንም ሙሉውን ግብይት ይፈርማል። አይነት ያለው `FeePaymentIntent` ትክክለኛውን የስፖንሰር ፕሮግራምና የማይለወጥ ስሪት፣ አስፈላጊ በሆነበት የgas ገደብ፣ እና ከፍተኛ ክፍያዎችን ይመርጣል።

የውሂብ ቦታ ካታሎግ ግቤት በተናጠል የተፈረመ ሥር አይፈጥርም። ገለልተኛ የውሂብ ቦታ ሥር የራሱ commit የተደረገ የክፍያ ምንዛሬና ፖሊሲ አለው፤ ክፍት የስፖንሰር ካዝናዎች የግል ሥሩን ክፍያዎች መፍቀድ አይችሉም። ስፖንሰርሺፕን ከመንደፍዎ በፊት የአፈጻጸም ሥሩን ያቋቁሙ።

## 1. commit የተደረገውን የክፍያ ፖሊሲ ያቋቁሙ {#_1-establish-the-committed-fee-policy}

የተፈረመ genesis `RootFeePolicy` የያዘ አንድ `root_fees_v1` ብጁ መለኪያ ይመሠርታል። የክፍያ ምንዛሬን፣ የክፍያ መቀበያን፣ የስፖንሰር ጥበቃ መለያን፣ የጥያቄ ነፃነቶችንና ተመኖችን ያስራል። እያንዳንዱ መደበኛ ብሎክና የክፍያ ግምት የያዘውን commit የተደረገ ፖሊሲ ይጠቀማል። የተፈቀዱ የፖሊሲ ማዘመኛዎች ከሚቀጥለው ብሎክ ይተገበራሉ።

ለዓለም አቀፍ አፈጻጸም ናቲቭ ክፍያው በፊርማ የታሰረውን ትክክለኛ የአውታረ መረብ XOR ምንዛሬ ያቃጥላል። የስፖንሰሩ የፕሮግራም ካዝና ያንን ምንዛሬ ያቀርባል። የኖድ ቅንብሮችና የግብይት ሜታዳታ ከፋይ አይመርጡም ወይም ስፖንሰርሺፕ አያነቁም።

የአውታረ መረቡን ቀኖናዊ የምንዛሬና የመለያ ማንነቶች ይጠቀሙ። ተለዋጭ ስም መፍታት commit የተደረጉ የምንዛሬ፣ የጥበቃ ወይም የመቀበያ ማንነቶችን ወደ ሌላ ማዞር የለበትም።

## 2. የስፖንሰር ፕሮግራም ይፍጠሩና ይሙሉ {#_2-create-and-fund-a-sponsor-program}

የፕሮግራሙ ID `<canonical-sponsor-account>/<program-name>` ቅርጽ አለው። የአሁኑ SDK እና የውሂብ ሞዴል በሚያቀርቧቸው አይነት ያላቸው መመሪያዎች ያቋቁሙት:

| መመሪያ | ዓላማ |
| --- | --- |
| `CreateFeeSponsorProgram` | በዝግጅት ላይ ያለውን ፕሮግራም ከግዴታ የክፍያ መቀበያ መለያው ጋር ይፍጠሩ። |
| `StageFeeSponsorProgramRevision` | አንድ የማይለወጥ የብቁነት፣ የክዋኔና የበጀት ፖሊሲ ይግለጹ። |
| `EnrollFeeSponsorBeneficiary` | ብቁ ተጠቃሚን በሰንሰለቱ ላይ ይመዝግቡ። |
| `FundFeeSponsorProgram` | ንብረቶችን ወደ ጥበቃ ያስተላልፉ፣ ትክክለኛውን የፕሮግራም ካዝና ሒሳብ ይጨምሩ። |
| `ActivateFeeSponsorProgramRevision` | በዝግጅት ላይ ላለው ስሪት ቀደምት የማንቂያ ከፍታ ይወስኑ። |

ስፖንሰሩ ወይም በትክክል የተወከለ አስተዳዳሪ የፕሮግራሙን አስተዳደር ይፈቅዳል። ገንዘብ ማውጣት ስፖንሰሩን ራሱን ይፈልጋል፣ ፕሮግራሙ ለጊዜው ቆሞ ወይም እየተዘጋ እያለ ገንዘቡን ወደ ፕሮግራሙ የተመዘገበ የክፍያ መቀበያ መለያ ብቻ ይመልሳል።

እያንዳንዱ ስሪት የሚከተሉትን ይወስናል:

- ግልጽ ምዝገባ፣ ወይም ምዝገባ ከተፈቀደ የመንገድ-ነባሪ ብቁነት ጋር፤
- በትክክለኛ ናቲቭ መመሪያ wire IDዎች ወይም በኮንትራት አድራሻዎች፣ በኮድ ሃሾችና በመግቢያ ነጥቦች ላይ የፍቀድና የከልክል ደንቦች፤
- ለእያንዳንዱ ንብረት የግብይት፣ የብሎክ፣ የፕሮግራም-ዘመን እና የተጠቃሚ-ዘመን ገደቦች፤
- ዝቅተኛ የመጠባበቂያ መጠን እና ውሳኔያዊ የዘመን ርዝመት።

የክልከላ ደንብ ከፈቃድ ደንብ ቅድሚያ አለው። የውሂብ ቦታ `fee_sponsor_program_id` የመንገድ-ነባሪ ብቁነት የሚሰጠው ንቁው ስሪት ሲፈቅደው ብቻ ነው፤ ግብይቱ አሁንም ትክክለኛውን ፕሮግራምና ስሪት መሰየም አለበት። ከቀድሞው ስሪት ያሉ ያልተጠናቀቁ ምደባዎች ጊዜያቸው እስኪያልፍ ድረስ ማንቃት ሊዘገይ ይችላል።

የስፖንሰር ካዝና ንብረቶች `Global` የቀሪ ሒሳብ ፖሊሲ መጠቀም አለባቸው። የስፖንሰሩን መደበኛ መለያ ብቻ መሙላት የተለየውን የፕሮግራም ካዝና አይሞላም፣ አንድ ፕሮግራምም የሌላውን ቀሪ ሒሳብ መጠቀም አይችልም።

## 3. ትክክለኛውን ግብይት ክፍያ ያስሉ፣ ይፈርሙና ይላኩ {#_3-quote-sign-and-submit-the-exact-transaction}

የSDK ውህደት እነዚህን ደረጃዎች ይፈጽማል:

1. ያልተፈረመ `TransactionPayload`ን ከፈቃድ ያለው አካል፣ ከሚፈጸም ይዘት፣ ከጊዜ ማህተሞች፣ ከnonce፣ ከሜታዳታ፣ ከትክክለኛው የስፖንሰር ፕሮግራም ስሪት እና ከማንኛውም የሚፈለግ የgas ገደብ ጋር ይገንቡ። ከፍተኛ ክፍያዎች በመጀመሪያ ባዶ ሊሆኑ ይችላሉ።
2. `POST /v1/fees/quote`ን ከ`{"payload": <payload>}` ጋር በመለያ ይፈርሙ። የጥያቄው ፈራሚ የግብይቱ ፈቃድ ያለው አካል መሆን አለበት።
3. የታየውን ከፍታ፣ የተወሰነውን የውሂብ ቦታ መንገድ፣ የክፍያ ክፍሎችን፣ ገንዘብ የሚቀነስበትን ምንጭ እና የስፖንሰር አቅም ይመርምሩ። ምላሹ የተመረጠውን ከፋይ፣ ስሪትና የgas ገደብ እንደሚያቆይ ያረጋግጡ።
4. `payload.fee_payment`ን ብቻ በተመከረው intent ይተኩ፣ ከዚያ ያንን ትክክለኛ ጭነት ይፈርሙና ይላኩ።
5. ግብይቱን በሁኔታ እስከተወሰነ `Applied` የመጨረሻነት ይከታተሉ፣ እውነተኛውን የስፖንሰር ፕሮግራም፣ ስሪትና ክፍያ የያዘ ደረሰኙንም ያቆዩ።

የክፍያ ግምት መዝገቡን ይመለከታል፤ አቅም አያስይዝም። ወደ ወረፋ መቀበል ብቁነትን እንደገና ይመረምራል፣ የተፈረሙትን ከፍተኛ መጠኖችም ያስይዛል። የስፖንሰር እምቢታ ከተጠቃሚው ክፍያ ወደ መቀነስ ሳይመለስ ግብይቱን ይከለክላል።

CLI ያንኑ የክፍያ ምንጭ በግልጽ ይሰይማል። ለምሳሌ ፕሮግራሙ ይህን ትክክለኛ የንብረት ዝውውር ከፈቀደና መለያው ብቁ ከሆነ በኋላ:

```bash
iroha --config ./user.client.toml \
  --fee-payer sponsor \
  --fee-program '<SPONSOR_CANONICAL_I105>/team-payments' \
  --fee-program-revision 1 \
  ledger asset transfer \
  --definition '<ASSET_DEFINITION_BASE58>' \
  --account '<USER_CANONICAL_I105>' \
  --to '<RECIPIENT_CANONICAL_I105>' \
  --quantity 1
```

ከአውታረ መረብዎ ንቁውን ስሪትና ትክክለኛ መለያዎች ይጠቀሙ። የተጠቃሚው ውቅር የዚያን ተጠቃሚ ፈራሚ ብቻ ይይዛል፤ ብቁ በስፖንሰር የተሸፈነ ግብይት ለመላክ የስፖንሰሩ የግል ቁልፍ አያስፈልግም።

## 4. ተጠቃሚው የመተግበሪያ ክፍያ ይከፍል እንደሆነ ይወስኑ {#_4-decide-whether-the-user-pays-an-application-fee}

መተግበሪያው ከተጠቃሚው ምንም ሳይቀበል ስፖንሰር ዓለም አቀፍ ክፍያዎችን ሊሸፍን ይችላል። መተግበሪያው አካባቢያዊ ቶከን ከሰበሰበ ያንን ዝውውር ወይም የኮንትራት ደንብ በተጠቃሚው የተፈረመ የሚፈጸም ይዘት ውስጥ በግልጽ ይግለጹ። እያንዳንዱን ክዋኔ በስፖንሰር ስሪቱ ፖሊሲ ያካትቱ፣ የሙሉ ጭነቱን የክፍያ ግምትም ይመርምሩ። ከአውታረ መረብ የክፍያ intent የመተግበሪያ ቶከን ዝውውር አይገምቱ።

## የእምቢታ ምክንያትን ይመርምሩ {#diagnose-a-refusal}

ኖዱ የመለሰውን ቋሚ የክፍያ ኮድና የማስተካከያ ዝርዝሮች ይጠቀሙ:

| ኮድ | ምርመራ |
| --- | --- |
| `program_not_found` | ትክክለኛ ቀኖናዊ የፕሮግራም ማንነት። |
| `revision_not_active`፣ `program_not_active` | የስሪት ማንቃትና የፕሮግራም የሕይወት ዑደት። |
| `beneficiary_not_eligible` | ምዝገባ ወይም የተፈቀደ የመንገድ-ነባሪ ብቁነት። |
| `operation_not_allowed`፣ `operation_denied` | እያንዳንዱ ትክክለኛ የተፈረመ ክዋኔና የክልከላ ደንብ። |
| `invalid_gas_limit`፣ `signed_limit_exceeded` | የgas ገደብና የተፈረሙ ከፍተኛ መጠኖች ከአዲስ የክፍያ ግምት ጋር። |
| `vault_insufficient` | የዚህ ፕሮግራም ትክክለኛ ምንዛሬ ካዝና የተሞላ ቀሪ ሒሳብ። |
| የበጀት ማለቅ ኮዶች | የግብይት፣ የብሎክ፣ የፕሮግራም-ዘመን እና የተጠቃሚ-ዘመን አቅም። |

ውጤቱ ግልጽ ያልሆነ መላክን ሲመረምሩ ዋናውን የግብይት ሃሽና የክፍያ እምቢታ ዝርዝሮች ያቆዩ። ምትክ ከመገንባትዎ በፊት ሁኔታውን ያረጋግጡ።
