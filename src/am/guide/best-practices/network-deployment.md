# የአውታረ መረብ ማሰማራት {#network-deployment}

የ Iroha አውታረ መረብን እንደ የተቀናጀ ስርዓት ይያዙት። አውታረ መረቡ ብሎኮችን ከመጀመሩ እና ከማጠናቀቁ በፊት አረጋጋጮች በብሎክቼይን ጀነሲስ፣ ቶፖሎጂ፣ የታመኑ የአውታረ መረብ እኩዮች እና ከስምምነት ጋር ተዛማጅነት ባለው ውቅር ላይ መስማማት አለባቸው።

## የአካባቢ መለያየት {#environment-separation}

- ለአካባቢያዊ ልማት፣ ለጋራ ቴስትኔት፣ ለዝግጅት እና ለምርት የተለየ የውቅረት ቅርቅቦችን ያቆዩ።
- ለእያንዳንዱ የማይጣሉ አካባቢዎች ትኩስ ቁልፎችን ይፍጠሩ። በምርት ውስጥ localnet ወይም Taira ቁልፍ ቁሳቁስ እንደገና አይጠቀሙ።
- የአውታረ መረብ አቻ ውቅረትን፣ የደንበኛ ውቅረትን፣ የተፈረመ የብሎክቼይን ጀነሲስን፣ ስክሪፕቶችን እና የማሰማራት ማስታወሻዎችን እንደ ስሪት የመልቀቂያ አርቲፋክት አንድ ላይ ያቆዩ።
- የግል ቁልፎችን ከማከማቻዎች እና ከማሰማራት አብነቶች ውጭ ያከማቹ።

[ለአውታረመረብ ማሰማራት ቁልፎች](/am/guide/configure/keys-for-network-deployment.md) ተመልከት።

## Blockchain ጀነሲስ እና ቶፖሎጂ {#genesis-and-topology}

- እያንዳንዱ አረጋጋጭ መገለጫው በሚፈልግበት ጊዜ አንድ አይነት የተፈረመ የብሎክቼይን ጀነሲስ ግብይት፣ የታመነ የአውታረ መረብ አቻ ስብስብ፣ ቶፖሎጂ እና አረጋጋጭ እንዲጠቀም ያድርጉ።
- ለትንሹ የባይዛንታይን ስህተት-ታጋሽ ማሰማራት ቢያንስ አራት አረጋጋጮችን ይጠቀሙ።
- በአቅም እቅድ ውስጥ አረጋጋጮችን ከተመልካቾች ይለዩ። ታዛቢዎች ድምጽ አይሰጡም፣ አያቀርቡም ወይም አይሰበስቡም፣ ነገር ግን አሁንም ማከማቻ፣ ማመሳሰልን ያግዳሉ እና የአውታረ መረብ ባንድዊድዝ ይጠቀማሉ።
- የብሎክቼይን ጀነሲስ፣ አስፈፃሚ እና ቶፖሎጂ ለውጦችን ከነጠላ-አቻ አርትዖቶች ይልቅ እንደ የተቀናጁ ፍልሰት ይያዙ።

[blockchain ጀነሲስ](/am/reference/genesis.md)፣ [የአውታረ መረብ አቻ አስተዳደር](/am/guide/configure/peer-management.md) እና [አፈጻጸም እና መለኪያዎች](/am/guide/advanced/metrics.md#node-count-and-quorum) ተመልከት።

## Torii እና የአውታረ መረብ መዳረሻ {#torii-and-network-access}

- ከአስተናጋጁ ወይም ከግል አውታረመረብ ውጭ ሲጋለጥ Torii ከተገላቢጦሽ ፕሮክሲ ወይም ፋየርዎል ጀርባ ያስቀምጡ።
- TLS ን ያቋርጡ እና ማሰማራቱ በሚፈልግበት ጊዜ መሰረታዊ ማረጋገጫን፣ የፍጥነት መገደብ እና የጥያቄ መጠን መቆጣጠሪያዎችን በጠርዝ ላይ ይተግብሩ።
- በአካባቢው የሚፈለጉትን API የመጨረሻ ነጥቦችን ብቻ ያትሙ። የኦፕሬተር እና የቴሌሜትሪ መስመሮች ከህዝብ ተነባቢ-ብቻ መስመሮች የበለጠ የተገደቡ መሆን አለባቸው።
- የአውታረ መረብ እኩዮች የርቀት ትራፊክን በቀጥታ መቀበል በማይኖርበት ጊዜ የአድማጭ አድራሻዎችን ከአስተናጋጅ-አካባቢያዊ በይነገጾች ጋር ያያይዙ።

[Torii API የመጨረሻ ነጥቦች](/am/reference/torii-endpoints.md) እና [ምናባዊ የግል አውታረ መረቦች](/am/guide/security/vpn.md) ተመልከት።

## መግባባት እና አቅም {#consensus-and-capacity}

- የጋራ መግባባት ሰዓት ቆጣሪዎችን ከማስተካከልዎ በፊት ማሰማራቱን ይለኩ። ዝቅተኛ የጊዜ ማብቂያዎች መዘግየትን ሊቀንሱ የሚችሉት የአውታረ መረብ፣ ማከማቻ እና የማስፈጸሚያ ንብርብሮች ሲቀጥሉ ብቻ ነው።
- አጭር የመተላለፊያ ናሙናዎችን ብቻ ሳይሆን የወረፋ አቅጣጫን ይመልከቱ። በቋሚ ጭነት ወቅት የሚያድግ ወረፋ አውታረ መረቡ ከመጠን በላይ ተጭኗል ማለት ነው።
- ለእያንዳንዱ መለኪያ ውጤታማ Sumeragi መለኪያዎችን፣ የቴሌሜትሪ መገለጫን፣ የማረጋገጫ ብዛትን፣ የአውታረ መረብ RTT ን፣ የስራ ጫና ቅርፅን እና የሃርድዌር ዝርዝሮችን ይመዝግቡ።
- በአንድ ጊዜ አንድ የታሰረ ወረፋ ወይም ጭነት መልሶ ማግኛ ገደብ ይቀይሩ እና የፊት-እና በኋላ መዘግየት፣ ትራፊክ፣ ማህደረ ትውስታ እና የኋላ ግፊት ማስረጃዎችን ይያዙ።

[አፈጻጸም እና መለኪያዎች](/am/guide/advanced/metrics.md) ተመልከት።

## ባዶ-ብረት እና የሂደቱ አስተዳደር {#bare-metal-and-process-management}

- የእያንዳንዱን የአውታረ መረብ አቻ `config.toml`፣ የግል ቁልፍ፣ የማከማቻ ማውጫ እና ወደቦች ይለያዩ።
- እንደ systemd ያሉ የሂደት አስተዳዳሪዎችን በግልፅ ዳግም ማስጀመር፣ ምዝግብ ማስታወሻ እና የግብአት ፖሊሲዎች ይጠቀሙ።
- የሙከራ ቶፖሎጂን ወደ ሚተዳደሩ አስተናጋጆች ሲተረጉሙ የመነጨውን README ያቆዩ እና ትዕዛዞችን ከ Kagami localnet ጥቅሎች ይጀምሩ።
