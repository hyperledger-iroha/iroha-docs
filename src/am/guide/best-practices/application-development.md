# የመተግበሪያ ልማት {#application-development}

Iroha መተግበሪያዎች የግብይት ባህሪን ግልፅ ማድረግ አለባቸው ፣ ፊርማውን ሁኔታ መያዝ እና ጥያቄዎችን እና ክስተቶችን በምርት ውስጥ በቀላሉ ለመከታተል በሚችሉ መንገዶች መጠቀም አለባቸው።

## ደንበኛ ማዋቀር {#client-setup}

- የመተግበሪያው ምንጭ ኮድ ውጭ የደንበኞችን ውቅር ያከማቹ. ሰንሰለት ID, Torii URL, ፊርማ መለያ እና ግብይት ቅንብሮች ከአካባቢ-ተኮር ቅንብር ይጫኑ.
- `client.toml` ፋይሎችን ለሎካልኔት ፣ Taira ፣ Minamoto እና ለግል አውታረ መረቦች ለየብቻ ይያዙ። የተገለጸው የሙከራ ኔት ፊርማ ፈራሚ በጭራሽ ዋና የኔት ፊርማ መሆን የለበትም ።
- በጣም አጭር የህይወት ዘመን በተለመደው የአውታረ መረብ ጭንቀት ውስጥ ሊያልቅ ይችላል ፣ በጣም ረጅም ጊዜ ደግሞ ድርብ ማቅረቢያዎችን ለማመዛዘን አስቸጋሪ ሊያደርግ ይችላል።
- `nonce = true` የሚጠቀሙት ተደጋጋሚ ግብይቶች የተለዩ ሃሽዎች ሊኖራቸው ሲገባ ብቻ ነው። ለነፃ የንግድ ሥራዎች የመተግበሪያ ጥያቄን ID ያስቀምጡ እና እንደገና ይጠቀሙ ስለዚህ ዳግም ሙከራዎች መከታተል ይችላሉ ።

የአሁኑን TOML መስኮች ለማግኘት [የደንበኛው ውቅር ](/am/guide/configure/client-configuration.md) ይመልከቱ።

## ግብይቶች {#transactions}

- በተቻለ መጠን JSON ወይም በቁጥሮች ከተሰበሰቡ ጥቅማጭነቶች ይልቅ በትይዩ SDK መመሪያዎች ላይ ግብይቶችን መገንባት።
- Preflight አስፈላጊ በንባብ ብቻ መጠይቆች ይጽፋል-የሂሳብ መኖር ፣ የንብረት ሚዛን ፣ የፍቃድ ሁኔታ ፣ የክፍያ ንብረቶች ተገኝነት እና ዒላማ ዕቃዎች ሁኔታ ።
- ከመላክዎ በፊት የግብይት ሃሽ, ባለስልጣን መለያ, መመሪያ ማጠቃለያ, እና የሚጠበቀው ሁኔታ ለውጥ ይመዝገቡ.
- `Rejected`, `Expired` እና የጊዜ ገደብ ውጤቶች በተለያየ መንገድ ይስተናገዳሉ። አንድ ጊዜ ገደብ ማለት ደንበኛው የመጨረሻውን ሁኔታ አልጠበቀም ማለት ነው; ይህ አውታረመረብ ግብይቱን ችላ እንዳለው አያረጋግጥም.
- በተሳካ ሁኔታ ከተጻፈ በኋላ የተገኘውን ሁኔታ ከንግድ ሥራው ጋር የሚዛመድ የጥያቄ ወይም ክስተት ማረጋገጫ ነጥብ ጋር ያረጋግጡ ።

ለግብይት ሜካኒክስ [Transactions](/am/blockchain/transactions.md) የሚለውን ይመልከቱ።

## ጥያቄዎችና ክስተቶች {#queries-and-events}

- ለለውጥ ማሳወቂያዎች የአሁኑን ሁኔታ እና ክስተት ዥረቶች መጠይቆችን ይጠቀሙ። ክስተት አያያዝን በተደጋጋሚ ሰፊ ጥያቄዎችን በመተካት ማስወገድ።
- እንደ መለያ፣ ንብረት እና የብሎክ ዝርዝሮች ያሉ ሰፋፊ ተደጋጋሚ መጠይቆችን ገጾች ያዘጋጁ።
- ለደንበኝነት ምዝገባዎች እና አስነሳሾች ጠባብ ማጣሪያዎችን ይመርጣሉ። ሰፋፊ ማጣሪያዎች ለምርመራ ጠቃሚ ናቸው ነገር ግን አላስፈላጊ አፈፃፀም እና የደንበኛ ጎን ሂደት ሊጨምሩ ይችላሉ ።
- የማንበብ-ብቻ ጭስ ምርመራዎች ከተፈረሙ የግብይት ሙከራዎች ተለይተው እንዲቆዩ ያድርጉ ፣ ስለሆነም የፍፃሜ ነጥብ ተገኝነት ለመመርመር ቀላል ነው።

[ጥያቄዎች](/am/blockchain/queries.md)፣ [ክስተቶች](/am/blockchain/events.md) እና [ፊልተሮች ](/am/blockchain/filters.md) ይመልከቱ።

## በወኪል የተደገፈ ልማት {#agent-assisted-development}

- ወኪሎች የግብይት ኮድ እንዲጽፉ ከመጠየቃቸው በፊት ሰነዶችን ፣ SDK ኮድን እና ንባብ-ብቻ የአውታረ መረብ ሁኔታን ይመርምሩ ።
- የቀጥታ አውታረመረብ ሙከራዎች እንደ `TAIRA_LIVE=1` ባሉ የአካባቢ ባንዲራ በስተጀርባ እንዲካፈሉ ያድርጉ.
- የግል ቁልፎችን፣ የሂሳብ ማግኛ ቁሳቁሶችን፣ API ቶከኖችን ወይም የተላኩ የደራሲ ራስጌዎችን ወደ ጠቋሚዎች አይጣበቁ።
- ማንኛውም ወኪል የቀጥታ የሙከራ አውታረ መረብ ግብይት ከማቅረብዎ በፊት የግብይት ዕቅድ ይጠይቁ ። እቅዱ አውታረመረብን ፣ ባለሥልጣኑን ፣ መመሪያዎችን ፣ የክፍያ ንብረትን ፣ ከበረራ በፊት ንባቦችን ፣ የሚጠበቁ ውጤቶችን እና እንደገና የመሞከር ባህሪን ሊጠቅስ ይገባል ።

ለ Taira MCP የስራ ፍሰት, ተመልከት [በ SORA ላይ መገንባት 3: Taira እና Minamoto](/am/get-started/sora-nexus-dataspaces.md#taira-mcp-for-agents).

## SDK ንፅህና {#sdk-hygiene}

- ፒን SDK እና የሁለትዮሽ ስሪቶች በጋራ በመጠቀም [ ተኳሃኝነት ማትሪክስ](/am/reference/compatibility-matrix.md)።
- የተፈጠሩትን የደንበኛ ኮድ ፣ ቅንጥቦች እና ምሳሌዎች ከታሸገ የስራ ቦታ ማሻሻያ ጋር አብረው ያቆዩ ።
- ትግበራዎ የሚወሰነው አነስተኛውን የንባብ እና የመጻፍ ጎዳናዎች ለማግኘት ለግብይት ኮድ ግንባታ ዩኒት ሙከራዎችን እና ውህደት ሙከራዎችን ያክሉ ።
