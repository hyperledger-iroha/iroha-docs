# አፕሊኬሽን ልማት {#application-development}

Iroha አፕሊኬሽኖች የግብይት ባህሪን ግልፅ ማድረግ አለባቸው ፣ መፈረምዎን ይቀጥሉ
የተካተቱት ሁኔታ, እና ጥያቄዎችን እና ክስተቶችን ቀላል በሆነ መንገድ ይጠቀሙ
በምርቱ ላይ ይከታተሉ.

## የደንበኛ ማዋቀር {#client-setup}

- የመተግበሪያው ምንጭ ኮድ ውጭ የደንበኞችን ውቅር ያከማቹ
  ሰንሰለት ID, Torii URL, የፊርማ ሂሳብ እና ከግብይት ቅንብሮች
  ለአካባቢው የተወሰነ ውቅር።
- ይቀጥሉ `client.toml` ለ localnet የተለዩ ፋይሎች፣ Taira, Minamoto, እና
  የግል አውታረ መረቦች። የተገለጸው የሙከራ ኔትወርክ ፊርማ ዋናው ኔትወርቅ መሆን የለበትም።
  ፊርማ።
- የግብይት ጊዜዎችን እና የአቋም ጊዜዎችን ሆን ተብሎ ያዘጋጁ።
  የህይወት ዘመን መደበኛ የአውታረ መረብ jitter ሥር ማብቂያ ይችላል, በጣም ረጅም አንድ
  በተደጋጋሚ የሚቀርቡትን ሐሳቦች ማሰብ ይከብዳል።
- አጠቃቀም `nonce = true` በተደጋጋሚ የሚደረጉ ግብይቶች ልዩነት ያላቸው ሲሆኑ ብቻ
  ለሥራ ባልተፈቀደላቸው የንግድ ሥራዎች፣
  የማመልከቻ ጥያቄ ID ስለዚህ መልሶ ሙከራዎች መከታተል ይችላሉ.

ተመልከት [የደንበኛው ውቅር](/am/guide/configure/client-configuration.md) ለ
የአሁኑ TOML መስኮች.

## ግብይቶች {#transactions}

- ከታየ የግብይት መገንባት SDK መመሪያዎችን በተቻለ መጠን
  ጥሬ JSON ወይም በቁጥሮች የተዋሃዱ ጥቅማጭነቶች።
- Preflight አስፈላጊ የሚጽፈው በንባብ ብቻ ጥያቄዎች ጋር ነው: መለያ መኖር,
  የአክሲዮን ቀሪ ሂሳቦች፣ የመፈቀድ ሁኔታ፣ የክፍያ አክሲዮኖች ተደራሽነት እና ግብ
  የዕቃ ሁኔታ።
- የግብይት ሃሽ፣ ባለስልጣን መለያ፣ መመሪያ ማጠቃለያ እና
  ከመቅረባቸው በፊት የሚጠበቀው የስቴት ለውጥ።
- ሕክምና `Rejected`, `Expired`, የጊዜ ሰሌዳ ውጤቶች በተለያየ መንገድ ይወጣሉ።
  ደንበኛው የመጨረሻውን ሁኔታ አልታዘበም ማለት ነው;
  ኔትወርኩ ግብይቱን ችላ ብሏል።
- ስኬታማ ጽሑፍ በኋላ, አንድ ጥያቄ ጋር የተገኘው ሁኔታ ማረጋገጥ ወይም
  ከንግድ ሥራው ጋር የሚዛመድ የክስተት ፍተሻ ነጥብ።

ለግብይት ሜካኒክስ ተመልከት [ግብይቶች](/am/blockchain/transactions.md).

## ጥያቄዎችና ክስተቶች {#queries-and-events}

- ለለውጥ ማሳወቂያዎች የአሁኑ ሁኔታ እና ክስተት ዥረቶች መጠይቆችን ይጠቀሙ።
  ክስተት አያያዝን በተደጋጋሚ ሰፊ ጥያቄዎችን በመተካት ማስወገድ።
- እንደ መለያ፣ ንብረት እና ብሎክ ያሉ ሰፊ ተደጋጋሚ መጠይቆችን ገጾች ያዘጋጁ
  ዝርዝሮች።
- ለደንበኝነት ምዝገባዎች እና አስነሳሾች ጠባብ ማጣሪያዎችን ይመርጣሉ።
  ለምርመራ ጠቃሚ ነገር ግን አላስፈላጊ አፈፃፀም እና የደንበኛ ወገን ማከል ይችላል
  ማቀነባበር
- ለንባብ ብቻ የሚሆኑትን የጭስ ቁጥሮች ከተፈረሙ የግብይት ሙከራዎች በተለየ መልኩ ያድርጉ
  የጨረታ ነጥብ ተደራሽነት ለመመርመር ቀላል ነው።

ተመልከት [ጥያቄዎች](/am/blockchain/queries.md), [ክስተቶች](/am/blockchain/events.md), እና
[ማጣሪያዎች](/am/blockchain/filters.md).

## በወኪል የተደገፈ ልማት {#agent-assisted-development}

- ወኪሎች ዶክተሮችን ይመርምሩ፣ SDK ኮድ, እና አንብብ ብቻ አውታረ መረብ ሁኔታ በፊት
  የግብይት ኮድ እንዲጽፉላቸው መጠየቅ።
- የቀጥታ አውታረ መረብ ፈተናዎች እንደ አካባቢ ባንዲራ በስተጀርባ opt-in ማስቀመጥ
  `TAIRA_LIVE=1`.
- የግል ቁልፎችን, የሂሳብ ማግኛ ቁሳቁሶችን አያጣጥፉ, API መለያዎች፣ ወይም
  የደራሲ ራስጌዎችን ወደ ማሳሰቢያዎች አስተላልፈዋል ።
- ማንኛውም ወኪል የቀጥታ የሙከራ አውታረመረብ ከማቅረቡ በፊት የግብይት ዕቅድ ይጠይቁ
  ዕቅዱ አውታረ መረቡን፣ ባለስልጣኑን፣ መመሪያውን፣
  የክፍያ አክሲዮን፣ የቅድመ በረራ ንባቦች፣ የሚጠበቀው ውጤት እና ዳግም ሙከራ ባህሪ።

ለ Taira MCP የስራ ፍሰት፣ ተመልከት
[አቋራጭ ሁን SORA 3: Taira እና Minamoto](/am/get-started/sora-nexus-dataspaces.md#taira-mcp-for-agents).

## SDK ንፅህና {#sdk-hygiene}

- ፒን SDK እና በሁለትዮሽ ስሪቶች በአንድነት በመጠቀም
  [ተኳሃኝነት ማትሪክስ](/am/reference/compatibility-matrix.md).
- የተፈጠረውን የደንበኛ ኮድ, ቁርጥራጮች, እና ምሳሌዎች
  የስራ ቦታን ማሻሻል በቅድሚያ ተጣብቋል።
- ለግብይት ኮድ እና ውህደት ሙከራዎች የአንድነት ሙከራዎችን ይጨምሩ
  ማመልከቻዎ የሚወሰነው ትንሹን የንባብ እና የመጻፍ መንገድ ነው ።
