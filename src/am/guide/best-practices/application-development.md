# የመተግበሪያ ልማት {#application-development}

Iroha አፕሊኬሽኖች የግብይት ባህሪን ግልጽ ማድረግ፣ የመፈረሚያ ሁኔታን መቀጠል እና መጠይቆችን እና ክስተቶችን በምርት ውስጥ በቀላሉ ሊታዩ በሚችሉ መንገዶች መጠቀም አለባቸው።

## የደንበኛ ቅንብር {#client-setup}

- የደንበኛ ውቅረትን ከመተግበሪያ ምንጭ ኮድ ውጭ ያከማቹ። የሰንሰለት መታወቂያውን ይጫኑ፣ Torii URL፣ መለያ መፈረም እና የግብይት ቅንብሮችን ከአካባቢ-ተኮር ውቅር ይጫኑ።
- የ`client.toml` ፋይሎችን ለlocalnet፣ Taira፣ Minamoto እና የግል አውታረ መረቦች እንዲለዩ ያድርጉት። የተቀዳ የቴስትኔት ክሪፕቶግራፊክ ፈራሚ በፍፁም የዋና መረብ ምስጠራ ፈራሚ መሆን የለበትም።
- ሆን ብለው የግብይት የህይወት ዘመኖችን እና የሁኔታ ጊዜዎችን ያዘጋጁ። በጣም አጭር የህይወት ዘመን በተለመደው የአውታረ መረብ መንቀጥቀጥ ስር ሊያልቅ ይችላል፣ በጣም ረጅም ደግሞ የተባዙ ማቅረቢያዎችን ለማመዛዘን አስቸጋሪ ያደርገዋል።
- ተደጋጋሚ ግብይቶች የተለየ ምስጠራ ሃሽ ሲኖራቸው ብቻ `nonce = true`ን ይጠቀሙ። ለአይደምፖተንት የንግድ ስራዎች፣ ድጋሚ ሙከራዎች እንዲገኙ የመተግበሪያ ጥያቄ መታወቂያን ያከማቹ እና እንደገና ይጠቀሙ።

ለአሁኑ TOML መስኮች [የደንበኛ ውቅር](/am/guide/configure/client-configuration.md) ይመልከቱ።

## ግብይቶች {#transactions}

- ከተቻለ ከተተየቡ SDK መመሪያዎች ግብይቶችን ይገንቡ ጥሬ JSON ወይም ሕብረቁምፊ-የተገጣጠሙ ጭነቶች።
- ቅድመ-በረራ አስፈላጊ የመጻፍ ክዋኔዎች ከተነባበ-ብቻ መጠይቆች ጋር የመለያ መኖር፣ የንብረት ቀሪ ሒሳቦች፣ የፍቃድ ሁኔታ፣ የክፍያ ንብረት ተገኝነት እና የታለመ ነገር ሁኔታ።
- ከማስገባትዎ በፊት የግብይቱን ምስጠራ ሃሽ፣ የፍቃድ ዋና መለያ፣ የመመሪያ ማጠቃለያ እና የሚጠበቀው የሁኔታ ለውጥ ይመዝግቡ።
- `Rejected`፣ `Expired` እና የጊዜ ማብቂያ ውጤቶችን በተለየ መንገድ ይያዙ። የጊዜ ማብቂያ ማለት ደንበኛው የመጨረሻውን ሁኔታ አላስከበረም ማለት ነው; አውታረ መረቡ ግብይቱን ችላ ማለቱን አያረጋግጥም.
- ከተሳካ የመጻፍ ክዋኔ በኋላ የተገኘውን ሁኔታ ከንግድ ሥራው ጋር በሚዛመድ መጠይቅ ወይም የክስተት ፍተሻ ነጥብ ያረጋግጡ።

ለግብይት መካኒኮች፣ [ግብይቶች](/am/blockchain/transactions.md) ይመልከቱ።

## ጥያቄዎች እና ኩነቶች {#queries-and-events}

- ለለውጥ ማሳወቂያዎች ለአሁኑ ሁኔታ እና የክስተት ዥረቶች መጠይቆችን ይጠቀሙ። የክስተት አያያዝን በተደጋጋሚ ሰፊ መጠይቆች ከመተካት ይቆጠቡ።
- እንደ መለያ፣ ንብረት እና የብሎክ ዝርዝሮች ያሉ ሰፊ ሊደጋገሙ የሚችሉ መጠይቆችን ገጽ ያድርጉ።
- ለደንበኝነት ምዝገባዎች እና ቀስቅሴዎች ጠባብ ማጣሪያዎችን ይምረጡ። ሰፊ ማጣሪያዎች ለምርመራ ጠቃሚ ናቸው ነገር ግን አላስፈላጊ አፈፃፀም እና የደንበኛ-ጎን ሂደትን ሊጨምሩ ይችላሉ።
- API የመጨረሻ ነጥብ ተገኝነት ለመመርመር ቀላል እንዲሆን የተነበበ-ብቻ የጭስ ፍተሻዎችን ከተፈረሙ የግብይት ሙከራዎች ይለዩ።

[መጠይቆች](/am/blockchain/queries.md)፣ [ክስተቶች](/am/blockchain/events.md) እና [ማጣሪያዎች](/am/blockchain/filters.md) ተመልከት።

## በወኪል የታገዘ ልማት {#agent-assisted-development}

- ወኪሎች የግብይት ኮድ እንዲጽፉ ከመጠየቃቸው በፊት ሰነዶችን፣ SDK ኮድ እና ተነባቢ-ብቻ የአውታረ መረብ ሁኔታን እንዲፈትሹ ያድርጉ።
- የቀጥታ አውታረ መረብ ሙከራዎችን እንደ `TAIRA_LIVE=1` ካሉ የአካባቢ ባንዲራ ጀርባ መርጠው እንዲገቡ ያቆዩ።
- የግል ቁልፎችን፣ የመለያ መልሶ ማግኛ ቁሳቁሶችን፣ API ቶከኖችን ወይም የማረጋገጫ ራስጌዎችን ወደ መጠየቂያዎች አያስተላልፉ።
- ማንኛውም ወኪል የቀጥታ የቴስትኔት ግብይት ከማቅረቡ በፊት የግብይት እቅድ ይጠይቁ። እቅዱ ኔትወርክን፣ የፍቃድ ርዕሰ መምህራን፣ መመሪያዎችን፣ የክፍያ ንብረቱን፣ የቅድመ በረራ ንባቦችን፣ የሚጠበቀውን ውጤት እና ባህሪን እንደገና መሞከር አለበት።

ለ Taira MCP የስራ ፍሰት፣ [በ SORA 3 Taira እና Minamoto ላይ ይገንቡ](/am/get-started/sora-nexus-dataspaces.md#taira-mcp-for-agents) ይመልከቱ።

## SDK ንፅህና መጠበቂያ {#sdk-hygiene}

- SDK እና ሁለትዮሽ ስሪቶችን [የተኳኋኝነት ማትሪክስ](/am/reference/compatibility-matrix.md) በመጠቀም አንድ ላይ ይሰኩ።
- የመነጨ የደንበኛ ኮድ፣ ቅንጥቦች እና ምሳሌዎች ከተሰካው የላይኛው ተፋሰስ የስራ ቦታ ክለሳ ጋር እንዲመሳሰሉ ያድርጉ።
- መተግበሪያዎ የሚመረኮዝበትን ትንሹን የማንበብ እና የመፃፍ መንገዶች ለግብይት-ግንባታ ኮድ እና የውህደት ሙከራዎችን የክፍል ሙከራዎችን ያክሉ።
