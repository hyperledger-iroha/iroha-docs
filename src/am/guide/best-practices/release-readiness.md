# የመልቀቂያ ዝግጁነት {#release-readiness}

የ Iroha መተግበሪያን ወይም የአውታረ መረብ ለውጥን ከማስተዋወቅዎ በፊት ተገቢውን አደጋ ሊያጋልጥ በሚችል ትንሽ አካባቢ ያለውን ባህሪ ያረጋግጡ እና ከዚያ ሆን ብለው በጋራ ቴስትኔት እና የምርት በሮች ውስጥ ይሂዱ።

## Localnet በር {#localnet-gate}

- ተመሳሳይ Iroha ትራክ እና በጣም ቅርብ በሆነው ተግባራዊ አረጋጋጭ ብዛት ሊጣል የሚችል የአካባቢ አውታረ መረብ ያስጀምሩ።
- ለግብይት ግንበኞች፣ ለጥያቄ ትንተና፣ ላለመቀበል አያያዝ እና ለማዋቀር ጭነት የክፍል ሙከራዎችን ያሂዱ።
- አፕሊኬሽኑ በኋላ በሚጠቀምበት ተመሳሳይ SDK ወይም CLI ቅርፅ ትንሹን የተሳካ የማንበብ እና የመፃፍ መንገዶችን ይለማመዱ።
- የሚጠበቀው የግብይት ምስጠራ ሃሽዎችን፣ ሁኔታዎችን፣ ክስተቶችን እና የሁኔታ ንባቦችን በሙከራ አርቲፋክቶች ውስጥ ይያዙ።

[አስጀምር Iroha 3](/am/get-started/launch-iroha.md) እና [SDK አጋዥ ሥልጠናዎች](/am/guide/tutorials/) ተመልከት።

## የተጋራ የቴስትኔት በር {#shared-testnet-gate}

- ለ API የመጨረሻ ነጥብ ባህሪ፣ ክፍያዎች፣ የመለያ የገንዘብ ድጋፍ፣ መዘግየት እና የአሠራር ልምምዶች Taira ወይም ሌላ የጋራ የሙከራ መረብ ይጠቀሙ።
- ተራ የሙከራ ሩጫዎች በአውታረ መረብ ተገኝነት ላይ የተመሰረቱ እንዳይሆኑ ወይም የቴስትኔት ገንዘቦችን እንዳያወጡ የቀጥታ ቴስትኔት መርጦ መግባትን ይቀጥሉ።
- እያንዳንዱን የቀጥታ ሙከራ ግብይት ከማስገባትዎ በፊት የምስጠራ ፈራሚ የገንዘብ ድጋፍ፣ የክፍያ ንብረት ሜታዳታ፣ የፍቃድ ዋና ፈቃዶች እና የሚጠበቀውን ሁኔታ ያረጋግጡ።
- የተርሚናል ሁኔታን ይጠብቁ፣ ከዚያ የተገኘውን ሁኔታ በተነባቢ-ብቻ መጠይቅ ያረጋግጡ።

[በ SORA 3 Taira እና Minamoto ላይ ይገንቡ](/am/get-started/sora-nexus-dataspaces.md) ተመልከት።

## ዋና መረብ ወይም ፕሮዳክሽን በር {#mainnet-or-production-gate}

- የተለየ የምርት ምስጠራ ፈራሚዎችን፣ የገንዘብ ድጋፍን፣ ጎራዎችን እና የማዋቀር መንገዶችን ይጠቀሙ። የቴስትኔት ቁልፎችን ወይም የቴስትኔት የገንዘብ ድጋፍ አገልግሎት ግምቶችን አያስተዋውቁ።
- የሚፈለጉትን የመስቀል-SDK ሁኔታዎችን በ[የተኳኋኝነት ማትሪክስ](/am/reference/compatibility-matrix.md) ያረጋግጡ። በማሰማራቱ ጥቅም ላይ የሚውለውን ትክክለኛውን CLI፣ የአውታረ መረብ አቻ ሁለትዮሽ፣ ውቅር እና የአውታረ መረብ ልቀትን በተናጠል ይሰኩ እና ይሞክሩ።
- ከመልቀቅ መስኮቱ በፊት ፈቃዶችን፣ የክፍያ ስፖንሰርሺፕን፣ የዋጋ ገደቦችን፣ ክትትልን፣ የመጠባበቂያ ሁኔታን እና የመመለሻ መስፈርቶችን ይገምግሙ።
- ከፍተኛ ተጽዕኖ ላላቸው የመጻፍ ክዋኔዎች የተጻፈ የግብይት ወይም የፍልሰት እቅድ ያስፈልግ።

## መመለስ እና መልሶ ማግኘት {#rollback-and-recovery}

- የትኞቹ ለውጦች በኮድ ማሰማራት ወደ ኋላ ሊመለሱ እንደሚችሉ፣ በሰንሰለት ላይ ግብይት የሚጠይቁ እና በቀጥታ ሊቀለበስ የማይችል ይግለጹ።
- በሰንሰለት ላይ ላሉ የውሂብ ለውጦች፣ ከመጀመሪያው ምርት ከመፃፉ በፊት የማካካሻ ግብይቶችን ወይም የፍልሰት ስክሪፕቶችን ያዘጋጁ።
- ለአውታረ መረብ ለውጦች፣ በሚለቀቅበት ጊዜ የቀደመውን ሁለትዮሽ፣ የማዋቀር ቅርቅብ፣ የተፈረመ የብሎክቼይን ጀነሲስ እና ኦፕሬሽናል runbook እንዲገኝ ያድርጉት።
- እንደ ውድቅ መጠን፣ ወረፋ እድገት፣ መዘግየት ወይም የአውታረ መረብ እኩዮች ጤና ባሉ ተጨባጭ ምልክቶች ላይ በመመስረት ልቀቱን ለማቋረጥ የውሳኔ ነጥብ ያዘጋጁ።

## የመጨረሻ ማረጋገጫ ዝርዝር {#final-checklist}

- ውቅሩ ለየአካባቢው የተለየ ነው፣ ለሙከራ ብቻ የሚያገለግሉ ሚስጥሮችንም አይዝም።
- የግብይት ድጋሚ ሙከራ ባህሪ idempotent ወይም በግልጽ የታሰረ ነው።
- አፕሊኬሽኑ ውድቅ፣ ጊዜው የሚያበቃ፣ የጊዜ ማብቂያ እና API የመጨረሻ ነጥብ ተገኝነት አለመሳካቶችን መለየት ይችላል።
- ክትትል የመተላለፊያ ችሎታን፣ መዘግየትን፣ የወረፋ ጥልቀትን፣ ውድቀትን፣ ለውጦችን እና ተዛማጅ የንግድ ክስተቶችን ይሸፍናል።
- ኦፕሬተሮች ለሚጠበቁ የውድቀት ሁነታዎች አሂድ ደብተሮች አሏቸው።
- የደህንነት ግምገማ ቁልፍ ጥበቃን፣ ፈቃዶችን፣ የአውታረ መረብ መጋለጥን እና አውቶሜሽን የፈቃድ ባለቤትን ይሸፍናል።
