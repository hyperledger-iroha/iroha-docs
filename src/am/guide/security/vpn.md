# ምናባዊ የግል አውታረ መረቦች {#virtual-private-networks}

A <abbr title="Virtual Private Network">VPN</abbr> Iroha አገልግሎቶችን ማን መድረስ እንደሚችል የሚገድብ የአውታረ መረብ ቁጥጥር ነው። አረጋጋጮች፣ የመተግበሪያ ጀርባዎች እና ኦፕሬተሮች ክፍት የኢንተርኔት መስመሮችን ከመክፈት ይልቅ በግል አድራሻዎች መገናኘት ለሚችሉበት ለግል እና ለጥምረት ማሰማራት በጣም ጠቃሚ ነው።

A VPN Iroha የአውታረ መረብ አቻ ቁልፎችን፣ የመለያ ቁልፎችን፣ ፈቃዶችን፣ የፋየርዎል ህጎችን፣ ክትትልን ወይም ደህንነቱ የተጠበቀ የቁልፍ ማከማቻን አይተካም። በ ውስጥ እንደ አንድ ንብርብር ይያዙት የማሰማራት ወሰን VPN የአውታረ መረብ ተደራሽነትን ያጠባል፣ Iroha ውቅር እና አስተዳደር የትኞቹ የአውታረ መረብ እኩዮች እና መለያዎች እንደሚታመኑ ይወስናሉ።

## መቼ መጠቀም እንዳለበት ሀ VPN {#when-to-use-a-vpn}

VPN በሚከተለው ጊዜ ይጠቀሙ -

- አረጋጋጮች የሚከናወኑት በተለያዩ ድርጅቶች ወይም በተለያዩ ማስተናገጃ አካባቢዎች ነው
- Torii ሊደረስበት የሚገባው በመተግበሪያ ጀርባዎች፣ ኦፕሬተሮች ወይም የታመኑ ደንበኞች ብቻ ነው
- መለኪያዎች፣ ምዝግብ ማስታወሻዎች፣ SSH ወይም ሌላ የአስተዳደር API የመጨረሻ ነጥቦች በግል ኦፕሬተር አውታረመረብ ላይ መቆየት አለባቸው
- የሙከራ ወይም የዝግጅት አውታረመረብ ይፋዊ API የመጨረሻ ነጥቦችን ሳያጋልጥ የምርት መዳረሻ መቆጣጠሪያዎችን መምሰል አለበት።

ለእያንዳንዱ ማሰማራት ሀ VPN አያስፈልግም። የህዝብ አውታረ መረቦች ሆን ብለው Torii ን በሕዝብ ጌትዌይ፣ በጭነት ሚዛን ወይም በተገላቢጦሽ ፕሮክሲ ሊያጋልጡ ይችላሉ። እንደዚያ ከሆነ እንኳን፣ በተቻለ መጠን አረጋጋጭ የአቻ-ለ-አቻ ትራፊክ እና አስተዳደር API የመጨረሻ ነጥቦችን በተከለከለ አውታረ መረብ ላይ ያቆዩት።

::: tip

አሳሽ VPN የሚጠብቀው ትራፊክን ከዚያ አሳሽ ብቻ ነው። እነዚያ ሂደቶች በተመሳሳይ የግል አውታረመረብ ካልተላለፉ በስተቀር `iroha3d`፣ CLI፣ SDK፣ SSH፣ መለኪያዎችን ወይም የመጠባበቂያ ትራፊክን አይከላከልም።.

:::

## የማሰማራት ንድፍ {#deployment-pattern}

ለግል አረጋጋጭ ጥልፍልፍ፣ ለእያንዳንዱ አረጋጋጭ የተረጋጋ VPN አድራሻ ወይም የግል DNS ስም ይስጡት። የማስታወቂያ የአቻ-ለ-አቻ አድራሻዎቻቸው በዚያ አውታረ መረብ ላይ ካሉ ሌሎች አረጋጋጮች እንዲደረስባቸው የአውታረ መረብ እኩዮችን ያዋቅሩ

```toml
trusted_peers = [
  "PUBLIC_KEY_1@10.20.0.11:1337",
  "PUBLIC_KEY_2@10.20.0.12:1337",
  "PUBLIC_KEY_3@10.20.0.13:1337",
  "PUBLIC_KEY_4@10.20.0.14:1337",
]

[network]
address = "10.20.0.11:1337"
public_address = "10.20.0.11:1337"

[torii]
address = "10.20.0.11:8080"
```

በ`network.address` እና `network.public_address` ውስጥ ለአሁኑ የአውታረ መረብ አቻ የተመደበውን አድራሻ ይጠቀሙ። እያንዳንዱ የአውታረ መረብ አቻ ተመሳሳይ የታመኑ የአውታረ መረብ አቻ ማንነቶችን መዘርዘር አለበት፣ ነገር ግን ከራሱ VPN የመንገድ ሠንጠረዥ ሊደረስባቸው በሚችሉ አድራሻዎች።

የደንበኛ እና CLI ውቅሮች በ VPN ወይም ቁጥጥር በሚደረግበት የውስጥ መግቢያ በር በኩል ሊደረስበት የሚችለውን Torii API የመጨረሻ ነጥብ ማመልከት አለባቸው -

```toml
torii_url = "http://10.20.0.11:8080"
```

Torii ከ VPN ውጭ መገኘት ካለበት፣ TLS፣ ማረጋገጫ፣ የፍጥነት መገደብ እና ምዝግብ ማስታወሻዎችን ከሚያቀርብ የተገላቢጦሽ ፕሮክሲ ወይም ሎድ ሚዛን ጀርባ ያስቀምጡት። ጥሬ የአቻ-ለ-አቻ ወደቦች ወይም የአስተዳደር API የመጨረሻ ነጥቦችን በቀጥታ ለህዝብ በይነመረብ ከማጋለጥ ይቆጠቡ።

## የፋየርዎል ህጎች {#firewall-rules}

VPN በሚኖርበት ጊዜም የአስተናጋጅ እና የደመና ፋየርዎል ህጎችን ይጠቀሙ -

|አገልግሎት|የሚመከር መዳረሻ|
| --- | --- |
|የአቻ-ለ-አቻ ወደብ|ሌሎች አረጋጋጭ VPN አድራሻዎች ብቻ|
|Torii|የመተግበሪያ ጀርባዎች፣ ኦፕሬተሮች ወይም የታመኑ ደንበኛ VPN ክልሎች|
|መለኪያዎች እና የጤና ምርመራዎች|በኦፕሬተር አውታረመረብ ላይ የክትትል ስርዓቶች|
|SSH እና አስተዳደር|Bastion አስተናጋጅ ፣ ልዩ ኦፕሬተር VPN ክልል ፣ ወይም መስበር መስታወት ሂደት|
|ምትኬዎች እና ማከማቻ ማባዛት|በግል አውታረመረብ ላይ የመጠባበቂያ ስርዓቶች|

ነባሪ-መከልከል ህጎች ከሰፊ የፍቃድ ህጎች ይልቅ ኦዲት ለማድረግ ቀላል ናቸው። አዲስ የአውታረ መረብ አቻ አውታረ መረቡን ሲቀላቀል የ VPN አባልነትን፣ ፋየርዎልን የፍቀድ ዝርዝር እና Iroha የታመነ የአውታረ መረብ አቻ ውቅረትን እንደ አንድ የተቀናጀ ለውጥ ያዘምኑ።

## የአሠራር ማረጋገጫ ዝርዝር {#operational-checklist}

- እንደ WireGuard፣ IPsec ወይም በድርጅት የተፈቀደ የሚተዳደር የግል አውታረ መረብ ያለ ኦዲት የተደረገ እና በንቃት የተያዘ VPN አተገባበር ይምረጡ።
- ለእያንዳንዱ አስተናጋጅ እና ኦፕሬተር ልዩ VPN ምስክርነቶችን ይጠቀሙ። የ VPN ቁልፎችን በአረጋጋጮች መካከል አያጋሩ።
- የ VPN ምስክርነቶችን ከ Iroha የግል ቁልፎች እና ከብሎክቼይን ጀነሲስ ፊርማ ቁሳቁስ ይለዩ።
- VPN መዘግየትን፣ ፓኬት መጥፋትን፣ እንደገና መገናኘትን እና የመንገድ ለውጦችን ይቆጣጠሩ። መግባባት ለቀጣይ የአውታረ መረብ አለመረጋጋት ስሜታዊ ነው።
- ውጤታማውን MTU ይሞክሩ። የፓኬት መከፋፈል የማያቋርጥ የአውታረ መረብ አቻ ወይም Torii ውድቀቶች ሊመስል ይችላል።
- የትኛዎቹ VPN ክልሎች ከአቻ ለአቻ፣ Torii፣ መለኪያዎች፣ SSH እና ምትኬ API የመጨረሻ ነጥቦች እንዲደርሱ የተፈቀደላቸው ሰነድ።
- አስተናጋጅ፣ ኦፕሬተር መለያ ወይም ድርጅት አውታረ መረቡን ለቆ ሲወጣ የ VPN ምስክርነቶችን አሽከርክር።
- በአረጋጋጮች መካከል እንደ ብቸኛው መንገድ አንድ ነጠላ VPN መግቢያ በር ያስወግዱ። ለምርት አውታረ መረቦች ተደጋጋሚ መግቢያዎችን ወይም ከጣቢያ ወደ ጣቢያ መንገዶችን ያቅዱ።
- ኦፕሬተሮች የኔትወርክ ክፍልፍልን ከ Iroha የሂደት ውድቀት መቼ እንደሚለዩ እንዲያውቁ በአደጋ ምላሽ ልምምዶች ውስጥ VPN ውድቀቶችን ያካትቱ።
