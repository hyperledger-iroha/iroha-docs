# ምስጠራ ቁልፎችን ማከማቸት {#storing-cryptographic-keys}

የእርስዎ ስሜታዊ መረጃዎች የግል ሆነው የሚቆዩት የምስጠራ ቁልፎችን ለመጠበቅ <abbr title="Operational Security">OPSEC</abbr> ልምዶችን ከተቀበሉ ብቻ ነው ። ባለሥልጣን ሆኖ የሚያገለግል ሰው የግል የምስጢር ቁልፍዎን ለመስጠት እርስዎን ለማጭበርበር የሚሞክርበት ማህበራዊ ኢንጂነሪንግ ስጋቶች እውን ናቸው ። ሁሌም ጠንቃቃ ሁኑ እና የግል ቁልፍዎን ከመጋራት ይቆጠቡ ፣ የቤትዎ ቁልፎች ለታመኑ ግለሰቦች ብቻ የተቀመጡ እንደሆኑ አድርገው ይመለከቱት ።

<abbr title="Operational Security">OPSEC</abbr> እና ምርጥ ልምዶቹን በተመለከተ ተጨማሪ መረጃ ለማግኘት [የስራ ደህንነት ](./operational-security) ን ይመልከቱ።

## ምስጠራ ቁልፎችን በዲጂታል ማከማቸት {#storing-cryptographic-keys-digitally}

ምስጢራዊ ቁልፎችን በዲጂታል ለመጠበቅ ሲመጣ በዋነኝነት ሁለት አቀራረቦች ብቻ ይገኛሉ [SSH](https://www.ssh.com/) እና [GPG](https://www.gnupg.org/)። እነዚህ ዘዴዎች ያልተፈቀደ መዳረሻን ለመከላከል የደህንነት ደረጃዎችን ይሰጣሉ ።

ብዙዎች Iroha የሕንፃ ውሳኔዎች በ ‹Secure Shell› መርሆዎች ተጽዕኖ ተደርገዋል (`SSH`) ፕሮቶኮል ፣ ለዚህም ነው በዚህ ክፍል ውስጥ በዋነኝነት ትኩረት የሚሰጠው `SSH` የክሪፕቶግራፊያዊ ቁልፎችን በመረጃ ቋቱ ውስጥ ለማከማቸት ፕሮቶኮሉን ውጤታማ በሆነ መንገድ እንዴት ተግባራዊ ማድረግ እንደሚቻል መመሪያዎችን በመስጠት Iroha ሥነ ምህዳራዊ ስርዓት።

### SSH እና SSH ወኪል በመጠቀም {#using-ssh-and-ssh-agent}

ደህንነቱ የተጠበቀ የ Shell ፕሮቶኮል (`SSH`) እንደ ምናባዊ መግቢያ ሆኖ የሚያገለግል የምስጠራ አውታረመረብ ፕሮቶኮል። SSH ቁልፎችን በመጠቀም በጣም ደህንነታቸው ባልተጠበቀ አውታረመረቦች በኩል ለርቀት ማሽኖች አስተማማኝ መዳረሻን ያስችላል ። በዚህ አውድ ውስጥ `SSH` ሁለት ዋና የማረጋገጫ ዘዴዎችን ያቀርባል-የተለመደው የይለፍ ቃል ላይ የተመሠረተ አቀራረብ እና የበለጠ ደህንነቱ የተጠበቀ የህዝብ-የግል ቁልፍ ጥንድ ዘዴ።

ስለ `SSH` ተጨማሪ መረጃ ለማግኘት [የተዛመደውን SSH አካዳሚ ርዕሰ ጉዳይ ](https://www.ssh.com/academy/ssh) ተመልከት።

የመግቢያ ሂደቱን ለማመቻቸት እና ተደጋጋሚ ግብዓት አስፈላጊነትን ለማስወገድ ፣ የ `SSH` ቁልፎችን ከ SSH ወኪል (`ssh-agent`) ጋር ማጣመር ይቻላል) የ `SSH` ቁልፎችዎን እና / ወይም የይለፍ ቃሉን ለክፍለ-ጊዜው የሚቆይ ረዳት ፕሮግራም። ይህ ቅንብር `SSH` በር ከሌሎች ማሽኖች ጋር በሚገናኝበት ጊዜ ሁሉ ቁልፎቹን በቀላሉ ለመድረስ ያስችለዋል.

እዚህ ያለው የስራ ፍሰት እንደሚከተለው ነው: የእርስዎ የህዝብ ቁልፍ በርቀት ስርዓት ላይ የተከማቸ እና የግል ቁልፍዎን ደህንነቱ የተጠበቀ ያድርጉ. ወደ ሩቅ ስርዓት ለመድረስ በሚፈልጉበት ጊዜ ሁሉ `ssh-agent` የሕዝብ ቁልፍዎን ለተቀበለው ስርዓት ለማስተላለፍ እርምጃ ይወስዳል. ከዚያ የርቀት ስርዓቱ ለግል ቁልፍዎ ብቻ በትክክል ምላሽ መስጠት የሚችል [ችግር](https://en.wikipedia.org/wiki/Challenge%E2%80%93response_authentication) ይመለሳል ። የእርስዎ `ssh-agent` የግል ቁልፉን በመጠቀም ይህንን ፈተና ያስተናግዳል እና ትክክለኛውን ምላሽ ወደ ሩቅ ስርዓት ይመልሳል። መልሱ ከስርዓቱ ከሚጠበቀው ጋር የሚስማማ ከሆነ መዳረሻ ይሰጥዎታል.

የ `ssh-agent` ውበት በስብሰባዎ ወቅት የግል ቁልፍዎን ይይዛል ፣ ስለሆነም ከርቀት ስርዓት ጋር በሚገናኙበት ጊዜ ሁሉ የይለፍ ቃልዎን ወይም የግል ቁልፍ የይለፍ ሐረግዎን ማስገባት አያስፈልግም ።

ስለ `ssh-agent` ተጨማሪ መረጃ ለማግኘት [የተዛመደውን SSH አካዳሚ ርዕሰ ጉዳይ](https://www.ssh.com/academy/ssh/agent) ተመልከት።

::: info ማስታወሻ

የ `SSH` ፕሮቶኮል እና የ `ssh-agent` መሳሪያ ዝርዝር አጠቃላይ እይታ ለማግኘት የሚከተሉትን [SSH አካዳሚ ](https://www.ssh.com/academy) ርዕሶች ይመልከቱ:

  - [ምንድን ነው SSH (የደህንነት ሼል) ?](https://www.ssh.com/academy/ssh)
  - [ssh-ወኪል: እንዴት ssh-ውኪል, ወኪል ማስተላለፍ, እና ወኪል ፕሮቶኮል ማዋቀር እንደሚቻል](https://www.ssh.com/academy/ssh/agent)

:::

### የይለፍ ቃል አስተዳዳሪ ፕሮግራም ማከል {#adding-a-password-manager-program}

የ `SSH` ቁልፎችዎን ደህንነት በፓስዎርድ በመጠበቅ እንዲሻሻሉ ይመከራል ፣ ይህም የእርስዎን ስሜታዊ መረጃ ለማግኘት በሚፈልጉ ተንኮለኛ አካላት መንገድ ላይ ተጨማሪ እንቅፋት ሆኖ ያገለግላል።

ለተጠቃሚዎች የይለፍ ቃሎችን እና `SSH` ቁልፎችን ጊዜያዊ በሆነ መንገድ ለማከማቸት የተለያዩ የይለፍ ቃል አስተዳዳሪዎችን መጠቀም ይቻላል ። ለግልፅነት ሲሉ ፣ [KeePass](https://keepass.info/) እንደ ምሳሌ የይለፍ ቃል ሥራ አስኪያጅ ሆኖ ጥቅም ላይ ይውላል ፣ በተለይም በሊነክስ ላይ የተመሠረተ ኦፕሬቲንግ ሲስተሞች ላይ የሚሠራው የ [KeePassXC ](https://keepassxc.org/) ወደብ።

KeePassXC እንዴት ማዋቀር እንደሚቻል መመሪያ ለማግኘት ከዚህ በታች ያለውን [Configuring KeePassXC](#configuring-keepassxc) ክፍል ተመልከት.

![KeePassXC: `Main` ማያ ገጽ UI](../../../img/KeePassXC.png)

KeePassXC የተሻሻለ ደህንነት, ተለዋዋጭነት እና ቁጥጥርን ያቀርባል. የይለፍ ቃሎችን ብቻ ሳይሆን የ `SSH` ቁልፎችንም ያስቀምጣል. ለቁልፍ ማከማቻ ጥቅም ላይ በሚውልበት ጊዜ ይህ የይለፍ ቃል አስተዳዳሪ ለተከማቹ ቁልፎች `ssh-agent` ይሰጣል, የ KeePassXC መስኮት ከተዘጋ በኋላ ወዲያውኑ ከሜሞሪው ውስጥ ይወገዳሉ።

::: ጫፍ

በንድፈ ሀሳብ, ማንኛውም KeePass ወደቦች [በኦፊሴላዊ ድረ ገጽ ላይ የተዘረዘሩ](https://keepass.info/download.html) ለቁልፍ ማከማቻ ዓላማዎች ጥቅም ላይ ሊውል ይችላል. [KeePassX](https://www.keepassx.org/) ወይም [KeePassXC](https://keepassxc.org/).

:::

#### KeePassXC ን ማዋቀር {#configuring-keepassxc}

KeePassXC ን ለማዋቀር የሚከተሉትን እርምጃዎች ይከተሉ:

1. KeePassXC ን ይጀምሩ፣ ከዚያም ወደ መሣሪያዎች > ቅንብሮች ይሂዱ ወይም ከላይ ባለው UI ፓነል ላይ ያለውን የመሣሪያ አዝራር ይምረጡ።

2. በሚታየው የመተግበሪያ ቅንብሮች ትር ውስጥ ከግራ ምናሌው SSH ወኪል ይምረጡ፣ ከዚያም SSH ወኪል ማዋሃድ እንዲቻል ያድርጉ የሚለውን የቼክ ሳጥን ይምረጡ።

   ::: info የማጣቀሻ ቅጽበታዊ ገጽ እይታን አሳይ

   ![KeePassXC `SSH Agent` ትር: SSH ኤጀንት](../../../img/keepassxc_ssh_agent.png) እንዲፈቅድ ማድረግ

   :::

3. አዲስ KeePassXC የመረጃ ቋት ይፍጠሩ። መመሪያ ለማግኘት [KeePassXC የተጠቃሚ መመሪያ ተመልከት > የመጀመሪያ የመረጃ ቋቱን መፍጠር ](https://keepassxc.org/docs/KeePassXC_UserGuide#_creating_your_first_database).

4. በፈጠርከው KeePassXC የመረጃ ቋት ውስጥ ለማከማቸት የሚፈልጉትን እያንዳንዱ ቁልፍ የሚከተሉትን ደረጃዎች ይከተሉ:

   - በመረጃ ቋቱ ውስጥ አዲስ መግቢያ ይጨምሩ. መመሪያ ለማግኘት [KeePassXC የተጠቃሚ መመሪያ > የመጀመሪያ የመረጃ ቋትዎን መፍጠር ](https://keepassxc.org/docs/KeePassXC_UserGuide#_creating_your_first_database) ይመልከቱ።

   - አዲስ መግቢያ ሲጨምሩ የሚከተለውን በማድረግ ቁልፉን የያዘውን ፋይል ያያይዙ: ከግራ ምናሌው ውስጥ የተራቀቁን ይምረጡ, ከዚያም በመያዣዎች ክፍል ውስጥ ይጨምሩ የሚለውን ይምረጡ. በሚታየው የ "ፋይሎችን ይምረጡ" መስኮት ውስጥ የሚፈለገውን ፋይል ይምረጡ።

   - አዲስ ማስገቢያ ሲጨምሩ ከግራ ምናሌው SSH ወኪል ይምረጡ፤ ከዚያም የግል ቁልፍ ክፍል ውስጥ ካለው አባሪ ምናሌ የጨመረው ቁልፍ ፋይል ይምረጡ፣ ከዚያም የሚከተሉትን የመለያ ሳጥኖች ይምረጡ:

      - የመረጃ ቋቱ ሲከፈት/እንደሚከፈት ለኤጀንት ቁልፍ ይጨምሩ

      - የመረጃ ቋቱ በሚዘጋ/በተቆለፈበት ጊዜ ቁልፉን ከኤጀንት ያስወግዱ

      - ይህ ቁልፍ ጥቅም ላይ ሲውል የተጠቃሚ ማረጋገጫ ይጠይቁ

   - አስፈላጊ ሆኖ ሲገኝ ሌሎች ለውጦች ማድረግ።

   - ሲዘጋጅ OK የሚለውን ይምረጡ፤ ይህ መረጃ ለማስቀመጥ።

##### የሚጠበቁ ውጤቶች {#expected-results}

- የ KeePassXC መስኮት ክፍት ሆኖ ሳለ ሊደረስበት በሚችል KeePassXC የመረጃ ቋት ውስጥ እንደ መግቢያዎች የሚከማቹ ምስጠራ እና `shh` ቁልፎች።

- የተከማቹ የክሪፕቶግራፊ እና `ssh` ቁልፎች ለፍቃድ አስፈላጊ በሚሆኑበት ጊዜ ሁሉ ሊጠቀሙባቸው ይችላሉ ።

- የ KeePassXC መስኮት ከተዘጋ በኋላ የተከማቹ ምስጠራ ቁልፎች እና `ssh` ቁልፎች ከ `ssh-agent` ይወገዳሉ ።

::: info ማስታወሻ

ይህ ቁልፍ ጥቅም ላይ በሚውልበት ጊዜ የተጠቃሚ ማረጋገጫ ይጠይቁ የሚለውን አማራጭ ሳያበራ፣ `ssh-agent` የይለፍ ቃል አስተዳዳሪው ሂደት በማልዌር የተቋረጠ ከሆነ ወይም የስርዓት አገልግሎት በ `SIGKILL` ሲግናል, ቁልፉ ምናልባት በ ውስጥ ይቆያል `ssh-agent`, የዩኒክስ ሥርዓት ፕሮግራሞች መቋረጥ ስለማይችሉ `SIGKILL`.

:::

## የክሪፕቶግራፊ ቁልፎችን በአካል ማስቀመጥ {#storing-cryptographic-keys-physically}

ከመስመር ውጪ ከፍተኛውን የደህንነት ደረጃ ለሚፈልጉ ሰዎች ፣ ምስጢራዊ ቁልፎችን የማከማቸት አማራጭ ቁልፎቹ ከዲጂታል አውታረመረቦች ሙሉ በሙሉ እንደተገለሉ ያረጋግጣል ፣ ስለሆነም ያልተፈቀደ መዳረሻ አደጋን ይቀንሳል ። አካላዊ አማራጩን መገንዘብ የተለያዩ የደህንነት ፍላጎቶችን ለማሟላት ያለንን ቁርጠኝነት ያጎላል።

### የሃርድዌር ቁልፍ መጠቀም {#using-a-hardware-key}

የእኛ ቡድን የሃርድዌር ቁልፎች ምርጥ የደህንነት እርምጃዎች መካከል አንዱ እንደሆነ ይቆጥራል. አንድ ሃርድዌር መክፈቻ በ USB ወደብ በኩል የሚያገናኝ እና የተለመደ ፍላሽ ድራይቭ መጠን ያለው የታመቀ መሣሪያ ነውወደ ማሽን ሲገናኝ ብቻ የደህንነት ጋር ተያያዥነት ያላቸውን ክስተቶች ያከናውናል. ይህ መሣሪያውን የደህንነት ጥሰት በሚከሰትበት ጊዜ በቀላሉ ለማቋረጥ ወይም በተፈለገው ጊዜ በቀላሉ ወደ ሌላ ማሽን እንደገና ለማገናኘት ያስችልዎታል ።

ሆኖም ፣ ብዙ የምርት ስም የሃርድዌር ቁልፎች ስላሉ እያንዳንዳቸው ልዩ የሆኑ APIs የእርስዎ ፍላጎቶች በጣም የሚስማማውን ቁልፍ ለማግኘት የገበያ ጥናት ማድረግ አስፈላጊ ነው ።

እስካሁን ድረስ ቡድናችን [YubiKey 5C](https://www.yubico.com/il/product/yubikey-5c/) ሃርድዌር ቁልፍን በቤት ውስጥ ሞክሯል ይህም ሁለገብ የሆነውን API ተግባርን ጨምሮ ብዙ አዎንታዊ ባህሪዎች እንዳሉት ተረጋግጧል ።

ይሁን እንጂ ሊታሰብበት የሚገባ አንድ ችግር አለ። የ [HMAC ፈተና-ምላሽ ማረጋገጫ](https://en.wikipedia.org/wiki/Challenge%E2%80%93response_authentication)ን ተግባራዊ ማድረግ እና ለዚህ ምላሽ የሚዛመድ የግል ቁልፍ ማከማቸት ተጋላጭነት ሊፈጥር ይችላል ። ይህ አቀማመጥ አጥቂዎች በ YubiKey 5C ማህደረ ትውስታ ውስጥ ስለተከማቹ መረጃዎች የተማሩ ግምቶችን እንዲያደርጉ ሊያደርግ ይችላል ፣ በዚህም አጠቃላይ ደህንነትን አደጋ ላይ ሊጥል ይችላል ።

እንደ እድል ሆኖ ፣ ይህ ተጋላጭነት YubiKey 5C ን ለመጠቀም አማራጭ አቀራረብን በመከተል ሊቀንስ ይችላል ። ሀሳቡ የ YubiKey 5C ን በመጠቀም የእርስዎን ምስጠራ እና `SSH` ቁልፎችን የሚይዝ ወደ KeePassXC የመረጃ ቋት ደህንነቱ የተጠበቀ መዳረሻ ማድረግ ነው ። ይህ ዘዴ ጠቃሚ እንደሆነ ተደርጎ ሊወሰድ ይችላል ፣ ምክንያቱም የአብዛኛዎቹ የይለፍ ቃሎች ደህንነትን ስለሚበልጥ እና KeePassXC የመረጃ ቋት በሚለቀቅበት ጊዜ ተንኮል አድራጊው የሃርድዌር ቁልፍዎን እንዲይዝ አስፈላጊ ያደርገዋል።
