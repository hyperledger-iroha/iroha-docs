# I105 የመለያ አድራሻ ቅርጸት {#i105-account-address-format}

I105 ለ Iroha 3 `AccountId` ነጠላ ፕሮቶኮል-መደበኛ ውጫዊ የጽሑፍ ቅርጸት ነው።

የእሱ ጭነት የመለያ መቆጣጠሪያውን ይወክላል።

የእሱ ጠባቂ የታሰበውን አውታረ መረብ በሰንሰለት መለያየት ይለያል።

API፣ ግብይት፣ ፍቃድ ወይም መጠይቅ አንድ ፕሮቶኮል-መደበኛ መለያ መታወቂያ በሚጠይቅበት ቦታ ሁሉ ይጠቀሙበት።

I105 መለያ መታወቂያ ጎራ የሌለው ነው።

እንደ `treasury@payments.universal` ያለ እሴት የመለያ ተለዋጭ ስም እንጂ ሌላ የ I105 መታወቂያ አጻጻፍ አይደለም።.

I105 መታወቂያ ማግኘት መለያውን አይመዘግብም ወይም አይደግፍም።

::: warning አብዛኛዎቹን የውህደት ውድቀቶችን የሚከላከሉ ህጎች

- አድራሻን ከመቀየርዎ ወይም ከማረጋገጥዎ በፊት የአውታረ መረብ መገለጫውን ይምረጡ።
- ነጠላ ፕሮቶኮል-ስታንዳርድ UTF-8 ሕብረቁምፊን በትክክል ያከማቹ እና ያወዳድሩ።
- የፊደሎችን አቢይና ንዑስ ሆሄ ሁኔታ ይጠብቁ እና የ `Unicode` መደበኛነትን አይተግብሩ።
- I105 መታወቂያ `@domain` ወይም `@domain.dataspace` ቅጥያ ሊኖረው አይገባም።
- Iroha SDK ወይም `iroha tools address` ይጠቀሙ።
- መደበኛ አገላለጽ I105 አረጋጋጭ አይደለም።

:::

## ቃል በቃል የሰውነት አካል {#literal-anatomy}

አንድ I105 ቃል በቃል ሦስት ተያያዥ ክፍሎች አሉት እና መለያየት የለውም -

```text
<network sentinel><base-105 canonical payload><six checksum symbols>
```

ጭነቱ እና ቼክ ድምር የመለያውን መቆጣጠሪያ ይለያሉ።

ጠባቂው የአውታረ መረብ አውድ ይመርጣል።

ተመሳሳይ ተቆጣጣሪ በ Taira እና Minamoto ላይ ተመሳሳይ ጭነት እና ቼክሰም አለው፣ ነገር ግን እያንዳንዱ አውታረ መረብ የተለየ መሪ ጠባቂ ይጠቀማል።

ዲኮደር የሚጠበቀውን ልዩነት ማስፈጸም አለበት።

ቼክ ድምር የሴንቲነል ምትክን መለየት አይችልም።

እንደ `n00042`፣ `n369`፣ `n753` እና `n0` ያሉ ቅጾች ነጠላ ፕሮቶኮል-ደረጃ አይደሉም።

የግብይት-ሰንሰለት መታወቂያ እና I105 ሰንሰለት መለያየት የተለያዩ እሴቶች ናቸው።

API የመጨረሻ ነጥብ ወይም የሰንሰለት መታወቂያ መምረጥ በተዘዋዋሪ የአድራሻውን መገለጫ አይመርጥም።

## መደበኛ ነጠላ-ቁልፍ ምሳሌ {#normative-single-key-example}

ከታች ያለው ጭነት እና Minamoto ቅጽ የሚመጣው ከ SDK-አቋራጭ ተገዢነት የሙከራ ውሂብ ነው።

የ Taira ቅጽ Taira ሴንቲነልን ለተመሳሳይ ጭነት ይፈጻል -

```text
Public-key payload:
3B6A27BCCEB6A42D62A3A8D02A6F0D73653215771DE243A63AC048A18B59DA29

Public-key multihash accepted by tooling:
ed01203B6A27BCCEB6A42D62A3A8D02A6F0D73653215771DE243A63AC048A18B59DA29

Canonical account payload:
0x020001203b6a27bcceb6a42d62a3a8d02a6f0d73653215771de243a63ac048a18b59da29

Minamoto I105, discriminant 753:
sorauﾛ1NﾗhBUd2BﾂｦﾄiﾔﾆﾂﾇKSﾃaﾘﾒﾓQﾗrﾒoﾘﾅnｳﾘbQｳQJﾆLJ5HSE

Taira I105, discriminant 369:
testuﾛ1NﾗhBUd2BﾂｦﾄiﾔﾆﾂﾇKSﾃaﾘﾒﾓQﾗrﾒoﾘﾅnｳﾘbQｳQJﾆLJ5HSE
```

ነጠላ ፕሮቶኮል-መደበኛ ጭነት የሚጀምረው በ `02 00 01 20` ራስጌ `0x02`፣ የታመቀ ነጠላ-ቁልፍ መለያ `0x00`፣ `Ed25519` ከርቭ መታወቂያ `0x01` እና ባለ 32-ባይት ቁልፍ ርዝመት `0x20`።

የ`multihash` ቅድመ ቅጥያ የግቤት ሜታዳታ ነው እና ወደ መቆጣጠሪያው ጭነት አልተገለበጠም።

## መታወቂያዎችን በ CLI ይፍጠሩ እና ይፈትሹ {#create-and-inspect-ids-with-the-cli}

ለህዝብ አውታረ መረብ የተሰየመ መገለጫ ይምረጡ -

```bash
PUBLIC_KEY='ed01203B6A27BCCEB6A42D62A3A8D02A6F0D73653215771DE243A63AC048A18B59DA29'

TAIRA_ACCOUNT_ID="$(
  iroha tools address convert --profile taira "$PUBLIC_KEY"
)"

MINAMOTO_ACCOUNT_ID="$(
  iroha tools address convert --profile minamoto "$PUBLIC_KEY"
)"
```

የአድራሻ-ኮዴክ ባህሪን በሚመረምሩበት ጊዜ የ I105 ግቤትን መደበኛ ያድርጉት እና ያወዳድሩ -

```bash
NORMALIZED_ACCOUNT_ID="$(
  printf '%s\n' "$TAIRA_ACCOUNT_ID" \
    | iroha tools address normalize --profile taira
)"

test "$NORMALIZED_ACCOUNT_ID" = "$TAIRA_ACCOUNT_ID"
```

የተገኘውን ቅርጸት፣ ነጠላ ፕሮቶኮል-ስታንዳርድ ሄክስ እና የተመረጠውን የአውታረ መረብ አውድ እንደ JSON ይፈትሹ

```bash
iroha tools address convert \
  --profile taira \
  --format json \
  "$TAIRA_ACCOUNT_ID"
```

የትንታኔ ውድቀቶችን በጸጥታ ሳይቀበሉ አዲስ መስመር-የተለየ ፋይል የአድራሻ-ኮዴክ መዋቅርን ኦዲት ያድርጉ -

```bash
iroha tools address audit \
  --profile taira \
  --input account-ids.txt \
  --format json
```

::: caution CLI የማረጋገጫ ድንበር

የ `convert`፣ `normalize` እና `audit` ትዕዛዞች በዝቅተኛ ደረጃ `AccountAddress` ኮዴክ ላይ ይሰራሉ።

ሴንቲነልን፣ ፊደላትን፣ ቼክሰምን፣ የባይት ርዝመቶችን፣ `CurveId`/የቁልፍ ቅርፅን እና ትክክለኛውን የአድራሻ-ንብርብር ድጋሚ ኢንኮዲንግ ያረጋግጣሉ።

እነሱ አይፈጽሙም `AccountId`.

ሁሉንም የብዝሃ ፖሊሲ ትርጓሜዎች በራሳቸው አያረጋግጡም።

የራስጌው ክፍል ከመቆጣጠሪያው ጋር መዛመዱን አያረጋግጡም።

ከፈቃድ መስጠት ወይም ከማከማቸት በፊት ጥብቅ `AccountId` ማረጋገጫ ይጠቀሙ።

:::

ለግል አውታረ መረብ፣ የተዋቀረውን ልዩ መለያ በ `--network-prefix` በግልጽ ይጠቀሙ።

አንድን ነባር አድራሻ በግልጽ አውዶች መካከል ሲቀይሩ፣ ምንጩንም በ `--expect-prefix` ያቅርቡ፦

```bash
iroha tools address convert \
  --expect-prefix 369 \
  --network-prefix 753 \
  "$TAIRA_ACCOUNT_ID"
```

እንደገና ኢንኮዲንግ የአውታረ መረቡን አውድ ብቻ ይለውጣል።

መለያውን በዒላማው አውታረመረብ ላይ አይመዘግብም ወይም ተመሳሳይ መቆጣጠሪያ እዚያ እንደገና ጥቅም ላይ መዋል እንዳለበት አያረጋግጥም.

## ኢንኮዲንግ አልጎሪዝም {#encoding-algorithm}

ነጠላ ፕሮቶኮል-መደበኛ ኢንኮደሮች እነዚህን ስራዎች ያከናውናሉ -

```text
canonical = header || controller
payload_digits = base_convert(canonical, base_256, base_105)
checksum_digits = bech32m_6(hrp = "snx", convert_8_to_5(canonical, pad = true))
literal = sentinel(discriminant) || alphabet[payload_digits || checksum_digits]
```

መሪ ዜሮ ባይት እንደ ዜሮ ዋጋ ያላቸው `base-105` አሃዞች ተጠብቀዋል።

ቼክ ድምር `Bech32` `polymod` ጄነሬተሮችን እና ቋሚ `0x2bc830a3` ይጠቀማል።

የቼክሰም-ብቻ HRP ASCII ሕብረቁምፊ `snx` ነው።

የቼክሰም-ብቻ HRP በአድራሻው ውስጥ አልታተመም።

ስድስቱ የቼክሰም እሴቶች በክልል `0..31` ውስጥ ናቸው እና ከጭነቱ ጋር በተመሳሳይ I105 ፊደል ይቀርባሉ።

### I105 ፊደል {#i105-alphabet}

105ቱ ምልክቶች በዚህ ትክክለኛ ቅደም ተከተል ተጠቁመዋል።

የመጀመሪያው ረድፍ `Bitcoin Base58` ፊደል ሲሆን አሃዞችን `0..57` ይዟል።

ሁለተኛው ረድፍ አሃዞችን ይዟል `58..104`.

ኮዴክን በሚተገብሩበት ጊዜ ረድፎቹን ያጣምሩ.

```text
123456789ABCDEFGHJKLMNPQRSTUVWXYZabcdefghijkmnopqrstuvwxyz
```

ፊደላት `Unicode` ስሜታዊ ነው።

ትክክለኛው ቅደም ተከተል `compatibility-width` የጃፓን `kana` ምልክቶችን እና ለ `ヰ` እና `ヱ` የሚታዩትን የኮድ ነጥቦችን ይጠቀማል።

NFC፣ NFKC፣ የስፋት ልወጣ፣ የአቢይ/ንዑስ ፊደል ማጠፍ ወይም ተመሳሳይ መልክ ባለው ቁምፊ መተካት አይተግብሩ።

ASCII `0`፣ `O`፣ `I` እና `l` የፊደል ምልክቶች አይደሉም።

## ነጠላ ፕሮቶኮል-መደበኛ መለያ ጭነት {#canonical-account-payload}

የ`base-105` አካል የሁለትዮሽ መለያ ጭነት እንጂ የህዝብ ቁልፍ ሕብረቁምፊ እና Norito JSON ነገር አይደለም።

```text
header:u8 || controller:variable
```

ከታች ያሉት ሁሉም ባለብዙ ባይት ኢንቲጀሮች ያልተፈረሙ እና `big-endian` ናቸው።

ጎራ፣ ዳታ ቦታ፣ ተለዋጭ ስም፣ UAID እና የመለያ ሜታዳታ ባይት አይገኙም።

### የራስጌ ባይት {#header-byte}

|ቢት|ስፋት|የአሁኑ የኢንኮደር ውፅዓት|ትርጉም|
| ------ | ----: | ---------------------------: | ---------------------------- |
| `7..5` |     3 |                          `0` |የአድራሻ አቀራረብ ስሪት ሜዳ|
| `4..3` |     2 |`0` ነጠላ ቁልፍ፣ `1` multisig|የአድራሻ ክፍል|
| `2..1` |     2 |                          `1` |መደበኛነት ስሪት መስክ|
| `0`    |     1 |                          `0` |የተጠበቁ `extension flag`|

የአሁኑ V1 ኢንኮደሮች ለአንድ ቁልፍ መቆጣጠሪያ ራስጌ `0x02` እና `0x0a` ለባለብዙ ሲግ መቆጣጠሪያ ያመነጫሉ።

የአድራሻ ክፍሎች `2` እና `3` አልተመደቡም።

አንድ `extension flag` የ `1` ውድቅ ተደርጓል።

ዝቅተኛ ደረጃ ዲኮደር ሌሎች ስሪት እና መደበኛነት ቢት እሴቶችን ማቆየት ይችላል እና ክፍሉን በተናጥል ከመቆጣጠሪያው መለያ ጋር አያረጋግጥም።

ወደ `AccountId` መቀየር እና ነጠላ ፕሮቶኮል-ደረጃውን የጠበቀ አተረጓጎሙን ማወዳደር የአሁኑን V1 ከነጠላ ፕሮቶኮል-መደበኛ ቅጽ ጋር መከበራቸውን ያረጋግጣል።

### ባለብዙ ሲግ መቆጣጠሪያ {#multisig-controller}

እያንዳንዱ የአባል መዝገብ የሚከተለው ነው-

|መስክ|ስፋት|ትርጉም|
| ------------ | --------------: | ------------------------ |

ትክክለኛ ፖሊሲ ቢያንስ አንድ አባል፣ አዎንታዊ ክብደቶች፣ ያልተደጋገሙ የሕዝብ ቁልፎች እና ከ `1` እስከ የአባላት ክብደት ድምር ያለ ገደብ አለው።


```text
member_sort_key = stable_algorithm_name || 0x00 || raw_public_key
```

I105 ቃል በቃል ምንም ቋሚ የቁምፊ ርዝመት የለውም ምክንያቱም መልቲሲግ እና ድህረ-ኳንተም ተቆጣጣሪዎች ትልቅ ሊሆኑ ይችላሉ።.

## ጥብቅ AccountId ማረጋገጫ እና ነጠላ ፕሮቶኮል-መደበኛ ቅጽ ማክበር {#strict-accountid-validation-and-canonicality}

SDK ን ከሚጠበቀው ሰንሰለት ጋር ካዋቀሩ በኋላ ወደ `AccountId` ይተንትኑ እና የተመለሰውን ነጠላ ፕሮቶኮል-ስታንዳርድ አተረጓጎም ከተከረከመው ግቤት ጋር ያወዳድሩ።

ንፅፅሩ ጠቃሚ ነው ምክንያቱም ተንታኙ `AccountId` በሚገነባበት ጊዜ ሊገለጽ የሚችል የመቆጣጠሪያ ቁሳቁስን መደበኛ ማድረግ ይችላል።

```rust
use eyre::{ensure, Result};
use iroha::data_model::prelude::AccountId;

fn parse_canonical_account_id(input: &str) -> Result<AccountId> {
    let input = input.trim();
    let parsed = AccountId::parse_encoded(input)?;

    ensure!(
        parsed.canonical() == input,
        "account ID is valid but not in its current canonical I105 form"
    );

    Ok(parsed.into_account_id())
}
```

ለማይታመን ሕብረቁምፊ፣ የሚስማማ መተግበሪያ የሚከተሉትን ማድረግ አለበት -

1. በተሟላው እሴት ዙሪያ ነጭ ቦታን ብቻ ማጓጓዝ ይከርክሙ።
2. ሴንቲነሉን ያንብቡ እና የሚጠበቀውን ሰንሰለት ልዩነት ይጠይቁ።
3. እያንዳንዱን የቀረውን `Unicode` ምልክት በትክክለኛው ባለ 105 ምልክት ፊደል ካርታ ያድርጉ።
4. ስድስቱን የቼክ ድምር አሃዞች ይከፋፍሉ።
5. የጭነት አሃዞችን ወደ ነጠላ ፕሮቶኮል-መደበኛ ባይት ይለውጡ።
6. በእነዚያ ነጠላ ፕሮቶኮል-መደበኛ ባይቶች ላይ የቼክ ድምርን ያረጋግጡ።
7. ራስጌውን እና መቆጣጠሪያውን ይተንትኑ፣ የሚጠይቁትን ይጠይቃል
   - ትክክለኛ የመስክ ርዝመቶች
   - የሚደገፍ `CurveId`
   - የሚሰራ የህዝብ ቁልፍ
   - ምንም ተከታይ ባይት የለም።
   - አስፈላጊ ሆኖ ሲገኝ የሚሰራ የባለብዙ SIG መመሪያ
8. `AccountId` ይገንቡ።
9. ለሚጠበቀው ልዩነት `AccountId` በነጠላ ፕሮቶኮል-መደበኛ ቅጽ ያቅርቡ።
10. ከተከረከመው ግብዓት ጋር `byte-for-byte` እኩልነትን ይጠይቁ።

የመተግበሪያው ግልጽ የመጨረሻ `render-and-compare` እርምጃ አነስተኛ ያልሆኑ የቁጥር ጠባቂዎችን፣ ነጠላ ያልሆኑ ፕሮቶኮል-ደረጃውን የጠበቀ የመቆጣጠሪያ አቀማመጦችን፣ እንደገና የታዘዙ የፖሊሲ ቁሳቁሶችን እና ሌላ ማንኛውንም የፊደል አጻጻፍ የሚፈታ ነገር ግን የኢንኮደሩ የአሁኑ V1 ውፅዓት ያልሆነን ውድቅ ያደርጋል።

የተሳካ የቼክ ድምር ወይም ዝቅተኛ ደረጃ `AccountAddress` ትንታኔ የዚህ ቼክ ምትክ አይደለም።

እነዚህን እሴቶች በጥብቅ የመለያ-መታወቂያ መስክ ውስጥ አይቀበሉ -

- እንደ `alice@wonderland.universal` ያለ መለያ ተለዋጭ ስም
- I105 ቃል በቃል ከተጨመረው `@domain` ቅጥያ ጋር
- እንደ `ed0120...` ያሉ የህዝብ ቁልፍ `multihash`
- ነጠላ ፕሮቶኮል-መደበኛ ጭነት ሄክስ እንደ `0x02000120...`
- ለተሳሳተ ሰንሰለት መለያየት አድራሻ
- አቢይ ወይም ንዑስ ፊደሎች፣ የቁምፊ ስፋቶች፣ `kana`፣ የፍጆታ ጭነት ወይም የቼክ ድምር የተቀየረበት ሕብረቁምፊ

በማመልከቻው ወሰን ላይ ተለዋጭ ስሞችን ይፍቱ እና የተመለሰውን ነጠላ ፕሮቶኮል-ስታንዳርድ I105 መታወቂያ ለፍቃድ፣ ለመፈረም፣ ለፈቃዶች እና ለኦዲት መዝገቦች ያቆዩ።

## API፣ የማከማቻ እና የማሳያ ህጎች {#api-storage-and-display-rules}

- ትክክለኛውን I105 UTF-8 ሕብረቁምፊ በ JSON መለያ መስኮች ውስጥ ይላኩ።
- `Percent-encode` በ URL የመንገድ ክፍል ውስጥ ከማስቀመጥዎ በፊት የተሟላ መለያ መታወቂያ።
- የመለያ ተለዋጭ ስም በ I105 መታወቂያ በጭራሽ አይተኩ።
- በኮዴክ የተመለሰውን ነጠላ ፕሮቶኮል-ስታንዳርድ ሕብረቁምፊ ከ`byte-preserving` የንፅፅር ትርጓሜዎች ጋር ያከማቹ።
- የፊደላትን አቢይ/ንዑስ ሁኔታ እና የቁምፊዎችን ስፋት የሚጠብቅ የማነጻጸሪያ ደንብ ይጠቀሙ።
- ሰንሰለቱን ወደ ውጭ ከተላከ የመለያ ውሂብ እና ምትኬዎች ጋር የተለየ ወይም የተሰየመ የአውታረ መረብ መገለጫ ያቆዩት።
- አድራሻን ከአውታረ መረቡ አውድ ጋር ብቻ እንደገና ይጠቀሙ።
- ሙሉውን አድራሻ አሳይ እና የቅጂ እርምጃ ያቅርቡ።
- እያንዳንዱን `kana` ቁምፊ በትክክል ጠብቅ።
- የታመቀ ማሳያ መካከለኛውን ክፍል ሲያሳጥር ሙሉውን አድራሻ እንዲገኝ ያድርጉ።
- ከቅጽል ስም እንደገና ከመገንባት ይልቅ የተከማቸውን ካኖኒካል ID ይጠቀሙ።

የ `AccountId` ማሳያ እና JSON ካኖኒካል I105 ይጠቀማሉ።

የታችኛው ደረጃ `AccountAddress` ማሳያ/JSON ውክልና ለውስጣዊ እና ለማረም አውዶች ነጠላ ፕሮቶኮል-መደበኛ ሄክስን ይጠቀማል።

የውጭ መለያ መታወቂያ በሚያስፈልግበት ጊዜ ግልጽ የሆነውን `AccountAddress` I105 ኢንኮደር ይደውሉ።

ለመለያ ፈጠራ እና ተለዋጭ ስም አፈታት የስራ ፍሰቶች፣ በ[መለያዎች እና ተለዋጭ ስሞች](/am/cookbook/accounts-and-aliases.md) ይቀጥሉ።
