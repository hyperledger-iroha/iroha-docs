# Norito {#norito}

Norito ነው Iroha ይህ በፓር ጊዜ ጥቅም ላይ የዋለው ባይት ቅርጸት ነው, SDKs, CLI መሳሪያዎች፣ Torii, Kura, የተፈጠሩ ዕቃዎችም በተመሳሳይ ጥቅማጥቅሞች ላይ መስማማት አለባቸው።

Norito ን ይጠቀሙ መረጃው የጋራ ስምምነት ፣ ፊርማ ፣ ሃሺንግ ፣ መቋቋም ወይም መስቀለኛ SDK በይነተገናኝነት አካል በሚሆንበት ጊዜ። አንድ የመጨረሻ ነጥብ ለኦፕሬተሮች ፣ ለዳሽቦርድዎች ወይም ፈጣን ማረም በግልጽ ሊነበብ የሚችል ትንበያ ሲያቀርብ JSON ን ይጠቀሙ ።

## የቅጥያ ባንዲራዎች {#layout-flags}

Norito የመጨረሻው ራስጌ ባይት ውስጥ አቀማመጥ አማራጮችን ያስቀምጣል ። ነባሪ የ v1 ረዳቶች ለኮምፓክት በዋጋ ርዝመት ቅድመ ዝግጅቶች `COMPACT_LEN` (`0x02`) ያወጣሉ ። ጠሪዎች በ `flags = 0x00` ሲቀዱ ግልፅ ቋሚ-ሰፊ ርዝመት prefixes ሊነበብ ይችላል ።

## የኮዲንግ ደንቦች {#encoding-rules}

Norito በ Iroha የውሂብ ሞዴል ውስጥ ለሚታዩት የተለመዱ የመረጃ ቅርጾች የሚወስኑ አቀማመጦችን ይጠቀማል-

- ገመዶች `[len][utf8-bytes]` ናቸው; `len` ከተቻለ `COMPACT_LEN` ይከተላል.
- `COMPACT_LEN` ሲዘጋጅ በአንድ እሴት ርዝመት ላይ የታመቀ ቀለም ይጠቀማል.
- `COMPACT_LEN` በሌለበት ጊዜ በአንድ እሴት ርዝመት 8-ባይት አነስተኛ ኢንዲያን `u64` ነው.
- የቅደም ተከተል ርዝመት ራስጌዎች በ v1 ውስጥ የተስተካከሉ 8-ባይት አነስተኛ ኢንዲያን `u64` ናቸው.
- `Vec<u8>` በአንድ ባይት ውስጥ ከአንድ ርዝመት ይልቅ `[len_u64][raw-bytes]` ተብሎ ይከፈታል.
- የታሸጉ ቅደም ተከተሎች `(len + 1)` ሞኖቶኒክ `u64` ኦፕሰቶችን ይጠቀማሉ ፣ ከዚያ በኋላ የተጣበቁ የኤሌክትሪክ ጭነቶች ይከተላሉ ።
- ካርታዎች የቤት ውስጥ ማስገቢያ ቁጥሮች በ ቋሚ `u64` እና የተወሰነ ቁልፍ ቅደም ተከተል ይጠቀማሉ. `HashMap` ግቤቶች ከመቀየራቸው በፊት በቁልፍ ይመደባሉ; `BTreeMap` ተፈጥሮአዊ ቅደም ተከተሉን ይጠቀማል.
- `BigInt` በ `u32` ባይት ርዝመት እና በ 512 ቢት ካፒ ጋር አነስተኛ የሁለት-የተሟላ ባይቶችን ይጠቀማል.
- `Numeric` እንደ `(mantissa, scale)` ይከፈታል ፣ እዚያም ማንቲሳ የሙሉ ቁጥር እሴት እና ሚዛን የትንሽ አሃዞችን ብዛት ያስቀምጣል ።

እነዚህ ደንቦች ለፊርማዎች እና ለሃሽ አስፈላጊ ናቸው ሁለት SDKs ተመሳሳይ አመክንዮአዊ ግብይት የሚፈጥሩ ተመሳሳይ የካኖኒካዊ ባይቶችን መፍጠር አለባቸው ።

## የቅጥያ ሃሽስ {#schema-hashes}

የተጻፉ Norito ጥቅማጥቅሞች በዕውቀቱ ውስጥ የ 16 ባይት ስክሪም ሃሽ ይይዛሉ ። ነባሪው ሃሽ ሙሉ በሙሉ ብቁ ከሆኑት ዓይነት ስም የተገኘ ነው ። መዋቅራዊ ስክሪሞችን ማካተት የሚችሉ ሕንፃዎች ሀሽውን ከካኖኒካል ስክሪሙ ይመርጣሉ።

የታይፕ ዲኮደሮች የስኪማ አለመሳሰቦችን ይክዳሉ። ይህ ደንበኞችን ልክ የሆነውን Norito ክፈፍ በስህተት እንደ የተሳሳተ ዓይነት እንዳይዘረዝሩ ይከላከላል እናም አንድ SDK ቋሚ ጥቅል ከአውታረ መረብ የውሂብ ሞዴል በሚወጣበት ጊዜ የተለመደው የአካል ጉዳተኛ ሁኔታ ነው ።

## መጭመቂያ እና ማፋጠን {#compression-and-acceleration}

Norito የሎጂካዊ አጠቃቀም ጭነት ሳይቀይር ግልፅ እና ተጣጣፊ መጭመቂያ ይደግፋል

|ገጽታ |ዓላማ|
| --- | --- |
|`to_bytes` |አንድ አርዕስት እና ያልተጨናነቀ payload ተከትሎ ኢንኮድ.|
|`to_compressed_bytes` |Zstd ጋር ኢንኮድ እና ራስጌ ውስጥ የመጭመቂያ መለያ መቅዳት.|
|`to_bytes_auto` |መጭመቅ ዋጋ ያለው መሆን አለመሆኑን ለመወሰን የዴተሪሚኒስት ሄውሪቲክስ ይጠቀሙ። |
|CRC64 ማፋጠን | ተንቀሳቃሽ ጥቅም ላይ ይውላል CRC64-XZ በሁሉም ቦታ ፣ በ CLMUL በ x86 ላይ_64 ወይም PMULL በ aarch64 ላይ ይገኛል. |
|GPU CRC64 እና መጭመቂያ |አማራጭ ሜታል ወይም CUDA ረዳቶች ትላልቅ ጥቅማጥቅሞችን ሊያፋጥኑ እና ከዚያ ወደ CPU ዱካዎች ይመለሳሉ ። |

የሃርድዌር ማፋጠን የተከፈለውን ይዘት በጭራሽ አይለውጥም ። CRC እና JSON ማፋጠሪያዎች ተንቀሳቃሽ የውጤት ቢት-ለ-ቢት ማዛመድ አለባቸው። Zstd ክፈፍ ባይቶች በ CPU እና GPU ኢንኮደሮች መካከል ሊለያዩ ይችላሉ ፣ ግን የተከፈተው ጠቃሚ ጭነት እና Norito ራስጌ ሜታዳታ ለማረጋገጫ ወሳኝ ናቸው ።

## JSON ድጋፍ {#json-support}

Norito የ Norito ዓይነት ስርዓትን ሳይለቁ JSON ለሚያስፈልጋቸው መጨረሻ ነጥቦች እና መሳሪያዎች የተፈጥሮ JSON ክምችት ያካትታል ።

|JSON ባህሪ |አጠቃቀም ጉዳይ|
| --- | --- |
|`norito::json::{to_json, from_json}` |የዲተሪሚኒስት ትይፕ JSON ኮድ / ዲኮድ። |
|ቆንጆ እና ጸሐፊ ረዳቶች |CLI ውፅዓት, ማያ ገጾች, እና የዥረት `std::io` ውህደት.|
|DOM እሴቶች |በ Norito JSON እሴት ሞዴል አማካኝነት የፕሮግራም ማነቃቂያ። |
|ፈጣን ጽሑፍ JSON |ለሞቃት DTO መንገዶች በሥነ-ሕንፃ ቴፕ ላይ የተመሠረተ ዲኮድ/ኢኮድ። |
|የዜሮ ቅጂ አንባቢ |በተቻለ መጠን ከግቤት ውስጥ ገመዶችን የሚበደር ምልክት ቅኝት። |
|ደረጃ 1 ማፋጠን |አማራጭ AVX2, NEON, የብረት ወይም CUDA መዋቅራዊ ኢንዴክሽን ከስካላር ውድቀት ጋር። |

Iroha ኮድ ይመርጣል `norito::json` ለደብዳቤዎች የሚረዱ API ጥቅማጥቅም ጭነቶች. `serde_json` ለምርታማነት መንገዶች ከሚጠበቀው መርሃግብር እና የመስክ አያያዝ ባህሪ የሚለዩ አደጋዎች SDKs እና Torii የማስወጫ መሳሪያዎች።

## የመነሻ ድጋፍ {#derive-support}

Rust የውሂብ ዓይነቶች በአጠቃላይ ከእጅ ኮዴክ ኮድ ይልቅ የተመነጩ ማክሮዎችን ይጠቀማሉ ። የመነጨው ንብርብር የ Norito ባይንሪ ኮዴኮችን ፣ መርሃግብሮችን እና JSON ረዳቶችን ሊፈጥር ይችላል።

የተለመዱ የመስክ ባህሪዎች የሚከተሉት ናቸው:

|ባሕርይ|ተጽዕኖ|
| --- | --- |
|`#[norito(rename = "other")]` |ለ schema እና JSON ተኳሃኝነት የተረጋጋ ተከታታይ ስም ይጠቀማል። |
|`#[norito(skip)]` |ኢንኮደር መስክ ያስወግዳል. ዲኮደር `Default` እሴት ያቀርባል. |
|`#[norito(default)]` |`Default` ጥቅም ላይ የሚውለው የከፈተው ጭነት ሜዳውን በማይሸከምበት ጊዜ ነው።|
|`#[norito(skip_serializing_if = "...")]` |የዲተሪሚኒስት ዲኮዲንግ ነባሪዎችን በመጠበቅ ላይ ሳለ, predicate የሚስማማ ከሆነ JSON ውስጥ መስኮች ያስወግዳል. |

የዲሪቨር በተጨማሪም በተቻለ መጠን የተመሰጠረ ርዝመት ጥቆማዎችን እና ትክክለኛ ርዝመት ስሌቶችን ያጋልጣል። ኢንኮደሮች እነዚህን ጥቆማዎች በመጠቀም ቡፈሮችን ለማስቀመጥ እና ተጨማሪ ቅጂዎችን ለማስወገድ ይጠቀማሉ ።

ከምንጭ Iroha ወይም SDK ማያዣዎችን በሚገነቡበት ጊዜ የ Norito ባህሪዎች የትኞቹ ረዳቶች እና አፋጣኞች እንደሚገኙ ይመርጣሉ:

| --- | --- |
|`derive` |ዳግም የተላኩ የሂደታዊ ማክሮዎች ለሁለትዮሽ ፣ ስኪማ እና JSON ውርዶች። |

|`packed-struct` |የታሸጉ የተገኘ-ተመነጨ መዋቅር አቀማመጦች.|

## Torii እና Norito RPC {#torii-and-norito-rpc}

Torii የተጋለጡ JSON ለበርካታ ኦፕሬተር መስመሮች, ነገር ግን የተጻፈ የሁለትዮሽ መስመሮች መጠቀም Norito. የተጻፈ የአሁኑ መገናኛ ዘዴ Norito HTTP አካላት ናቸው `application/x-norito`.

አንድ የፍጻሜ ነጥብ Norito ሲቀበል ወይም ሲመልስ እነዚህን ራስጌዎች ይጠቀሙ:

```http
Content-Type: application/x-norito
Accept: application/x-norito
```

አንድ መጨረሻ ነጥብ ሁለቱንም ውክልናዎች የሚደግፍ ከሆነ ደንበኞች ግልፅ የሆነ ምርጫ ዝርዝር መላክ ይችላሉ:

```http
Accept: application/x-norito, application/json
```

የዲኮድ ውድቀቶች እንደ Torii የተጻፉ ስህተቶች እና በቴሌሜትሪ የተቆጠሩ ናቸው ። የተለመዱ ምክንያቶች ልክ ያልሆነ አስማት ፣ ያልተደገፈ ስሪት ፣ የማይደገፍ ባህሪ ባንዲራ ፣ የቼክ አኃዝ አለመጣጣም ፣ የተበላሸ UTF-8 ፣ ልክ ያልሆነ enum መለያ እና የስካማ አለመጣጣም ናቸው።

Norito RPC ትራንስፖርት የሚመረጠው በትራንስፖርት ውቅር በኩል ነው. የጥያቄዎችን መዘግየት ፣ ውድቀቶች ፣ ንቁ ግንኙነቶች ፣ የምላሽ ባይቶች እና `torii_norito_decode_failures_total` በተናጠል ከ JSON ትራፊክ.

## የአሠራር አቅጣጫ {#operational-guidance}

- SDK ገንቢዎች እና የተፈጠሩ አገናኞች በእጅ ከተሠሩ Norito ባይት ይልቅ ይመርጣሉ ።
- የአውታረ መረብ አለመሳካትን እንደ ጊዜያዊ ችግር ሳይሆን እንደ ስሪት ወይም የማስተካከያ ችግር አድርገው ይመለከቱ።
- መዝገብ `.nrt`, `.norito`, እና እነሱን ያመነጩት በመልቀቂያ ወይም ክስተት ጥቅል ውስጥ የተገለጹ ጥንታዊ ቅርሶች.
- ለተፈረሙ፣ ለሃሽ የተደረጉ ወይም የቀሩ መረጃዎች Norito ን እንደ እውነቱ ምንጭ ይጠቀሙ። ለዳሽቦርዶች እና ለእጅ ቁጥጥር JSON ትንበያዎችን ይጠቀሙ።
- አዲስ Torii የተጻፈ የመጨረሻ ነጥብ ሲጨምር JSON፣ Norito ወይም ሁለቱም ተቀባይነት እንዳላቸው ሰነድ አድርግ፤ እንዲሁም በ `/openapi` ውስጥ የሚደገፉ የይዘት አይነቶችን አስቀምጥ።
- ማፋጠሪያውን ከማግበርዎ በፊት የስካላር ውፅዓት ላይ የእኩልነት ሙከራዎችን ያካሂዱ ። ማፋጠን ከከሸፈ የዴትሪሚኒስት ስካላር መውደቅ ይጠቀሙ። የፍጆታ ጭነት ትርጉም ሳይለወጥ መኖር አለበት ።
