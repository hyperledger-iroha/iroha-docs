# Norito {#norito}

Norito የ Iroha ነጠላ ፕሮቶኮል-መደበኛ ተከታታይ ንብርብር ነው።. የአውታረ መረብ እኩዮች፣ SDKs፣ CLI መሳሪያዎች፣ Torii፣ Kura እና የተፈጠሩ አርቲፋክቶች በትክክል በተመሳሳይ ጭነት ላይ መስማማት ሲፈልጉ ጥቅም ላይ የሚውለው የባይት ቅርጸት ነው።

ውሂቡ የመግባባት፣ የመፈረም፣ የሃሺንግ፣ ጽናት ወይም የመስቀል-SDK መስተጋብር አካል ሲሆን Norito ን ይጠቀሙ። API የመጨረሻ ነጥብ ለኦፕሬተሮች፣ ዳሽቦርዶች ወይም ፈጣን ማረም በሰው ሊነበብ የሚችል ትንበያ በግልፅ ሲያቀርብ JSON ን ይጠቀሙ።

## የአቀማመጥ ባንዲራዎች {#layout-flags}

Norito የአቀማመጥ ምርጫዎችን በመጨረሻው የራስጌ ባይት ውስጥ ያከማቻል።. ነባሪው v1 ረዳቶች `COMPACT_LEN` (`0x02`) ለተጨናነቁ የዋጋ ርዝመት ቅድመ ቅጥያዎች ያመነጫሉ። ደዋዮች በ`flags = 0x00` ኮድ ሲያደርጉ ግልጽ የሆነ የቋሚ ስፋት ርዝመት ቅድመ ቅጥያዎች ሊነበቡ የሚችሉ ሆነው ይቆያሉ።

## የኢንኮዲንግ ህጎች {#encoding-rules}

Norito በ Iroha የውሂብ ሞዴል ውስጥ ለሚታዩ የተለመዱ የውሂብ ቅርጾች ዲተርሚኒስቲክ አቀማመጦችን ይጠቀማል -

- ሕብረቁምፊዎች `[len][utf8-bytes]` ናቸው; `len` ሲነቃ `COMPACT_LEN` ይከተላል።
- `COMPACT_LEN` ሲዋቀር፣ የእያንዳንዱ እሴት ርዝመት የታመቀ ቫሪንት ይጠቀማል።
- `COMPACT_LEN` በማይኖርበት ጊዜ፣ የእያንዳንዱ እሴት ርዝመት 8-ባይት ትንሽ-ኢንዲያን `u64` ነው።
- የቅደም ተከተል ርዝመት ራስጌዎች ተስተካክለዋል ባለ 8-ባይት ትንሽ-ኢንዲያን `u64` በ v1.
- `Vec<u8>` በአንድ ርዝመት ከአንድ ባይት ይልቅ እንደ `[len_u64][raw-bytes]` ተቀምጧል።
- የታሸጉ ቅደም ተከተሎች `(len + 1)` ሞኖቶኒክ `u64` ማካካሻዎችን ይከተላሉ እና የተዋሃዱ ንጥረ ነገሮች ጭነቶችን ይከተላሉ።
- ካርታዎች የመግቢያ ቆጠራዎችን በቋሚ `u64` ኮድ ያደርጋሉ እና ዲተርሚኒስቲክ ቁልፍ ቅደም ተከተል ይጠቀማሉ። `HashMap` ግቤቶች ከመቀየርዎ በፊት በቁልፍ ይደረደራሉ; `BTreeMap` ተፈጥሯዊ ቅደም ተከተሉን ይጠቀማል.
- `BigInt` ትንሽ-ኢንዲያን ሁለት-ማሟያ ባይት ከ`u32` ባይት ርዝመት እና ባለ 512-ቢት ካፕ ጋር ይጠቀማል።.
- `Numeric` እንደ `(mantissa, scale)` ተቀምጧል፣ ማንቲሳ የኢንቲጀር እሴትን ያከማቻል እና ልኬቱ የክፍልፋይ አሃዞችን ብዛት ያከማቻል።

እነዚህ ደንቦች ለፊርማዎች እና ምስጠራ ሃሽዎች አስፈላጊ ናቸው. አንድ አይነት አመክንዮአዊ ግብይት የሚገነቡ ሁለት SDKs አንድ አይነት ነጠላ ፕሮቶኮል-መደበኛ ባይት ማምረት አለባቸው።

## መርሃግብር ምስጠራ ሃሽ {#schema-hashes}

የተተየቡ Norito ጭነቶች በራስጌው ውስጥ ባለ 16-ባይት መርሃ ምስጠራ ሃሽ ይይዛሉ። ነባሪው ምስጠራ ሃሽ ሙሉ ብቃት ካለው አይነት ስም የተገኘ ነው። መዋቅራዊ መርሃግብር ሃሺንግን የሚያነቃቁ ግንባታዎች በምትኩ ምስጠራውን ሃሽ ከነጠላ ፕሮቶኮል-መደበኛ እቅድ ያመነጫሉ።

የተተየቡ ዲኮደሮች የመርሃግብር አለመመጣጠን ውድቅ ያደርጋሉ። ይህ ደንበኞችን በአጋጣሚ ትክክለኛ Norito ፍሬም እንደ የተሳሳተ አይነት ከዲኮዲንግ ይጠብቃል እና የ SDK የሙከራ አብነት ቅርብ ከኖድ ዳታ ሞዴል ሲንሸራተት የተለመደው የውድቀት ሁነታ ነው።

## መጨናነቅ እና ማፋጠን {#compression-and-acceleration}

Norito አመክንዮአዊ ጭነቱን ሳይቀይሩ ግልጽ እና የሚለምደዉ መጭመቅን ይደግፋል -

|የባህሪ|ዓላማ|
| --- | --- |
|`to_bytes`|ያልተጨመቀ ጭነት ተከትሎ ራስጌን ኮድ ያድርጉ።|
|`to_compressed_bytes`|በZstd ኮድ ያድርጉ እና የመጭመቂያውን መለያ በርዕሱ ውስጥ ይመዝግቡ።|
|`to_bytes_auto`|መጭመቅ ጠቃሚ መሆኑን ለመወሰን ዲተርሚኒስቲክ ሂዩሪስቲክስን ይተግብሩ።|
|CRC64 ማፋጠን|ተንቀሳቃሽ CRC64-XZ ን በሁሉም ቦታ ይጠቀማል፣ CLMUL በ x86_64 ወይም PMULL በ aarch64 ላይ ሲገኝ።|
|GPU CRC64 እና መጭመቅ|አማራጭ ብረት ወይም CUDA ረዳቶች ትላልቅ ሸክሞችን ሊያፋጥኑ ይችላሉ፣ ከዚያም ወደ CPU መንገዶች ይመለሳሉ።|

የሃርድዌር ማጣደፍ የተመሰከረውን ይዘት በጭራሽ አይለውጠውም። CRC እና JSON አፋጣኝ ከተንቀሳቃሽ ውፅዓት ቢት-ለ-ቢት ጋር መዛመድ አለባቸው። የZstd ፍሬም ባይት በ CPU እና GPU ኢንኮደሮች መካከል ሊለያዩ ይችላሉ፣ ነገር ግን የተመሰከረው ጭነት እና Norito የራስጌ ሜታዳታ ለማረጋገጫ ዲተርሚኒስቲክ ሆነው ይቆያሉ።

## JSON አማርኛ {#json-support}

Norito የአገሬው ተወላጅ ያካትታል JSON ቁልል ለ API የሚያስፈልጋቸው የመጨረሻ ነጥቦች እና መሳሪያዎች JSON ሳይለቁ Norito ዓይነት ስርዓት.

|JSON ባህሪ|ጉዳይ ተጠቀም|
| --- | --- |
|`norito::json::{to_json, from_json}`|ዲተርሚኒስቲክ የተተየበ JSON ኢንኮድ/ዲኮድ|
|ቆንጆ እና ጸሐፊ ረዳቶች|CLI ውፅዓት፣ የሙከራ አብነቶች እና በዥረት መልቀቅ `std::io` ውህደት።|
|DOM እሴቶች|በ Norito JSON እሴት ሞዴል በኩል የፕሮግራም ማጭበርበር።|
|በፍጥነት የተተየበ JSON|ለሞቃት DTO መንገዶች በመዋቅራዊ ቴፕ ላይ የተመሰረተ ዲኮድ/ኢንኮድ።|
|ዜሮ-ኮፒ አንባቢ|በተቻለ መጠን ከግቤቱ ሕብረቁምፊዎችን የሚበደር ቶከን ቅኝት።|
|ደረጃ-1 አፋጣኝ|አማራጭ AVX2፣ NEON፣ ብረት ወይም CUDA መዋቅራዊ መረጃ ጠቋሚ ከስካላር ተተኪ አማራጭ ጋር።|

Iroha ኮድ ለተተየቡ API ጭነቶች `norito::json` ረዳቶችን መምረጥ አለበት።. በምርት መንገዶች ላይ ግልጽ `serde_json` ማከል በ SDKs እና Torii ኤክስትራክተሮች ከሚጠበቀው የመርሃግብር እና የመስክ አያያዝ ባህሪ የመለየት አደጋ አለው።.

## ድጋፍ ያግኙ {#derive-support}

Rust የውሂብ አይነቶች በአጠቃላይ በእጅ ኮዴክ ኮድ ይልቅ የመነሻ ማክሮዎችን ይጠቀማሉ።. የመነጨው ንብርብር Norito ሁለትዮሽ ኮዴኮችን፣ መርሃግብሮችን እና JSON ረዳቶችን ማመንጨት ይችላል።

የተለመዱ የመስክ ባህሪያት የሚከተሉት ናቸው

|ባህሪ|ውጤት|
| --- | --- |
|`#[norito(rename = "other")]`|ለ እቅድ እና JSON ተኳኋኝነት የተረጋጋ ተከታታይ ስም ይጠቀማል።|
|`#[norito(skip)]`|ኢንኮደር መስኩን ይተዋል. ዲኮደር የራሱን `Default` ዋጋውን ያቀርባል.|
|`#[norito(default)]`| ይጠቀማል `Default` የተመሰከረ ጭነት ሜዳውን በማያካትትበት ጊዜ። |
| `#[norito(skip_serializing_if = "...")]` | መስፈርቱ ሲሟላ የ JSON መስኮችን ይተዋል፣ የማይለዋወጡ የዲኮዲንግ ነባሪዎችንም ይጠብቃል። |

ተዋጽኦዎች በተቻለ መጠን የተመሰጠሩ ርዝመት ፍንጮችን እና ትክክለኛ ርዝመት ያላቸውን ስሌቶች ያሳያሉ። ኢንኮደሮች እነዚህን ፍንጮች ቋት ለማስያዝ እና ተጨማሪ ቅጂዎችን ለማስወገድ ይጠቀማሉ።

## የሶፍትዌር ጥቅል የባህሪ ቤተሰቦች {#crate-feature-families}

Iroha ወይንም SDK ማሰሪያዎችን ከምንጩ ሲገነቡ Norito ባህሪያት የትኞቹ ረዳቶች እና አፋጣኞች እንደሚገኙ ይምረጡ

|የባህሪ ቤተሰብ|ምን እንደሚፈቅድ|
| --- | --- |
|`derive`|በድጋሚ ወደ ውጭ የተላኩ የሥርዓት ማክሮዎች ለሁለትዮሽ፣ እቅድ እና JSON ያመነጫሉ።|
|`compression`|የ Zstd ድጋፍ ለራስጌ-ፍሬም ጭነቶች።|
|`packed-seq`|የማካካሻ ሰንጠረዦችን በመጠቀም የታሸጉ የስብስብ አቀማመጦች።|
|`packed-struct`|የታሸጉ የመነጩ መዋቅር አቀማመጦች።|
|`compact-len`|የቫሪንት በእሴት ርዝመት ቅድመ ቅጥያዎች።|
|`columnar`|Norito የአምድ ብሎኮች፣ የሚለምደዉ AoS/NCB ረድፍ ኮዴኮች፣ እና ለስካን-ከባድ መንገዶች የተበደሩ እይታዎች; በነባሪው `node-codec` ባህሪ ስብስብ ውስጥ ተካትቷል።|
|`strict-safe`|በተሳሳቱ መንገዶች ውስጥ ያሉ ድንጋጤዎችን ወደ የተዋቀሩ ስህተቶች ይለውጣል።|
|`simd-accel`|CPU ማፋጠን በሚገኝበት ቦታ፣ ከዲተርሚኒስቲክ ተተኪ አማራጭ ጋር።|
|`json`|ቤተኛ JSON ተንታኝ፣ ጸሐፊ፣ DOM፣ የተተየቡ ተዋጽኦዎች እና ፈጣን መንገዶች።|
|`json-std-io`|አንባቢ እና ጸሐፊ ረዳቶች በ JSON ቁልል ላይ ተደራርበዋል።|
|`metal-stage1`፣ `cuda-stage1`|አማራጭ GPU JSON መዋቅር-መረጃ ጠቋሚ ጀርባዎች።|
|`metal-stage2`|ለ JSON መዋቅራዊ ቴፕ አማራጭ የብረት ሜታዳታ ምደባ።|
|`metal-crc64`፣ `cuda-crc64`|ለትልቅ ሸክሞች አማራጭ GPU CRC64 ረዳቶች።|
|`gpu-compression`|አማራጭ ብረት ወይም CUDA Zstd ማጣደፍ ለትልቅ ጭነቶች።|
|`stage1-validate`|የተፋጠነ JSON መዋቅራዊ ኢንዴክሶችን ከስካላር ውፅዓት ጋር የሚያወዳድር የማረም ማረጋገጫ።|

የባህሪ ተገኝነት በ SDKs እና በልቀት መገለጫዎች መካከል ሊለያይ ይችላል። የዋየር ቅርጸቱ የሚተዳደረው በአካባቢያዊ የግንባታ ባንዲራዎች ሳይሆን በራስጌው እና በመርሃግብሩ ነው።

## Torii እና Norito RPC {#torii-and-norito-rpc}

Torii ለብዙ ኦፕሬተር መስመሮች JSON ን ያጋልጣል፣ ነገር ግን የተተየቡ ሁለትዮሽ መስመሮች Norito ይጠቀማሉ። ለአሁኑ የተተየቡ Norito HTTP አካላት የሚዲያ አይነት `application/x-norito` ነው።

API የመጨረሻ ነጥብ ሲቀበል ወይም ሲመልስ እነዚህን ራስጌዎች ይጠቀሙ Norito

```http
Content-Type: application/x-norito
Accept: application/x-norito
```

የ API የመጨረሻ ነጥብ ሁለቱንም ውክልናዎች ሲደግፍ ደንበኞች ግልጽ የሆነ የምርጫ ዝርዝር መላክ ይችላሉ -

```http
Accept: application/x-norito, application/json
```

የዲኮድ ውድቀቶች እንደ የተተየቡ Torii ስህተቶች ይታያሉ እና በቴሌሜትሪ ክትትል ይደረግባቸዋል። የተለመዱ መንስኤዎች ልክ ያልሆነ magic እሴት፣ የማይደገፍ ስሪት፣ የማይደገፍ የባህሪ ባንዲራ፣ የቼክሰም አለመመጣጠን፣ የተበላሸ UTF-8፣ ልክ ያልሆነ የኢኑም መለያ እና የመርሃግብር አለመመጣጠን ያካትታሉ።

Norito RPC መጓጓዣ የሚመረጠው በትራንስፖርት ውቅር ነው። የኦፕሬተር ዳሽቦርዶች የጥያቄ መዘግየትን፣ ውድቀቶችን፣ ንቁ ግንኙነቶችን፣ የምላሽ ባይቶችን እና `torii_norito_decode_failures_total`ን ከ JSON ትራፊክ ተለይተው መከታተል አለባቸው።

## Norito በዥረት መልቀቅ {#norito-streaming}

Norito በዥረት መልቀቅ ለሚዲያ እና ለእውነተኛ ጊዜ የመጓጓዣ ቦታዎች ተመሳሳይ ዲተርሚኒስቲክ አቀራረብን ያራዝመዋል። የእሱ ቁልፍ ክፍሎች የሚከተሉት ናቸው

|የዥረት ባህሪ|ዓላማ|
| --- | --- |
|የቴክኒክ መገለጫዎች|የክፍል ክሪፕቶግራፊያዊ ኮሚትመንቶችን፣ የግላዊነት መንገዶችን፣ ችሎታዎችን፣ የኮዴክ መገለጫን፣ የምስጠራ ስብስብን እና የይዘት ቁልፍ ሜታዳታን ያውጁ።|
|ክፍል ራስጌዎች|የክፍል ቁጥርን፣ የቆይታ ጊዜን፣ የቁራጭ ብዛትን፣ ጊዜን፣ የኢንትሮፒ ሁነታን፣ የድምጽ ማጠቃለያ እና የሜርክል ሥሮችን ያስሩ።|
|ክሪፕቶግራፊያዊ ኮሚትመንቶችን ያሽጉ|ተመልካቾች እና ቅብብሎሽ ከማገልገልዎ ወይም ከመፍታትዎ በፊት ጭነቶችን በቴክኒካል ማኒፌስት ላይ እንዲያረጋግጡ ያድርጉ።|
|ክፈፎችን ይቆጣጠሩ|ቴክኒካዊ ማኒፌስት ማስታወቂያዎችን፣ ግብረመልሶችን፣ ቁልፍ ዝመናዎችን እና የአቅም ድርድርን ይያዙ።|
|HPKE ቁልፍ ዝመናዎች|የተደራደረውን ስብስብ እና በብቸኝነት የሚጨምሩ ቆጣሪዎችን በመጠቀም የትራንስፖርት ሚስጥሮችን ያሽከርክሩ።|
| የችሎታ ድርድር | ሁለቱም ወገኖች የሚደግፏቸውን የባህሪ ቢቶች፣ የዳታግራም ገደቦች፣ የግብረመልስ ድግግሞሽ እና የግላዊነት መስፈርቶች ይመርጣል። |

## የአሠራር መመሪያ {#operational-guidance}

- በእጅ ከተሠሩ Norito ባይት ይልቅ SDK ገንቢዎችን እና የመነጩ ማሰሪያዎችን ይምረጡ።
- የመርሃግብር አለመመጣጠን እንደ ስሪት ወይም የሙከራ አብነት ችግር ይያዙት እንጂ እንደ ጊዜያዊ የአውታረ መረብ ውድቀት አይደለም።
- ማህደር `.nrt`፣ `.norito` እና ቴክኒካል አንጸባራቂ አርቲፋክቶች በተለቀቀው ወይም በክስተት ጥቅል ውስጥ።
- ለተፈረመ፣ ለተስተካከለ ወይም ለቀጣይነት ያለው ውሂብ Norito ን እንደ የእውነት ምንጭ ይጠቀሙ። ለዳሽቦርዶች እና በእጅ ፍተሻ JSON ትንበያዎችን ይጠቀሙ።
- አዲስ የተተየበ Torii API የመጨረሻ ነጥብ ሲጨምሩ JSON፣ Norito ወይም ሁለቱንም ይቀበላል እና በ`/openapi.json` ውስጥ የሚደገፉትን የይዘት አይነቶች ያጋልጡ።
- አፋጣኝ ከማንቃትዎ በፊት በስካላር ውፅዓት ላይ የእኩልነት ሙከራዎችን ያሂዱ። አፋጣኝ ካልተሳካ፣ ዲተርሚኒስቲክ የሆነውን ስካላር ተተኪ አማራጭ ይጠቀሙ። ጭነት ትርጓሜ ሳይለወጥ መቆየት አለበት።
